# R-3d253 一般半覆盖候选与静态组件的停界审查

## 精确承重式与跨枝缺口

一般证明工作稿保留最优比较并集 O、实际覆盖 C、D=|O\\C|、G=|C\\O| 的准确关系
\[
\operatorname{OPT}_m-2W=D-G-W.
\]
真正目标只需付 D≤W+G；更强的 D≤W 已被71客户两人完整SPE反例否定，但该反例仍满足half。Root hybrid 沿同一完整策略强制最优前缀，逐步IC保留真实后继，却没有把每步客户系数求和成统一非正债；重新表述不产生跨枝共同支付。

工作稿还保留聚合安全值、extra-one、完整菜单、真实行流和福利余项等未证候选，有限阴性不改变量词。

## 静态模块与有限诊断

独立静态模块证书给四主题34客户模块的精确下界：固定混合 p*=(10,10,21,10,10,21)/82，任意整数竞争槽 t 的期望值满足
\[
E_{p^*}f_B\ge2411/246-587(t-2)/246.
\]
在 n 个模块、2n+1 个静态不观察对手槽中得到 v_{2n+2}≥2411/246-587/(246n)，但将这些静态模块拼成完整SPE仍有迁移偏离缺口。

`attack_uniform_time.py` 在六个冻结完整策略上交替优化客户权重与查询分布 LP，目标为 \(\sum_i\min_A g_p(Z_i(A))\le W\)。JSON 六个结果均为负gap（约−0.1667至−0.2），是有限浮点诊断，不能证明候选普遍成立。独立攻击检查点还给出静态全背景比较式
\[
F_r(b)\le(r+s)v_{s+1}(b),
\]
其中 F_r 是固定背景的静态未来利润；它不支付动态SPE。

`eo_module_contract_exact_output.json` 的 pair/triple exact rows（含根收益29/3）是静态局部身份，不提供全树IC共同付款。所有程序保持完整有序历史与单位客户边界，未把count-Markov子类当原模型。

## 结论与接续

本批实际阅读后可复用 D-G-W 账本、静态模块仿射界、有限完整策略锥诊断和 F_r 静态比较式；跨枝共同支付、聚合安全值和 Q-CAG-HALF 仍开放。后续必须把静态组件嫁接到完整有序历史策略并逐动作 Fraction 核验，或给出严格 \(\operatorname{OPT}>2W\) 的真实单位客户反例。
