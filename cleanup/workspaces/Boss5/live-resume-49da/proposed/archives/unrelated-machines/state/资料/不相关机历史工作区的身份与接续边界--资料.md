# 四个字段的实际合同

| 字段 | 原值及程序含义 | 不能推出的内容 |
| --- | --- | --- |
| `schema` | 整数 `1`。已读旧/当前 `workspace_init` 均要求对象恰有 schema/save/actor/instance 四键，且 `type(schema) is int`、值为 1。 | 不是数学模型版本、定理版本或审查等级。 |
| `save` | `unrelated-machines` 是存档路由 ID。旧程序据此把工作区拼在 `research/workspaces/<save>/<actor>/`，保存范围亦依绑定存档区分；更换题目通常另用 clone。 | 字符串本身不定义 R∥Cmax 的输入、量词或任何近似保证，也不授权恢复暂停的旧题。 |
| `actor` | 该 R-前缀发布标识与目录名、配套 README 一致，形状符合旧 R-UUID 合同。旧程序优先显式 actor、环境指定或本地绑定；缺省时才生成 R-加 UUID。 | 仅由其形状不能断言这一次确由缺省生成，也不证明真人身份、独立审查、研究权或作者贡献。它不是当前 Boss5 的新身份。 |
| `instance` | 32 位小写十六进制值。程序读取本地 `wcg.instance`，缺少时生成 UUID hex；已存在 profile 的 instance 与本地不同且未显式 resume 时拒绝接管，显式 resume 时采用 profile 的旧 instance。 | 不是调度问题的输入 instance、样本编号、数学证书、权限令牌或密码。不能由此证明某个旧执行者已经停止或本次材料已推送。 |

原件的 schema 精确为整数 1，actor 符合 `R-[0-9a-f]{32}`，instance 恰为 32 位小写 hex；这只核对文件形状与已读合同的相容性。本次没有运行 start、workspace、resume、checkpoint、身份迁移或任何远端操作，未声称对当前生产环境做过恢复测试。

旧 `workspace_init` 对已存在 profile 还检查 save/actor 与本次调用相等，拒绝 profile/README 或路径组件的符号链接，只在文件不存在时排他创建，不覆盖已有 README。所谓 resume 是接受同号已有实例的防误操作步骤；历史工作区总 README 明说身份记录不是认证秘密或强制权限系统。私聊和工作区访问也不能从这四个字段推出加密或访问隔离。
