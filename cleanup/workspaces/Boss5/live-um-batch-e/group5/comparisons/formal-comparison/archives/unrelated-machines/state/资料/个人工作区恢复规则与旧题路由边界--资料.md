## README 实际规定的工作区规则

原文把个人工作区定义为持续备份区，允许保存未完成、未核验、后来发现错误的推导、代码、实验和失败尝试；保存时不要求先形成 Claim、通过数学审查或证明有价值。README 应记录正在做什么、文件在哪里、卡点和下一步。每个独立对话使用独立 clone，个人目录位于 `research/workspaces/<save>/<actor>/`；Boss 团队由所在对话汇总，不另开研究分支。

恢复路径是：用 `work.py workspace` 初始化或恢复个人区，用 `work.py checkpoint` 保存阶段备份；只有回执 `status=pushed` 才能保证远端可恢复；同 clone 继续使用原身份，环境丢失时用原 actor 和 `--resume`，先读取已保存 README。同行 `visit` 只能读取已推送个人材料；公屏和私聊继续经过根 `work.py`。

共享正文、候选、审查和研究地图按数学对象组织，不按角色分区。个人备份不自动进入可靠结论，必须经检查整理后放入共享位置，并让工作区链接正式正文。默认 checkpoint 只附加本人工作区；显式路径会替换默认范围并要求列全本次保存文件。

## 旧题路由边界

文档开头把最新方向写成一般人数、一般共同目录的 Q-CAG-HALF，存档为 `customer-attraction`，并要求停止特殊人数、特殊目录和局部常数任务。它还指向旧 customer-attraction RUNBOOK 和 shared/unrelated-machines 绑定。这些是该 README 所属旧题的路由事实，不是当前 Boss3 对话的主任务。当前会话明确处理六人 SPE、六提供者完整有序历史和目录主题覆盖目标，采用 `repository-cleanup` 存档、`rebuild/research-v2` 结果分支及当前 clean claim/show/done 协议；不能把 README 的“停止特殊任务”倒灌成当前数学结论。

同样，README 的“做不出来不构成不可能性证明”是通用研究纪律；它不能替代当前每个来源的实际数学处置，也不能把一份个人备份写成已证明或已证伪。
