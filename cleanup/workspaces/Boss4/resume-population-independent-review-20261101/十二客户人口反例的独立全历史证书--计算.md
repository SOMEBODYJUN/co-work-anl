# 十二客户人口反例的独立全历史证书

本资源完整读取4416B审查、5837B标准库程序、56827B冻结JSON。数学反例本身已在父档[人数增加的十二客户全部均衡福利下降](../../../../state/反例/人数增加的十二客户全部均衡福利下降--反例.md)自足保存；本三源增量是另一历史独审、每一根路径对应的完整有限函数、全部输出字段与程序合同。它们不新授一个人口反例。原件和本次完整字段/动作比较在[证据目录](../../tools/evidence/population-independent-review-primary/README.md)。

## 实例、反例量词与缩放

原共同目录模型有不同单位客户、有限非空共同主题集合、单位提供者依次观察全部有序历史，最终被覆盖客户在覆盖者间均分。所有重复行动、离轨历史和合法平局均保留。这里标签0/1/2分别为A/B/C，固定兴趣客户如下。

| 兴趣 | 不同单位客户数 |
|---|---:|
| A | 3 |
| B | 3 |
| C | 1 |
| AB | 1 |
| AC | 2 |
| BC | 2 |

无ABC客户，共12人，主题大小6、6、5，各有私有客户，覆盖两两不同且互不包含。对于终局计数(a,b,c)，**仅当对应主题确被选**才计算

$$U_A=3/a+1/(a+b)+2/(a+c),\quad
U_B=3/b+1/(a+b)+2/(b+c),\quad
U_C=1/c+2/(a+c)+2/(b+c). \tag{1}$$

因此实际收益读取没有零分母。三人全部完整纯SPE有序路径恰ABC/BAC、W12；四人全部路径恰AABB六排列、W11；OPT₃=OPT₄=12。最佳和最差SPE福利都随3→4下降，反驳直接人口福利单调归纳；两人数均满足half。每个兴趣组复制任意正整数q倍，全部收益和IC同比乘q、所有严格比较和平局及路径集合不变，福利从12q降至11q，绝对损失q无界。缩放结论是一般代数，不是有限q扫描的外推，也不宣称任意人数都会下降。

该对象归六人子档作为归纳障碍资源；这份原审计没有六人输入。它也不同于父档[四主题2→3严格人口下降族](../../../../state/反例/两人到三人的严格人口福利下降族--反例.md)：后者有13/40客户及q≥22的不同输入，其中严格版全历史唯一；不能把其唯一性或符号IC搬给本三主题容许平局的十二客户例。

## 原程序的生成与证书验证是两个步骤

population_audit.py独立使用Fraction、lru_cache、itertools.product和嵌入常量BASE，不导入customer_attraction、发现者代码或max-min门槛递推；无外部输入文件、LP、随机种子或第三方依赖。enumerate_game(players,scale=1)把每类型显式展开成count×scale名单位客户。实际run只调用n=1,2,3,4、scale1，另对n3/4调用scale2，对n2调用scale0；不是任意文件输入的通用认证器，也没有畸形参数校验合同。

记E(h)为从**有序**前缀h可由完整纯SPE实现的有序终局集合。叶E(h)={h}，内部为三个孩子分别选择一条终局

$$(t_A,t_B,t_C)\in E(hA)\times E(hB)\times E(hC),$$

再保留这个**指定实际菜单**中所有使当前玩家最终收益最大的行动，令其所选叶加入E(h)。必要性是任一完整SPE每个孩子自身可信；充分性是三个孩子的策略域不交，可分别拼接，再由当前最佳行动获得一个完整SPE。这给全部根路径，不要求同计数历史采取同动作或共享平局。

程序为每条终局仅用answer.setdefault保留**第一份**完整子策略证人。对父节点这已足够：当前及更早角色在每个孩子看到的收益只由那个完整终局确定；同一终局的其它策略如何选离轨动作，不改变该父菜单收益。因而不需要保存所有策略才能完整枚举路径。输出“一路径一证书”绝不等于穷尽所有纯SPE策略。

生成结束后才单独检查每份动作表：域必须恰为所有长度0,…,n−1的有序历史；从任意历史按同一动作表走到叶；对于每个备选a，先强制a再按该表的真实孩子继续，比较当前角色收益

$$u_{|h|}(z_\sigma(h))\ge u_{|h|}(z_\sigma(ha)). \tag{2}$$

三个a全部比较，**包括自身**。相同固定程序里这一步独立于生成菜单循环，但不是另一作者程序或当前重新盲审。有限完美信息一步偏离原理使全部节点(2)足以认证完整SPE；这一步不在偏离后冻结实际叶。

## 冻结JSON的每个字段与全体证书

根恰五字段：status=independently_verified；main_half_coverage_status为“unchanged OPEN; not a target counterexample”；method为“all ordered histories, Cartesian child menus, explicit unit clients, Fraction”；records；boundary_checks。status是**原冻结运行声明**，不是本轮新执行回执。文件没有时间戳、Python版本、代码哈希、运行命令或生产stdout；三源字节身份由本轮外层manifest固定，不向旧报告补造运行元数据。

四record每项恰八字段：players、scale、unit_clients、attainable_ordered_paths、decision_histories_per_certificate、all_action_comparisons、certificates、tables。全部scale1、unit_clients12。每certificate恰terminal、payoffs、welfare、minimum_spe_slack、actions五字段；payoffs和minimum_spe_slack是原Fraction字符串，不是浮点分数。actions每项恰history数组和action整数，A/B/C依次0/1/2；空数组表示根。全部12份完整动作表的276项与全部数值、路径和表行均已读，原顺序和字节保留。

历史数为$(3^n-1)/2$，比较总数为证书数×历史数×3。全文件828比较中，276项自身、552项非自身。minimum_spe_slack每份都是字符串“0”；因为比较含自身，这个零自动存在，不能解释为所有非自比较都平局，或靠它判断严格性。原报告没有非自strict/ties计数，本对象不从其它版本抄入。

一份明确的非count-Markov证书保存在records[3].certificates[2]，实际叶ABBA：其history=(A,B)指定B，而history=(B,A)指定A，二者过去计数同为(1,1,0)。BABA证书也有同计数不同动作。因此即使显示的终局**集合**只依计数，也不能把保存的完整策略表改成统一计数动作。三人两个证书和四人其它四证书是否依计数不是一般净化定理。

## tables的准确语义与原审查数学

每record的tables按depth=n−1,…,0排列；每层只有depth、rows，每row恰prefix_counts与attainable_terminal_counts。这是**完整终局计数**，包含过去，不是续局增量，也不是策略动作。程序先逐有序历史求E(h)，再检查相同计数的输出计数集合确相同，才按计数保存表。这种相等是本输入计算/结构事实，不是预先绑平局。

三人末位完整表为200→210，110→111，101→111，020→120，011→111，002→{102,012}；一人前缀100/010/001的全部终局计数都是111，根也111。但根C在可信后继的收益仅3，而根A/B为9/2，所以真正根路径只有ABC/BAC，不能因计数表同111就把CAB/CBA误列为根SPE。

四人末位完整表为300→310，210→220，201→211，120→220，111→{211,121}，102→112，030→130，021→121，012→112，003→{103,013}。再往前两人前缀200/110/020→220，101/011→{211,121}，002→112；一人前缀100/010→220，001→{211,121}；根→220。这些全部列表已与原数组逐项读比。

原独审的根比较为A/B各11/4，C的任意可信后继均8/3，差$11/4-8/3=1/12>0$，故四人根排C。三人AB背景末位C严格最佳、四人AAB/ABB背景补B/A严格最佳，就是拥挤改变末位排序的具体机制。完整收益表、AC/BC背景平局如何独立拼接、全部六排列的双向分类见父档既有[自足反例](../../../../state/反例/人数增加的十二客户全部均衡福利下降--反例.md)；原population_review.md全文与其一致。本源不给不含C的终局普遍结论，不能推广出任意m的人口下降模式。

## 边界、接口与两版审计的差别

run对n3/4的scale2重新生成完整结果，断言路径集不变、各证书福利恰乘2；对scale0/n2断言九条有序路径全可实现且各W0。**这些scaled/zero结果的完整证书不在JSON中**，最后仅存boundary_checks.double_scale=true、zero_clients=true两布尔值；不能把未存数组冒为原报告内容。零客户无收益除零：utility对客户的空和返回Fraction(0)，所有行动平局；解析上每份策略均SPE。任意q>0的复制结论来自同次缩放，而非这两个布尔值。

CLI的--output可选；未指定时只打印根状态/边界和每record的路径摘要，排除certificates与tables。指定路径使用open('x')，已有目标会失败，不覆盖冻结文件。源码在输出前run完数学检查。此处**没有运行这个CLI**，也没执行其run/enumerate_game；正文描述的是实际源码合同。

已完整比较发现者continuation_order/population_paradox.md、population_paradox_audit.py/json及其已有stdout。旧程序也用有序Cartesian子菜单和逐单位Fraction，原n1至5；逐证书只比较两个非自身行动，JSON只为每n保存一个selected_strategy以及每条路径的审计计数。旧程序main还会覆盖旁边JSON；本轮不执行。它的n5路径AABBC六排列、W12，和零/单个全主题/三个全主题客户边界，**不属于本独审三源的范围**。

本轮逐字段比较新旧n1…4：全部根路径、福利集、第一份证书收益与完整动作表均完全一致；旧审计的其它路径只有统计，本独审版首次在本次primary资源内保全其全部动作表。这是互相支持的版本关系，不是字节相同源，也不声称两作者发现过程完全独立。本population_review原称审查前只收到实例与待查结论、未读发现代码/证明，是其历史独审合同；本轮同时读了两版，不自称盲重构。原作者尚无外审、新颖性或最小性认证。

## 当前核对与可复用边界

本批只执行一次[结构/来源比较脚本](../../tools/evidence/population-independent-review-primary/inspect_records_and_compare.py)，输出[complete-semantic-read-and-comparison.json](../../tools/evidence/population-independent-review-primary/complete-semantic-read-and-comparison.json)，保全部字段及完整动作的无损A/B/C读本，并检查schema、动作域/合法标签、数量、两份报告相等项及非count动作差异。它不算效用、不枚举SPE、不核IC，不冒原独审复跑。原/旧两个审计入口和新数学执行均0；没有重复已成功且无新疑点的旧人口检查。
