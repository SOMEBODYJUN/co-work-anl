# 六人填充残差输入的自由完整菜单精确封顶

原1212B JSON的source完整指向R275 `direct_global/padded_residual_m6_dag.json`，scope为`fixed padded residual input full-terminal one-deviation menu, NOT universal bridge`。这与同目录的四人245客户crosscap点、三人固定组策略都不同。

旧实例六人，主题0…8分别A/B/T/D/E/P0/P1/P2/P3。十个单位客户类型为{A,D}:2、{A,E}:2、{B}:3、{B,D,E}:2、{T}:3、{T,D,E}:2及四个{Pi}:4，总30客户。实际路径(5,6,7,8,0,1)，收益(4,4,4,4,4,5)，W25、OPT26。旧输入只反common-query regret≤minimum provider payoff，松弛−1，不反half。

## 完整菜单与额外查询

固定同一旧DAG策略。在actual第i个节点强制主题b，其完整终局含过去、forced b和全部原指定后继，共六槽，记Z_i(b)。i=1…6、b=0…8共54列，去重后菜单𝒵恰16个计数。对额外静态查询a，f_Z(a)=Σ_(客户x∈a)1/(1+load_Z(x))；不是删去forced者后的五槽背景，也不增加原游戏玩家。

菜单值定义为

\[
v_{\mathcal Z}=\max_{p\in\Delta_9}\min_{Z\in\mathcal Z}E_p f_Z(a)
=\min_{Q\in\Delta(\mathcal Z)}\max_a E_Qf_Z(a).
\]

Q可自由混合不同actual位置/强制动作产生的列；不是同一p驱动的独立a,b推送律，不要求每个actual位置各自封顶。本记录给这个固定菜单的精确saddle证据，不给一般桥。

## 本批准确新增的检查

本批仅另写并执行一次标准库Fraction薄层检查：跟随保存DAG的actual动作，再对六actual节点的九个children逐个跟随其规定动作至叶，核终局与对应target相同；保存全部54个位置/forced动作/child索引/后继索引/完整计数及16个去重列。然后从原十客户类型直接算f、p、Q，原全部16primal及九query数与1212B报告逐项相同，最小primal=最大query=75/23。

这次检查不重算任何SPE阈值、不遍历所有5440节点、没有LP调用或原group核验器运行。输入/报告/checker的SHA及完整54列均在[菜单算术证据](../../tools/evidence/group-full-push-primary/padded-menu-arithmetic.json)，旧DAG的生成/节点成功记录另标复用。它为本固定菜单的数值身份补足证据，不能算成原父group审查曾审过padded，也不能把30客户和245客户相混。
