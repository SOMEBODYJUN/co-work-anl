## 声明先行重构与攻击顺序

审查者首先只收到精确目标声明，未读新证明；按要求仅将旧正文§10作为比较。独立重构认为，旧开链的空 sink 可从尾端逐件腾空，因此要排除中性步骤必须消除该入口。把尾任务第二边闭合回 root 是可能的机制：root 在坏态已满，任何局部后缀的正回流都必须伴随其他根任务先离开。

在取得构造之前已向主研究者提出两项风险：

- 若 macro 回流尾的处理时间排在 tinies 之前，宏根与宏尾的质量可能先占满一槽，破坏原来的槽0冲突和唯一坏分配。
- 闭合尾边通常比 home 边便宜，因此不能照抄旧证明的“任意额外后缀增加总成本”；需要真正排除或计算这些后缀。

收到扰动构造之后，从端点和两个最优整数调度自行重建 x、区间槽、全部合法分配和最小匹配，没有读取或导入作者的审计程序。之后才读取上述冻结正文，逐步核对一般证明。

## 一般证明的承重核查

1. **最优值与初始化。** S0、S1 的 root 负载分别为 `1-c/2` 与 `b+5c/4<=1`；其余负载是 a 或1。若 `Cmax<1`，所有 g 均不能使用时间1的第二端点，于是 root 单靠 g 的负载已为 `2b+c/4>1`。因此 OPT=1；x 是完整实际最优调度的显式凸组合。每条有限边质量均正。
2. **全部平局次序。** 根处 `g_k > g_0 > ordinary tiny > ordinary tail > special tail` 的处理时间组严格分离；组内平局只影响普通 tiny 或普通 tail。g_k 与 g_0 的区间恰覆盖槽0，特殊尾的区间只接槽 k。坏分配使用的剩余普通 tiny 可按任意既定次序分别注入槽1至k−1。故平局不改变实际坏分配。
3. **全体槽匹配。** 槽数恰 n。任意覆盖匹配必须占满所有槽，因此每个 home 恰接一任务。每环相邻迁移 bit 由 `z_(l-1)+(1-z_l)=1` 强制相等，故每环全开或全关。这里并未假设其他实际调度也具有该性质。这一槽计数有效地排除了成本可能降低的孤立后缀。
4. **最小成本的唯一机器分配。** 任意覆盖匹配至少开特殊 tiny 环或 macro 环；各整环成本增加都严格正，而特殊环增加量严格最小。显式坏匹配达到该增量。因此全部最小成本匹配确实只有一个实际机器分配；不需要槽级匹配唯一。
5. **全体合法实际重分配。** 任意 `Cmax<=B` 的实际调度只得到 bit 非减，允许部分后缀。若不新迁出任何原留 root 的 g，则特殊环保持原状或回退导致 root 净增至少 `delta-c/4>0`，其他环的非空后缀也给 root 严格加 c。唯一不超 B 的情形就是原分配。这覆盖了所有实际调度，未只枚举指定循环。
6. **双锐界与边界。** 新激活普通 tiny 环改 d+1 个原始任务，端点是 root 及 d 个 home，故同一次动作达到两界。root 新负载是 `2-4/k+7/(2k^2)>1`，且下降 `delta-c>0`。k=3、d=1 没有退化；单个环仍由两个不同任务、两台不同机器组成。
7. **构造位复杂度与范围。** 参数通过显式任务和机器数量给出，有限数都可用 `4k^2` 分母表示；构造及证书按实际输出位长为多项式。没有给出一般实例上的近似算法、一般局部最优性判定器或复杂度困难性归约。

## 有限计算覆盖

独立程序：`tests/audits/unrelated_machines/optimal_hull_closed_cycle_reviewer.py`。它只用 Python 标准库和 Fraction，不导入仓库规范构造、槽代码或旧开链代码。

程序直接重建每件任务两个端点，枚举每个二进制 bit 向量，因此检查的是全部带标号合法实际分配；另从最优凸组合重建正区间交长槽图，用 subset-DP 求最小总处理时间匹配并保留全部最小成本机器分配。该匹配方法不依赖正文的“每环全开/全关”化简。

实际运行记录：`evidence/runs/unrelated_machines/optimal_hull_closed_cycle_audit.json`。参数 `(k,d)=(3,1),(3,2),(4,1),(5,1)` 的完整分配数分别为1024、16384、8192、65536，总计91136。每例均得到 OPT=1、坏峰值为公式 B、两种最小支持均为 d+1，且 subset-DP 保留的最小成本实际机器分配数均为1。

另对 `(3,1)` 与 `(4,1)` 穷举普通 tiny 组和普通 tail 组的全部根排序平局次序，分别12和144种。全部槽图的最小成本实际机器分配仍唯一且相同。这些有限枚举是独立审计，不是一般证明。

## 单任务逃逸最小峰值的独立补审

另审拟定新身份 `UM-CLOSED-CYCLE-SINGLE-JOB-ESCAPE-THRESHOLD-v1`；其陈述不改动原邻域 Claim：在同一实例与同一 sigma 上，所有逐步仅改变一件任务、最终达到真实最优调度的路径中，最小可能峰值恰 `B+c`，其中 `c=1/k^2`。允许中间任意恶化和任意长路径。

独立先检查所有可能的第一步，按原 sigma 分组：

- inactive 环的根任务或内部非尾任务前移，接受 home 同时得到时间1与 a，峰值至少 `1+a`。
- inactive 环的尾任务前移到 root，root 峰值恰 `B+c`。
- active 特殊环的根任务回 root，root 峰值为 `B+delta+c/4`。
- active 特殊环的任意 e 回原 home，同样使该 home 同时得到时间1与 a。

以上穷尽全部单任务合法第一步，且 `1+a-(B+c)=(4k-5)/(2k^2)>0`、`delta+c/4-c=(k-7/4)/k^2>0`。所以任何离开 sigma 的单任务路径峰值至少 B+c；下界不要求路径单调，甚至不要求其最后达到最优。

上界依次激活每个普通 tiny 环：先将尾任务送 root，再逆序将各 e 向下一 home 送，最后将根任务送首 home。每个环暂时只在 root 增 c，其余 home 负载至多1，环完成后 root 降 `delta-c>0`。首次环的峰值恰 B+c，以后环峰值递降；最后恰为 S0，步数为 `(k-1)(d+1)`。因此精确最小峰值成立。

独立程序 `tests/audits/unrelated_machines/closed_cycle_escape_independent.py` 再次从整数 `4k^2` 缩放的端点单独重建输入，不导入前一个程序或仓库规范代码。它在 `(3,1),(3,2),(4,1)` 的完整带标号分配超立方体上用 bottleneck Dijkstra 求到任一 OPT=1 状态的最小峰值，并另核对上述显式路径。结果见 `evidence/runs/unrelated_machines/optimal_hull_closed_cycle_audit.json`，三个参数均精确为 B+c。

本补审的数学下界与上界已独立闭合；最终新增正文的冻结 hash 和复核覆盖范围见下一节。此结果只定量说明该反例族需要微小暂时增载，不能推称一般实例存在同样的逃逸阈值或多项式路径算法。


## 最终新增段与固定参数推论

已读取新增§11.4a、§11.5及cactus限制；读取时整文件 SHA256 为 `202bd695916a008daa5b4b054576a2eb667e4ccfbc6e1bb2ea019bb69147bfd0`。单任务阈值的一般证明与前述独立重构完全吻合。

一项量词措辞已反馈主研究者：应把“到任意OPT调度”写成“终点属于最优调度集合的全部路径之最小峰值”。现有上界给出S0，而没有逐个预先指定最优终点；最优终点集取最小正是已证明、也原先拟定的精确陈述。该文字更正不增加或削弱所需数学结论。

固定 k 后，`m+1=(k+1)(d+1)`，故最小参与机器数恰 `(m+1)/(k+1)`。对预定 ε 固定足够大 k，再让 d 增大，任何 o(m) 参与机预算最终小于该量，确实不能从 sigma 以不增最大负载动作启动。这里 k 必须在 m 增长前固定；正文已准确保留该量词顺序。

逐环机器多重图的结构确为共享 root 的 cactus；当 d=1 时，一个tiny根任务与尾任务是两条带标签平行边组成的长度2环。读取既有 `cactus_configuration_gap_and_block_exactness.md` 的 `UM-TWO-CHOICE-BLOCK-RANK-EXACT-v1` 合同后确认，每块环秩1符合其参数范围。因此新增局部障碍与已有精确算法兼容。审查没有将其扩大为所有cactus配置LP精确性，也未认证外部文献新颖性。
