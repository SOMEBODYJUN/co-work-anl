## 最重要的结论

需要区分“数学推理图”和“研究记忆／证据／执行系统”。外部项目并不共享一个只准定理的节点集合，但它们没有提供“一个文件存在且字段齐全，就可以充当数学前提”的依据。

本库可以采用更严格的数学上下文投影：只放能陈述的数学对象、结论、反例、条件、可复用方法和准确义务；证据通过对应对象按需展开；纯身份与执行履历从当前正式树删除。不能借“对齐上游”把已知好的数学内容压成摘要，也不能用上游的宽泛资源节点为本库的冗余开例外。

## 当前执行稿的缺口与修订要求

### 1. 必须有原知识保护检查，不能只做准入分类

现稿要求明确陈述、理由、用途和缺口，方向正确，但尚不足以回答“原来好的是否被整理坏了”。每组重写必须列出承重语义单元：模型、量词、假设、结论、构造/证明关键步、边界、仍未解的步骤。将原有好正文或可信来源与新稿逐项对应。

- 只是删除身份或重复输出：不用重做数学。
- 正文合并但承重语义均有保全位置：属于合并整理。
- 原量词变窄/变宽、关键证明省掉、旧反例被误称原模型反例：属于语义修复，不能以字段修复完成。
- 无法确认某段数学是否已保全：保持待判，不删除；只读必要来源，不机械重读全部历史。

不能用“新结论更一般”替代覆盖证明。新稿应明确推出哪些旧结论，同时保留旧材料中独立的构造技巧、等号/平局和失效边界。一个更强上界不自动包含旧例的所有认识。

### 2. 类型化验收，不要求所有对象交同一种证明

现稿“每个对象必须给完整推导及后续可检验问题”容易过严。建议：

| 数学角色 | 准入必须内容 | 不应强制 |
| --- | --- | --- |
| 定义/模型 | 对象、域、符号、量词、与相关模型的区别 | 为定义本身伪造真值证明或新研究问题 |
| 已证结论 | 精确陈述、假设、可定位的完整理由、实际证据范围 | 为已有充分证明再跑全部历史审计 |
| 反例/构造 | 被否命题、满足前提的精确见证、失败的一步 | 必须参数化，或必须另获正向一般定理 |
| 有限精确结论 | 有限域、穷尽理由、精确判定规则、结果的数学作用 | 用运行计数替代域和覆盖保证 |
| 猜想/义务 | 精确待证陈述、已知支撑、尚缺步骤 | 无依据判真/假，或因无证明删除 |
| 失败路线 | 失败合同、精确障碍、仍可行的边界 | 将“试过但没成功”当路线不可能 |
| 未理解的数学 | 保留可恢复的数学片段与待判问题 | 以无法立即复用或无人引用为由删除 |

“有一个数值反例”本身已能反驳全称命题，即使尚未找到更一般机制，仍应保留准确数学；删除的是包装与重复履历。

### 3. 准入必须绑定内容，而非只绑定路径和 ID

现稿只要求稳定身份与准入名单；若后续正文更改，旧“已准入”可能继续通行。至少绑定当前正文内容指纹及必要证据指纹。正文有任何实质变化后，应使其准入/关系审读过期，等待重判。可以先采用保守的全文 SHA，允许纯排版变化也要求确认；以后再细分陈述/证明的逻辑版本。

文件重命名不应偷偷改变数学身份；同一 ID 的陈述或模型改变不能沿用旧边。别名用于找回旧对象，不能自动把“旧例反驳旧命题”改接“新例反驳新命题”。

### 4. 状态至少有三个独立维度

- 内容角色：定义、结论、构造、反例、义务、有限结论等。
- 数学状态：已证、已反驳、条件、未解、尚未评估。
- 图准入/关系审读：未处理、准入、仅附件、删除、过期；关系可 proposed/accepted/rejected。

一个猜想可以作为明确目标进入研究图，但不能成为已成立的前提。一个被反驳的命题可作为反驳关系的精确目标，不因此被图删除得无从解释反例。一个合法反例即便作者叫 audit，也应提取为数学内容，而不是按文件类别删除。

### 5. 合取、或分支、假设和作用范围应可表达

逻辑推导 `{A,B} -> C` 是一条联合边，不能转换为 `A -> C` 与 `B -> C`。若存在两个独立证明，应保存两份证明支持，不要把它们合成必须同时成立的一个前提集。候选路线可以有 OR 备选，但不当作已证推导。

边应绑定具体结论与证明段落，说明前提各自作用、变量代换与共同模型；“同文件”“互相引用”“实现调用了库”不等于逻辑依赖。跨模型关系必须给映射及保留/丢失条件。

### 6. 纠错传递要撤销支持，不自动宣布所有后继为假

Danus 的严格事实 DAG 可级联撤回文件，本库可能包含多个证明或替代路线，宜采用：纠错旧命题/证明 -> 标记使用它的具体关系过期/不可用 -> 计算待复核闭包 -> 重评后继是否还有独立有效支持。无支持的后继不能继续显示“已有完整证明”；但不自动标“已反驳”。

Noemesis 明确将 correction-impact 解释为复核范围，这比全图真值级联更适合本库。纠错后旧正式页必须显示当前结论或就近指向修正，不能只在另一页说原页有误。

### 7. 断链和解析失败不能造成数学内容丢失

当前 maps.py 在遇到一个不合协议的元数据时整体报错，另会误扫历史副本。2.5 应将候选路径列出并给局部诊断；未解析文件保持待判，不能默认排除就宣布完成。暂缺关系端点可隔离该候选边，保留已有数学正文；断链不应把可用数学抹去。

迁移时允许两阶段操作：先枚举诊断和判定，再提交明确动作。父对象尚未完成可不影响其他已完整对象群继续整理；但不能把局部完成包装成全仓最终图。

### 8. 删除与既有 done 的兼容必须是原子变更

删除无数学页同时更新入链、当前来源目标去向、准入记录和第三阶段读取集合。历史 done 是原事件，不证明当前页应保留；同时不能通过随便改 old receipt 为 retired 来回避丢失独有数学的判断。

至少要求每个被替换页有当前处置：明确非数学删除，或数学去向（新对象/附件）。批量删除不允许仅按目录、短文长度、审查/PASS关键词，或“没有入边”决定。

### 9. 前台数学上下文与后台执行要求分离

数学 agent 主要读取模型、结论/证明、障碍与邻接上下文；ID、哈希、字段、来源清单和路由可由程序处理。保留机器最小迁移记录合理，但不能又把这份记录包装为数学“资源”页放回 state。

不能照搬 MATEK 当前空报告 fallback：只有“没有建立定理”或“下一步继续”不构成本库的准入内容。也不要照搬 Danus 的“模型 verifier 是唯一正确性权威”为事实；保持独立检查与精确证书的不同证据等级。

## 与当前 maps.py 的直接差距

1. `read_records` 第12–13行广义 rglob，含证据副本；应改为受审准入集合且路径严格限定。
2. 只检查 id/title/kind/status/summary 和非空正文；没有内容角色、数学状态、原知识保全、当前指纹与准入判断。
3. 任意 kind 都可生成 NodeRecord，资源/执行信息和数学推理没有投影区别。
4. edge accepted 只要求字段/端点/文件存在，未绑定前提当前版本，也未区分前提已证或候选。
5. 正式 build 把来源 done 与数学整理挂钩，且要求每个旧 target 继续存在；缺少2.5合法合并/删除后的去向解析。
6. 当前来源处置全完成和“无 scaffold”不代表数学对象语义与关系已审完。

## 可直接给 2.5 agent 的补充任务指令

先判原有知识是否完整，而后决定整理动作。你需要交付对象组中的可用数学内容；不要用来源字节数、核验次数或完成声明代替结论。

对每份原有好正文，保持模型、量词、承重条件、关键证明/构造、边界和独有技巧。只是冗余时删包装、合并入口，不重做已充分的数学；出现实质缺失或扭曲时只重构受影响的数学链，并写清精确差异。不能以“看起来同机制”判重复，也不能以“尚未一般化/没有引用”判无用。

把对象状态如实区分：已证、已反驳、条件成立、有限精确结论、猜想、缺口或尚未评估。只将已成立的前提用于已接受逻辑推导。每条联合边明确各前提作用和共同条件；候选、启发、来源、实现与证明依赖分开。

删除无数学履历页，必要证据依附数学对象。与删除/合并同步修改引用和当前去向。正文和承重证据改变后重新审读受影响支持，不能继承旧hash或旧 accepted 标记。保留可用数学和待判内容，隔离无依据的关系；不要为了让结构检查通过而静默丢弃内容或造边。

## 不应写进用户结论的夸大

- “所有最新数学Agent都规定计算/失败路线不得为节点”：不成立。
- “采用上游存储格式已经符合其数学准入”：不成立，本库只复制了数据容器与平坦解析器。
- “模型 verifier 通过保证数学100%正确”：不成立。
- “一个前提撤回意味着所有后继命题都被反驳”：不成立，只能撤销该支持并复核其他支持。
- “格式通过、全量登记完成、边数很多说明原数学被完整保全”：不成立。
- “必须得到更一般定理才可保留一个反例”：不成立，精确反例本身可反驳全称。
