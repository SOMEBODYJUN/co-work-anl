# 10 精确证书：从一行概率到完整续局

一个程序输出“通过”，本身不解释发生了什么。我们需要一份证书，使读者即使不信任构造程序，也能重新回答三个问题：每个客户为何愿意按照给出的概率行动？每家设施搬到任何其他合法地点后，收益为何没有超过指定倍率？没有逐条存进文件的布局，究竟使用什么客户均衡？

本章先把这三个问题化成可以手算的规则，再说明它们怎样对应 JSON 字段和代码。它介绍[共同目录黄金比构造](../facility_spe/shared_phi.py)、[任意设施数有限构造](../multi_facility_spe/two_exists.py)和两个独立检查器。程序入口以 [USAGE](../USAGE.md) 为准；本次修改的是讲义，不改变求解器。

## 10.1 输入中写的究竟是什么

两设施入口按地点列出客户：

```json
{"weights":[2,3,5],"locations":[[0,1],[1,2]]}
```

客户 0、1、2 的原子权重分别为 2、3、5。地点 0 覆盖客户 0、1，地点 1 覆盖客户 1、2。地点覆盖集合是客户编号集合，不是权重列表。省略 `U1/U2` 表示两家设施共用全部地点；若明确写出两个目录，共同目录程序要求二者是同一非空集合。

任意设施数入口则按客户列出地点：

```json
{"m":2,"k":3,"clients":[
  {"weight":2,"sites":[0]},
  {"weight":3,"sites":[0,1]},
  {"weight":5,"sites":[1]}
]}
```

这里 `m=2` 是地点数，`k=3` 是设施数。它表达同一批客户与覆盖关系，但设施数不同。地点和客户编号都从 0 起；同一地点可以有多家设施，它们的标签仍不同。

权重宜写成整数或精确分数字符串，例如 `"1/3"`。程序内部用 `Fraction` 保存精确有理数，避免把理论中的平局变成舍入误差。任意设施数入口拒绝二进制浮点权重；双设施命令行对 JSON 十进制做精确解析。两种 JSON 输入格式以及两种证书格式不能互换。

## 10.2 对一份概率策略逐客户检查

**定义 10.1（概率矩阵）。** 固定有标签布局 $\ell=(\ell_0,\ldots,\ell_{k-1})$。$p_{if}$ 表示客户 $i$ 选择设施 $f$ 的概率；不同客户独立随机化。客户 $i$ 的可达设施集合为

$$F_i(\ell)=\{f:\ell_f\text{ 属于客户 }i\text{ 的覆盖地点集}\}.$$

策略合法性要求：每个 $p_{if}\ge0$；若 $f\notin F_i(\ell)$，则 $p_{if}=0$；若 $F_i(\ell)\ne\varnothing$，则 $\sum_f p_{if}=1$；若 $F_i(\ell)=\varnothing$，则整行均为零。最后一种是未被覆盖，不是客户自愿退出。

**命题 10.2（定义级 NE 检查）。** 对任意设施数的线性负载成本模型，一个合法独立概率矩阵为精确客户 NE，当且仅当对每名参与客户 $i$，所有被它以正概率使用的设施，都达到它的可达设施中的最小条件期望成本，其中

$$c_i(f)=w_i+\sum_{j\ne i}w_jp_{jf}.\tag{10.1}$$

设施 $f$ 的收益则为

$$L_f=\sum_iw_ip_{if}.\tag{10.2}$$

**证明。** 客户 $i$ 决定选择 $f$ 时，自身必贡献完整的 $w_i$，其余客户的期望贡献由独立概率给出，因此得到 (10.1)。若它正概率使用的某设施严格更贵，把那一部分概率移到最便宜设施便严格降低成本；所以 NE 必须满足所述条件。反之，若全部支持行动均最便宜，改变自己的概率只是在这些最小值和更大值之间重新加权，不可能更便宜。式 (10.2) 由期望的线性性得到。$\square$

这就是手算顺序：先确认概率可达、非负和行和，再对每名客户计算每个可达设施的 (10.1)，最后用 (10.2) 算设施收益。客户的成本和设施收益使用不同的式子；不可把自己的平均贡献 $w_ip_{if}$ 当作自己确定选 $f$ 后的实际贡献。

**例 10.3（同址混合也要算上自身）。** 对 §10.1 的三名客户，取布局 $(0,0,1)$，把权重 2、3 客户分到地点 0，把权重 5 客户分到地点 1；同站两设施均匀分摊。概率矩阵为

$$p_0=(1/2,1/2,0),\quad p_1=(1/2,1/2,0),\quad p_2=(0,0,1).$$

收益为 $(5/2,5/2,5)$。权重 3 的公共客户在前两家各有条件成本 $3+2/2=4$，在第三家有成本 $3+5=8$；它只使用前两家，因此满足支持条件。权重 2 的客户只可到前两家，两边成本均为 $2+3/2=7/2$。权重 5 的客户只可到第三家。于是这确是精确客户 NE。此处只核验这个客户均衡，尚未检查所有设施搬迁。

### 两设施的简写条件如何覆盖三个分支

两设施代码只存公共客户选第一家的概率 $p_i$。独占总重为 $A,B$ 时，先计算

$$X=A+\sum_iw_ip_i,\quad Y=B+\sum_iw_i(1-p_i),\quad d_i=X-Y+w_i(1-2p_i).$$

$d_i$ 是第一家成本减第二家成本。

| 概率 | 被使用的行动 | 应当检查什么 | 理由 |
| --- | --- | --- | --- |
| $p_i=1$ | 仅第一家 | $d_i\le0$ | 第一家不能更贵 |
| $p_i=0$ | 仅第二家 | $d_i\ge0$ | 第二家不能更贵 |
| $0<p_i<1$ | 两家 | $d_i=0$ | 两个支持行动必须同为最便宜 |

`shared_phi.py` 的 `exact_ne` 实现为

```python
difference = x - y + w * (1 - 2 * z)
if (z != 0 and difference > 0) or (z != 1 and difference < 0):
    raise ValueError("Customer profile is not an exact Nash equilibrium")
```

`z != 0` 检查第一家在支持中时不更贵；`z != 1` 检查第二家在支持中时不更贵。真混合同时触发两项，平局则允许纯选择或混合。这不是只检查真混合者。

## 10.3 怎样检查设施的完整搬迁目录

**定义 10.4（倍率达到证书）。** 给定实例和 $\alpha\ge1$，证书指定一个在轨布局及客户 NE，并为每家设施到每个其他合法地点的实际单边偏离指定客户 NE。偏离时只修改该设施的布局坐标。若其在轨收益为 $L_f$、偏离续局收益为 $L_f'$，每项必须满足

$$L_f'\le\alpha L_f.\tag{10.3}$$

共同目录 $m$ 地点、$k$ 家设施有 $k(m-1)$ 项实际偏离。“再选原地点”不计偏离；两家同时换地点也不计单边偏离。零在轨收益仍必须按 (10.3) 检查；它要求偏离收益也为零，不能因比值无法计算而省略。

每个偏离记录都应恰好出现一次。遗漏一个地点，就没有检查完整设施条件；多写同一偏离也不能弥补遗漏。在任意设施数程序中 `facility` 使用 $0,\ldots,k-1$；双设施证书的 `deviator` 使用 1、2，因此访问负载列时分别用 `f` 和 `who-1`。

**例 10.5（四个布局可以全部手算）。** 仍取 §10.1 的两地点三客户输入，现有两家设施。在轨布局取 $(0,1)$，权重 3 客户纯选第一家，所以收益为 $(5,5)$。下面给整个四布局的续局。表中概率是选第一家的概率；“未覆盖”表示概率行全零。

| 带标签布局 | 权重 2 客户 | 权重 3 客户 | 权重 5 客户 | 两家收益 |
| --- | --- | --- | --- | --- |
| $(0,0)$ | $1/2$ | $1/2$ | 未覆盖 | $(5/2,5/2)$ |
| $(0,1)$ | $1$ | $1$ | $0$ | $(5,5)$ |
| $(1,0)$ | $0$ | $0$ | $1$ | $(5,5)$ |
| $(1,1)$ | 未覆盖 | $1/2$ | $1/2$ | $(4,4)$ |

异址时，公共客户留在地点 0 的成本为 $2+3=5$，改到地点 1 的成本为 $5+3=8$。同址时两家都只影响客户的标签选择，独立对半使每名客户的两个条件成本相同。第一家从在轨地点 0 改到 1，得到 $(1,1)$ 中的收益 4；第二家从 1 改到 0，得到 $(0,0)$ 中的收益 $5/2$。二者均不超过原收益 5。因此这一张表给出完整倍率 1 证书，不只给出一项局部 NE。

## 10.4 没有逐条列出的布局使用什么规则

证书可以是完整表，也可以是“在轨条目、实际偏离条目、所有其他布局的确定默认算法”。默认算法必须真的返回 NE，不能写一句“任选一个”而不给可执行规则。

**规则 10.6（共同目录双设施默认续局）。** 对任一尚未列出的布局，独占客户选其唯一可达设施；所有公共客户先纯选第一家。重算两家负载 $X,Y$，然后反复执行：若 $X>Y$，在仍处于第一家且满足 $w_i<X-Y$ 的公共客户中选最大权重者，并列时选最小客户编号，移到第二家。第一次负载次序反转或相等、或已无严格改善者时停止。

为什么停下就是 NE？每次搬迁是严格改善，差距绝对值严格下降。反转以前第二家处于低负载侧，没有在那里客户愿意去高侧；第一家若无人满足 $w_i<X-Y$，也没有改善。若最后一次搬迁造成反转，新差距小于该客户重量，而此前移动者都不比它轻，因此第二家上的所有公共客户仍稳定；原第一家的客户现在在低侧，也稳定。这还给至多每名客户移动一次的步数界。

双设施独立检查器要求 `default_continuation` 精确指定此规则，并在每个剩余带标签布局重算其输出和客户条件成本。`family`、菜单计数、响应环文字只解释构造来源；检查器不凭这些字段认证证明。

**规则 10.7（任意设施数默认续局）。** 对任一尚未列出的布局，每名被覆盖客户先选最小标签可达设施，未覆盖客户标为 `-1`。然后按客户编号扫描，找到第一个有严格改善的客户；在其其他可达设施中选当前负载最小者，平局选最小标签。若 $L_g+w_i<L_f$ 就搬迁，重新扫描；若全部客户都无严格改善则停止。

第 04 章势函数证明这个过程有限终止并返回纯 NE。它没有一般位长多项式迭代界。规则中的扫描顺序和平局顺序使每个未列布局的输出确定，而不只是证明该布局存在某个 NE。

`evaluate_continuation` 先查在轨布局，再查实际偏离条目，其余才执行规则 10.7。因此紧凑证书确实定义整个 $m^k$ 布局空间的续局，虽然没有将它们全部存盘。

## 10.5 构造器怎样产生证书中的条目

共同目录双设施程序先在每个布局构造第 02 章的有限客户 NE 菜单。每个菜单条目先经精确条件成本检查，才可登记。程序在各有序地点对取偏离者菜单收益极小值，形成菜单威胁，再扫描在轨候选并比较全部设施偏离。这是可快速计算的足够续局；它没有枚举全部客户 NE，因而较小的输出倍率也不等于已经求到实例最优。

任意设施数 `search_lexmax` 则真正枚举所有物理占据和可行站点纯分配。设地点 $s$ 有 $q_s$ 家设施、分给该站的总客户重为 $W_s$；每家在轨收益为 $W_s/q_s$。程序把**每家设施** 的收益写入向量，从小到大排序，再按字典序最大化。代码

```python
key = tuple(sorted(mass[s] / len(groups[s]) for s in layout))
```

遍历 `layout` 的各设施坐标，所以一个三设施站会写入三次同样收益，绝非每站只记一次。只枚举排序后的占据不会损失目标最值，因为设施标签置换不改变这个排序向量；输出仍恢复完整带标签布局。

求出字典序最大在轨状态后，每项偏离按第 03 章的证明构造离轨纯策略。设偏离设施原收益为 $a>0$。客户先按原池重新分给仍在原地的设施、或新偏离设施；各站客户池按 $2a$ 装箱，超过 $2a$ 的客户单独放一箱。然后做严格纯改善。普通设施上的客户当前成本不超过 $2a$，加入一个孤立超重客户所在设施后的成本却大于 $2a$，所以不会向它移动。超重客户自己的成本已经是仅含自身的重量，也不可能靠移动取得严格更小成本；普通设施之间的严格改善不会超过帽。因此偏离者最后收益不超过 $2a$。若所有地点的 reach 都为零，所有客户在每个布局都未覆盖，概率全零、设施收益全零，直接得到完整倍率 2 证书，不进入正 $a$ 的分池与装箱。若存在一个正 reach 地点，把全部 $k$ 家设施放在那里并把它覆盖的客户分给该站，就得到每家收益 $R/k>0$ 的可行候选。字典序最大首先最大化最小收益，故所选状态的每家收益也为正，才可使用上面的 $a>0$ 分支。分池质量预算、每站至多 $q$ 箱及偏离者初始质量至多 $a$ 的理由见第 03 章完整证明；本章不把这些断言改成“因为程序中有 assert”。

| 任意设施数字段 | 数学对象 | 重新核验的内容 |
| --- | --- | --- |
| `on_path.layout` | 在轨带标签布局 | 每个地点合法，设施坐标完整 |
| `on_path.site_assignment` | 客户的物理站点纯分配 | 被覆盖者分到可达已占站；与均匀概率转换一致 |
| `on_path.probabilities` | 在轨独立概率矩阵 | 合法性与命题 10.2 |
| `deviations` | $k(m-1)$ 项实际偏离的纯策略 | 一项不漏且不重复；各为 NE；满足 (10.3) |
| `default_rule` | 规则 10.7 | 实际求值结果满足 NE |
| `factor` | 所给倍率 | $\alpha\ge1$，每项线性收益不等式成立 |
| `search_audit`、`complexity` | 搜索计数与方法说明 | 是该次运行记录，不是一般复杂度证明 |

有限全局穷举落实了存在性证明中的选择，但其候选数可指数。`site_allocations_evaluated` 的一个小数值不能改变一般算法的复杂度。

## 10.6 独立检查器认证到哪一步

任意设施数的 `tests/multi_facility/definition_check.py` 不调用构造器的 NE 核心。它先检查概率行的合法性，再直接实现

```python
costs = {f: w[i] + sum(w[j] * p[j][f]
         for j in range(n) if j != i) for f in accessible}
minimum = min(costs.values())
assert all(costs[f] == minimum for f in accessible if p[i][f] > 0)
```

这与 (10.1) 逐项对应。`check_certificate` 随后核对全部实际偏离，并执行 (10.3)。`all_layouts=True` 对未列布局独立穷举纯均衡，检查**存在某个** 可补续局；它不直接检查构造器默认算法实际选出的那个策略。若要验证所指定完整规则，必须逐个调用 `evaluate_continuation`，再用独立 `check_ne` 检查返回策略。

两设施 `facility_spe.cli.verify_phi` 则从原始覆盖输入重算每个条目，还对默认布局执行规则 10.6。它同时精确检查 $\alpha\ge1$ 与 $\alpha^2-\alpha-1\le0$，从而认证所给有理倍率不超过黄金比。二者通过检查，都只认证该实例达到所给倍率；实例最优还需要完整谱的下界证明，普遍存在性还需要对任意输入的数学证明。

## 10.7 可以自己重放的完整检查

从仓库根目录用 Python 3 运行。构造器只用标准库。输出文件名应是尚不存在的新名称；任意设施数入口拒绝覆盖已有证书。

```sh
mkdir -p study_outputs
python3 -m facility_spe.shared_phi \
  examples/shared/tiny.json \
  --output study_outputs/shared.json
python3 -m facility_spe.cli.verify_phi \
  examples/shared/tiny.json \
  study_outputs/shared.json
python3 -m multi_facility_spe \
  examples/multi_facility/rational.json \
  --output study_outputs/kfac.json
```

随后用 Python 执行以下代码，既检查偏离证书，又检查完整规则实际选出的每个续局：

```python
import json
from itertools import product
from pathlib import Path
from multi_facility_spe.two_exists import evaluate_continuation
from tests.multi_facility.definition_check import (
    check_certificate,
    check_ne,
)

cert = json.loads(Path("study_outputs/kfac.json").read_text())
print(check_certificate(cert, all_layouts=True))
inst = cert["instance"]
count = 0
for layout in product(range(inst["m"]), repeat=inst["k"]):
    p = evaluate_continuation(cert, layout)
    check_ne(inst, layout, p)
    count += 1
print("chosen continuation checked at", count, "labeled layouts")
```

该输入有 3 地点、4 设施，所以最后循环检查 $3^4=81$ 个带标签布局；在轨的实际偏离有 $4(3-1)=8$ 项。读输出时，先取一个概率行按 (10.1) 手算，再取一个偏离按 (10.3) 手算，最后检查一个未列布局如何执行默认规则。这样每个程序字段都有独立的数学含义。

通过这次有限核验，得到的是这个输入的完整达到证书。它不代替任意输入的存在性证明，也不解决任意设施数的一般高效构造问题。
