# 09 研究工作坊：人类团队如何从学习转到探索

人类团队的任务是重新判断结构、量词和路线，而非只是检查程序是否跑完。现有结果不保证下一条路线会成功，也没有证明一般因子 2 算法不可能。第 13–14 天先产出少量可判断的研究卡，随后再展开实现。

## 先固定总目标

输入是共同目录、显式设施标签、任意 (K\ge2)、任意正二进制有理原子权和显式可达集合。输出包含纯设施布局、一个精确独立客户在轨 NE，以及完整续局的可计算描述。每个一步设施偏离收益至多在轨收益的 2 倍；总运行时间和中间数位长都必须关于联合输入长度多项式。

因子 2 存在性已在内部证明层闭合；本轮主攻是计算构造。不能通过改客户模型、改成可拆分、只处理条件类或把有限枚举称作多项式来完成原目标。

## 发散阶段不要预先锁死盒路线

先让每位成员独立写 2–3 个想法，再共享；第一轮只讨论机制和可能杠杆。可以从以下入口起步，也可以提出不同结构：

- 保留贪心布局，构造与偏离控制兼容的精确原子在轨 NE；完整盒是一种已知充分条件。
- 保留贪心信息而放宽盒，用原池重置、强制背景或只限制偏离者来生成续局证书。
- 改变选址机制，同时维护客户激励和设施预算，避免先造布局再用不兼容规则修复。
- 针对最窄的混合重数、异轻权、至少三占站部分交叠研究结构，提炼可推广交换或分解；一个新条件类只有揭示新机制时才值得主攻。

本阶段允许未证明的直觉，但须标为猜想，不进入现行命题账本。20–30 分钟后，再用必要障碍筛路线，避免一开始只围着旧规则做补丁。

## 每条路线填一页研究卡

| 项目 | 要写出的具体内容 |
| --- | --- |
| 输入与目标 | 原模型还是明确受限类？构造哪一个对象？最终接到总目标哪一步？ |
| 新机制 | 一两句说明与现有预算、交换、重置或冻结接口相比新增什么 |
| 已有前提 | 命题编号及适用条件；每项是否对任意输入成立、可否有效检查 |
| 关键未证步 | 一个带量词的引理；不要写成“找个好均衡” |
| 进展证书 | 成功会给出完整证明、条件证书、复杂度界，还是有限反例？ |
| 最早否定方式 | 具体小实例、分支或不等式；失败将排除什么，不能排除什么？ |
| 时间界 | 状态数、迭代次数、每步计算和位长分别如何控制？ |
| 两天内的动作 | 手算一个尖锐边界、证明一个交换、精确验证一种候选；结束条件写清 |

选不超过三条路线进入后续一周。研究卡中缺失的关键前提优先于扩写代码和整理更多截图。

## 互审只带五个检查问题

1. 它是否还是原子、独立、精确客户 NE 和完整续局的模型？
2. 好状态是否存在，算法是否真的选到；所控制的预算是否与客户 NE 同时成立？
3. 是否只证明了一个选择器不好，却把结论写成所有布局都不好？
4. 运行时间是否关于数值或状态数，遗漏了输入位长和分数位长？
5. 离轨要求是否比总目标更强，是否可以只控偏离者而保留其他设施超载？

这五问来自 [第 06 讲](06_frontier.md) 的机制，不必附上所有旧反例。若要声称困难性，额外说明归约的准确搜索/判定问题；精确最优 oracle 的困难性不会自动传给所有近似构造。

## 数学与实验怎样协作

先写公式、前提与预期性质，再用整数/有理精确算术验证。反例必须核查真实逐席贪心初态、完整可达表、每步严格改善以及最后精确 NE；需要否定整个布局时还要覆盖全部 NE。程序帮助寻找和核验，不能替代全输入证明或迭代上界。

有价值的发现遵守 [研究进入规则](../research/GROWTH.md)：候选放问题页，可审证明放现行层，测试/输入/证据各自归位。教会一条旧定理不算新增数学结论；一条路线失败也要记录它准确排除的量词，而非仅留下大段运行日志。

## 研讨会结束后的三项实际交接

团队交出一张主定理依赖图、一份未理解/待外部审查的具体公式清单、至多三张研究卡。报告人负责补齐自己未覆盖的分支；质询者复核补充。若基础关未过，先补课；若研究卡未找到新机制，暂停扩建技术枝条，重新讨论选址和偏离控制。
