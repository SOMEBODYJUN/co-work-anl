## 当前条件决定的实现边界

用户目前使用手动开启的独立 Work 对话。一个这样的对话有一个对外发布身份，其主 Worker 组织内部 subagents、汇集交付物、执行本 clone 的 Git 写入并与其他同级 Worker 交流。这是本版的操作约定；不能从“子 agent 可能共享工具”推断它已经获得另一个独立、持久、可由人类直接管理的 Work 对话。

必须逐次说清“创建”指什么：

| 对象或动作 | 当前怎样完成 | 完成时能声称什么 |
|---|---|---|
| Work 界面的新对话、新界面 Project、重新触发已结束的对话 | 用户手动操作；目前所检查程序没有对应控制接口 | 用户实际打开并发起工作后，才能登记该对话已参与 |
| 仓库中的逻辑 Project、研究存档、路线和材料入口 | 已运行且有写入权限的 Worker 可以创建目录和文件 | 研究现场的文件已建立；不代表有新模型正在执行 |
| 当前 Worker 的内部 subagent | 由该 Worker 在平台实际允许的能力内创建、通信和汇集结果 | 本次委派存在；不代表它成为独立 GitHub 发布者或永久房间 |
| 公屏讨论话题、收件记录、待办请求 | 程序或 Worker 写入记录 | 请求已保存；对方看到、理解、生效需要另外的证据 |
| 逻辑角色接续 | 用户恢复原对话，或另开对话并交给接续材料 | 同一职责或研究节点继续；不承诺恢复旧模型进程的内部状态 |

上述边界适用于当前部署，不宣称所有 OpenAI 产品都不具备其他能力。OpenAI 官方文档描述内部子代理和独立的 App Server thread/turn 接口；**有可开发接口，不等于现有 Work 对话或本仓库程序已经接入该接口**。[官方子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)；[App Server 文档](https://learn.chatgpt.com/docs/app-server)。

本版可组织长期研究、保留职责和接续现场；它没有总稿中的完整运行控制、持续调度和权限隔离。不能因此删除总稿相应目标，也不能用同名文件冒充这些能力。

## 把原设计映射到当前载体

以下路径都是**拟新增的组织入口**，尚未创建；现有数学资产继续使用既定位置。当前仓库先对应一个逻辑 Project，不要求每个研究存档另开 GitHub 仓库或 Work 界面 Project。以后多 Project 时再显式选择同仓分区或独立仓库，不能把文件夹当作权限边界。

| 原设计对象 | 本版建议载体 | 关键内容及边界 |
|---|---|---|
| Project | 仓库总入口与现有共同登记 | 共享数学对象、材料入口及协作约定；界面 Project 与逻辑 Project 分别记录 |
| Research Save | `collaboration/saves/<save-id>/README.md` | 原始意图、当前目标、原始材料指针、路线、Frontier、基线提交、采用的对象版本和恢复入口 |
| 长期 Scaffold | 存档入口、路线记录与可生成的关系视图 | 记录派生、会合、改向、暂停；存档并非必须组成单根树 |
| 数学对象与超边 | 现有正文、精确账本、review_status、assets、graph | 关系写完整数学含义、角色、版本、前提和异议；不另造一套真值账本 |
| Worker | `collaboration/workers/<worker-id>.json` | 对应用户实际打开的对话；登记职责、参与存档、最近报告、接续关系；不含认证秘密 |
| 内部 subagent | 主 Worker 的阶段报告与来源记录 | 记录必要任务、材料、返回物和实际委派来源；不逐个登记为公屏独立发布者 |
| 研究行动 | 有必要时在存档下建立有界行动记录 | 保存目标、材料、验证与结束条件；普通数学动作不强加对象层级 |
| 请求与回执 | `collaboration/actions/<action-id>/` | 原话、目标、各项执行结果、未执行原因及接续入口；需要补程序，非现有运行接口 |
| 对外交流 | 复用现有公屏程序，扩展明确范围 | 普通讨论与成果/纠正通知分别展示；消息本身不是正式数学事实 |

存档入口只引用已有资产，不复制整套证明。当前目标可以不同，数学对象可以共享。共享对象并不强制合并存档，文件路径改变也不改变对象身份。

历史世界线建议固定其采用的对象 revision，另保存“已知的新纠正”。收到纠正不自动改写历史快照；旧条件下的结果也不能继续无条件对外使用。最新头、显式吸收与失效通知的精确协议仍是原稿未决项，须在对应功能施工前闭合。

## 人类代理者、仓库维护者和研究者怎样工作

总稿已经明确 Human Proxy 是操作者；上一轮将其说成管理评审者的扩权不能保留。同时，人类确实需要 AI 承担仓库维护。当前可以由同一个已打开的管理 Worker 承接操作与维护职责，但必须说明本次执行的是哪一项职责；兼任不等于获得独立判断数学真假的权威。

| 职责 | 当前可执行的工作 | 碰到超出职责的情况 |
|---|---|---|
| Human Proxy | 理解操作范围，整理请求，移动/路由材料，创建文件入口，执行当前确实可执行的操作，逐项返回回执 | 跨 Work 启动、停止和唤醒不可执行时，生成用户可直接使用的启动或继续材料，并明确待人工操作 |
| 仓库维护 | 检查增量与失联资产，整理可读正文和命名，修复入口及引用，维护真实地图，核对提交范围，commit/push/确认 | 数学等价、真假、贡献与删除价值先交专业调查；不能凭外观合并或删数学资产 |
| Project Director | 从公开 State、公屏和警报发现组织问题，向适当专业者询问建议，按建议组织 | 不读全项目私有聊天；咨询可由本 Worker 的子任务完成，需要新独立 Work 对话时请用户打开 |
| 同级研究 Worker | 自主选择方法，可同时研究多线或同题，组织内部研究/审查，交流并保存真实阶段资产 | 无中央排他认领，无固定岗位流水线，无保证运行时长；新重大结果按实际义务接受独立攻击 |
| 验证、价值、仲裁、星探、拾荒等职责 | 有任务时由已运行 Worker 或其内部子任务承担，保存针对精确版本的报告 | 文件中登记该职责不代表它正在执行；当前需要更强独立性或新会话时由用户手动开 |

“常驻”在当前版能实现身份、职责、材料、检查游标和接续入口长期存在。主动巡视只能发生在该 Worker 实际运行期间；对话结束后不能承诺它仍在后台看仓库。恢复后先读自上次基线以来的增量，而不是重新吞下所有聊天。

维护不应把研究者变成只填表的执行员。普通 idea 可以直接讨论，达到可接续程度的候选可以按候选保存，正式状态提升另走匹配的检查。存档或共同登记的编写分工不产生排他的研究权。

## 一次真实操作怎样闭环

假设用户对管理 Worker 说：“从这个观察另开一个研究档，让研究员独立试；暂停旧证明线，实验继续。”

管理 Worker 可以保存原话和材料，建立有来源的存档入口，保留多种数学解释，准备所需的精确定义、当前事实、已证障碍及未决义务。需要展开研究纲领时，询问研究职责并保存其建议，不由纯操作 Proxy 编造数学方案。

如果当前 Worker 自己继续研究，或在自身执行树内开研究子任务，可立即做；如果需要新的独立 Work 对话，它交付可直接粘贴的启动材料和稳定身份/存档信息，用户手动打开。**建立存档已完成、独立 Worker 尚待用户启动**必须分别报告。

管理 Worker 在记录中提出只针对旧证明线的暂停请求，列出实验继续的排除范围。能控制的本次子任务按实际工具处理；另一个 Work 对话需在读取请求后响应，或由用户直接进入该对话干预。未收到停止回执时只报告“已请求／未确认”，不得显示“已暂停”。

另一个 Worker 在实际启动或继续后，同步仓库，核对存档与对象版本，读取针对它的材料并回执。它内部组织 subagents；对外发言和本 clone Git 写入仍由主 Worker 执行。存在重要发现时，先形成可接续资产，按现有规则维护正文、账本、审查与地图，再提交并核验远端。普通讨论无需先完成这套资产流程。

用户需要做的是当前平台没有开放给代理的界面操作，以及真正属于研究偏好的选择；AI 应完成材料准备、路由、整理、核验与保存，不让用户逐个猜文件。

## 公屏、送达和纠正怎样适配

现有公屏已经支持署名消息、话题、回复、冻结资产引用以及失败重试，但没有原生的 Project/存档/收件人/吸收回执语义。不能把正文里写“发给 R2”说成已实现程序投递。

建议扩展消息范围、对象 revision、接收对象、原操作来源、纠正所指消息及接收回执。旧消息保持可读，升级 schema 时显式迁移；不直接给现有严格校验器塞额外字段。普通探索讨论仍允许发送；成果、公屏投影、纠正通知从可靠记录链接，不成为另一套 State。

处理顺序是保存请求、等待接收方实际读屏、接收方核对完整材料并回报用途/冲突/缺失、执行相应动作、返回实际结果。单有消息落盘或推送成功不能跳过后面的步骤。

运行中的 Worker 在启动、阶段交接、准备引用他人成果和正式升级之前读取有关增量。长工具运行时或对话已结束时，不能保证立即读取；紧急事项由用户直接介入相应 Work 对话。没有常驻调度器，就没有跨会话的保证送达延迟。

可靠反例或条件修正需要发布明确 Correction 并查已投递者与依赖者。依赖传播沿数学支持关系，而非只沿委派父子树。多条独立证明中仅一条失效时，先核对其他支持路径；不能机械撤掉整个结论。

## 暂停、旧版本和恢复的实际强度

| 总稿语义 | 本版可做部分 | 当前缺口 |
|---|---|---|
| LIVE_STEER | 当前对话可接收用户介入；主 Worker 在工具支持时给自身子任务发送调整 | 公屏不能直接注入另一 Work 的模型上下文；吸收情况须回执 |
| PAUSE_INJECT_RESUME | 保存边界快照、未完成义务和新材料，收到请求的 Worker 协作停止并继续 | 没有所有 Work、CLI、远端工具及写入的统一暂停控制 |
| HARD_FENCE | 可补“升级前重新检查所依赖版本与撤销记录”的程序门槛 | 现有代码未实现；所有人仍可直接写 main 时，本地门槛可被绕过，不能称强制封锁 |
| 崩溃恢复 | 从已推送材料回到同一逻辑存档、角色与义务，未确认外部动作标未知 | 不能保证重新获得旧 subagent ID、旧隐藏上下文、未保存推导或远程进程内存 |
| 一键继续 | 将来可准备一条接续入口与材料清单，用户打开对话后接续 | 当前不能由仓库按钮唤醒任意结束的 Work 对话 |

建议版本检查只阻止过期依赖的**无条件采用或正式升级**，仍允许保存为候选、历史证据或待重核材料。无关研究文件变化不应让全仓所有任务作废。

如果未来需要真正 HARD_FENCE，必须让所有正式升级只能经过一个受控写入口，并处理远端竞争、撤销与重试；只约定“都运行脚本”不能得到同等保证。共享 main 可以继续保存候选，不必把每次提交变成等候全部评审。

并发修改必须保留双方。Git 文本可合并不证明数学语义相容；同一个 revision 的条件被双方改动时，保留两个提案，交专业核对，不用最后写入覆盖。暂停请求、接收、实际停止、重做和恢复分别记录。

## 验证、价值、文献和材料完整性

总稿的数学职责保留，执行载体改为当前 Worker 的有界任务或用户打开的独立 Work 对话。验证森林可以分批开展，不必让每条验证线都成为独立对外发布者。已知结果、候选、反例、方法障碍、计算覆盖、论文贡献与原问题状态仍要分别记录。

未验证局部引理可以按候选保存并条件性使用；候选版本、条件性下游和临时证伪义务要一起存在。证伪义务已排队不等于证伪者正在运行，更不等于验证通过。需补程序检查缺失义务；当前没有对应事务服务，不把这一约定冒充已经原子实现。

材料独立与权限隔离分开。新子任务应从问题、定义、版本和允许材料开始，避免继承原证明；独立报告提交前不互相透露结论。已经看过证明的同一上下文不能靠“现在盲审”恢复未见状态。共享 clone、共享凭据或可读整个仓库的子 agent 并无强制隔离；要求严格盲区时，给独立对话只提供允许材料，不能同时开放不应读的原证明。监察的出口也需防止跨区泄露。

价值报告应对比最近文献的精确条件、结论、方法、机制和可复用内容，扣除直接推论，保留最强反对意见及后续研究地图。用户当前的高水平论文目标是投入标准；不是“标成高价值”或“题目来自大人物”即可达标。录用与独立成文能力不由程序保证。

文献由问题缺口驱动分线搜索；保存身份、原件版本、完整数学单元、证明材料、准确位置、用途和未核实依赖。原件/基础包可复用，当前 Project 的解释独立。登录或付费材料等请求集中列入待人工处理入口，只阻塞相关路线。没有明确要求就不建立持续论文监听。

专家库与 Project 事实分开。当前可先按任务使用已有可信材料包；总稿提及的旧 SQLite 库没有在本轮拿到，不宣称已经接入或迁移。Working Set/Context Capsule 保存精确定义、量词、版本、障碍、反证、未决义务及回源入口，完整原文按需读取；不让摘要丢掉关键限定。

## 星探、仲裁、拾荒、监察和 Trace

这些研究机制不删去，但必须由实际运行的执行者办理。星探做真实数学比较；等价关系经独立核对后才组织整合。确认等价不等于把存档合并，也不等于删除一方过程；暂停和组建联合工作仍受跨 Work 操作边界约束。

拾荒分析具体失败机制、仍成立局部引理、自然修复条件与独立方向，并接受价值及反驳检查。它可以在执行期间建有来源的新存档文件；需要新的独立对话时，由用户手动开。监察可以检查已保存且在其范围内的外显报告和工具证据，发现遗漏或旧条件；没有跨 Work 遥测时，不能声称实时看见每个执行中的错误。

Trace 应由真实保存事件和精确来源形成委派、研究路线、证据依赖视图。当前只能记录实际可取得的阶段报告、提交和证据；尚未采集的私有窗口、CLI 事件和中断动作标记缺失。不能以最终报告补造“完整实时 Trace”。

收尾时汇集实际产物、少数意见、主问题状态、未决义务、子任务与迟到结果，供人类审阅后决定结束或继续。文件可保留逻辑研究现场，但旧执行进程、所有房间和 CLI 不释放的产品体验当前尚未实现。专业成果签署、后代处置等原稿未决责任仍保持未决。

## 清理与硬删除不能偷换含义

明确的文件整理、引用修复与无价值产物移出当前树可以执行；判断数学低价值、等价或仍被依赖时需要专业依据。专项清理先核验整理稿、完整命题/证明、来源、删除理由及依赖迁移，再处理明确范围。没有证明的候选如何整理、共享 Artifact 如何删等原稿缺口仍需解决。

普通 `git rm` 加一次提交只从当前版本移除文件，历史提交及已有克隆可能仍保留原文。它不能满足“从所有历史与副本彻底删除”的强含义。后一种删除涉及历史重写与副本协调，不能沿用普通 checkpoint，也不能在本轮静默执行。这里保留总稿硬删除目标，明确当前实现缺口，不擅自改回永久留存。[Git 官方说明](https://git-scm.com/docs/git-rm)；[GitHub 历史清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。

## 逐节对应，避免遗漏

|---|---|---|

## 可施工顺序与可复验出口

以下是下一步工程建议，不是声称已经施工。沿用现有 main 和公屏分支，不为每个存档或 Worker 新建研究分支。

| 工作包 | 实际改哪里 | 验收出口 |
|---|---|---|
| 存档与启动路由 | 将 work/board/checkpoint 的旧主题常量抽为共同配置；保留现有入口兼容；新增存档入口与工作集生成 | 同一程序能明确选择不同存档，显示目标/读什么/写哪里；缺失或歧义时拒绝猜旧题；提交默认范围包括实际资产和入口 |
| 身份与接续 | 稳定对话身份、参与存档及接续来源；启动材料可直接使用 | 新对话不冒用旧运行状态；恢复目录丢失时靠登记重建，旧 Worker 未确认终止时保留并发/未知状态 |
| 交流与操作回执 | 给公屏增加范围、接收、纠正和操作关联；保留普通讨论；明确迁移旧 schema | 接收方结束时消息待处理；部分成功逐项可见；重复请求不重复执行同一操作 |
| 仓库维护职责 | 整理现有正文/命名/登记，生成实际可读入口；启动和阶段保存时做有界增量检查 | 主入口能走到精确命题、证明、异议、审查、证据；没有失联资产或漏推送；不创建无意义审计堆积 |
| 协作版本门槛 | 正式采用/升级前核对直接及相关传递依赖版本、撤销和未决异议；候选保存单独处理 | 过期结论不能经约定入口升级；新提交导致竞争时重新核对；无关变更不误阻塞 |
| 独立验证与专业报告 | 为实际候选生成有版本的审查、价值、证伪和必要综合任务 | 记录真实材料独立性、覆盖与反对意见；无空名义团队，不把同一上下文换角色说成独立验证 |

完整桌面产品、App Server 调度、强隔离、强制 State 写入边界、统一工具暂停、所有房间持续可见与全历史硬删除是另外的工程子系统。当前方案不以它们先建成为研究前提，也不宣称 GitHub 文件已经替代这些系统。

## 方案检查的证据与限度

本轮针对现有仓库程序运行本地 Git 回归；针对拟议协议用 Python 枚举代表性的启动/读取/结束顺序，并检查单 Worker、无人运行、跨 Work 暂停、部分成功、独立证明路径、条件性引理、版本竞争和删除范围。实际结果见本节最终核验记录。

这些检查只核对提议中明确写出的规则是否自相矛盾，以及已运行的现有程序在其测试范围内的行为。**未给新路由、回执、版本门槛或后台控制写生产实现，未做跨 Work 界面控制实测，未执行删除。**本轮交付是忠实且可施工的适配规格。

核验记录：原总稿的 30 个二级章节均逐一对应，复制件与上传原件哈希一致。现有协作程序本地回归实际运行 65 项全部通过；该测试套件使用本地 Git 和测试凭据，不代表本轮已运行新的跨 Work 控制。有限回执模型的事件为发送、读取、吸收、执行、结束、人工继续，逐一枚举长度为 5 的 7776 个事件序列并检查每个前缀；另对上述边界场景作确定性断言。模型只检验所写规则，不是待施工系统的端到端实测，不能据此声称自动唤醒、即时暂停或强制隔离已经存在。
