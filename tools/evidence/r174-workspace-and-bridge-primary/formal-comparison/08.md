# 完整历史求解器的规范实现、独立枚举与复现边界

## 实际交付和模型

可运行目录为 [tools/evidence/exact-spe](../../tools/evidence/exact-spe/)，各文件的冻结来源ID、完整提交与SHA-256见 [PROVENANCE.json](../../tools/evidence/exact-spe/PROVENANCE.json)。五个包文件、原始测试和两个JSON依赖均逐字节保留。程序属于[共同目录单位客户模型](../定义/共同目录完整历史模型--定义.md)，不含客户侧NE；目录标签可以覆盖相同集合。理论正确性见[全集递推与证书展开](../算法/完整历史纯SPE终局全集--算法.md)。

`CustomerType` 把正整数重数解释为同类单位客户；`Instance` 拒绝布尔数伪装整数、非整数或负计数、越界主题、重复标签、正人数的空目录。空兴趣类型与空覆盖主题合法。`from_topic_sets` 只创建出现在某主题中的客户；若要保留完全无兴趣客户，需显式给空类型。完全无兴趣客户不改变收益、覆盖或最优值。

`topic_payoffs` 对最终计数求有理收益，未占用主题的返回坐标约定为零，不能把该坐标当作已经执行一次偏离的收益；偏离需要相应完整终局。`optimal_welfare` 枚举至多 $m$ 个不同标签的支持，精确求最大覆盖；不足次数可重复补齐。它没有效率保证。

## 可直接运行

从上述 `exact-spe` 目录运行：

```sh
python3 -m unittest discover -s tests -p test_customer_attraction.py -v
python3 -m customer_attraction examples/customer_attraction/residual_counterexample.json --certificate --output result.json
python3 -m customer_attraction examples/customer_attraction/residual_counterexample.json --verify result.json
```

CLI 的 `--verify` 接受裸策略或带 `certificate` 的求解报告，先做完整定义级验证；生成报告前也验证所构证书。输出已存在时拒绝覆盖。依赖仅Python标准库；精确整数和 `Fraction` 没有固定宽度整数溢出边界，但仍受实际时间和内存限制。源包 `__init__.py` 只导出模型、求解器和证书接口，不需要其他历史搜索脚本。

## 独立oracle的真实量词

原测试的 `direct_ordered_strategy_paths` 枚举有序历史树上的**全部完整纯策略映射**。它把客户重数展开为单位客户，逐行动分支用单位客户定义计算收益，按深度检查每个节点的最佳反应；没有调用或重新写全集递推。有限域是：

- 两主题的三个非空兴趣类型各取重数 $0,1,2$，共27个输入，各测 $m=1,2,3$；其中三人树逐实例枚举 $2^{1+2+4}=128$ 份完整策略。
- 三主题的七个非空兴趣类型各取存在/不存在，共128个输入，测 $m=2$；逐实例枚举 $3^{1+3}=81$ 份完整策略。

共209个输入与14,094份完整策略映射。逐实例比较根终局计数集合和全部可实现有序路径；两主题组还比较非空前缀的子博弈集合，并验证每个返回终局的完整证书。此范围不包括任意客户重数、任意主题数或任意人数。

## 原始11项回归的内容和本次运行

本次从保全后的目录实际执行全部11项测试，通过。运行摘要见 [replay.json](../../tools/evidence/exact-spe/replay.json)。除上述oracle外，测试逐项检查：

- 空、单、重复覆盖目录；零客户、无兴趣客户、零玩家；克隆压缩下终局集合与逐路径收益一致，终局收益总和等于覆盖；含 $2^{1000}$ 重数的任意精度有理收益。
- 大主题家族 $m=1,\ldots,6$ 的all-big路径、最差SPE覆盖 $m$、最优覆盖 $2m-1$ 及完整证书。这里只认证这一有限家族输入；家族名没有给一般上界。
- 同计数历史 $(0,1)$ 和 $(1,0)$ 可以采用不同后续；完整证书覆盖全部离轨历史。
- 三主题三客户路径 $(C,A,C)$ 是SPE但不是同时行动PNE；十四客户五主题证书否定逐人和聚合残余保证。
- JSON证书往返；缺历史、额外历史、错误根终局、违反激励的策略均被拒绝；非法实例、不可实现的指定次序、非法selector被拒绝；CLI正确求解、核验并保护已有输出。

这些是原实现的行为检验与有限复现，不是六人半覆盖的新证明。`verify_certificate` 独立于集合递推，但两者共用规范模型的收益代码；oracle另按逐名单位客户计算，因此其有限对照提供另一实现层的检查。没有新增外部同行审查或世界新颖性认证。

## 来源比较与独有内容去向

`exact_solver.md` 提供完整归纳和规模分析；`model.py` 提供合法输入、精确收益、最优覆盖及大主题家族；`exact.py` 提供全集、路径和证书构造；`certificate.py` 提供独立完整树验证和违规诊断；包入口保留公开接口和CLI；README的上手合同转入本页；测试全文及其两个实际依赖在证据目录保全。没有只保留README摘要而丢弃源码。

后续 `uploaded_tool_audit.md` 的实现比较确认其他工具使用同一全集递推，但其NumPy稠密表和固定宽度整数限制不同；不得拿上传工具的有限反例或随机测试替代本规范包的域。固定策略锥的优化也不等同于枚举全部策略。接续者可直接调用本包重放候选完整策略，若要优化算法则应继续以定义级完整树验证和微小域oracle校验量词。
