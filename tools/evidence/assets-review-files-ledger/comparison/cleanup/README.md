## 第二阶段：读、比较、分类并整理正文

1. 用新版work.py独立clone并读近期公屏认领；`clean list --available`看未领项、`clean claim`正式领取。按prefix领取下一批跳过已领项，`clean list --owner self`恢复本人当前批次；完整来源信息按需加--full。领取范围按数学对象/来源路径，不靠“我看了这个目录”虚称完整覆盖。
2. `clean show ID`读冻结实际文件。PDF/图片/二进制导出后用合适工具读，代码要理解功能和真实输入。只看文件名、摘要、检索命中或旧图不算完成。
3. 查全仓相关对象和后续更新，读实际数学，比较假设、量词、对象身份、证据及差异。原稿声称、内部复核、独立实现、外审和新颖性分别判断；出现冲突追到相关证据，不直接相信较新的README或多数人意见。
4. 按数学对象归档、拆分或合并，保留独有论证。正式Markdown讲清是什么、所有条件、推导/证据、用途与如何接续。未成熟idea仍可留工作室并指明卡点；尚未理解的内容继续处理或needs-decision，不直接退休。
5. 先checkpoint正文与必要依赖；随后done提交逐来源语义处置记录，可单条或批量。只有字段完整且目标已推到结果分支才可勾；记录本身不证明阅读质量或数学正确性。

处置integrated/retained/duplicate/retired均须真实理由；后三者也不能只写“旧/没用/不在主线”。对于学习、历史、稿件和程序目录都要判断独有内容。未完成数学不是清洗失败；未读懂来源不是清洗完成。当前仍有未决来源时不能声称全仓结束。

一源可拆多个对象，多源也可合一正文；因此逐文件勾选和数学对象数量不要求一一对应。底层源版本分母冻结，后来的新材料用独立增量批次登记，不覆盖旧证据。

## 第三阶段：对象、子存档、存档和全仓超图

第二阶段全量语义处置完成后，第三阶段人员读正式对象、必要原始证据和现有关系，逐条建立有解释的超边。它不是把链接列表自动当因果图，也不是把旧1153节点/1353边直接导入。

每边说明参与对象各自作用、共同前提/量词、何种联系、为什么成立、保持条件与精确证据。多前提联合推导保为多源边；推广、反驳、迁移、启发、来源、实现、有限检查各用相应语义。对象可能孤立，不能为连通造边。上游格式和三级投影见[图协议](../map/README.md)。

全仓图包含所有已整理对象，档内图更详细地呈现相应对象和必要跨档边界；稳定ID和正文地址共享，图不复制整篇正文。每个实际数学对象都应被登记到图或有明确暂不纳入原因，每条关系由实际人员斟酌。最终图可有几百条超边，但数量不构成质量标准。

以后每次正式入库新对象时，Boss或其一个subagent做一次关系判断、更新相应投影或说明暂无已知联系；不把此职责变成常驻审批工种，不妨碍自由Solver继续研究。

## 完成判断

第二阶段看源版本是否都有准确、可接续的语义处置，未决/未读不能勾；第三阶段看对象与每边解释/证据是否被实际阅读，三级投影与正文链接是否一致。程序检查不代替数学判断。开放问题可以仍开放，完整模型条件不能被整理省掉。数学Agent及正式Boss提示词等三阶段基础完成后再接入。
