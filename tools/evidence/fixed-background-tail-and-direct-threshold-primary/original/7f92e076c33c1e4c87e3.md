# OPT/(2m) 阈值不能仅由全菜单根尾排序支付

2026-10-24；探索笔记、精确辅助桥反例。一般 Q-CAG-HALF 与父方候选 `DIRECT-INDIVIDUAL-COVERAGE-FLOOR-v0` 均未被本页反驳。

## 被检查的桥

父方正在研究 root 版本：每个空背景完整 SPE 的每位实际玩家是否满足

\[
2m u_i\ge\operatorname{OPT}_m.
\]

另有一个更强的 `PREFIX-DIRECT-v0`：固定原目录和总人数 m，在每个由不超过 m−1 个合法主题产生的背景下，对剩余人数对应的每个完整子 SPE，同样用原目录 OPT_m 定义阈值，要求各玩家收益至少 OPT_m/(2m)。prefix 版本若成立则推出 root 版本；目前没有证明两者等价。

只有对这一更强 prefix 版本，才可按固定总人数 m、允许全部合法背景，对坏例取剩余人数最小的 r，得到如下局面：所有根偏离主题的真实终局中，根收益至多某个 u<t，全部后继收益至少 t，其中 t=OPT_m/(2m)。不能直接从 root-only 版本调用这个跨背景归约。本页只检查**丢弃所有更深最佳回应后**，这组菜单排序是否已经自相矛盾。答案是否。

## 一般环族与精确值

对任意 k≥9，取 k 名不同单位客户 e_0,...,e_(k−1)，下标模 k，共同目录为 k 个主题

\[
A_i=\{e_{i-1},e_i,e_{i+1}\}.
\]

取 m=r=3、空背景。每个根 A_i 配一个抽象终局

\[
L_i=(A_i,A_{i-1},A_{i+1}).
\]

根中央客户 e_i 被三人覆盖，另两名客户各被两人覆盖，故根收益

\[
d_i=\frac13+\frac12+\frac12=\frac43.
\]

任一尾玩家在当前终局有一名三重客户、一名二重客户和一名单独客户，故其收益

\[
v_i=\frac13+\frac12+1=\frac{11}6.
\]

每主题大小为三，所以 OPT_3≤9。主题 A_1,A_4,A_7 两两不交（k=9 时同样成立），覆盖九名客户，所以 OPT_3=9。因此

\[
\frac43<\frac{\operatorname{OPT}_3}{2\cdot3}=\frac32<\frac{11}6.
\]

所有根同时满足上述更强 prefix 候选的最小坏例归约所得的根/尾阈值排序。这个论证覆盖全部 k≥9，有限程序不承担该量词。

## 为什么必须保留真实更深最优性

在有序历史 (A_i,A_(i−1)) 后，指定末位 A_(i+1) 的收益是11/6，但合法主题 A_(i+3) 与两项已选主题的并集不交，给末位收益3。因此该菜单的每个根分支都明确违反一个更深真实节点的最佳回应。它不是完整 SPE，不是 direct floor 或 half 反例。

此实例直接改写既有 `R-cd789330fc7141299ac491bbb3ffa420/global_mechanism/cycle_threshold_obstruction.md` 的二窗口环机制。旧二窗口环 m=3 根收益1、OPT_3/(2m)=1，不能严格击穿父方新阈值；三窗口改写专门补足这一检查。不认领环构造、模型或一般反例机制的全球新颖性。

## 实际核验

`audit_opt_threshold_cycle.py` 不导入规范 SPE oracle 或优化器。它使用 Fraction，在 k=9,10,11,12 上对所有根检查三位份额，枚举全部三主题组合得到 OPT_3，枚举每个末位全部合法动作得到最大收益3，并核验明确远处行动 A_(i+3)。冻结结果见 `opt_threshold_cycle_audit.json`。

核验和辅助负例只明确了需要保留的真实后继最优性，不能计作一般正面推进。后续工作应给出使用这份最优性的新增通用支付关系。

`/root/general_proof/potential_attack` 在只收到陈述后独立逐客户核对了4/3、11/6、OPT=9及末位改选得3的四项结论，并确认这只是否定松弛桥。该审查不涉及全历史 SPE，因为本页从未主张此菜单为 SPE。父方另明确了 root 与 prefix 两个候选的量词差别，已按该修订保留。
