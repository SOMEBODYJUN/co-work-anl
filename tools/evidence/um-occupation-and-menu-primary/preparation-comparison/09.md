# 2. 闭环构造与一般证明要点

初始调度 `S0,S1` 的 root 负载分别为 `1-c/2` 与 `b+5c/4≤1`，其余负载为 `a` 或 1。若 `Cmax<1`，所有 `g` 都不能使用时间 1 的第二端点，root 单靠 `g` 的负载已为 `2b+c/4>1`，所以 `OPT=1`；`x` 是完整实际最优调度的显式凸组合，所有有限边质量严格正。

处理时间组严格分离为 `g_k>g_0>ordinary tiny>ordinary tail>special tail`；组内平局只出现在普通 tiny/tail，不改变坏分配。槽数恰为 `n`，任意覆盖匹配必须占满所有槽，因此每个 home 恰接一任务。每个环相邻迁移 bit 由
\[
z_{\ell-1}+(1-z_\ell)=1
\]
强制相等，所以每环全开或全关；这只是覆盖匹配的结构，不冒称其他实际调度均有该形式。

任意最小成本匹配至少开启特殊 tiny 环或 macro 环；整环成本增量严格为正，特殊环增量严格最小，显式坏匹配达到该增量。因此所有最小成本匹配只有一个实际机器分配，无需槽级匹配唯一。对所有 `Cmax≤B` 的实际调度，bit 只能非减；若不新迁出任何原留 root 的 `g`，特殊环保持或回退会令 root 净增至少 `delta-c/4>0`，其他环的非空后缀也向 root 严格加 `c`，故唯一不超 `B` 的是原分配。

新激活普通 tiny 环改变 `d+1` 个原始任务，端点同时达到两界；root 新负载为
\[
2-\frac4k+\frac{7}{2k^2}>1,
\]
下降量 `delta-c>0`。`k=3,d=1` 不退化：一个环仍由两个不同任务和两台不同机器组成。参数可用 `4k²` 分母表示，构造和证书按显式输出位长为多项式；没有一般实例的局部最优性判定器、近似算法或 hardness reduction。

# 3. 有限审计与独立覆盖

独立程序 `tests/audits/unrelated_machines/optimal_hull_closed_cycle_reviewer.py` 只用标准库与 Fraction，逐件重建两个端点，枚举全部带标号二进制分配；另从最优凸组合重建正区间交长槽图，用 subset-DP 求最小总处理时间匹配并保留全部最小成本机器分配，不依赖正文的环化简。记录参数 `(k,d)=(3,1),(3,2),(4,1),(5,1)`，完整分配数为 1,024、16,384、8,192、65,536，总计 91,136；每例均得 `OPT=1`、坏峰值为 `B`、两种最小支持均为 `d+1`，最小成本实际机器分配数均为 1。

另对 `(3,1)` 与 `(4,1)` 穷举普通 tiny/tail 的全部根排序平局次序（12 和 144 种），槽图仍给出唯一且相同的最小成本实际机器分配。有限运行记录位于 `evidence/runs/unrelated_machines/optimal_hull_closed_cycle_audit.json`；这是独立审计，不代替无界证明。

# 4. 单任务逐步逃逸的精确阈值

补审身份为 `UM-CLOSED-CYCLE-SINGLE-JOB-ESCAPE-THRESHOLD-v1`。在同一实例与 sigma 上，允许中间任意恶化、任意长路径，只要求逐步改变一件任务并最终落入最优调度集合，则最小可能峰值恰为
\[
B+c,\qquad c=1/k^2.
\]

按原 sigma 穷尽第一步：inactive 环的根或内部非尾任务前移会产生至少 `1+a`；inactive 环尾任务前移到 root 恰为 `B+c`；active 特殊环根回 root 为 `B+delta+c/4`；active 环任意 `e` 回 home 会使该 home 同时得到时间 1 与 `a`。差值
\[
1+a-(B+c)=\frac{4k-5}{2k^2}>0,
\qquad
\delta+c/4-c=\frac{k-7/4}{k^2}>0
\]
保证任何离开 sigma 的单任务路径峰值至少 `B+c`，不要求路径单调，也不要求预先指定最终最优状态。

上界按顺序激活普通 tiny 环：先把尾任务送 root，再逆序把各 `e` 送下一 home，最后把根任务送首 home。每环只在 root 暂时增加 `c`，其他 home 至多 1；完成后 root 降 `delta-c>0`。首次峰值恰 `B+c`，以后递降，最终到 `S0`，步数为 `(k-1)(d+1)`。独立程序 `closed_cycle_escape_independent.py` 在 `(3,1),(3,2),(4,1)` 的完整带标号分配超立方体上用 bottleneck Dijkstra 到任一 `OPT=1` 状态，三例均精确得到 `B+c`，并核对显式路径。

# 5. 量词、cactus 限制与固定 k 推论

新增 §11.4a、§11.5 和 cactus 限制的整文件 SHA-256 为
`202bd695916a008daa5b4b054576a2eb667e4ccfbc6e1bb2ea019bb69147bfd0`；最终正文 SHA-256 为
`ba5d9763aca26d9b8fee7b49f353c3588291fbd94d89f111e77a23808fe41fc5`。量词已修正为“从 sigma 到最优调度集合的全部路径中取最小峰值”，而不是对任一预先指定的最优终点逐一声称已有证明；上界给出 `S0`，取最优终点集合的最小值正是闭合结论。

固定 `k` 时 `m+1=(k+1)(d+1)`，参与机器数恰为 `(m+1)/(k+1)`。先固定足够大的 `k` 再令 `d` 增大，任何 `o(m)` 参与机预算最终不足以从 sigma 以不增最大负载动作启动；`k` 必须在 `m` 增长前固定。逐环机器多重图是共享 root 的 cactus，`d=1` 时 tiny 根/尾任务形成两条带标签平行边的长度 2 环。读取 `cactus_configuration_gap_and_block_exactness.md` 的 `UM-TWO-CHOICE-BLOCK-RANK-EXACT-v1` 合同后，块秩 1 落在其参数范围内；这只说明兼容性，不扩大为所有 cactus 配置 LP 的精确性。
