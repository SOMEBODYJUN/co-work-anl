# 2. 外部配置质量与正向转换

每个外部配置中至多有一个 `F` 保持质量 `Q`，且该质量等于外部任务质量；因为 `v` 配置均为真子集，外部任务质量至少 1。正向其实只需 `Q≥1`：若配置含多个 `F`，可先删去全部 `F`，再保留一个最小值任务。这里 `Q` 是该转换接口的充分证书，不是所有可能方法的必要条件。

普通边保留强制质量；新 `e` 边必须从指定机器优先选 mass 1。普通顺序若选错机器，独立负控得到目标质量 0；指定机器优先后得到质量 1。重复配置在主转换中必须合并其质量，不能用 dict 覆盖相同配置。初始共同分母 `D` 足够，转换只做加减与 min，不发生迭代分母相乘；因此“配置点转换位多项式”须相对于显式矩阵和证书总编码长度理解，不提供通用配置 oracle。

# 3. 逆向可行性、拆分与 probe 边界

逆向使用 `argmin` 和补集分布恢复一个可行性证书，但不承诺恢复全部原始单边 probe。两机小例已精确枚举合法配置验证这一差别。每步全局至多一次 split，支持界为
\[
S-S_v+1,
\]
其中 `S` 是当前支持规模、`S_v` 是被收缩的 v 配置支持；正向只做有限加减，逆向一行合并至多 `|F|` 个遗漏任务，且总量 `Σ|F|≤n_initial+m`。

稀疏族端点 `F` 的外部域不交；`k=3` 时左右任务不交，共享 `t2` 不破坏该条件。终态保留全部 terminal three-unit 任务，core 含一个 unit 入任务与 `k` 个 small 项；`z` 的微小任务数不变，因此不剩余极小星。精确 OPT 下界用 `T` 恢复，上界用阈值 `θ` 再次正向压缩，两个方向各有独立凭据。

# 4. 有限实现、边界与主研究者核对

规范独立实现 `tests/audits/unrelated_machines/star_configuration_transfer_independent.py` 只导入旧 instance/certificate generator，不调用旧 verify，也不导入主转换。它自写矩阵收缩、全局 greedy、强制边祖先跟踪、逐配置负载/归一、逐任务覆盖、强制边、大任务基数、支持增量和无极小星检查，并包含 k3 H5 全部最终有限边、缺失互斥反例、逆向 probe 反例和指定优先序负控。主研究者另外从外部占用质量重建正向证明，以补集分布重建逆向证明，核对当前互斥、指定机器优先和批量支持不累乘。

主程序在合并重复证书列后执行转换，并检查 zero/空 `T=0` 无规则、有理一次 split、指定机器优先、缺占用拒绝、完整逆恢复和旧整数上界压缩。最终 1,778 条有限边（其中 972 条替代任务边）均实际核验。序列化终态矩阵和最高 z 配置负载条件点从 JSON 逐行重算：行归一、配置容量、大任务槽、全任务覆盖、强制边质量 1、整数上界 5/3 和无规则均通过。具体输入/证书 hash 与软件版本保存在 `star_configuration_transfer_audit.json`；旧冻结证据未改写。

有限范围仅为 `k=3,H5`，没有展开一般 `k`，没有求通用配置 LP，也没有实现一般近似算法或统一 epsilon 声明。两套实现共享旧 instance/certificate generator，并非独立原始数据源。
