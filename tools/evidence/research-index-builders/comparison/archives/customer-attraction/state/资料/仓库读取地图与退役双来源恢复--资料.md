# 仓库读取地图与退役双来源恢复

## 资源用途及其不承担的证明

这三份冻结入口回答如何找实际数学、保存半成品、同步受影响入口及恢复退役来源。它们没有给新的客户实例、SPE、核表示定理、调度算法或复杂度证明。本资源保存其独有合同；载体位于CAG存档是旧主攻的历史位置，下面五研究线及退役候选不因此成为CAG的子模型。

三主源均全文实读。两套退役来源的README仅作**额外入口比较**，也全文读了；其指向的候选正文、程序和输出没有因读索引而被自动审读或done。旧“59条候选”、旧审计计数、角色数或日期都是来源快照内的描述，不是本树当前进度或已完成数量。主源与旁读范围、SHA和来源路线见[证据包](../../../../tools/evidence/repository-guide-primary/README.md)。

## 分层读取：先确定问题，再选证明和证据

旧总目录把研究链写成“模型→精确目标→逐范围成果地图→当前义务正文、实际审查、证据”。根README是短总览，本题短入口是读取路线，数学README是逐文件地图，catalog是名称、用途和读取条件的检索登记；这四层不是四套重复证明，也不互相产生真值认证。精确账本管身份，五轴审查管实际审查层次，资产合同管文件及接口，关系图管声明的依赖；地图和自动结构检查都不是数学真理来源。

旧总目录首段列一般证明工作稿、成果总账、SYNTHESIS和全部个人区恢复索引；生产指南同时明确不默认展开长总账、全部个人区、公屏历史、工具源码或每份JSON。可接续的读取方式是：先从短入口和模型确定精确义务，必要时查总账或恢复索引定位相关片段，然后读承重正文、对应版本审查和实际证据。**看到索引链接不等于要把所有工作区作为默认前置材料，更不等于这些材料已经被读过。** `general_half_proof.md`的工作稿名称也不把一般目标改成已证。

旧页“只做一般目录任意人数、不继续特殊范围”的主攻安排属于当时语境。现行AGENTS将当前焦点定为恰六名单位提供者、一般有限共同目录、每份完整有序历史纯SPE的$2W\ge\operatorname{OPT}_6$；任意人数仍是父问题。旧角色、main/wcg-board、默认存档和R-UUID规则不覆盖当前显式Boss编号、结果分支或三阶段清洗规则。

## 总入口的五条独立研究线

| 入口研究线 | 实际对象及读取边界 |
| --- | --- |
| 顺序客户吸引 | 有限单位客户、共同主题目录、单位提供者依次观察全历史、客户价值均分，目标量化每份纯SPE；一般及恰六人任意目录目标仍开放，五人和极大覆盖结构结果分别按精确scope读。实际模型见[完整历史定义](../定义/共同目录完整历史模型--定义.md) |
| 不相关并行机 | 非负有理处理矩阵，要求统一常数改善及实际不可分调度的确定性位多项式输出；一般正向与真正近二困难性不是同一命题。模型和LP比较合同见[不相关机定义](../../../unrelated-machines/state/定义/不相关机器与两个调度松弛--定义.md)，某配置gap不能直接作为原题困难性 |
| 加权拥塞 | 非负多项式加权原子游戏的全状态近似纯均衡问题；旧$Cd/\ln d$目标已被内部全状态线性下界否定，有限次数精确常数和外审各有义务；不由总目录一句“内部完整”取代构造及审查 |
| 两阶段设施 | 设施先同时选址，主动正权原子客户再按负载费用取NE，普遍结论有存在完整客户NE规则的量词；共同/异构双目录、任意设施数、线性/非线性费用分别保模型。共同目录双设施$\phi$与全$k$因子二不能互相换名，详见[跨模型分诊资源](旧研究入口的跨模型分诊与版本合同--资料.md) |
| 正占用核 | 固定有限$n$和严格正质量、Boolean输入、非负共享负载幂核组成的向量锥，交互秩是active表的多重线性次数；有限表示、锐坏项预算和闭包是不同工具结论。它不需要博弈；[定义与桥边界](../../../positive-kernels/state/定义/正占用核与顶背景交互秩--定义.md)只在零动作成本恒零等额外条件下给逐状态表示接口，没有一般均衡存在桥 |

本表按主源的导航身份及已核精确scope保存，不是五家族所有证明的新审查。正占用核即使源于拥塞局部工具，其非负表示、严格正权及有限维固定参数条件也不能省略；表示成功不推出selector可行或一般近似PNE。暂停的调度和旧设施线的独有数学仍保留，不因主攻改变而删除。

## 七类资产和入口同步责任

生产指南在CAG当时的旧树给出七种去处。现树已按对象类型重构，下面保留的是合同，不强制重新创建旧目录。

| 内容 | 必须能够恢复的信息 |
| --- | --- |
| 精确目标与当前义务 | 问题README、Claim、前沿和失败机制指向同一精确身份；精确账本及逐命题审查可核其真正范围 |
| 自足证明、反例与工具 | 全条件、量词、核心推导和适用边界；导航摘要不能成为唯一证明 |
| 可接续候选 | 准确标候选、缺口和下一步，不为通过结构检查而升格 |
| 已发生的独立检查 | 检查者、版本及实际覆盖；有限核算不替代一般定理，参与证明后的复核不全称独立盲审 |
| 规范实现与验证 | 代码、测试、真实输入、证书和运行范围分别清楚；软件接口不凭命名继承证明 |
| 个人研究与恢复备份 | 问题、材料、当前卡点和下一步；未完成、未核验及错误尝试可保存，整理后再进入共享资产 |
| 过期指挥文本与原始来源 | 源提交、路径、hash和替代入口；重复无增量输出可退出当前读取链，真实独有数学不按旧题批量删除 |

个人每有一段工作、换路线或中断前可以checkpoint，个人README负责恢复，不以共享入库标准阻止备份。正式共享资产则需整理正文及证据、明确实际身份/状态/依赖、做对应核验，再普通提交推送；**只有实际`status=pushed`才报告远端保存**，Git保存本身不升级数学状态。

| 实际变化 | 原指南要求同步的入口 |
| --- | --- |
| 个人推导、实验、卡点 | 本人工作区README；无需每次改共享图 |
| 新增、替换、改名、移走共享正文 | 所属数学README中的资产、用途与实际引用，及catalog名称登记 |
| 新定理、反例、范围或缺口变化 | 对应精确Claim和状态，以及真正受影响的前沿/失败摘要 |
| 一般目标、最佳已知范围、主攻方向变化 | 根摘要和本题短入口中真正受影响部分 |
| 稿件判断或文章结构变化 | 对应稿件入口；研究状态只记录真实数学变化 |

正式入库的人在同次提交维护相应入口，清洗者实质检查整合，整理者扣除前人贡献后判断合理拆合、读者和论文意义。角色的历史名称不构成探索前的审核或写作批准要求。共享文件和首标题表达数学对象及用途；已有稳定路径不因美观反复改名，不用日期、actor或`proof2.md`替代身份。旧`check_active_research.py`及`build_catalog.py --check`检查漏图/失效链接和名称用途，不检查数学摘要是否忠实；本批没有执行这些旧命令。

## 隔离、显式保存范围与不改写来源

旧指南强调一个独立对话一个clone、subagent由所属Boss汇总，不接管别人的身份；旧绑定存档不自动改绑。公屏用于研讨，半成形想法可讨论但需标不确定性，公屏不是成果唯一副本；私聊依显式收件人隔离。这是恢复来源时理解actor和通信记录的背景，不是本批新的发消息指令。

有一项容易丢失的具体合同：旧checkpoint的显式`paths`会**替换整个默认保存范围**，不是把路径并入默认范围，所以必须列全本次成果，不用`.`粗包。这解释为何恢复清单必须列实际正文和必要依赖；不代表现行工具必然具有相同默认行为。当前操作以当前工具和AGENTS为准。

旧推送规则要求保留本地工作后安全同步、冲突保双方内容，不强推、不自动ours/theirs、不另开研究分支回避冲突；凭据始终在仓库外。新增或移动文件同步真实链接，修改命题才更新实际涉及的精确账本/审查/资产/关系；按需核验，不为适配新路径修改冻结证据原字节。本批只读这些历史合同，没有执行源文Git、通信、认证或build指令。

## 两套退役来源的精确恢复合同

主源退役README指向两套不同快照。旁读其各自入口确认了下面精确来源，不以同名Claim自动合并。

| 快照根（按冻结来源解释） | 研究分支及完整提交 | 原入口所指内容，不代表已审完 |
| --- | --- | --- |
| `history/retired_topic_selection/multi_lane/` | `research/or-topic-battle-20261020`；`4f9269dd7abc92e256636b5c144d5738f40f1749` | 多线候选/比较、拟阵girth与交换距离、等长theta、有限权重势、图公平参数、两资源及两列射线LP、cloning、反方和精确探针 |
| `history/retired_topic_selection/independent_review/` | `research/topic-selection`；`1b8928d53a6db0b6112a8b8e75360c9053cbd7cc` | 独立选题比较、BMKP两容量候选及反方、laminar/副本公平、rank2 chores、Nash候选、成本保留舍入核查和验证导航 |

原正文、代码、结果及Claim状态按原字节保留，相对路径按各snapshot根解释，旧绝对路径及hash不为新树改写；省略的导航、临时身份、工作区和操作代码可按完整来源提交恢复，但不作为当前运行时或任务指令。六分支收口的tip及保存提交已由[前批历史资源](旧研究入口的跨模型分诊与版本合同--资料.md)和其只读祖先检查保存，本批没有重复远端审计。

同名编号可能属于不同输入类、反例范围、版本和审查判断；先恢复各自源定位并读承重内容，再按实际数学判定是否同一对象。原主源说完整一般算法仍有未闭合义务，这只保原等级，不是对每条候选的新结论。`multi_lane`入口的历史“59条”只是该冻结索引的标题，既不是当前在研数量，也不证明59份材料已实读。旧两个额外公屏只存选题进度、查新警报和资产指针；未落盘想法不据聊天升级或虚构结果。所有被链候选仍须逐源处理。

## 与前批区别、关系及接续

前批资源保存九行问题分诊、入库版本合同和六分支审计；本页新增的具体恢复对象是：总目录的五条研究线（含正占用核独立工具）、分层读取和全个人区索引的限制、七类资产、五类变化的入口责任、显式paths替换范围、隔离与稳定路径合同，以及两套退役快照的精确branch/commit与相对路径解释。没有另写一套数学真值账本，也没有覆改前批正文。

已知关系只有来源导航、版本/恢复合同和资料互补；来源入口不能推出所链定理。特别是正占用核到一般均衡、旧稿到一般半覆盖、旧候选列表到完整算法均没有本批建立的推导边。三级超图留第三阶段逐边建立，不能因导航互链制造数学依赖。

下一步可逐源处理两套退役README，再按各自目录选具体数学候选；大`branch_cleanup.json`的逐files合同及`source_crosswalk.json`仍是独立未完成来源，本批没有领它们。完成与否按逐源阅读、比较、独有内容去向判断，不按入口数、链接数或本资源篇幅判断。
