# 一般 root-only 论证的独立检查点

2026-10-23。**未完成草稿，无新一般福利下界。** 模型为 `research/current/customer_attraction/model.md`；根可能有缺陷，所有正深度子博弈必须为完整有序历史纯 SPE。允许任意平局和重复主题。本文没有把“任意根计划”误称完整根 SPE。

## 1. 真正目标与菜单重写

固定一份 root-only 计划。根强制选择目录主题 A 后的真实完整终局为 Z_A，包含根和全部真实后继；写

\[
f_A=u_1(Z_A),\qquad W_A=W(Z_A),\qquad M=\max_A f_A.
\]

实际根 A_0 的缺陷为 \(\Delta=M-f_{A_0}\ge0\)。任意最优 m 元组覆盖量记 O。待证稳健式是

\[
O\le2W_{A_0}+3(M-f_{A_0}). \tag{R?}
\]

因为实际根可以任意，(R?) 等价于以下同一份 root-only 菜单的全范围关系：

\[
\boxed{\min_A(2W_A-3f_A)+3\max_A f_A\ge O.} \tag{MENU?}
\]

这是纯代数重写，不是证明，且没有给出跨枝共同预算。它的作用是明确应同时控制哪个菜单的哪两个极值；不能把 \(W_A\) 和 \(f_A\) 换成不同续局的值。

## 2. 被放弃的单终局简化

曾考虑直接要求每个实际玩家的最终利润至少为实际终局的额外查询 cap：

\[
u_i\stackrel?\ge\max_T\sum_{x\in T}\frac1{1+c_x(Z)}.
\]

这个简化为假。已有 `root_tax_counterexample.md` 中，实际终局 AAAF 的前三位各得9，而未使用的主题 B 的额外查询值为10。该观察只排除了“用实际终局一列就给每人封顶”的办法；不排除混合多个真实菜单列、真正静态安全值或 MENU?。

逐人 \(u_i\ge v_{m+1}(0)\) 是原总稿§8附近的已存开放候选，并非本工作区新发现。它弱于受根菜单支持限制的 cap 要求；本工作区未证明或反驳它，后续由 security 方向处理。

## 3. 一个更强、非常紧的 root-only 候选

更强的候选是

\[
\boxed{O\le2W_{A_0}\quad\text{对每个正深度完整 SPE 的 root-only 计划。}} \tag{FREE-ROOT?}
\]

这是把 (R?) 的缺陷系数设为0；没有被证明。把实际根设为空主题后，它要求 r 位完整 SPE 的覆盖至少为 \(\operatorname{OPT}_{r+1}/2\)，比较元组比实际理性玩家多一槽。

其自然性来自全人数紧族，而非有限阴性证据：r 人游戏中，大主题 A 有 r 个客户，另有 r 个与 A 及彼此不交的 singleton 主题。全部历史一律选择 A 是完整 SPE（遵循收益至少1，任意 singleton 偏离至多1），实际覆盖 r；r+1 个比较槽可覆盖 A 及所有 singleton，\(\operatorname{OPT}_{r+1}=2r\)。加一个实际被强制选空主题的无理性根，并在其他根孩子选任意存在的完整 BI 续局，即得到 FREE-ROOT? 的等号 root-only 族。该族没有证明一般 FREE-ROOT?。

还可提出固定任意合法非空前缀、剩余 r 位完整 SPE 的更强背景形式：总覆盖 \(W\stackrel?\ge\operatorname{OPT}_{r+1}/2\)。它同样未证；不能把固定前缀的覆盖福利和剩余玩家利润混为一谈。

## 4. 唯一有限攻击及其严格限度

仅针对 FREE-ROOT?，检查过既有三人六标签 X/Y 完整策略的全客户类型线性锥（根0；第二位见 X 选3，否则选0；末位选第二动作所属组三标签中最小尚未出现者）。在63个非空客户兴趣类型上，以实际覆盖归一化为1，保留全部真实 SPE 行，对每个四标签比较元组最大化其覆盖。这个**指定策略锥**内最大比值是7/4，没有否定 FREE-ROOT?。

此计算没有证明一般候选、没有证明人数推广、没有证明其他策略结构，且不是继续扩样的理由；只记录已经做过的一次精确候选攻击。没有把该数值提升为新固定人数结果。

## 5. 当前未闭合位置

逐客户瞬时 utility/势交换恒等式可以分解一个根改选，但其后继会真实重置。根菜单中 \(2W_A-3f_A\) 的最小枝和 \(f_A\) 的最大枝可以不同；目前没有把这两个枝用一份正深度理性信用共同支付。强制最优主题依次形成 hybrid 前缀只给每个新节点的 IC，不控制已经行动者在换枝后的利润。因此没有得到 (R?)、MENU? 或 FREE-ROOT?。

只继续给缺陷加标量税、用末位最大利润代替平均利润、或把 hybrid 尾部冻结，均不能补齐这个缺口。本检查点准确状态是 OPEN；可直接交给另一个方向用于排除重复工作。
