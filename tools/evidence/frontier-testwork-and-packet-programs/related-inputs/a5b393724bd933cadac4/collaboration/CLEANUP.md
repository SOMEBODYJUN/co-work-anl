## 清洗服务于什么

清洗的主要工作是阅读、理解、比较、重组和解释，让后来的 Boss/Solver 能从已经积累的全部相关条件出发，知道眼下已经成立什么、为什么成立、有什么工具可用、什么想法还未完成，以及下一步可以怎样推进。

研究状态随时间演化。旧版本的猜想可能已经被后来的证明、纠错或反例改变；整理者必须读到相关后续，写出截至当前版本的准确状态。不能只保存一串时间流水，也不能压缩成没有条件、证明和理由的结论列表。此处的研究状态演化不自动把数学模型改成某种连续动力系统；本题完整有序历史依赖必须按原定义保留。

**删除是判断后的处置之一，不是清洗目标。** 有用的完整结果和未完成研究都应找到可接续的位置。未入库、没有独立审查、没有证明完毕、文件年代早，都不能直接说明材料无用。

## 对每份材料怎样工作

1. **读实际正文。** 看它提出了什么数学对象、精确命题、假设、量词、关键论证和证据；需要时读相关代码、真实输入及输出。只看文件名、聊天摘要或脚本输出不能完成清洗。
2. **与全仓相关内容比较。** 主动搜索同一对象、机制、引理、反例和后续纠错，读取相应原文，判断是否已有更完整版本、独立证明、范围差异或矛盾。全仓可访问；按相关性扩读，不要求每个人先把全仓塞进上下文。方法名称不同的两份材料也可能在做同一个数学步骤。
3. **判断真实价值与状态。** 它增加了什么？在哪些条件下能用？对后续完整目标有什么作用？原推导的缺口是否仍存在？失败否定的是辅助模板还是主命题？不因难以快速分类就丢掉，也不为了入库把候选升级为定理。
4. **找到数学上的归属。** 按数学对象及用途合并到合适正文；跨主题通用工具应解释适用模型。与现有材料重叠时先吸收独有信息，再退役重复。尚未理解清楚或仍需研究的内容，保留准确卡点和下一步，交给相关人继续。
5. **改写成后人能用的内容。** 定义术语，保留承重数学，说明推导、用途和边界；必要时写出直观解释和如何接到当前问题。摘要可用于导航，完整证明、反例及可复现输入另有唯一正文。
6. **接入当前状态并保存。** 更新本主题唯一 README 的相关段落和直接链接；有结论变化才同步必要的 Claim/依赖，不机械扩张 JSON。跑与实际改动有关的检查，显式路径 checkpoint 并确认 `status=pushed`。

## 一段保留内容必须让读者知道什么

不要求每项套固定表格或新建文件，但正文应能回答：

- **是什么、讲什么：** 对象、问题、准确结论或猜想，全部承重假设与量词。
- **为什么：** 关键推导、证明、反例或精确证据；尚未证明的步骤明确保留。
- **有什么用：** 它支付哪一步、解释哪种结构、排除哪种具体错误、能在何种输入条件下复用。
- **对下一步有什么帮助：** 能直接调用的接口、可接续的 idea、需要补齐的真实缺口；不要制造空泛研究建议。
- **来源与现况：** 读过的实际来源、与先有结果的关系、重要后续纠错及截至当前版本的状态。

例如，一个 analytic envelope、LP 可行点或 Farkas 证书有价值时，应说清它约束的数学对象、输入域和它真正否定的模板。它不是原模型反例的，就不能写成反例。重复扫描和更多数值行本身不等于新知识。基础数学、组合、拓扑、势函数或其他表示都由研究者自由考虑；清洗不得把任何一种路线设为后续 Solver 的必经步骤，也不能因不属于旧路线而漏掉材料。

## 正文放哪里

GitHub 上本分支的 Markdown 正文就是共享、可更新的知识库，不再另建一套同步到其他云端的副本。

| 内容 | 归属与整理方式 |
| --- | --- |
| 可自足复用的数学知识 | `research/current/<对应主题>/`；按对象合并正文，说明用途与范围 |
| 有价值但未完成的想法 | 个人工作区继续保存；已能准确提出的开放问题可整理进对应 `research/questions/`。标清条件、已走到哪一步和接续需要 |
| 审查与异议 | 保留所审版本、实际理由和影响范围，与原正文直接关联；不把审查票数当证明 |
| 必要计算证据 | 保留代码、真实输入、精确核验输出与对应正文。没有数学用途的过程日志不进入启动内容 |
| 主题 README | 该主题唯一启动入口：题目、现况、有用正文与直接读取条件；随新信息替换相关段落 |
| 操作配置与索引 | 程序实际需要的配置可留；冗余导航及其生产/消费脚本一起处理，不为过旧检查而重新造无用途索引 |

旧材料已被充分吸收且没有独有信息时，可以删除工作树副本；先处理真实引用和复现依赖。Git旧版本提供来源恢复，不把所有旧文件搬进新“归档区”继续堆积。未知未跟踪文件先确认内容与来源。

## 多个清洗对话怎样合作

每个对话独立 clone，共用同一文件分支与公屏。在公屏读近期认领，说明自己负责的数学对象/目录及预计改动文件，避免两人同时重写同一正文。每人都可以访问全仓和使用实际可用工具。协调者维护根程序、根入口和跨范围整合；局部阅读、理解、自查和整理由各人独立完成，出现新的数学判断、idea、冲突或接续需要时再交流。

可并行工作面包括：客户吸引正式正文；本题个人研究中的未完成与遗漏知识；其他研究模型各自的数学；必要代码/输入/证据；旧操作词和派生登记；学习与写作材料。可按实际对象进一步拆分，人数依工作增加，不凑固定数量或固定十种角色。需要改其他人负责的正文时先协调，避免覆盖。

在自己现有工作区 README 简要记录确实读过和处置过的范围、仍未理解的材料以及接续位置；只记有恢复价值的内容，不能把“搜到”当“读过”，不能把“搬动”当“整理完成”，不能把一次扫描当全仓清洗完毕。全体共享状态仍以本主题 README 和实际正文为准，不维护另一套庞大覆盖数据库。

## 模型、证据和研究自由

本题必须保留有限单位客户、共同主题目录、六名单位权提供者、重复、空主题、零客户、完整有序离轨历史和任意历史依赖平局。一次前期改选会改变后续行动，不能只比较冻结后继的静态结果。压缩表示只有在已证明保留原条件时才可作为等价表示。

其他研究模型保留各自定义与目标，不能把 NE、两阶段主动客户模型和此处 SPE 混用。完整证明、候选、条件结论、观察、方法障碍和真正目标反例分清；内部复核、外审和新颖性分别说明。语义整理不提升证据等级。

日后 Boss 带内部自由 Solver；Solver 获得同一完整目标、全仓及工具访问能力，能自行解题、自查和交流。大部分推理资源用于解题。检查随具体材料需要进行，不持续设专职审核关卡，不规定数学方法或探索配额。本轮不搭建外部数学求解 Agent。
