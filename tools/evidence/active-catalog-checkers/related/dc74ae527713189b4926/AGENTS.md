# 仓库工作规则

当前数学目标 **Q-CAG-HALF-6**，存档 `customer-attraction`，状态 **OPEN**。六名单位权提供者、有限单位客户、任意有限非空共同主题目录、全部有序历史依赖纯SPE；需证每个SPE覆盖数至少为六个主题最大覆盖数的一半。空主题、重复、零客户、离轨历史与任意历史平局均保留。准确模型见 research/current/customer_attraction/model.md。其他研究模型独立保留，不能把其NE、两阶段设施模型或条件结果混入本题。

当前用户要求先交付程序和清洗部署，再由多个对话整理全仓；数学Agent及正式研究提示词留到清洗之后。活动规则在 [collaboration/CLEANUP.md](collaboration/CLEANUP.md)，操作在 [collaboration/README.md](collaboration/README.md)。新对话默认存档 `repository-cleanup`、长期文件分支 `cleanup/research-foundation-20261028`、共用公屏 `wcg/board-cleanup-20261028`；清洗后仍在同一分支研究和定期整理，不按对话或轮次另建分支。旧提示词中的一般人数优先、只许main、强制全套JSON登记和默认路线要求均不能覆盖本轮指令。

## 求解与交流

- Boss负责整体理解、接收整理、资源和上下文交流；内部研究subagents均为Solver，获得同一完整目标，主动访问全仓和实际可用工具，自由选择方法，能自行完成研究、自查与计算。
- 不按证明/反例/实验/文献给Solver预分工，不要求走LP、拓扑、五人证明或其他路线，不规定方法配额、固定步骤、开工审查或时间额度。清洗工作可按目录和数学对象分工避免写入冲突。
- 大部分研究资源给求解。具体证明/反例形成后按需检查；整理随实质变化进行。公屏和私聊可交流未成熟idea、关键障碍、异议和接续需要；不广播全部工具日志与无信息状态。
- 默认只读对应存档的启动入口，随后按需读实际正文。默认少读不等于限制访问；Boss及时传递新信息，也不把公屏流水、全历史库存和大JSON灌给所有Solver。

## 内容与入库

- 保留数学对象、域、量词、假设、精确结论、依赖和证据。已有证明、候选、条件结论、实验观察、方法障碍和真正目标反例分别标明；内部复核、外审和新颖性独立说明。清洗不提升真值。
- 未完成研究允许在个人工作区持续保存和接续，未入库不是无价值。正式材料以自足可复用、准确范围和清楚来源为准；候选与失败机制也能按其真实身份入库，不以独立审查完成为草稿保存门槛。
- 清洗以阅读、理解、全仓相关内容比较、数学归属与知识重组为主要工作。逐份讲清对象/条件/量词、关键推导、真实状态、用途和后续价值；研究状态随时间演化，追到相关后续纠错后再形成当前判断。只搬文件、只做摘要、只搜索索引都不算完成清洗。
- 吸收独有信息后合并重复，确认无用后才删除相应副本。未知未跟踪工作先确认，不能按文件年龄、未证明或未入库直接删除。GitHub本分支Markdown是共享知识正文，Git历史提供恢复，不另造全量历史库存或云端副本。
- 每主题一个README作为启动与现况入口，正文按数学对象组织；变化时改对应段落，不叠加每轮流水。JSON仅在实际程序需要时保留；去掉冗余索引时同时处理生成器、消费者、检查和真实引用，不为满足旧检查器而重建冗余资产。

## 程序和保存

- 根work.py是统一入口；独立对话独立clone，复用已绑定身份、存档、角色、文件分支和公屏。不同绑定不自动改写。内部subagents由父对话汇总，不冒用他人身份。
- 先查Git状态和remote，保留未提交工作。清洗在指定分支进行，sync/checkpoint只操作绑定文件分支；不自动合入main，不强推，不更改凭据到remote。凭据只放仓库外用于认证，不打印或入库。
- 有用的阶段工作及时checkpoint，只有回执status=pushed才报告远端保存。清洗显式列出本次修改路径，避免顺带提交别人的草稿。共享文件先协调写入范围；发生真实冲突时保留各方内容再解决。
- 检查与改动相称：程序验证真实行为，数学检查承重推导，迁移检查依赖和链接。旧全仓catalog/assets/graph强制维护属于本轮待清理对象；纯工具或个人草稿改动无需运行全套数学数值实验。
