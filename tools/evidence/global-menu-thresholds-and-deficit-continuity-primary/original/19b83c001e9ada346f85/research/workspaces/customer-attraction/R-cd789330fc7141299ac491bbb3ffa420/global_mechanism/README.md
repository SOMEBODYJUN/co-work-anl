## 1. 当前判断

原本独立提出的一般候选为

\[
\operatorname{OPT}_m\le\sum_{x:c_x>0}\left(2-\frac1{c_x+1}\right).
\tag{L}
\]

它若成立直接推出 half；实际完全无拥挤时给 `OPT≤3W/2`。
旧无拥挤无限族只迫使纯负载系数 `f(1)≥3/2`，不否定 (L)。
协调者告知它在 `C⊆O` 情况与其他工作区 signed-harmonic 最弱桥重合，故本分支不把它作为独占新路线，亦不继续固定锥调参。
`attack_load_candidate.py` 曾对一个确定种子的1460个有限实例，使用规范集合值全SPE oracle 检查 (L)，未找到反例；这是有限诊断，既不证明 (L)，也不提供一般正面证据。

随后转向 root 给出的抽象菜单义务。结果是：**只保留每个根主题的一份低根收益、高尾部收益菜单，即使把静态对手槽数增加任意固定常数，也无法推出所需安全值阈值；root提出并经本分支核算的无界奇数槽版本进一步排除任意人数无关的乘法近似。**
环菜单首先由 sibling `mixed_menus` 发来；本分支在未读取其文件或发现代码的情况下，从客户定义独立重建全部代数及下述固定额外槽数加强。
这是一项辅助桥停界，不是完整SPE反例，不否定主目标。

## 3. 接续义务

一般证明不能只把每个主题压成一条最终收益有序菜单；必须保留真实后继在更深历史处的最优性，或保留另一足以排除环菜单的策略一致性条件。
环菜单的致命未认证点非常具体：末位指定邻主题收益 `3/2`，但一个与旧前缀不交的合法主题收益 `2`。
进一步寻找菜单的静态混合分布无法修正这一缺口，因为环实例的安全值已经有匹配原始/对偶证书。
