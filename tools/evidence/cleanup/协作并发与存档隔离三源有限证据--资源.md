# 实读与用途

三份冻结 JSON 在 `legacy-cleanup`（68fad804…）与 `main`（aefc58ea…）逐字节一致；本页保留其 SHA、source ID 和测试量词。它们属于协作工具工程证据，不能放进 unrelated-machines 或 customer-attraction 的数学定理层，也不能把测试通过写成“数学采用”。

## 增量聊天发布回归

`incremental_chat_release.json` 在 Python 3.12.14、base commit `4c71d3ed…` 上声明 `status=passed`，共 95 个测试：board 22、board entry 5、checkpoint 35、并发 2、安全 15、work 16；报告耗时约 66.5 秒。复现命令包括完整 unittest、map/crosswalk 检查和资产检查。真实本地 Git 场景模拟 10 个独立 clone、10 个并发消息发送者、10 条公屏消息、10 条定向消息和 10 个并发 workspace checkpoint。

这些检查覆盖公屏与 JSON 视图排除 DM、私聊收件人和 save 一致、无效收件人不落回公屏、幂等重试/丢失回复恢复、workspace identity/resume、远程 visit 保留索引与草稿、出站 commit/blob 范围与凭据审计、冲突保留快照以及“不新建研究分支”。证据只说明隔离本地 bare Git 场景的回归通过；源本身明确没有生产 GitHub 吞吐测试、数百个 live Work 并发认证、DM 访问控制/加密保证，也不证明没有其他潜在 bug。

## 消息路由与竞争模型

`message_routing_model.json` 在一个有限本地规格模型中检查 `logical_workers=500` 和 `directed_pairs_checked=249500`，路由与边界检查通过。它给出四种假设频率下的计算量：每分钟一次时 500 pushes/min、30,000 writes/hour；每五分钟一次时 100/min、6,000/hour；每十分钟一次时 50/min、3,000/hour；每六十分钟一次时 25/3 per minute、500/hour；若每 worker 每分钟做一次 REST poll，则 30,000 requests/hour。

同步竞争只是在指定对抗模型中的组合计数：1 writer 1 次尝试、10 writers 55 次尝试/45 rejects、100 writers 5,050/4,950、500 writers 125,250/124,750。它们是模型输出，不是实际吞吐预测；源限制为本地有限规格、无 GitHub 并发负载测试，路由可见性也不是访问控制。

## unrelated-machines 存档范围隔离

`unrelated_machines_scope_release.json` 记录 2026-10-16 的变更：checkpoint 默认按 bound save 选择、保留 shared legacy 行为、unrelated-machines 不继承 weighted-congestion 主题路径。对 checkpoint 测试 42 项和全体测试 103 项均报告 `OK`；覆盖新 save scope 注册、unknown save 的公共寄存器与个人 workspace、空合法 scope 停止、tracked deletion、旧主题出站提交阻断、其他 actor/save 草稿保留、start→checkpoint、已有十 clone 并发/DM/public 路由/幂等回归。

该源还给出明确边界：测试全在隔离本地 bare Git remote；没有把测试身份/消息写入生产公屏；没有数百 live Work 吞吐认证；显式 checkpoint 路径会覆盖默认路径并需要有意复核；不同 Work 对话仍需人工打开。它支持“保存范围和研究存档路由的工程契约已在有限测试中覆盖”，不支持跨数学对象迁移任何定理或把工程测试当作全仓来源已处理。
