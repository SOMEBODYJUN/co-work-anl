# 固定背景bitset程序：优化的是活跃利润

4073B `search_background.py`只依赖标准库。输入q标签、r剩余人、非负整数主题过去计数p、兴趣mask→整数重数w；过去可按这些主题计数任意排序实现，未规定它在根SPE实际到达。每个重数表示不同单位客户。类没有完整schema校验，外部非法q/r、前缀长度、mask或权重不由此自动拒绝；下面递推只用于合法输入。

枚举所有Σc_a=r的相对终局，L=lcm(1,…,Σp+r)。对类型I，d_I=Σ_(a∈I)(p_a+c_a)，e_I=Σ_(a∈I)c_a。预计算每标签L倍单人收益Σ_(I含a,d_I>0)w_I L/d_I，以及

\[
P(c)=\sum_{I:d_I>0}w_I e_I/d_I.
\]

后者包含旧客户向剩余人支付的份额，通常不等覆盖数。cut[a]按单人整数收益递增，累积保存各收益以下叶索引的bitset；二分找每个孩子集合对当前a的最低收益，取所有动作最低值的最大值作floor，再合并孩子中当前收益≥floor的叶。这是[全历史全集递推](<../../../../archives/customer-attraction/state/资料/全历史纯SPE终局搜索的递推与有限证据--资料.md>)的固定背景版本；充分性依赖未选孩子可各自指定最低收益SPE，必要性依赖每份真实SPE必须压过它们。缓存按相对计数c而非有序历史不强迫Markov策略。类不直接输出完整策略。

`minimum()`取所有SPE终局的**活跃总利润**最小值；`optimum()`取所有相对终局的该利润最大值F_r(b)，而非C*或OPT。main默认trials1000、q7、r5、seed193773；每次随机0至5个过去行动，抽q至3q−1个非空mask并给1至30重数，每逢F/minP严格增大即覆盖相邻`background_best.json`。若minP为零，源码把ratio约定1，没有自行断言F也零。非零合法可覆盖客户时，一位活跃者选择可覆盖主题至少有正的有限份额，故均衡总利润为正；全零输入应另保不等式而不形成效率比。

main有guard，导入类不跑随机搜索。`solve`是类方法上的无界lru_cache，键含self，旧实例因缓存而持续被引用；长循环没有清缓存，复用时应注意内存，不能把它误写成每轮自动释放。组合状态数是binom(q+r,r)，叶数binom(q+r−1,r)；这不承诺输入位长多项式。

# 1590B不变量循环及旧入口的精确边界

`search_invariants.py`用星号导入上述模块后立即执行3000轮，**没有main guard**；import本文件就会开跑。固定seed171771、q7/r5；先抽7至24个mask，重数1至12，再抽0至8次过去行动。它遍历每个输入全部SPE终局，令new(c)为旧背景未覆盖的客户中终局新增人数，maxnew=max_c new(c)，计算

\[
\mathrm{gap}=P(c)+\mathrm{new}(c)-\mathrm{maxnew}.
\]

这精确等于BG余额而非新不变量。首次负值保存`regret_counterexample.json`并退出；否则每100轮打印当前最小值。`best_pot=1000`未被使用。仅当过去为空，才另计算Φ(c)=Σ_Iw_I H_(Σ_(a∈I)c_a)，并与全目录r主题最大裸覆盖optcover比较；首次Φ<optcover保存`potential_counterexample.json`并退出。这里的optcover不是F_r(b)。
