# 固定版本精选材料的依赖闭包与隔离复现

## 三个程序的职责

[九主源及历史报告账本](<../../../../archives/customer-attraction/state/资源/六人精选交接包的模型合同与历史证据账本--资源.md>)保数学状态。这里完整说明三份原程序的实际输入、生成过程与限制；[原件](<../../../../archives/customer-attraction/tools/evidence/curated-six-provider-handoff-package-primary/original>)字节不改。本次三入口均未执行，只有读取、SHA核对与冻结stdout静态解析。

`build_bundle.py` 从固定提交6da46a68073073e9038cd538fd01019a0f112ede读取，不从运行时HEAD取材料。它靠祖先存在`customer_attraction/model.py`定位旧源树ROOT，并用Git列固定树、取blob和提交时间。当前干净结果树已迁移该模块，不能把原脚本随意复制到结果树就称直接可跑；须恢复对应旧布局、base对象及脚本同级五份说明/启动器和可选VALIDATION。

## 精选与依赖闭包的准确范围

固定分组包括模型及工具、五人完整证明、三份五人审查、六人共同见证、六人后缀包络、七客户zero-reset、其它一般障碍/候选、有限精确博弈工具。`selected`先取这些指定路径的集合，并断言全部在base树中。

静态依赖遍历只从`verify_joint_atoms.py`及`root_extension.py`出发，用AST读取`import`和带module的`from`，只取首级模块名。它在`research/workspaces/customer-attraction/`下按Python文件stem找候选；**恰一个同名候选**才自动纳入并递归。相对导入无module、动态加载、外部包、重复stem和其它入口的全部依赖，并不由这段AST自动解决。

代码再显式补入importlib使用的`six_maxroot/discover.py`及若干JSON，包括joint_system、strong_pair_projection、iterate_same_menu、compact_cuts、fourth_indexed_projection、三份maxroot cuts及两份AB projected rows；`target_joint.json`只有base存在才加入。所有显式依赖同样断言存在。这个“最小依赖”是指定入口的收集与历史解压测试合同，不是证明全部仓库链接或任意动态执行均闭包。

## 载荷、字节与历史建包报告

每件所选源用`git show BASE:path`原样读取，记原路径和Git blob。另生成无认证、通信或仓库操作的`source/work.py`找根占位。复制五件任务/材料/复现/manifest核验/运行启动器，生成requirements（NumPy、SciPy）与SELECTION，可选加入VALIDATION。SELECTION保原审查身份，并明确精选非全仓；原文件内指向未入选资产的相对链接可以仍不闭合。

载荷文件名用PurePosixPath检查非绝对且无`..`；所有读取内容和生成内容均做PAT模式扫描。MANIFEST逐件写size、SHA以及源文件的原路径/blob；它是对**加入MANIFEST以前的载荷**列清单，不自列自身。历史最终107文件与97源文件的差额为找根占位1、五个说明/启动器5、requirements1、SELECTION1、VALIDATION1、MANIFEST1。

ZIP成员加统一`Q-CAG-HALF-6/`前缀，时间取base提交UTC秒元组，权限0o100644，deflate级别9；生成后检查CRC、无重名、成员数与逐manifest SHA。报告在ZIP之外写出。安全名和哈希保证的是所检查字节，不证明数学结论、来源真实性或完整策略IC；它们也不代替目标文件的审查。

冻结BUILD_REPORT声称已建并逐字节核验、97/107文件、1,976,965B解压量及348,234B压缩量。当前保存这个历史报告，不把它当本轮重新认证的包。若未来重建，ZIP压缩实现/环境也可能改变压缩字节；内容身份须逐成员确认，不能仅凭历史zip SHA或相同文件数授权数学结论。

## manifest核验器

`verify_manifest.py`从自身目录读MANIFEST，逐条验证普通文件、不是符号链接、非绝对路径、无父目录分量、实际长度及SHA，打印PASS/文件数/source_commit。它不校验MANIFEST本身来自何处，不排未列出的额外文件、不验证manifest行唯一，也不验证数学。它在已解压目录检查，不负责ZIP解压安全。

这些限制不会使历史已列载荷字节检查失效，但未来输入或分发场景变化时不能把它视作完整发布安全审计。代码依靠Python断言，因此应正常执行，勿使用禁用断言的`python -O`来声称完成同一核验。

## 六个隔离运行入口

`run_checks.py`将同级`source/`完整复制到临时目录；每个job使用该临时source作为cwd，PYTHONPATH只指该副本，并把BLAS/OMP线程各设1、禁写pyc。它启动当前Python解释器，捕获stdout/stderr和monotonic耗时；遇首个非零退出码停止，完整结果数匹配所选job数且全部零退出才标PASS。

| 可选名 | 原始入口及参数 |
| --- | --- |
| half5-local | `customer_attraction/proofs/half5_exact_v1/components/verify_local_components.py` |
| half5-main | 同证明目录`verify_certificate.py --manifest .../row_manifest.json --output <临时报告>` |
| zero-reset | R-23ab27…/general_n/independent_zero_source.py |
| suffix-envelope | R-a8ee6…/parent/verify_suffix_envelope.py |
| joint-atoms | R-a8ee6…/closure/verify_joint_atoms.py |
| root-extension | R-a8ee6…/closure/root_extension.py `--verify` |

无`--only`时按表中六项顺序执行；可显式传所选名字及`--output`写报告。`nargs='+'`接受重复名字，因此报告检查数不必总是六，须看真实选项。程序不自行先调用manifest核验器，也不解析stdout中的数学字段；零退出只代表该入口完成其代码断言，语义须结合原实现与结果内容判断。

临时复制避免原源码邻接输出被覆盖；没有为每个子进程设timeout。环境继承`os.environ`，`source/`中的占位不负责认证。此启动器自己不调用网络、Git、LP优化器或凭据；被调用原入口及其依赖必须另按真实源码审查，不能由wrapper无网络代码推出任意替换载荷也无网络。

已有成熟数学证明/成功复现足以支持本包的历史结果分类，本次不重复六次数学运行。未来若为新环境或缺失依赖补核，可从固定base恢复原布局，运行manifest字节检查，再按需要选job，并另存实际新事件；旧VALIDATION的耗时和stdout不可倒填成本次。
