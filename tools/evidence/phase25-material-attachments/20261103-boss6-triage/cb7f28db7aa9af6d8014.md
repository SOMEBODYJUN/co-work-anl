## 原数据是什么

本对象逐字节保存 35014 B 的 [普通报告](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/original/joint_0012_345.json>) 和 791 B 的 [strip 报告](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/original/joint_0012_345_strip.json>)，原十进制拼写和 signed zero 不改。全部 19/14 个根字段、63 个质量坐标、84 个计数动作、259 个有序动作均已读；不是仅摘最小目标值。模型与 4772 B 代码的逐行解释见[程序对象](<../../../../archives/customer-attraction/state/程序/固定路径计数策略与客户质量的两步安全联合搜索--程序.md>)。

这是四名单位提供者、六共同标签的客户兴趣质量搜索，实际路径固定为 (0,0,1,2)。非空兴趣集合 M 的质量位于数组 M−1，标签 a 对应低位 bit a；空题、重复主题、相同覆盖不同标签及任意离轨平局仍在底层模型中。完整有序策略是每个长度 0…3 历史的规定行动，客户在终局覆盖者之间均分。两表的非负、单位质量和 SPE 原意只是搜索约束；保存数值是否满足，须另外核验。它们不是某个单位客户集合的自动认证。

本页的底层行动域是程序保留别名的**有限标签接口**。[定义页](<../../../../archives/customer-attraction/state/定义/共同目录完整历史模型--定义.md>)的严格集合目录约定与其单列的软件同覆盖标签扩展须区分：覆盖互异时直接适用严格集合读法；出现同覆盖别名时，指定完整σ及比较首先在原标签历史上解释。若要合并别名，须另证指定全历史σ可下降并保持全部真实偏离，不默认仅因覆盖相同即可合并。本文保留原标签、全部比较及另行全兴趣校准的标签身份，不把它们自动改成严格集合目录上的同一策略输入。

seconds 是源码在调用 MILP 前后计时所得，不包括前面的模型构造；不是命令请求值。两份表均保存时间限制状态，不应称 optimal。普通表有 z.x 时才会附加动作和质量，故它确有原数值 incumbent；strip 无五个候选字段且 objective=null，只能说未保存 incumbent，不是数学不可行证明。它们没有 argv、源码 hash、环境、stdout、进程退出码、每个 solver 状态和请求的 seconds；不能按文件名补造命令。

程序没有保存完整 U、z、t、h 或 MIP 最佳界、gap、节点数等。因而数据可以核查其抽出的策略和质量，无法恢复当时全部内部约束余量或目标构成。把原 minΓ 与 tiny objective 直接叫严格反例会跳过这些缺口。

三项严格负坐标已经阻止把这份 raw 数据当作客户质量。质量和也不精确等于 1。当前 [冻结源码](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/original/pair_joint.py>) 无条件固定 w₆₃=0，普通表却几乎全部质量在 63；这个约 1 的不符远大于微小负坐标。因此不能声称当前字节程序复现了普通表，亦不能仅凭 “strip” 名推断某个未保存旧版本或开关。两份冻结提交的原字节相同，不是两次独立实验。

原 count_policy 在深度 0,1,2,3 分别有 1,6,21,56 个节点，总计 84；full_policy 对应有 1,6,36,216 个有序历史，总计 259。一次独立标准库核验检查无重键、域完整、所有标签合法，并逐项验证

\[
\sigma(h)=\mathrm{count\_policy}(count(h))
\quad\text{对全部259历史成立。}
\]

它还从空历史沿真实规定动作得到 (0,0,1,2)，终局计数与原字段完全一致。这个结论仅认证完整形式策略和展开身份；同计数节点共用平局动作限制了策略类，不表示其他完整策略不存在。

## 唯一新核验：两个数值解释，均不精确可行

新 [audit_reports.py](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/audit_reports.py>) 只用标准库，不导原代码、不创建 MILP 矩阵、不调用 LP/原 Space/求解器。它对**同一保存表的两种明确输入**各做一次定义级全史诊断：

1. decimal_tokens：直接把 JSON 小数 token 解释为有理数；
2. decoded_binary_floats：先按 Python JSON 解码为 binary64 float，再取该浮点本身的精确有理值。

这不是把小数四舍五入到邻近整数，不使用 `limit_denominator`，没有修复或重新缩放质量/分布。两种解释分别对每个 h 计算按 σ 真实完成的叶子，以及每个动作 a 后按 σ 完成的偏离叶子，再按兴趣客户份额逐项求差。每种 259×6=1554 项，其中 259 项为自身恒等式、1295 项为非自身比较；合计 3108 项。结果为

| 项目 | 十进制 token | 解码 binary64 |
|---|---|---|
| 负质量数 | 3 | 3 |
| 负 / 零 / 正全史余量 | 662 / 259 / 633 | 662 / 259 / 633 |
| 非自身零余量 | 0 | 0 |
| 最小余量 | −72130998708005857 / (4·10²⁹) | −57148064879540791 / 316912650057057350374175801344 |
| Σp−1 | −1 / 25000000000000000 | −1 / 18014398509481984 |
| ΣQ−1 | −1 / 10000000000000000 | −1 / 18014398509481984 |
| Σw−1 | −10660944169949647 / 125000000000000000000000000000 | −3378088105309295 / 39614081257132168796771975168 |

共同的最小见证在历史 h=(3,3,5)：原规定动作 4 得终局 (3,3,5,4)，偏离 5 得 (3,3,5,5)。十进制解释下的真实份额分别为

\[
u_4=\frac{6249999999995981706435374311}{25000000000000000000000000000},
\quad
u'_5=\frac{100000000000007838301673994833}{400000000000000000000000000000}.
\]

差为上表负数，约 −1.8032749677001464·10⁻¹³。原保存 minΓ 与该精确数十分接近；十进制数值之差为 3/(4·10²⁹)，binary64 解释之差为 1/316912650057057350374175801344。这说明原 tiny negative 不能当精确零，而非宣称原数值算法异常。即使只看近零符号，仍有负质量、概率和及当前全兴趣零上界三类独立可行性问题。

完整 3108 条比较，包括每条 h、规定/偏离动作、两条真实叶子及两收益和差，全部保存在 [full-history-ledger.json.gz](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/exact/full-history-ledger.json.gz>)；不是只留下最坏见证。压缩 84476 B、解压 1795593 B，各自 SHA 在报告中绑定。原数值及校验结果无需重扫即可接续。

## 固定 p/Q 的全背景诊断不是原目标重放

两种输入解释还分别按定义枚举全部 56 个三槽根背景，以及尾前缀 (0,0) 后六个纯查询在六个单槽对手上的份额。它们给出形式量 ℓ=min_H E_p[pay]、C=max_a E_Q[pay] 与原叶前两人份额 d，重建紧形式值 D=d−4ℓ+2C。

| 输入解释 | 重建形式 D 的近似 | 原保存 objective |
|---|---:|---:|
| 十进制 token | +3.756483229172229e−13 | −4.286519276155032e−14 |
| 解码 binary64 | +3.7568607849283854e−13 | 同一原 JSON token |

每个背景的六个纯收益、混合值以及每个尾查询在各对手下的收益均写入全账；ℓ、C、d、D 的完整分数见 [exact-audit.json](<../../../../archives/customer-attraction/tools/evidence/joint-pair-policy-cone/exact/exact-audit.json>)。本 D 是在保存坐标上**另行定义**的紧形式值；原缺 t,h，不能说它等于当时 fun，不能追认原求解最优性。由于此处 w 有负值且 p/Q 的精确和非 1，甚至不能把这份诊断直接称合法安全界或 PAIR 上界；上界证明须满足程序对象所述前提。

若另外取 w₆₃=1、其余 0 并用真正归一概率，四人任何行动终局每人 1/4，所有 IC 恒零，根/尾安全值均 1/4，PAIR=1/2+2·1/4−4·1/4=0。这是既有全兴趣零系数解析式的特例，解释数值停点为何靠近平凡等号面。它**不是原输出**，并且仍违反当前 strip 模型 w₆₃=0。当前没有新跑这个校准点、没有把它作为原报告的修正版或负例。
