# 当前全部1047列的精确核价

本轮没有执行price_aligned.run/check/main、block.run/check/main，也没有重复历史386秒全型定价或205秒坐标上升。只在独立runtime导入price_aligned定义（四原rows及canonical定义前缀），逐条固定旧负列调用其原direct Fraction行定义。每条重算**全部2196行系数**，验证名字集与所用对偶完全相同；共1047×2196=2299212个系数。未宣称另写了一套全部2196真IC推导。

为将浮点记录和精确符号分开，把Python解析JSON所得每个β、λ的二进制float视为其**确切有理数**，用Fraction(float)形成确定参数向量，再精确算

\[
\rho=\beta W-O-\sum_n\lambda_nG_n.
\]

这不是恢复作者未保存的“理想精确最优对偶”，也不把其余非负域列认证；只是对已绑定存储参数的有限列条件作严格符号检查。所有1047列均ρ<0，且原float residual均<−10⁻⁸；重算浮点与原值差的最大量分别8.881784197001252×10⁻¹⁶、4.996003610813204×10⁻¹⁶。

每列记录原子SHA、W/O/d、原残差、精确有理残差、浮点差及按行名排序的全2196系数SHA；数据在[完整列核价](<../../../../archives/customer-attraction/tools/evidence/global-prices-five-boss3/replay/all-reported-column-checks.json>)。这足以确认这些负列确实排除对应存储对偶的全型有效性，而不是某个字段舍入导致的伪负。它不构造非负原始质量使全部行满足，更不构造目录游戏和全部历史策略。

这里全部两JSON字段及全部报告列已处置；875KB不是只解析header。完整域验证、原Fraction行和参数化严格负值使其可直接用作两个具体对偶的分离证据。不能从“每mask均有一负列”推其它对偶也失败，也不能从block没记录某列推该列非负。
