# 被检查的候选与准确接口

采用[共同目录完整历史模型](<../../../../archives/customer-attraction/state/定义/共同目录完整历史模型--定义.md>)。有有限共同主题标签目录、依次移动的单位提供者，整数重数表示不同的相同兴趣单位客户。客户在最终覆盖自己的提供者之间均分。对主题计数背景 (b)，客户类型 (S) 的背景负载为 (b_S=\sum_{j\in S}b_j)，重数为 (n_S)。脚本计算的“单例值”是

\[
F_b(a)=\sum_{S\ni a}\frac{n_S}{1+b_S}.
\]

它是只插入一个当前动作后的背景单人势；没有先把未来提供者的负载加入这个分母。“最大单例”指 (a\in\arg\max F_b)，不要求该主题只含一个客户。

令 (R(b)) 为该背景下**全部完整历史纯子SPE**可以实现的完整终局计数集合。总人数由固定实例给定，剩余人数是 (m-|b|)。对非终局背景，规范求解器给

\[
M(b)=\max_a\min_{c\in R(b+e_a)}U_a(c).
\]

候选是：对每个合法背景及每个最大单例主题 (a)，只要插入后仍有决策者，就有 (M(b+e_a)\le M(b))。脚本只寻找它的一次严格反向不等式。这里比较前后两个**不同当前决策者**的可信阈值，不能把 (M(b+e_a)) 解释成插入者在孩子中的最低收益。

规范 `ExactSPESolver` 的 (R) 递推及其充分性拼接见[终局全集算法](<../../../../archives/customer-attraction/state/算法/完整历史纯SPE终局全集--算法.md>)。相同计数只缓存可实现集合；不同有序历史可以使用不同续局和平局选择，程序不选定一份匿名策略。相邻换位还需要[准确的两道门槛](<../../../../archives/customer-attraction/state/引理/可信相邻换位与固定计数坏点正常形--引理.md>)，最大 (F_b) 并未消除其中任何一道。

# 原入口、依赖与输入边界

2504字节原脚本SHA-256为 `236da078a49e1f5da680b59991294c70c164db15f4b59d281c4fb5f23793c59c`。已完整实读，不仅依据文件名或原README概括。它只有 `compositions`、`check`、`main` 三个函数；标准库依赖为 `fractions`、`itertools`、`pathlib`、`json`、`sys`。`CustomerType` 被导入但脚本没有直接使用。

`main()` 没有命令行参数，固定读取 `examples/customer_attraction/aggregate_theta_failure.json`。根目录取脚本的 `parents[5]`，因此本轮保留原相对目录层级，未改路径常量。规范包的 `__init__.py`、`exact.py`、`model.py`、`certificate.py` 均按冻结字节导出并读过；其中 `certificate.py` 是导入依赖，本入口不调用其验证器。没有第三方数值库、浮点LP、随机数或外部服务。

`check(instance)` 可接受规范 `Instance`。模型验证非负整数人数、正整数客户重数、合法主题索引和互异非空标签；允许空覆盖主题、覆盖相同的不同标签及空兴趣客户类型。正人数要求至少一个主题。它不支持混合SPE或非整数客户质量；重数不改变单位客户含义。`check` 对零人和一人根本没有可比较的前后非终局阈值，直接返回 `None`，这不证明任何非平凡单调结论。

本入口的固定输入有三名提供者、六标签 (X_0,X_1,X_2,Y_0,Y_1,Y_2)、18种兴趣类型、36名单位客户：9种跨组二元兴趣各一人，9种各组各选两标签的四元兴趣各三人。完整输入与既有[三人聚合末位保底反例](<../../../../archives/customer-attraction/state/反例/三人聚合末位保底--反例.md>)相同；不是新构造或新half反例。

# 循环究竟检查什么

`compositions(length,k)` 先遍历长度为 `length` 的弱递增主题索引序列，再统计每个索引的次数。它恰给出每个总和为 `length` 的非负 (k) 维计数向量一次；不是遍历全部有序历史，更没有把一份策略在同计数节点的行动绑定。

`check` 的循环为：

1. `length in range(instance.players - 1)`，即 (0,\ldots,m-2)。这保证插入后 (b+e_a) 仍是非终局，`threshold(child)` 有定义。长度 (m-1) 的背景没有被检查，因为再插入就到终局。
2. 每个背景精确计算全部 (k) 个 (F_b(a))，求最大值和 (M(b))。`Fraction` 使用任意精度整数有理数；没有容差。
3. 按标签顺序遍历**所有**达到相同最大值的主题。仅当 `after > floor` 时返回结果，严格上升即足够；平局上升方向不被误作反例。
4. **第一次分离立即 `return`**；若走完指定范围未找到，返回 `None`。它不收集全部分离点，也不穷尽不同目录或不同客户重数。

对三人六主题输入，若不提前返回，外循环仅会有空背景和六个单主题背景，共七个计数背景。实际第一个空背景中主题0就给分离，因此脚本没有继续检查其余最大主题或六个非空背景。底层 `threshold(0)` 的完整逆归纳确实计算所需全部孩子 (R)；这不能改写成外层候选检查已跑完七个背景。

# “证书”的准确含义与独立性

输出提供有限输入、具体背景、最大单例值、前后阈值与两个终局集合，是可以回算的**阈值分离数据**。它没有 `actions` 字段，没有调用 `solver.certificate()` 或 `verify_certificate()`，没有给每个有序历史的完整策略表。因此原断言中的“36-customer certificate”不能解释为本文件新生成并逐节点认证了完整SPE。

本轮原入口重放继续依赖同一冻结 `ExactSPESolver`；它与历史JSON一致是可复现性证据，**不是独立实现相互验证**。终局集合的全SPE含义由既有[递推证明](<../../../../archives/customer-attraction/state/算法/完整历史纯SPE终局全集--算法.md>)承担；36客户原完整43节点策略及其独立定义级核验由[原反例](<../../../../archives/customer-attraction/state/反例/三人聚合末位保底--反例.md>)和[静态安全核验](<../../../../archives/customer-attraction/state/计算/静态安全值与聚合保底的精确核验--计算.md>)承担，不能并入本程序的新运行计数。

原representation README还给解析分类：插入首主题后第二人重复该题的可保证收益9，同组新题的值12，跨组新题的最小值10，故孩子门槛12；根每个主题都可以被两名后继选另一组不同主题压到10，而不存在更低的该首人SPE收益，故根门槛10。这个解析依据与程序输出一致；本对象保存程序合同，不把两处同源描述伪作两份盲审。
