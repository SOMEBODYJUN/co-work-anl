# NP末端与首降三原审计的准确复现

三相关原代码14857B由Root正常取得，全部字节/函数/导入/内嵌输入及输出读齐核SHA256/size/blob；四canonical依赖25475B同SHA缓存全部再次全文核，完整导入闭包仅标准库和这四个模块。相关代码/报告不在本五MD primarydone里。未见这三个原入口的充分同SHA先前成功，因此当前每个原CLI在各自新空source-root原布局**只一次**exit0，断言开，源/依赖前后SHA同，未预放任何冻结输出/输入，stderr空、0失败。

输入是原code内嵌参数域和random.Random种子/标准库算法，不读JSON/CSV/命令行文件；原程序没有导出每个随机实例或其完整策略表，故当前不编造这种原输出。冻结原代码、精确Python版本、完整依赖和种子保可复现生成，事件另存真实调用环境，不把旧报告叫输入。

## 四模块的真实职责

`customer_attraction/__init__.py`691B导model/exact/certificate；model8640B把整数multiplicity当不同单位客户，允许空覆盖、同覆盖不同label，收益按真实终局计数Fraction；exact9943B求完整可实现终局**集合**，threshold=max_a min_child u_a，保每个达threshold的child终局，可恢复任意历史依赖纯SPE，不限Markov。certificate6201B被导入以提供完整动作图类型，含独立verify函数，但这两原main**没有调用**verify_certificate，不能说当前已运行该泛型独审。

原main取`certificate(min(solver.worst_outcomes()))`，先最差福利终局集合再lex最小counts，展开每有序历史一份策略；不枚举所有完整SPE map。canonical虽缓存count集合，恢复时各有序history允许不同孩子，不等于把同计数策略强行识别。2043原pivot入口完全不导canonical，只显式单位集合算clone末位与核。
