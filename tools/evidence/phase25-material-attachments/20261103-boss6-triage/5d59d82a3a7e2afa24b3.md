# 原件与程序实际问题

[原3726B代码](<../../../../archives/customer-attraction/tools/evidence/two-pool-tail-search-program/original/two_pool_tail_search.py>)的SHA256为 `f268d9322c947d4bf805397b2c489f7f310b81966c9f4d8b8378bfb93376746e`，两冻结提交相同。直接依赖只有标准库 `itertools,pathlib,json` 和NumPy，不调用LP、规范ExactSPESolver或任何仓库模块。本次已完整实读三个函数 `coefficient_tables,test_parameters,main`，没有把429B输出字段当作代码语义。

它检查的是一个固定背景后的**三名尚未行动者**，以及指定尾路径能否由这个子博弈的某份完整纯SPE支持。对该三人尾，它保留全部合法动作和任意平局，判据是精确充要条件；对原六人游戏，它只是必要条件，因为前面三名玩家的偏离尚未检查。`survivors`若非空也只表示通过这项尾局条件，不是六人策略证书。

本次唯一原main在隔离副本中运行约16.87秒，809个批次完整结束；生成429B JSON与冻结输出逐字节相同。[执行事件](<../../../../archives/customer-attraction/tools/evidence/two-pool-tail-search-program/rerun/execution.json>)及[被动批次记录](<../../../../archives/customer-attraction/tools/evidence/two-pool-tail-search-program/rerun/captured-batches.json>)保存原代码和输出指纹、真实函数调用次数与门槛分布。它们不是第二次独立搜索；独立客户定义核验由配套数据任务另行保存。

# 客户块、主题和候选路径

沿用[共同目录完整历史模型](<../../../../archives/customer-attraction/state/定义/共同目录完整历史模型--定义.md>)：客户和玩家均单位权，客户价值在终局覆盖者间均分，策略观察全部有序历史。块大小表示这么多个不同单位客户，不是一个带权不可分客户。目录非空，允许重复行动、空主题、覆盖相同的不同标签，以及任何离轨历史上的弱平局。

先给函数构造的一般参数。令旧组数g为非负整数，k=g+1，有k个组；各组有两两不交客户块X_i、H_i，大小分别x、a。另有四块P₁,Q₁,P₂,Q₂，大小b₁,d₁,b₂,d₂。六个大小均为非负整数，所有这些块彼此不交。定义

\[
A_i=X_i\cup H_i,\quad B_{i1}=X_i\cup P_1,\quad
B_{i2}=X_i\cup P_2,\quad C_i=X_i,
\]
\[
D_1=P_1\cup Q_1,\qquad D_2=P_2\cup Q_2.
\]

“双池”指这两套公共尾支持块；不是只有两名客户或两种主题。标签共有p=4k+2个，按每组 `(A_i,B_i1,B_i2,C_i)` 后接D₁,D₂排序，组索引从0开始。旧前缀固定为 `(C₀,…,C_{g−1})`，所以旧X组负载1、新组X_g负载0，其余块尚未覆盖。只剩三人行动，候选尾为 `(C_g,D₁,D₂)`。

默认main固定g=3、k=4、p=18，主题索引如下。

| 索引 | 标签 |
|---|---|
|0,1,2,3|A₀,B₀₁,B₀₂,C₀|
|4,5,6,7|A₁,B₁₁,B₁₂,C₁|
|8,9,10,11|A₂,B₂₁,B₂₂,C₂|
|12,13,14,15|A₃,B₃₁,B₃₂,C₃|
|16,17|D₁,D₂|

完整候选六行动为 `(3,7,11,15,16,17)`；程序只从前缀 `(3,7,11)` 往后检查。候选尾首人选择C₃后没有后继碰X₃，所以其收益恒为x=6；这就是 `root_ok` 比较的阈值，不是凭空给定的安全值。

若仅把这条完整路径作为终局，其覆盖为 `W=4x+S=24+S`，其中 `S=b₁+d₁+b₂+d₂`。六主题 `(A₀,A₁,A₂,A₃,D₁,D₂)`覆盖所有客户，故该目录的 `OPT₆=4(x+a)+S=40+S`，从而 `W/OPT₆=(24+S)/(40+S)≥3/5>1/2`。这些是本页从集合定义推得的数量，程序没有计算W或OPT。源码注释“targeted5/3”来自a/x=4/6，以及固定S复制组数时 `(k(x+a)+S)/(kx+S)→5/3` 的目标；不能当作当前六人福利比，更不能当作SPE近半反例。

# 终局整数收益表：全部5832个有序三行动

`coefficient_tables(g)`枚举所有 `(r,s,t)∈{0,…,p−1}³`，包含重复标签，不将相同覆盖标签去重。对每个有序叶及三个位置建立六维系数，返回 `topics,coeff`，数组形状为 `(3,p,p,p,6)`，dtype为int16。默认包含5832叶、104976个整数系数。

固定一个叶，设 `n_X(i)=1_(i<g)+尾部选择组i任一主题的次数`，`n_A(i)=尾部选A_i次数`，`n_B(r)=尾部选任何B_ir或D_r次数`，`n_D(r)=尾部选D_r次数`。一名尾玩家的收益完整为

| 所选主题 | 收益 |
|---|---|
|A_i|x/n_X(i)+a/n_A(i)|
|B_ir|x/n_X(i)+b_r/n_B(r)|
|C_i|x/n_X(i)|
|D_r|b_r/n_B(r)+d_r/n_D(r)|

表中只在该主题实际被选时计算，故列出的各分母都正。X分母最多旧1加尾3等于4；A、公共B、D分母最多3。因此12同时整除所有可能分母1、2、3、4；源码的 `12//load` 是精确整数商，而非向下近似。前缀旧玩家也分走X的价值，其负载已计入；程序只省略它们的收益输出，并没有省略拥挤作用。

六维参数顺序固定为 `(x,a,b₁,d₁,b₂,d₂)`。例如A行只用第0、1槽，B_i1用第0、2槽，D₂用第4、5槽。`test_parameters`把批参数转为int64二维数组，再作

```python
values = np.einsum('rabcv,nv->rnabc', coeff, pars, optimize=True)
```

得到三个位置、每个参数、每个有序三行动的**12倍**收益，默认形状 `(3,n,18,18,18)`。optimize仅选择张量收缩顺序，整数dtype保持精确，没有浮点比较或容差。批128时这个主值数组为17,915,904字节，另有最佳回复掩码和中间数组；不是全部十万参数同时物化。

在默认x6、a4及四池0…18域，单人真实收益至多max(10,24,36)=36，缩放后至多432；系数至多12。因此本域的int16系数及int64收益安全，排除掩码的哨兵 `10**12` 也严格大于所有合法值。函数本身不验证任意外来参数的整数性、非负性、六列形状、溢出或哨兵界；尤其转int64不是一般有理数接口。扩大参数域必须重新检查这些实现条件，不能把本有限精确性升级为任意精度整数实现。

# 三层可信过滤与全部平局的自足证明

下文省去公共缩放12。固定一个参数以及一个首动作r，分别记三个尾玩家在叶(r,s,t)的收益为U₁、U₂、U₃。

先求每个有序历史(r,s)的全部末位最佳回复

\[
BR(r,s)=\arg\max_t U_3(r,s,t).
\]

源码 `last_ok = last == best_last` 保所有相等最大值，没有任选一个代表。每个集合非空。再定义

\[
\lambda_r(s)=\min_{t\in BR(r,s)}U_2(r,s,t),\qquad
\theta_2(r)=\max_s\lambda_r(s),
\]
\[
E(r)=\{(s,t):t\in BR(r,s),\ U_2(r,s,t)\ge\theta_2(r)\}.
\tag{1}
\]

代码依次用 `next_min,next_floor,next_ok` 实施(1)：非最佳末回复填大哨兵后取min；对第二行动取max；再在全部末BR叶中保第二玩家收益**大于等于**门槛的叶。

(1)恰是首动作r之后全部两人子SPE的有序结果。必要性：所选末位须BR；对任一第二行动s′，原策略在该孩子选某个BR，其第二收益至少λ_r(s′)，故实际第二收益至少θ₂(r)。充分性：对要实现的(s,t)，在选定孩子用t；其余每个s′独立选达到λ_r(s′)的BR，便将所有偏离收益压在θ₂(r)以内。全部末节点仍是BR，故构成完整两人子SPE。它允许依历史独立破平局，而非强制相同负载节点选择同一动作。

E(r)非空：取达到max λ的s，该孩子任一BR都使第二收益至少λ_r(s)=θ₂(r)。因此后面的最小化总有真实候选，哨兵不会成为答案。

然后对首人计算

\[
L(r)=\min_{(s,t)\in E(r)}U_1(r,s,t),\qquad
\theta_1=\max_rL(r).
\tag{2}
\]

源码 `root_min`在所有不满足next_ok的叶填哨兵，再对第二、末动作两个轴取min；`root_floor`对首动作取max，返回的是12θ₁。`root_floor`不是收益最大的可信尾、任意后继都成立的保底，也不是完整SPE数量；它是首玩家在所有可信离轨续局选择下的最低支持门槛。

对于指定首动作r*和指定两尾(s*,t*)，存在一份完整三人子SPE实现该有序路径，当且仅当

\[
(s^*,t^*)\in E(r^*)\quad\text{且}\quad
U_1(r^*,s^*,t^*)\ge\theta_1.
\tag{3}
\]

必要性由实际孩子可信及所有首偏离的下界L(r)得出。充分性是在选定孩子实现该(s*,t*)；每个其它首动作r独立采用E(r)中达到L(r)的一份两人子SPE。由(2)所有首偏离都不超过θ₁，故首人也最优。有限性保证所有argmin达到，子树是不同有序历史，不发生跨孩子策略冲突。

这正是[完整历史终局全集递推](<../../../../archives/customer-attraction/state/算法/完整历史纯SPE终局全集--算法.md>)在三层上的数组实现；它枚举有序叶及可支持性，不枚举完整策略映射，也没有输出拼接得到的动作表。所有弱平局都保留。零块可使不同标签覆盖相同或主题为空，仍分别参与max/min；全零参数时所有叶及指定路径都可支持，虽然默认主搜索并不包含x=a=0。

本程序取r*=15、s*=16、t*=17。`fresh_c=len(topics)-3`、两个D取末两个索引，所以 `tail_ok=next_ok[:,15,16,17]`；`root_ok=root_floor<=12*pars[:,0]`。返回三数组依次为 `(root_ok & tail_ok,root_floor,tail_ok)`；第二项必须除12才是收益门槛，第三项只检查指定末两步而不含首人的IC。

# 确定性搜索域、预滤和写出合同

main只使用g=3、x=6、a=4，四个池大小 `(b₁,d₁,b₂,d₂)∈{0,…,18}⁴`，共19⁴=130321个整数点。没有随机种子或随机抽样，没有连续优化、对称轨道删减、参数交换归一化或早停。它按product字典序生成四元组，先筛

\[
2(b_2+d_2)\ge6+b_1,\qquad d_2\ge3.
\tag{4}
\]

(4)是指定完整路径最后一人的两个必要BR比较。到D₂出手时四个X组都已有一次覆盖，P₁已由D₁覆盖，P₂尚未覆盖。D₂收益b₂+d₂；改任一B_i1收益 `6/2+b₁/2`，改B_i2收益 `6/2+b₂`，正好给(4)。因此预滤删掉的参数确定不能支持该指定尾，不是启发式去除潜在成功者。预滤不含所有末位比较，例如A_i给收益7，D₁也可被查询；后面的18动作全末BR检查才补齐这些条件。

通过预滤有103474点，其余26847点不进入BI。每128点一批，共809批，前808批各128、最后50。`checked`每批加真实batch长度；`eligible`加tail_ok为真的个数；`survivors`只收两条件都真的参数，并保存 `root_floor_times_12` 整数。这些计数分别是参数点数，不能理解为SPE数、策略数、终局数或不同目录的同构类数。

程序没有参数解析器：直接执行会跑上述全部固定搜索；没有 `--verify`、输入JSON或调整x/a/range的命令开关。main通过 `Path(__file__).with_name('two_pool_tail_search.json')` 写源码同目录的JSON，会覆盖同名输出；导入模块因main guard不执行搜索。若要复现，应把未改原件放在新目录，避免覆盖已保存结果。两个公共函数可用于其它参数，但不会因此扩大主搜索报告的认证范围。

输出JSON全部字段为scope、old_groups3、fresh_groups1、x6、a4、pool_range[0,18]、parameter_order、pre_filter说明、prefilter_pass、exact_BI_checked、actual_D1_D2_tail_supported、survivors。JSON保存完整survivors；stdout先打印去掉survivors的缩进JSON，再打印 `survivors` 数量和前五条Python列表repr。因此stdout整体不是单个JSON文档，不能把最后“前五”误当文件截断。
