源 ID 为 `6fe2930bc934a6386fbe`，冻结字节数 6524，SHA-256

与既有《归一化门菜单福利与对数调色板 padding 有限审查》相比，本源的独有内容是

也不把报告作者声称的执行冒充为本次重新运行。

## 2. 输入模型与版本边界

报告把目标程序固定为
`co-work-anl-boss11-negative/tests/audits/unrelated_machines/normalized_gated_menu_welfare.py`。
初始实读版本 SHA 为
`11dca801e3ae81aa45042c883a55dedb1bf729fc03152fad75a2575bf0b9084d`，
当前复核版本 SHA 为
`31aeb2b57bbf78e0f980f552bd5985e4f0a15b57f98f93f46be1296a19b156f6`。
报告明确指出：首次进程是在源码替换后启动的，不能把新版输出回填为旧版执行结果。
因此版本差异是证据的一部分，而不是可忽略的注释。

对象仍是归一化 gated-menu 的有限显式输入：有限组、资源、indexed states、菜单
系数、`lambda/z/x` 和完整原 jobs。零 incidence job、显式零 job、未选 state、unused
resource、重复 state 均保留。报告同时复述既有实现边界：有限有理数输入、有限列举和
精确 `Fraction` 断言；`production_lp_solver`、任意输入成功保证、一般 UM solver、
source hardness 均不由这批运行建立。

## 3. 有理 LP 证书与 welfare/price 双重检查

SciPy/HiGHS 的输出只作为有理化候选。每一行候选经
`Fraction(...).limit_denominator(10**8)` 后逐式检查：primal 非负、全部等式、upper-bound
dual 非正、reduced cost 非负和 primal/dual 目标精确相等。因此对报告列出的有限 LP
实例，成功行有精确有理最优性证书；不能把这个流程写成任意有理输入的通用精确 LP
后端。分母过大而无法被候选有理化的合法输入也没有 fallback。

报告还把序列化 dual 转成福利价格：链接价 `a>=0`、资源价 `b>=0`、组价 `eta`，
检查正 incidence 上的 `a+b_u>=p` 与每个 state 的
`eta_g>=sum_u a_gsu`，并验证 `sum b + sum eta` 与精确可行 primal 福利相等。
72 个 general certificates 和 3 个 coin fixtures 通过该检查；supplied nonbasic
point 被另外检查为可行且目标相同，不能误写成 certificate 的 basic primal 就等于
supplied nonbasic point。两条 `2^200+1` 分母 fixture 使用源给定的精确最优点，
不依赖浮点候选。

这些内容补强既有审查中“finite exact certificate”的证据层级。它们仍是列出实例的
条件结论；没有给出 `limit_denominator` 对所有输入都成功的量词，也没有产生通用
舍入定理。

## 4. 期望、coin 与完整 jobs 的独立重算

源报告核对 `expected_max_sum` 的按高度积分：同一组内 state 相关性合并在该组分布，
组间独立才用于乘积；固定 state 后只在正 `z` 上选择，避免除零。coin 阶段在所有
state 固定后执行，每步 state/coin 平均都以 `Fraction` 精确相等断言，tie-breaking
也保持有理比较。

报告称其另用完全枚举的 state/coin outcome 期望替换原高度积分，重算 36 support、
72 general、3 nonbasic 和两条大分母 fixture：共 113 个实例、904 次独立期望评估，
并逐件重算全部 113 个实例的 private/root/resource loads 与总 jobs。这个独有数字应
与既有 JSON 的 `all_rounding_cases_with_independent_outcome_expectation=113`、
`independent_expectation_calls=904`、`all_jobs_load_rechecks=113` 对照使用，不能
把 113 当作参数族的大小或一般完备性证明。

实际 bundle 每资源只给最高正 offer 的一组，不能声明“所有组都交资源”；报告只允许
改用 attaining state，值只能增加。selector、connector、所有 indexed-state
incidence（包括 unselected state 和显式零 job）均保留，这正是既有
`OPT=2-beta*` 门控回填语义所需的任务身份。

## 5. 普通 UM 穷举和负控制

报告独立重建普通任务资格，没有复用目标程序的 `build_gate`、`brute_gate_opt`、
`exhaustive_values`、`actual_values` 或 `balanced` 来证明普通任务最优性。它对十二个
小实例逐项访问全部合法完整调度，计数为

```
8, 64, 16, 256, 24, 576, 96, 9216, 8, 64, 16, 256
```

总数 10,600。每例都得到相同 `beta_opt`，且真实普通 UM 最优值等于 `2-beta_opt`，
与原搜索结果相符。这是十二个固定小输入的 exact replay，不是通用 UM optimizer 或
归约证明。

负控制必须独立标为原模型边界：两组、每组一个 state、一个资源、所有 private time
为 1 时，flat optimum 为 2，而 gated optimum 为 `3/2`；新版确实调用真实 gated
搜索，报告又无剪枝枚举 4 个 flat、64 个 gated 合法调度，重得 2 与 `3/2`。这说明
门控在该输入改变了原 flat 问题；不能把 `3/2` 外推为所有 gated menu 的改善，也不能
把 gated 保证反推给 flat 模型。

## 6. 大分母、输出保全与证据级别

两条大分母 fixture 使用 `2^200+1`：一条含两个零 incidence job、`n=1` 和两 state，
另一条两组共享资源，coin 为 `tiny` 与 `1-tiny` 并实际进行两次非平凡 coin 决策。
它们验证有理表示、给定 LP witness、bundle 值、全部 jobs loads 和独立资源最优枚举，
但不提供关于分母位长的复杂度界。

在已有输出路径再次运行新版 CLI 时，入口以 exit 2 拒绝覆盖，输出 SHA 前后保持
`2b40b0bc6e3b11a3bf1a3b6f678873873d0a12ec6d29e404cbfd8f41b30ebe86`；写入还用
exclusive `open('x')` 防止检查后的竞争覆盖。该字段是证据保全和复现合同，不能被
误读为数学最优性。

证据分级如下：

- **完整有限证书：** 列出的 LP primal/dual、期望、负载和调度枚举均按报告范围提供
  精确数据；
- **条件结论：** 输入满足该 gated-menu 语义、对应行的约束和舍入前提时，可使用该行
  的 welfare/peak/beta；
- **有限实验：** 36/72/3/12/2 分层、113/904/10600 等是固定运行计数；
- **障碍：** 两个 fractional-`z` 行出现 `output_welfare` 与 `welfare_opt` 差距，且
  `production_lp_solver=false`；这阻止把有限证书升级成一般舍入或求解定理；
- **候选：** 负控制和大分母 fixture 可继续用于构造失败族或压力测试，但当前不是
  参数族和反例证明。
