# 首轮与增量研究的执行流程

每一轮都要形成明确主判断。流程的长度来自必须解决的问题：资料取得、口径统一、学习观点、检查传导、测算量级、裁决与写作分别完成，并留下可接续的实质产物。阶段完成后立即保存；发现新问题回到受影响阶段，不把整个项目重做一遍。

执行分工与超边的经济裁决见 `docs/AGENT_PLAYBOOK.md`，具体派工用 `prompts/06_SPECIALIST_TASK.md`；观点的原文、竞争解释与阅读任务见 `docs/VIEWPOINT_PROGRAM.md`；科学评分与概率模型执行 `docs/SCIENTIFIC_MODELS.md`。这些阶段是依赖与提交里程碑，采集、观点学习、专题分析和建模应按争议交错回流。程序的文件和版本校验之后，还要完成表内实质研究的独立审查。

## 首轮 Pro：20 个阶段

阶段 ID 是程序实际采用的 ID。每阶段的 `--files` 传入工作区内相对路径；正文、原始输入和复算脚本一起保存。表中路径是建议组织，不是要求制造空文件。

| 阶段 ID | 必须读什么 | 必须做成什么 | 提交点与退回条件 |
|---|---|---|---|
| `s01_scope` | 用户问题、当前提示词、已有项目状态 | `research/scope.md`：事件定义、研究截点、核心问题、家庭决策问题和责任分工 | 完成后提交；“2027年必爆发”“十年必熊市”没有作为结论预填 |
| `s02_inventory` | 输入简报、证据表、方法手册、旧研究索引 | `research/inventory.md`：已有来源、来源家族、可复用时序、决定性缺口、待搜索问题 | 完成后提交；不重扫原 1214 份文件，不把47行算成47份独立来源 |
| `s03_acquisition` | 已有检索记录与 P0/P1/P2 缺口 | 原始发布、真实时序、检索记录、事件去重簇、数据字段词典 | 每个研究批次保存；原发布更新、旧检索过期、缺少决策变量时继续定向补采 |
| `s04_vintages` | 原始表、发布时间、统计期、各版本 | `research/data_reconciliation.md` 与可用面板：修订、存量流量、同比环比、名义实际、全国城市全部对齐 | 口径改变使受影响分析退回；不能靠平均掉冲突来消除矛盾 |
| `s05_methods` | 仓库工具说明、锁定版本、接口、许可、输入要求 | `research/method_runs.md`：实际运行、原始输入、结果、采用范围、未采用原因 | 每个选用方法留下实际运行；接口接通和真实中国经济估计分别记账 |
| `s06_viewpoints` | 学者原文、工作论文、长篇分析和可追溯 GitHub 研究 | `research/viewpoints.md`：理论视角、机制、隐含假设、历史检验、可借用分析动作 | 学到一个有用机制就保存；不按粉丝数、赞数、危机态度排专家 |
| `s07_property` | 量价租、库存、开发商现金流、城市分化 | `research/property.md`：冲击发生在哪、谁承担损失、成交与资产价格路径 | 全国数据不能替代用户城市；价格、交易量、投资分别判断 |
| `s08_fiscal` | 土地净资源、预算、转移支付、LGFV、债务期限利息 | `research/fiscal.md`：地方现金约束、展期与减债区别、政策资源和时滞 | 毛土地收入不能直接等同净可用财政资源；置换不记为债务消失 |
| `s09_households` | 居民收入分布、偿债、就业工资、企业利润回款 | `research/households_firms.md`：居民和企业分组、消费投资传导、就业收入路径 | 不用平均资产判家庭安全；经营收入、工资收入分开建模 |
| `s10_banks` | 银行分组、关注逾期不良、拨备资本、净息差与期限 | `research/banks.md`：损失承接、流动性与偿付、显性和延后损失的机制 | 每个“银行危机”判断回答敞口、损失、缓冲和触发；不把房价降幅当坏账率 |
| `s11_external` | 出口增加值、汇率、能源、全球金融、政策实施资料 | `research/external_policy.md`：抵消与放大因素、资源、执行规模、到账时滞 | 同时审已发生的缓解与压力；只宣布未执行的措施不写成实际效果 |
| `s12_history` | 事件定义、可比案例原文、历史时序 | `research/history.md`：日本/韩国/香港/美国等对照、相似起点、制度差异、失败类比 | 用案例解释机制和恢复变量；不能直接移植年份、系数或市场回报 |
| `s13_graph` | 前述专题与观点卡 | 联合前提超边、替代因果链、反馈与阻断条件；每条边能定位正文和证据 | 新前提、新反证或机制改动使下游待复核；同一新闻不因多边使用被算成多份证据 |
| `s14_models` | 通过口径整理的时序、超边、方法运行 | `research/model_results.md`、输入、脚本和输出：基线、即时活动、部门现金流/损失测算、敏感性；采用评分/概率时另交模型卡和留出验证 | 有新数据和参数变更时定向重算；执行科学建模规范，拒绝任意赋权和未经检验的概率映射 |
| `s15_adversarial` | 承重主张、最强支持证据与最强反对解释 | `research/challenges.md`：独立论证、证据挑战、替代机制、现实量级和逐条回应 | 尚有会逆转主判断的可解决争议则回研究；不以投票或对称措辞结案 |
| `s16_verdict` | 图、专题、测算和挑战结果 | `formal/judgments.json` 与 `formal/scenarios.json`：核心问题逐项裁决、主路径、时间窗口、反转条件 | 必须选出主判断；无校准概率就给排序与方向，不杜撰百分比 |
| `s17_writing` | 已裁决判断及能支撑它的原始来源 | `formal/report.md`：有主线、传导、历史、情景和家庭行动的成稿 | 写作暴露机制缺口就补分析；不得把报告写成资料罗列或免责书 |
| `s18_calculator` | 情景参数、贷款合同逻辑、家庭输入规范 | `formal/calculator.html`、引擎源文件、独立对照、策略运行结果 | 真正逐月计算、真实策略枚举和离线交互；现金失败不能虚算十年终值 |
| `s19_audit` | 冻结的报告、判断、参数、代码、复算输入与输出 | `research/final_review.md`：事实口径、因果量级、计算、文字以及离线操作的逐项结论 | 审查绑定内容版本；拒审、文件改动、反证未处理必须修复再审 |
| `s20_release` | 当前版本全套产物和审查回执 | 发布清单、研究状态、简短变更记录、下一轮高价值问题 | 最后实际从新目录恢复、复算，再提交发布；每项“完成”对应真实文件 |

研究过程中发现新资料，先入库，再更新受影响的专题、超边、测算和裁决。若一个批次同时影响两个专题，采集一次，两个专题引用同一 ID。数据更新不要求重新搜索全部问题。

## 后续 agent：8 个阶段

增量工作保留当前正式版及其基准版本，在已发布的同一工作区运行 `init --mode update` 进入下一周期；新 clone 恢复同一工作区路径与状态后也采用这个入口。每个 agent 处理一组有共同传导关系的问题，给出可合并修改；主代理串行更新正式版。

| 阶段 ID | 实际工作 | 实质提交 |
|---|---|---|
| `i01_restore` | 读当前主判断、原始证据、图、最近相关修改和未被采纳的旧反对意见 | 基准版本、所领问题、受影响范围；恢复既有断点 |
| `i02_delta` | 先查事件簇、来源版本与检索记录，确认哪些资料已存在、哪些已更新 | 新增信息清单与复用清单；零结果检索也保留，防止重复空搜 |
| `i03_research` | 定向补采、深入学习新方法/观点、跑相关测算、比较新旧机制 | 新证据或新推理的明确增益；没有改变判断也提交有内容的保留理由 |
| `i04_proposal` | 对旧主张和传导链提交保留、加强、削弱、替代或撤回提案 | 基准 revision、旧句、新句、理由、证据/方法、边与参数、受影响下游、重算任务 |
| `i05_review` | 独立读实际承重材料，攻击提案最关键一步，检查是否忽略旧历史；运行 `proposal-review` 登记提案审查 | 通过/拒绝及具体理由；审查绑定当前目标与来源版本，反转要回应上一次选择旧观点的理由 |
| `i06_merge` | 主代理核对基准未过期，串行合并被接受部分 | 正式正文、图、判断和参数的具体补丁；不自动接受 agent 的自报通过 |
| `i07_replay` | 重跑受影响计算、情景、家庭策略及交叉引用 | 新旧结果比较；新目录恢复后仍能得到同一结果 |
| `i08_release` | 冻结当前版再审，提交新版本和下一轮问题 | 更新版成品、简短变更说明、保留和驳回依据 |

一次深化可以改变一个机制，不必等所有新闻更新。新观点如果只是重述，保留旧版并说明其没有增加解释力；如果改变政策传导、群体分布、损失承担者或时间结构，就把这些具体变化写进提案。不能仅为产出差异反复反转。

## 保存与协作

运行入口是 `python crisis.py --workspace work/<run>`。首次 `init --mode first`，后续周期 `init --mode update`；`status` 恢复当前状态；`stage --id <阶段ID> --files <相对文件...> --note <实质结果>` 保存阶段回执。模型先写成产物，再登记阶段。阶段回执记录实际内容的版本，不能用空白文件通关。

提案使用 `proposal --file <JSON文件>` 登记，独立复核者用 `proposal-review --id <提案ID> --verdict pass|reject --reviewer <复核者> --note <实质意见>` 保存裁决。只有绑定当前目标和来源版本的通过审查才允许 `apply --id <提案ID>`；拒审的提案保留拒绝记录，修改内容后使用新提案ID。目标、来源或补丁文件版本变化时，重新比较并提交新提案，不能沿用旧审查。

已存在图节点后，新入库证据必须注明 `targets: [<受影响节点ID>]`，包括削弱旧判断的反证。若确实不影响现有节点，写 `targets: []` 和具体 `impact_note`，不能漏挂后仍把旧判断当成已处理。新材料的事实、观点、数据和方法类型也保留在入库对象里。

发布文件复核与提案审查分别记录。完成全部阶段后，对当前版本运行 `review --verdict pass|reject --files <正式文件...> --reviewer <复核者> --author <作者> --note <实质意见>`；通过后用 `release --files <同一正式文件...> --judgment <明确主判断>` 发布。先完成实读和运行，才登记通过。

JSON与文件路径遵守实际接口：`--file` 是执行命令时可读的JSON路径；`raw_file`、阶段 `--files`、提案 `files[].path` 和发布文件采用工作区内相对路径。不要把仓库根相对路径误当工作区路径。

| 对象 | 实际字段 |
|---|---|
| `ingest` 记录 | `id`、`kind`、`url`、`source_family`、`published_at`、`text`或`raw_file`；`kind`为`fact/observation/dataset/opinion/method`，前三类要求`observation_period`；可附`event_id`，已有节点后必须显式`targets`，空列表附`impact_note` |
| `search-log` | `query`、`topic`、`period`；可附`executed_at`、`results`和已入库的`result_ids`；零结果保留空结果并说明具体检索范围 |
| 图节点 | `id`、`kind`、`statement`、`evidence`；类型`fact/judgment/opinion/action/method`；证据ID必须已经存在 |
| 联合超边 | `id`、`tails`、`head`、`mode: "ALL"`、`conditions`列表、`counterevidence`列表、`mechanism`、`falsifier`、`lag`；前提和反证引用已有ID，后件引用已有节点 |
| 修改提案 | `id`、`author`、`target`、`base_revision`、`action`、`reason`、`old_statement`、`new_evidence`或`new_method`；节点修改提供`new_statement`，边修改提供完整`replacement`，撤回除外 |
| 正文补丁 | 提案`files`列表内各项为`path`、`base_sha256`与完整新`text`；回到旧判断时用`responds_to`回应此前已接受提案 |

`graph-put` 接受单个节点/边、对象列表，或含 `nodes` 与 `edges` 的对象。图中旧对象的实质修改必须走提案；不能用同ID覆盖。程序验证结构、版本和来源类型，研究者仍须判断原文、机制与经济量级是否成立。

每个实质批次及阶段结束提交一次 Git；只加入本轮产物、必要原始输入和复算脚本。批次过大时先保存已完成部分及精确断点。主代理串行 Git 写入和正式版合并，子代理写各自提案文件。多代理分析通过真实调度工具进行；CLI 提供记忆、数据、依赖和工具接口，不模拟模型的独立思考。

用户主要接收研究报告和离线计算器。内部过程保存在仓库，最终答复只报告关键结论、交付位置与实质变更。需要继续研究的问题写为下一轮具体任务，不放入成稿当作逃避裁决的结尾。
