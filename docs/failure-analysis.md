# 全量重建与三轮独立复核的缺陷分析

这套流程能减少遗漏、锚定和版本混淆，并让结论可追溯；它不能证明绝对零错误，也不能用审计文件证明代理真正仔细看过原图。验收要同时看内容证据、完整性、身份与版本，不接受只看一个“通过”标记。

## 关键失败模式与对应约束

| 失败模式 | 为什么会失效 | 防范与可观察的检查 | 仍存的限制 |
| --- | --- | --- | --- |
| 把最多三份并行误解成同一份由三人随意交叉改 | 文件互相覆盖，作者和审阅者混为一体 | 笔记级活跃集合上限为三；每份每时刻只有一位轮次责任人；子代理只写独立目录，总协调者合并 | 仍须核查实际调度，日志本身可失真 |
| 用空位立即接下一份，突破用户的批次顺序 | 前一批未审计完，后续笔记已经展开，责任与进度难以核查 | 固定第1—3、4—6、7—9、10—11份；本批全套结束才进下一批，资源不足只降低本批内部并发 | 本批一份真实工具阻塞会延后下一批；字形未决必须留在模型恢复循环中，不能伪装成工具阻塞 |
| 同一代理连续看三次，自报“三轮独立” | 先前判断持续影响后续结果 | 同笔记每轮创建此前未参与的新实例，记录实际代理 ID 与创建事件；作者和修订者也不复用为其后续独立审阅者 | 新实例可能共享模型偏差，不等于统计独立 |
| 声称清空上下文，却把答案藏在任务包里 | 旧稿、前轮结论和“快通过了”的暗示产生锚定 | 原图先读后提交记录，再发冻结稿和旧稿；屏蔽前轮结论与稳定计数；记录实际暴露情况 | 无法取消已继承的信息；无法严格屏蔽就披露限制，不虚报盲读 |
| 硬编码未提供的工具或参数 | 产品名和文档样例不等于本环境实际能力 | 先检查实际工具签名与结果；`fork_turns='none'` 仅在明确支持时使用；缺少独立子代理能力就不给独立复核证书 | 平台能力可能变化，提示词不能替平台创造能力 |
| 只读取 OCR 或 PDF 文本层 | 可能丢掉笔迹、边注、公式和图形 | 逐页实际看原图，必要时放大；原图证据定位，OCR 仅辅助 | 视觉识别仍会错；扫描源也可能不足 |
| 把生成六张裁图当成已经检查充分 | 默认区域可能切断长式子、箭头、页边字，文件存在也不代表被查看 | 全页先看，默认六重叠区只是起点；额外局部图实际查看，跨区与跨页对照；每区由两位不同新代理完成两次视觉检查 | 两次检查仍不能保证没有共同漏看 |
| 把第二遍区域检查充作最终三轮之一 | 在未定稿版本上的检查无法认证最终文件 | 作者首遍、第二位新线程全区检查、修订锁定、再由另外三位新线程连续全量复核，阶段分别记录 | 修改会增加审阅成本，不能为省成本挪用旧报告 |
| 来源表只有已识别内容 | 遗漏区域根本没进表，表内“全覆盖”是假完整 | 对页面做独立版面检查，从原图向新版和从新版向原图双查，特别查页边和跨页边界 | 单元划分仍依赖判断，不能只靠数量校验 |
| 只有一份整理稿，没有忠实转写层 | 无法区分原文、重排、原错误和后加证明 | 分别交完整 `source-transcript.md`（原页序）和 `study-notes.md`（复习顺序）；来源单元映射到两个目标 | 两个层都需要维护，不能以一个层完整为另一个层删减辩护 |
| 以复习清晰为由删重复、合并两条推导 | 课堂重复、不同证明路线和细节丢失 | 原稿与旧稿的重复均保留；两层稿件都不去重、不合并路线；用户以后另行授权才可改变 | 同一物理对象在重叠裁图中的多个视图可以共用来源ID，这不是删除原稿重复 |
| 只查新版，没有逐项追旧稿 | 旧稿的有用新增或纠错消失 | 旧稿每个单元都要有新版去向与核对状态；独有新增保留为蓝色，标历史来源及未核原图 | 内容保留可能降低流畅度，需分区与辨析而非删除 |
| 把旧稿独有内容一律当 OCR 垃圾 | 旧稿可能包含真实补充、另源内容或此前正确修复 | 无原图支持不等于错误；分别标未核、疑误、已证错误；已证错误也保留辨析和纠正对应 | 来源不明的真实性可能无法最终解决 |
| 用数学通顺性猜定模糊字 | 合理的候选未必是老师写的原文 | 视觉证据和数学推断分开；保留候选与未决；不能因多轮重复猜测升级确认 | 无法唯一恢复时保留候选、位置与证据，继续其余内容；只有原图或视觉工具确实不可用才停止 |
| 自动标准化老师术语 | 改掉课程内部有意义的命名，破坏复习对应 | 保留原词与符号，建立术语表；标准术语只放蓝色补充 | 同一词可能多义，需要逐处语境判断 |
| 纠错时覆盖错误原文 | 无法区分老师原稿、历史误读与模型新增 | 黑色保留可辨认原稿，蓝色写纠正及理由；旧稿也有变更去向 | 文件太拥挤时需良好版式，但不能牺牲来源 |
| 红色兼指错误、空白和看不清 | 失去“原稿留白”的专有语义 | 红色仅为原稿确实留空；不可辨认用中性未决定位标记，候选与证据放独立疑点表 | 源图空白与浅淡笔迹有时也需保留不确定性 |
| 主笔记被蓝色 OCR/来源审计大章淹没 | 复习内容与过程记录混杂，蓝色不再表示教学补充或纠错 | 补充和纠错在知识点就地短标类别；识读、哈希、代理报告等放独立记录；主笔记只保留必要中性疑点ID | 详细证据需要读者通过ID打开独立文件 |
| Markdown 语法上色，实际公式不上色或丢失 | 源文件有标签不等于用户能看出来源 | 检查实际渲染，颜色加文字标签；交付可靠显示三类语义的可读版本 | 不保证所有第三方 Markdown 渲染器一致 |
| 用随机代入宣称证明完成 | 有限样本无法证明一般数学命题 | 有限可枚举问题全枚举，数字正反核算；一般结论给有效推理与条件，数值仅辅助 | 计算工具和证明本身也可能误用，仍需复核 |
| 只查前轮改动 | 未改部分的系统性错误持续遗漏 | 每轮从头到尾看全部页、全部来源、旧稿和新版，改动专项检查不计完整轮 | 成本更高，需要分段保存但不能缩小范围 |
| 三轮各审一部分，合起来冒充三轮 | 没有任何一轮真正全量覆盖 | 一轮只有全部分片与接缝完成才可计数；报告逐项列未完成范围 | 长笔记会受上下文和工具额度影响 |
| 审阅时稿件持续变化 | 不同人实际审了不同对象 | 不可覆盖的冻结快照；开始/结束核验同一内容哈希；只有协调者合并 | SHA-256 绑定字节，不绑定“认真看过”的行为 |
| 改完仍沿用旧稳定计数 | 旧证书覆盖不到新稿，新错可能刚被引入 | 实质新发现中断连续性；实质修订重新冻结、计数归零；任一内容字节变动使旧哈希不再适用 | 排版修改也会使字节哈希变化，应在复核前定版 |
| 为避免重置，把问题说成“排版”或“已知” | 降低门槛来凑完成 | 预定义实质变化范围；保留被拒误报与裁定证据；来源、颜色、未决状态变化也需重置 | 总协调者的裁定本身仍可能有偏差 |
| 发现既有未决便直接无损关闭 | 没有新证据却把不确定性洗成确认 | 关闭未决须有来源/推理证据；未决答案或状态改变属实质修改 | 三轮无新发现可与未决共存，最终必须明示 |
| 计算哈希的审计账本也不断追加 | 内容每轮都变，无法对同一版本累计 | 冻结内容集合与追加审计区分开；内容、来源映射、未决清单在前者，轮次报告在后者 | 需明确文件边界，不能把内容修订藏进审计区 |
| 脚本通过便宣称确实看图 | 代理能生成格式完美但虚假的记录 | 审计只检查结构、引用和哈希一致性；模型仍须实际打开原图并记录具体证据 | 无法从日志自动证明实际视觉注意力或辨认质量 |
| 额度不足就摘要交差 | 正文、页面或未决项被静默丢弃 | 经常保存完整阶段成果；中断报告精确未完成范围和恢复任务包 | 中断时可能无法在当轮完成全部工作，只能如实交接 |

## 稳定计数的边界案例

| 场景 | 计数与状态 |
| --- | --- |
| H0 两层初稿完成并自查 | 计数为零；不算独立轮。 |
| 新线程完成第二遍全区检查并完成相应修订 | 记录两次逐区检查已完成；锁定最终稿后，连续三轮计数仍从零开始。 |
| 新审阅者甲全量审 H0，无新发现 | H0 的连续计数为一。 |
| 新审阅者乙全量审 H0，无新发现 | H0 的连续计数为二。 |
| 再让甲重看 H0，无新发现 | 不能计第三轮，因为甲已参与过该笔记。 |
| 新审阅者丙只检查修订页 | 部分复核，无效于完整轮计数。 |
| 新审阅者丁全量发现一个此前遗漏的条件 | 连续性中断；修订成 H1 后，从零重新累计。 |
| H0 的两轮后，协调者补了一个蓝色来源标签 | 内容字节已变，H0 证书不覆盖新稿；新冻结稿重新累计。 |
| H0 的两轮后，仅追加独立审计日志 | 内容哈希未变且无实质发现，H0 的既有有效计数保留。 |
| 新审阅者全量审 H0，但一页图像打不开 | 不能报全量，该轮不增加计数；明确未读页。 |
| 三位符合身份的新审阅者对同一 H0 连续全量无新发现，但仍有原先记录的模糊字 | 可称达到三轮收敛门槛，须列未决；不能称全部辨清或零错。 |
| A、B、C 三份笔记各无新发现一轮 | 各自计一，不能凑成某份笔记的三轮。 |
| 审阅报告说 H0，但结束核验已成 H1 | 无法绑定一致版本，本轮无效。 |
| 新审阅者提出一个误报，协调者用原图或有效推理证明该建议不成立，内容和未决均无改变 | 保留发现与驳回证据；不能仅因“不同意”就视为误报。证据充分且其他条件满足时，才可计无新实质发现。 |

## 工具与产品事实的核实边界

已参考的官方资料仅用于确定应当检查运行环境能力，而非承诺每个 Codex Project 都暴露相同 API：

- [OpenAI：Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)：说明子代理工作流与协调职责。
- [OpenAI Codex 官方源码：multi_agents_spec.rs](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/multi_agents_spec.rs)：当前源码中存在上下文继承相关工具参数的定义；部署环境仍可能采用不同接口或不提供此工具。

因此提示词对 `fork_turns='none'` 采用明确条件，不要求猜测或伪造调用。若无法获得新的独立子代理，清点、重建、数学验证、映射和交接仍可进行，但不能把单代理重复工作认证为两位代理的视觉检查或三轮独立复核。

主提示词显式调用 `$math-notes-evidence-audit`，项目内上游 `.agents/skills/handwritten-math-notes-to-latex/` 仅为辅助规程。本次要求覆盖其允许省略冗余图形、局部语义整理等默认选项：图形、重复和推导细节完整保留，不能援引上游放宽用户要求。上游的原稿优先、术语/记号/依赖/决定登记、数学纠错分类、实际引用核实、完整构建和检查点交接可补充使用；引用其规程不等于已经执行其检查。

## 最终结论该说到哪里

可核查的完成表述应同时绑定具体输入、具体冻结输出、三位不同新审阅者的有效全量报告、覆盖状态与未决清单。门槛达成说明流程收敛，不说明客观正确率达到某个数值。若有缺页、未读页、未配对文件或未完成映射，必须明确未完成；若只剩原图无法消除的未决，应保留候选和所需证据，不用重复审阅换取虚假的确定性。
