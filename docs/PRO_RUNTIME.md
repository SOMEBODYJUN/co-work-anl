# 固定身份，完整执行，修复后验收

首轮是一次完整研究任务。先把现有20阶段贯通，交出实质报告和计算器；过程中发现缺口就回到受影响阶段研究、修改、复算。不能把首轮拆成只能交计划的许多次对话，也不能承诺一次上下文能无条件完成所有工作。身份、输入、已完成产物和未决问题保存在文件与Git中，环境中断后接着做。

## 只给身份号的入口

在仓库根目录执行：

```sh
python work.py session start --actor Boss11
python work.py session next --actor Boss11
python work.py session check --actor Boss11
```

默认工作区为 `work/Boss11`。数字身份也接受，例如 `12341234` 对应 `work/12341234`。编号按原字符串保存：`Boss11`不能改成`Boss1`，日期变化不改身份号。没有日期角色表，也不随机发新身份。同一身份恢复原run_id、周期和阶段；已经发布也不会自动开启下一轮。

已有其他路径时显式指定，后续沿用该路径：

```sh
python work.py --workspace work/cn-v0 session start --actor Boss11
python work.py --workspace work/cn-v0 session next --actor Boss11
```

已有绑定不可换作者。分支与仓库相对工作区路径一起保存；从新clone恢复同一分支、同一相对路径即可接续，不依赖旧机器的绝对目录。命令不会自动换分支、覆盖旧工作区或替其他Boss合并。一个Boss管理一个工作区；专题工作者的意见通过提案传入。

`start`只初始化和恢复；`next`返回实际未完成阶段、未决图节点/边、提案、发布状态、验收缺项及下一动作。实际研究由Pro/agent执行，命令不会启动一个模型，也不会在会话外自动持续调用Pro。Git提交仍由主代理串行处理。

## 直到什么状态才停止

`session check`完整通过时返回`complete: true`、退出码0；未通过时返回具体缺项、`complete: false`、退出码3。工具运行错误另返回退出码2。未通过不是请用户重新授权的理由：可补的证据继续补，可修的程序继续修，可复算的计算继续算。权限、环境、预算或必要输入真实阻塞时保存精确断点和已完成文件，不把中断登记为通过。

停止条件同时满足：

1. 当前首轮20阶段或增量8阶段的实质产物已完成，阶段文件哈希有效。
2. 未决节点、机制和提案已裁决，承重原文及历史版本没有被篡改。
3. 本周期实质验收记录、报告、计算器、判断、场景和复核记录均进入当前独立复核快照。
4. 同一当前版本通过独立复核并实际发布，必要正式文件包含在发布清单中。
5. 模型实算和采用范围、观点框架、主判断、家庭引擎、离线操作及新目录恢复逐项验收通过。

机器检查结构、身份、周期、依赖和哈希；研究者实读材料、检查经济推理及运行结果。把字段手工写成pass不构成实质科研验证。独立复核必须由实际独立的研究执行者完成，改一个名字不能制造独立性。

## 实质验收记录

保存为工作区内 `research/acceptance.json`。在`s19_audit`（增量为`i07_replay`/`i08_release`）完成实际检查、写记录并登记；最终review包括此记录和它引用的所有证据文件。新增模板 `examples/acceptance-template.json`全部为pending，必须据真实运行填写，不能直接盖pass。

| check ID | 实际通过的依据 |
|---|---|
| `sources` | 承重事实能定位原文、时期、单位和发布版本；关键缺口已经研究并处置 |
| `frameworks` | 连续原文支持的分析动作与慢变前提，包含失误和竞争解释；实际改变了哪项专题判断 |
| `models` | 真输入、代码、划分、估计、基线、样本外成绩和用途裁决；拒绝不适用的复杂模型也可以通过此项 |
| `hyperedges` | 联合前提、机制、时滞、反证和下游修改已经实质核对；图结构通过不替代因果检验 |
| `judgments` | 核心问题有排序明确的主路径、机制、窗口、行动和具体改判条件 |
| `household_engine` | 120月多资产、合同贷款、策略枚举、现金失败与独立算例符合计算器规范 |
| `offline_ui` | 真实离线打开，修改输入、运行策略、查看结果与导入导出均经过操作检查 |
| `independent_review` | 独立执行者对承重结论、模型用途和代码逐项提出并处理问题，记录绑定当前版本 |
| `fresh_restore` | 从已保存提交建立新目录，恢复同一工作区、依赖和输入，关键计算重放一致；保留命令、版本与结果 |

每项含 `id`、`verdict`、`evidence`和`artifacts`。`artifacts`为工作区内相对路径，引用实质检查记录/输入/输出，全部进入最终复核。记录顶层含schema、真实输入标识、cycle、author和reviewer；示例见模板。作者等于绑定身份，复核者不同于作者并与最终review一致。合成用例可以验工程，但不能通过正式研究验收。

正式报告、计算器、判断和场景路径固定为 `formal/report.md`、`formal/calculator.html`、`formal/judgments.json`、`formal/scenarios.json`；独立意见在`research/final_review.md`。审后改任何承重文件，回到受影响阶段，再复核、发布和check。验收记录本身也受哈希约束。

已通过的周期停止。收到新证据或新的深化任务后才运行 `init --mode update`，保持同一身份进入8阶段增量周期；新周期必须更新验收记录。明确拒绝一个科学用途、明确保留旧结论，都可以是有研究成果的结案；永远调参和反复重跑同一信息不属于完成要求。
