# 研究者分工、专题接口与传导链裁决

首轮Pro负责形成有解释力的中国经济主判断。分工围绕待解决的问题组织：数据、理论、地区与群体、量级、政策约束和历史检验共同支撑结论。CLI保存研究记忆、依赖和版本；专题作者、挑战者、复核者与主代理承担实质判断。

## 主代理怎样组织20阶段

20阶段是具有依赖关系的交付与提交里程碑。研究过程允许反复交错：财政研究发现缺少净土地资源，立即回采集和口径整理；银行研究发现原有损失率适用对象不同，立即修模型与传导；写作暴露因果跳步，再回分析。先保存具体成果和断点，受影响文件修好后按引擎要求重新登记失效阶段。不能为了凑满20个回执，把同一份摘要复制20次。

主代理在 `research/scope.md` 为每个核心判断建立问题ID、当前解释、竞争解释、责任人、决定性缺口和下一步。分别处理地产调整、地方财政、居民企业需求、就业收入、银行系统、长期增长和股票实际总回报；这些问题共用数据与机制，事件定义和裁决仍分别保留。

主代理负责四项不可外包的工作：决定最有价值的下一问题；核对跨专题接口；明确裁决主路径与替代路径；串行合并正式版和Git提交。子代理提交可检查的专题、输入输出、机制提案和替换文字，不直接覆盖其他人的正式文件。

## 滚动专题角色

下表是可复用职责，不是要求同时启动12名agent。每个任务只领取一个有边界的问题及相关共享阅读端点。主代理按实际并发空位滚动启动，作者与其独立复核者使用不同真实agent。

| 角色 | 必须回答的具体问题 | 主要材料与方法 | 分组、接口与实质交付 | 退回的具体情况 |
|---|---|---|---|---|
| 数据与检索负责人 | 当前争议缺哪个变量？已有原发布、版本和查询能否复用？ | 原始统计表、财政预算与决算、银行财报、政策执行、发布日历；URL/正文/原发布版本/事件去重 | 建数据字典、来源与检索记录、可复算时序；向各专题提供同一证据ID和口径说明 | 统计期或单位不明、累计当月混用、媒体转载被当新来源、数据无法由保留输入复算 |
| 地产研究者 | 压力首先发生在开发商、交易、价格还是居民净值？城市和住房用途如何分化？ | 销售量价、库存、租金、开工交付、房企现金流、交易与持有成本；量价分解、现金流与分组比较 | 城市/区域、期房现房、新房二手、开发商/家庭分别分析；交 `property.md`、数据与地产→财政/家庭/银行的候选机制 | 全国均值直接套用户城市；销售额降幅当价格跌幅；房价降幅当贷款损失率 |
| 地方财政研究者 | 土地压力如何改变地方实际可用财力、拖欠和支出？展期把成本转给谁？ | 土地收支、一般预算、转移支付、专项债、LGFV期限利息与项目收入；部门存量流量与期限核算 | 按地区财力、债务期限、平台用途分组；交 `fiscal.md`、资金缺口与资源承接表；与地产/企业/银行核对同一暴露 | 毛土地收入直接等同净财政损失；再融资或债务置换被记作债务消失；同一支出算两次 |
| 居民、企业与就业研究者 | 资产、偿债、工资和回款如何影响消费投资？哪些群体承受主要损失？ | 分组收入/债务/就业、工资、社零、利润、应收账款、账期；家庭债务与融资约束框架、分布比较 | 有贷/无贷、有房/租房、工资/经营收入、出口/内需、行业与地区分别分析；交 `households_firms.md`、收入中断和恢复路径 | 用平均净资产判现金安全；把社零等同全部消费；把营业收入当税后可用现金；重复叠加同一地产冲击 |
| 银行研究者 | 是利润受压、局部资本不足、流动性紧张，还是系统性危机？损失在哪里确认和承担？ | 银行分组财报、关注/逾期/不良、拨备、资本、利润、融资结构、地产与平台暴露；损失与缓冲核算 | 大行/股份行/城商行/农商行、地区和贷款类别分组；交 `banks.md`、暴露与承损表、触发条件 | 以总量缓冲覆盖所有小银行；以展期自动认定无损失或任意坏账；把流动性和偿付能力混为一谈 |
| 政策资源与外部研究者 | 哪项措施已经改变现金流？资金从何处来、规模多少、何时落地？外需如何缓解或放大内部压力？ | 实际拨付、债务置换、住房收储执行、中央地方资源、出口增加值、汇率与能源；执行规模和时滞核算 | 宣布/获批/拨付/使用分别记录，中央地方分别列账；交 `external_policy.md` 与政策资源、执行和受益群体表 | 用公告金额当已支出；用“有能力”代替资金和执行分析；外贸总额直接当国内增加值 |
| 历史与观点研究者 | 哪种理论更能解释本题的群体、制度和时间结构？哪些历史类比失败？ | 作者原文、论文、数据、相互反驳及后续检验；机制比较与反事实 | 按争议建立观点卡，区分作者原命题与本题迁移；交 `viewpoints.md`、`history.md`、可区分预测和拟修改的链条 | 只列名家结论；只看摘要却称完成全文研读；按悲观程度或赞数选观点；移植国外年份与系数 |
| 计量与科学评分研究者 | 目标是活动、危机发生、烈度还是持续期？已有数据支持哪种识别或预测？ | 明确定义的事件样本、发布版本面板、基线和候选模型；时间/国家留出、校准、误报漏报和稳定性检验 | 将指标仪表盘、统计评分、事件概率分别命名；交模型卡、原始输入、代码、样本外结果和采用理由；与专题核对变量意义 | 任意赋权；训练集成绩当验证；把标准化分数当概率；用一套模型同时宣称解释所有危机类型 |
| 家庭引擎实现者 | 在给定收入、资产、合同和情景下，哪类具体行动先保护现金偿付？ | `05_CALCULATOR_SPEC.md`、真实用户输入规范、贷款对照；120月逐月会计、有限枚举与逆向压力测试 | 收入来源、资产、关联贷款分别记账；交完整离线HTML、引擎、输入、候选策略、独立对照和错误用例 | 虚构家庭金额；资产处置与结清重复扣款；失败后继续生成正常十年终值；界面数字不绑定计算 |
| 独立因果与量级挑战者 | 哪一步最可能改变主判断？共同原因、反向因果、遗漏渠道、时滞或量级能否解释现象？ | 作者冻结专题、原始数据、最强替代解释与独立算例 | 不先接受作者结论；交逐条挑战、区分两种解释所需的观测，以及足以改变结论的现实量级 | 只说“也可能”；无机制、无资源、无量级的理论例外；用相反语气代替独立分析 |
| 事实与代码复核者 | 承重数据、计算、传导接口和版本是否匹配？ | 冻结原表、专题、机制卷宗、代码、输入输出；独立读取与复算 | 交事实/口径/算式/时点/版本的明确通过或拒绝及修复位置；作者不能审核自己的提案 | 只看作者摘要；复核旧文件却放行新文件；不运行会影响结论的计算 |
| 终稿编辑者 | 读者能否理解主判断、传导和行动？文字是否改变数字或裁决？ | 已裁决报告、判断与参数；中文编辑规则 | 交成稿补丁和实质内容核对；保留明确判断、时间和行动条件 | 把强判断改成模糊平衡；加入无依据细节；删除会改变行动的条件或引用 |

作者必须给明确主判断、最强替代解释及排序原因。数据缺口转成具体补采或敏感性问题；测出什么方向或量级会推翻判断。不能只交“材料不足，无法判断”，也不能用伪精确数字填洞。

## 轮次怎样衔接

1. **建立采集台。** 数据负责人先返回原发布与查询台账；主代理为各专题指派需要的变量和新增检索。专题研究者可以提出新检索需求，采集台负责认领和归并；已有结果直接引用，不因换人重新搜同一新闻。
2. **独立专题分析。** 地产、财政、居民企业、银行分别先写解释，再看其他专题的结论，防止整组从同一句“2027年必爆发”出发。共享事实，独立分析。观点与历史角色提供竞争框架及可区分预测。
3. **跨专题对账。** 主代理组织地产↔财政、财政↔企业、地产/平台↔银行、收入就业↔消费等接口。逐项核对部门范围、单位、时间、敞口、损失承担和重复计数，形成接口记录。
4. **独立挑战与复算。** 挑战者只攻最影响主判断的承重点；计量、政策资源和代码复核者按问题加入。先交独立意见，再对关键异议回应。每轮必须产生补证、改机制、改量级、保留旧判断的实质理由或明确结束，不安排固定次数的空辩论。
5. **主代理裁决和构图。** 比较解释力、反证、现实约束和量级，明确接受/削弱/条件性保留/撤回哪一条。初建图由主代理登记；旧图通过提案与独立审查修改。不同解释分别保存，不能取平均得到“中间答案”。
6. **反事实与重算。** 把转移支付、再融资、需求和处置时点改到现实可解释的范围，重算受影响的部门、情景和家庭行动。主判断对哪些变化稳定、在哪些条件下反转，写到裁决中。
7. **写作、实现和终审。** 成稿与计算器使用同一判断和情景参数；编辑、事实复核和代码复核分别完成。新目录恢复后发布。随后进入8阶段增量流程，按受影响的问题派新任务。

没有必要把每个角色常驻。若只有三个子代理空位，可先用数据/地产、财政、银行三个任务推进，主代理同时研究居民企业和政策；这批成熟后释放空位给独立挑战、历史观点、计量和代码任务。作者退出后，其原文和断点供新复核者读取，不能把作者重命名成复核者。

## 用当前输入开第一批任务

主代理先读47条输入及其18个来源项，建立共享检索清单，记录研究截点。原证据ID保留原有口径与状态，新取得的原表和版本另行登记。下面是可直接派出的三个首批专题；具体责任人填写实际agent身份。

| `bank-absorption-01` | `E31`—`E34`、监管分类数据与上市银行原始财报 | 风险集中在哪些类别、地区和贷款？利润、拨备、资本和融资怎样承接损失，什么触发条件才会从慢性压力转成集中冲击？ | 分类型暴露和缓冲表、流动性/偿付分开裁决、最强稳定解释与风险解释、尚需哪项数据才能区分两者 |

主代理同期处理 `E22`—`E30`、`E35`—`E40` 的信用、就业、企业现金流与居民机制，并向共享采集台发出明确缺口。首批成熟后组织接口核对，再给新历史观点/独立挑战者读取已保存的原文和计算。计量任务以这些专题暴露的可检验问题为目标，例如“预测未来若干季度银行压力”和“估计地产下行与消费分组关系”应分别建立模型，不先造一个万能危机分。

第一批不是等全部资料搜完才写分析：作者先形成当前最强解释，找能区分它与竞争解释的下一项观测，更新解释后继续。主代理每次只派有研究增益的下一任务，任务未完成时先保存可接续断点，不把换agent当成重置。

## 超边由谁提出、谁决定

经济超边是研究裁决的表达。一个主张进入正式图，走以下责任链：

| 环节 | 责任人 | 必须做成的事 |
|---|---|---|
| 候选机制 | 专题作者 | 写限定对象和时间的结论、全部共同前提、机制正文、条件、反证、量级和时滞；不能只画箭头 |
| 接口核对 | 至少一名相邻专题研究者 | 核对从本部门流出的资金/损失是否等于另一部门接收的项目，检查时间、范围和重复计数 |
| 独立经济审查 | 非作者的因果/量级复核者 | 读原文和必要计算，检查共同原因、反向因果、可区分预测及现实资源；明确通过、拒绝或需收窄的结论 |
| 正式裁决 | 主代理 | 明确采用何种机制和适用范围，回应最强替代解释，决定主路径与条件性分支 |
| 登记或合并 | 主代理 | 初建用 `graph-put`；旧对象走 `proposal` → 独立 `proposal-review` → `apply`，保存实际版本及正文补丁 |
| 新证据后的复审 | 受影响专题与新独立复核者 | 补充、加强、削弱、替换或撤回旧边；重算下游；历史反转必须回应旧理由 |

程序已校验引用、ALL前提、来源类型、版本、下游失效和审核快照。它不会自动判断某个地区的财政行为、某个作者的理论或一条因果机制在现实中成立。`current`表示本轮采用的版本处于当前状态；`grounded`表示引用结构有支撑路径，都不等于计量上完成了因果识别。

## 每条机制的研究卷宗

作者在 `research/mechanisms/<机制ID>.md` 保存以下内容；它是实质研究文件，和边JSON一起列入阶段、复核文件及Git提交。现有引擎不逐字段强制下面的经济解释，主代理与独立审查必须逐项阅读。

| 内容 | 必须回答什么 |
|---|---|
| 精确命题 | 哪个群体、地区、变量，在什么时间范围发生什么变化？结论是条件性还是当前主判断？ |
| 前提与条件 | 哪些事实/约束必须共同成立？哪些是已观测、哪些是研究假设、哪些尚未满足？ |
| 方向与中间环节 | 资金、收入、抵押品、支出或损失怎样传递？谁有决策权？ |
| 量级与损失承担 | 用何种观测、核算、历史估计或明确判断给出范围？谁付出成本、谁得到缓冲？ |
| 时滞与反馈 | 冲击何时开始、按什么期限兑现、能否持续或反馈，反馈怎样由外部观测锚定？ |
| 共同原因和反向因果 | 两个变量是否同时受另一冲击影响？后件是否也会反过来影响前件？ |
| 竞争解释与可区分预测 | 现有解释与最强替代解释对哪些观测给出不同预期？当前事实支持哪一边？ |
| 识别与适用范围 | 是会计关系、机制推断、历史经验相关、估计的预测关系还是有识别设计的因果效果？不得互换名义。 |
| 反证和阻断 | 哪个当前反证最强？何种可观察变化足以切断或收窄本条传导？ |
| 裁决与改动 | 主判断、为何采用、独立意见如何回应、旧理由如何处理；哪段正文/参数/下游要重算？ |

尚未满足的条件不能写成已经观测到的事实。尚未成立的候选机制先留在卷宗和待研究清单；若保留条件性判断，命题正文必须完整保留“在这些条件下”的范围，后续不得把它当作无条件已发生结论使用。条件性的经济意义由复核者检查，不能靠 `conditions` 非空就声称程序已核实它。

例如“土地出让收入下降→地方政府支出下降”，需要财政作者补净可用资源、转移支付、债券/平台再融资和刚性支出。地产作者核对冲击起点，财政作者核对资金，企业就业作者核对付款/订单影响，独立复核者再查是否存在共同需求冲击和相反方向。主代理最后裁决具体地区、支出项目、时滞和强度，必要时保留有缓冲地区的替代分支。

## 一次派工怎样结束

每个任务至少交：精确主判断；原始证据与观点的ID/定位；相对旧版的新解释；最强反对意见及回应；需要合并的正文/机制/参数；实际计算与复现输入；未决问题的精确断点和下一步。

有新机制但无新新闻，可以构成进步；必须说明它修正旧解释的哪一步。没有改变判断，也可交保留结论，必须说明新材料为何没有推翻原机制。主代理根据这些内容决定下一任务，不按代理数量、辩论轮数或文件数量计完成。
