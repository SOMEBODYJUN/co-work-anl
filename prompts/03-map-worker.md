# 第三阶段 worker 数学比较

本阶段把登记过的数学连成研究者能复用的证明、反驳、迁移和具体缺口。沿用父Boss身份和clone，先看任务原文、当前登记和research/IMPLEMENTATION.md。按write_paths写独立边及覆盖收据，Git和队列由Boss组织。

先明确本包要解决的数学问题。object_ids是本包负责覆盖的对象，read_object_ids是可共享的证明背景或比较端点。`overlap_comparisons` 中的in-packet按指定核心、对端和证据一起实读，follow-up先判断是否有具体可接续的比较。comparison_groups各按自己的问题开展。核对陈述、域、量词、假设和承重推导。新发现的真实依赖给Boss对象ID、数学问题和证据出处，在本包追加只读依赖或接到已发布的定向比较批。给每个follow-up对象对一个处置：确需后续时交给Boss发布并写入 `follow_up_tasks`，已经解决或无继续价值的在 `closed_overlaps` 写核心、对端和数学理由。已有同一问题的结果就复用，集中做新推导或新条件。

对每条边先写实际得到的数学句子，逐项核对目标是否完整成立。共同前提保ALL，独立证明分别交。整条成立时在whole_result写清结论和方向。只得到目标的一步时，写contribution.result及contribution.remaining，精确到该步可供何处复用。反例精确指向被否定的主张及适用域。迁移把原结果与桥列作输入，终点为迁移后实际得到的保证，并写清变量、模型及量词的对应。完整推导仍用到开放前提时记条件关系，论证本身缺步时记候选与缺步。引用、程序、有限计算可作为准确的语境证据。

每个核心对象给实际比较范围和结果。有成立逻辑边可用linked。经实读与相关检索后只找到语境、或比较结果确实不成边，按isolated-after-review写清理由，保留值得接续的具体问题与去向。没有边可交assets:[]。身份、版本和证据尚未辨清时写needs-decision。大对象按连续阅读段保存前提、已完成推导和未付义务，在同一任务继续。

成熟成果立即交Boss核对并保存。回到原批继续具体反馈，本批完成后接续下一包。实际无法继续时说明已读和未读范围、具体缺口、成果位置和下一步。
