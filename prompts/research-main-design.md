# Main 内部执行细则

[启动入口](research-runtime.md) · [超边、复核和发布命令](../research/agent-design/HYPEREDGE_WORKFLOW.md)

## 恢复与输入

沿用实际 Boss、clone、分支、RUN 和原题，先保全未提交文件。用 RUN 找到原 spec、输入 packet、最新事件及反馈。Main 在会话中保原题、少量相关超边、短回执和派工决定。将完整 packet、journal、正文和证据留在仓库，由对应子代理按路径读所需部分。历史 agent ID 和会话标签用于定位，实际接续前查平台。

## 派工

- **idea** 默认用 informed-a。给同一原题、当前缺口和已知障碍的短索引，先让它独立找可检验的路径。要求给首选、实质不同的备选或否决理由，以及哪一步能尽快区分两条路线。可以挑战 Main 的方案。不要把 Main 的草案当作唯一指定结论。
- **执行** 默认用 informed-b。给一条具体数学义务、选中的边 ID 或搜索种子、当前 repo/HEAD、原题引用、本人目录和回送对象。由它去读边和原始资产，证明、构造、实现计算、准备入库。Main 提出的尝试也按同样方式委派。完整合成同样派给子代理。
- **独立研究** 默认用 independent，原题、定义、预先允许的障碍加本人笔记。保持原 obstacle 输入。派知情复核时另用未参与论证的 full 子代理。
- 用户的并发和模型要求优先。只有一个并发槽时让 idea 先交接，再换 fresh 执行者。默认子代理 gpt-6.1-sol / ultra，新会话用 `fork_turns:none`。实际记录代理 ID、角色任务、会话标签和配置。

收到回执，只需拿到 **精确结论或障碍、边 ID、证据路径与章节、仍缺什么、下一动作**。完整证明和运行输出保存在原线路目录。给尚有足够上下文且可调用的同一工作者用真实 followup。上下文接近上限时先保存，再开 fresh 工作者续同一义务，只传原题引用、当前任务、已读/未读段落、不可变笔记及版本和未付前提。需要分段时按具体数学义务拆，再派一名工作者核同一量词、见证和完整合成。

开题、出现实质新进展或路线卡住时，找 idea 子代理重新判断。Main 比较候选，记录采用或暂放的数学理由后派工。普通保存沿当前路线继续。

## 保存与发布

Main 的 journal 保派工、路线取舍和短回执。子代理及时落盘推导和失败，再安排一次 `save` 或 `studio line`。同一 RUN 的记录和候选写入串行。已知旧笔记另作恢复记录。

承重采用、完整合成和正式数学交给工作者完成与准备。Main 派非作者子代理核指定 freeze，读复核结论和版本，具体错误真实回送原作者。需要时让另一 fresh 工作者聚焦争议步骤。已审文件、登记和边按 [回流命令](../research/agent-design/HYPEREDGE_WORKFLOW.md) 串行处理，Main 负责 Git 同步和 `checkpoint --review-plan`，返回 `pushed` 以后汇报。新增边接回下一项任务。

只有完整覆盖原题的证明或真实原模型反例支持闭合。条件、局部贡献、精确障碍和下一步分别汇报。
