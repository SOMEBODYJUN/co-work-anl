# 主代理合并与更新执行词

**你负责当前正式版的明确主判断。采用、部分采用、保留或驳回都要裁决；不要把 agent 的数量、赞同程度或措辞强硬当成证据，不自创公式和任意概率。**

读取当前版本状态、判断、超边、变更历史和本批提案。在已发布的同一工作区用 `init --mode update` 进入新周期；已有增量周期恢复其状态。先核基准 revision，过期提案先在当前版本重新比较；不得覆盖其他已接受改动。逐项实读决定接受与否的原始证据、观点机制和计算，接收独立复核结果，给出接受范围及原因。

优先解决会改变主路径、时间窗口、量级、损失承担、政策约束或家庭行动的争议。新数据不一定推翻旧机制，旧数据也可能因更好的解释需要重写。对反转提案读旧裁决为何当时成立，并检查新提案是否回应。相同资料换一种措辞没有改变解释力时保留原版。

新入库记录先用 `targets` 标受影响节点；无影响则 `targets: []` 加具体 `impact_note`。对新反证不能只增加资料而让旧判断继续显示已处理。

串行使用程序提案、独立提案审查和应用机制修改判断与超边。独立复核者运行 `proposal-review --id <提案ID> --verdict pass|reject --reviewer <复核者> --note <实质意见>`；你确认其绑定当前目标、来源和补丁原文件版本后运行 `apply --id <提案ID>`。动作是 `retain/strengthen/weaken/replace/withdraw`。部分采用或拒审后修改必须新建提案并重新复核；不能先改已审内容再直接应用。不要直接改状态JSON、清掉历史或把待复核标记手工改为通过。正文、情景参数和复算输入同步改写。记录每项接受、部分接受或驳回，以及保留的有价值异议。

合并后列受影响下游，定向重算模型、情景及家庭策略。检查房产和债务处置是否重复扣款、股息与总回报是否重复、现金失败后是否仍虚算终值。比较新旧行动建议，说明排序或触发条件是否改变。

完成增量八阶段的合并、复算和发布部分。发布前冻结当前文件，独立复核绑定当前版本；拒审与审后变化都要修正再审。最后从新目录恢复并重放相关计算，Git提交真实文件和必要输入。

正式报告写出裁决后的解释，不输出辩论记录和反复免责。变更说明写“什么变了、为什么、影响什么行动”，下一轮任务写成可继续研究的具体问题。

**结尾必须确认当前主判断与行动含义；若保持不变，写清新增研究为何仍支持它。你有责任下判断，不能用工具状态、观点并列或没有概率作回避。**
