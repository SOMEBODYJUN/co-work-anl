# 第二阶段半：研究资产登记与读取索引

~~~text
本阶段不是研究、证明、复现或建超边，也不是把多个数学对象强行合并；它把第二阶段已经形成的细粒度 Markdown 对象登记成可供第三阶段和后续研究 Agent 调用的资产目录。

底层来源仍逐源保留哈希、处置和版本关系。每个数学对象仍保留自己的 Markdown；一源多对象、多源同对象只在登记表中表达关系，不能为了减少文件数静默改写正文。

## 资产登记

每个登记项必须绑定一个 problem_id、一个或多个 object_id、实际正文路径、来源和证据。登记内容至少包括：

- 当前问题、精确定义、模型身份、量词和适用范围；
- 已知结论及其 claim_type（定义、定理、条件结果、反例、障碍、有限检查、猜想）；
- 开放边界、失败路线和不能继承的结论；
- 证据文件、运行入口、已知命令或尚缺复现条件；
- 相关对象和局部关系；
- 下一批可检验问题；
- 当前邻接对象和边界标签；若超图尚未建立，只记录候选关系，不宣称超边成立。

JSON 只负责编号、登记、路由和状态；数学推导、证明、反例和限制继续写在独立 Markdown。JSON 通过 `research/schemas/` 校验，Markdown 是人和 Agent 阅读的主要正文。2.5 不因登记而修改正文，也不把登记字段当数学结论。

## 两跳读取索引

2.5 可以为每个对象生成轻量邻接索引，但不提前把它当成证明关系：

- 0 跳：当前对象和直接问题定义；
- 1 跳：直接相关对象、来源和证据；
- 2 跳：由相关对象再展开一层的依赖、反例、障碍和开放边界。

两跳是后续研究 Agent 的默认读取窗口，不是硬上限。遇到明确的边界对象或缺失前提时，Research Boss 才按路径继续展开；不能把整张超图塞给所有 Agent。

## 登记门槛

- 没有稳定 object_id、正文路径、来源绑定和真实类型，不能进入登记完成；
- 只有目录名、摘要或旧图提示，不能填充数学结论；
- 候选关系只写 candidate/boundary，不能在 2.5 直接写 accepted edge；
- 登记完成后要更新简明入口，但不要求合并对象正文；
- 研究运行、六 Agent 分流、工作区和 checkpoint 见 `prompts/research-runtime.md`。
~~~
