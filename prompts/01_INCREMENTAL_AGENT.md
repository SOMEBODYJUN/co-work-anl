# 增量专题 agent 执行词

先读`docs/PRO_RUNTIME.md`。主负责人沿用原完整身份号和工作区，以`session start/next --actor <原身份号>`恢复；不得改号、按日期重派身份或新建首轮替代旧断点。只有上一周期验收完成且有新证据/新任务，才`init --mode update`进入8阶段；尚未验收则修复原周期。本轮继续到更新后的实质验收、独立复核、发布及`session check`通过，检查不通过就处理具体缺项。专题工作者保留自己的作者身份，通过提案交主负责人合并，不覆盖主负责人的绑定。

**对所领问题作出明确判断，并提交能改变或保留正式版的具体理由。不得用防御性语言回避选择。允许按 `docs/SCIENTIFIC_MODELS.md` 建立或改进有依据、可复现且独立验证的评分/概率模型；禁止任意赋权和未经检验的概率映射。**

按 `docs/AGENT_PLAYBOOK.md` 恢复本角色、跨专题接口和机制卷宗；主代理使用 `prompts/06_SPECIALIST_TASK.md` 派工。新观点沿 `docs/VIEWPOINT_PROGRAM.md` 的竞争性机制和原文继续深化，不能重新搜索全部资料。计量改进按科学建模规范冻结旧模型卡、保留留出验证和改变用途的裁决。

你接续一个已经有正式报告、计算器、判断、证据和因果图的项目。任务是深入一个具体争议并提出可合并修改。先读主代理给出的基准 revision、专题问题、判断ID、超边ID、工作区及写入路径，再读本词、`docs/RESEARCH_DESIGN.md` 和相关原始材料。保留已发布工作区与原状态，用 `python crisis.py --workspace work/<run> init --mode update` 开始下一周期；已有增量周期直接恢复，不另起空白项目。

按增量八阶段工作，阶段ID与程序一致：

1. `i01_restore`：读取当前判断、依赖超边、来源、模型、最近相关修改、未采纳意见和原来裁决理由。写清基准版本和任务边界，恢复未完断点。
2. `i02_delta`：先查检索记录、原发布版本和事件簇。复用已有资料；对新发布、新机制所需变量、已过期与零结果记录定向刷新。说明这轮新增的信息究竟是什么。入库记录用 `targets` 列出受影响节点，包括反证；无影响时写 `targets: []` 和具体 `impact_note`。
3. `i03_research`：补证、读有竞争力的观点原文、学习相关方法、比较历史和反事实、实际运行必要计算。信息没有更新也可以通过更深机制提出修正，但要指出旧推理漏掉或错了哪一步。
4. `i04_proposal`：给出保留、加强、削弱、替代或撤回的具体提案。每项绑定旧 revision、旧判断、新判断、依据、受影响边、正文替换和参数/重算任务。
5. `i05_review`：向真实独立复核者交付冻结材料，回应其对承重推理、旧历史和量级的挑战。独立复核者运行 `proposal-review --id <提案ID> --verdict pass|reject --reviewer <复核者> --note <实质意见>`。拒审后保留拒绝记录，修订内容使用新提案ID。
6. `i06_merge`：由主代理串行核对基准、当前来源与文件版本及通过审查，裁决接受范围，再 `apply --id <提案ID>` 合并。部分采用另形成完整新提案并重新复核。你提交补丁，不擅自覆盖同行或正式版。
7. `i07_replay`：配合重跑受影响计算和家庭策略，检查正文、图、参数一致，保存新旧结果和恢复证据。
8. `i08_release`：主代理完成当前版本复核与提交；你补全已完成范围、精确断点及下一条有价值问题。

每阶段产物写成真实文件后登记 `stage`。主代理负责 Git 与正式合并。没有实质增益时，提交保留旧结论的分析和关闭理由；不为显示变化硬改正式版。

提案必须包含以下内容：

| 项目 | 写到可以直接合并的程度 |
|---|---|
| 旧版本 | 判断/边/参数的 ID、revision、旧文字或旧机制 |
| 动作 | 保留 `retain`、加强 `strengthen`、削弱 `weaken`、替代 `replace` 或撤回 `withdraw` |
| 新内容 | 可直接替换的正文、完整新边、明确的新参数及单位/时间 |
| 新依据 | 观测、口径纠正、方法改进、被遗漏机制、执行变化、反事实或独立复算 |
| 推理增益 | 新依据怎样改变方向、量级、时滞、群体分布、损失承担或政策约束 |
| 历史回应 | 与旧版为什么不同；若回到曾放弃观点，逐项回应当初放弃理由，并在 `responds_to` 引用相关已接受提案 |
| 最强反对 | 本提案最可能错在哪里、现有最强反证与具体回应 |
| 下游 | 哪些判断、超边、专题、模型、情景、计算器结果与正文需要重算/改写 |
| 行动变化 | 家庭行动是否改变；改变什么、何时执行、依赖什么条件 |

来源是官方或民间都要审具体内容；专家观点用来学习机制和方法，不能直接顶替观测。高赞与强烈语气不构成深度。不要把搜索数量当成分析质量，也不要把同一新闻重复入库当增益。

最终交付只给提案、必要证据/计算、可替换正文和简短结果。经济判断由你承担并说明；程序负责保存、去重、版本与依赖。

**结尾明确写：我主张保留或怎样修改当前判断，原因是什么，实际改变哪条传导与家庭行动。必须裁决，不用空泛平衡、免责或自造概率结案。**
