# 专题研究、机制修订与独立复核任务模板

必须形成明确主判断，并交出能合并的研究成果。使用事实、机制、现实量级、历史和竞争解释作裁决；不靠免责话语结束任务，不拍脑门凑分数或概率。

主代理每次派工时填写以下任务包。复核任务使用不同真实agent，读取冻结原材料；不能由作者给自己登记通过。

```yaml
task_id: "<本批唯一ID>"
role: "<地产/财政/银行/居民企业就业/政策外部/历史观点/计量评分/家庭实现/独立因果复核/事实代码复核/终稿>"
workspace: "work/<实际RUN>"
base_commit: "<本轮读取的Git提交>"
question: "<一个需要作出判断的具体问题>"
scope: "<地区、群体、变量、统计期和决策窗口>"
current_judgment: "<当前句子；首轮没有则写待裁决问题>"
target_ids: ["<受影响节点或边ID>"]
read_first:
  - "<原文/专题/观点/历史改动的精确路径及定位>"
evidence_ids: ["<已有承重和反对证据ID>"]
competing_explanation: "<真正有竞争力的替代机制>"
analyst_context: "<原作者历史目录、原文背景、观点变化、失败预测、竞争解释和已读范围>"
search_scope: "<决策缺口、变量、地域、期数；先读已有查询>"
methods: ["<采用的方法、输入和选择理由>"]
neighbor_interface: "<需与哪个专题核对哪一笔资金/损失/收入/时间>"
write_paths:
  - "research/tasks/<task_id>/analysis.md"
  - "research/tasks/<task_id>/inputs/"
  - "research/tasks/<task_id>/results/"
  - "research/mechanisms/<机制ID>.md"
  - "research/tasks/<task_id>/proposal.json"
end_condition: "<解决什么承重争议、完成什么复算和具体替换后交付>"
```

先读 `docs/AGENT_PLAYBOOK.md` 的本角色职责和相关专题接口，再恢复当前研究状态、相关历史提案和未采纳旧反对意见。只在授权的任务路径写草稿；正式版和Git写入由主代理串行处理。

## 作者执行

1. 用一句完整命题固定本题的地区、群体、变量和时间。拆开观测事实、作者观点、研究机制、预测关系和压力假设。
2. 搜索前查 `search-plan`，阅读同范围记录和零结果。新增资料或原发布更新才定向采集；记录实际工具、查询、时点与结果。对同一原发布只采集一次，各专题引用同一ID。
3. 读最强解释与竞争解释的原文。观点卡写清其真正命题、机制、隐含约束、适用边界、历史检验、区分两者的观测，以及将改变本题哪一步。
4. 完成必要分组、会计核算、估计或反事实。方法输出与原始输入一起保存，明确真实数据和合成测试。科学统计评分或事件概率要按项目模型规范完成样本外验证和适用性审查；不因模型名字科学就默认可信。
5. 写主判断与排序原因，回答方向、量级、时滞、谁承担损失、政策需要什么资源。缺口转为具体补采或敏感性分析，明确该变量怎样变化才会改变判断。
6. 与相邻专题对账；发现范围、时点或重复计数冲突，先修对应分析。提出联合前提传导机制，填写 `research/mechanisms/<机制ID>.md` 卷宗。
7. 提交具体正文、参数与机制修改，并保存可复算材料。没有修改也要交有内容的保留理由；不能只交搜索清单或“建议继续研究”。

新增来源遵守实际 `ingest` schema：`id, kind, url, source_family, published_at, text/raw_file`，事实类还要 `observation_period`；已有节点后填写受影响的 `targets`，确无影响时写空列表和具体 `impact_note`。把反证挂到被挑战的判断。

## 机制与提案格式

初建图时，作者交候选节点/边和机制卷宗，由相邻专题核对、独立经济复核及主代理裁决后统一 `graph-put`。边的实际字段如下；只使用已经登记的引用，示例ID由任务真实对象替换。

```json
{
  "id": "<机制ID>",
  "tails": ["<共同前提ID1>", "<共同前提ID2>"],
  "head": "<后件节点ID>",
  "mode": "ALL",
  "conditions": ["<适用条件；未满足者明确保留为条件>"],
  "mechanism": "<限定群体和时间的实际传导；详细推理、量级和复核见research/mechanisms/机制ID.md>",
  "counterevidence": ["<已登记反证ID>"],
  "falsifier": "<能切断、削弱或推翻本条机制的可观察变化>",
  "lag": "<有依据的兑现和持续时间>"
}
```

`conditions`文本不会被程序自动核实，图上的 `grounded/current` 也不等于因果识别成立。机制卷宗必须另外解释共同原因、反向因果、分布、现实量级、损失承担与竞争解释。卷宗列入实际阶段与最终审核文件，不能只留下不受版本约束的外部链接。

旧节点或边通过提案修改。节点提案使用：

```json
{
  "id": "<新提案ID>",
  "author": "<真实作者身份>",
  "target": "<旧节点ID>",
  "base_revision": 1,
  "action": "replace",
  "old_statement": "<逐字引用当前statement>",
  "new_statement": "<新判断和适用范围>",
  "new_evidence": ["<已登记的新证据ID>"],
  "reason": "<旧机制何处被修正；新证据或学习增加了什么解释力>",
  "responds_to": [],
  "files": [
    {
      "path": "<工作区内相对路径>",
      "base_sha256": "<当前原文件实际SHA256>",
      "text": "<替换后的完整文件文本>"
    }
  ]
}
```

`action`可为 `retain/strengthen/weaken/replace/withdraw`。没有新观测但有实质新方法时，以具体的 `new_method` 替代空的 `new_evidence`；不能只写“深入思考”。边提案的 `old_statement`逐字引用旧`mechanism`，提供完整`replacement`对象，不用`new_statement`替代整条边。`base_revision`和`base_sha256`从当前版本取得，不沿用示例值。回到被放弃的旧观点，用 `responds_to`引用相关已接受提案，并在正文回应当时放弃它的理由。

## 独立复核执行

复核者先读冻结原文、机制卷宗、必要计算和旧反对意见，再读作者的结论。分别回答：事实口径是否匹配、因果方向是否合理、替代解释能否解释同一事实、量级是否足够、资源与时滞是否现实、修改是否真正解决旧争议、正文和参数是否跟随变化。

指出最能改变主判断的错误或补证。作者回应后，复核者明确通过或拒绝，并给出引用和实际复算结果。拒绝的提案保留历史；修订内容使用新提案ID。不能用投票、折中语气或纯理论例外决定结论。

实际登记流程：

```sh
python work.py --workspace work/<RUN> proposal --file <提案JSON路径>
python work.py --workspace work/<RUN> proposal-review --id <提案ID> --verdict pass --reviewer <真实独立复核者> --note '<具体审查结论>'
python work.py --workspace work/<RUN> apply --id <提案ID>
```

前两步由实际执行者完成实质工作后登记，最后一步由主代理串行合并。拒审用 `--verdict reject`，不再`apply`该提案。审查后目标、来源或补丁原文件改变，按当前版本重新比较并提交新提案。机制与结论分别受影响时，分别复核和修改；更新一条节点不会自动证明其入边仍成立。

## 必交回执

交付时用简短回执列出：主判断、改变的旧主张、承重证据、最强反证及回应、实际运行、待合并文件/提案、受影响下游，以及精确断点。主代理据此接续，完整推理保存在正文与输入输出中。

必须把本题作出明确判断：采用哪个解释、为什么胜过替代解释、在什么群体和时间成立、什么变化会改判、对应什么行动。每轮留下真实研究增益，不以文件数和辩论轮数代替分析。
