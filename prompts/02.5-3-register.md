# 2.5第三步：登记Boss

你的任务是把第二步已经整理好的材料变成可读取的数学对象登记。收到任务后立即运行代码和读取文件；不要先写权限说明、背景解释或防御性长文。

启动：

```sh
python work.py --repo <独立clone> start --actor BossN --role curator --save repository-cleanup --branch rebuild/research-v2 --workflow-run p25-register-v2 --token-file <仓库外凭据>
```

启动后执行：

```sh
python work.py doctor
python work.py sync
python work.py research prepare-inputs --scope repository \
  --coverage-note '第二步已发布材料的当前正式文件快照；本命令只绑定字节，不作数学准入' \
  --output research/registration/inputs.json
python work.py checkpoint research/registration/inputs.json -m 'Freeze 2.5.3 input inventory'
python work.py research freeze --inputs-file research/registration/inputs.json
python work.py checkpoint research/registration/baseline.json -m 'Publish 2.5.3 frozen input baseline'
```

写入统一通过 `work.py checkpoint`。命令成功就继续；命令失败才报告错误并保存本地成果。

登记规则只有这些：

- 一个Markdown页面可以登记多个对象；多个材料可以支持同一对象。
- 对象是定义、模型、定理、引理、反例、构造、方法、算法保证、猜想、障碍或开放义务。
- 材料编号、对象ID、任务ID、edge_id分开。对象ID用 `research new-id` 一次分配，已有ID继续使用。
- 保留模型、域、量词、假设、结论、状态、范围、证据和反对意见。改题目时创建新版本或新对象。
- 正文不搬、不合并、不切碎；代码和输出只有在有数学owner时登记为附件。
- 不能判断的材料写 `needs-decision`，继续处理其它批次。

执行方式：

1. `prepare-inputs`只从当前正式归档文件生成path/SHA清单；若只处理一部分，使用`--scope partial --path ...`逐项列出，不能用旧数量代替文件清单。检查清单后先checkpoint/pushed，再freeze；freeze不会替你猜材料。
2. 每个处理者只写自己的`research/registration/batches/<batch>.json`，格式固定为：

```json
{"schema":2,"objects":[],"materials":[],"edge_files":[]}
```

对象正文和证据必须引用冻结字节；新增对象用`python work.py research new-id --count N`一次分配。批次完成后立即checkpoint，只有远端确认`pushed`才交给集成人。

2.5.3不临时发明第二套抢任务系统：登记集成人先生成并推送`research/registration/assignments.json`，每行固定写`batch_id,owner,material_paths,write_path`，材料路径不得在两行重复，`write_path`必须唯一。各Boss只处理自己被分配的batch；公屏只公布分配、pushed批次和handoff。若分配表不存在或范围重复，立即停止，不让多个Boss凭公屏口头认领同一材料。

```json
{"schema":1,"baseline":{"path":"research/registration/baseline.json","sha256":"..."},"assignments":[{"batch_id":"batch-01","owner":"Boss1","material_paths":["archives/.../state/a.md"],"write_path":"research/registration/batches/batch-01.json"}]}
```

```sh
python work.py research assignments-check --assignment-file research/registration/assignments.json
python work.py checkpoint research/registration/assignments.json -m 'Publish disjoint registration assignments'
```

3. 汇总manifest固定为：

```json
{"baseline":{"path":"research/registration/baseline.json","sha256":"..."},"batches":[{"batch_id":"batch-01","record":{"path":"research/registration/batches/batch-01.json","sha256":"..."}}]}
```

集成人先`work.py sync`再读取远端批次，重算每个SHA，运行`research compose --manifest research/registration/batches.json`；冲突就保留两个版本并处理冲突，不静默覆盖。恢复时重新sync、重读manifest和批次，不依赖公屏摘要。

4. 集成人写候选registry，运行`research register --record-file research/registration/proposed.json`和`research registration-check --final`。
5. 每个有价值批次和汇总都立即checkpoint；远端返回`pushed`才写入公屏和交接。登记完成后才进入第三阶段，不能在2.5.3里提前造边。

本阶段只建立对象登记和读取入口。完成登记后立即交给第三阶段，不在这里建超边或启动数学Solver。
