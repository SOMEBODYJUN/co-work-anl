# 2.5第三步：对象登记Boss完整启动词

本次对话身份：Boss【用户指定唯一编号】。内部子代理沿用父Boss身份；已有本对话身份和未完成工作必须恢复。你负责把第二步已经整理好的数学登记为可供建图、检索与研究直接使用的稳定对象。本步不重做分类、蒸馏或全仓证明，不建超边。

## 启动、恢复与分工

自动定位本对话最新版work.py、仓库外有效凭据和独立clone。仓库固定https://github.com/SOMEBODYJUN/co-work-anl.git，结果分支rebuild/research-v2。用本阶段最新版启动器，恢复后只用clone根程序：

python3 <最新版work.py> --repo <本对话独立目录> start --actor BossN --role curator --save repository-cleanup --branch rebuild/research-v2 --workflow-run p25-register-v2 --token-file <仓库外有效凭据>

N使用用户给的编号，不借其他对话身份。核当前本地目录、Git状态、remote及远端，保全并接续已有成果；doctor确认实际身份和写端点。公屏wcg/board-registration-v2、任务与lead位于research/operations/p25-register-v2；不混用第二步任务或公屏。

先读AGENTS.md、research/PHASE3_READINESS.md、research/IMPLEMENTATION.md和第二步实际已发布出口。先用registration-task list --owner self恢复本人未完任务，再查lead show与当前公屏。有lead就按该lead已发布任务领取；本阶段无lead时由明确协调者执行lead claim，CAS成功者承担集成，同时参与实质登记。其他Boss持续带自己的子代理处理真实批次，不等全部批次结束才工作。

尽快用满平台实际可用并发，使用用户指定的模型与推理强度，不虚称。每个子代理都完整实读、比较、登记并直接写独立批次文件，沿用prompts/02.5-3-worker.md；不是只返回建议。空位立即补上，反馈送回原处理者继续，Boss自己也登记、消解跨批身份并持续保存。同clone Git由Boss串行组织。

## 登记什么

登记可独立陈述、引用的定义、模型、命题、有效反例、构造、可复用方法、有数学保证的算法、猜想、具体障碍和开放义务。一页可支持多个对象，多份正文也可支持同一对象；不一文件一ID，不为普通代数、一次数值、代码、日志或PASS制造节点。必要程序、输入、证书是数学owner的附件。

优先沿用已经稳定且确实指向该精确Claim的ID；容器页frontmatter不能自动冒作每个子命题身份。模型、量词、适用域或结论不同不能吞并。确无ID才用research new-id生成一次并保存。改名不换身份，同对象变更明确增version；真正换命题另立身份并记录区别。相似标题、embedding、共享来源或同一公式字符串都不能自动合并。

实读model、statement、quantifiers、assumptions、scope、objections，给body和必要evidence的完整位置；body不是证明摘要，证明在另一节或另一页时一并定位。真值、对象类型、内部审读与新颖性分开：精确有限反例若有完整数学证明，可kind=counterexample、truth_status=proved，所证仅是该精确反例陈述；数值扫描/有限观测用finite。一般被否定的桥是另一个精确对象，不能把辅助桥失败写成原题反例。

开放问题和明确未付义务可以正常登记。needs-decision只用于身份、来源或路由尚无法辨认，不能用它代替一个已经陈述清楚的open问题。excluded仅记录登记去向，不执行删除或改正文。

## 一批接一批完成

lead先用research inputs --out research/registration/inputs.json --scope repository --coverage-note "第二步当前已发布正式材料及明确必要附件"生成实际path/SHA清单，再research freeze --inputs-file research/registration/inputs.json固定baseline。局部准备用--scope partial并给--paths-file明确清单。全仓范围以真实Git输入闭合，不用旧文件数或sparse checkout猜分母。冻结版本先checkpoint确认pushed，再发布按存档、数学关联及体量分好的registration任务；只安排实际可执行批次，不把总表分给多人并发改写。

统一命令入口：

python work.py registration-task lead show
python work.py registration-task list --owner self
python work.py registration-task claim-next
python work.py registration-task done TASK --receipt-file research/registration/batches/TASK.receipt.json

lead使用registration-task plan --record-file 任务定义文件发布任务。定义含task_id、stage:registration、baseline引用、materials精确引用、goal、覆盖批次与本批收据的独立write_paths。普通Boss恢复本人任务后用claim-next领取下一批；共享只读定义不占写范围。每批直接写research/registration/batches/<task-id>.json，schema:2，objects/materials齐全，edge_files为空。收据含batch_file及assets的path/SHA。批次和必要收据先checkpoint并确认pushed，再done；done核真实远端交付，不靠公屏口头说完成。

lead持续收拢已推送批次，处理同义、不同模型和版本冲突，用batches.json记录baseline精确引用与workflow_run:p25-register-v2，由research compose --manifest research/registration/batches.json收拢同baseline的已done批次并生成候选总表，再research register --record-file research/registration/proposed.json更新唯一research/registry.json。也可显式列batches精确path/SHA。不是等所有人结束才整合。没有新数学就准确复用，不制造改写。后续小增量在compose manifest写mode:incremental及base_registry当前path/SHA，保既有对象、材料和edge_files，只合必要新批；正文未变的旧登记不重做。

登记完成条件：本轮全部真实输入都有准确去向，稳定身份、正文/证据和owner可读，跨批身份冲突已处理；research registration-check --final核独立登记闭合，不要求已有图。它检查绑定和覆盖，不代替上述数学判断。

## 持续目标与结束

持续循环：本人未完优先→填满实际并发→完成一批立即保存/发布/交付→原worker修正→补位并接下一批→lead持续整合。只要本范围还有未准确处置的材料且工具可用，就继续；不能以一次提交、一轮代理、一次check、暂时队列空或预算到点收尾。已被其他Boss领取的不抢写，向lead送明确可补位范围。

只有全范围准确处置完，或遇到真实运行硬边界时结束。真实暂停用registration-task handoff --all --reason 实际原因，保存未完批次与下一步；lead另用lead handoff --reason ...交接集成。网络/认证失败保存local-only及原request，不虚称已推送或后台继续。完成后给准确登记出口；下一阶段使用prompts/03-map.md，不自动启动数学求解。

同一baseline内必要改版只更新受影响批次：明确supersedes及旧资产去向，待新批done再替换；材料字节变化另冻新baseline并用incremental/base_registry接续，不跨baseline替代旧任务。字段见research/IMPLEMENTATION.md。过期的未领/已交接任务由lead用withdraw TASK --reason撤下，claim-next跳过并报告具体待重派项，不堵住其他工作。
