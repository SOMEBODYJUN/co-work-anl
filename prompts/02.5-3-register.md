# 2.5第三步：登记Boss

你的任务是把第二步已经整理好的材料变成可读取的数学对象登记。收到任务后立即运行代码和读取文件；不要先写权限说明、背景解释或防御性长文。

启动：

```sh
python work.py --repo <独立clone> start --actor BossN --role curator --save repository-cleanup --branch rebuild/research-v2 --workflow-run p25-register-v2 --token-file <仓库外凭据>
```

启动后执行：

```sh
python work.py doctor
python work.py sync
python work.py research freeze --inputs-file research/registration/inputs.json
```

写入统一通过 `work.py checkpoint`。命令成功就继续；命令失败才报告错误并保存本地成果。

登记规则只有这些：

- 一个Markdown页面可以登记多个对象；多个材料可以支持同一对象。
- 对象是定义、模型、定理、引理、反例、构造、方法、算法保证、猜想、障碍或开放义务。
- 材料编号、对象ID、任务ID、edge_id分开。对象ID用 `research new-id` 一次分配，已有ID继续使用。
- 保留模型、域、量词、假设、结论、状态、范围、证据和反对意见。改题目时创建新版本或新对象。
- 正文不搬、不合并、不切碎；代码和输出只有在有数学owner时登记为附件。
- 不能判断的材料写 `needs-decision`，继续处理其它批次。

执行方式：

1. 从第二步实际出口生成 `research/registration/inputs.json`，冻结当前path/SHA。
2. 每个登记处理者只写自己的 `research/registration/batches/<batch>.json`，`edge_files`保持空。
3. 集成人用 `research compose` 合并批次，冲突就保留两个版本并处理冲突，不静默覆盖。
4. 集成人写 `research/registry.json`，运行 `research registration-check --final`。
5. 每个有价值批次都直接 checkpoint；远端返回 `pushed` 才写入公屏和交接。

本阶段只建立对象登记和读取入口。完成登记后立即交给第三阶段，不在这里建超边或启动数学Solver。
