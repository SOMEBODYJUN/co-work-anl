## 恢复、分工和持续目标

先读AGENTS.md、research/IMPLEMENTATION.md、research/PHASE3_READINESS.md及第二步实际出口；内部处理者使用prompts/02.5-3-worker.md。这些由你自行读取，不要求用户另提供Project文件。

先registration-task list --owner self恢复本人未完，再lead show与当前公屏。已有lead就接其发布任务；无lead时lead claim，CAS成功者承担集成，同时参与实质登记，其他Boss继续自己的数学批次。尽快用满平台实际可用并发，按用户指定模型/强度启动，不虚称。每个子代理完整读原文、比相关成果、写独立批次、自查；Boss也实质整理身份与跨批联系。同clone Git由Boss串行。

持续循环：本人未完优先→填实际空位→读写一批→成熟立即checkpoint/pushed→done→反馈原worker继续→完成者立即接下一批→lead边做边集成。只要本范围还有未准确处置材料且工具可用，就继续；不能以一轮代理、一次提交、一次检查、暂时队列空或自设预算结束。没有可领项就向lead给具体可补位范围，不抢别人正在写的成果。

## 输入与批次

只有本run尚无已发布baseline时，lead初始化真实输入；其他Boss复用该冻结版本，不各自重写总清单：

```sh
python work.py registration-task lead show
python work.py registration-task lead claim
python work.py research prepare-inputs --scope repository --coverage-note '第二步当前已发布正式材料及明确必要附件' --output research/registration/inputs.json
python work.py checkpoint research/registration/inputs.json -m 'Publish actual registration input inventory'
python work.py research freeze --inputs-file research/registration/inputs.json
python work.py checkpoint research/registration/baseline.json -m 'Publish registration baseline'
```

repository按真实Git输入闭合；稀疏缺页先恢复，不用可见文件数冒充全仓。局部明确用--scope partial --path <实际路径>，可重复--path。必要附件显式加入清单。输入已存在就恢复而非覆盖；材料字节变更另冻新baseline。

lead按数学关联和实际体量写任务定义，再registration-task plan --record-file <定义文件>，成功即发布。普通Boss恢复本人任务后claim-next，只领当前有实际空位可做的批次，不预占以后工作。字段见IMPLEMENTATION：task_id、stage:registration、baseline引用、materials精确引用、goal、独立write_paths。材料可共享阅读，批次写路径互斥。

```sh
python work.py registration-task list --owner self
python work.py registration-task claim-next
python work.py registration-task done TASK --receipt-file research/registration/receipts/TASK.json
```

每批写research/registration/batches/<task-id>.json，schema:2，objects/materials齐全，edge_files:[]。收据含batch_file及assets的path/SHA。批次和收据先checkpoint确认pushed，再done，不靠公屏口头完成。已有固定owner安排则按用户安排执行；assignments-draft --owners <用户明确的Boss逗号清单>可生成可选安排草稿，assignments-check核表；不预填不存在的Boss，也不要求每轮另手填一套表，实际状态以阶段队列为准。

## 数学登记

一页可登记多个精确对象，多份正文可支持同一对象。定义、模型、定理/引理、条件结论、有效反例、构造、可复用方法、算法保证、猜想、具体障碍和开放义务均可登记。普通算术、一次数值、程序、日志和PASS不另造节点；必要输入/代码/证书作为数学owner附件。

优先沿用指向该精确Claim的稳定ID；容器页ID不吞不同命题，新对象才research new-id一次生成并保存。模型、量词、域或结论不同不因标题相似而合并。同对象实质改动增version，换命题另立身份并说清区别。

实读并保留model、statement、quantifiers、assumptions、scope、truth_status、objections、准确来源及body/evidence。定位完整必要论证，不把证明缩成一句摘要，也不为编号切碎或搬正文。精确有限反例若有完整证明可proved；扫描/观测为finite。一般被否定的桥与原题保持独立。已经陈述清楚的open数学可正常登记，needs-decision只用于身份、来源或去向尚无法辨认，不等于必须解完开放问题。

## 集成、增量和交接

lead持续registration-task collect --baseline <本轮已发布baseline路径>收已done批次，先保全本地并sync。manifest用baseline精确引用与workflow_run:p25-register-v2，research compose --manifest research/registration/batches.json生成候选；也可显式batches精确引用。消解同义、不同模型和版本冲突后research register --record-file research/registration/proposed.json，由一个lead改唯一总registry，不等所有人结束才整合。

后续定向增量manifest用mode:incremental及base_registry当前精确引用，保已有对象、材料和edge_files。新baseline不重收旧baseline。仅同baseline替换已done批次才supersedes并明确旧资产去向；字段见IMPLEMENTATION。过期available/handoff任务由lead用withdraw TASK --reason撤下，claim-next跳过并报具体待重派项，不堵其他工作。

全部真实输入都有准确去向、稳定身份、完整正文/证据及owner可读、跨批冲突已处理后，research registration-check --final独立验登记，不要求图；程序检查不替代数学判断。

真实暂停用registration-task handoff --all --reason <实际原因>保存草稿、已共享情况和下一步；lead另lead handoff交接集成。网络/认证或真实工具硬边界时保local-only及原request，不虚称pushed/done或后台继续。全范围准确处置完才交登记出口，下一阶段用prompts/03-map.md。
