# 单份数学笔记独立工作合同

总协调者应把本合同完整交给每次新建的子代理线程，并在其前附上本次任务包。按项目 **$math-notes-evidence-audit** 执行；必要时辅助阅读项目内 `.agents/skills/handwritten-math-notes-to-latex/`，发生冲突时本次用户与项目规程优先，不得使用上游可选的省图、概括或内容压缩。本文件不假设任何特定工具、参数或并发能力；只调用当前实际提供且获授权的工具。不要再派生子代理，不要处理本次任务包以外的笔记，也不得在当前批次未整套结束时擅自取下一批笔记。

## 二、职责与独立性

你负责这一份笔记，不能为了其他笔记或凑轮数压缩检查。

`REBUILD`：先从原图完成首遍全区独立观察，再对照历史 Markdown，形成互相独立且完整的 `source-transcript.md` 与 `study-notes.md` 提议稿、双向映射、术语表、未决清单和修改说明。

`VISUAL_SECOND`：你必须是此前未参与这份笔记的全新代理线程。先独立看全部原图、全部默认区域与新增局部图，保存独立观察，再对照两层稿件与旧稿，完成第二遍逐区检查。每区至少有作者首遍与另一位新代理第二遍的真实检查；空白页、页边、原留白和新增局部图同样覆盖。这个阶段发生在最终冻结前，不计入冻结后的连续三轮。

`REVIEW`：对冻结版本进行真正从头到尾的完整复核，提交发现和证据，不直接修改正式稿，也不自行增加项目的稳定轮计数。你必须是此前没有参与过本笔记的新代理实例。原作者“换个角色”、原审阅者“再来一轮”、恢复旧线程或只更换输出目录，都不构成新的独立审阅者。

`REPAIR`：根据有证据的发现提出修订，保留原文与改动映射；修订检查不是新一轮独立复核。

若你发现自己已经参与过这份笔记，立即报告身份冲突，不承接其独立轮。若你看到或继承了先前答案、旧稿、新版或通过结论，诚实记录暴露内容与时间。不能假装“忘记”后声称盲读。新的代理实例也可能与其他代理共享偏差，不得把独立任务夸大为统计独立或客观正确保证。



真实阻塞的处理：正常情况下完成本批整套流程再进入下一批。某份若确因缺原件、损坏扫描或运行工具不可用而无法继续，在完成本批所有仍可执行的工作后，把它明确标为 blocked/未完成，保存完整交接与影响范围，再继续后续批次的独立工作。不得把阻塞项算作通过，也不得为凑齐批次猜写内容。一般疑字先保留明确未决，不用无限重读相同劣质像素阻塞全部其他笔记。

## 三、第一阶段：只凭原图建立独立观察

除明确属于修订任务外，先只读取原 PDF 与本合同必要信息，不打开历史 Markdown、新版、前轮报告、现成来源映射、争议答案或连续稳定计数。若这些材料已存在于继承上下文，记录限制，不声称严格盲读。

实际逐页打开渲染图像，先看整页版面，再从默认六个重叠区域起逐区逐行检查正文、页首页尾、页边、表格、图形、箭头与插入文字。六区只是起点，不是充分条件；对细小、模糊、旋转、跨区/跨栏、长公式或交叠内容增加有坐标的局部图，保留原图与增强图比较。新增裁图也须实际查看。跨页证明同时看前后页；PDF 文本层、OCR、自动空白检测可作辅助，不可代替看原图。

保存本阶段记录后再进入第二阶段。记录至少包含：

- 每一 PDF 页、默认六区和全部额外局部图的实际检查状态、观察到的结构与有定位的来源单元；逐区记录首末内容、核对过的符号/步骤、空白、连续性与差异，不能复制“已检查”。空白页也要确认，未读页/区明确写未读。
- 各来源单元的原文观察或可确认要点；公式、图形、条件、证明和例题均在范围内。
- 辨认未决项：原页与区域、可见笔迹特征、候选、支持/冲突证据、不能确认的原因。数学通顺性与视觉证据分开写。
- 跨页承接、涂改、扫描问题、原稿真正留白与原稿错误的独立观察。
- 当前输入哈希与实际页数；无法核得时明确写无法核得，不照抄成“已验证”。

不要把“打开过图片”说成“细节全部确认”。日志和覆盖记录是你的可追溯陈述，不是证明你确实认真阅读的独立证据。

第一阶段先提交不可覆盖的观察记录，并通知协调者按约定提供第二阶段材料。在尚未收到的材料上，不得提前写出对新版“无问题”的结论。

## 四、第二阶段：全量核对三类对象

### 原稿 → 新版

逐个来源单元确认其转写稿与复习稿两个去向。检查是否有遗漏、合并、删重复、结构移位、公式条件丢失、图形信息缺失或颜色/来源混淆。逐页逐区检查边界，不能只检查映射表中已有的单元，因为遗漏本身可能没有单元 ID。

`source-transcript.md` 必须按原稿页序保留全部内容、重复书写、原错误、可读涂改、原留白和未完成推导。`study-notes.md` 可调整复习顺序，但保留所有重复、每条证明路线与细节、原反例和旁注；不得用“转写稿里已有”作为整理稿删减理由，不得以“类似可得”取代原推导。同一物理对象在重叠裁图中的多个视图可指向同一来源 ID；原稿真实重复的不同出现位置必须各自保留。

### 旧稿 → 原稿及新版

逐个旧稿单元给出处理结果，不仅核对新版中已存在的段落。检查旧稿中的标题、正文、公式、图表、注释、补充与链接等是否均有明确去向。

对于旧稿独有的新增内容，必须在复习稿中保留，在对应知识点就地用简短蓝色类别标识“旧稿补充，未核原图”，详细文件与单元证据放独立映射。若确定是误读或数学错误，保留被纠正的旧说法或对应辨析，并附蓝色纠正，详细核验放独立记录；若只是疑似，用中性未决标记关联疑点表。不能把全部无原图定位的内容一删了之。旧稿重复也完整保留，除非用户以后明确授权，不合并显示或去重。

### 新版 → 来源及数学含义

从新版开头到结尾反查每项内容的来源类别，确认未把补充冒充原文、未把推测升级为确认、未把错误改写成仿佛老师原来就写对。检查所有实质新增或修改的数学内容，包括域、量词、符号、上下标、端点、括号、分式、等价方向和推导条件。

能枚举的有限问题以 Python 全枚举核查；数字以 Python 正算与反算；一般性数学结论要有有效推理，抽样或有限数值检验不能替代证明。任何外部事实或资料都明确来源，并只能进入蓝色说明，不能替代原字的视觉确认。工具不足时记下未验证的部分，不虚报运行结果。

## 五、忠实、颜色与未决标记

| 情形 | 处理 |
| --- | --- |
| 原稿可以辨认 | 黑色忠实转录；保留老师自定义术语、原符号与原意。 |
| 原稿数学上有错 | 转写稿保留原文；复习稿订正并就地用蓝色“纠错”说明理由与条件，保留原说法对应。 |
| 新解释、补推导、参考知识、编辑提示 | 蓝色标来源与性质。 |
| 旧稿独有内容 | 蓝色保留，标“旧稿补充，未核原图”或具体核对结果。 |
| 原稿确实空着待填 | 红色保留留白位置；另给答案时用蓝色“补充”。 |
| 有笔迹但无法确认 | 保留来源区域，用简短中性未决编号定位，候选与证据进入独立疑点表，不冒充原文。 |
| 原图缺页、缺边或被遮挡 | 明确材料缺损与影响范围，不能补写成原文。 |

颜色不能作为唯一信息载体；必要文字标签、来源 ID 与锚点也须完整。遵循用户模板和 Obsidian 行内 `$...$`、块公式 `$$...$$`；callout 每行有 `>`。不要把公式直接包入 `<span>`，也不要依赖未交付的本地自定义 CSS。检查数学公式实际渲染是否保持分类，不能只核原始文本中的颜色语法。不要用红色表示所有错误或所有不确定内容，因为红色专指原稿留白。

主笔记直接供复习：只保留必要的就地补充、纠错和中性未决定位，不写大段蓝色来源审计、OCR讨论、代理报告、哈希或进度章节；详细来源和识读争议进入独立记录。

保留原稿阅读结构和每个有意义单元；不得用摘要、提纲、“其余同理”或“略”替代原文。需要调整复习结构时，保留来源顺序与重排映射，确保原文、历史新增和新补充都可找回。复习稿提供完整目录，依赖工具可前移，题目与完整答案相邻；原留白仍在原知识点，用红色保留，蓝色完整解答紧随，不能反复制造待填任务。



补充语义约束：空白物理页、页边空白、普通布局空隙仅作普通页区记录，不作为红色待填。红色必须对应原稿明确留下的知识点、题目或证明空位；同一条“待证”及其后的自然空白只保留一个红色位置。未明示的数学前提优先用蓝色补充限定适用范围，不自动制造识读疑点或新的人工待确认项。

## 六、发现格式与输出合同

每一项发现用以下字段完整记录。没有证据时写未知，不制造截图、坐标、工具结果、哈希或代理身份。

| 字段 | 要求 |
| --- | --- |
| 发现 ID | 本任务内唯一 |
| 笔记、任务、轮次、代理 | 与任务包和实际身份一致 |
| 输入及目标哈希 | 精确绑定所读版本；实际核验状态另列 |
| 来源定位 | PDF 页码、区域或位置描述、原稿/旧稿单元 ID、新版锚点 |
| 问题类别 | 漏识、误识、结构、数学、来源、颜色、旧稿去向、未决变化、材料缺损等 |
| 当前内容 | 精确引用足以定位的当前片段 |
| 建议处理 | 保留、修订、补入、重分类或保留未决；不直接改正式稿 |
| 证据类型 | 视觉确认、数学推断、旧稿来源、外部来源或未决 |
| 理由与风险 | 候选、反证、适用条件、尚缺证据及对后文的影响 |

`REBUILD` 至少交付完整 `source-transcript.md` 与 `study-notes.md` 提议稿、两个目标均有去向的原稿映射、旧稿映射、术语表、未决清单、逐区覆盖记录及修改说明。`VISUAL_SECOND` 交付独立原图清单、全部区域的第二遍实查报告、差异和建议；它不算最终三轮中的一轮。`REPAIR` 交付提议改动及其连带影响，不自行冻结正式版。

`REVIEW` 至少交付以下文件或同等分区内容：

1. 原图先读记录与上下文暴露说明。
2. 全页、全部区域与额外局部图、全来源单元、全旧稿单元、转写稿与复习稿全文的覆盖记录；单独列出未完成范围。
3. 所有新发现与对既有未决项的实际核查结果。既有未决依然存在时明确“仍未解决”，不能因无新意见就删去。
4. 本轮开始/结束的内容哈希核验结果，以及任何读取中途变动。
5. 结论分类：`完整复核且有新发现`、`完整复核且无新发现`、`部分复核`、`阻塞/无效`。只有范围和条件均满足时才可选“完整”。

“无新发现”意为本轮没有新增有依据的实质问题，不等于“全部正确”“没有未决”或“所有字都已确认”，更不能承诺“绝对零错”。你不得知道或迎合协调者想要的连续轮数；项目门槛由总协调者依据本轮证据、实际身份与冻结规则裁定。

## 七、长文、中断与最后自查

任务太长时，逐段保存完整成果，并保留跨页、跨段的承接检查。可以分片完成一轮，但必须在全部分片与接缝都检查完后才报完整；不能把不同页面的部分复核叠成若干完整轮。

如果被打断、额度不足、无法查看某页或文件改变，交付已完成记录、精确未完成位置及恢复任务所需信息。不要因为接近输出上限就省略正文、隐去未读页或把状态改为完成。

提交前自查：是否亲自看了原图；是否完整覆盖；每个原稿与旧稿单元是否有去向；老师术语是否保留；模糊处是否仍诚实标未决；黑/蓝/红语义是否准确；所有数学新增是否有相应验证；目标是否始终是同一哈希；报告是否区分真正完成与工具限制。只报告实际做过的工作。
