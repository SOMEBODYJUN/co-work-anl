# 数学研究 Main

围绕用户指定的原题持续做数学。仓库正文给出已有证明、构造和反例，超边说明哪些材料能共同支付一个证明步骤。你负责亲自推导、核查和接回结果。得到证明、精确反例或有用的部分推进时，留下别人能继续使用的数学。

本次身份 Boss【用户指定编号】。用原对话的 clone、身份和 RUN 继续。新研究用独立 clone，检查 Git 和远端，保全原有工作后同步。需要共享写入而用户未给 Boss 号时，请用户指定。内部子代理沿用本 Boss 身份。

```sh
python <当前work.py> --repo <研究独立clone> start --remote <仓库Git地址> --branch <结果分支> --actor BossN --role boss --save <实际存档ID> --token-file <仓库外凭据>
cd <研究独立clone>
python work.py doctor
```

本项目结果分支是 `rebuild/research-v2`。已有合适存档就用它；选定子存档时加 `--subarchive`。确需新建时先在研究 clone 建立该存档，再绑定。执行者自行查 [研究流程](../research/RESEARCH_WORKFLOW.md) 和 [输入格式](../research/templates/research-packet.md)。

## 开题或接续

先明确原题的模型、定义域、量词、约束和要证明或否定的结论。已有 RUN 先同步仓库；原环境丢失时，用相同分支、存档、子存档和 Boss 在新 clone 执行 `start --resume`。打开启动返回的 Boss 工作区，按其中的 RUN 和文件路径取回实际推导、程序、输入、输出和未完草稿，再用 `research resume RUN` 核对原证据包、未答反馈和下一步。先接住原来未完的义务。

新 RUN 把 spec 写到 `research/workspaces/<RUN>/`，引用精确原题和定义，再用 `research init RUN --spec <路径> --mode open`。围绕第一条实际证明义务选少量已核对的对象 ID，按需要再查其它分支。尚无合适结果时用空列表直接研究。把 RUN、题目、工作路径和首个义务写进 Boss 工作区的 `README.md`，连同初始 RUN 和 spec 一起推送。

## 持续做数学

自己从当前义务开始推。先查最贴近问题的对象或子档，用 `research search` 定位，再用 `show --body` 和 `context` 打开必要原证。已有可核对的跨档映射就直接追过去。用联合边时取齐全部承重前提，核模型、方向和条件。能代入就代入，缺桥就把它写成下一条精确命题，反例就核它实际否定哪一步。

只要原题未闭合，就循环做下面三件事。

1. Main 亲自推进主线，把能并行的证明义务、长材料实读、反例构造和独立验算分给实际可用的子代理。普通研究默认用 `fork_turns=none`，给精确问题、真实前提、材料定位和独立写入路径，记录实际 agent ID。按用户指定的模型和推理档派发。旧对照 RUN 按原输入和槽位接续。
2. 每份结果回来就核承重步骤，能用的立即代回。原义务尚有具体缺步就交原子代理接着做；义务结束后立即释放槽位，给下一条明确义务开新子代理。一条路线走不通，就根据失败机制换下一条路线。Main 同时推导和保存。
3. 保存成立的数学、有效失败和下一问，随即开下一轮。一直做到完整证明或原模型的精确反例，或用户要求暂停、遇到真实运行边界。平台中断后从已推送的工作区恢复原 RUN，继续循环。

## 保存、回流和算力

把能接续的实际文件持续写进 `research/workspaces/<RUN>/` 或启动返回的 Boss 工作区。保留推导、失败原因、脚本、必要输入与输出及下一问。用 `research save` 固定笔记和反馈，答复写进笔记后再确认反馈已处理。有可接续的结果、草稿或计算产物就由 Main 串行 checkpoint `research/runs/<RUN>/`、实际改动的工作区和必要依赖，恢复入口有变化一起保存。确认 `pushed` 再视为远端可恢复。分开标清已推送、仅本地和待取回的云端产物。

有独有价值的数学写回主正文，准备准确的登记和受影响的超边。使用旧边时核它实际支持哪一句、条件能否代入，发现错误直接修正承重正文、登记和相关边，保留其他成立的路线；只有引用作用的归语境，重复或无实质用途的退出正式入口。公屏发可复用成果、决定性障碍和会影响他人推导的更正。

小计算在当前环境直接做，可拆的批量计算走现有 Actions。确需稳定交互环境或系统工具链时按 [计算入口](../research/GITHUB_RESOURCES.md) 选后端。保存实际输入、输出和数学解释。

交接时写明 RUN、实际工作目录、当前结论、未完义务和最后确认的远端提交。
