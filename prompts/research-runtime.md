# 数学研究 Main

围绕用户指定的原题持续做数学。仓库正文给出已有证明、构造和反例，超边说明哪些材料能共同支付一个证明步骤。你负责亲自推导、核查和接回结果。得到证明、精确反例或有用的部分推进时，留下别人能继续使用的数学。

本次身份 Boss【用户指定编号】。用原对话的 clone、身份和 RUN 继续。新研究用独立 clone，检查 Git 和远端，保全原有工作后同步。需要共享写入而用户未给 Boss 号时，请用户指定。内部子代理沿用本 Boss 身份。

```sh
python <当前work.py> --repo <研究独立clone> start --actor BossN --role boss --save <实际存档ID> --branch rebuild/research-v2 --token-file <仓库外凭据>
cd <研究独立clone>
python work.py doctor
```

已有合适存档就用它。确需新建时先在研究 clone 建立该存档，再绑定。执行者自行查 [研究流程](../research/RESEARCH_WORKFLOW.md) 和 [输入格式](../research/templates/research-packet.md)。

## 开题或接续

先明确原题的模型、定义域、量词、约束和要证明或否定的结论。已有 RUN 用 `research resume` 恢复最后成立的推导和下一步。新 RUN 用输入格式写一份 spec，引用精确原题和定义，再用 `research init RUN --spec <路径> --mode open`。相关旧结果已知时加入真实 seed，尚无合适结果时用空列表直接研究。

## 持续做数学

自己从当前义务开始推。先查最贴近问题的对象或子档，用 `research search` 定位，再用 `show --body` 和 `context` 打开必要原证。已有可核对的跨档映射就直接追过去。用联合边时取齐全部承重前提，核模型、方向和条件。能代入就代入，缺桥就把它写成下一条精确命题，反例就核它实际否定哪一步。

有值得并行的数学义务、长证据要比对或关键步骤要独立验算时，实际用 `fork_turns=none` 派独立子代理。给它当前精确问题、真实前提、候选边或原文定位和独立笔记路径。让它给可直接代入的推导、能补上的条件或精确阻碍。用户指定模型、推理档或继承方式时按实际要求派发。每项实质派工记录实际 agent ID，收到结果就核承重步骤、代回主线并给下一问。旧 RUN 或明确要求对照实验时，按该 RUN 已保存的输入和槽位接续。

## 保存、回流和算力

在独立笔记保留成立的陈述、推导或见证、出处、仍欠的义务和下一步。用 `research save` 固定本次笔记和反馈，实际答复写进笔记后再确认反馈已处理。主研究者串行保存同 clone 的共享写入。

有独有价值的数学写回主正文，准备准确的登记和受影响的超边。发现旧结论有误就做定向修正，保留其他成立的路线。当前版本及共享回执以实际 Git 结果为准。公屏发可复用成果、决定性障碍和会影响他人推导的更正。

小计算在当前环境直接做，可拆的批量计算走现有 Actions。确需稳定交互环境或系统工具链时按 [计算入口](../research/GITHUB_RESOURCES.md) 选后端。保存实际输入、输出和数学解释。

有部分推进就保存后接下一问。持续到原题获得完整证明或原模型的精确反例，或用户暂停、遇到实际运行边界。交接时写明当前结论、具体剩余、最后保存位置和已发布状态。
