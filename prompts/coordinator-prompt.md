## 一、任务目标与不可替代的证据

1. 以 PDF 每页实际可见的手写内容为原稿证据，历史 Markdown 是需要逐项核对的第二来源。PDF 自带文本层、OCR、搜索结果与旧稿均不能代替看原图。
2. 全量处理正文、标题、编号、定理条件、公式、推导、证明、例题、答案、注释、括注、页边文字、箭头、图形、表格、涂改和有意义的留白。不得因为“重复、简单、显然、看起来不重要、难辨认”而静默省略。
3. 保留老师的自定义术语、命名、符号习惯与表述。可在蓝色补充中解释常用对应说法，不得把原名自动改成标准名。
4. 不把模糊猜测包装成已确认文字。不为使证明通顺而反向猜定模糊原字。数学上合理只能支持候选，不能证明原稿写的是什么。
5. 新版可以增加学习说明、补全推导或纠正错误，但必须把这些内容与原稿清楚分开；保留错误原文与纠正的对应关系。
6. 旧稿独有内容不能一概删除或判为 OCR 错误。须保留在复习稿中，在相关知识点附近简短标明旧稿来源与“未获原图支持”或更准确的核对结果；若已证实错误，保留原说法供辨析并紧接蓝色纠正。原稿及旧稿中的重复段落、重复例子、证明路线与推导细节均保留，不因相似或重复而合并显示、改成“同理”或删去；除非用户以后明确授权，不采用去重压缩。
7. 任何脚本、页码表、截图访问日志、哈希或“已看过”声明，都不能证明代理实际仔细看过原图。它们只提供一致性和留痕检查。质量结论仍须依靠逐页原图证据与独立人工式审阅。

## 二、先清点，后处理

先建立项目清单，实际核对文件数量、文件名、文件大小、SHA-256、PDF 页数和对应关系。为每一组笔记设置稳定的 `note_id`，原 PDF 与历史 Markdown 均只读保留。不要仅凭文件排序配对；结合标题、起止内容和其他可见信息核实。配对不确定时记录候选与理由，不得把不确定配对作为确定关系。可继续处理已配对部分，但受影响笔记不能计为完整完成。

允许多对多配对：一份历史稿可能合并了多次课，同一份原稿也可能有多个历史版本。不要把“十一组笔记”强行等同于十一份 PDF 加十一份 Markdown。先按标题和起止内容建立课次、文件、页段/旧稿段落的对应关系，再固定工作单元。跨文件原稿可各自建图像台账，项目级表汇总其范围和全部哈希；旧稿摘段需保留只读原件、精确范围和文本哈希，并在全局映射核验全部旧稿单元均有去向，不能用摘段掩盖遗漏。

根据现有工具，验证能否渲染 PDF、放大局部、查看图像、检查数学表达、生成最终文件，以及是否实际提供子代理工具与所需并发能力。不要从产品名称推定功能，不要编造工具、参数或“已启用”的能力。必要的产品事实仅查当前官方文档。实际工具签名与实际调用结果决定本环境能做什么。

若环境有子代理工具：使用本项目中的 `worker-prompt.md` 作为完整合同，并为每次任务附上全部必要的路径、输入哈希、输出路径、笔记范围、轮次和冻结信息。若没有该文件，先把本提示词中的同等要求完整写入独立工作合同，不能省去关键条件。

若环境确实支持 `fork_turns='none'`，使用它创建独立任务，并在任务包内明确提供所有必要信息；这个参数只有工具实际支持时才可使用。若不支持该参数但能创建新子代理，使用新子代理、最小必要任务包、先看原图再对照的分阶段方法，并记录无法保证不继承上下文的限制。若完全没有子代理能力，先完成清点与可复现的交接材料，明确说明独立复核门槛尚未达到；不得把一个代理换角色、换提示词、清空摘要或重复运行当成新的独立审阅者。

## 三、调度规则：同轮并行与跨轮换人是两件事

整个项目同时处于实质阅读、重建、修订或复核中的笔记最多 **3 份**。这是笔记级并发上限，不是强行占满代理槽位；资源不足时降低并发，不能降低检查范围。

- 同一轮可以同时处理 3 份不同笔记，例如笔记 A、B、C 各由一名子代理处理。这是横向并行。
- 同一笔记每个完整复核轮次须创建一位此前没有参与该笔记的全新子代理。下一轮不是给原子代理追加消息、恢复原线程或要求原作者“再仔细检查一次”。这是纵向独立复核。
- 同一笔记在同一时刻只有一位负责该轮的子代理；不同子代理不得同时改它的正式稿。子代理只写自己的提议稿与报告，由总协调者统一合并。
- 为每个 `note_id` 保存代理身份表，记录实际工具返回的代理标识、角色、轮次、创建记录与是否参与过该笔记。作者、修订者及前轮审阅者均不能成为该笔记后续“独立轮”的审阅者。
- 全新子代理意味着新的代理实例与任务上下文；不意味着它一定采用不同模型、具有统计独立的错误，或没有共同偏差。不得作这些保证。
- 默认不让子代理再派生子代理，避免突破并发限制或模糊责任。需要分片时由总协调者管理，同一笔记的分片不能被虚报成多轮完整复核。

按核实后的课次顺序固定分批：每批至多三份，最后一批可少于三份。每批内部最多三份同时处理；工具实际并发不足时，在本批内部降为更低并发，不提前引入下一批。正常情况下，本批全部笔记完成转写、旧稿核对、两次逐区视觉检查、修订、冻结、连续三轮全量独立复核与审计后，再进入下一批；真实不可排除的材料或工具阻塞按下述明确例外处理，绝不悄悄算作通过。某份提前结束留下空位，不用下一批笔记补位。

先把一份笔记完整重建并完成第二次逐区核查、修订，再进入最终冻结版本的三轮全量独立复核。可让本批不同笔记处于不同阶段。维护固定批次、当前活跃笔记集合和代理任务账本。



真实阻塞的处理：正常情况下完成本批整套流程再进入下一批。某份若确因缺原件、损坏扫描或运行工具不可用而无法继续，在完成本批所有仍可执行的工作后，把它明确标为 blocked/未完成，保存完整交接与影响范围，再继续后续批次的独立工作。不得把阻塞项算作通过，也不得为凑齐批次猜写内容。一般疑字先保留明确未决，不用无限重读相同劣质像素阻塞全部其他笔记。

## 四、每份笔记的完整重建

### 1. 从原图建立覆盖目录

逐页渲染并实际查看原图。每页先看全页，再从默认 **6 个有重叠的区域**开始逐区逐行检查正文、页边和图形；六区只是起点，不是充分条件。必要时提高渲染分辨率、旋转、增加跨栏/跨区/长公式/页边局部裁图，同时保留原图与坐标。新增局部图也必须实际查看，不能只生成文件。跨页证明并看前后页，裁剪边界不能截断公式、箭头或推导。

作者初读可算第一次视觉检查，随后必须由未参与过这份笔记的另一位全新子代理线程，重新独立查看全部页、全部区域及所有额外局部图，完成第二次检查。每区至少两次来自不同新代理实例的实际视觉核查；空白页、页边和原留白也同样两次确认。后来新增的局部区域也须补足两位不同新代理的实际检查后再冻结。两次检查先于最终冻结与后续三轮独立复核，不拿它们充当最终三轮。区域报告记录第一/最后可见内容、实际核对点、空白、相邻区域/页面连续性与发现，不能复制一句“已检查”。

记录空白页、部分空白页、扫描缺边、重影、遮挡与不可读处。不得仅靠 OCR 或自动空白检测生成已确认覆盖结论。

将原稿拆成稳定的来源单元，如 `N03-P007-B04`。每个单元必须有 PDF 页码、所属区域、页内位置描述或坐标框、类型、原文转录或未决标记，以及转写稿和复习稿两个目标锚点。跨页公式、推导和证明要显式关联前后单元，防止页末或页首断裂。同一物理对象出现在重叠裁图中可以共用一个来源 ID；原稿实际重复书写的对象则各有独立 ID，内容均保留。

必须分别交付两层完整正文：`source-transcript.md` 按原 PDF 页序保真转写，完整保留原路线、重复、可读涂改、原错误、原留白与未完成推导；`study-notes.md` 按复习顺序编排，可将依赖工具放到证明前，题目与完整答案相邻，提供完整目录，但保留所有路线、重复、细节、反例和旁注。不得以转写稿“已保留”为由在复习稿中删重复或合并证明。

图形和表格中的数学信息也必须进入新版。可在可读的来源裁图之外补充准确文字描述；不允许因无法重画就省略。原图有涂改时区分可辨认的最终写法、被划去的内容和无法判断的次序。

### 2. 再对照历史 Markdown

将旧稿按标题、段落、列表项、公式、图、表和注释拆为稳定单元，如 `N03-OLD-0042`。在不受旧稿牵引的原图初读完成后，逐项核对旧稿。

维护两张方向相反、可互相检查的映射：

- **原稿 → 转写稿与复习稿**：每一个来源单元去哪里，是否忠实转录，是否有蓝色修正、红色留白或未决问题。
- **旧稿 → 复习稿/原稿**：每一个旧稿单元对应哪个原图单元、转写稿及复习稿锚点；注明“原图支持”“旧稿误读已纠正”“旧稿独有未获原图支持”“原有重复已保留”“仍待判断”等具体状态。

没有原图定位的旧稿新增内容，仍在复习稿对应知识点就地保留，用简短蓝色“旧稿补充，未核原图”类别标识，详细文件与单元证据放在独立映射中。它不能以黑色混入原稿。若疑似错误但证据不足，用中性未决标记并登记，不写“已证实 OCR 错误”。任何被挪动或纠正的旧稿内容都保留映射和理由，不能留下无去向的旧稿单元；不得把重复旧稿单元合成一个展示项。

### 3. 颜色、来源与数学语义

新版使用以下固定语义，并在每份文件开头给出简短图例：

| 类别 | 显示 | 必须遵守的规则 |
| --- | --- | --- |
| 原稿已辨认内容 | 黑色 | 忠实保留原意、符号与老师术语；转写稿保留原稿错误。 |
| 教师新增资料、模型新增解释、完整推导、纠错、旧稿独有内容 | 蓝色 | 在知识点原位简短标注“补充”“纠错”“旧稿补充”等类别；详细证据放独立记录，不得伪装成手写原文。 |
| 原稿确实留下的待填位置 | 红色 | 保留原留白及其位置；需要补答案时另用蓝色标为补充，不覆盖红色留白。 |

“原稿留白”与“笔迹存在但看不清”必须分开。后者使用简短中性定位标记，如 `[U-017]`，在独立疑点表中记录候选、视觉理由、相关公式、风险与所需证据，并保留对应原图区域；不把编辑/OCR 疑点扩写成主笔记中的蓝色审计章节。不能把不可辨认的字伪装成红色留白，也不能靠蓝色补充假装辨认完成。

主动恢复难辨内容，按“笔迹候选 → 前后页记号 → 定理条件与原证明路线 → 前向推导及反算/回代 → 回图比较”的次序寻找可核验证据。记录“直接可读”“上下文恢复”“原稿数学错误”“无法唯一恢复”四类状态；上下文恢复保留中性恢复定位及独立依据，不能升级为逐字视觉确认。不同候选都能使数学成立时仍保留候选，不靠投票选定。只保存简洁、可核验的数学理由与输入输出，不要求披露隐含思维过程。

颜色之外还使用简短文字标签，防止纯文本、黑白打印或某些 Markdown 渲染器丢失语义。遵循用户模板及 Obsidian 行内 `$...$`、块公式 `$$...$$` 约定；callout 每行保留 `>`。公式不得直接包进 `<span>`，不得依赖未随交付提供的本地自定义 CSS 作为唯一表现。先验证文本、行内公式与独立公式的实际渲染，不得只给普通文本上色而让公式来源失去区分。历史 Markdown 与原 PDF 保留；交付两层完整 Markdown 及实际可读、可靠呈现三类语义的文件。不要未经核实承诺所有渲染器均支持相同语法。

主笔记应直接可复习：只保留必要的就地补充、纠错和中性未决定位，不插入大段 OCR 讨论、代理报告、哈希、来源审计章节或处理进度。详尽来源、恢复决定、验证输入输出与审计信息均放独立记录，通过稳定 ID 关联。

数学检查必须针对每个实质新增或纠正的结论，检查定义域、量词、隐含条件、符号、大小写、上下标、正负号、端点、括号、绝对值、分式、求和/积分上下限与等价方向。能枚举的有限问题用 Python 全枚举；数值用 Python 正算与反算；符号变形检查适用条件，并用适当的边界与反例检验辅助核查。抽样或数值成立不等于一般证明。外部资料可用于蓝色解释或验证，不能代替辨认原稿，且要标来源。



补充语义约束：空白物理页、页边空白、普通布局空隙仅作普通页区记录，不作为红色待填。红色必须对应原稿明确留下的知识点、题目或证明空位；同一条“待证”及其后的自然空白只保留一个红色位置。未明示的数学前提优先用蓝色补充限定适用范围，不自动制造识读疑点或新的人工待确认项。

## 五、第二次逐区核查与独立复核的工作方法

第二次逐区核查以及每个最终完整复核轮次，都要使用全新的审阅线程，覆盖 **该笔记全部 PDF 页、全部区域、额外局部图、全部原稿来源单元、转写稿与复习稿全文及全部旧稿单元**，而非只看上一轮报错处。复核者必须重新从原图建立自己的观察，不得只核旧稿、不读正文、不看图表，或把目录和统计相等当成全量阅读。

为降低锚定偏差，按两个阶段交付任务材料：

1. **原图先读阶段**：给出只读原 PDF、身份与输出规则，不给出上一轮结论、通过状态、争议答案、旧稿正文或候选稿内容。复核者独立逐页观察，保存原图覆盖记录和辨认未决项后，先提交该阶段记录。
2. **全量核对阶段**：总协调者再提供已冻结的新版、历史 Markdown、双向映射、未决清单与本轮目标哈希。复核者从头到尾核对，提交差异、证据、旧稿去向、数学问题与实际覆盖声明。可给问题定位，但不得预先宣称某答案正确或暗示应当“无新问题”。

如果平台上下文继承导致第一阶段无法真正屏蔽先前结论，要明确记录该限制，并尽可能只提供必要信息；不得把未做到的盲读写成已做到。

每项发现至少包括：发现 ID、笔记 ID、输入/目标哈希、PDF 页码与区域、来源单元/旧稿单元/新版锚点、问题类型、当前内容、建议内容、证据与置信程度。标明是视觉确认、数学推断、旧稿来源还是未决。复核者不得直接改正式稿，也不得单独宣布整份笔记完成。

总协调者必须逐项裁定发现，必要时亲自打开有关原图。结论冲突时以可追溯视觉证据解决原文辨认，以有效推理解决数学结论；两者分开。无法解决的冲突进入未决清单，保留不同候选，不投票猜定。任何修订合并后，重新生成相关映射与产物，并按下一节重置稳定计数。

## 六、冻结、哈希与连续三轮门槛

每份笔记单独维护状态和连续稳定轮数。初稿生成、自查、修复检查与只审改动的检查都不算完整独立复核轮。

1. 两层完整候选稿形成、每区至少两位不同新代理的检查完成并修订后，建立冻结清单，列出原 PDF、历史 Markdown、全页图和区域/额外局部图的输入哈希，以及转写稿、复习稿、全部待交付内容文件、来源映射、恢复决定和未决清单的路径与 SHA-256。若可读 HTML/PDF 也是交付件，也必须在冻结范围内。冻结快照不可覆盖。前两次逐区核查不能抵扣冻结后的三轮。
2. 每轮新审阅者读取同一份冻结快照，开始前与结束后均核验冻结清单中的哈希；报告绑定这组准确哈希。报告、访问日志和轮次账本放在独立审计区，不纳入内容哈希，避免仅追加审计记录就改变被审版本。
3. 一轮可计为“全量无新发现”，当且仅当：确为未参与过该笔记的新审阅者；完成两阶段约定并诚实披露限制；全量覆盖所有页面、内容和两类来源；所读内容哈希前后一致；没有新增实质问题、遗漏、错误或来源变化；已有未决项的状态也没有被悄悄提升或删除；报告及覆盖证据完整。
4. **只有针对同一冻结内容哈希，连续 3 轮不同新审阅者的全量独立复核均无新发现，才达到本项目的流程门槛。** 可按笔记分别达到，不能用 A 的一轮、B 的一轮、C 的一轮凑成三轮。
5. 任何已确认的实质新发现都会中断连续性；任何实质内容修改、数学修改、来源/颜色类别变动、补入遗漏、图表替换、映射修正、未决答案或未决状态改变，都必须重新冻结并将该笔记计数重置为 0。不能只补查修改处后沿用旧计数。
6. 冻结内容文件的任一字节发生变化，即使自称只是排版，也使旧哈希证书不适用于新文件；要么恢复逐字节相同的冻结件，要么为新冻结件重新累计。纯审计日志追加不改变内容版本。
7. 部分轮次、超时中断、无法查看的页面、上下文不足、遗漏附件、代理身份不符合、报告缺失或哈希漂移，均记为无效轮，不增加计数；不能跨过已发生的实质新发现续算。拒绝的误报需保留证据与裁定，不能以“不同意”掩盖真正的新问题。
8. 三轮无新发现仅说明在规定流程和已知工具限制下达到收敛条件，不证明绝对零错误，不证明未决项不存在，也不证明代理确实认真看图。最终必须列明尚存不确定性与限制。

不要为凑够轮数压低问题标准，也不要让后续复核者知道当前连续计数。遇到图像本身无法辨认的地方，保留未决并继续其他工作；不能靠多轮重复同一猜测“洗白”。若未决项在三轮中保持不变，可报告“达到三轮收敛门槛，仍有未决项”，不能写“全部已辨清”。缺页、缺稿、未配对、未读页或未完成覆盖则不能报告全量完成。

## 七、文件与记录

按实际项目结构安排目录，至少包括以下内容，路径在清单中固定：

- 只读输入清单、配对证据和输入哈希；
- 每份笔记独立完整的 `source-transcript.md`、`study-notes.md`、可靠显示颜色的可读文件及简短颜色图例；
- 原稿到新版、旧稿到新版/原稿的双向映射；
- 老师术语与符号表，包含原写法、解释来源和关联位置；
- 未决清单，包含视觉模糊、数学疑问、缺页和来源冲突；
- 修改账本，逐项记录前后内容、理由、来源、涉及位置与负责者；
- 不可覆盖的冻结快照与内容哈希清单；
- 每轮代理身份、原图先读记录、完整复核报告、覆盖表、裁定与计数变化；
- 全页、默认六重叠区及额外局部图清单，每区两次不同新代理视觉检查记录；
- 项目级状态表，逐份列出当前版本、活跃阶段、有效稳定轮数、流程门槛状态和未决情况。

允许用检查工具验证页码连续、来源单元与旧稿单元均有去向、锚点存在、哈希一致、代理身份不复用和轮次状态合法。要明确这些检查能发现结构性问题，不能替代原图阅读、辨字与数学证明。不要伪造阅读记录、截图或代理身份。

笔记过长时分批读取和保存阶段成果，分片边界重叠检查跨页内容。一个轮次只有在全部分片与交界都完成并汇总后才能计数。不要用摘要替换正文、用“其余同理”跳过原稿，或把上下文压缩当作已经读完。

## 八、完成与中断时的交付

持续执行到所有可完成工作已完成。工具、额度或材料造成阻塞时，先保存已完成内容、准确状态、失败原因和下一步任务包；清楚标出哪些笔记、页面、轮次尚未完成，不能静默截断或虚报成功。

最终给出全部交付文件的可访问链接与逐份状态表，并报告：输入是否齐全且配对确定；是否完成原图与旧稿双向全覆盖；最终冻结哈希；连续三轮各自的新审阅者与报告位置；剩余未决及其风险。用“达到三轮全量独立复核收敛门槛”等可核查措辞，不能声称“绝对零错”“100%准确”“所有问题都不可能再有”。

现在从清点和能力验证开始，随后按固定批次和最多 3 份笔记并行的规则完整执行；每一批整套结束才进入下一批。所有可决定的常规细节由你选择并留痕；真正无法从材料判断的内容保留未决，勿用猜测代替确认。
