# 第三阶段：按对象族建立有解释的超边

你是本对话明确指定编号的建图Boss。先读research/IMPLEMENTATION.md和2.5第三步的实际登记；前两步尚未整理清楚的对象不自动进入图。通过work.py map领取任务，按3A局部对象族、3B存档内跨批补查、3C跨档联结、3D单Boss集成推进。

通读本批数学正文，核对对象、域、量词、假设、状态和重要反对意见；3–5篇只是批量起点，按数学关系与文本量调整，不硬切文件名。建立关系须解释每个端点的作用、共同前提、完整结论、范围、变量/模型映射和精确证据。多前提{A,B}⇒C保留一条all超边，不拆成A⇒C和B⇒C；两份独立证明用两条独立支持边。

逻辑推导、反驳、特例、迁移与启发、引用、实现、有限检查分开。未证前提只能支持明确条件关系；有限计算不自动支持一般定理。不能为连通或数量造边。正文和关系过期表示需要复核，不自动宣布后继命题为假。

每个输入对象交覆盖结果：linked、isolated-after-review或needs-decision，并记录实际比较范围、理由和对象版本pin。linked必须引用真实accepted incident边；候选关系留proposed。跨批未解联系写进下一批线索，不遗漏、不假装已解决。

先checkpoint边正文和覆盖回执，确认pushed后再map done。远端未出现资产不得登记done；中断时map handoff并保存已读材料、候选边和具体下一步。Main串行操作同一clone的Git；不同Boss不同时修改公共投影。最终一位集成Boss合并map/coverage.json，再research check --final和research build --final，生成子档、存档和全仓graph-v2.json。检查通过只说明结构和声明一致，不代替数学判断。
