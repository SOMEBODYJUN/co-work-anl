# 1. `toy_search.py`：signed graph、三值 MMS 与 Delta 玩具

source ID `0dfd4144a8ecf95e50ce`，大小 4995 bytes，SHA-256 `f25aa4dfe14f3f4a789c45b58fd73fd8b9a4907369de7f46fcaed29c025351e4`。

## 1.1 配额 MMS 生成

`equal_partitions(items,n,q)` 固定第一个 item 以去除 block 顺序，对 (m=nq) 件物品穷举等大小 q 的无标号 partition。`mms_trials` 为每个 agent 独立从给定整数 `values` 随机生成 (n\times m) costs；矩阵乘法得到每个 agent 对每个 q-subset 的 cost，`mus` 取每个 n-block partition 中最大 block cost的最小值。随后构造所有 labelled allocations（对每个 unlabelled partition 遍历 agent permutations），检查每人恰 q 件且 own cost≤MMS。若全无 feasible allocation，才用整数交叉乘法计算最佳比例并保存 failure。

因此 `toy_results.mms` 的 280 unlabelled partitions、1680 labelled allocations、10000 sampled profiles 是脚本直接实现的量词；`first_failure=null` 只表示三组固定整数 alphabet 的随机 profiles 未触发 failure。它没有覆盖任意实数、任意 n/q 或连续 MMS。

## 1.2 `mixed_efx` 的实际 (EFX^+_0) 语义

图 edge (e=(u,v)) 的 profile 存两个 endpoint values；orientation 把 edge 给 `edges[e][z]`。`mixed_efx(n,edges,profile,orient,include_zero_own)` 先算每个 observer (i) 对所有 bundle totals。对每个有 envy 的 (i,j)：

- own bundle 中若 item 对 (i) 为负，或 `include_zero_own=True` 且值为零，则逐件检查删去后 own 是否达到对方 total；
- 对方 bundle 中对 (i) 严格正值的 item 逐件检查删去后是否达到 own。

函数仅在**允许删除的 item**上检查；若没有可删项，该侧没有额外循环约束。这正是本题的 zero-removal variant，不能改写成 chores-EFX 或普通 additive EF1。`mixed_extension_toys.py` 传入 `include_zero_own=True`，故前批 C3/C4/C6/cactus 结果的零值语义由此决定。

`cycle_trials` 对 (C_k) 构造 edges ((i,(i+1)\bmod k))，endpoint profile 用 `product(ends,repeat=k)` 穷举；若给 trials 则以固定 seed 随机生成 profile。每个 profile 穷举全部 (2^k) orientations，保存第一个无可行方向的 profile；因此 `no_EFXplus0_witness=null` 是有限 profile 域上的方向存在性记录。

## 1.3 淘汰的 sharp-Δ demo

`optimal_alpha_demo(delta=5)` 对 cost matrix `[[delta,1,0],[delta,0,1]]` 穷举全部 (2^3) assignment，只保留 social cost=delta 的 OPT allocations，并用整数分数比较 own-after-deletion 与 other bundle。该 demo 生成两个 assignment 及 alpha 字段；它支持 restricted-cost Δ 负面 lesson，但脚本自身没有证明任意 (m) 的紧界，且候选报告已把该路线淘汰为简单推论。

# 2. `cross_field_battle/toy_checks.py`：三模型的独立有限检查

source ID `e5e7c644c62fd3c6715c`，大小 5161 bytes，SHA-256 `8fc46c77f144bfbac88d597086ed29356dedece7b68090cb380875b16bd14288`。该脚本把不同模型放在同一运行入口，但没有共享公平定义。

## 2.1 copies

`copies_exhaustive()` 固定 n=3、types=4，遍历 16 个 multiplicity vectors；固定 agent 0 的 type order 为 identity，agents 1/2 遍历 (24^2) strict orders，共 9216 profiles。每个 type 的副本接收者 choices 是 `combinations(range(3),c)`；每 profile 枚举 product 全 allocation，`copies_sd_ef1` 对每个 observer order 做 prefix counts，并在任何前缀出现 count 差超过 1 时失败。结果 `allocations_per_profile=3**t=81`、counterexamples=0。它是与 fair_goods copies 结果独立实现的有限复核，不覆盖 ties、更多 types/agents。

## 2.2 两类无 loops chores

`rank2_exact()` 对 (n=3)、(m=3,4,5,6,7,8) 和所有 `combinations_with_replacement(range(8),m)` 的 3-bit word multiset 穷举，共 12825 个 multisets。`rank2_witness` 在全 word type 出现时取互补 pair；否则枚举缺字、构造邻接图并做最大匹配，给未匹配 item 任一邻居。`rank2_cost` 是 bundle 中第 i 位 distinct labels 数，最终只检查 EF（不是逐件 EFX）。因此 `EF_failures=0` 是**所有 n=3、m=3..8 word multisets** 的有限精确 EF 检查，比随机 rank_toy 更强，但仍只覆盖两类无 loops、固定 n=3；不扩展到三类/loops/rank-cap-2 一般结论。

## 2.3 K8

`key8_random()` 显式生成 category sizes `[3,3,2]` 且每 agent 恰 2 件的 864 allocations，使用 Python `random.Random(20261020)` 生成 1000 个 (0..20) 整数 valuations。valid 条件对所有 (i,j) 检查 numeric EF1（从 (j) 包删观察者最高值 item），并仅在 `i<j` 加 ordered no-envy；每 profile 要求至少一个 valid allocation。它不是连续估值证明，也不把 1000 profiles 与 2cec 的 5000 profiles 直接合并为独立样本。

# 3. `verify_frozen.py`：独立标量核验的真实范围

source ID `c881cce8a0c31075098a`，大小 2111 bytes，SHA-256 `ff19f582a7bbac8d5087f6b5a0e33cd9f54984415cf5bebf2e3b02cf0a3070b5`。脚本读取同目录 `toy_results.json`，对 `keys` 的每个 worst valuation matrix 重新枚举每类 permutations 并计算 feasible allocation 数；逐 (i,j) 检查 numeric EF1 与 i<j ordered no-envy，断言 witness count 等于冻结 `minimum_witness_count`。

随后它读取 `copies` 的 worst rankings 和外部 `copies_exhaustive_results.json` 的 worst profile，用所有 recipient combinations 重新计算每个排序前缀的 own/other counts，断言 count 等于冻结最小 witness。输出五行 `matches_frozen=true` 的含义只是这次独立纯 Python 标量重算与冻结 numbers 一致。

它不检查 `toy_results.mms`、`mixed_graphs`、`discarded_alpha_idea`，也不独立验证 copies 的全部 9216 profiles；输入 toy_results/copies JSON 同时是其前提。因此它是最坏 witness 的独立回算，不是完整重跑、外部审稿或定理证明。
