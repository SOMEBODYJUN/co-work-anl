# 读取范围与模型

三份源都属于四代理、三类型 additive chores 的固定成本边界探针，直接承接三值反例对象 `SEL-CHORES-TRIVALUED-AUDIT-v1`。模型、alpha-EFX 删除自身 item 的量词和 costs ((R,1,q)/(R,q,1)) 已在[三值反例与 fPO 边界审查](三值家务EFX反例与公平fPO边界三源处置--审查.md)中写明；本页只新增删除偏序与参数网格的实际字段和实现。原件、SHA、脚本与验证见 [retired-fair-boundary-deletion-grid-20261031](../../tools/evidence/retired-fair-boundary-deletion-grid-20261031/)。

# 1. `deletion_subinstances.json`：固定反例的删除偏序极小性

source ID `b556c35d41be87e595fb`，大小 16321 bytes，SHA-256 `24463078d080d6cff1af43db5e38846e69df53d511e070b06d01fddce9666081`。JSON 有 142 行，每行给三类 multiplicities `[a,b,c]`、type allocation 数和 `efx_types`，对应固定 costs ((R,q)=(20,7)) 下从 `(3,5,5)` 坐标逐项删除得到的全部非空子实例，总件数不超过 12。

逐字段统计：142 行均有 `efx_types>0`，最小 EFX type allocation count 为 1，最大为 40；没有一个删除子实例保留“无 EFX”状态。因此，已知 `(3,5,5)`、(R=20,q=7) 反例在这个**坐标删除偏序**下是极小的：任意非空真删除子实例至少有一个 EFX type-count allocation。这里的“极小”不等于 item 数全局最小、成本值全局最小或所有非坐标删法都可行；不同类型重命名、代理删除和改变成本均未被该 JSON 覆盖。

JSON 不保存每个 witness 的具体 bundle，只保存计数，因此不能单凭它重建所有 EFX allocations。其独有价值是 142 个输入的完整计数覆盖与最小/最大数量；应与 exact_probe 的生成逻辑一起引用。

# 3. `exact_probe.py`：生成和判定的真实实现

source ID `6c2c6dde2322b5262652`，大小 5498 bytes，SHA-256 `b379a3680ddd46c1546acd734f800755307c1c0b23b04b9993e2e43f518b8d2e`。它是确定性整数探针，不使用随机搜索。

## 3.1 type-count EFX mask

`compositions(total,n=4)` 生成每类重数在四代理间的所有弱组合；`chore_counts(a,b,c)` 对三类组合做笛卡尔积并转成 `[allocation,agent,type]` 张量。`efx_mask(counts,middle,large)` 为每位 agent 计算成本向量 `[[large,1,middle]]*2+[[large,middle,1]]*2`，取 own bundle 的最小正成本并检查

$$
\text{own cost}-\text{smallest own item}
\le\min_j \text{cost}_i(X_j).
$$

这正是固定 additive chores 的 EFX 条件；同类型副本的标签不影响 costs，故 type-count quotient 对该输入是精确的。`run()` 断言 `(3,5,5)` 有
$$
\binom63\binom83^2=62720
$$
行且零 EFX。

## 3.2 删除、网格和额外着色检查

脚本构造：

- `fixed_13_grid`：middle 2..12、large middle+1..50 的 473 点，并写出 `trivalued_grid.json`；
- `deletion_minimal_probe`：(a\in0..3,b,c\in0..5)，排除总件数 0 或超过 12，得到 142 个非空坐标子实例，并写出 `deletion_subinstances.json`；
- `multipartite_coloring`：对总件数 1..30 的全部整数 partitions、agent n=1..12 构造近均衡 bundle，验证每 bundle 至多一种 part 且未着色顶点需与其它 part 共存；这是独立的结构 sanity check，不是 EFX 定理。

该脚本还固定记录 `arithmetic=int64 exact, entries at most 50 and 13 chores`；没有 Fraction、随机 seed 或浮点容差。`multipartite_lemma_check` 的循环可能比本页两个 JSON 大得多，且本批没有等待其长时间运行完成；源码逻辑本身已逐行读取，不能把未运行的额外检查写成已通过结果。
