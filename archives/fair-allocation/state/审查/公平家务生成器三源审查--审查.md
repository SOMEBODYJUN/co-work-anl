# 阅读范围与依赖边界

三份脚本是前批 fair_chores 结果 JSON 的生成/检查依赖，不是新数学命题。原脚本、SHA、大小、marker 验证见 [retired-fair-toy-generators-20261031](../../tools/evidence/retired-fair-toy-generators-20261031/)。`mixed_extension_toys.py` 还导入另一个未在本批 claim 的 `toy_search.py`；因此本页只确认调用边界和本文件可见的枚举量词，不冒称其底层 (EFX^+_0) checker 已独立复核。

# 1. `construct_rank2.py`：FC-LEMMA-R2-2C-v1 的真实构造

source ID `0cfcffcae334583ec32f`，大小 3982 bytes，SHA-256 `3e109ea30d7bb8c42e301807a29f48243145628b8b674a610516fbf0fa2a95fa`。

## 1.1 输入与匹配

`words` 是每件物品的 binary tuple，允许重复；脚本明确 no loops。`matching(words,w,n)` 建图：agent (i) 与 item (e) 相邻当且仅当 `words[e][i] != w[i]`，用递归增广的朴素最大匹配返回 left/right/adj。`missing_word(types,n)` 逐前缀计数，找第一个缺失 lexicographic binary word，并断言其不在 distinct type set。

`construct(words,n)` 的分支与局部引理正文一致：

- (n=1) 直接把全部物品给唯一 agent；
- (m<n) 给前 (m) 名 agent 各一件；
- 所有 (2^n) type 出现时，按互补 word pair 取 n 对（脚本按首位 0 的代表配 complement），剩余物品放入 agent 0；
- 有缺字时循环求匹配。若未覆盖所有 agents，从未匹配 agents 交替可达得到 (S,T)，断言 (|T|<|S|)，在 (S) 中挑一个单坐标翻转后仍缺失的 word，重新求匹配并断言匹配大小严格增长。

脚本没有实现 trie；`types` 是 set、`missing_word` 为逐前缀计数，因此这是证明可行性的原型而非复杂度优化实现。它选择第一个可翻转缺字，不探索所有选项；严格增长由断言检查。

## 1.2 EF/EFX 检查

得到 matching 后每个 agent 先拿匹配 item；对未匹配 item，脚本选择任一满足 `words[e][i] != w[i]` 的 agent。`check(words,X,n)` 先断言全部 item 恰好出现一次，然后定义 agent (i) 对 bundle 的成本为该 bundle 中第 (i) 位的 distinct binary labels 数。它对每个自身 item 逐一删除并检查 chores-EFX；当 (m\ge n) 还检查完整 EF。没有 PO、连续估值或一般 matroid 分支。

脚本主程序固定 seed 20261020，(n=2,ldots,8)，(m\in\{n-1,n,2n,4n,100\}) 每项 100 个随机 words，并在 (2^n\le256) 时另跑 full cube，生成 3507-case JSON。`max_matching_flip_rounds_observed` 是运行观察，不是常数轮定理；脚本通过也不替代引理中的 Hall/缺字证明。

# 2. `mixed_extension_toys.py`：图方向枚举的上层逻辑

source ID `c27580ad820c383f2587`，大小 1081 bytes，SHA-256 `d7e70c77f3c3fd5c6d2714a468d5e674b45ad7025e65bc2425561bb6da07719f`。

`test_graph(n,edges,vals,trials,seed)` 将每条边的两个 endpoint utility 从 `vals` 笛卡尔积取样，生成所有 (2^{|E|}) orientations。每个 profile 只要有一个方向使导入的 `mixed_efx(...,True)` 返回真，就视为通过；第一个没有任何方向通过的 profile 记录 `counterexample_to_universal_EFXplus0` 和 trial index 后停止。它生成的正是前批 e5cd 的 C6/双三角 cactus 两行。

`cycle_trials(3,(-1,0,1))` 与 `cycle_trials(4,(-1,0,1))` 被直接导入，底层 profile/方向穷举不在本文件；因此 JSON 的 exhaustive 标记应追溯 toy_search.py。此脚本自身没有证明 (EFX^+_0) 判定的正确性，也没有处理任意实数 utility、未完成 trial 或 cactus 全域量词。前批已记录双三角 trial686 的六对端点反例；本文件只说明它如何停止并保存该 witness。

# 3. `rank2_cap_toys.py`：真正截断 rank-cap-2 的 wrapper

source ID `4dbc6f9a7ed5080f9423`，大小 844 bytes，SHA-256 `7d429375b6998aeb0bbff5906eae77a86c0d1310ca2cc579afc74e77f2d61735`。脚本从 `rank_toys` 导入 `rank_tables`、`allocations`、`check`，对每个随机 label profile 计算

[
D_i(S)=\min\{\text{raw class-touch count},2\}.
]

这是 d096 结果与 ec907 class-touch 结果的关键区别。它跑三行：((n,m,k,mathrm{trials},seed,loops)=(3,9,3,1000,20261027,False))、((3,9,3,1000,20261028,True))、((4,8,3,250,20261029,True))。每行先用 `rank_toys.allocations` 显式建出 (n^m) assignments，再对每个 profile 做 `np.minimum(...,2)` 后调用 EFX checker；出现失败即记录 label matrix/trial，否则 completed 等于 requested。它没有声称一般 rank≤2，也不检查 EF/PO，只继承 `check` 的 EFX 量词。

## loops 与边界

`loops=True` 用 `rng.integers(-1,k,...)` 生成 -1 label，`rank_tables` 跳过负 label；这才是带 loops 的 rank-cap-2 toy。由于 classes 固定为 3、profiles 仍随机、allocation 才在 profile 内全枚举，空 counterexample 只能是有限正面证据。脚本 wrapper 也没有给 word/Hall 构造，不能把两类无 loops 的证明自动延伸到这里。

# 4. 处置与接续

三份 source 均处置为 `integrated-reproduction-method`：

- `construct_rank2.py` 保存局部引理的实际 matching/分配/EFX checker；
- `mixed_extension_toys.py` 保存有限 signed graph profile 的全 orientation loop 和 first-failure 语义，但其底层 checker 另待脚本来源；
- `rank2_cap_toys.py` 保存真正 `min(raw rank,2)` 的 wrapper，明确与 class-touch 三类行分离。

第三阶段可把各脚本作为 result JSON 的“实现”或“有限验证”前提；不能把断言、随机 seed 或 observed rounds 连成一般 EF/EFX/rank-cap-2/图定向定理。若要复现混合图结果，下一步必须单独读取 `toy_search.py` 并核对 `mixed_efx` 的删除语义。
