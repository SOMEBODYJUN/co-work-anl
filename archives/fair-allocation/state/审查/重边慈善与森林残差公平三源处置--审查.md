# 模型身份

三源属于端点 goods 图上的 additive EF/charity 研究，与 fair_chores 的 rank cost、goods-with-copies 的 SD-EF1、以及当前 CAG-SPE 均独立。每条图边可以给某端点或删除；端点对边有非负整数收益，公平检查是每个 agent 对自己的收入至少不小于对任何其他 bundle 的可见收入。第二个 probe 还固定重边支持和 heavy visible offsets，目标是判断完整 EF orientation 是否存在。

原件、SHA、字段验证和脚本副本见 [retired-heavy-edge-fairness-20261031](../../tools/evidence/retired-heavy-edge-fairness-20261031/)。

# 1. `charity_probe.py`：simple graph 的 3^k 慈善搜索与 flow 扩展

source ID `00630b75b9bf652479bd`，大小 4041 bytes，SHA-256 `db44e5985190561332fc19ef13dfd910102747cf2cea51458f3747f0be872bae`。

## 1.1 EF 与 brute force

`ef(n,edges,dec)` 对每条 edge decision (d\in\{0,1,2\})：0 表示捐出/删除，1 给第一端点，2 给第二端点；累计 owner revenue `rev` 和每个 observer 对 recipient bundle 的 visible value。要求
$$
\mathrm{rev}_i\ge \mathrm{visible}_{ij}\quad(i\ne j).
$$

`brute` 穷举所有 (3^{|E|}) decisions，最小化删除数并保存 EF witness。该目标是简单图端点 orientation + deletion 的最小 charity，不是一般 mixed EFX^+_0，也不允许平行边或超边。

## 1.2 `algorithm` 的受限构造

算法先把边分三类：heavy（两端都正且至少一端值≥2）、light（恰为 (1,1)）和带零端的 forced edges。它枚举所有 heavy 方向/删除模式 (3^k)，把 forced/heavy 贡献压成每个 agent 的 own `s_i` 与最大可见 `q_i`。对 light 支持的每个连通分量：若无 anchor 且是 tree，则删除整棵 component；否则保留 light edges。

随后构造 lower bound (b_i)，用 source-agent 到 edge-node 再到 sink 的 unit-capacity flow 选择保留 light edges 的端点入流；若 flow 达到 (sum b_i)，把每条 light edge 定向，重新调用 `ef` 断言。算法在枚举 heavy decisions 后取最少删除数。

这是一个明确受限的 simple-graph 结构：heavy 参数被枚举、light 支持被 flow 处理、无 anchor tree component 被捐出。脚本没有证明 arbitrary multigraph、平行 heavy edges 或 mixed EFX 的普遍算法；`assert ef` 只验证每个枚举实例的输出。

## 1.3 有限运行

主程序 seed `37042027`，(n=1..6)，每个 n 200 个随机 simple graph，最多 8 条边；edge endpoint values 取 ((0,0),(0,1),(1,0),(1,1),(1,2),(2,1),(2,2),(2,3))。共 1200 cases，每例 `algorithm` 与 brute (3^m) 比较最优 charity，结果 `mismatches=0`。这些是有限 exact integer cases，不能替代对 simple graph 全域的证明，也不能迁移到 multigraph。

# 3. `probe.py`：固定 heavy residual 与森林动态规划

source ID `91237b3de32668948978`，大小 3846 bytes，SHA-256 `42e30ce279197f7ef176f7eefd2a7b6f5986200d921949eab34271a13c857981`。

## 3.1 输入与 brute

`verify(n,m,s,h,x)` 的 unit support 是重数 `m[(i,j)]`，`s_i` 是固定 own revenue，`h[(i,j)]` 是 i 对 j 的 fixed visible heavy value；余边方向变量 `x[(i,j)]` 满足每对总量为 m。EF 条件是
$$
s_i+\sum_jx_{ij}\ge h_{ij}+x_{ji}\quad(i\ne j).
$$

`brute` 对每条 pair 的 (0..m_{ij}) 全枚举，返回第一个 EF orientation；这是小规模 feasibility oracle，不是优化器。

## 3.2 `forest` threshold DP

脚本要求 unit support 是 forest（若发现 cycle 则 `ValueError`）。从叶到根计算 child upper (U_{ic}=m_{ic}-L_c)，汇总可安全转移的 (S_i)，再由 non-neighbor heavy thresholds 和 parent edge 的二元约束得到 child lower `threshold[i]`。若根的父输入为零时仍需正量，则拒绝；否则向下恢复每条 edge 的 orientation 并断言 `verify`。

它实现的是固定 heavy offsets + unit forest 的 exact EF feasibility DP。没有覆盖 cycle、平行 heavy 支持、删除 charity、signed values 或一般 graph。

## 3.3 固定边界与随机一致性

主程序固定五点路径 (1-2-3-4)，三条 unit multiplicity 各 100，`s=[87,0,0,0,0]`，heavy visible (h_{1,0}=87)。给出一组 EF orientation，内部 balanced split 使中间点对前驱的约束为 `u-w <= 75`，同时记录 `forest_solution`。随后 seed `37042026`，n=1..7、每 n 600 个随机 forests，multiplicity 1..4、s/h offsets 0..7，共 4200 tests；`brute` 与 `forest` 可行性 mismatch=0。

这组数据支持森林 residual contract 的有限实现一致性，但没有给 arbitrary graph 的 EF 定理；固定路径的 87/100 数字是边界解释，不是新 asymptotic lower bound。
