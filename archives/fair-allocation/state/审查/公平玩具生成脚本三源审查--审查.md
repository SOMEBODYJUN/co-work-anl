# 读取范围与依赖关系

三份脚本是此前 fair_goods/fair_chores 结果摘要的生成与检查依赖，不是新的数学命题。原件、SHA、大小、marker 校验和复现目录在 [retired-fair-toy-scripts-20261031](../../tools/evidence/retired-fair-toy-scripts-20261031/)。本页完整读实现，目的在于确认结果 JSON 的真实模型、枚举量词和边界；脚本通过不等于其实现对所有输入正确，也不等于外部审稿。

# 1. `toy_checks.py`：K8/K12 与 copies 的实际 checker

source ID `b11a9d5a64d329c10c8a`，大小 4225 bytes，SHA-256 `0dd9b02ab90c72c308186f73ff94f315d2b6953ea3e1340b20a86fbab7b4cb22`。

## 1.1 key allocations 和 ordered EF1

`key_allocations(sizes,n=4)` 对每个 category 取一组 `permutations(range(n),s)`，拼成 0/1 ownership assignment；只保留每个 agent 恰有 `rank=m//n` 件的行。返回所有 labelled allocations 与布尔 incidence 张量 `X[allocation,agent,item]`。因此 K8 的 864、K12 的 31104 是脚本直接生成的完整可行分配数，而不是从摘要推测出来的。

`ordered_ef1_witness(V,owners,X)` 先算
[
U[a,i,j]=\sum_g V_{ig}X_{a,j,g},
]
其中 (i) 是观察者、(j) 是 bundle owner；`own=U[a,i,i]`。对每个 (i,j)，令 `maxgood` 为 (j) 包中观察者 (i) 的最大 item value，并检查
[
U_i(X_i)\ge U_i(X_j)-\max_{g\in X_j}V_{ig}.
]
此外只在 `i<j` 时加 ordered no-envy 约束 `own>=U[a,i,j]`。所以结果字段 `ordered_no_envy_and_EF1_failures=0` 的真实量词是这个方向性的 (i<j) 约束加 EF1，不是所有 pair 都要求 no-envy；普通 EF1 与 ordered 加强版必须分开。

`key_search()` 固定 seed 20261020，每个 K8/K12 profile 按 `t mod 3` 在 uniform 0..10、binary、powers-of-two 三种整数分布中循环，保存 witness 数、最坏矩阵和 K8 的 Lemma12 top-separation count。随机 profile 完成而非 valuation 域穷举；无浮点。

## 1.2 copies allocation 和 SD-EF1

`copies_allocations(c,n)` 对类型 (g) 的 (c_g) 副本枚举所有 `combinations(range(n),q)`，每列正好给 (q=c_g) 个不同 agent，因而强制每人每型至多一件和完整分配。`sd_witnesses(rankings,X)` 对每个观察者排序 `order` 取前缀累计计数，逐 (i,j) 检查
[
\operatorname{prefixCount}_i(X_i)\ge\operatorname{prefixCount}_i(X_j)-1.
]
这正是 copies SD-EF1 的序数前缀判定，不是数值 EF1 或近似 MNW。整数累计、无浮点；`toy_results.json` 中 n=3/4 的 allocation counts 和 witness 矩阵由此生成。

# 2. `copies_exhaustive.py`：9216 profiles 的严格穷举

source ID `58cb6c9207d66baec4b6`，大小 1562 bytes，SHA-256 `f9bfecf8ad21c76b61db78709e5343b909bc304a07507ba456a32cdfac9c173d`。脚本固定 `orders=list(permutations(range(4)))`，把 agent 0 的 order 固定为首个 `[0,1,2,3]`，只枚举 agents 1、2 的 (24^2) 排序；四个类型的重数遍历 (2^4=16) 个 `[1,2]` 向量，得到 9216 个 profile，正是同时类型重命名的归一化域。

它调用 `copies_allocations(copies,3)` 得到每 profile 的全部 allocation；预先为每个 agent/order 构造满足所有 prefix inequalities 的 bitset，再用三个 bitset 交集计算 witness count。若某个 profile 无 witness，脚本立即 `raise AssertionError(worst)`；正常完成才写 `all_instances_have_sd_ef1=true`、最小 witness count 和 worst profile。这里的“穷举”覆盖的是声明的有限 strict-order/type-multiplicity 域；ties、更多类型、更多 agent 和统一副本 (c_g=3) 的推广仍是模型论证，不是脚本结果。

# 3. `rank_toys.py`：class-touch 成本与 loops 编码

source ID `8133b8a1671be745ebc7`，大小 1764 bytes，SHA-256 `878e8f5fccf285c7fd86421250229e6045a5c9813555da55dde0b200f4fa5c6e`。`rank_tables(labels,k)` 对每个 agent 和 item subset 计算其触达的**非负 label distinct count**；label `-1`（只在 `loops=True` 时生成）被跳过。`allocations(n,m)` 显式构造所有 (n^m) item-to-agent assignments 和 bundle masks。

`check(D,masks,m)` 对每个 agent 的 own bundle，逐件删除每件自身物品并取余成本的最大值 `residual`，要求 `residual <= D[i,masks[j]]` 对所有比较者 (j)，再检查至少存在一个 allocation。它实现的是所有自身物品删除的 chores-EFX checker；它不检查 PO，也不输出一般构造。

`trial` 使用 `rng.integers(-1 if loops else 0,k,size=(n,m))` 生成 labels，遇到第一个失败就停止并记录 trial；否则 `completed_trials=requested_trials`。因此结果摘要中的五行是随机 label profile + 每 profile 完整 (n^m) 分配枚举。对 `number_of_classes=3` 的 rows，成本是触达类数，未取 `min(2,·)`；它们不能被称为真正 rank-cap-2，也不能替换 `rank2_cap_results.json`。

# 4. 方法边界和处置

三份脚本都使用整数/Numpy 数组和显式枚举；没有概率置信区间、连续估值证明、外部复核或独立实现。`toy_checks.py` 的 ordered no-envy 是 `i<j` 单向加强条件；`copies_exhaustive.py` 固定 agent0 顺序以消除类型重命名；`rank_toys.py` 的 loops 与 class-touch 语义必须按代码保留。脚本与相应 result JSON 一起作为复现依赖整合，但“脚本断言通过”不改变既有正文中的有限证据等级。

处置：三个 source 均为 `integrated-reproduction-method`。第三阶段可以从结果对象连到本页的“实现/有限验证”边；不能把脚本本身连成普遍 EF1、SD-EF1 或 rank-cap-2 定理。若后续要声称复现，需在新目录运行并记录 Python/Numpy 版本、seed 和完整 stdout，而不是只引用冻结 JSON。
