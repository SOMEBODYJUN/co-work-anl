## 2.2 具体边界和精确逻辑

确定性的 partial-slot fixture 有 sink masses (4/3,2/3)，actual first-prefix cost (3/10)，virtual-prefix budget (1/2)。显式 blocked-conservation fixture 给出 (x=1)、(sum allowed\ y=0)、demand (1/2)，因此 LP 以 (0=1) 不可行。这是一个输入证书的阻断机制，不是一般 LP infeasibility theorem。

zero-target logic 是：每个 task 都有 zero edge 当且仅当 OPT=0，empty conjunction 为真；这与 zero-target、empty-assignment、zero-profile 三个直接边界一致（各 1、1、16 个 assignments）。正文保留该逻辑，避免把“零边存在”错误解释成任意零目标调度。

normative replay 的 16 个 assignments 全部标记 `same_assignment_as_independent=true`；其中有 home loads ((1/12,1/4))、((61/60,49/60))、((11/20,5/4,5/12))、((3/2,3/2)) 等，sink loads 亦逐项保留。reviewer software 另外接受 5 个合法边界：ordinary positive demand、zero-(ar B) endpoint、(T=0) empty macros、empty task set、zero-demand bypass；拒绝 10 类非法证书，包括 bad upper/lower envelope、positive demand bypass、broken common flow、floating target、boolean sink count、negative token mass、receiver budget exceeded。

## 2.3 失败机制和量词边界

该实现只做 exact supplied-LP witness validation 与 rounding；没有 rational LP backend、pseudo-witness 全枚举或 unknown-OPT search。故“1,192,421 个 assignments”只说明列出的有限源域已经运行；不能从中推出任意 LP 都可生成 witness，也不能推出 rounding 算法对任意未知 OPT 输入成立。后续若要形成一般定理，必须补上 LP 生成、source witness 的存在性和 assignment 解码的同一量词。

# 3. 五任务配置：ST 槽位阶乘界的精确反例

## 3.1 输入与配置 LP 证书

`f7f9531d3c8cf2e60629` 的命令为 `python3 tests/audits/unrelated_machines/k5_configuration_slots_audit.py`，精确 Fraction、无浮点和 solver。它取 (K=5)、15 jobs、16 machines、(b=1)、(T_{CONFIG}=1)。五种大小为

五个 (H) primary count patterns 的权重为

[

其总权重和为 1，且 `primary_fractional_load=1`。`primary_home_qualification_sum=41/12`，五个 strict prefix margins 都是 (1/144)。因此配置层的 (T_{CONFIG}=1) 是该明确实例的 exact certificate。

## 3.2 ST-slot envelope 与实际 matching

五个 primary slot maxima 为 (1,1/3,1/4,2/9,3/16)，其 envelope 为

[
287/144.
]

冻结稿把普遍阶乘式上界的候选写成 (239/120)，两者相差

[
287/144-239/120=1/720>0.
]

因此该输入精确反驳“对 (K=5) 的所有 ST slots 和所有 complete matchings 都有 (2-1/5!=239/120)”这一普遍说法。实际存在一个坏的完整 ST matching：heavy machine (H) 收到五类各一项的跨槽任务，负载为 (287/144)；同时存在一个好 matching，把所有 15 jobs 放到各自 P-machine singleton，负载为 1。故真实 OPT=1，且 `OPT_lower_bound` 是 (j0_0) 在每个 finite endpoint 的处理时间都为 1。

这一区分很关键：来源的 scope 明确说它 refutes universal ST-envelope/all-matchings bound at (K=5)，但不 refute choosing or repairing a matching。坏 matching 的存在不等于任何选择算法都会选它；好 matching 的存在也不说明一个普遍修复器已实现。

## 3.3 与已有配置/Hall审计的关系

这项反例与《Hall联合流与前缀匹配增量审计》中的全局 parity 3DM NO 证书属于同一“局部分数/槽位约束可能不能直接整数化”的方法线，但输入合同不同：Hall 审计的实际全局实例为 10 machines/14 jobs、Fractional load 1 而 OPT=3/2；本源是 16 machines/15 jobs、配置 (T=1) 而一个坏 ST matching 达到 (287/144)。两者不能合成一个统一整性缺口，更不能把坏 matching 的 envelope 当真实 OPT。

与《配置剥离与联合匹配有限审计》的 k=3/4 bundle-subdivision 边界相邻：那里记录目标膨胀 (5/4\to7/4) 等有限族，本源新增 (K=5) 的 exact (1/720) 超额和“good matching 仍为 1”这一选择/修复边界。
