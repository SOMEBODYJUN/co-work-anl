# 未知机器倍率公共尺寸的共同容量阈值搜索

## 身份

`UM-COMMON-MULTIPLIER-UNKNOWN-B-EXACT-v1`。这是 `UM-COMMON-SIZE-UNKNOWN-B-EXACT-v1` 的严格受限扩展草稿，不声称解决一般 `UM-TARGET-v1`。

## 精确命题

给定冻结核心分配 `sigma_0`，其机器负载为非负有理数 `f_i`，以及残余任务集 `U`。令残余资格图 `G=(M,U,E)` 的每个连通分量 `C` 满足：存在一个正有理公共尺寸 `q_C`，和每台机器一个正有理倍率 `a_i`，使得对 `C` 内每条有限边

```
p_ij = a_i q_C.          (1)
```

不同分量的机器侧不相交（这是连通分量的定义）；零处理时间任务先任取一个有限零端并从 `U` 中删除。若残余任务非空且每件至少有有限端，则可在输入总二进制长度的多项式时间内精确求出

```
B* = min_tau max_i ( f_i + sum_{j:tau(j)=i} p_ij )
```

并输出达到 `B*` 的整任务分配 `tau`。若某个分量的所有正边不满足 (1)，接口检测失败并不声称有算法。机器不参与任何残余任务时仍贡献其冻结负载 `f_i`。

## 目标值候选与判定

在分量 `C` 中，若机器 `i` 接收 `t_i` 件任务，其最终负载恰为 `f_i+a_iq_C t_i`。因此该分量的最优峰值必属于有限表

```
S_C = { f_i + a_i q_C t : i in M_C, t=0,...,|U_C| } .       (2)
```

对候选有理 `B`，先做冻结核心下界检查：若 `B < max_{i in M_C} f_i`，则拒绝。此后定义整数槽容量

```
c_i(B) = max(0, floor((B-f_i)/(a_i q_C))).                 (3)
```

建网络 `s -> j` 容量 1、`j -> i` 容量 1（当 `(i,j) in E`）、`i -> t` 容量 `c_i(B)`。最大流值为 `|U_C|` 当且仅当存在 `tau` 使每台机器最终负载不超过 `B`：必要性由 (3) 取整，充分性由网络整数性。按 (2) 去重排序并二分首个满流候选，得到分量最优值 `B_C*` 和实际分配。

全局结果为

```
B* = max( max_{i isolated} f_i, max_C B_C* ).             (4)
```

每个分量独立求流再合并，因其机器侧不交，任何全局调度的峰值是分量峰值与孤立冻结机器峰值的最大值。`U=empty` 时直接返回 `max_i f_i`；全零残余任务可在最后任取资格端，不改变负载。

## 正确性证明

固定分量 `C`。任意整分配给机器 `i` 的任务数是某个整数 `t_i`，故其峰值 `max_i(f_i+a_iq_Ct_i)` 取值于 (2)，所以在候选表上搜索不会跳过最优值。对任意 `B`，若真实分配满足峰值 `<=B`，则每台机器任务数 `t_i<=c_i(B)`，给网络一个值 `|U_C|` 的整数流。反向，满流给每个任务唯一机器，容量 (3) 保证

```
f_i + a_i q_C t_i <= f_i + a_i q_C floor((B-f_i)/(a_i q_C)) <= B.
```

故候选首个满流值恰为 `B_C*`。最大候选 `max_i(f_i+a_iq_C|U_C|)` 一定满流：每台机器容量至少 `|U_C|`，任一任务至少有一条资格边；二分上端存在。候选表大小至多 `|M_C|(|U_C|+1)`，网络显式规模多项式。

所有候选值和槽容量由有理加法、乘法和精确整除得到。处理时间输入的分子/分母位长总和为 `L` 时，`a_i` 可由一条参考边用交叉乘法取出，候选分子/分母位长 `O(L+log |U|)`（更保守地不约分时为 `O(L)` 的多项式）；排序、最大流、回溯输出均为总位多项式。零任务预处理不改变剩余最优值。

## 结构检查

在每个资格连通分量内，取一个正边 `(i_0,j_0)` 定义 `q_C` 为其处理时间。对同一机器的所有边，精确检查 `p_ij / q_C` 是否与任务无关；若不相等则该机器倍率条件失败。再检查每台机器与任务的图连通分量是否包含多种公共尺寸；若同一分量存在两种 `q`，(1) 不成立并拒绝该接口。可以把 `a_i` 记为任一边的比值；所有比较使用有理交叉乘法，不使用浮点。

这比“每个分量所有边同一个 `q`”允许异端机器速度，只要速度差是机器固定倍率。它仍不允许同一分量内两个独立任务尺寸共享机器；那一旦出现，容量变成不可分割多尺寸装箱，普通流的整性消失。

## 边界和反例

1. **冻结核心 guard 必须存在。** `f=(2,0)`, 一件残余任务仅可在机器 2 上且 `q=1`, 候选 `B=1` 时 (3) 给满流，但完整峰值至少为 2；先检查 `B<max_i f_i` 可排除该伪通过。
2. **分量分离是必要的。** 若两个公共尺寸在同一机器上共享，(3) 只按一个尺寸计槽而会错报。例如一台机器 `a_i=1` 同时接一件尺寸 1 和一件尺寸 2，`B=2`；按任一单尺寸容量都不能表达两件的不可拆分总量。
3. **去掉机器倍率条件不安全。** 以每任务最小边当尺寸会把异端矩阵 `[[2,100,2],[100,2,2]]` 错当成三件尺寸 2；`B=3` 的分数共同流通过但任何整调度峰值为 4。
4. 这只是共同尺寸/倍率结构的精确阈值生成，不能从任意 `P` 自动提取该分解，也不能给出一般 `FAIL=>OPT>T`。分量结构失败时只报告“接口不适用”，不是对原 UM 实例的 sound FAIL。

## 关系到未知目标义务

该命题关闭了 `JC-THRESHOLD-ε(T)` 中一个以前未分离的目标生成子义务：在该结构里，`T`（或最终 `B*`）未知不需要数值二分、估值 oracle 或预给共同目标；候选阈值是由实际机器负载轨道 (2) 产生，整性由一次整数流保证，输出是完整实际分配。它没有处理一般矩阵中“如何选共同容量/核心/任务身份”，也没有统一 `2−ε`，所以仅作为可复用受限 branch。

## 已知 objection

- 若同一支持分量包含两个任务尺寸但仍有机器倍率，容量问题是广义指派/不可分割装箱；普通最大流不再给出整性，不能把本算法延伸到该域。
- 若分量结构是输入承诺而非可验证条件，算法应先验证所有有限边；验证通过才可声明本接口成功。
- 分量数、候选表和最大流均按显式 `m,n` 计数；不按处理时间数值展开。`q_C=0` 任务必须先删，不可在 (3) 中除零。
- 该结构族包含普通同机/等尺寸例，外部新颖性未认证；只记录数学正确性和未知-B处理，不改变 `UM-TARGET-v1` OPEN 状态。
