# LST 正支撑锁定的精确近二容量障碍

本页修正并加强 `UM-LST-SUPPORT-RELEASE-v0` 的原始族。旧族的“`OPT=T=1`”数值声称不成立：其小任务可以放到扩展机，实际最优值严格小于 1。本页给出一个新的、逐块可核验的族，确实满足 `OPT=T=1`，并把需要释放的零质量支撑边数与最坏负载精确分开。

## 精确命题：`UM-LST-SUPPORT-RELEASE-OPTIMAL-v1`

对任意整数 `m≥2`、`r≥1`，构造 `r` 个互不相交的块。块 `b` 有核心机器 `c_{b,1},…,c_{b,m}` 和备用机器 `s_b`。它有私有任务 `a_{b,1},…,a_{b,m}` 及一个锚任务 `g_b`，处理时间为

- `a_{b,i}` 在 `c_{b,i}` 和 `s_b` 上均为 `q=1−1/m`，在本块其他机器上不可用；
- `g_b` 在每个核心机器和备用机 `s_b` 上均为 `1`，其他块不可用。

不同块之间所有边均不可用。给定阈值 `T=1`，定义分数分配 `x`：每个 `a_{b,i}` 全部放在 `c_{b,i}`；每个 `g_b` 在该块的 `m` 个核心机器上均匀分配 `1/m`；备用机器分数为零。每个核心机器的分数负载恰为

`q+1/m = 1`,

故 `x` 是 `T=1` 的可行分数解。其正支撑只含私有任务的核心边和锚任务的核心边；私有任务的备用边是零质量边。

### 最优值

每个锚任务 `g_b` 的每条可用边处理时间都是 `1`，所以任何合法调度的最大负载至少为 `1`。将每个私有任务 `a_{b,i}` 放到对应核心机器、将 `g_b` 放到备用机 `s_b`，每块最大负载为 `1`；故 `OPT=1`。这也给出了每块只激活一条零质量备用边即可达到最优的具体修复。

### 精确支撑释放前沿

若一个块没有激活任何零质量备用边，则所有私有任务仍固定在各自核心，锚任务必须选一个核心，故该块最大负载为 `q+1=2−1/m`。若一个块至少激活一条私有备用边，则把该私有任务移到备用机、把锚任务放到其核心，块最大负载为 `1`；这是该块的下界。因此若全局至多激活 `k` 条零质量边，块之间独立，

`C^*(k)= { 2−1/m, 0≤k<r; 1, k≥r }`.

这里 `C^*(k)` 是在该限制下的最小可能最大负载。特别地，任意固定的支撑释放预算 `k<r` 都保留比例 `2−1/m`；令 `m→∞` 可使该比例趋近 `2`。这是相对于真实 `OPT=1` 的近二障碍，而不是只相对于错误的分数阈值比较。

## 证明和边界

块间没有任务或机器交叠，所以全局最大负载是各块最大负载的最大值。每个未释放块含一个锚任务，其锚边必选核心且对应私有任务仍在同一核心，给出 `q+1`。每个释放块使用一条备用边即可达到 `1`，而锚任务下界排除小于 `1`。因此上式同时给出下界和构造。

命题只排除“先固定一份给定 LST 正支撑、再只激活少于所有块数的零质量边”的合同。它不证明 `R∥C_max` 没有统一低于 `2` 算法，也不排除联合重选分数解、从头构造支撑、激活随实例规模增长的边，或允许真实任务迁移的其他机制。其可回收义务是：任何支撑释放路线若要给统一 `2−ε`，必须给出不随块数线性增长的共同支撑选择或不依赖该固定支撑的联合舍入。

`m=1` 时 `q=0`，比例退化为 `1`，故命题从 `m≥2` 开始。所有时间均为常数有理数，空任务和 `T=0` 不属于本族的承重情况。

## 核验范围

`tests/audits/unrelated_machines/lst_support_release_optimal.py` 使用 `Fraction` 构造分数解，并独立枚举单块调度，核验 `m=2,…,5`、`r=1,…,3` 及所有 `k` 的前沿；冻结输出在 `evidence/runs/unrelated_machines/lst_support_release_optimal_audit.json`。这是有限精确证据，不能替代上述参数化证明。
