# 重型匹配凸化与逃逸残余审计

## 1. 模型与证据层级

本批三份 JSON 都围绕 heavy/light matching 和 configuration filter：主程序在 Fraction 上比较 primal/dual 与共同重型面；独立程序直接穷举有限矩阵和可行 schedule；残余程序把 threshold multiplicity、path-only filter 与压缩参数族分开。三者都保留“实际调度、配置可行性、分数/联合松弛”三个对象的区别。

源中没有 generic LP solver、没有从任意输入生成可行 schedule 的近似算法，也没有把 filter 造成的 NO 误判写成 coupled hierarchy 结论。原始字节、哈希、冻结来源和大小在 [source-manifest.json](../../tools/evidence/heavy-matching-20261030/source-manifest.json)。

## 2. 主 primal/dual 和共同重型面

`15369...` 的算术是精确 Fraction，无随机 seed。13 个 primal/dual fixtures 都逐项保留；例如 two-machine 参数 (1/2,3/5,4/5,99/100) 等的 primal 与 dual 均为1，实际两机负载记录为 (9/8,7/8)、(11/10,9/10)、(21/20,19/20)、(401/400,399/400)。这些是 primal=dual 的具体价格闭合，不是所有输入的强对偶证明。

`dual_common_heavy_faces=5`。expanded tree 的两组为：

| k | T | common | original optimum | admissible states |
|---:|---:|---:|---:|---:|
| 2 | 3/2 | 3/2 | 3/2 | 18 |
| 3 | 4/3 | 5/3 | 5/3 | 32 |

这两行直接显示一个边界：k=2 的共同重型面达到目标，而 k=3 的 common 只为4/3、原始 optimum 为5/3。未剪枝固定 m 的 fractional/joint loads 为 m=1:1/1、m=2:1/2、m=3:1/3、m=7:1/7。源明确写 larger-k checks are algebra only，vertex/state enumeration exponential；因此不能把这些表格写成任意 k 的 LP 算法。

## 3. 独立 weighted matching escape

`f9d...` 使用 Fraction，independent 与 production 的 SHA 都保存，`exhaustive_weighted_matching_cases=28672`。edge-preservation 层检查 13,824 matrices、16,000 feasible schedules、threshold=1、7 boundary cases 和6 rejected invalid cases。

expanded family 的三行是：k=2,height=1，7 machines/7 jobs，10 个 optional matching witnesses，configuration target 3/2，exhaustive optimum 1；k=3,height=1，9 machines/11 jobs，16 witnesses，target4/3，optimum1；k=4,height=3，171 machines/265 jobs，362 witnesses，target5/4。compressed DP 只针对该 symmetric family，source 明确不是 general OPT oracle：

| k | height | optimum | configuration target | ratio |
|---:|---:|---:|---:|---:|
| 4 | 3 | 7/4 | 5/4 | 7/5 |
| 5 | 5 | 9/5 | 6/5 | 3/2 |
| 8 | 11 | 15/8 | 9/8 | 5/3 |
| 16 | 33 | 31/16 | 17/16 | 31/17 |
| 32 | 88 | 63/32 | 33/32 | 21/11 |
| 64 | 221 | 127/64 | 65/64 | 127/65 |

这里的意义是：在显式对称族里，配置 target 与真实 optimum 的比率随 k 增长，给出一个“重型匹配过滤不能保留真实 optimum”的参数化障碍。它不说明任何算法必须达到该比率，也不说明一般配置问题 NP-hard；compressed scope 明确限制为此 family。

## 4. residual audit 与 k=4 expanded filter

`b13...` 用 seed=20261016，Fraction/integer，无浮点和通用 LP。主矩阵计数为3375，threshold tests=16875，保留的 feasible schedules with threshold multiplicity=36224，另有120 random rational cases、5 boundary、7 invalid。

`expanded_k4` 给出一个重要的对象身份：`original_rejected=True`、`path_only_local_survives=True`、`path_only_global_rejected=True`，escape machines=171、escape jobs=265、deleted edges=0，escape configuration checked=True。也就是说，局部 path-only 检查可能通过，但在全局原始资格上被拒；这正是把 local filter 当 global configuration 证书时会发生的逃逸机制。

`compressed_parameters` 有61行，前几项为 k=4,h=3: optimum7/4、target5/4、ratio7/5；k=5,h=5: 9/5、6/5、3/2；k=6,h=7: 11/6、7/6、11/7；k=7,h=9:13/7、8/7、13/8，并延伸到 k=64 的 127/64 对 65/64，ratio 127/65。源把 k=4 expanded 与 k=4..64 formula checks 分开：只有 k=4 物化 expanded schedule；更大的 k 只是压缩公式检查。

因此 residual 输出同时给出两种用途：一是实际 filter 的局部/全局反例边界，二是压缩族的参数化 ratio lower bound。它明确声明没有 universal approximation algorithm、没有 feasible-schedule output，optimizer oracle cross-check 与 independent family reconstruction 也分开。不能把61行公式代替全部 schedule enumeration。

## 5. 与全仓配置和匹配对象的关系

* 与 [配置剥离与联合匹配有限审计](配置剥离与联合匹配有限审计--审查.md) 的关系是同一量词纪律：本批新添 heavy matching 的共同面、threshold multiplicity 与 path-only/global rejection；既有 bundle peeling、subdivision、joint matching 的有限证书不被重算为本批定理。
* 与 [Hall 联合流与前缀匹配增量审计](Hall联合流与前缀匹配增量审计--审查.md) 的连接是“分数/局部资格和整数全局调度可能分开”。本批的 path-only local survive/global reject 与 Hall 的 parity/3DM 边界是不同输入合同，不能互换。
* 与 [两层标签费用逃逸与真实最优值增量审计](两层标签费用逃逸与真实最优值增量审计--审查.md) 的关系是共同的逃逸主题：本批通过 heavy matching/configuration filter 造成 ratio，two-level 批则通过两标签收费得到3/2边界；两者都不能推广为一般 UM 近似下界。

若后续要形成定理，必须补上从压缩族到实际机器 schedule 的统一构造、所有 k 的 source/assignment 解码、global filter 的 soundness，以及与真实 OPT 的同一量词。当前三源已经足够记录一个可复跑的 finite obstruction 和参数族，但没有关闭一般调度问题。

## 6. 逐源处置

`15369...` 保留13个 primal/dual fixtures、5个共同重型面、expanded k=2/3 和未剪枝 m 对照；`f9d...` 保留28672 weighted cases、edge-preservation 全量、expanded 小 k 与 compressed 对称族；`b13...` 保留3375矩阵、threshold multiplicity、k=4 path-only/global filter 反例以及61行压缩参数。三源均已全文读取、与配置/匹配/Hall/菜单对象比较并保全原字节，所有有限范围和未完成的普遍化义务均已写入正文。
