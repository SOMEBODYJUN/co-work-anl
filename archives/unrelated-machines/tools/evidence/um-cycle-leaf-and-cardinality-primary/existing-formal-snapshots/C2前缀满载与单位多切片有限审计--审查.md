# 1. 研究对象与实读范围

本批完整实读三份冻结 JSON，并将原始字节保存在 `tools/evidence/c2-prefix-load-20261030/`，manifest 记录来源 ID、原路径、字节数与 SHA-256：

* `c2_prefix_full_load_independent_audit.json`（2,296 字节）；
* `c2_prefix_full_load_repair_audit.json`（507 字节）；
* `c2_unit_multislice_gap_audit.json`（5,008 字节）。

逐字段读取了所有顶层对象、嵌套数组、每个 (m) 的 moment/PSD 记录、独立运行的 pivot signs、边界和 limits。全仓比较了既有的《配置剥离与联合匹配有限审计》以及其中 C2 prefix parity 段落；本批是同一对象的更细满载/修复/多切片增量，不把旧 `e0dc...` 的五位 parity 计数误写成一般定理。

# 2. C2 prefix 满载独立审计

独立源固定三台机器 (A,B,C)、七件 job、阈值 (T=2)。两个支持源大小均为 16；实际合法 endpoint literal 为 13；枚举所有 endpoint-subset 的 degree (le4) 情形共 1,093 个，其中 compatible 706、incompatible-zero 387。实际合法调度枚举 64 份，全部满足 `true_OPT=2`，且 `all_sources_are_true_OPT_schedules=true`。

四阶数据核验包括：

* 所有 degree (le4) 的 one-hot moments 相等；
* 2,142 项 one-hot conservation checks 全通过；
* (M_2) 矩阵维数 86、exact PSD rank 16；三个 machine load localizer 的维数均 14，rank 为 6、6、0；
* 16 个支持长度的 prefix probability 为 (1/16)。按 parity 分为两类时，conditional full-load 向量分别为 ((1,0,2)) 与 ((0,1,2))，第五阶 (B_5) moment 分别为 0 与 (1/16)。

因此该独立审计精确展示了一个信息边界：相同的 degree-(le4) moment 数据不能唯一确定指定 source 的 conditional full-(B) load。它没有构造任意算法的不可行性，也没有限制算法选择另一个 coupling；源文件的 scope 只声称 `same fourth-order data fail to identify the specified source conditional full B load`。

# 3. C2 prefix repair 审计

repair 源用同一两个 16-support 源与 13 个合法 endpoint，对 degree (le4) 的 1,093 个 endpoint subsets 做精确 Fraction 重放。它报告 prefix probability (1/16)、`true_OPT=2`，并把修复后的 conditional full-(B) loads 记为 ([0,1])，旧 witness 的两类 full-(B) loads 为 ([3/2,3/2])。

这个比较的数学含义是：修复改变了指定 source/conditional event 的接口数值，使其落在 0 或 1 的合法端点范围；它不是对所有 prefix encodings 的唯一修复，也没有说明通过增加配置、改变 coupling 或使用其他 source 就能或不能达到某个全局近似比。`scope="source-specific information boundary; no algorithmic impossibility"` 必须原样保留。修复源的 code SHA 与独立源不同，故两份报告互补而非重复提交。

# 4. 单位多切片 gap 审计

`c2_unit_multislice_gap_audit.json` 的主声明为 `UM-C2-LOAD-UNIT-GAP-v1`，算术使用 Fraction / exact integer Bareiss，无数值容差。它同时引用主脚本 `c2_unit_multislice_gap.py --full-m 3 4 5` 与独立脚本 `c2_unit_multislice_independent.py`，并保留四个输入/脚本 SHA 与 base commit。

## 4.2 独立重放与 (m=2) 边界

独立数组含三个记录：

* (m=2,n=3)：矩阵维数 19，`psd=false`，rank 4，tail nonzero index 为 11、15，integer scale 16，pivot signs `++++`；
* (m=3,n=4)：维数 67，`psd=true`，rank 16，scale 243；
* (m=4,n=5)：维数 181，`psd=true`，rank 61，scale 6144。

这说明 (m=2) 是一个明确边界，不能把 (mge3) 的 PSD 模式倒推到 (m=2)。`certificate_check` 又核对了 256 个 explicit moments、81 份 independent original schedules 和 `integer_OPT=2`。独立输出没有给 (m=5) 的第二实现，也没有声称任意 (m) 的完整 SDP 运行。

# 5. 数学关系、反例与未决缺口

1. **有限 exact 证书。** 64 份三机调度、1,093 个 endpoint subsets、(m=3,4,5) 的完整 moment/PSD 消元和 256 个 explicit moments 都是可复现的有限证据。
2. **条件信息缺口。** 四阶 moment 相同而指定 source conditional full-(B) load 不同，是 source-specific identifiability 障碍；repair 只修复一个给定 source，不是全域算法结论。
3. **(m=2) 失败机制。** 独立 (M_2) 在 (m=2) 不是 PSD，tail entries 11、15 非零；这保留为有限边界/失败证据，不能拿 (m=3) 之后的正 pivot 解释成全 (m) 定理。
4. **比例记录。** 主点的 (OPT/T=3/2,8/5,5/3) 是三个参数点的精确整数结果。它们是 gap/边界数据，不是 unrelated-machines 的一般近似比；也没有 C2+CONFIG witness 或通用 SDP solver。
5. **模型隔离。** 三份来源都属于 unrelated-machines 的 job-machine endpoint/load 对象，不涉及 CAG 的共同目录、SPE 或客户均分；不能把“half”或六人目标的量词迁移过来。
