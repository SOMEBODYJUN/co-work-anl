# 1. 当前代码核的是完整机器负载

原2491B脚本、SHA `e9ce6730e65c8924d619f42919b2d494a63096794573ebf1113eb32d64db1960`完整读。本轮原字节CLI一次exit0，无输入/外部依赖，Fraction精确枚举；当前源码自身就是修复后的版本，不是旧冻结e0dc…所记4e0845…脚本。

原矩阵有A/B/C三机、七jobs、13个finite端。jobs1–4在A/B均为零；job5在A/B均为一；job6在A/B均为零、来源中固定到A；job7仅C端、时间二。未列端禁止。五bits的even/odd parity各16个串：前4 bit=1选A、=0选B；第5 bit=1使job5选B、=0选A。每支持调度执行全部七jobs，C固定负载二、A/B分担unit job，故全峰二；job7给OPT≥2，来源支持又达到二，所以都是真实最优分布。

程序不是搜所有legal schedules：原矩阵有64种（job6也可在A/B自由选），当前两来源固定job6于A，合计只逐一核这32份支持调度。历史另一独立程序枚举64份，不是本源本轮的计数。

# 2. 全端低阶矩和深度四的差异

枚举13个finite endpoint literals的全部无重复subsets，degree0..4共1093个。对每S，两来源中所有`assignment[j]=i`同时成立的个数相等；不相容one-hot选择自然计零。因为parity的任意≤4个非平凡bits边际相同，job6/7是常量，低阶相同有自足解释；重复powers在真实Boolean assignments上约化，未假设未知pseudo-probability。

令F为前四jobs都选A，则两来源各恰一支持调度满足，概率1/16。even下job5选A，**整台B**负载0；odd下job5选B，整台B负载1。程序按全部七jobs的原处理时间求机器负载，再条件平均，不是只报告某个literal概率。

一般指定来源mu的条件平均负载为

`L_i(mu|F)=Σ_(e∈E_i)p_e*y_(F∪{e})/y_F`。

|F|=t时标量分子需最高t+1阶；degree-one localizer和完整条件C2还分别可能需要t+3、t+4阶。当前t4的B5联合是第五阶，even/odd为0与1/16，四阶表不包含它。F概率零时不可套此除法。一般次数解释由当前5259…原正文承担，脚本只核该五位实例。

# 3. 旧见证的错误和真实版本链

原旧构造让两个互补jobs都以3/2分到A/B，只检查一枚job的literal条件概率0/1；但B的完整负载是 `3/2*b5+3/2*(1−b5)=3/2`，两来源都相同。当前代码明确重新计算这个表达式，assert旧fullB=(3/2,3/2)，再核新fullB=(0,1)。

历史e0dc61…515B冻结记录仍引用旧SHA4e0845…、写的是`conditional b5=0/1`和heavy pair解释；它**不能**作为修复后整机负载的运行证据。原文保留，未改旧JSON，也没有因为同路径/Claim ID而说字节相同。未取得旧源码时，本批不虚构旧源码diff；目前可实核的是旧记录SHA/措辞和新源码的旧表达式计算。

# 4. 可复用和不能推出的事

本例只说明共同四阶数据不能唯一识别**指定来源**的深层条件负载。两来源都可行，算法允许另耦合、重求残余证书或不用深prefix；不推出所有下一选择相反、通用舍入不存在或调度hardness。它是真实分布信息边界，与同批unit-gap的含负三阶伪矩不是同一对象。
