# 关联环秩审计的七个枚举查询与实现边界

本对象是主源2dee的复现依赖说明；review `e7faed81ea53ac5394c5`、程序 `f4c32edec8faa5dd71db`只作完整旁读，本批不对它们新done。三原件/源SHA/两冻结commit路由见[清单](../../tools/evidence/incidence-rank-primary/source-manifest.json)。

原1887字节tiny脚本只有`brute`及四helper。`brute`遍历m^{|J|}个机器编号元组，过滤不存在端，以Fraction累加，遇首个峰≤T的实际分配便返回；不是最优求解器，未用的best/best_s变量也不改变这一点。它不计算b、不选生成森林、不枚举反馈边、不调用叶消元或二状态DP。

实际main七次brute：

| helper | 矩阵与目标 | 实际断言 |
| --- | --- | --- |
| leaf_paths | 4机3任务，菜单{0:1,1:2,2:1}、{1:1,3:3}、{2:1}；T=2及1 | 两次都找得完整可行分配。原未剪枝关联图为森林且首任务支持3。 |
| cycle_core | 2机2任务，菜单{0:1,1:2}、{0:2,1:1}；T=1及0 | 1时可行、0时不可行。T=1删p>T后只剩对角边，**没有执行残余单环**；原拓扑四环不等于其算法环DP已被测试。 |
| zero_and_empty | 1机空任务T0；2机任务{0:0,1:3}、{1:0}，T0 | 空分配和全部零负载分配正确。 |
| fail_leaf | 2机两任务都只在机0时间2，T2 | 确实无完整可行分配。 |

所以是五个不同矩阵、七个矩阵/阈值查询、四helper组。stdout字段`incidence_components_checked:4`来自固定字面数4，不是程序真正统计四连通分量，也不是四种算法实现。

本次原程序实际运行一次，Python3.12.14，未启用-O，exit0，完整stdout52字节和空stderr均真实保存于[执行证据](../../tools/evidence/incidence-rank-primary/replay/run.json)同目录；结果为`{'incidence_components_checked': 4, 'status': 'ok'}`。没有伪造不存在的冻结JSON或重复本代码旧成功运行；inventory未给本程序的旧独立运行JSON。正常断言是实质检查，-O会移除它们。

短review重构反馈边完备性、安全叶交换及零边界，称有限核回算覆盖共任务反馈边拒绝与单环核心。该泛述可能包含未交付的手工/私有计算，但**所提供tiny代码没有这些算法路径**；本次只认实际代码/输出的七次brute，不把review句话当成已交付后端。一般[算法证明](../算法/有限反馈边与安全叶消元的精确调度--算法.md)仍是自足解析结果，未因代码弱而否定；若要验证生产实现，需另给该算法及实际身份输出，对照此brute并触达残余真单环/共任务分支/孤立冻结峰等域。这里没有为这些未来检查预写PASS。
