# 1. 程序的精确输入和输出

原脚本903B、SHA256 `41cd56189f129fa60dbf97c5dad55c9cb283e9912910657a22a6c4b7adf65495`，已全文读。它没有输入参数/外部依赖；只用标准库Fraction与硬编码矩阵。原件、命令、stdout/stderr和execution记录见[本包证据](../../tools/evidence/um-next-four-audit-primary/README.md)。

取 `U=[[1,1,1,1],[1,1,0,0]]`、B=1、lambda=2/5，原处理时间 `p_ij=B−lambda*u_ij`。balanced分配为两机分别`[2,3]`、`[0,1]`（0-based），两负载都是6/5；overflow为`[0,1,2]`、`[3]`，负载9/5与1。脚本断言峰值分别6/5、9/5及比值3/2<19/10。

脚本本身**没有遍历求OPT**。数学上全部finite时间至少3/5，四job给两机必有一机至少两job，故任何actual峰值≥6/5；balanced达到下界，才可由人工推导确知OPT=6/5。不能把这条推导记成程序调用过精确OPT oracle。

另对rho=3/2、19/10、2，各从`q=max(2,floor(1/(rho−1)))`出发，必要时加一至`(q+1)/q≤rho`，并逐个assert。三例最终q均为2。程序只核这三个rho的一个q，不穷举所有有理rho或所有q。

本轮实际一次执行exit0，stdout为 `{'status':'passed','rho_witness':'3/2','uniform_count_bound':'verified'}`。与历史JSON c4f03674003e646df675所保存stdout完全相同；这是**新增一次复跑**，不是把旧执行改名为本轮。

# 2. 自足数学含义及未覆盖部分

若另已保证每机恰q件，仿射式有 `L_i=qB−lambda*Σu_ij`，makespan才反转最小效用。没有等基数时基线是`|A_i|B`。所有效用均相同的情形中，每job时间p0、总jobs=qm，均衡峰值q*p0；把两机计数改q+1、q−1，峰值(q+1)*p0，只要`q≥1/(rho−1)`仍在rho近似内。这个一般推导说明乘性makespan不能单独强制等基数，由[既有双源审查](../审查/仿射固定基数边界与锚任务缺额联合舍入双源审查--审查.md)及当前source8088原正文承担全称量词。

本程序没有实现效用恢复/裁剪、所有decoder攻击、近二参数搜索或hardness归约。其具体overflow机2只有零效用原资源，说明“近似调度再按数量裁剪”可能丢源值，但程序不执行该裁剪。一般UM目标、额外非仿射选择器和其它归约不被否定。

本源是仿射边界的可运行有限资源，与同批anchor、cover-MW、degree-two-menu三程序没有共同参数合同。本轮一原程序执行，无新增blind/外部审核，原件未改。历史结果、原正文与本轮结果各有独立SHA/路径；source清单和实际比较结果在证据manifest。第三阶段可将它作为finite-check支持仿射边界，不能当通用定理证明边。
