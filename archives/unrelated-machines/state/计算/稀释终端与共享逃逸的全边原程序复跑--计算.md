# 1. 原程序及完整输入的生成

11101B底座程序SHA `9aa9c7c3390b658da10b925618ff0fed2762c61e768cf6e2c232fc3936fd9092`、8623B扩展程序SHA `a56a90992101d73a404c92578cebe0ad048b7dbf6782309bcf95a3c9e4c160c8`均完整读且未改。扩展实际动态import底座及14747B的GHMR实现SHA `63f64a5497223e451374c74359dade6bec14ea507b3ed901d8f9495a699f2deb`，后者本轮也完整读。它只调用该模块的`filter_domains`，没有运行模块的独立audit/CLI或其旧rounding依赖。

对整数k，h从α_1=1/(k−1)起、每层乘k/(k−1)，取首次α_h≥1/2；N=k(k−1)，T=1+1/k。两棵k叉物理机器树共h层，bridge在两根各时间1，父子任务父端1/k、子端1。每个底层父配N台独立终端：k个普通任务各在父端1/k、自己的一个终端1；另N−1个阻塞任务可在该组**全部**终端时间1。其余端∞。代码显式生成这些原任务，未丢未选树/组。

根/内机的配置由child入边边际递推：全k个小出边与各{incoming,一个小出边}混合；根再稀释bridge边际为1/2。终端以普通任务singleton权1/k（有该普通任务时），其余权按N−1个阻塞任务均分。`check_config`检查行质量1、配置合法负载≤T及每job覆盖1；列数不是求解通用CONFIG LP的迭代数。

扩展只增加一台共享物理机器z，**全部组全部阻塞任务**在z再有时间1/2；z的CONFIG只取空集。普通/bridge仍两端，阻塞任务从N端变N+1端，不满足每job两/三资格的额外承诺。

# 2. 每条独立LST点和星匹配究竟核什么

默认所有普通任务去大端、bridge去第一根。每组终端余量c_t=T−u_t，总和NT−k=N−1；每个阻塞任务按c_t/Σc送终端。强制一条旧边时，代码按类型改一个普通任务或bridge位置；若强制阻塞任务占其终端，则先把那台终端的普通任务移回父端、重算余量，再按比例分其余阻塞任务。新增b→z探针只把该阻塞任务固定z，其余仍按各组余量比例分配。每个完整点重新核全job覆盖、剪枝资格、所有机器负载≤T和指定边质量1。**不同边允许不同点**，没有共同全局分布要求。

对查询(i,j)，星任务为其它有i端、且其每个备选端都严格>T/2的任务F_i(j)。代码独立增广匹配把这里全部F任务送到不同备选机器，于是匹配收益W=Σ_F p_iℓ，必要负载界退为p_ij≤T。该规则的安全性来自真实T调度中这些大备选任务不能同机，故真实移出量≤最大部分匹配收益；它不输出完整可行调度。T/2等号不属于大端。

# 4. 共享逃逸：完整k4与实际GHMR对照

扩展CLI本轮一次、没有skip-peer/skip-star。实际k4/h3/N12是427机、521job、4914资格端、4571配置列。代码重算4562旧边+352新增z边的全部LST点，最大负载5/4；4914全边星匹配；给每个4394大边查询另显式构造匹配，覆盖必走大边任务、强制查询和查询机器全部唯一小端任务。z本身无大边查询，代码仍另给全部352个z-唯一小端阻塞任务匹配到不同终端。

`only_mandatory_job=0` 的**0是bridge任务编号**；必走大边集合恰{bridge}，并非mandatory数量零。代码先验证这一点，再实际调用peer `filter_domains`，结果接受、rounds1、deleted_edges0，所有原域保持。这个实际调用与4394个独立构造匹配是两项检查；后者没有import peer的匹配routine来代证自己。

未用z的完整路径调度值7/4经全部原job重算。增加z后不能照抄底座下界：若B<2−1/k，每个活跃父至少外送两普通任务，h≥3迫至少四活跃底层组，每组至少一个阻塞任务去共享z，负载≥4·1/2=2>B。因此该一般族OPT仍2−1/k；这是解析下界，不是本轮521-job全分配枚举。

扩展另对k4..64的61行只算h、2^(h−1)、escape-load、(2k−1)/k、T及ratio=(2k−1)/(k+1)，**仅k4物化**。不把这些行记61次调度审计。代码没有实现条件点内部同时加CONFIG/大边基数或强制边后再运行整个GHMR的嵌套探针。底座更强大边基数探针对准确阈值的证明不能直接覆盖共享z变体所有目标。
