# boss7历史工作台的实际内容

`01f60d42d482f23ab4c0` 是旧 boss7 工作台，不是本次Boss注册。它采用两个数学接口：真最优调度凸包固定槽损失（7ff5e8374a6b9826845c），以及既知的有向需求token桥（1612ef209f096d6f4803）。其“构造共同迁移算法”仍为未完成义务，不能因链接审查、代码、输入和证据就当算法已给出。

本批对第一个原稿16794B全文实读，并比较[固定工作/固定槽审查](../审查/固定工作局部极小与真实凸包固定槽双源审查--审查.md)。第二个接口复用已全文比较的[根树桥审查](../审查/根树流环正规化与有向需求桥冻结审查--审查.md)与前批准确资源[共同拥塞与非单位分叉](共同拥塞的支撑搜索与非单位分叉参数--资源.md)，不冒称本批重读17392B桥原稿或所有证据。前批已经提交“单枚根任务g”最小修正，Root另行处理，本批不重复该proposal。

# 真最优凸包仍不足以固定槽舍入

m≥2台相同机器，一个big（每端1）与m²−1枚tiny（每端1/(m+1)）。tiny可分为m−1组，每组m+1枚；构造m个循环最优调度，每次big独占一机，其余各机拿一组。每台负载1，故OPT=1。均匀平均这些真实最优分量，得每任务每机x_ij=1/m；这明确是 **真实OPT整数调度凸包中的点**。

按处理时间降序将每机分数质量放单位槽，每机质量m、槽数m。总任务m²、总槽m²，任一覆盖全部任务的槽匹配必用尽全部槽，因此每机恰接m任务。big所在机还有m−1个tiny，其负载

\[1+(m-1)/(m+1)=2-2/(m+1),\]

其他机m/(m+1)。任何tiny平局顺序、任何覆盖匹配都相同，故不能靠选同图“最佳matching”修复；标准Hall保证覆盖匹配存在。限制仅在固定槽输出空间：若输入还提供真实分解，可直接选一份分量；重新开槽、改变x、加槽外任务边都不是该接口。

# 槽外的精确修复与one-destination限制

移走big机的m−1个tiny，一件给每台其他机器，立即到OPT1，Hamming=m−1；这是最小值。big若搬走，其新机器原有m个tiny，为达到1需全撤，因此至少m+1件改变。

若额外要求每个源机器的原任务只能去一个外部目的地，big不动的最小Hamming是m(m−1)/2。单目的地功能图需从big机依次经过所有机器：第一批送m−1件，接收机超出的m−2件必须去下一机，再m−3…1，累计三角数；用各机原库存完成这些批次可达到。强制big搬走的最小值为m(m+1)/2。这个派生条件不是一般迁移限制的事实，更不能说所有合法修复都是最短；m=3存在Hamming7的合法循环。

在big固定的路径修复中，第t批完成后峰值(2m−t)/(m+1)，每批严格下降，最后到1。接收机可以增载，且批内每一单任务不承诺严格下降；故它反驳冻结坐标/单目的地的错误推断时须保“整批同步”与原任务身份。它也不同于[固定工作量族](固定工作量单任务势停滞与批量逃逸--资源.md)的三件启动逃逸。

# 最小工作量面：不同矩阵、不同原理

另取big B每机时间m；每台home有m−1枚small，home时间1，其他机时间1+d，d=1/m。目标T=m+d，真实OPT=T：big一台，移其m−1枚small各去另一机，负载big机m、其他机m+d。若不迁任何small则big机2m−1。若峰值<T<m+1，big机不能带small，其他每机最多m枚small；m(m−1)枚small迫使其他m−1机各恰m枚，每机原home只有m−1枚，故各至少一枚off-home，负载至少m+d=T，矛盾。assignment LP的最小可行阈值为m（small全home、big均分）。

在阈值T的LP上再最小化总工作量，设S(x)为small离home分数质量，则

\[W(x)=m^2+dS(x).\]

故整个最小工作量面固定全部small home，只分big份额b_i。负载约束给b_i≤(m+1)/m²，Σb_i=1又给b_i≥1/m²>0。因此整个面的正支撑都只含home small与全部big端，任何仅用此支撑的整数调度峰值2m−1，趋二比(2m−1)/(m+1/m)。取前m−1个b_i=(m+1)/m²、最后1/m²可得basic点；即使开放全最优面，也没有跨home small边。**这个族不属于前面真OPT凸包身份**，不可混用其凸组合证据。

## 正确的工作量预算

对实际整数调度，若有s枚small离home，工作量恰m²+ds。对整数q≥0，预算

\[W\le m^2+dq=m^2+q/m\]

等价于至多q枚small迁移。该预算内最佳峰值为

\[\max\{2m-1-\min(q,m-1),\ m+1/m\}.\]

big机初有m−1枚small，不移big而向外迁min(q,m−1)件分别给其他机器达到公式；下界由big机至少剩这些small及真实OPT共同给出。若移入其他home的小任务，只会增加big机负载；big位置可任取，计数相同。

旧双源审查把“工作量增加q/m”误写成“工作量增加q”后仍套“至多q枚”，量纲错误。显式m=3，允许ΔW≤1时可迁2枚small（实际增2/3）达到10/3，而错当仅q=1件会给峰值4。本批附原稿§6正确dq与旧页before SHA最小替换，不改源。一般实数预算Δ应对应s≤⌊mΔ⌋，不是s≤Δ。

恢复OPT需m−1枚迁移，成本增加(m−1)/m；与基线m²相比相对增量→0。因此这族不排任何固定正乘法成本松弛，也不排改变工作量目标或支撑的算法。

# token桥的正确接口与主目标状态

旧工作台第二链接采用既知机制：有向需求D中每顶点一台机器，**只有一枚**unit根任务g固定于r；每个正需求点v仅有q_v=min(k_v,outdeg_D(v))枚不同token，每枚在v时间1/k_v、在任一原child时间1，另有一枚只在v的filler补到home总量1（时间1−q_v/k_v；为0可省）。这保原任务身份，且Σq_v≤|E|，不会按二进制巨大k_v展开。任意峰值C<2的调度可解码真实单父根树，反向树构造调度，给OPT=2−b*（截断比例、终端与死端按定义处理）。二进制大需求必须使用压缩构造/流容量，不能免费复制指数枚token；一般共同分支/合流资源的选择仍是未完成义务。准确阈值归约保≥/严格端点和给定支撑条件，不能当作找未知根树的oracle。

两条接口分别约束固定槽/固定成本支撑与共同资源选择；它们没有提供一般ε>0实际调度算法。旧README明确不再免费依赖(Aδ)oracle，也不为没有一般增量保证的固定平方势或常数半径探索制造新定理；本资源保留这一未成熟状态与可接续量词，0新run、0外部新颖性认证。
