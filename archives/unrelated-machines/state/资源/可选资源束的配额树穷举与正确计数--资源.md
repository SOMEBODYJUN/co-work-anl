# 数学输入及程序的两个计算方向

99行 `k_uniform_bundle_matching_floor.py` 处理q个选择点x=0…q−1，每x可有多个标签资源束S，1≤|S|≤k；根需求q、x需求1、标签需求K≥1、资源终端需求0。t-领取从不同x各选一个标签，再从其S取t资源，所有领取不交，最大点数为ν_t。q>0时树评分恒等式为
\[
b^*=\max_{1\le t\le\min(k,K)}\min\{\nu_t/q,t/K\}.
\]
从正评分b树取每x一个标签和t=ceil(Kb)孩子，根及单父性给两个下界；反向不交t子束直接造树。这里每个x的标签相关性不能丢，资源名本身的类型/坐标全部保留。

`bundle_choices(S,t)`精确列出所有t子集为frozenset。`nu_t`按x递归，每步可跳过x或选其某S的一个不交t子集。`formula`逐t求上式；`brute_b`则枚举非空x子集、每x一个父标签、每标签任意非空子资源集，检查总基数等于并集基数后直接评分。它不先调用ν_t，也不生成UM任务，所以是两个有限组合计算方向，不是两份调度后端。

`brute_b`的候选已将每x标签剪成一个；对评分≤1且x需求1的正树，删多余标签及其子树不降低该x比例到1以下，足够求最优。score未再显式写min(1,…)也合法，因为选中x数/q≤1。K大于资源束大小时可达到的t自然受|S|限制。

# 主入口的真实范围和计数

| 实际循环 | 精确范围及比较次数 |
|---|---|
| q1穷尽 | 两资源的非空子集只有{0},{1},{0,1}三种；标签全集3项，边集mask有2³=8个，各测K1…4，**32**次 |
| q2固定seed随机 | 四资源、束大小1…3，总28条(x,S)可能标签；Random(20261017)抽1200个样本、每项被选概率1/4，各测K=1,2,3,4,7，共6000次。样本不保证互异。 |
| 固定单资源地板 | 两x各一互不交singleton，K1…9，共9个断言 |

本批原入口在独立新空目录执行一次，exit0/stderr空。原stdout仍写 `exhaustive_q1=16*4`，这是硬编码计数错误；实际代码/新诊断确认8*4=32，原程序字节及真实stdout不改，不把64当运行规模。[执行证据](../../../../tools/evidence/um-parity-quota-and-three-dimensional-programs/runs/8af37296657f6ee6656d/execution.json)保命令/SHA/退出和输出。

# 零分支、算法成本及不能继承的结论

代码`formula(q=0)`明确返回0，`brute_b`空枚举也为0，主入口没有测试q0。它是原公式采用的**软件空值约定**，不能据此调用一般token桥得到OPT2：标准根树若根需求0且为终端，截断评分为1，原桥只剩unit根任务时OPT1。一般数学身份和桥梁在这里须先限q>0；空值约定不悄改原桥。

边集为空、某x无标签在当前固定循环会出现，正树被跳过，值0；集合中的资源可为任意可比较稳定名字，程序只用其精确身份。没有输入检查来认证一般API的任意q/K/索引。全部配置/资源子集与树枚举指数增长，`formula`若K数值大也不能叫通用位多项式求值器。

理论上t1层是普通X—资源二部匹配，ν₁=q给b*≥1/K。固定K、δ时，t₀=floor(Kδ)+1，候选(x,B)超边大小t₀+1，极大匹配至少ν_t₀/(t₀+1)；在δ<1/(t₀+1)可区分特定完整YES/低评分NO。这是既有数学的受限复杂度地板，脚本没有实现这套一般筛选/归约，不能从固定9断言或6000样本推出hardness。

# 与相邻模型及证据的关系

3DM的每三元组资源束是**带类型**的{Y_y,Z_z}，每x有多可选标签，属于本bundle模型k2；[3DM原程序](../审查/三维匹配树枚举的资源标签缺陷与有限合同--审查.md)的singleton重标缺陷不在本程序frozenset资源实现里。本批独立诊断在显式q2反例上核本程序b1/2，直接typed树也1/2；把同x所有标签取并集后，单邻域值却1，说明那种模型替换无效。

[单邻域程序](单邻域配额枚举的自由根需求与模型边界--资源.md)仅在每x一个标签且根需求等于|X|时直接是本接口特例；它还允许根需求独立q，须另保截断1。源正文/旧审查的相关特例及空值措辞有独立最小勘误建议，不改原源。

原程序全99行及标准库依赖Fraction/itertools/random均实读，无文件输入/仓库模块/外部solver。本批一个原entry运行和一个独立语义诊断分别记录，不把它们冒称外部独立全文审查。原件见[冻结源](../../../../tools/evidence/um-parity-quota-and-three-dimensional-programs/original/8af37296657f6ee6656d.py)；一般公式来自结构证明，程序只是上述有限输入的精确核验。
