# 文献源目录登记检查点

## 实际对象与运行范围

冻结 JSON 的 `base_commit` 为 `a6be1a8ef5d43a3609d3f23ace1fa4dc290a1786`，运行时 Python 为 3.12.14。变更只把 `history/source/literature/unrelated_machines` 加入已登记的 archive 默认范围；其他题目目录和前缀相似的 source 目录必须保持本地，不得因字符串前缀被顺带发布。实际命令是 `python -m unittest discover -s research/weighted_congestion_frontier/tests -p 'test_checkpoint.py'`，42 个测试返回 `OK`。

源记录的四类覆盖是：

1. 新文献 source 目录在本地 bare remote 上实际 checkpoint；
2. 其他 topic source 目录不被发布；
3. prefix-lookalike source 目录不被发布；
4. 既有 checkpoint 历史、冲突、凭据和范围回归仍通过。

它保存了被测 `checkpoint.py` 与 `test_checkpoint.py` 的 SHA-256，因而可以把“范围选择行为”与当时的代码版本绑定。该记录支撑的是工程路由合同，不是 unrelated-machines 的调度定理，也不证明当前 `rebuild/research-v2` 新版程序的所有行为。

## 证据等级和边界

这是一份有限、本地 bare-remote 的回归证据；源明确记载完整 103 测试套件来自前一 scope release，本次只重跑受影响的 42 个 checkpoint 测试。没有生产公屏流量、线上负载、并发吞吐或文献内容正确性的验证。后续使用时只能引用“该版本的 checkpoint 范围选择通过了指定测试”，不能把它扩大成所有路径过滤、远端权限或数学结论。

同路径在 `legacy-cleanup` 与 `main` 两个冻结提交中视为同一对象；本登记保留双来源定位，不复制原始 JSON。若以后程序改变默认 archive、范围匹配或 source 注册表，应重新生成带新代码 SHA 的回归，而不是沿用本记录。
