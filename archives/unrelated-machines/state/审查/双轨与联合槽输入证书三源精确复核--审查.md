这三个源是既有 unrelated-machines 数学对象的输入级原件，不是客户吸引六人 SPE 模型的来源。第一个源是组联合槽位舍入的 16 个有限输入；后两个源属于同一归一化双轨编码族，一个给 A=1,…,8 的单例外 arity 尖锐证书，另一个给完整 signed cube 的 A=3 实际证书。它们分别补齐了既有审查中的冻结输入引用，不能把有限证书解释成一般调度近似、硬度或六人半覆盖结论。

# 组联合槽位输入（`b083c8d4196a16c48a20`）

冻结对象 `examples/unrelated_machines/distorted_group_joint_slot_cases.json` 的顶层 seed 为 `2984106`，包含 16 个 case。每个 case 明确给出：有限私有组的 `w/E/b/p` 参数、sink 数、宏任务机器时间、阈值 `T`、小任务上限 `delta`、汇点包络 `kappa` 与 `Bbar`、槽参数 `r`，以及 `source_schedules`、`LP_macro_flow`、`LP_token_flow` 和输出中的 `private_assignment`、`home_loads`、`sink_loads`、`token_loads`、`demand`。

逐案计数为 86 个 `source_schedules`、15 个宏流列表条目、32 个 token 流列表条目以及 77 个私有任务赋值。参数覆盖空组、无 sink、无宏、零 `delta`、`Bbar=0`、非零 demand、两宏/三组组合和一个约 `2^{-127}` 的极小 `T` 与任务时间。输出中的 home load 包含宏在被选 home 上的机器相关时间；不能只把私有任务的 `w` 相加。已有材料中将给定 LP witness 舍入审计为 1248 fixtures、1,192,421 assignments、105 个非整数末槽和 16 个 normative replay 的记录，属于更大的冻结运行证据；本源本身的 16 个 JSON case 与这些证据通过相同输入 SHA 绑定。

本次独立校验用 `Fraction` 逐组检查：

1. 每个私有任务的输出目标要么是其 home，要么是 `E` 中的 sink；sink 目标使用对应 `p[z][j]`，home 目标使用 `w[j]`。
2. 每个宏的 `macro_home_slot` 指向该宏可用的 home，并按宏字典中的处理时间加入对应 home load。
3. 重新求和得到的全部 home/sink loads 与 JSON 输出逐项相等；赋值长度、sink 数、组数及 demand 长度均相符。

这确认的是输入证书和输出记录的内部一致性。它没有生成通用 LP witness，也没有证明未知 `OPT` 情形一定能构造 witness；既有《联合槽位与均匀束匹配有限审查》保留的 blocked-conservation、zero-target、无通用 LP backend 及 unknown-OPT 缺口仍然有效。与《失真组联合槽舍入与固定汇点占位双源审查》比较，本源唯一增量是直接把冻结 input JSON 作为独立来源绑定，并把宏时间对 home load 的贡献纳入复核；数学结论仍由已有受限合同承担。

# 单例外 arity 尖锐族（`0d323a2d8638ce87fc76`）

源的 scope 明确写为 “A1..8 explicit actual arity2A+1 sharp family; lower bound separately proved”，status 为 `pass`。它给出 A=1,…,8 的八份完整实际证书。第 A 份证书满足：

- 机器数 `m=4A+4`；
- 原始 job 数 `6A+3`；
- 每个 job 的 `sigma` 目标均在该 job 的 `original_jobs` 资格字典中；
- 机器负载以有理数给出，实际 makespan 与 `proved_optimum` 均为 `(A+1)/A`。

因此八个精确值依次为

\[
2,\;\frac32,\;\frac43,\;\frac54,\;\frac65,\;\frac76,\;\frac87,\;\frac98.
\]

独立脚本逐 job 重算每台机器的负载，验证八个 `sigma` 都合法，重算负载与原数组逐项相同，且最大负载等于上述 `(A+1)/A`。这保留了 arity `2A+1` 族的显式 sharp witness，并与既有双轨审查中的严格阈值边界相容：它是固定模板下的实际证书，不能推出任意双轨 gadget 都存在同样下界，也不能把 `A` 的八个值当作对所有编码或所有 unrelated-machines 实例的全称结果。

与现有《双轨阈值实际前沿与逐行均匀相关防护双源审查》及 `threshold-bundle-20261030` 证据比较后，新增的语义去向是“原始 arity 尖锐输入逐 A 展开、真实 `sigma` 与精确 makespan 的直接核验”。其余关于三二上界、严格阈值解码失败和 full-cube 公式的证明条件沿用既有正文，不能由本 JSON 单独承担。

# 完整 signed cube 的 A=3 证书（`c364b9a5b3af1dd211c5`）

该源的 scope 是一个 balanced two-rail selector code on an explicit full signed cube，且明确声明不反驳其它 block codes。实例参数为 `A=3`、`d=5`，含 5 枚 selector、32 个 clause mask 产生的 160 枚 port，总计 165 jobs；机器数组长度为 42。每个 selector 只能在其两条变量轨上用时 1，每个 port 在变量轨上用时 `1/16`，在对应 clause 外机上用时 `1/3`。源同时给出 `exact_value_formula` 的候选：

| B | 每条负轨保留容量 | 移出 port 总数 | 值 |
|---:|---:|---:|---:|
| 3 | 2 | 7 | 9/8 |
| 4 | 1 | 1 | 4/3 |
| 5 | 0 | 0 | 5/3 |

选取 B=3，得到 `9/8`。源包含两个实际 `sigma` 证书：`A3_hand_certificate` 和 `certificate`。二者均为 165 个合法目标，均重算出 42 台机器的完整有理负载，最大值均为 `9/8`；两证书的负轨内部计数分布不同（分别为 `[2,2,1,1,1]` 与 `[2,2,2,1,0]`），但都移出 7 枚 port。这种重复证书应保留为同一精确值的两个见证，不能误合并为一条唯一策略。

源附带的 `source_no_scope` 是：对 `A>=2`，每个 source assignment 都有一个全真 clause，因此即使把阈值降到 `d-1` 仍不可能。这个断言只对当前完整 signed cube 代码和其 clause/port 构造成立；它不等于一般 SAT 编译、一般 unrelated-machines 下界或 `UM-TARGET-v1` 的 hardness 证明。

独立 `Fraction` 校验逐 job 检查两个 `sigma` 目标都在 `eligible` 中，并重算全部 42 台机器负载。校验结果与源的 `actual_machine_loads`、`actual_makespan=9/8` 完全一致；原件的 `code_sha256` 与冻结审查中记录的 balanced full-cube 实现哈希保持绑定。与既有双轨审查比较，本源新增的是 A=3 真实证书的完整输入、两份不同负轨分布的合法见证和 B=3/4/5 候选对照；一般 `A` 的公式仍需依赖既有证明段落，不能从这个单点证书外推。

# 处置、关系与未决点

三个来源均已完整读取、解析、与已有双轨/联合槽位正文和证据比较，并保留其独有输入级内容。处置目标为本审查页和 `dual-rail-input-certificates-20261031/` 证据目录；它们分别链接到既有对象：

- 组联合槽位源接入《联合槽位与均匀束匹配有限审查》及《失真组联合槽舍入与固定汇点占位双源审查》；
- 两个双轨源接入《双轨阈值实际前沿与逐行均匀相关防护双源审查》及 `threshold-bundle-20261030` 证据。

仍未解决的承重问题是：如何生成一般输入的有理 LP witness、如何在未知 `OPT` 下保留同一量词、如何把双轨弱端的有限逃逸阻断为真正的近二 soundness，以及如何从 full-cube 的有限精确式推广到其它编码。第三阶段可以据此建立“有限证书来源于双轨/联合槽位对象”的关系边，但不应把它们作为六人 SPE 覆盖模型的前提。

本页只声明有限输入保存和精确复核完成；没有把 `integrated` 误写成一般数学问题已解。
