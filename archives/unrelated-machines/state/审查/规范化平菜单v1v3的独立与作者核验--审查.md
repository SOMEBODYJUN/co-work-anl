# 规范化平菜单 v1/v3 的独立重构与作者读后核验

## 审查对象和版本身份

本批实际读取四份冻结记录：v1 statement-first 独立审查、v3 statement-first 独立审查、v1/v3 author read-after、以及 final canonical scope review。记录共同引用正支撑 FSLP 合同，但版本和阅读顺序必须保留：v1/v2 过程版本不是额外成熟定理；final review 声称匹配 v3 Exact 与 author Proof，却没有把旧过程稿升级为独立结果。

四份源在冻结树上的源文件 SHA-256 分别为：v1 statement-first `dff69ad05b38d92604c8aa7227009cd2a61bdbeeb60b5409471a39fca66f8c92`，v3 statement-first `22acf36bac189365e4c4d5d85da30938f8623f8d383ca033d5e2fbf8e53950b7`，author read-after `868552332c93f685734c1cb70bedf5bf026bd521f64f337d1ff917af7bab070c`，final scope `786853806869ef8245754e3aa67f8db6c975d8e270300785e43bc2fab69c2088`。审查记录还列出其所读 canonical Exact/Proof 的哈希（v3 Exact `6a31b269...`、v3 Proof `fb652fd0...`、v1 Exact `9fd64439...`、v1 Proof `7f8bd074...`），但这些 canonical 文件不在本次冻结源正文中；本批不冒称重新读取它们。

## 已支持的数学内容

四份记录在以下范围内相互一致：

1. 输入是 finite nonempty normalized flat menus，state 总值为一，资源标签在 state 内互异；允许 zero incidence、unused resource、indexed duplicate states。FSLP 仅按 (p>0) 的正支撑成员计 (0/1) 容量。
2. restricted-flat machine CONFIG(1) 与正支撑 FSLP 双向变换保留全部原 job 身份。forward 把 selector+zero 私有项与全部 incidences 分成两类配置；reverse 用 selector 边缘 (α)、unit resource 端和正私有关联的互斥性得到容量不等式。只保证 threshold one 与该结构化两端，不保证 arbitrary UM/threshold。
3. Tree reverse 允许 off-path fractional activation，通过 root flow 与叶原 state 质量 (W_g≥1) 归一化；port-path 以 hole 分布和 (d-1) helpers 给出容量等价，d=0、d=1、全零 membership 明确处理。
4. state-dummy SC 桥用 (K-1) 个 unit dummy。SC CONFIG(1) reverse 将无 dummy 的配置认作完整 real support，有 dummy 的配置剪为一个 dummy，容量推出组内 real 质量至少一；阈值大于一时 dummy 需求 (K) 超过容量 (K-1)。实际 SC 值的整数桥与 fractional CONFIG 证明分开。
5. SC unit-helper 路径在 actual value 上正向需要 (0<v≤1)，反向对任意 (v>0) 成立；helper 可以拿相邻两份 copy，不能偷偷剪成 singleton。finite CONFIG forward 需 (0<t≤1)，reverse 对任意 (t>0)，阈值零用空配置单列。旧 optimum/最高阈值不超过一时才宣称保持。
6. 自足 (Q_D) 族给实际值 (1/D)、FSLP/CONFIG 阈值一和显式 (D^2) 规模；它是 bounded-row CONFIG 障碍，不是实际 OPT≥1 promise 的反例。

## 独立重构、作者证明和最终审查的差异

作者与独立重构在 tree reverse 有两种等价写法：作者从 root 发一单位流并逐边按 state 概率封顶；独立重构先证叶原 state 质量总和至少一再归一。两者都只降低原资源使用，不要求目标只有一条活路径。

若 CONFIG 只给 job coverage≥1，记录允许逐 job 删除冗余并在需要时拆分一个配置权，以得到精确 coverage=1 证书；该步骤保留机器负载并以显式有限支持为前提。作者的若干逆向用逐组下截，独立写法可除以组总质量 (W_g≥1)；两者都不展开分母。

final scope review 逐节核对：zero private jobs 仍在 UM 实例；FSLP 不按 private time 加权；SC reverse 不假定 helper singleton；实际 value 与 CONFIG 阈值边界分开；所有位复杂度结论按显式输入/证书支持计费。该 review 的 verdict 是“VALID / no fatal”，属于内部阅读记录。

## 明确不支持的外推与遗留义务

- 不给任意 UM 矩阵、任意 threshold 的 CONFIG 保持，也不保存一份给定证书的每个原边际。
- 不给 unknown optimum 或指数配置表的 oracle；FSLP 可用标准有理 LP，但对象本身不交付通用 solver。
- (Q_D) 的实际值低于一，不能否定 actual-OPT-at-least-one promise 算法；未给 near-two、NP-hardness 或一般常数 finder。
- 不把 BCG、作者自述阅读或审查标题当外部同行评议、新颖性认证或文献事实；本批也未运行代码/有限枚举。
- canonical Exact/Proof 的外部 scratch 路径只在源记录中作为 provenance 出现。本批可复用的是记录已展开的数学论证和精确边界，后续若要升级为“直接原稿核验”需重新取得并读取那些版本。

## 用途与接续

此审查对象用于后续地图和引用时区分“内部有效的 v1/v3 证书合同”与“尚未完成的 promise 算法问题”。引用 (Q_D) 时必须同时写出 (D≥2)、显式规模和实际值 (1/D)；引用 SC 路径时必须保留 oldOPT/old-threshold≤1 以及正阈值 (v,t) 的方向条件。任何新代码或 general-UM 结论都需另立对象和复现证据，不能从本审查状态继承。
