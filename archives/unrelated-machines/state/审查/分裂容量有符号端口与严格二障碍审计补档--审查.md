# 实读和复跑

三项 source 均 clean show 导出并逐行读取。split-capacity 程序本地输出 exact finite audit JSON；counts 包括 exhaustive split template constructions=18479、random split actual constructions=2000、sharp inside/outside modes=32768、sharp selector capacity patterns=8、invalid domains rejected=8。strict-sub2 程序输出两组 PASS，覆盖 k=2,3,7,100 和固定 epsilon=1/100,1/50,1/20,1/19。signed-one-job independent 程序逐段核验，但其 registered_private_host_schedules 依赖 signed_one_job_port_sharp_profiles.json 不在当前结果树，本轮没有伪造 JSON。

# Signed one-job port

程序只处理每个 port 只有一个内部 endpoint 和一个 global bit 的 downset。它接收两个实际 uniform internal assignments，翻转一个 port 的 incoming bit，构造 mixed witness，检查内部 loads、profile、strict bound 和 invalid input。外部端点容量不纳入投影；multi-job encoding、shared external capacity、求解 uniform assignment 和一般 decoder 明确超出范围。缺失 fixture 只影响 registered example，源码中的显式审计合同仍被完整读取。

# Split capacity dual rail

split-capacity 程序以显式 variables/clauses schema 构造二轨 rails。每个 clause 有整数 A，arity 不超过 2A；每个 occurrence 的 port 在对应 sign rail 上时间 1/K_sign，在每个 clause-unit external machine 上时间 1；selectors 在两个 distinct rails 上时间 1。一个 integer flow 被所有 clauses 共享，构造器不调用 SAT/OPT/LP oracle，并输出全部 original eligible edges。审计同时覆盖 empty-A1、even-arity giant-A、sharp selector capacity、inside/outside modes、随机 actual constructions 和 invalid domains。它只给限定分裂容量模板的三半结构，不能外推一般 UM。

# Strict sub-2 batch barrier

strict_sub2 程序定义三台机器的 loads(k,x,y,u,v)，其中 a=(8k-1)/(8k)。它逐项检查坏状态峰值 1+a<2、完整释放状态 loads=(1,1,1)、单侧释放少于 k 个 escorts 会越过 2、第一次合法严格二下界需要 k+1 jobs，以及固定 epsilon 选择 k>1/(8 epsilon) 的支持推论。该程序是精确阈值审计，不是一般 approximation lower bound；它不证明所有 UM 输入都必须经历该 batch barrier。

# 处置

三源均处置为 integrated。代码与可复现输出保存在 batch7 evidence，signed-one-job fixture 缺失如实记录。结论只适用于有符号单 job、双轨 split-capacity 或该参数族的 strict-sub2 batch；不升级为一般 unrelated-machines 近二算法、NP-hardness、外部新颖性或 customer-attraction/SPE 结论。
