## 三维匹配需求放大：精确地板恒等式

给三维匹配实例 (A=(X,Y,Z,E))，(|X|=|Y|=|Z|=q)，令 (
u(A)) 为最大三维匹配大小，令 (mu(A)) 为二分图 (X\)--\((Y\cup Z)) 最大匹配大小。对整数 (K\ge2)，需求树 (D_K(A)) 的根需求为 (q)，每个 (x\in X) 需求 1，每个三元组点 (e=(x,y,z)) 需求 (K)，终端 (y,z) 需求 0，边为 (r\to x\to e\to y,z)。沿用桥梁评分
\[
b(H)=\min(\{1\}\cup\{\deg_H^+(v)/k_v:k_v>0\}),\qquad b^*(D)=\max_H b(H).
\]

当前正文给出的自足恒等式为
\[
b^*(D_K(A))=\max\left\{\min\left(\frac{\mu(A)}q,\frac1K\right),\min\left(\frac{\nu(A)}q,\frac2K\right)\right\},
\]
并约定 (q=0) 时两边为 0。下界分别来自 (X\)--\((Y\cup Z)) 最大匹配和最大三维匹配；上界按评分是否 (\le1/K) 分两支：低评分时每个三元组点取一个终端，单父约束给出二分图匹配；高评分时每个被选三元组点必须取两个终端，得到真正的三维匹配。

这一步是反面路线的精确障碍。完美三维匹配时 (mu=\nu=q)，所以 (b^*=2/K)。把 (K) 放大以压低 NO 值同时也压低 YES 值；固定 (K=2) 时，一终端逃逸仍让 (b^*\ge\min(\mu/q,1/2))。因此直接把三维匹配接入现有需求树桥梁，不能同时保持 YES 的 (b^*=1) 与任意小 NO。这是接口恒等式，不是一般调度 hardness，也没有关闭 `UM-TARGET-v1`。

同一正文给出共享终端族 (Q_{q,K})：根需求 (q)，(q) 个需求 1 的 (x_i)，每个 (x_i) 只连自己的需求 (K) 三元组点，三元组点共享同一组 (K) 个零需求资源。若选 (r) 个 (x_i)，Hall 碰撞给出
\[
b^*(Q_{q,K})=\max_{1\le r\le\min(q,K)}\min\left(\frac rq,\frac{\lfloor K/r\rfloor}{K}\right).
\]
固定 ((q,K)=(20,20),(40,40),(80,80)) 的精确值分别为 (1/5,3/20,1/10)。私有化三元组终端则回到 (b^*=1)。这是后续一致性 gadget 的目标形状，不是已经完成的编码。

规范脚本使用 Fraction 对 (q\le2) 的全部 (2^{q^3}) 边集和 (K=2..6) 穷举，对 (q=3) 做空图/满图及 600 个固定种子随机边集（(K\in\{2,3,4,7\})），并对 (q=1..4) 的完美匹配族核对 (2/K)。JSON 的 `PASS exhaustive_q<=2=256*5 and random_q3=602*4; perfect_floor_checked` 只证明审计执行成功；恒等式的一般性来自上述树结构论证。

## 三外接机器选择器：完整状态下锐 3/2 逃逸

三主机合同是：有限内部机器与三台不同外接机器 (a,b,c)，基础任务不随状态改变，每个任务至少一条有限边，处理时间为二进制非负有理数；开放外接机预载 0，关闭外接机有不可迁移预载 (T\ge0)，关闭机的原有限边仍可给基础任务。若开放集合 ({a}) 与 ({b,c}) 各有实际完整基础分配，含预载总 makespan 不超过 (T)，则开放 ({b}) 或 ({c}) 至少一侧有完整分配，makespan 不超过 (3T/2)。系数对 (T>0) 锐；(T=0)、空任务、零时间和单可用边均包含。

证明将两份调度拼成
\[
w_{uv}=\sum_{j:\sigma_1(j)=u,\;\sigma_2(j)=v}p_{uj},
\]
权取第一份源机时间；因第一份中 (b,c) 满预载，行和为 0。固定 (b,c) 的二色、其余节点从零翻一的阈值闭包保证每个点同色内行权至少为 (L_i/2)。令 (W) 是包含 (a) 的色类，输出任务在源/目的都在 (W) 时取第二份目的地，否则取第一份。(W) 内每台机器分成第二份进入子集（至多 (T)）和跨出行权（至多 (T/2)）；(W) 外保持第一份基础任务并加相应预载，逐台得到 (3T/2) 上界。该 proof 直接核全任务身份和预载，不把接口投影当完整调度。

锐例为两项任务 `a:T/2,b:T` 与 `a:T/2,c:T`。开放 (a) 时两项放 (a)，开放 (b,c) 时分别放到两台，均为 makespan (T)；只开放 (b) 或只开放 (c) 的最优值为 (3T/2)，所以系数不能改小。

JSON 报告精确 Fraction/整数、seed `202610171103`、7000 个随机 instances、1,391,178 个 full assignments、5,879 次 random bootstrap flips，最大随机 unit-scale makespan `3/2`；正式锐例的输入矩阵、开放机、负载 `[3/2,1,1]`、两坏 profile optimum `3/2` 和 4 个 eligible full assignments 均写入冻结对象。其包装还包含独立 Santa/actual-complement 段，但字段 `santa_sharp_section_checked=false`、`other_claims_checked=[]` 明确禁止把该段当作三主机程序代签 Santa 一般证明。

`independent_original_matrix_optimum_and_normative_test` 另做 45,760 个 exhaustive matrices、534,595 个完整分配、22,952 个双 YES 和 798 个精确锐例，并随机检查非标准 host 输入；其 scope 明确 normative helper 只是受测对象，OPT core 独立枚举原始分配。这些数字是有限回归证据，不代替三主机闭包证明。

## 与既有存档的关系、处置和缺口

1. **与 rooted-DAG bridge：** 三维匹配恒等式只说明某个需求树接口的 (b^*) 地板，并通过既有 `OPT=2-b^*` 桥梁传到相应调度实例；不新建调度算法，不扩展 bridge 的定义域。
2. **与私有资源复制/共享 Hall 障碍：** (Q_{q,K}) 是共享终端的 Hall 样板，指出真正缺少的是跨模块一致性测试；私有化会破坏 NO 侧碰撞。
3. **与三主机 selector review：** 本审查把 audit JSON 的计数、输入 SHA 和 Santa 段边界接到现有三主机自足证明；不把有限枚举替代全量词，也不把旧摘要当新来源。

**完整数学结论：** 需求树恒等式及三主机 (3/2) 闭包定理在各自明示合同内自足；三主机常数有精确锐例。

**有限实验：** q/K 网格、共享终端样板数值和三主机 JSON 的随机/穷举计数，适合重放和回归。

**障碍：** 仍缺将源问题的全局一致性编码进共享资源、同时保持 YES (b^*=1) 且低评分树可解码 NO 的 gadget；也缺状态相关资格、跨模块容量和未知 YES 见证的通用处理。不得从本批两源推出一般 UM hardness、一般近二算法或已完成的完整反面归约。
