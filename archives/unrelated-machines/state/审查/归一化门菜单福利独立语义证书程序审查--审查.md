## 2. 版本钉扎和旧/新重放关系

脚本把目标源码 SHA 固定为
`31aeb2b57bbf78e0f980f552bd5985e4f0a15b57f98f93f46be1296a19b156f6`，并读两个独立

文件 SHA 未变并重新核对源码 SHA。这是证据保全合同，不是数学最优性证明。

## 3. `semantic_dual` 的精确证书语义

脚本将每个 general case 的 `lp_certificate` 解码为有限菜单 LP 的 `(z,x)`：前 `S`
个 primal 坐标切成每组 state 权重，随后按正 incidence key 写入 `x`；`feasible` 逐项
检查每组 `sum(z)=1`、非负 state、每个正 incidence 的 `0<=x<=z`、资源容量
`sum(x)<=1` 和零 incidence 位置的 `x=0`。它没有把隐式 state、未列 job 或重复
state 悄悄删掉。

dual 被重新解释为链接价 `a`、资源价 `b` 和组价 `eta`：

\[
a_{gsu}\ge0,\qquad b_u\ge0,\qquad a_{gsu}+b_u\ge p_{gsu},
\]

且每个 state 满足 `eta_g >= sum_u a_gsu`。随后以原菜单和重建的 `x` 计算 primal
value，并要求它与 dual value `sum(b)+sum(eta)` 以及 certificate objective **精确相等**。
因此，对 JSON 中列出的 general certificates，脚本的审查强于“浮点 solver 返回成功”：
它同时检查约束、符号、逐式支配和目标等式。三条 coin fixtures 也用
`optimal_lp_certificate` 走同一语义 dual，并额外检查 supplied `(z,x)` 可行且值为 1。

边界必须保留：有理化、JSON certificate 和目标源码均是外部输入合同；脚本不实现一个
可对任意菜单自动找证书的 exact LP solver。它也不能由检查 dual 的非负性推出所有未列
输入都存在可接受分母的证书。

## 4. 独立 outcome expectation 与完整 jobs

脚本重新定义 `expected_max_sum`，按每个资源枚举组间 outcomes。state 未固定时使用
`z[g][s]`，state 固定后只保留对应 state；正 incidence 用 `x/z` coin，零 incidence
保留零值 outcome，且对 `coin=0`、`coin=1` 不做非法除零或空分支。资源贡献在所有组
outcome 上取最大值，组内 state 相关性通过同组的 outcome 分布保留，只有组间使用笛卡尔
积。之后将这个独立函数注入目标模块的 `round_welfare`，逐行核对输出 welfare、初始
期望（若存在）和完整调度 peak。

独立 peak 检查显式创建 root、gate、private、resource loads，并将所有原 jobs 计入
`job_count = 1 + 2*n + sum_s,m |state|`；未选 state 与零系数 incidence 仍进入 private
load。support rows 按固定阈值 `3/8` 取 H，其他 rows 按目标的 `balanced` 取 H，再将
`gate_schedule` 的 peak 与独立 loads 的最大值、JSON `peak` 三者精确相等。该结构核对
了门控回填依赖的“完整任务身份”，不能简化成只检查选中 bundle。

脚本计数器 `expect_calls` 与 rounds 输出可对应既有独立审计中的 904 次 expectation
和 113 个 rounding rows；本脚本本身只在其外部冻结 JSON/目标代码可用时产生这些数字，
此处不把静态阅读当作本地重放。

## 5. 十二例普通 UM 完整枚举与负控制

`independent_resource_opt` 对每个资源枚举 owner `-1,0,...,n-1`，对每组取最大 state
value，计算总福利和排序后的 `beta`；`independent_full_um_enumeration` 则为每个完整
job 枚举它的所有合法 machine choices，直接累加 loads 和取最小 peak，不调用目标文件
的 `build_gate`、搜索或 summary。随机输入流按固定 seed 20261018、support 36 行和
general 72 行推进后，再用 `brute_um_cases` 逐行要求 `beta_opt`、`um_opt=2-beta`
和资源 allocation 数与 JSON 相等，同时保存每例完整调度数。

负控制用两组、单 state、单资源、全 private 时间 1 的显式菜单；分别枚举 flat 与
gated，要求 `(flat, assignments, gated, assignments)=(2,4,3/2,64)`。这只证明该
控制输入的 flat/gated 差异，不能外推为门控始终改善，也不能把 gated 结论迁移回裸
Cartesian 模型。

两条大分母 fixture 只要求独立资源分配福利等于 1、`beta` 与 JSON 相等；注释以相同
归一化行给出上界理由。这是两条精确 witness 的复核，不是分母位长复杂度或一般 LP
上界证明。

## 7. 证据分级与接续

- **完整有限证书：** 对已列 certificate、outcome、loads 和小例调度，脚本写有精确
  Fraction/整数断言；
- **条件结论：** 只有在目标源码、JSON schema、菜单归一化和完整 jobs 前提保持不变时，
  才能采用这些行的结果；
- **有限实验：** 36/72/3/12 分层、113 rows、904 calls 和 10,600 schedules 是冻结
 运行范围，不是普遍量词；
- **障碍：** 生产 LP、任意输入分母成功、一般 solver 和 source hardness 仍未建立；
- **候选：** 负控制、大分母和 fractional-`z` 行可用于后续反例/舍入压力测试，但当前
 不能命名为一般原模型反例。

该来源不进入六人 SPE 目录覆盖主模型。后续 mapper 可将
“独立 semantic certificate → gated-menu finite audit → v2 Exact/Proof”作为证据链，
但不能把脚本的有限枚举升级为一般 unrelated-machines 算法或 hardness 结论。
