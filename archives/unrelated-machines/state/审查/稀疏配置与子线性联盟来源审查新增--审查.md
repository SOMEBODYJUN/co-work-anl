# 2. 稀疏深树：逐边证书的精确量词

## 2.1 对象和数值结论

稀疏源固定整数 `k>=3`，令

\[
 r=(k-1)/k,\quad s_0=\min\{s\ge1:kr^s\le1\},\quad M=(k-1)k^{s_0-2}.
\]
取 `H>=s_0` 且 `2^(H-2)>=M`，设 `gamma=2^(2-H)`、`T=1+1/k`。实例有两棵独立的完整 `k` 叉树、根桥任务、父端 `1/k`/子端 `1` 的树边、底层星任务、相邻终端间的路径阻塞任务以及共享机器 `z`。每项任务最多三台有限机器，处理时间为 `1/k,1,gamma`。

审查确认在该参数族内

\[
 \operatorname{OPT}=2-1/k,\qquad
 \operatorname{OPT}/T=2-3/(k+1).
\]

下界来自桥激活根后每个活跃核心至少下传两个孩子；底层活跃簇至少占用两个终端，而 `B<2` 时每终端不能接两个单位任务，于是阻塞任务被迫进入 `z`，其总负载达到 `gamma 2^{H-1}=2`。上界沿根到终端的一条路径下传，其他小任务留在父端，并把阻塞任务沿终端路径定向。

## 2.2 逐边配置点是“分别存在”

对 incoming 边际 `alpha`，核心配置取“全体小出边”的质量 `1-alpha` 与各个“incoming+一条小出边”的质量 `alpha/k`，出边边际按 `alpha\mapsto r alpha` 衰减。底簇星边际不超过 `1/k` 时，阻塞路径可逐终端以单项配置完成；超出时，审查采用将该簇的 `k-1` 个阻塞任务一次放入 `z` 的合同，最多 `M` 个任务，因而 `gamma M<=1`。树边、星边、阻塞边、桥边四种查询都能各自选取完整配置点，把指定有限边的边际固定为 1。

关键量词是：对每条有限边 `e`，存在一个配置点 `y^(e)` 满足 `x_e=1`；不同 `e` 可以用不同点。来源明确不要求这些点共享同一全局联合分布、共同基点或交叠 bag 的一致边际。因此“逐边条件配置可行”与“存在一个同时满足所有强制边的配置点”不能互换，也不能称作一般 SA/SDP 层级下界。

## 2.3 四机器 bag 合同的逃生口

稀疏审查还精确区分独立逐边证书与更强的 bag 合同。把桥、树边和底簇路径写成含 `z` 的 bag 后，bag 图是树，最大 bag 大小为 4、相邻 separator 最大为 3。若要求同一 bag-tree 上每个 bag 的完整配置元组联合分布，并要求相邻 bags 在整个交集元组上分布一致，则有限树胶合给出一个全局样本；每个任务的完整机器域包含在某个 bag 内，覆盖边际为 1 又迫使任务几乎处处恰选一次，于是得到真实 `T` 调度。

这个结论依赖整个 separator 联合分布一致；只匹配单机器边际不能应用胶合。它说明本稀疏族不是更强全局一致性合同的反例，也没有给出该合同在一般输入上的可计算 oracle 或复杂度结论。来源同时标明极小星预处理的限制：在 `k=3,H=5` 展开上端点星规则确实触发，但审查没有研究穷尽该预处理后的 gap，因而不能声称“预处理后仍保持近二”。

## 2.4 证据层级和错误捷径

独立程序在 `k=3,H=5` 完整展开实例上逐条核验有限边、bag tree、running-intersection 和配置点，并对 `k=3,...,40` 检查参数及坏簇计数；这些是有限证据，不能替代一般证明。审查特别拒绝一个错误的局部公式：仅把 `ceil(k a-1)` 个阻塞任务送入 `z` 不保证剩余路径可配置；`k=4,a=3/4` 已给出剩余端点容量不足的反例。有效证明采用“整个坏簇移入 `z`”，不能把错误捷径写入对象。

稀疏源还确认源稿在 `k>=3`、四机器 bag 量词和极小星 scope 上的修订。它没有认证全球新颖性、UM-TARGET-v1 算法、NP-hardness 或任何一般低于 2 的保证。

# 3. 任意 `r(M)=o(M)` 的子线性联盟投影

固定 `k` 的长链族把每条终端平行边替换为长度 `ell` 的两端路径；机器数为

\[
 M_{k,ell}=A_k+B_k\,ell
\]

其中 `A_k,B_k` 只依赖固定 `k`，机器图围长为 `2ell`。若 `r(s)/s\to0`，则先固定 `k` 后令 `ell\to\infty`，得到

\[
 r(M_{k,ell})/ell\to0,
\]

所以最终可取 `r(M_{k,ell})<2ell`。森林耦合于是适用于大小至多 `r(M)` 的每个机器集合，而长链族仍有 `OPT/T_{CC_{r(M)}}` 至少 `2-3/(k+1)`。先对任意 `epsilon>0` 取 `k` 使 `3/(k+1)<epsilon`，再取足够大的 `ell`，得到比值 `>2-epsilon`。

这一量词加强只以机器数 `M` 为参数；来源明确没有把它改写成总输入位长的子线性结论。路径端点编号会引入额外编码长度，`r` 也不需要可计算或单调。因而本结果不能直接作为统一位多项式困难性或一般算法不可能性。它与已有《长链联合投影与子线性联盟高围长双源审查》数学一致；本批新增的是对 review source 本身的 provenance、量词和“机器数而非位长”边界确认。

# 4. UM-TARGET 阶段方向审计的处置

方向审计把一般目标的承重义务写成同一全输入桥：从任意 `P,T` 提取可计算共同容量状态，输出所有机器的实际整数调度，统一不退化 `epsilon`，给出可靠的 `FAIL=>OPT>T` 语义，并控制总位复杂度。它确认多条路线（逐机探针、固定槽、给定矩/支撑、home/sink repair、局部 macro）各自有诊断价值，却没有一条同时覆盖四个义务。审计还保留两类具体边界：早期 threshold-cover 恢复和 C2 条件负载抵消曾发生语义错误；最新 heavy-light residual min-max 仍是 candidate obstruction，不能因为有限 Farkas 例直接移入 current。

本审查把该来源归为 `retained` 的路线/工作模式记录，独有内容写入本节：

- 主目标、一般反面和各受限合同保持独立身份，配置 gap、局部 3/2 或有限代码不自动升级为一般 UM 结论；
- 每条后续主线必须绑定一个承重义务，设置独立 blind red-team，强制记录位复杂度、oracle、输出合法性、失败语义；
- 连续两轮只增加样本、换参数或重复局部机制而未关闭义务时，应诚实 salvage 并换线；
- 当前未闭的共同容量、全机整数输出、sound FAIL 和总位多项式四项合同仍不可由本批稀疏/子线性结果替代。

这些是研究流程约束和状态证据，不是数学定理；第三阶段关系图应把它连到相应 current/障碍对象作为“路线审查/状态来源”边，而非逻辑依赖边。
