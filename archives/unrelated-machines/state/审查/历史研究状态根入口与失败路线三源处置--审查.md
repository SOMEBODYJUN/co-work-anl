# FAILED_ROUTES（`f69fabefcfb4e043c0a2`）

FAILED_ROUTES 是三源中数学信息最密集的文件，标题明确要求记录“尝试机制、具体失败步骤、反例或缺口、排除范围、仍成立的回收结果及重试条件”。它的 19 个顶层段落覆盖以下可复用失败边界：

1. **独立 source witness 与真实共同容量。** 随机完备源、部分 MinRep、几何整数表和 joint-choice 只提供源/选择接口；缺 compiler、全低负载实际 decoder 或共同容量，因此不能单凭 source NO/LP 证书否定一般 UM-TARGET。
2. **固定宏任务后重开 tiny。** 即便允许全部 tiny 重放、联合优化和真实负载，宏任务共同占位可以使 (2r/(r+1)) 趋二；回收条件是必须共同选择宏与微任务卸载，不能把 tiny 舍入误差当唯一障碍。
3. **条件矩运输。** 直接使用 \(RYR^\top\) 或固定后备会产生真实列超载；回收是重新耦合、对角修正和残余容量证明，而不是把矩反例当调度 gap。
4. **菜单、槽、CONFIG 与 repair。** 固定槽、单机配置、强相容矩、逐行均匀、固定势局部极小和循环修复各有精确失败族；失败只排明确合同，不能扩大到一般调度。
5. **共同选择和接收容量。** 逐机器价格、残余次模、占位基、多个 sink 和加权组出口要求保留任务身份/共同容量；固定 (K)、唯一 home 或给定 group 的正面算法不覆盖一般输入。
6. **源编译与一致性。** dual-rail、coordinate slice、affine line、private graft、resource repetition、复制和标签收费路线都可能出现实际 NO→YES、局部选择冲突或源状态无法物理保持；重试必须改变共同容量或真实身份合同，不能只增加有限局部样本。
7. **历史纠错。** 文件多次标记“逐批支持量”“辅助桥”“旧 OPEN”不能直接当当前真值；后续 source/正文、独立审查和版本 hash 必须按当前对象回读。

每条失败记录都同时写出回收内容，例如给定 \(\tau\) 的 pruning path、fixed-K occupation、weighted group joint slot、prefix atomic decoding、某些 tagged line 或 dual-rail 子类；这些回收结果仍保持明确输入和量词。该文件最有价值的不是“失败列表”本身，而是把“什么被排除、什么仍开放、下一次重试必须增加哪种共同信息”写成可接续义务。

与当前已清洗对象比较，FAILED_ROUTES 中许多名称已经在 `archives/unrelated-machines/state/审查` 和 `state/定理` 中各自拆分，且新版本可能已经纠正旧路线的范围。例如旧页面把“全部宏任务冻结”作为失败时点，后续 `shared_sink_joint_macro_assignment` 和 `weighted_group_joint_slot_rounding` 已建立更强给定结构的正面接口；这不删除旧失败，而是将其限定为原合同。故本源处置为 `retained` 历史失败索引，不把其摘要直接转成新障碍对象。
