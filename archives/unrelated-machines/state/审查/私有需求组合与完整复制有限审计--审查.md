# 1. 处置范围与对象身份

本审查实际读取冻结的 `private_graft_repetition_audit.json` 全部 JSON，并回读《私有需求组合与共享三维匹配复制的保真障碍》及其同目录的需求树桥梁、审查稿和有限脚本。来源有两个同路径版本：legacy-cleanup commit `68fad804ec5946cb296f77dc5b336308a66abf12` 与 main commit `aefc58eac3fc6eb5d7a47d087dd2c62b5aa9974c`。本次的对象是有限精确运行的可复现性与量词边界；现有正文已经承担一般恒等式和 parity 反例的证明，不能把本审查的枚举重新写成证明。

本批冻结结果同时报告两个身份：

* `UM-PRIVATE-GRAFT-NO-AMPLIFICATION-v1`：私有终端替换只产生 `max/min` 瓶颈；它是一般组合恒等式，有限运行只检查其实现域。
* `UM-RESOURCE-REPETITION-SOUNDNESS-NO-v1`：完整元素池把有分母的三维匹配解整数化；parity 实例和直接坐标张量给出真实的 NO 到 YES 反例。

因此本对象的真值等级是“有限精确审计已整合，支持已有一般障碍”，不是新的 hardness 定理，也不是一般 unrelated-machines 近似下界。

# 2. 规范运行：私有 graft、parity 与复制

规范记录使用 Python 3.12.14、`integers and fractions.Fraction; exact`，命令为

```text
python3 tests/audits/unrelated_machines/private_graft_and_resource_repetition.py
```

它枚举 153 个小 DAG（按拓扑标号的 1、2、3 点图）和 21,384 个私有 graft 情形。需求只取 0、1、2，零需求只允许在 sinks；每一对图先做不交重标，再扩展到最多 6 个顶点。这是一个明确的有限族，不能称作“全部有限 DAG”或对任意需求上界的穷尽。

规范 parity 输入的最大 3DM 匹配数为 1、完美目标为 2，根评分 `b*=1/2`。对应 token 实例有 11 台机器、13 个作业；完整 assignment 搜索调用计数为 514 与 14，实际最优值为

\[
  \operatorname{OPT}=3/2.
\]

来源给出的一个达到 `3/2` 的机器序列为
`[0,0,1,3,2,3,7,4,4,5,5,6,6]`，机器负载为
`[3/2,1,1,3/2,1,1,1,1,0,0,0]`。这是实际整数调度证据；`b*=1/2` 到 `OPT=2-b*` 的一般翻译由已有 token bridge 证明承担。

同一输入的完整 pool double-perfect witness 大小为 4。规范记录还核对直接 tensor powers：`t=2,...,10` 的匹配大小分别为

| 幂次 `t` | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 完美匹配大小 | 4 | 8 | 16 | 32 | 64 | 128 | 256 | 512 | 1024 |

这些运行显示给定 parity 输入的两种重复都通过，但不构成“所有重复 gadget 保留 NO”的命题；source `limitations` 明确排除一般身份、一般 hardness 以及其他重复操作。

# 3. 独立 graft gate：边界和真正的反例

独立脚本不导入仓库 oracle，使用 parent-choice exhaustive exact `Fraction`。它检查 815 个基图、4,500 个 terminal substitutions、2,000 个 private gate cases，需求集合为

\[
\{0,1,2,7,2^{60}\}.
\]

全部通过。这里有两个必须保留的机制性输出：

1. 两个 private modules 各自评分为 1 时，把它们的叶合并为一个共享叶会得到 `1/2`。这不是私有 graft 的恒等式失效，而是故意离开“接口私有、不跨模块共享”的前提；因此它是共享资源的反例，不应删掉或改写成 private 结果。
2. self-composition 的评分为 `1/2` 而不是 `1/4`。这直接审计了 `b*(G\circ H)=min{b*(G),b*(H)}` 的“不乘法”边界；有限脚本只覆盖列明的小图，恒等式本身由已有正文的根树投影/拼接证明覆盖。

独立 graft 运行的有限性包括：基图最多 3 点、终端替换最多 6 点、需求只在上述有限集合中取值。即便包含 `2^60`，也只是大整数边界探针，不是任意二进制需求的复杂度证明。

# 4. 独立完整池：分数到整数的审计

独立 pool 脚本枚举全部 256 个 `q=2` 的三维匹配支持，分别取 `r=1,2,3`，共 768 组。每组都通过 exact pool check。parity tensor-square witness 的四条源边为

\[
000,\quad 132,\quad 213,\quad 321,
\]

pool 中的边数为 32，tensor square witness 使用 16 条边。它与规范 parity 输出相互核对“分数 perfect matching 经完整克隆可以整数化”的实例层证据。

已有障碍正文给出一般等价：若每条源边的权重属于 `(1/r)\mathbb Z_{\ge0}` 且每个原元素的总权为 1，则给每次多重出现独立标号即可得到克隆池完美匹配；反向则把克隆匹配按源边计数投影。独立 768 组不是这条等价的证明，也没有扩展到任意 `q` 或二进制 `r` 的位多项式输出界。

# 5. 与已归档正文的比较

## 5.1 与《私有需求组合与共享三维匹配复制的保真障碍》

该正文已证明私有 graft 的精确 `min` 恒等式、异质终端公式、固定根门的排序公式，以及完整元素池的分数整数化和 parity/直接张量反例。本审查只增加冻结 JSON 中实际可复现的计数、机器/作业调度见证、`t=2..10` 运行表和独立 gate/pool 覆盖。为了避免重复证明，正文仍是数学对象的主落点；本文件是 `evidence/runs/...` 的独立审计落点。

## 5.2 与其他重复或 Kronecker 对象

完整机器任务克隆和完整矩阵 Kronecker 反例是不同对象：前者改变资格图的同型复制，后者保留机器/任务元组；本批只处理三维匹配元素池和需求 DAG 的 private graft。不能把本批的 `t` 次坐标张量匹配直接导入矩阵 Kronecker 的调度结论，也不能用同型任务复制替代完整池的多重边标号证明。

## 5.3 不应升级的陈述

以下结论没有被本批证明：

* 任意共享接口都可由一个有限 `min/max` 公式刻画；
* 任意重复操作都把一个 NO 实例保留为 NO，或任意固定重复次数都不产生新的见证；
* 一般 private graft/repetition 问题的 NP-hardness、ETH 下界或近 2 调度下界；
* 对任意 `q,r` 的显式复制都具有关于输入位长的多项式规模。

这些是开放缺口或其他对象，不能用 153/21,384/768 个有限样本填补。
