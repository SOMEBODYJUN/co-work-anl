# 读取范围和冻结身份

本审查逐项读取三份冻结 JSON、`tiny_work_stability_joint_rounding.py`、`tiny_work_stability_selection_audit.py`、当前正文 `tiny_work_stability_joint_rounding_and_selection_barrier.md` 及既有 joint-rounding review。稳定 ID 与文件 SHA 为：`c5b104ba8c219b40ab97`（`tiny_work_stability_exact_encoding_cli.json`，SHA `c33e0a40952498cf08f650f736c98f73ad1c6a1969b74452d91420f9052881b1`），`089d8fbb24416cf6875b`（`tiny_work_stability_joint_rounding_exact_encoding_audit.json`，SHA `17714bfbe3814a8359dff92e6ca85d2f24efdeba1c3a912703ca12c6f8b00c6f`），`d08a62346bce05ef8d63`（`tiny_work_stability_selection_audit.json`，SHA `dff07141158d51756b20ca5ddf7cd60d514a12d3701fd680231434413912efbf`）。legacy-cleanup/main 是同一路径的冻结绑定，不记作重复实验。

三源共同使用 `Fraction` 或清分母整数，且把“给定显式 CONFIG 证书的构造”“有限 exact 回归”“寻找稳定证书的复杂度障碍”分开。它们不提供一般 UM 近二算法，也不把有限 case 误写成 NP-hardness 证明。

## 1. Exact encoding CLI：5000 位分母的完整等式复现

`c5b...` 的命令是 `tiny_work_stability_joint_rounding.py --input scratch-generated-singleton.json`，输入配方为
(p_{00}=1/(10^{5000}+1))、(K=10^{5000})、(T=1)、(delta=0)、单 singleton weight 1。报告记录 `K_bits=16610`、负载分母十进制位数 5001、`full_exact_output_equality_verified=true`，并给出另一个 programmatic API 配方 `p00=1/10^5000,K=1` 在 cap 4300 重置后的 exact output equality。`alpha_denominator_constructed=false`，说明这次压力测试没有显式构造巨大的 (alpha_K) 分母；它验证的是输入解析、精确比较和输出一致性。

这条证据的独有用途是证明“极小工作量/大分母”不会迫使程序按数值大小迭代，也不会因为默认子进程环境改变 exact output。它没有运行任意大 CONFIG、没有验证通用 LP backend，也不能从一个 singleton 输入推广到所有证书。

## 2. Joint rounding audit：给定 CONFIG 构造器的边界

`089d...` 的 `kind` 明确为 `supplied_CONFIG_constructor_audit_only`。它有 7 个 success fixtures、15 个 rejected inputs、9 次 round-slot 调用，均以 Fraction 构造 exact certificate；`new_matching_or_LP_solver=false`、`alpha_denominator_constructed=false`。成功 fixture 覆盖：混合角色的原 job 列、tiny 数超过 (K) 且 big capacity 为零、全局零作业删除先于 big cardinality、空作业/零目标、二进制巨大 K 且无需 alpha 分母、K=2 大分母、有正 r 的 K=3 以及附加零目标/合法零权大列边界。每行均核对 tiny/big bound、actual load 和 exact alpha mode。

15 个拒绝样例覆盖原 job coverage 不为一、CONFIG forbidden edge、超载、负权、负处理时间、浮点输入、重复 job identity、行概率质量不为一、positive atom big count 超 K、零权非法配置、非法 delta、bool/zero K 等。这里的拒绝是输入合同检查，不是数学反例。

核心数学边界和当前正文一致：所有机器的 big/tiny 槽放入同一个二部匹配图，每个原任务只出现一次；原 CONFIG 证书提供 fractional matching，整数匹配负责跨机器角色一致性。对正权配置逐行使用 (alpha_K) 的 big 槽包络，tiny 槽用 ST 前一满槽，得
[
L_i\le \alpha_K(T-r_i)+s_i+b_i,
]
若 (s_i-r_i\le\omega T)，则 (L_i\le(\alpha_K+\omega+\delta)T)。这是假设“证书已给出”的条件桥；不含寻找 CONFIG、一般 LP 或未知稳定点。

## 3. Selection audit：四元组 parity 的 exact 障碍

`d08...` 的 scope 是 `four-tuple parity only; all complete assignments; exact Fraction arithmetic`。两例均有 (source_q=2,source_\mu=2,source_\nu=1)，分别为 (ell=2)（10 jobs、20 finite edges、1024 assignments）和 (ell=3)（14 jobs、28 finite edges、16384 assignments）。实际 OPT 分别为 (3/2) 和 (4/3)；makespan histograms、absolute second decoder 和 17/21 positive certificate columns 均写入 JSON。两例都 `certificate_accepts_omega_half=true`、`certificate_stability_max=1/2`，同一 certificate 拒绝 (omega=1/3)。

当前正文的解析量词更强：在给定 tiny work CONFIG 证书的选择族上，(omega<1/2) 的稳定证书存在性等价于 perfect3DM；因此若 (P\ne NP)，不能要求一个总的确定性多项式程序在所有 YES 输入上自动生成这种证书。该结论依赖完整 selector/root/leaf 构造和既有 perfect3DM 复杂度事实，不由两个有限 case 单独证明。正文另给同一矩阵的三值峰值：(
u=q) 时 1，(
u<q,mu=q) 时 (1+1/ell)，(mu<q) 时 (1+2/ell)。这是构造族的条件恒等式，不能直接扩展到未识别的任意原矩阵。
