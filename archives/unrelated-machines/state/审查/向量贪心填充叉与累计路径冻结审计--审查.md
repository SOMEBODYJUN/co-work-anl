## A. 真实最优矩上的投影向量贪心

### 对象与已证结论

对象 `UM-PROJECTED-VECTOR-GREEDY-UNBOUNDED-v1` 的输入是一个真实最优完整调度分布 μ、处理上界 (T)、任务固定顺序和由常数及全部边指示张成的有限维空间 (V)。对当前状态 ψ，把每个可用端的乘法指示压缩到 (V)，选择 “压缩后范数平方” 最大者并左乘更新。正文证明：对任意 (k\ge2)，存在三机、全部处理时间正且有限、每个支撑调度峰值 (T=OPT=1) 的有理实例，使一个固定任务顺序的所有选择严格，输出峰值大于 (k-1/2)。这是给定真实最优分布和固定顺序的统一有限近似比无界结论。

证明的关键不是抽象 PSD 效应，而是真实乘法压缩。对二分事件 (E)，若 (A=Pi M_E|_V)，则另一端为 (I-A)，评分差是
\[
 \|A\psi\|^2-\|(I-A)\psi\|^2
 =\langle\psi,(2A-I)\psi\rangle.
\]
严格正的评分差在复制同一指示后仍至少按 (4^{-r}) 保持正；一维支持子空间的特征值 1 极限再把状态净化到该事件指示。事件链中每一步同时要求下一事件的严格多数和正内积，连续性只用于证明某个**有限**复制次数存在；它没有被偷换成把极限当成实际任务。事件链使用完整正有理类别/控制位立方体，使所有最终任务指示生成的 (V) 与预先分析的 (V) 相同。

提升到三台全正机器时，重任务端时间 (a=1-Bd)、辅助任务端时间 (d=1/(2kN))，另加一件三机均为 1 的固定任务。每个支撑调度机 1 负载至多 1，机 2 负载至多 (1/(2k))，机 3 由固定任务给出下界 1；因此每个支撑原子确实是最优。第三机器在非固定任务上的算子为 0，不改变前两端严格赢家；末件固定任务严格选机 3。有限事件链的所有重任务和辅助任务都被规则送到机 1，得到
\[
 L_1=ka+Bd=k-(k-1)Bd>k-1/2.
\]

### 冻结运行与独立核验

`08c48c4d8d64c69cf6af` 的 JSON 记录双路 Fraction 运行。五机五任务、14 个真实最优单位原子的无辅助碰撞实例有 δ 维空间 12，默认顺序严格输出 `(1,2,3,4,2)`，负载 `(1,2,1,1,0)`，峰值 2；120 个任务顺序中 78 个全程严格，全部 120 个均被枚举，另有成功的重排顺序。这是精确有限碰撞证书，不能扩成所有顺序都失败或自适应调序不可能。三机正数提升实例有 12 个正原子、323 件任务、维数 5；两路独立投影都严格完成全部步骤，输出负载
\[
 (2579/966,0,1),
\]
且每个支撑原子峰值 1。最小归一化评分差以精确有理 hash 记录；边界自检覆盖空输入、零值、不可用边、大分母和错误输入拒绝。事件参数 (k=2,\ldots,64) 的 2016 个转移和 89376 个条件概率检查只验证显式公式范围。

审查确认的可回收正面边界是：若所有压缩算子两两交换，它们成为投影并保持 (V) 对指示乘法封闭，此时规则退化为真实交事件，任意顺序均保持 (T) 可行。故失败机制精确是非交换压缩更新遗忘过去共同支撑，而不是“真实矩不够”或“给定分布不存在”。本文没有给出从一般 (P) 计算 μ 的算法，也没有复杂度困难性或对 UM-TARGET-v1 的否定。

## B. 填充叉与最小成本槽初始化的审计

对象沿用 `UM-FORK-MINCOST-ROUND-REPAIR-NO-v1`。canonical 正文先给出循环菜单的完整局部优化器，再给三机分流合流核心和加 (N=8k) 个私有填充机的真实有理族：(T=OPT=1)，坏态 σ 的峰值 (C=2-1/k)，所有最小总处理成本槽匹配都诱导同一个机器分配；任何非平凡、每台机器至多一个迁出目的地且不增加 makespan 的重分配都不能达到 ≤(C)。其准确否定范围是“任意给定 assignment-LP 点 + 最小成本槽匹配 + 单目的地 makespan 非增修复”这一合同，不是全部槽算法、全部 LP 点或 UM-TARGET-v1。

`3e853e2f77d938aaf6cc` 的冻结审计覆盖 (k=2,\ldots,64) 共 63 个实例（17,010 个显式 job-to-slot 注入对）。每一实例均有 `OPT=1`、初始峰值 (2-1/k)、`initial_is_min_cost_support_slot_matching=true`、`initial_is_unique_min_cost_support_slot_assignment=true`、以及零个通过 one-destination makespan-nonincreasing repair 的非平凡输出。代表性 (k=2) 实例为 19 台机器/22 件任务：

- (a=3/4,	heta=1/2,t=7/12,\beta=1/6,F=5/2)；初始峰值 (3/2)，真实最优峰值 1；
- 16 台私有填充机各只接一个不可迁出的私有任务；任一填充机接收四个核心分数任务会超过 (C)，所以坏态的核心分流必要性不被 padding 绕开；
- fraction 点每台核心机负载 (7/8)，每台填充机负载 (29/32)，所有任务质量和为 1；槽注入覆盖全部任务；
- 这只是对正文显式族和算法合同的有限重放，不能声称每个 LST 实现都会选该槽匹配，也不能把非基本的分数点说成配置投影点。

与前一节的矩规则不同，这里障碍来自真实处理时间下的共同容量和分流/合流方向；它保留“需要让接收机适度升载”的开放义务。canonical 同时给出工作量守恒的相同机器派生边界：逐坐标负载非增而总工作量不变时每坐标必须相等，但该派生只排逐坐标非增，不排全局 makespan 下降的接收机升载。

## C. 累计 take/continue 编译的八五逃逸

对象 `UM-PARTIAL-SUM-TAKE-CONTINUE-FLAT-MENU-ACTUAL-ESCAPE-v1` 是一个固定、显式、不可拆资源的反例，不是通用 source-hardness 结果。三个 agent、两件不可拆 item，每个 agent 对每 item 值 (3/5)；每个 agent 有 r、m、l 三个 groups，共 take1、off/take2、off/accept 五个 states，公共资源 (u_1,u_2) 以及私有资源 (x_a,y_a,z_a)，全部未选状态的 incidence 仍保留。精确实际矩阵有 26 台机器、30 件任务、57 条有限资格。

固定局部路径的 partial value 是 (V=2/5)，而源的真实 (OPT_{SC}=0)（三人不可能同时得到不可拆的两个 item）。完整 actual 仍能达到峰值 (8/5)：三个 root 选择 take1、三个中段选择 take2、三个末段选择 accept，导出九个私有资源，其他未选 incidence 留在对应 private；三台 agent 的 private 负载为 (8/5,1,7/5,1,1)，公共资源机不超 1。任意完整实际调度若峰值小于 (8/5)，每个 root 的唯一 take1 端都不能把 (u_1) incidence 留在自己的 private（否则与 selector 叠成 (8/5)），于是三件 root incidence 必须一起进入同一个 (u_1) 资源机，负载达到 3，矛盾。因此该矩阵的实际最优值确为 (8/5)。

`a020d8a2dc3bb375fd57` 的 root full-matrix verification 只做两个**固定矩阵**的 audit-only 复核：

1. 26 台机器/30 件任务的 57 条有限资格，精确 witness 峰值 (8/5)，部分值 (2/5)；没有运行优化器，analytic lower bound 来自 canonical 证明。
2. 固定半权 SAT/UNSAT 实例（8 台机器、10 件任务、24 条有限资格）枚举全部 5,184 个完整分配，得到 exact optimum (3/2)，峰值直方图按十分之一单位记录；这只核一个显式 UNSAT 源，不承担“所有公式”的定理。

审查处理了一个来源标签纠正：原始 `Exact` 笔记含完整证明，不能冒称 statement-first 的盲审；最终正文把作者证明、statement-only 重建和 root 的 57 条资格/负载 Fraction 核对分开登记。故应保留有限证书与审查历史，但不能把一次枚举升级为一般编译不可能性。

# 交叉比较与接续

- 向量贪心的失败依赖非交换压缩和固定顺序；若改成真实条件化、交换压缩或重新耦合，当前证书不适用。
- 填充叉的失败依赖单目的地且 makespan 不增；允许多目的地的分流/合流或接收机升载，当前反例不排除。
- take/continue 的八五逃逸依赖明确的 additive partial credit 与共享不可拆资源；它不否定 selector-tree、其他 AND 耦合或不同实际矩阵。
- 三者都没有给出一般 UM 近似困难性、没有改写 `UM-TARGET-v1` 的开放状态，也没有把有限审计当成全称证明。后续若使用这些对象，必须分别保留真实矩阵、任务量词、可用端、部分值定义和“所有未选 jobs 仍执行”的合同。
