# 配置激活与有限覆盖增量审计

## 1. 范围和身份

本页整理五个 `unrelated_machines` 冻结运行输出。它们研究的是配置（configuration）覆盖、支撑删除后的激活方向和一个有限高girth cover fixture；没有一个源宣称解决一般不相关机器调度，也没有一个源把有限 `OPT` 数值升级为全体输入的 gap 定理。原 JSON 字节保存在 [source-manifest.json](../../tools/evidence/config-activation-cover/source-manifest.json) 和 `source/`，每个源以 `clean show` 全文读取。

这里需要区分三个量词：

* `configuration` 的阈值/延伸检查通常固定一个有限机器、任务和配置族；它可能穷举全部单机配置，但不一定穷举所有完整 schedule。
* `support activation` 只沿一个指定方向删除部分支撑，再比较端点的最优 completion；不同 pivot、重新开放被删支撑或全列秩并不由这一步自动得到。
* `finite cover` 用 128 个基调度及一个 q=6 提升检查 lift/cover 的精确数值；高girth词的数量和退化边界是有限回归，不能替代存在性、复杂度或一般 soundness 证明。

## 3. 紧凑配置探针：穷举边界不能扩大

`fad6...` 的 primary 和 independent 两段都只使用 `Fraction`，没有浮点容差。参数族写作 (N=2k^2, G=N-2k, T=1)。在 k=2，primary 的机器类型 V/G/R/E 查询数为 40/36/120/137，总 333 个 machine configurations 全部枚举，18450 个实际配置条目通过；independent 也写明所有 333 个配置及其 complete extensions 均验证。这个范围足以把 k=2 的 seed 作为可复查的精确局部证书。

k=3 与 k=4 的 primary 则明确写 `full_all_machine_configurations=False`，只检查全部非-z配置和声明的 z 情形；independent 在 k=3..128 只运行 127 个 scalar/representative 样本，expanded machine configurations 并不全部枚举。故这里可以接续“紧凑配置中共享逃逸的数值边界”这一研究对象，但不能写成所有 k 的 configuration LP 可行性，更不能声称已有 schedule enumeration 或近似算法。

源还记录三个 invalid configurations 被拒绝，最大 checked weight bits 随样本增长；这些是输入合法性和精确算术证据，不是新的反例。已有 [私有菜单树有界叶重数配置界](../定理/私有菜单树有界叶重数配置界--定理.md) 对注入状态给出的 (5/3) 结构上界仍需遵循其注入、菜单树和配置 LP 前提，本批不扩大到任意紧凑探针。

## 4. 支撑激活：两端 (5/4) 与中间 `OPT=1`

两个 activation 源完全共享四核心、七任务的有限 seed，原 assignments 穷举 128 个且 exact OPT=5/4。`9eb...` 在指定 support-deleting pivot 后构造 16 台/12 jobs 的 lift，14 个 optimal atoms 中的 CONFIG 路径参数为 1/4、1/2、3/4；lift 的 OPT=1，而 endpoint exact completion 又回到 5/4。`7b3...` 把同一指定方向的符号扩为 + 和 − 两侧，`maximum_steps_by_sign` 均为 1/2，五个 θ 样本和两端 positive/negative completion 均为 5/4；矩阵摘要给出 N=58、J=22、P=8、rank=30、nullity=28。

因此可保留一个明确的障碍机制：沿这个支持方向，单纯把半激活路径的 CONFIG 值当作 endpoint completion 的全局上界会失败；两种符号都不能靠该方向把 endpoint 的 5/4 降到 1。可写成条件结论：**指定 seed + 指定 pivot + 指定支持重开规则下**，两端 completion 保持 5/4。不可写成“所有 pivot 都失败”或“端点不存在 full column rank”。源的 scope 还明确把不同方向选择和 support reopening 留在开放范围。

## 5. 有限 cover 与高girth词

`f1b...` 以 128 个基调度给 base OPT=5/3，并在 q=6 cover 上得到实际 makespan 4/3；160 个 random true mixtures、3 个 boundary 和 7 个 invalid case 都用精确输入哈希复核。它的限制字段明确排除 universal proof、general configuration solver 和 polynomial-size hardness reduction。

`172bab...` 是独立实现，重新列出 4 台机器、7 jobs、128 assignments 与 OPT=5/3，并把 q=6 lift 物化为 24 台、42 jobs，检查全部 128 个 base schedule lifts。另有 570 个 high-girth partial-permutation words 和三个退化边界。两源共同支持“这个有限 base/cover fixture 的数值和 lift 关系确实成立”；它们不支持“所有高girth图都存在”“配置 gap 的一般下界”或复杂度结论。q=6 的 4/3 是被检查的可行 makespan，不能单独当作最优值；base 的 5/3 也只有在源给出的 assignments 枚举范围内承担 exact OPT。
