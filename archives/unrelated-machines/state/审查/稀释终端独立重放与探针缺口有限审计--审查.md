# 1. 对象、量词与重复关系

本批与《稀释逃逸、行度交易与共享终端局部审计》存在直接版本关系：主审查已登记 k=4,h=3 的 427 机/521 作业/4914 eligible edges、row-degree 四案例、root replay scope 和 k=2 frame。本批不重复计数同一族的核心数字，而是分别保留三项独有内容：

1. `0ef72...` 的 k=2/3/4 **所有强制边的独立 LST probe** 与 k=2 全 assignment；
2. `b714...` 的 imported generator 之外的 k=4 独立 GHMR/full matching 重算；

所有结论仅到源声明的 finite exact scope。没有 generic LP solver、一般 approximation algorithm、complexity hardness 或 full global (M_2) 证明。

# 2. k=2/3/4 稀释终端 probe-gap

## 2.2 该 probe 反驳的对象

来源 limits 明确：这些 finite checks 不证明 general family theorem；没有 approximation algorithm 或 hardness；反驳的是 **independent per-edge LST probes**，不是 conditioned configuration-LP probes。故可安全写出的结论是：在列明 k=2/3/4 展开中，逐边 probe 与 star matching 证书同时通过，但 k=3/4 的构造值高于 T；这说明把独立边 probe 当作全局调度上界会丢失联合配置条件。

这里必须保留一个负面边界：`config_columns=74`（k=3）或 4570（k=4）不等于一个已求解的 CONFIG LP；来源没有 generic LP solver。`analytic_optimum` 也是该显式族的解析字段，不代表所有输入的 OPT oracle。

这些字段的数学身份是“完整 k=4 展开上的独立重算”：它不调用 submitted numerical checker、GHMR certificate、optimizer 或 filter，而是重新计算数值断言。它支持逐边 probe 最大负载 (5/4)、独立 matching 规模和一个 7/4 schedule 值在该展开上重现。

## 3.2 覆盖不足与和主批的关系

来源 limits 明确：只有 k=4 expanded；general proof 另行审阅；instance/point generators imported；实际点覆盖所有 bottom groups at z 但不覆盖全部 finite edges；没有该大实例的 full integer assignment enumeration，也没有 global approximation result。因而它与主稀释审查的关系是 independent confirmation，不是第二个独立族；`old_actual_points=58,new_actual_points=44` 也不能误读成覆盖所有 4914 条边。

和《重型匹配凸化与逃逸残余审计》相比较，本源的新内容是 427/521 的大稀释展开和 4394/4914 的独立 full matching counts；重型匹配批的 171/265 path-only/global filter 仍是另一输入合同。两者都支持“局部 probe 通过不等于全局 configuration coupling”，但不合并 ratio 或 hardness。

# 4. k=2 shared-terminal local frame 的双重代码重放

`71c23a2f148f2186256e` 不是新数学族，而是 k=2 one-component/selector regime 的软件重放范围记录。它完整保留两个运行：

- canonical code replay 使用同一 code SHA 和同一 output SHA，`exit_code=0`、`author_output_byte_identical=true`。

因此软件层可保留的确切事实是：121 个 component assignments 被送入 50 维 local affine frame/one B first-pair CONFIG，精确 Fraction、无 seed；两个路径产生字节相同的输出。它不是 full global (M_2)/contexts enumeration，也不是 general-k software verification。

`root_actual_read` 明确写出：root 实际读过原始 Exact/Proof、独立重构/read-after、final canonical text 和 reviewer record；但 independent reviewer 没有读/运行代码。这个身份字段很重要：byte-identical replay 是复现证据，不应被写成 independent mathematical review。
