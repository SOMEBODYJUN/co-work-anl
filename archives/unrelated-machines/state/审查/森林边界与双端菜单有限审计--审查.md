# 森林边界与双端菜单有限审计

## 1. 研究对象和不能外推的量词

这组六份输出研究稀疏森林接口中的 `a,b` 两个有限端、根负载以及局部菜单/预算返回。它们都是精确有限审计，不是一个一般不相关机器调度算法。输出里的 `forest` 前提包括稀疏边界、至多两个有限端/任务或源文件指定的局部结构；不能把它默认为所有 R||Cmax 输入。

本批分成两层：one-boundary 的上下方向和交叉核对，two-boundary 的主审计和独立强契约复核。每个源以 `clean show` 全文读入，原 JSON 字节、哈希和冻结来源在 [source-manifest.json](../../tools/evidence/forest-boundary-20261030/source-manifest.json)。

## 2. one-boundary 三类证据

### 2.1 Crosscheck：同一森林不变量的有限分歧

`5a826...` 使用 seed 671244、Fraction/integer 精确算术，跑 600 个 cases：382 个 `exact_feasible`，`down_returned=387`，`up_returned=414`，有 27 个 `different_success_status`、20 个 `different_root_load`，以及 323 个 disconnected-support cases。这个输出的独有价值是把向下/向上 oracle 的返回差异显式记录出来；它没有把两种接口默认为等价，也没有给任一方向的全称正确性。后续建模必须保留 success status 与 root load 可能分歧。

### 2.2 Downward：深链和随机精确回归

`66ff...` 检查 300-vertex deep chain，最大内部负载 `101/100`，包含四类退化、6 个大分母案例、100 次 nested-composition trial 和 2,500 次随机试验。输出计数为 `exact=True, returned=True` 1,496；`exact=False, returned=True` 34；`exact=False, returned=False` 970。它因此只能证明给定实现/输入域内的有限一致性，不能用 34 个“非 exact 但 returned”样本为一般 oracle soundness 背书。

### 2.3 Upward：固定私有 sink 族的数值边界

`78f...` 明确写 `finite exact family runs; not a generic scheduler or proof`，η=1/10。classical baseline 的 k=2 案例为 (T=3/2)、root_b=1/2、最大负载3/2；k=3 为 (T=4/3)、root_b=5/3、最大负载5/3，因而第二个 classical row 中 `root_b_at_most_T=False`。private-sink-B-fixed 的四个参数都给 root_b=max_load=1，且 all-B-home-small-moved 为 2、3、4、5。这个族的 B restriction 是源明确给出的对称性条件，只在该族内有效，不能当成所有私有 sink 输入的算法。

## 3. two-boundary 主审计和独立实现

`9855...` 声明 `UM-FOREST-TWO-BOUNDARY-MENU-v1`，seed 16102026。500 个随机 cases 中 288 个 original feasible，201 个 empty-menu certificates，1,465 个 covered original schedules，612 个 zero-b original schedules；最大菜单项8、最大 geometric guesses55，深路径1001 edges、2 menu items、K=4004。30 个 shared-boundary gadgets 的原始参考值和输出值相同，均为 (93/200)。输入契约是 normalized sparse forests、每个 job 至多两个 finite endpoints、a,b distinct，不含隐式 external-isolation validator；claim_status 明确“Finite audit only”。

`ccb2...` 是独立强契约审计，输出 `all independent strong-contract checks passed`。它覆盖 458 个实例、2,595 budget queries、7,351 knapsack updates；541 actual menu witnesses、1,211 covered strong-domain schedules、589 zero-b references、422 instances with reference、35 empty menus、1 个 nonempty-without-reference；结构族为 path 81、separate-b-component 81、branch-private 216、parallel-bundle 64、explicit 16。深路径 1,500 edges，shared-b gadgets 12 个，reference/output 均为 (39/500)。它还拒绝 3 个 invalid inputs。

两源共同支持的是：在各自列明的稀疏森林、菜单合同、真实负载消息和 geometric b budgets 结构下，有限配置可以被精确返回，并可在 shared boundary 上复现相同数值。`ccb2` 的 `scope` 同时写出没有 exhaustive arbitrary forests、ordinary-job compression、core selection 或 error-free nesting；因此 independent 并不等于一般定理。

## 4. 数学接续与关系

* 和已有 [未归档配置证书批次与量词边界](未归档配置证书批次与量词边界--审查.md) 的关系是同一类有限 configuration/菜单证据的增量。这里新增的是森林 one-boundary 的上下 oracle 分歧、two-boundary 的菜单返回和 shared-b 精确值；不重复宣布前批 5/3、4/3 或峰值结论。
* 与 [私有菜单树有界叶重数配置界](../定理/私有菜单树有界叶重数配置界--定理.md) 的接口相近，但该定理需要状态注入、菜单树和配置 LP 前提。本批的 `scope` 没有证明 ordinary job compression 或 core selection，不能把森林审计直接嵌入该定理。
* 与一般调度目标的关系只有条件性的：若后续能证明一个具体算法输出满足本批 normalized sparse forest 契约，有限证据可以作为回归；当前没有这种全局编译证明，也没有把 oracle 结果称为近似比。

## 5. 处置

六源均已完整读取、原字节保全、与全仓配置/菜单对象比较。`5a826...` 保留 one-boundary 上下方向的 600-case 分歧；`66ff...` 保留 downward 深链/随机精确边界；`78f...` 保留固定 private-sink 族；`980...` 保留 one-boundary finite resource-augmentation 返回/拒绝；`9855...` 与 `ccb2...` 合并为 two-boundary 主审计和独立强契约复核。所有有限数量、输入契约、失败状态及未覆盖的普通森林/一般调度量词都写入正文，没有把有限运行升级为一般算法或定理。
