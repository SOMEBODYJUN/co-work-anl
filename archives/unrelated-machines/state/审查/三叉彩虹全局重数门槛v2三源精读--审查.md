# 1. 精确模型与量词

输入是显式完整 rooted ternary tree `T`：高度 `h≥1`，每个内部节点恰有三个 child，所有叶深度相同；叶有显式颜色函数 `χ`，颜色 ID 可以重复。候选是保留原 root、在每个 active internal 恰选两个原 child 的完整 full binary subtree，叶仍在深度 `h`；rainbow 要求这 `2^h` 个叶颜色两两不同。重数约束按**最终整棵输出树**的全部叶统计；只在选中见证里不重复、或把控制色称为别名，均不满足合同。

Exact 的两项结论是同一对象的 sharp threshold：

1. 若每个颜色在整个 `T` 中出现次数至多 2，则任意高度都有 binary rainbow 子树存在。
2. 即使每色全局出现次数至多 3，判定是否存在 binary rainbow 子树仍为 NP-complete。确定性 many-one 3SAT 归约输出高度 `O(log(s+2))`、显式树规模及颜色编码多项式于公式长度 `s`；原色和辅助色都须满足 ≤3。

重数 2 项是存在性（独立稿实际上给出自底向上构造，可记录每个内部节点所选的两个 child，因此在显式输入上能够 traceback）；Exact 本身没有声称一般生产算法。重数 3 项是受限树判定的复杂性结论，不能改写成 `P≠NP` 意义上的“无多项式算法”而省略 NP 成员性/归约边界。

# 2. 重数≤2 的存在性证明

独立稿的简单证明把每个颜色的两次叶出现分别放入桶 A、B（单次出现任选桶；桶可空）。每个桶内部叶色单射。对任意完整三叉树，原始叶分割的 `q` 值满足并集子可加性：若 `q(A∪B)>q(A)+q(B)`，在根的三个 child 中按两个子集的 `q` 阈值计数可找到同时超过两侧上界的 child，与 child 归纳矛盾；高度 1 直接是叶计数。因为根的三叉分支给 `q(L)=3`，故 `3≤q(A)+q(B)`，至少一个桶有 `q≥2`，其见证叶色自动 rainbow。root proof 采用同一分割逻辑并明确这是整棵树全局重数，不是局部窗口。

这个证明不依赖 SAT 构件、固定 palette 或 UM 转换。它保留空桶、重复叶色和任意 `h`，但不认证任何仓库外实现、复杂度工程或外审。

# 3. 重数≤3 的新低重数编译

旧 v1 使用的高重数 `Rigid`/全树单色 `Dead` 不能直接满足 ≤3 合同；独立稿与 root proof 都明确重做控制色。关键构件如下。

* `Fresh_H` 是高 `H` 的完整三叉树，每个叶用独有 fresh 色，因此每色出现 1 次，任意二叉 pruning 都 rainbow。
* `Dead_H`（仅 `H≥1`）在每个最底层 internal 的三个叶上使用一个该 parent 私有色，不同 parent 及不同构件不复用。每个 dead 色全局恰出现 3 次；任一满二叉见证在该末层 parent 选两叶，必同色，因而该 dead 子树没有 rainbow 见证。
* 独立稿的 `Must_H(g)` 递归为 `Must_{H-1}(g)`, `Fresh_{H-1}`, `Dead_{H-1}`；`H=1` 为 `(g,x,x)`。因 dead 不可选，任意 rainbow 见证必须含 `g`，且 `g` 只在一条分支出现一次。root proof 给出等价的 protected-palette `R_H(S)` 版本：palette 两部分各只用一次，dead 替代旧递归的重复 palette，指定颜色可保持单次出现。两种描述共同承担“共享 guard 不会因递归复制而超重”的要点。

对于 AND，将等高的 `T,U` 与一个 `Dead_H` 作为新 root 三个 child；dead 被排除，见证必须同时取 `T,U`，且两者颜色集不能相撞。高度不足时只用私有 fresh padding。

对于 OR，先等高，构造两份各含同一个新 guard `g` 的 protected palette，然后分别以 AND 接入 `T`、`U`；第三 child 是 fresh filler。两份 option 的见证各必须含 `g`，不能同时选；选择 filler 加其中一个 option 正好实现 OR。`g` 在最终树恰出现两次；每一份 palette 的其它颜色独立命名。root proof 的 `R_H(S)` 版本把 palette 颜色集保持为 `S`，独立稿的 `Must_H(g)` 版本强调只需强制 guard，不需要旧高重数固定 palette；两者都拒绝把子式编成共享 DAG 或在父层复制。

# 4. 3SAT 归约、规模与全局计数

每个 literal occurrence 使用独有原色 `c_{j,l}`，编入 `Must_1(c)`/受保护 `R_1` atom。变量的 false bundle 聚合其 occurrence colors，变量子式是两种 truth bundle 的 OR；每个 clause 子式是其三个 occurrence atoms 的 OR；变量与 clauses 由 balanced AND 汇总。短 clause 通过重复 literal 的**不同 occurrence ID** 补为三位；空 clause/空 CNF 用明确的高 1 常量 YES/NO 分支，不能靠未声明的伪变量遍历。

每个 `c_{j,l}` 恰在变量 false branch 和对应 clause literal branch 两个 atom 出现，因此全局次数恰 2；neutral atom 色出现 1 次。控制色逐类计数：`Fresh` 色 1 次，atom 私有色至多 2 次，OR guard 2 次，palette/filler 色至多 2 次，`Dead` 的底层色恰 3 次。所有构件、不同公式模块使用全局互不相交的 fresh namespace，因而不存在“控制色免费”或跨构件意外复用。故输出全树每色 ≤3。

Atom、AND、OR 和 padding 的高度递归为常数增量加 balanced 聚合：`h=O(log(s+2))`。构件均显式展开，树顶点数 `(3^{h+1}-1)/2` 为 `s` 的固定多项式；颜色 ID 用实际出现变量 dictionary 重编号，位长为 `O(log |T|)`，没有通过共享 DAG 隐藏指数树。给定 binary subtree 可多项式核验 root、深度、每 active 恰两 child 和叶色单射，因此受限判定在 NP；标准 3SAT 归约给 NP-hard，合为 NP-complete。

# 5. 继承的 unrelated-machines 转换及其边界

转换沿已有 v1 私有树实例：每个 internal node 是私有机器；每个叶颜色是一个 resource machine；root pin 有单端 unit job 时间 1；树边 job 在父端时间 `1/3`，在唯一 internal child 或叶颜色 resource 端时间 1，其他端 `∞`。binary rainbow 见证把选中的 edge jobs 下送，active internal load 为 `1+1/3=4/3`，每个外部 resource 至多一个 unit；因此 YES 实例有 `actualOPT≤4/3`。若完整调度的 makespan `<5/3`，每个带 incoming unit 的 active internal 必须至少下送两个 outgoing jobs，否则父端负载达到 `5/3`；resource 端不能接两个 unit，递归提取 binary rainbow。无 rainbow 时任意根叶路径给 `5/3`，故 NO 树 `actualOPT=5/3`。在重数≤3族中，每个颜色 resource 仅有至多 3 个 eligible leaf jobs。

这个转换只产生 `5/4` 比值锚点，并非 near-2 hardness：它没有 `∀δ` 的大 `k` 放大，也没有一般不相关并行机模型的 reduction、近二近似排除或实现认证。来源还没有软件运行、有限审计、外审或全球新颖性证书；“重数3下 NP-complete”只能保留为受限三叉树判定结论。
