# 深度二配额有限核验

## 1. 范围

本批三个源围绕深度二（root–center–leaf）配额构造和其精确计数身份。对象包括异质需求、断连中心、非零根标签、极大整数 demand、星形边界和 bottleneck 值。所有输出均使用整数或 `fractions.Fraction`，但每个源都明确声明 finite verification/conformance only；不能将它们写成一般 DAG、一般不相关机器或 UM-target 算法。

原始 JSON 和指纹见 [source-manifest.json](../../tools/evidence/depth-two-quota-20261030/source-manifest.json)。

## 2. 三源内容

`c934...` 主审计以 seed=916202610 穷举 1,803 个输入，另跑250个随机、4个 boundary，拒绝3个非法输入。它的主题是“两层异质需求半配额构造”，但 `limits` 明确 general proof separate、没有 general DAG/UM-target algorithm。它承担实现层输入域和边界样本，不承担全称构造。

`50ea...` 是独立 per-leaf destination enumeration，1,000 个 seeded random instances，(U\le4,W\le5)，root labels shuffled、missing root edges permitted，demands 包括 (1,2,3,5,2^{130}+33)。其中断连中心631、非零根标签758、131位 demand 464，证明程序没有悄悄把这些边界归约成零根或连通情形。canonical、manuscript 和 script SHA 都保存，限制是 finite implementation conformance only。

`b726...` 是 star/bottleneck 精确计数：129,554 个 star cases、3,926 个 nonzero-count equalities、4,006 个 bottleneck cases，其中6个显式边界加4,000个 seeded instances；另有6,728 个 ceiling identities。需求含 (2^{100}+267) 和 (2^{100}+269)，没有数值容差。源的语义字段明确“finite verification is not a proof”。

## 3. 数学用途和边界

这些输出最适合支撑三类后续工作：

* 验证深度二的叶归属、root label 与 demand 传递不会因断连/零边界而改变；
* 作为星形和 bottleneck 公式的有限回归，尤其是 ceiling identity 与 nonzero-count 分支；
* 为配置/菜单证明提供一个可复跑的输入契约，但不替代一般 configuration LP 或 schedule 解码。

它们不能单独支持：

* 任意深度或含环/DAG 的推广；
* 对所有不相关机器实例的近似比、复杂度或 hardness；
* 由有限 129,554/4,006 cases 直接推导一般定理。

与二度菜单联合取整审计的关系是共同处理 degree/depth 二的有限结构；区别在于本批的配额计数和 leaf destination semantics，不包含前批的 bonus-delete backend。与 Hall/联合流审计的关系同样只是精确整数回归，不能合并量词。

## 4. 处置

三源均已全文读取、原字节保全、与配置/菜单/Hall相关对象比较。主审计保留 exhaustive/random/boundary 与 invalid rejection；独立 conformance 保留断连、非零根和131位需求计数；star/bottleneck 保留大整数需求、nonzero equality 和 ceiling identity 计数。三者合并为本审查对象，有限实现身份和一般化缺口均显式保留。
