# 稀释逃逸、行度交易与共享终端局部审计

## 1. 阅读范围、对象身份和证据等级

本批四个 ID 属于 `unrelated_machines` 的冻结证据，而不是当前六人共同目录/SPE 模型。四份 JSON 均用 `clean show` 导出并逐字段读取；原始字节、来源双提交定位、SHA-256、字节数和 JSON 解析状态保存在 [source-manifest.json](../../tools/evidence/diluted-escape-row-20261030/source-manifest.json)。导出的副本为四个 `source/*.json` 文件。结果只对源文件实际给出的机器、作业、配置列、矩、条件事件和参数族负责。

本页将结论分成三层：

* **有限精确证书**：在固定的机器/作业/行变量或 Gram frame 上，Fraction/整数程序实际完成了声明的穷举、矩检查或精确分解。
* **条件性或局部障碍**：证据说明某个 probe、行度截断、或 k=2 终端 frame 的边界，但量词仍固定在源给出的对象，不能自动推广。
* **未成立的普遍命题**：没有一个源给出一般 CONFIG/\(M_2\) 求解器、任意输入近似算法、硬度归约、或把局部逃逸直接升级成一般反例。源内明确列出的 limits 在本页保留。

为避免重复计数，本批与既有《重型匹配凸化与逃逸残余审计》比较了 heavy matching 的 171 机/265 作业族、path-only/global filter 边界和同样的压缩比率；与《配置剥离与联合匹配有限审计》比较了配置、tensor 和 bundle-peeling 量词；与《C2前缀满载与单位多切片有限审计》比较了有限 Gram/PSD 的信息边界。稀释批新增的数值和对象身份单独保留，不把旧表格当作本批证据。

## 2. 稀释逃逸 probe gap：k=4 的实际展开

### 2.1 固定展开与精确检查

`9e1d0a27bbf1c7bef705` 的标题是“稀释终端与共享逃逸的全部边探针及GHMR有限审计”。算术为 Python `Fraction`，无随机种子；扩展脚本和 base/peer 脚本的 SHA 在源中逐项给出。固定展开参数为

\[
 k=4,\qquad h=3,\qquad N=12,
\]

并实际包含 427 台机器、521 个作业、4914 条 eligible edges 和 4571 个 configuration columns。源报告：

* 全部原始边的 LST probes：4562；
* 新增 escape 边的 LST probes：352；
* 每个 probe 的最大负载为 \(5/4\)，阈值字段 `T` 也是 \(5/4\)；
* 独立 GHMR 大边证书 4394 个，star matching 证书 4914 个；
* `only_mandatory_job=0`，因而该展开没有把单个“强制作业”当作逃逸来源；
* 构造调度值为 \(7/4\)；
* peer GHMR 运行 `accepted=true`、`rounds=1`、`deleted_edges=0`，LST 阶段耗时字段为 119.472 秒。

这些字段共同支持一个**有限 exact audit**：在这一个完整展开实例中，所有列出的边 probe、star matching 和 GHMR 运行都按源程序成功，且一个显式调度的 makespan 为 \(7/4\)，而 probe 阈值为 \(5/4\)。这不是“所有配置列共同来自一个联合分布”的证明。源把边 LST probes 记录为彼此分离的 certificates，也没有承诺它们能同时满足 heavy-cardinality 或 configuration coupling。

因此可以把该结果作为一个**局部逃逸/探针间隙障碍**：逐边的阈值证书与实际构造调度值之间存在 \(7/4\) 对 \(5/4\) 的有限差异。它只说明该 probe 组合在这个展开上不能直接充当全局调度上界；它没有说明某个一般算法必然达到 \(7/5\)，也没有给出真实 OPT 的统一 oracle。

### 2.2 压缩行 k=4..64 的含义

源的 `compressed_formula_checks` 有 61 行，从 \(k=4\) 延伸至 \(k=64\)。每行含 \(h\)、active-bottom lower bound、escape-load lower bound、`optimum`、`T` 和 ratio。若只读取标量行，可以看到稳定的公式模式

\[
 \mathrm{optimum}=\frac{2k-1}{k},\qquad
 T=\frac{k+1}{k},\qquad
 \frac{\mathrm{optimum}}{T}=\frac{2k-1}{k+1},
\]

但这些等式在源中是**压缩族的公式检查**，不是 61 个完整的 assignment/schedule 枚举。代表行如下：

| \(k\) | \(h\) | `optimum` | \(T\) | ratio |
|---:|---:|---:|---:|---:|
| 4 | 3 | \(7/4\) | \(5/4\) | \(7/5\) |
| 5 | 5 | \(9/5\) | \(6/5\) | \(3/2\) |
| 6 | 7 | \(11/6\) | \(7/6\) | \(11/7\) |
| 8 | 11 | \(15/8\) | \(9/8\) | \(5/3\) |
| 16 | 33 | \(31/16\) | \(17/16\) | \(31/17\) |
| 32 | 88 | \(63/32\) | \(33/32\) | \(21/11\) |
| 64 | 221 | \(127/64\) | \(65/64\) | \(127/65\) |

`active_bottom_lower_bound` 和 `escape_load_lower_bound` 随行号快速增大，且后者在源中常为前者的一半；这反映压缩族的组合规模，而不是一个已经物化的机器 schedule。源的 limits 明确写出：只有 k=4 被展开；k=4..64 不是调度枚举；一般 OPT lower bound 在别处证明；没有 full expanded assignment oracle；各边 LST probes 不是一个 joint distribution；不保证 probes 能耦合 heavy-cardinality/configuration constraints；没有 universal approximation algorithm、hardness theorem 或 novelty claim。

故本节的正式身份是“**k=4 有限展开证书 + k=4..64 压缩公式/下界检查**”。若后续要把 ratio 写成一般障碍，必须补出压缩族到实际 machine/job assignment 的统一解码、真实 OPT 的同一量词以及全局 configuration soundness。

## 3. 行度—CONFIG 交易的四个有限实例

### 3.1 逐源内容

`bdcc6e5238ea9f9aceb0` 报告四个显式 \((d,k)\) 情形。每个情形都声称 `matched=true`、合法 CONFIG 总质量为 1、纯 home marginal exactly equal，并逐项检查到 d 阶的所有 square-free row monomials。精确读到的字段为：

| \(d\) | \(k\) | \(L\) | \(M\) | \(Z\) | 行变量数 | 已检查 d 阶单项式 | 最大 CONFIG load | 最小 CONFIG mass | d+1 阶 natural-law witness |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 2 | 2 | 8 | 15385 | 3 | 4 | 11 | \(3/2\) | \(321/61540\) | \(1/123080\) |
| 3 | 3 | 18 | 175045 | 7 | 6 | 42 | \(5/3\) | \(162/245063\) | \(1/3150810\) |
| 4 | 4 | 32 | 983281 | 15 | 8 | 163 | \(7/4\) | \(128/983281\) | \(1/31464992\) |
| 4 | 7 | 98 | 28271601 | 64 | 14 | 1471 | \(10/7\) | \(252361/44329870368\) | \(1/2770616898\) |

四行共有 `Amax=1`（最后一行除外，\(Amax=20\)），并且合法 `CFG_same_witness` 均为字符串 `"0"`。这里 `natural_law_degree_d_plus_one_witness` 是一个正的 d+1 阶见证质量；它显示“行度 d 的检查”与下一阶自然法则之间存在源程序显式保留的余量，但不能直接解释为 CONFIG 失败概率、全局矩阵非正定或调度 gap。

因此四个结论都归为**finite author audit**：源自身 status 写明“not general-d proof or independent review”，scope 写明只审 row trade、没有 global \(M_2\) 或 affine-localizer enumeration。最大 CONFIG load（如 \(3/2,5/3,7/4,10/7\)）是给定四组参数和 CONFIG 对象的精确输出，不是任意 d 或 k 的上界。

### 3.2 root replay 的独有内容与边界

`532449e142ac8377157f` 不是另一个数学实例，而是同一四案例源的 replay-scope 记录。它完整读取独立 standalone source，并记录：

* `precision` 为 Fraction 和整数 common-denominator exact、无 seed；
* `exit_code=0`，stdout 为 `{"cases_passed": 4, ...}`；
* replay 输出 SHA 为 `416d764ad20172efde6e845efab8c33f176bd45f34ba50d29acb88dfb0bf9841`，与四案例 JSON 的字节 SHA 相同；
* `author_output_byte_identical=true`；
* source scope 仍只有四个显式 \((d,k)\) 对，单项式计数 11/42/163/1471，不含 global \(M_2\)、affine-load matrices 或 general-d implementation。

它的独有价值是**可复现边界和字节身份**：确认重放读的是新的 standalone source，且最终四案例输出没有被手工改写。它不是 independent mathematical review；`byte_identical` 只支持程序输出一致，不能替代对行法则、CONFIG 质量或高阶 witness 的新证明。两源合并后，正式数学处置仍以四案例 audit 的有限范围为准。

## 4. 共享终端 k=2 的 affine Gram/CONFIG frame

`bf7d9bf31e92ddfca410` 给出一个与上述行度对象相邻、但量词不同的终端 frame。它固定 \(k=2\)、\(L=8\)、\(M=7681\)，只处理一个 component 的 exact affine Gram/CONFIG frame。源实际枚举 121 个 weighted states，B 配置数为 10，frame dimension 为 50，并把完整的 50 个 LDL pivot 作为正 Fraction 列表保存；每个 pivot 均为正，`exact_LDL_replay=true`。canonical Gram JSON 的 SHA 为 `4ad7e5c7dd98316b7ea62897ccb9e07bf27e88a9a429c63a44770419ff7d985c`。

B 配置 class masses 被逐项列为

\[
 \frac1{15362},\quad \frac{959}{30724},\quad \frac1{30724},\quad
 \frac{479}{15362},\quad \frac{7201}{7681},
\]

并且 `B_config_first_and_pair_match=true`。指定条件的两个均值间隙为

\[
 \Delta_H=\frac14,\qquad \Delta_Q=\frac{33}{64}.
\]

因此在源给出的 k=2、一分量、50 维对象上，可以保留如下**有限精确结论**：枚举得到的加权状态形成一个具有 50 个正 LDL pivot 的 exact Gram/CONFIG frame；B 配置的类质量和两个 conditional mean gaps 与源列值一致。正 pivot 证明的是该有限 Gram 对象的正定/半正定证书，不是完整 unrelated-machines 的通用 \(M_2\) 证明。

源的 `scope` 明确限定为 author k=2 one-component exact affine Gram/CONFIG frame；`not_claimed` 明确排除 full expanded-input \(M_2\)/contexts enumeration 和 general-k software proof。故不能把这个 k=2 frame 与 C2 前缀多切片审计中 (m=3,4,5) 的有限 PSD 结果合并成跨模型定理，也不能从正 LDL pivot 反推所有 k 或所有 context 的 PSD。

## 5. 与已有 unrelated-machines 正文的关系

### 5.1 与重型匹配/逃逸残余审计

已有《重型匹配凸化与逃逸残余审计》记录了 171 台机器、265 个作业的 heavy matching escape 展开、path-only local survive/global reject，并记录同一对称族的 7/5、3/2、11/7、31/17、127/65 等压缩比率。本批稀释源的独有内容是更大的固定展开（427 机、521 作业、4914 eligible edges、4571 configuration columns）和全部原始/新增 escape edge probes（4562+352）；它还单独保留 peer GHMR accepted、删除边为零以及 only mandatory job=0。两批共享“有限 probe 不能自动成为全局 schedule/configuration 证书”的量词纪律，但机器族、列数和检查程序不同，不能把数字相加或称为同一实例的独立复核。

稀释源的 61 行压缩检查与既有重型源的压缩行模式相邻，均只能作为参数化公式/下界检查；两者都没有 full expanded assignment oracle。因此它们共同支持一个方法层障碍：local/path/edge probes 需要额外的联合耦合与真实调度解码，才能进入一般 CONFIG 或近似算法论证。

### 5.2 与配置剥离、C2/PSD 和其他有限证书

《配置剥离与联合匹配有限审计》已经把 bounded configuration、bundle peeling、tensor joint-capacity 和 C2 prefix parity 分开登记。本批行度四案例新增的是“有限 row monomial 到 d+1 阶见证”的精确参数表；root replay 新增的是输出字节身份；终端源新增的是单分量 k=2 的 50 维 affine frame。它们不能替代既有 bounded configuration 或 tensor source 的输入合同，也不能把不同对象的 `M_2`、localizer 和 CONFIG mass 直接拼接。

《C2前缀满载与单位多切片有限审计》中的 (m=2) PSD 失败和 (m=3,4,5) 有限正证书，研究的是 C2 prefix/unit multislice 的矩阵对象；本批 k=2 terminal frame 是另一份 one-component affine/CONFIG 对象。二者都说明“有限正 pivot 不等于一般 PSD 定理”，但没有共同的变量、条件事件或 assignment domain，不能迁移 ratio 或失败索引。

### 5.3 与当前六人 SPE 目标的隔离

这些来源都属于 unrelated-machines 的机器—作业—配置语义，不涉及有限单位客户、共同非空目录、六提供者完整有序历史、终局覆盖者均分或 half-coverage 目标。任何 `k`、`T`、配置质量或 Gram pivot 不能直接解释为六人纯 SPE 的覆盖人数。若后续建立跨档关系，必须另给 source-to-model 的定义域、量词和映射；本批没有这条迁移边。
