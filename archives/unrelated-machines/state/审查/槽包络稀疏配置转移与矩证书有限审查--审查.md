# 审查范围与对象边界

本稿完整读取五份冻结 JSON，并回读其 proof/review 路径、独立脚本和配置对象。它们跨三个层次：槽位包络和配置身份的有限等式；三选稀疏深树与星收缩后的有限转移；以及用 M1/M2 矩阵表达 token-label、弱 H2 和局部化 PSD 证书。前两类是调度配置对象，后两类是矩/证书对象。矩证书中的 PSD、秩和负三阶相关不能直接解释成整数调度或近似算法。所有未覆盖的共同基点、separator 一致性、全 schedule enumeration 和通用 solver 都在正文中显式保留。

## 1. 槽包络身份与有限配置证书

`slot_envelope_identity_audit.json` 的 scope 是八个 custom exact boundary cases 加两个 small certificates，明确不是 general proof 或 optimizer。它使用 Fraction 与整数 Bareiss。最能说明定义域的是 `hand_fractional_certificate`：任务权重 `p=(3/5,2/5,3/10)`，分数向量 `x=(1/2,1/2,1)`，capacity `9/10`；两个 slot 的最大负载是 `3/5` 与 `3/10`，prefix ceilings 为 `(1,1,2)`，floor-chain 有两个原子，负载 `7/10` 与 `9/10`，各 weight `1/2`，包络为 `9/10`，线性负载为 `4/5`。`empty_row`、零容量、大分母 `1/1000003` 也通过了同一分段链检查。

几何证书逐行比较 fixed-capacity sublevel convex hull 与 convex epigraph section；`passed=true` 只表示在这些输入上两个 construction 相容。`two_machine_global_certificate` 另给出两机器、小任务的 exact OPT、slot matching、ST assignment 与 independently recomputed ST loads；它是一个 global certificate fixture，不是任意机器数或任意 x 的构造器。该 JSON 的用途是固定 `ceil`/prefix formula、floor-chain atoms、slot maxima 和 epigraph 口径，防止把“配置包络”写成简单的平均 load。缺口是通用 optimizer、任意 eligibility、任意多机器联合选择和从分数 x 自动生成 integral assignment。

## 2. 三选稀疏深树：全边条件配置的双路核验

`sparse_conditioned_configuration_audit.json` 的 main 与 independent 程序都使用精确整数/Fraction；没有随机数和浮点 LP。主程序把 fully expanded 的 `k=3,H=5` 实例固定为 1,051 jobs、729 machines、324 minimal-star contractions，有限边 2,426，最大 sink query load `3/4`，并给出上界调度 makespan `5/3`。该实例的配置证书检查了所有 expanded finite edges，`max_configuration_load=4/3`，`max_projected_big_cardinality=1`。

主公式表从 `k=4..32` 给出 `gap=7/5,3/2,11/7,13/8,...,31/17` 等行，并记录 `integer_sink_lower=2`、`s0`、`H`、`M` 和极小的 `gamma`。独立程序扩展到 `k=3..40`，检查 38 个 parameter/depth rows，并重放 2,426 条 expanded edges；bag tree 有 565 bags、564 edges，最大 bag size 4、separator size 3，所有 edge-conditioned points 都通过域检查。两套程序共同验证的是显式稀疏树合同和深度递推的有限输出。

关键限制有四个：只有 `k=3,H=5` 完全展开，`k>=4` 只验压缩公式；每个 edge-conditioned point 单独检查，没有共同 base 或 joint separator consistency；endpoint terminal 触发 minimal-star contraction，preprocessing-plus-probing 不在 claim 内；有限运行没有把正文的一般证明替代为实验。因而“`integer_sink_lower=2`”是该构造族的条件下界，不是任意稀疏 unrelated-machines 输入的全局整数下界。

## 3. 星配置转移：收缩后的稀疏支持与互斥反例

`star_configuration_transfer_audit.json` 同时登记 `UM-STAR-CONFIG-TRANSFER-v1` 与 `UM-CONTRACTED-SPARSE-CONFIG-GAP-v1`。主实例 `k=3,H=5` 有 1,051 个原始作业、729 台机器、324 次 contraction，压缩后 727 个作业、405 台机器，all final finite edges 1,778，replacement edges 972，最大 support 1,480，最大实际 split 162；整数上界为 `5/3`，阈值 `4/3`。独立生成器得到相同 edge 数和 support，并检查 every final finite edge。

小例还核对 rational roundtrip、zero/empty、forced-machine priority 和 missing mutual exclusion。`missing_mutual_exclusion_counterexample` 显示：没有互斥条件时旧 configuration 可行且 exterior occupancy 为 `1/2`；加入 forcing chain 后新 configuration 不可行。`reverse_conditioned_counterexample` 则显示原始 edge 到 `u` 不可能，而 reduced edges 全部可被强制，说明逆向条件化不能只看 reduced support。它们是模型内的有限反例和实现保护条件，适合用来审查 contraction/transfer 程序，不能被写成通用 sparse CONFIG solver。

`all_final_finite_edges=1778` 与 `all_probe_certificates_verified=true` 是独立代码的有限证据；两套代码仍共享旧的 instance/certificate generator。JSON 明确没有 all-schedule enumeration、generic CONFIG solver、外部 review 或 novelty certification。

## 4. Token-label M1/M2：精确作者反例与调度边界

`token_label_hypergeometric_lift_audit.json` 的状态是“author exact counterexample and audit; not a scheduling integrality gap or independent review”。它取 10 个 `X` label 与一个 `Y`，纯 X 部分是均匀 4-subsets，带 Y 的部分以 `delta=1/100` 叠加 signed bad 4-subset law：pure-half weight `1/8`、two-from-each-half weight `-1/400`。输入 M2 矩阵维度 67、秩 55、exact PSD；labelled M1 维度 46、秩 38、exact PSD；`Schur_D` 的 ones/sign/within-half eigenvalues 是 `5271/100,105/2,5313/1600`，差矩阵为正。

作者构造的负方向多项式为

\[
Y\sum_w \operatorname{sign}(w)\bigl(x_{0,w}-x_{1,w}\bigr),
\]

其 square expectation 为 `-1/150`。因此，原始矩约束的 PSD 与 labelled M1 的 PSD 可以同时成立，却不能保证这个带标签的多项式平方非负。该反例精确检查了所有 degree≤4 aggregate-cardinality ideals（232 个），但来源自身说明它不是 scheduling integrality gap，也不是独立复核。应将其归类为候选/完整有限反例：它准确指出“无标签 M2 → 标签提升”的推理缺口；不能据此否定所有带额外局部化约束的 lift，也不能把负矩值解释成实际调度 makespan。

## 5. 弱 H2 配置矩缺口与混合张量证书

`weak_h2_configuration_moment_gap_audit.json` 对两个 generic complete M2 matrices 与一个 mixed fixture 做 exact checks。generic multislice 的 `(m,n)=(3,4)` 维度/秩为 `(67,16)`，degree≤3 one-hot tests 为 700、row identity tests 为 525；`(3,5)` 为 `(106,30)`，对应 1,880 与 1,128。mixed `k=2,b=2` fixture 有 9 台机器、10 个作业、32 条边，`T=4/3`，M1 rank 18，all shared CONFIG-edge marginals 32 条；same-resource pair 为 `1/54`，same-resource triple 为 `-1/162`。mixed full M2 没有数值检查，正性依赖“PSD components 的 tensor products 再取非负平均”的一般证明。

来源还核对选定 gap sequence 的公式行：`k=3` 的 `OPT=5/3,T=6/5,ratio=25/18`，`k=5` 为 `9/5,15/13,39/25`，`k=10` 为 `19/10,110/101,1919/1100`，`k=100` 为 `199/100,10100/10001,1990199/1010000`。这些 ratio checks 是公式代入的有限回归；它们不构成 SDP 全局可行性或调度整数性证明。

故可保留两层结论：generic complete M2 的局部 one-hot/row identity 测试通过；mixed fixture 的局部 M1、边 marginals、低阶负相关与一般 tensor-PSD 证明形成条件证书。必须注明 mixed full M2 未数值检查、所选 gap sequence 只覆盖 `k>=3,b=k^2` 的明确族，并且没有通用 H2 kernel、近似算法或任意稀疏实例结论。

## 三个失败接口的解析定位

以下复用现有充分正文，补清有限记录背后的对象和违例，不增加一般求解器或全局困难性结论。

### A. 星收缩：外部任务数量不能代替碰星配置的质量

CONFIG($T$) 点是每台机器在其合法任务子集上的非负行分布 $y_{iC}$，每行质量1、每个原任务的总覆盖1。设 $F$ 是机器 $v$ 的全部邻任务，满足
\[
\sum_{j\in F}p_{vj}>T,\qquad
\sum_{j\in F\setminus\{a\}}p_{vj}\le T\quad(a\in F).
\]
收缩删去 $v,F$，加入替代任务 $e$，其外端时间为 $p'_{ie}=\min_{j\in F}p_{ij}$，并保存实现此最小值的原任务身份。整数容量的替回论证与CONFIG点的正向转移是两个接口。后者的充分证书是
\[
Q_F(y)=\sum_{i\ne v}\sum_{C:C\cap F\ne\varnothing}y_{iC}\ge1,
\]
而外部任务数量
\[
q_F(y)=\sum_{i\ne v}\sum_C |C\cap F|y_{iC}
=|F|-\sum_C|C|y_{vC}\ge1
\]
本身不够。同一外列包含多件 $F$ 时，$q_F$ 重复计数而 $Q_F$ 只计该列一次；外列至多含一件 $F$ 的互斥前提才使二者相等。

精确反例取 $T=1$，两根 $u_1,u_2$、两叶 $v_1,v_2$。桥任务 $c$ 仅在两根用时1；对 $\ell=1,2$，任务 $a_\ell,b_\ell$ 仅在 $u_\ell$ 用时 $1/2$、在 $v_\ell$ 用时1。每根以各半质量取 $\{c\}$ 或 $\{a_\ell,b_\ell\}$，每叶以各半质量取 $\{a_\ell\}$ 或 $\{b_\ell\}$，给完整CONFIG(1)点。收缩 $v_1$ 的 $F=\{a_1,b_1\}$ 时，$q_F=1$ 而 $Q_F=1/2$。替代 $e$ 只能去 $u_1$，用时 $1/2$；覆盖 $e$ 迫使 $u_1$ 的所有列含它，桥便只能由 $u_2$ 覆盖。于是 $a_2,b_2$ 都必须由 $v_2$ 覆盖，违反该行容量1。这严格否定“仅凭 $q_F\ge1$ 即可正向保CONFIG”的接口，不否定整数收缩的可行性恢复，也不声称 $Q_F\ge1$ 是所有其他方法的必要条件。

若还要保持指定替代边 $e\to i$ 的质量1，抽取外部质量1时必须优先从指定机器 $i$ 取；逆向argmin/补集恢复只保CONFIG可行性，不保所有旧带标签probe。一般转移、原任务资格、支持拆分界和这两个独立边界，复用[极小星配置转移的真实依赖与全边核验](../资源/极小星配置转移的真实依赖与全边核验--资源.md)。

### B. 标签提升：负值属于二次多项式的平方，不是 $Y^2$

十个Boolean heads $X_i$ 满足 $\sum_iX_i=4$，再有Boolean $Y$。令 $\nu$ 是全部210个四子集上的均匀真分布；将heads分为各五个的两半，$\beta$ 在完全落于某一半的10个四集各赋权 $1/8$，在前后各二的100个四集各赋权 $-1/400$，其余为零。因此 $\beta$ 总权1但不是概率分布。对总次数至多四定义
\[
Lf(X)=E_\nu f(X),\qquad L(Yf(X))=\delta E_\beta f(X),\qquad
\delta=1/100,
\]
并按Boolean关系约简。此聚合共同 $M_2$ 的PSD由[双Schur正文](匿名标签四次非扩展的双Schur证据与冻结范围--审查.md)的两个解析分解保证，不依赖一行数值PSD报告。

恢复四个原任务标签，记 $x_{a,i}$ 为原标签 $a$ 占head $i$。不放回形式核给单标签边际 $X_i/4$，不同标签、不同heads的二阶项 $X_iX_j/12$，冲突项为零，且不改变context $Y$。前半令 $s_i=1$、后半 $s_i=-1$，取两个不同原标签 $0,1$，定义二次多项式
\[
Q=Y\sum_i s_i(x_{0,i}-x_{1,i}).
\]
因为每个四集有四个heads，$E_\beta\sum_iX_i=4$；纯半四集的符号和平方为16、二加二四集为0，所以
\[
E_\beta\left(\sum_i s_iX_i\right)^2=10\cdot\frac18\cdot16=20.
\]
同原任务one-hot及上述形式核遂给
\[
L'(Q^2)=\frac{2\delta}{4\cdot3}
\left(4E_\beta\sum_iX_i-
E_\beta\left(\sum_i s_iX_i\right)^2\right)
=\frac{2\delta}{12}(16-20)=-\frac1{150}.
\]
这里 $L(Y^2)=L(Y)=\delta=1/100>0$，形式提升也保持这个值。负数是 $L'(Q^2)$，它违反恢复后共同 $M_2$ 对所有二次多项式平方非负的要求；不能写成“$Y^2$ 负”。聚合 $M_2$ 与恢复后 $M_1$ 可以同时PSD，却不足以推出该形式提升的 $M_2$ PSD。

更强的“该给定点不存在任何保全聚合四阶矩的原身份扩展”有额外完整论证：在原任务Boolean/one-hot、每head完整行CONFIG及共同 $M_2$ 下，[原任务标签提升的一阶PSD与全语境容量块](../证明/原任务标签提升的一阶PSD与全语境容量块--证明.md)给整体head×affine-context必要矩阵
\[
K_{(i,\ell),(j,t)}
=4\mathbf1_{i=j}L(X_i z_\ell z_t)-L(X_iX_jz_\ell z_t)\succeq0.
\]
取各head的context方向 $s_iY$，其二次型却为 $\delta(16-20)=-1/25<0$。这拒绝此给定聚合点的保矩扩展；$K$ 只是必要条件，不是充分lift判据。相关13机6任务ordinary实例实际OPT为1，故这个负值不证明普通调度不可行、整数间隙或一般PSD系统失败。

### C. 多行真实容量：$G$ 的全量词延伸与 $G+1$ 的一个失败pin

这里采用紧凑原任务族，区别于弱H2的稀释星族。令 $k\ge2$、$N=2k^2$、$G=N-2k$，有 $N$ 个中心 $V_a$、$G$ 台全局机、每块 $k+1$ 台 $R_{a,\ell}$ 和共享机 $z$。每块原任务及全部资格为：

| 原任务 | 合法机器与处理时间 |
|---|---|
| $X_a$ 一件 | 自身 $V_a$ 或任一全局机，均为1 |
| $Z_{a,s}$ 共 $k$ 件 | 自身 $V_a$ 为 $1/k$，本块任一 $R$ 为1 |
| $Y_{a,s}$ 共 $k$ 件 | 本块任一 $R$ 为1，共享 $z$ 为 $1/k$ |

静态count cap在 $V,z$ 为 $k$，在全局机和 $R$ 为1。[多行真实容量资源](../资源/多行真实容量的原任务延伸与尖锐预算审计--资源.md)及[完整多行追加证明](全局行计数审查的原冻结范围与多行追加证明--审查.md)已有以下全量词构造：对每个机器集 $U$，若 $|U\cap V|\le G$，则对每个 $v\in U$、每个合法单机配置 $C\in\mathcal C_v(1)$，存在一份全部原任务的合法分配 $\sigma$，使 $\sigma^{-1}(v)=C$、$U$ 的每机真实负载不超过1、所有机器守上述count cap。每个 $(U,v,C)$ 可换一份 $\sigma$；它是实际多行同时容量见证，不是分别单行见证的拼接，也不是各pin共享的共同分布。

尖锐反例取 $G+1$ 个中心连同 $z$ 入 $U$，固定 $v=z,C=\varnothing$。若某个受保护中心接 $X_a$，为守真实负载1，它的全部 $k$ 件 $Z$ 必须外送。$z$ 空又迫本块 $k$ 件 $Y$ 留在本块 $R$；$2k>k+1$ 件单位任务不能装进 $k+1$ 个count-1槽，故受保护中心均不能接自身 $X$。原 $N$ 件 $X$ 因此只剩 $G$ 台全局机和 $N-(G+1)=2k-1$ 个未保护自身中心，共
\[
G+(2k-1)=N-1
\]
个可用位置，Hall缺口为1。未保护中心的count cap虽为 $k$，但它只具有自身一件 $X$ 的资格，不能增加这些 $X$ 的匹配容量。这个必要容量证明不是全调度搜索；它否定把上述全量词预算从 $G$ 提到 $G+1$，不声称超过预算的每个pin都失败。

### 三层对象不能互换

星转移的CONFIG是逐机器真实行分布；标签的共同 $M_2$ 是同一四阶functional的Gram正性；多行延伸则是每个查询各自的一份完整原任务分配。这里不使用PSD推出CONFIG或CONFIG推出共同PSD的规则，也不把独立查询见证当共同实际law。

[共享一阶配置与共同二阶容量的边界](../资源/共享一阶配置与共同二阶容量的边界--资源.md)精确区分另一稀释星族的弱、强H2：弱合同显式同时要求共同PSD/localizers与同一一阶点的完整CONFIG，二者只共享一阶。其 $(k,b)=(2,2)$ 小fixture同R的pair为 $1/54>0$，而singleton行CONFIG的pair为0；三阶单项式 $-1/162$ 本身不是一个平方负值。要求同行二阶也相等才会排该弱证书，并经零范数正交传出条件容量1，最终证明一般正文所述稀释族的强阈值恰为真实OPT。这个结论既不把CONFIG和PSD视为互推，也不把同族修复提升成一般强系统的算法或间隙定理。

## 对象关系、失败机制与接续

- 槽包络的 prefix/floor-chain 处理的是一个固定机器行的配置负载；稀疏深树与星转移处理的是多机器 contraction/transfer。前者的 epigraph section 不能直接替代后者的 separator consistency。
- token-label 反例说明 PSD 的无标签到标签提升缺失；弱 H2 的 mixed fixture 展示在额外 tensor/localizer 假设下可以得到局部证书。二者必须保持不同身份，不能用一个排除另一个。
- 三选稀疏树和星转移的 `5/3`、`4/3`、`integer_sink_lower=2` 是固定构造的条件数字；不能与经典 VW 基线的 `2-1/k` 端点拼成统一全局界。
- 五源均已实际读完并归类为 `integrated`：槽包络和 generic M2 是条件/有限证书；稀疏树、星转移和 mixed H2 是固定族证书；token-label 是精确有限反例。剩余缺口包括共同 separator/global base、通用 CONFIG solver、带标签的普遍 PSD lift、全 schedule enumeration 和外部新颖性/同行评审。
