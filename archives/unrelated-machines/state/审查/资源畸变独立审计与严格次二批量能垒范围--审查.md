# 资源畸变独立审计与严格次二批量能垒范围审查

本页处置两个不同数学对象。第一对象是完整 flat 菜单模型中的逐资源正权畸变桥；它把带 baseline 的菜单值转成 restricted Santa 实例，再依赖外部 Cheng–Mao 定理解码全部原任务。第二对象是一个固定三机状态图中的严格 `<2` 批量能垒；它只限制一种局部重配置合同。两者都保留有限审计，但有限运行、外部算法合同和一般复杂度结论分别记账。

证据包 [source-manifest.json](../../tools/evidence/resource-distortion-strict-sub2-20261030/source-manifest.json) 保存两份冻结 JSON 的源 SHA、canonical/review/程序路径、实际重放命令及输出。源 JSON 原字节复制在同一目录；`replay-results.json` 记录本次用可取得程序的退出码与输出。未把审计 JSON 中的 `PASS` 或源程序 SHA 当作普遍数学证明。

## 1. 逐资源正权畸变对象：域、量词和结论

### 1.1 完整输入域

有限组集 G 非空；每组 g 有非空显式 indexed states S_g。每个 state x=(g,s) 有独占 private 机器 M_x，每个资源 u 有独占资源机器 R_u，两类机器互异。组 g 有一件 selector，只能在本组的 M_x 上耗时 1。每个显式 incidence (x,u) 是独立原任务，只能在 M_x 上耗时 p_xu ≥ 0，或在 R_u 上耗时 1；没有隐藏任务、预载或其它资格，未选 state 的全部原任务仍存在。

每行总质量为 W_x = Σᵤ p_xu ≤ 1，baseline 为 b_x = 1 − W_x。允许零 incidence、零权项、重复 indexed states 和显式 unused/all-zero resources。对每个资源只用正权多重集 P_u = {p_xu : p_xu > 0} 定义

```text
κ = max( {1} ∪ { max(P_u) / min(P_u) : P_u 非空 } ).
```

零项不进入比值，因此不会制造 0/0；κ 只用于分析，不作为输入上界或循环计数。

### 1.2 baseline 值与实际 OPT 恒等式

对各组两两不交的资源集合 B_g，定义

```text
f_g(B_g) = max over x in S_g of ( b_x + sum over u in B_g ∩ S_x of p_xu ),
V = max over pairwise-disjoint B_g of min over g of f_g(B_g).
```

这是 W_x < 1 时的正确值。若把 b_x 丢掉，全零 state 会被错误地记为 0；本对象明确使用含 baseline 的 V。有限菜单和 b_x + W_x = 1 给 0 ≤ V ≤ 1。

给达到 V 的 B_g，每组取达到 f_g 的 state，将 selector 放到该 state private 机，并把该 state 在 B_g 中的 incidence 外送到资源机；其余原 incidence（包括未选 state、零 jobs 和不在 B_g 的边）保留 private。选中 private 机负载为

```text
1 + W_x − sum over u in B_g ∩ S_x of p_xu = 2 − f_g(B_g).
```

其它 private 至多 1、资源至多一个 unit job，于是 OPT ≤ 2 − V。反向只在峰 C < 2 时读取资源 unit 的独占性：每组 selector 所在 state 外送资源形成两两不交 B_g，同一负载恒等式给 f_g ≥ 2 − C。若 OPT = 2 而 V > 0，正向构造会产生峰小于 2 的调度，矛盾；全 private 调度又给峰至多 2。因此 OPT = 2 − V。在峰恰为 2 时不把两件 unit 误判成冲突，V = 0 与 OPT = 2 端点也由同一分层闭合。

### 1.3 restricted Santa 桥和实际解码

中间实例每个 state 一个 player；每个资源仅建一件 real item，固有值取该资源所有正权中的最小值 q_u，而不是按 incidence 克隆。每个 b_x > 0 建只对 x 有价值的 baseline item；每组建 |S_g| − 1 件只对本组 players 有价值、固有值 1 的 dummy。令 V_minus 为该 restricted additive Santa 实例的最优最小 player value，则

```text
V / κ ≤ V_minus ≤ V ≤ 1.
```

左向由 p_xu ≤ κ q_u 和带 baseline 的 B_g 见证得到；右向从任意 Santa allocation 为每组挑一个没有本组 dummy 的 player，保留其不交 real items，并用 b_x + sum q_u ≤ b_x + sum p_xu ≤ 1 回到原菜单。V = 0、b_x = 0 和 all-zero resource 不需额外正性假设。

对固定 α > 4，canonical 选择有理 a 满足 4 < a < α，接受 Cheng–Mao restricted Santa Theorem 1 的完整固定参数实际分配合同，得到 t ≥ V_minus / a ≥ V / (ακ)。这一步是外部已发表算法事实；本仓库没有实现或重证其 Build/Collapse、未知目标处理或配置过程。

从实际 Santa allocation 中每组挑一名没有本组 dummy 的 player，将 selector 放回对应 M_x，只把该 player 收到且有正价值的 real items 对应原 incidence 外送，其余全部原任务保留 private。real items 不交，资源机负载至多 1；即使 player 没收到自己的 baseline，也有 t ≤ b_x + sum(received q_u) ≤ b_x + sum(exported p_xu)，所以 selected private 负载至多 2 − t，其他 private 负载至多 1。输出是每个原任务的具体机器编号，未用辅助 item 替代原任务。由 OPT = 2 − V 得

```text
C_max ≤ 2 − (2 − OPT) / (ακ)
      ≤ (2 − 1 / (ακ)) OPT.
```

第二不等式来自 O = OPT ∈ [1,2]、c = 1/(ακ) 时，差值为 2(1 − c)(O − 1) ≥ 0。

若 κ ≤ κ_0 固定且源 YES/NO 承诺分别为 OPT ≤ 1 与 OPT ≥ 2 − ε，只在 ε < 1/(ακ_0) 时能选固定有理 separator θ，满足 2 − 1/(ακ_0) < θ < 2 − ε，并检查实际峰值。此筛选只针对完整 flat 像类的固定 κ promise；κ 随输入或精度增长、共同非单位容量、全低载 decoder 和一般 UM 的正反面仍开放。它不是 NP-hardness 证明，也不推出 P ≠ NP 以外的结论。

## 2. 资源审计的实际范围和可复现性

来源 `492e1dbd4a1c805110ae` 的冻结 JSON 报告 `all exact finite checks passed`，声明 1296 个二组/二 state/二 resource、p ∈ {0, 1/2, 1}、W ≤ 1 完整矩阵，加 5 个边界，共 1301 个输入；原完整调度 1,328,275 个，Santa allocation 20,798 个。对 α = 41/10 和 7，各有 10,770 个满足近似前提的 allocation 被逐原任务解码；两者最大观察比均为 3/2。记录的最大 κ = 2147483647/100003，原 optimum 取值为 1, 2, 3/2, 7/6。

我实际运行冻结程序 `resource_distortion_independent_audit.py`，退出码为 0，输出与 JSON 字段一致；程序 SHA 为 `63673ce192f84e11f8cb948d7e393cc88732aeaa1da49191de3abad66c4fb488`。程序使用 Fraction，枚举原 jobs 的完整机器选择和辅助 allocation，并在每个候选解码时重算所有机器负载。它没有实现 Cheng–Mao/DRZ 后端，没有覆盖全部有理矩阵、一般 unrelated-machines、NP-hardness 或 `UM-TARGET-v1` 否定。因此 1301 个输入的通过只核公式方向、dummy-free 读出和有限边界，不能升级为式中全称算法证明。

为比较历史同对象，我也运行了 canonical 所列的普通 `resource_distortion_flat_menu.py`：945 个 ordinary matrix cases、精确 Fraction、seed 210721、七个 κ 参数（包括 10^30），退出码 0。它同样明确未检查 restricted Santa 后端、全部 rational matrices、一般 UM 和复杂度困难性；这份 945 例记录与本批 1301 例不可相加为一般覆盖。

## 3. 严格次二批量能垒：精确构造

固定整数 k ≥ 2，令 α = 1 − 1/(8k) = (8k−1)/(8k)，T = 1。有三台机器 A、B、E。两个大任务 X_B、X_E 各可在 A 与对应叶 B/E 上处理，处理时间均为 α。每个叶 Q ∈ {B,E} 有 2k 个小任务：在 Q 上为 α/k，在 A 上为 α/(4k)。每台机器再有一个只可在本机运行、耗时 1 − α 的固定 padding。

坏态 σ₀ 把两个大任务放在 A，叶小任务留在各自叶，padding 留在原机；三台负载均 1 + α = 2 − 1/(8k) < 2。忽略 padding 的变量子实例中，每个大任务无论放在 A 或对应叶都贡献 α，所以任意调度峰至少 α；把大任务移到对应叶并把两叶全部小任务移到 A，三机变量负载均为 α。加回各机 padding 1 − α，完整实例 OPT = 1。

任何状态由四元组 (x,y,u,v) 表示，其中 x,y ∈ {0,1} 指示两大任务是否已移到对应叶，u,v ∈ {0,…,2k} 是两叶移到 A 的小任务数。负载为

```text
L_A = 1 + α − α(x+y) + α(u+v)/(4k)
L_B = 1 + α + αx − αu/k
L_E = 1 + α + αy − αv/k.
```

令 s = 1 − α = 1/(8k)。若没有移动大任务（x+y=0）却移动任一小任务，则 L_A ≥ 1 + α + α/(4k) > 2，因为 α/(4k) > s。若 x=1，保持 L_B < 2 必须 u ≥ k：u ≤ k−1 时 L_B ≥ 1 + α + α/k > 2；y,v 同理。因此从 σ₀ 出发，所有中间态严格 `<2`、每一步最多改变 k 件任务的状态图中，坏态没有出口；第一步安全出口恰需移动一个大任务和对应叶的 k 个小任务，共 k+1 件。移动 X_E 与其叶的 k 件小任务后，负载为 (1+α/4, 1+α, 1+α) < 2，说明界是尖锐的。

canonical 还给出参数化余量：对任意 ε ∈ (0,1) 与固定支持预算 r ≥ 1，取 k > max{r,1/(8ε)}，则坏态 2 − 1/(8k) > 2 − ε，而严格次二出口仍需 k+1 > r 件同步变化。它只说明任何保持严格 `<2` 且每步至多 r 件的局部合同在该族上不能降低初态；允许无界批量、穿越峰值 2、重新求解或全局证书的算法均未被排除。

## 4. 严格能垒审计的实际范围与身份问题

来源 `3a06bbe84ebc02b48102` 的冻结 JSON 为 schema 1，claim 为 `UM-STRICT-SUB2-BATCH-BARRIER-v1`，声明命令 `python3 tests/audits/unrelated_machines/strict_sub2_batch_barrier.py`，输出 `PASS k=2,3,7,100; OPT=1 witness; strict-sub-2 batch threshold k+1`，状态 `finite_audit_only`。它只明确列出 k=2,3,7,100，不能单独承载 canonical 对所有 k ≥ 2 的代数证明。

我实际读取了 strict canonical、strict review 和冻结程序。当前 inventory 两个来源提交中可取得的程序字节 SHA 为 `2d5729ecbee8d2f0e6002a547e868b88a5b4d28bb484fd279b827793c4b93124`，运行通过四个 k 并额外输出固定 ε 四例。可是冻结 JSON 自报的 `script_sha256` 是 `12a4261cf3d280fbd577a53752081d1ce080b902cca158089cd1a64a6b0bc90f`，与可取得字节不一致；程序路径和有限输出虽相容，但不能声称该 JSON 已按其自报 SHA 完成 byte-for-byte replay。证据包保留两者并标 `identity_match=false`。因此本条来源处置为“保留有限报告 + 身份缺口”，而非“冻结报告已完全复现”。当前可取得程序的两行输出和退出码 0 只支持该程序版本的有限回归。

这一区分不削弱 strict canonical 的解析证明：canonical/review 逐行给出了负载公式、OPT = 1 见证、首次出口 k+1 的计数和允许范围。它只限制证据层级：四个参数的运行不能取代对任意 k 的证明，报告 hash 不一致也不能被引用为软件供应链认证。

## 5. 与全仓对象的比较和接续

### 5.1 与资源畸变既有对象

已有[逐资源正权畸变与 κ 边界](../定理/逐资源正权畸变与κ边界--定理.md)承担全域定义、baseline 恒等式、V/κ ≤ V_minus ≤ V 和固定 κ 的 separator 推论；已有[逐资源正权畸变与固定κ边界审查](逐资源正权畸变与固定κ边界审查--审查.md)承担前序 statement-first、作者 read-after、外部 PDF 读取和实现措辞修补的历史顺序。本批 `492...` 的独有内容是另一套不导入 canonical 的 1301 输入独立重算及 20,798 个辅助 allocation 计数；它补充证据而不重命名为新的近似定理。

已有 945 例普通矩阵审计只保存较早程序的七个 κ 参数和 `passed` JSON。本批 1301 例包含 1296 个半整数完整矩阵、五个零/空/大分母边界，且明确记录两组 α 解码数、最大观察比与原 optimum 集合；两者的覆盖集合、脚本 hash 和量词不同，不能用一个替代另一个。

### 5.2 与路径重配置和周期菜单

[剪枝首步与固定批量环能垒](../定理/剪枝首步与固定批量环能垒--定理.md)处理的是给定源调度到给定目标调度的首步峰值 U = max(2T, C+T/2) 及环族锐界；它允许经过 2T 级别峰值，且其环机器数随支持规模增长。严格次二对象固定三机、固定 padding，要求每个中间态严格 `<2`，从坏态到安全出口的首个批量阈值是 k+1。前者是一般首步/指定目标的峰值预算，后者是局部状态图的严格次二隔离；不能互相替代，也不能把任一者升级为一般近似困难性。

[周期菜单修复与独立交叉核对](../审查/周期菜单修复与独立交叉核对--审查.md)只对合成弧权、cycle extractor 和有限 fanout/ring fixtures 做回归；它没有为真实 UM 输入生成本文严格能垒的状态图，也不证明全局优化器一定找到同步出口。因此周期修复通过计数不构成 strict barrier 的算法反例。

### 5.3 与资源度三路径和正规形

[完整菜单的资源度三路径归约](../定理/完整菜单的资源度三路径归约--定理.md)通过真实 helper 保持 C < 2 下的完整调度双向投影，并把资源跨组度压到 3；它保 OPT 但增加机器、任务和组。该归约与资源畸变桥的关系是表示层接续：资源度限制不会自动限制同一资源正 private 权的 κ，所以不能由 degree-three 直接推出固定 ε。严格次二构造也不是 helper 路径的实例化：其安全出口依靠大任务和叶小任务的费用比例，而非资源 unit 独占。

### 5.4 六人半覆盖主模型隔离

上述两个对象都在 unrelated-machines 研究档，均没有客户、提供者、共同目录或 SPE 量词；它们不能直接作为当前六人有限共同目录问题的证明、反例或覆盖下界。资源菜单的 V 是静态资源所有权值，strict barrier 的状态图是任务迁移合同；两者与“每份完整历史纯 SPE 覆盖至少达到六主题最大覆盖人数一半”保持独立身份。

## 6. 处置决定、开放缺口和后续使用

* `492e1dbd4a1c805110ae`：**integrated**。其有限独立审计 JSON、1301 输入计数、逐 allocation 回译、最大 κ、原 optimum 值和明确未实现范围已写入本页及证据包；它补充既有资源畸变定理与 945 例旧审计，不重复宣称一般算法。
* `3a06bbe84ebc02b48102`：**integrated-with-identity-caveat**。冻结 JSON 的四个 k 报告、canonical 的全 k 代数范围、当前程序的可取得重放和脚本 SHA 不一致均已保存；完成字段只描述有限报告和身份缺口，不把报告当 byte-for-byte 复现。

仍未解决的数学或实现问题包括：Cheng–Mao restricted-Santa 后端在仓库中的生产实现；全部有理矩阵和一般 unrelated-machines 的统一解码；κ 无界时是否存在真正困难性；共同非单位容量和全低载 decoder；严格次二 barrier 之外的全局算法、无界批量或允许中间峰值的合同。有限审计、canonical 外部算法合同和这些开放问题必须在第三阶段关系图中使用不同关系标签。

本页没有把严格能垒称为 NP-hardness，也没有把资源审计的 3/2 观察比称为近似下界；它们可作为“有限检查”“局部障碍”“外部来源/实现缺口”的证据，供后续对象和超边继续引用。
