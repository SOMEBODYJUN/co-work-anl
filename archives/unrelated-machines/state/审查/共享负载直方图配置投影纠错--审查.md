# 来源、纠错与读域

`cae063344e0649dbddd1`（SHA `0e6d72ed452d0548c1ffb91d3697064e2edfb1ae97ed086e9550a8eecd9267eb`）完整记录 shared-load histogram/configuration projection 的 Exact→作者 Proof→erratum/v2→canonical 最终 whitespace read-after。原件、manifest 在 `archives/unrelated-machines/tools/evidence/shared-load-histogram-20261031/`，receipt 草稿在 `cleanup/workspaces/Boss2/shared-load-histogram-receipts-20261031.json`。

旧 full Proof 曾把每层 aggregate 误写成 true common H，并有 j=0/编码长度措辞问题。后续 erratum 与专用 weak recursion proof 明确改为 previous weak `Hhat` 递推，反向分段 `1−x=0`，补齐 j0/K0/zero/无端/LP 约束和 downround sound FAIL。canonical clean版只修行尾空格，数学字节与读后记录保持一致；旧 full Proof 不因被部分读取而升级为全文 PASS。

# 1. 正确双向恒等

弱层逐行 selected/stay flow 分解给完整 CONFIG；给任意 CONFIG 逐前缀分段拆，aggregate 落回此前弱层，覆盖所有实际概率点。显式网络与跨机 job coverage 等式不假定 TU；数值 K 的伪多项式量词和 rational objective 位长另计。向下舍入只支持 `LP infeasible ⇒ OPT>T` 的可靠 NO，不把 LP 可行静默升级成 actual assignment finder。

j=0/K=0、zero/无 finite 端、反向分段、未选 state 和 downround 边界均需保留；这些是专用弱递推的数学前提。真正 common true hull 的生成/查询/解码不由环境维数或配置投影自动提供。

# 2. 有限校准与范围

四机六任务例把 CONFIG=3 与 actualOPT=4、true-H5/weak-Hhat5 分开；独立 reviewer 重新枚举 4/5/6 tasks 的 16/32/64 assignments，核对 cap3 计数和最终 OPT4。有限 calibration 只支持该例，不替代一般恒等式证明，也不认证旧作者程序的所有 115400 tests 或未读 JSON/code。

经典 CONFIG 趋二是独立既有依赖，只限制相对 T 合同，不产生主问题 hardness。当前对象没有 production LP backend、true-hull generator、actual scheduler、一般 near-two 算法或一般 UM hardness；外审与新颖性未认证。

# 3. 关系与处置

该对象应与 raw K2/SH3、shared global-certificate hull 和 optimal-hull barriers 分开：它提供弱配置投影的正确数学接口和纠错历史，不提供 common true-hull、shared integer ownership 或 source decoder。UM-TARGET-v1 仍开放。

处置为 `corrected-weak-projection-read`；后续引用必须使用专用 weak Hhat 递推、严格区分 LP infeasible sound FAIL 与 LP feasible actual assignment，并注明旧 full-proof 错误已由 erratum/v2 处理。
