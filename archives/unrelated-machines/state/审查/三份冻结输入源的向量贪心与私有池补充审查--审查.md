## 一、q=13 真实最优矩向量贪心输入

### 输入的精确结构

`polynomial_vector_greedy_q13.json` 的标题是“q13真实最优矩向量贪心反例”，参数为 `q=13`、`r=1`、`m=13`、`n=14`。`processing_times` 是 13 行、14 列的有理/整数矩阵；前 12 行（机器）对普通 job 0 至 12 的时间均为 1，对 anchor job 13 不可用；第 13 行只对 anchor job 13 可用且时间为 6，对普通 job 全部不可用。矩阵共有 157 个有限 entry，`infinity_marker` 为 JSON `null`。

因此，按普通 R||Cmax 解释，13 个普通 job 只能使用前 12 台机器，至少有一台普通机器承载两个单位 job；anchor job 独占第 13 台机器且负载 6。该输入的真实最优值由 anchor 下界承担，完整 q=13 源审计进一步确认所有 13^3=2,197 个多项式标签源状态都有真实 makespan 6。输入本身只规定矩阵和参数，不含贪心动作或证明。

### 与既有审计的比较

现有 `固定阶向量贪心与 q=13 线性缺口增量审计` 已读取同一输入路径，并与 `polynomial_vector_greedy_primary.json`、独立 JSON 和 source replay 比较。该审计的承重结果是：q=13 的全部 2,197 个 source states 被检查，固定顺序向量贪心的 makespan 为 13，而 anchor 给出的真实最优值为 6，所以该显式源族的精确比值为 (13/6)。独立实现另外检查 q=3/5/7 的完整 Gram 与三阶压缩效果，并检查 q=13 的全部 source states 与 377 个至多三 job 子集；它没有构造 q=13 的 full Gram inversion。

这些结果的量词是“给定该真实最优源和指定的固定阶、固定任务顺序的贪心”。输入不能单独推出 q/6 的一般公式，更不能推出所有 unrelated-machines 算法的 hardness。已有审计还保留 `OPT0` 只在明确的 `T=OPT=0` promise 下适用、一次空乘积导致浮点除法的修复记录，以及 q=11/r=2 只检查选定 job sets 的边界。有限源输入与高阶矩证明分开保存。

### 处置

该源处置为 **integrated**：完整矩阵原件保存在本批 evidence，q=13 的 (13/6) 结果、真实最优 anchor、源状态全量检查和高阶矩缺口由现有向量贪心审查承担。第三阶段可把它作为“来源/有限验证”节点连接到固定阶向量贪心对象；边不能写成一般调度下界。

## 二、私有组共同退出池的六个边界输入

### 输入 schema 与逐例阅读

`private_group_exit_pool_cases.json` 的 `layout` 固定为：

```text
H, macros, private, rates, T, eta, beta, rho, pool_times
```

完整文件含六个 case。每个 case 通过有理字符串给出宏任务矩阵、私有任务的 home/时间/池上限、速率向量、阈值和退出池时间；未给出的端点用 `null` 表示不可用。

| case | H | T | rho | 边界含义 |
|---:|---:|---|---|---|
| 0 | 2 | 1 | 9/8 | 两个 home、3 个宏、4 个私有任务；每个 home 各有两件私有工作，池端点交替出现 |
| 1 | 0 | 1 | 1 | 无 home、5 个仅宏输入；用于空私有组和纯宏路径 |
| 2 | 1 | 0 | 3 | 零阈值，宏时间与私有时间均为 0，`beta=0`，检验 T=0 分支 |
| 3 | 0 | 0 | 1 | 空 home、空宏、空私有的零目标输入 |
| 4 | 2 | (10^{-40}) | 9/8 | 极小正阈值和极小有理处理时间，检验大分母/缩放稳定性 |
| 5 | 2 | (10^{40}) | 9/8 | case 4 的互反尺度，宏/私有时间使用对应的超大整数分数 |

case 4 与 case 5 的分母/分子由完整十进制字符串给出，不能用浮点近似替代。case 0 的宏端点含 `3/4` 与 `1`，私有任务时间为 `1/2`，池时间含 `9/128` 和 `1/16`；这些值保留了 rho=9/8 时的共同退出倍率。case 2 的 `T=0` 不能套用正阈值分支。

### 与共同退出审计的比较

现有《私有组退出与高阶负相关有限审计》处置的是同一接口的规范和独立运行 JSON：规范审计在 (\eta=\beta=1/8,\rho\in\{1,9/8,3/2\}) 下共检查 906 个 case，其中 706 个满足 promise 且 706/706 成功；另有 594 个 nonrank、321 个 zero target 和 6 个 illegal contract。独立原调度审计在两组 rho 层分别检查 700 cases，`false_reject=0`，同时保留 `T_zero`、`H_empty` 和 `OPT_zero`。

本六例输入是边界 fixture，文件本身不含运行结果。它的独有内容是：空 home、空目标、零阈值、零时间宏、极小/极大有理缩放和 home/pool 资格端点的具体排列。规范/独立 audit 承担 promise 内的精确成功与无误拒；它们没有给出所有 pool class 参数的 kernel theorem、一般结构提取器或普适近似比。

### 失败机制和开放量词

- `H=0` 与 `T=0` 是输入域边界，不能被当成算法失败或推广到正目标。
- `null` 端点是不可用机器，不是零处理时间；把二者合并会改变合法 pool。
- case 4/5 的大分母只证明 Fraction 表示可读，不能证明浮点实现的数值稳定性。
- promise 外的 nonrank/illegal contracts 不能由成功样本删除；它们是共同退出合同的适用范围。
- 规范审计的单 sink exit control 只约束该 API，不能自动升级为多 sink 的联合退出定理。

## 三、private sink k=2、r=4 输入

### 输入的精确模型

`private_sink_k2_r4.json` 声明 `schema=1`、`model=UM-MODEL-v1`、`k=2`、`r=4`。机器为四个 home `H0..H3` 和四个 sink `Z0..Z3`，共 8 台；任务为 1 个宏任务 `B` 和 8 个私有任务 `J(h,i)`（每个 home 两件），共 9 件。

处理矩阵的非空值为：

- `B` 在每个 home 上时间 1，在 sinks 上不可用；
- `J(h,i)` 在其 home `Hh` 上时间 (1/2)，在对应 sink `Zh` 上时间 (1/2)；
- 其它 home/sink 端点均不可用（`unavailable=null` 表示 JSON 采用 `null` 记录不可用，而非将它们视为零时间）。

因此每个 home 的两件私有任务可同时放在 home 或对应 sink；宏任务必须选择一个 home。输入具有 home/sink 对称性，适合检验 private sink 的 pairwise negative-correlation 与共同宏占位。

### 与既有有限证书的比较

现有 `clean-batch-config-certificates/8fd1a510a1c5956a66f3.raw` 对该输入路径保存了四个权重各为 (1/4) 的 `optimal_schedules`，并给出 `optimum=1` 及下界“B 在每个 eligible machine 上需占一个单位时间”。同一有限证书列出 52 个 pairwise-NC assignment，每个权重为 `1/64` 或 `1/16`，总权重为 1；按原矩阵逐 assignment 计算 makespan，直方图是

[
  \Pr[C_{\max}=3/2]=3/4,\qquad
  \Pr[C_{\max}=1]=1/4,
]

故精确期望为 (11/8)。本轮重新按输入矩阵和 52 条 assignment 计算了该直方图，未把证书中的 expectation 字段当成先验事实。

这些有限结果只说明该给定输入上存在四个对称最优调度及一个 pairwise-NC 组合，不能推出任意 `k,r` 的负相关核、统一期望界或一般 sink 选择算法。现有 higher-order NC 审查进一步说明 pairwise 约束和高阶 law 不是同一个对象；第三阶段引用时应将本输入连接到 private sink finite certificate，而不是任意汇点价格覆盖或 C2 多切片。

### 处置

该源处置为 **integrated**：原始 8×9 矩阵、机器/任务语义和不可用端点单独保全；四个 optimal schedules、52 个 pairwise-NC assignment、`OPT=1` 与 (11/8) 由既有 raw 证书承担并经过本轮复核。它是有限证据，不是一般定理或调度 hardness 反例。
