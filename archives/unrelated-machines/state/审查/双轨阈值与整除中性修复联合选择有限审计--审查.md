# 1. 阅读范围、模型分离和证据等级

本批完整读取三个 `clean show` 冻结 JSON，保全原始字节、来源 ID 与 manifest。三源都使用整数、`Fraction` 或半单位精确算术；它们研究的对象相邻，却分别是合并双轨、拆分容量双轨、半单位 3DM 联合选择和整除批次修复。不能把它们合并为一个“任意 unrelated-machines 输入都有 3/2 界”或一个一般 NP-hardness 证明。

- 双轨源包含四份 contract：归一化双轨、split-capacity 双轨、one-exception floor、full-cube cut。它给出共享容量分数证书和整数流/割的有限实现检查；四个模型的机器和端点语义不同。
- 整除源检查两类 batch-neutral repair：原始 (Q=m) 与修正 (Q=m^2) 的 exact integer tick 过程，并有独立实现的参数/宏步抽样。
- 半单位源是固定 (T=1)、边时间 (1/2) 与 (1) 的 per-x-source/two-incidence 3DM reduction 审计，含 q=0、q=1、q=2 完整族和 q=3 受限族。

程序输出的 `passed` 只证明冻结运行按自身断言完成；一般命题的真实性仍依赖来源中明示的证明合同。以下逐项保留定义域、量词、实际计数、sharp 见证和缺口。

# 2. 双轨阈值：四个 contract 必须分开

## 2.1 归一化双轨与三又二分之一上界

来源声明四项 claim：`UM-NORMALIZED-DUAL-RAIL-UNIVERSAL-THREE-HALVES-v1`、`UM-SPLIT-CAPACITY-DUAL-RAIL-THREE-HALVES-v1`、`UM-DUAL-RAIL-ONE-EXCEPTION-FLOOR-v1` 和 `UM-DUAL-RAIL-FULLCUBE-EXACT-FAILURE-v1`。它的规范证明路线是：先给共享容量的分数证书，再用整数流或半单位 Hall 构造恢复整数分配；归一化标量路线另行扣除经典 ST 半质量舍入项。程序本身只检查实现，未提供任意双轨 gadget 的统一 reduction。

`boss11_normalized_dual_rail_actual.json` 的精确运行计数为：748 个 exhaustive actual optima、12,565 个 template constructions、2,000 个随机不平衡异质 clause constructions、68,288 个 test-only exact assignment states、12 个非法域拒绝和 5 个空/零度/A1/大整数边界。精度是 integer maxflow 加 Fraction actual loads，seed=110723，运行 1.719 秒。

重复出现允许的 sharp witness 有 10 台机器、15 个 jobs、32,768 个 assignment states，构造实际最优 (3/2)。来源明确标为“允许 repeated occurrences；不声称 distinct-variable-clause sharpness”。因此 (3/2) 是该归一化模板中有完整整数调度和下界的 sharp instance；它没有扩展到任意 UM 输入。

## 2.2 split-capacity 模型

`boss11_split_capacity_dual_rail_actual.json` 使用 integer shared maxflow 和原始边 Fraction loads；计数为 18,479 个 split-template constructions、2,000 个随机 split constructions、32,768 个 sharp inside/outside modes、8 个 selector capacity patterns、8 个非法域拒绝，`physical_assignments_enumerated=0`。sharp repeated-occurrence 实例为 14 台机器、15 个 jobs，actual upper 与 exact optimum 都为 (3/2)。

这里的 (2^{15}) modes 不是物理调度空间 (2^3cdot3^{12})；因此程序没有完成原始作业的全 assignment enumeration。lower certificate 只对该 split-unit-machine 输入和列明的 selector-capacity cuts 有效。

## 2.3 full-cube cuts 与 one-exception floor

`boss11_dual_rail_cube_cut_actual.json` 检查 A1--A5 deletion-network cuts 和所有物理 load breakpoints：10 个 actual certificates、6,342 个 cuts、352 个 breakpoints、11,592 个原始 jobs/eligibilities/loads、680 个 source-no-assignment checks；它明确“不做原始作业 assignment 全枚举”。这是有限 cuts 证据，不是完整调度算法。

`boss11_dual_rail_one_exception_actual.json` 是 statement-first scratch：seed=202610171745，2,000 个随机 cases、3,920 个 binary-capacity unit augmentations、2,079 个独立 full-matrix optimum cases、597,223 个 full assignments，测试 arity `2A-1` 与更强的 `2A`，采用 Fraction/清分母整数 oracle。它保存三个 certificates（two-clause one-variable、empty rail、empty gadget idle dummy），但 scope 明确没有 source satisfiability assumption。故 one-exception 结论必须按该假设层级引用。

## 2.4 half-slot 独立 sharp 与大整数边界

归一化 half-slot 独立运行给出 32,768 个 assignments 的 (OPT=3/2) sharp 见证，全部 makespan histogram 只有 2 与 (3/2) 两档；另有 250 个随机 trials。它同时含空变量/空 clause、混合 (K_0/K_1) 和 258-bit `giant_A` 的边界，proof contract 是“独立 half-slot Hall construction；无 source assignment input”。大整数只是处理时间和边界压力测试，不把位长结论升级成复杂度结论。

### 双轨总边界

来源总限制明确：一般三又二分之一证明在 canonical account 中，有限测试只检查实现；split modes 与 cube cuts 不是物理 assignment enumeration；标量三又二分之一显式依赖经典 ST 半质量舍入；四个模型不能互换；没有外部复核、novelty certificate、一般 UM target 或负面 completion。本文保留这些限制，不将 (3/2) 写成普遍近似比或 hardness。

# 3. 整除两尺寸中性修复

## 3.1 exact integer tick 主审计

`divisible_two_size_neutral_repair_audit.json` 的运行使用 exact integers 与 `Fraction`、无数值容差。主程序 `divisible_two_size_neutral_repair.py` 返回 PASS：参数数 540、全部 count states 50,925、macro steps 53,100、tiny steps 99,663、最大 atomic support 8。修正 (Q=m^2) 的实例数为 435，原始 (Q=m) 实例数为 98；最后一组摘要分别为 repaired `[30,29,959,842]` 与 original `[100,102,99]`。

这里“中性”指 macro repair 在 exact tick 账本上保持所需资源/容量不变量；它不是一般 unrelated-machines 的调度算法。原 JSON 的 limits 明确：这是 finite implementation audit，普适陈述另有独立证明；没有通用 UM algorithm、hardness 或外部 novelty 验证；冻结记录是新增文件，不替换旧证据。

## 3.2 独立参数实现

独立运行检查 285 个 parameter sets、15,045 个 labeled initial states、7,075 个 macro steps、15,636 个 tiny steps、285 个 macro 内 tiny moves，最大 macro batch support=4，最大 (Q) 的二进制位长 201，并包含 (m=1)、空 jobs、(Q=1) 边界。它是实现交叉核对，不是第二个全量证明；没有声明任意 m 的算法复杂度。

## 3.3 与已有材料的关系

它和仓库已有的 cyclic-menu repair、fixed-work invariant、配置/配额审计共享“精确整数账本 + 局部修复”方法，但对象中的 (Q=m) 与 (Q=m^2) 量词和中性条件是独有内容。不能把 macro-step 计数当作 assignment enumeration，也不能以 `PASS` 字段替代对所有合法边和容量约束的数学证明。

# 4. 半单位联合选择与 3DM 阈值

## 4.1 固定构造和完整范围

`half_unit_joint_choice_audit.json` 的 claim 是 `independent half-window unique-small 3DM`。模型固定 (T=1)，可用边的处理时间只有 (1/2) 与 1，采用 integer half-units 和 Fraction；不导入仓库代码，seed=20261016。主审计总计：1,737 source states、362 instances、203 个 `yes_3dm`、259 个 exhaustive all families、3,604,399 个 big-selection states、3,036,526 个 scheduling states、1,448 个 delta queries、64 个 restricted q=3 families、9 个 explicit boundary cases 和 30 个 seeded samples。

完整范围是 q=0 一族 1 个、q=1 两族、q=2 的 256 族；q=3 只在大小为 6 的 restricted universe 中穷举 64 族，另取 30 个 seeded instances。独立实现另有 265 cases、4,743 DFS nodes、180 yes 结果；四个 rational deltas 为 (0,1/3,49/100,499999/1000000)。

## 4.2 可复用结论与边界

- unique small endpoint + job mass 1 时，每个 unmatched job 必须全部放到该 endpoint；这是固定构造中的 half-unit floor 机制。
- q=0 时加入 uniform dummy，(m=s+3q+1)，没有 jobs，所有 oracle 都返回 YES；这是空边界，不是正规模 hardness。
- (delta=1/2) 时所有 jobs 可留在 small side，source load 为 (3/2)，triple load 为 1，element/dummy load 为 0；因此 (delta=1/2) 是 endpoint，不能用来声称任意更小阈值。
- 负 (delta) 不在定义域：q=1 perfect instance 在 (delta=-1/4) 失败。
- triples 按 index 区分，重复 triple 有独立 machines，保留 source truth；只有列明 finite edges，时间为 (1/2) 或 1，没有 zero processing time。
- (T=0) reduction 未被声明。

因此该审计支持“固定 half-unit 构造中，联合选择与 3DM 证书在列明 q/delta 范围内一致”的有限结论；不提供独立的 classical 3DM NP-completeness 证明（依赖找到的 Karp 来源），不提供一般 epsilon 结果，也不提供多项式 joint-H selection 算法。两个搜索/调度 oracle 都是指数型有限审计。

## 4.3 endpoint false positive

独立输出的 `endpoint_half_false_positive=true` 很关键：(delta=1/2) 可以产生 full schedule，即使 source 本身不对应目标 perfect-3DM。它是阈值端点的 false positive 机制，必须保留在任何后续 reduction 中；不能只记录 YES 计数而忽略 delta 依赖。
