# 1. 对象区分与审查结论

本审查实际读取三个冻结 JSON 的全部字段，并比较了私有 sink/退出池相关正文、已有边际审查及树/复制对象。三源属于两个相邻但不同的合同：

1. `149e4663ac9c4fc60b45` 是共同退出、完整池和单 sink exit control 的规范有限审计；
2. `844ea5c699ee6c2cce57` 是同一对象的独立原调度/覆盖子集核对；
3. `b44a4c943689773ff949` 是 private sink higher-order negative-correlation 的 law/pointwise audit。

它们都使用精确 Fraction 或整数，没有浮点容差。前两源检查一个给定 pool class 的 promise、可行 T、共同退出和覆盖；第三源检查有限 law 的点态成功概率及公式逆向。它们没有合并成一般 kernel theorem，也没有产生 unrelated-machines 的通用近似算法。

本批的分类为：**一般结论候选**（只保留源声明的合同和待证明方向）、**有限实验**（全部实际计数和 law）、**障碍**（空目标、非 rank、非法合同、higher-order law 未由 pair budget 唯一决定）。没有把任何有限通过升级为完整证明。

# 2. 共同退出与完整池：规范有限审计

`149e4663ac9c4fc60b45` 使用 Python 3.12.14、seed `2026101606`、`Fraction`。参数固定为

\[
\eta=\beta=1/8,\qquad \rho\in\{1,9/8,3/2\}.
\]

完整计数为：

| 字段 | 数值 |
|---|---:|
| 总 cases | 906 |
| promise cases | 706 |
| successful outputs | 706 |
| 原始 assignments enumerated | 174,639 |
| nonrank cases | 594 |
| zero targets | 321 |
| illegal contracts | 6 |
| single-sink-exit control | `true` |

在 promise 域内，706/706 输出成功；这只说明指定 pool class 的精确 oracle 通过。594 个 nonrank、321 个 zero-target 和 6 个 illegal contract 不能从账本中删除：它们界定了 promise、目标为空和输入不满足合同的真实分支。`single_sink_exit_control=true` 也只控制该脚本的单 sink 退出接口，不等于任意多出口组合都可解码。

源 limits 明确写为 finite exact oracle checks；没有一般 approximation、没有全参数穷举。因此该源的安全结论是“列明 pool class 上的共同退出合同与 oracle 一致”，而不是 kernel theorem。

# 3. 独立原调度审计：覆盖和无误拒

`844ea5c699ee6c2cce57` 标题为“私有组共同退出与完整池的独立原调度审计”，seed `1739`，使用全原始 assignments、精确 covering subsets 和 macro destination enumeration。它独立重算两组 `rho`：

| `rho` | factor | cases | original assignments | `T_feasible` | `second_success` | `norm_success` | false reject | `T_zero` | `H_empty` | `OPT_zero` |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | `5/4` | 700 | 99,518 | 551 | 551 | 551 | 0 | 227 | 172 | 250 |
| `9/8` | `89/64` | 700 | 123,701 | 571 | 571 | 571 | 0 | 245 | 172 | 251 |

这里的 `false_reject=0` 是独立有限重算的精确输出，说明在两个给定 `rho` 层，规范的可行 T 未被第二阶段或归一化合同误拒。`T_zero`、`H_empty` 和 `OPT_zero` 仍保留为空目标、空 covering subset 和零最优值的合法边界；不能把无误拒读成所有非零目标输入都有成功分配。

独立审计支持规范脚本的实现一致性，但不改变其 scope：source 明确称 finite cases only，不证明 kernel theorem 或一般 unrelated-machine approximation。它也没有核对第三源的 higher-order law，因此不能把两个表拼成一个联合概率结论。

# 5. 机制比较与未闭合的数学义务

## 5.1 与 private sink marginal 审计

`19d6dbe5fca0f2c533e4` 的 independent/sharp-NC law 侧重 `(k,r)` 完整 assignment、expected makespan、universal NC lower 和 pair budget；本批第三源侧重 higher-order law 的点态 success probability 与公式逆向。两者可以相互作回归测试，但参数 `d,q`、collision 语义和 `rho` pool 合同并不自动相同。不能把一个源的 success 概率替代另一个源的 makespan 结论。

## 5.2 与私有 graft/复制障碍

私有 graft/complete-pool 审计处理需求 DAG 的 `min` 瓶颈、分数匹配整数化和 parity 重复；共同退出池处理的是一个有 promise 的覆盖/宏目的地合同。完整池一词在两处都有出现，但元素池、退出 pool 和 sink law 的对象定义不同。第三阶段引用时必须保留完整路径和 source ID，不能因都叫“pool”而合并。

## 5.3 仍开放的义务

以下内容没有被三源完成：

* 对所有合法 pool class 参数给出 kernel theorem，并证明可构造的全局共同退出；
* 把 `eta=beta=1/8`、`rho` 三值结果推广到任意有理参数或显式的全量输入域；
* 从 pairwise negative correlation 和 marginal constraints 推导任意 higher-order law，或证明某个 universal tail/rounding 常数；
* 在 `OPT=0`、`T=0`、空 `H`、zero target 和任意平局下保留同一量词并给出统一调度解码；
* 说明 32 个 attaining laws 的 `d,q` 公式与其它 tree/convex-hull 对象之间是否存在一般结构。

这些开放点来自源 limits 和有限边界输出；不能因为 706/706 promise success、两个 `false_reject=0` 表或 15,000 个点态检查就宣称通用近似。
