# 1. 来源身份与核心原则

源文是一份针对科研想法的 novelty-risk audit 模板，目的在于**先查可能的既有范式和最危险 baseline，再决定想法是否有可防守贡献，最后才组织论文包装**。它的中心次序是：

```text
先拆穿 → 再修补 → 再定义边界 → 最后包装
```

这份次序约束叙事，而不是证明新颖性。源文示例主要围绕 BIM 室内定位、LiDAR-to-BIM、Hough 候选、AMCL/MCL、HMM/Viterbi、拓扑定位和 180° yaw-flip；这些是通用示例，不是本仓库不相关机器模型的数学输入或外部文献结论。

本条目因此归入 `archives/unrelated-machines/state/资料/`。它可以指导已有定理、障碍、反例、程序和候选题的去重/优先权检查，但不创建 UM 定理、算法、gap、hardness、复杂度、外部新颖性或投稿判断。

# 2. 审计流程：从应用想法到可防守贡献

## 2.1 用一句话描述原始想法

第一步不是写摘要，而是用应用语言给出四个槽位：具体场景、已有方法、失败原因/错误、拟用方法和目标指标。句子应回答“在什么场景中，现有方法因何出现什么错误，我要用什么机制改进哪项指标”。

这一步只建立待审对象。它不能把应用背景当成算法新意，也不能从一句愿景推出 theorem、复杂度或实际性能。

## 2.2 去掉应用名词，抽象通用算法范式

源文要求把 BIM、LiDAR、Hough 等名词替换为结构问题，再检查想法是否落入经典范式。示例映射包括：

| 应用说法 | 可能的通用范式 |
| --- | --- |
| BIM + Hough + 多候选 + 运动后消歧 | multi-hypothesis localization、sequential Bayesian filtering、HMM/Viterbi |
| 重复结构下的多个位姿 | particle filter/AMCL、graph matching、symmetry-induced ambiguity resolution |
| 传感器与地图联合约束 | factor-graph optimization、semantic/topological SLAM |

抽象后应明确：哪些部分只是已有求解器（例如 Viterbi），哪些部分才可能是新的候选表示、约束、失败检测或证明。若核心机制只是把经典算法换到新应用，贡献应按应用型/短文强度评估，而不是直接称新方法。

## 2.3 四层相关工作检查

源文要求至少查四层，不能只搜同一应用名：

1. **直接相关工作。** 同任务、传感器、地图或输入格式的论文。要问它们是否已经产生多候选、做 candidate verification、处理重复结构和 ambiguous scenario、保护 top-1 错误。
2. **相邻相关工作。** 问题结构相近但术语不同的领域，例如建筑拓扑定位、scene graph matching、floor-plan localization、semantic SLAM、topological map localization。要问它们是否已使用房间/门/走廊图、无初值 global localization、graph-to-graph matching 或对称性处理。
3. **经典算法范式。** AMCL/MCL、Bayesian filtering、HMM/Viterbi、multi-hypothesis tracking、factor graph、loop closure/relocalization 等。必须回答想法是否只是这些范式换了观测模型或先验。
4. **危险 baseline。** 选择一旦表现良好就会削弱主张的基线，例如 BIM-to-occupancy-grid + AMCL、LiDAR2BIM Hough top-1/top-K、Hough + LIO-only、topology-only、S-Graph/A-Graph 类定位。

四层检查的结果应形成一个表：方法、相似点、差异点、novelty 威胁程度、必须如何区分。威胁程度不是概率，也不是新颖性认证；它是决定下一步实验和收缩 claim 的风险标记。

# 3. 相似性矩阵和危险 baseline

源文给出的相似性矩阵示范如下，结构比具体例子更重要：

| 方法范式 | 相似处 | 可能差异 | 风险与区分任务 |
| --- | --- | --- | --- |
| AMCL/MCL | 多假设、运动传播、观测更新、运动中消歧 | occupancy-grid 粒子与结构化候选 lattice 的差异 | 高风险；须证明 BIM 实体、候选模式和错误恢复带来额外能力 |
| LiDAR2BIM/Pose Hough | 产生 Hough 候选、做几何验证 | 序列级 delayed decision、拓扑约束和候选路径 | 高风险；须证明 top-1 错误时后续事件能恢复 |
| S-Graph/A-Graph | 建筑拓扑、无初值定位、图匹配 | 是否重建完整 scene graph，还是仅筛选 Hough 候选 | 高风险；须明确轻量候选 lattice 的非等价处 |
| Viterbi/HMM | 候选序列推理 | 求解器本身不是贡献 | 中风险；不要把通用 DP 算法冒充新意 |
| LIO-BIM | LIO 与 BIM 的连续 tracking/matching | 无初值、多峰候选、错误承诺检测 | 中风险；需证明拓扑约束的增量效果 |

对每个危险 baseline，源文要求同时写“为什么危险”和“怎么比较”。比较应覆盖会击穿主张的场景，例如重复走廊、180° 歧义、wrong-room、wrong-top1 recovery、false commitment，而不是只报最终平均精度。

将该结构转用于 UM 时，baseline 不是某个机器人系统，而是最接近的既有 theorem、经典松弛、局部 oracle、有限审计或已有 decoder。若一个既有配置 LP 已包含某个 gap、一个必要 flow 已无法保证整数 ownership，或一个定理已覆盖某个参数类，就应把它列为危险 baseline/重叠对象；不能因新命名、换图或换实现而称新主张。

# 4. 审稿人攻击模式

包装前，源文要求主动写出至少四类问题：

* **Q1：是不是既有方法 A 的简单变体？** 回答相同处、不可约差异和需要做的实验证明。对于 UM，应换成“是不是旧配置、Hall、势函数、舍入、XOS 或 decoder 的直接特例”，并指向量词和证据差异。
* **Q2：为什么不直接使用 baseline B？** 写出 baseline 的已知局限、方法额外利用的信息和验证这些信息确有用处的实验/证明。
* **Q3：哪些情况下失效？** 列输入域、对称性、零权、支持为空、阈值边界、低位复杂度或缺失 decoder 等具体失败条件。
* **Q4：核心模块是否只是工程组合？** 把非贡献的标准组件和真正新机制分开，避免把模块数量当作创新。

回应不是“预先防御”的一段空话。它必须通过正式对象、来源、程序、有限范围或未解决标记来回答；若没有证据，保留问题而不是用更强形容词掩盖。

# 5. 三档贡献判断

源文把每个想法分成三档，用来决定要不要继续：

### 最弱版本

如果只实现最简单版本，明确它可能只是某个经典算法/应用迁移。例如 “top-K 候选 + LIO + 选择最优” 很可能只是 AMCL/MCL 或候选重排的工程变体。对应 UM 的最弱版本可能只是把已有 LP/流/舍入组合起来，却没有新的可证明性质或解码。

### 可防守版本

加入关键区别模块，并用针对性实验或证明命中具体 failure case。例如显式建模 wrong-room、cross-floor、yaw-flip，并用拓扑事件消歧；对应 UM 则可能是一个新量词下的 sound FAIL、完整整数 decoder 或严格超出现有 baseline 的边界。此档仍须准确写出输入域和证据。

### 增强版本

再加入分析型贡献、强实验和可解释失败边界。例如 symmetry-aware delayed decision、ambiguity index、多建筑实测和完整 baseline 比较；对应 UM 可是参数化定理、可复用结构引理、渐近族、独立精确审计与可实现复杂度合同。增强版本只有在这些组件实际存在时才能写入地图。

三档不是论文质量评分，也不是接受预测。它们是为了在证据不足时主动收缩 claim，而不是为了把弱版本包装成强版本。

# 6. 不能声称与可以谨慎声称

## 6.1 不能声称

源文要求先列绝对不能说的句子，典型包括：首次使用 BIM 拓扑、首次提出多假设定位、首次利用运动消歧、任意错误初值都能恢复、所有场景均能解决 180° 歧义、不需要相对运动估计。

在 UM 档案中，等价的禁止项包括：

* “首次”除非完成针对性的外部优先权核对；
* 把作者提出的母问题、团队 C 派生子题和本地实现混成同一来源；
* 把固定实例、有限程序或局部松弛写成任意输入的全称定理；
* 把配置/flow 的必要性写成实际整数调度的充分性；
* 把某个有限 gap、障碍或反例写成整个 R||Cmax 的 hardness；
* 把内部审查、贡献地图或候选池状态写成外部同行评审、全球新颖性或接受概率；
* 把一个接近上界的数值、旧文献的 lower bound 或改写后的证明重复归为本团队首创。

## 6.2 可以谨慎声称

源文建议用具体对象、条件和机制约束句子。例如“针对 Hough-based LiDAR-to-BIM 在重复建筑中的 wrong-top1，提出候选序列消歧框架”；“在正确位姿位于 top-K 且轨迹包含足够拓扑事件时可恢复”；“完全对称时检测 remaining ambiguity，而不是过早提交”。

对应 UM 的谨慎句式应写成：

* “在明确的 `[模型/输入域/参数范围]` 内，证明 `[定理/必要条件/反例]`。”
* “给出一个独立的 `[有限精确审计/decoder/复杂度接口]`，其覆盖范围为 `[范围]`。”
* “与 `[旧对象]` 的差异是 `[具体结构、量词或证据]`，而不是仅换名称或实现。”
* “在 `[条件]` 下得到 `[结论]`；离开该条件的行为留作风险或开放义务。”

这些句式保留范围和失败边界，不把“谨慎”误解为没有贡献。

# 7. 技术可行性、新颖性可防守性和实验可证明性清单

源文 checklist 分三组：

## 7.1 技术可行性

* 输入数据是否稳定获得；
* 关键模块是否已有实现基础；
* ground truth 是否可获取；
* 失败现象是否真实存在；
* 正确答案是否经常在候选集合中；
* 算法是否能在合理时间运行。

在 UM 中对应检查处理时间/权重编码、合法资格集合、完整任务分配、输入位长、LP/匹配/decoder 是否真的可执行，以及有限程序是否读取了全部所宣称的状态。

## 7.2 新颖性可防守性

* 是否查过经典范式、直接竞品、相邻领域；
* 是否列出危险 baseline；
* 是否能说清和危险 baseline 的结构差异；
* 是否知道不能说什么；
* 是否有具体、狭窄、可验证的新贡献。

“搜索没有命中”只能是风险状态；不是全球新颖性证明。主张类型、来源身份和作者贡献必须分别核对。

## 7.3 实验可证明性

* 是否有明确 failure case；
* 是否能构造 targeted benchmark；
* 是否有 ablation；
* 是否能和危险 baseline 公平比较；
* 是否有一个核心指标直接支撑贡献；
* 是否能解释失败条件。

数学档案中“实验”可以是精确枚举、程序回放、证书检查或反例构造，但必须写明有限范围、算术、输入、seed、输出和未覆盖域。它们支撑相应 claim，不替代全称证明。

# 8. 实验设计与 baseline-first

源文强调不要只做最终精度；每条主贡献都要有针对性实验、指标和必须对比的 baseline。示例：

* 多候选序列消歧 → 在 Hough top-1 错误但 top-K 含正确位姿时测 wrong-top1 recovery rate、candidate re-ranking accuracy、decision length；
* 180° yaw-flip 处理 → 构造长走廊、矩形房间、对称办公室，测 yaw recovery、false commitment、remaining ambiguity detection；
* BIM 拓扑约束 → 比较 topology-only、odometry-only、topology+odometry、symmetry-aware，测 ATE/RPE、全局定位成功率、误报率、运行时。

转换到 UM 后，实验设计原则是：若贡献声称某个全状态边界，就跑覆盖所有宣称状态的精确程序；若贡献声称必要条件，只测是否 sound FAIL，不把 LP 可行性当实际调度；若贡献声称复杂度，记录输入编码、位运算、输出 decoder 和运行范围。

Baseline-first 的表格至少应为：

1. baseline；
2. 它为何危险；
3. 如何公平比较；
4. 哪个指标能证明新机制确实多做了事。

这可以防止“加一个标准模块”被当成主贡献，也能让失败实验回收为准确的边界，而不是浪费成品。

# 9. 最终论文主线与提问格式

完成上述检查后，源文才建议使用五句主线：已有方法能做什么；在什么具体场景因何失败；相邻方法虽然能做什么但未处理哪个特殊问题；本文聚焦的狭窄问题定义；提出的机制和在何种条件下得到的谨慎结论。

它还给出一个可直接复用的 prompt：先抽象通用范式，列四层相关工作和危险 baseline，给相似性矩阵，站在审稿人角度攻击，区分三档贡献，列不能/可以谨慎声称的内容，设计实验和消融，最后再建议论文定位。该 prompt 是审计流程的调用方式，不是外部检索服务或自动优先权认证。

最终判定格式至少包括：想法名称、抽象范式、最相似经典方法、最危险竞品、novelty 风险高/中/低、最弱/可防守/增强版本、不能声称、可以谨慎声称、必须打败的 baseline、必须实验、推荐论文定位和下一步最小验证。

# 11. 失败机制和停止条件

源文的主要失败机制不是算法崩溃，而是错误的贡献推断：

* 只换应用名词，实际核心是经典范式；
* 没查直接/相邻领域，误把重叠方法写成新颖；
* 只报最终平均精度，没有验证最危险 baseline 或 targeted failure；
* 把工程模块组合写成理论贡献；
* 不列失败条件，暗示任意输入都能恢复；
* 把有限试验、内部 review 或搜索空结果写成外部证明；
* 用“首次”“解决所有”“完全优于”超出证据的强主张；
* 先包装再补边界，导致 introduction 与正式定理不一致。

对应停止条件是：若抽象后与经典范式等价且没有不可替代机制，收缩为应用/短文或停止；若最危险 baseline 已覆盖主现象，重新定义问题或放弃；若正确答案不在候选集合、缺少 ground truth、无法公平比较或失败机制不可解释，不把精度实验当贡献；若外部 priority 未完成，保留“未认证”状态。
