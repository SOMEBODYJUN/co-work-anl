# 论文论证重构的主线、证据对齐与结构边界

## 来源身份与处置

本对象完整实读上游 `paper-from-zero` 的 `paper-argument-reconstructor/SKILL.md`，导出源大小 5948 字节，SHA-256 为 `b45769a14b7929bea991c5d5106b4acf5ed934f600ef63c56b540348bd1ba4fe`。clean source ID 为 `6f570b55c690785d6aa3`；冻结索引的 inventory blob 需以当前清单为准，原字节已保存至 [paper_argument_reconstructor_skill.md 原文证据](../../tools/evidence/paper-argument-reconstructor-20261031/original/paper_argument_reconstructor_skill.md)。

处置为 `integrated` 资料资源。该技能是论证设计和受约束重写的工作流，不提供 unrelated-machines 的定义、算法、证明、反例、近似比或外部文献优先权。归档的独有内容是：把一篇稿件从模块堆叠改成问题驱动的链条；对每段、模块、公式、理论、实验和结果做 claim-to-evidence 对齐；在 evidence 不足时 Flag 而不补写；对已经由其他工具改过的段落使用 verification mode，避免竞争性重写。

## 适用范围与工具分流

该技能用于诊断、重构或改写学术稿件的逻辑、故事线、贡献陈述、章节结构、公式解释、理论/证明叙述、实验—主张关系、结果讨论和结论。核心任务是 argument design，不是单纯语言润色、文献综述、新颖性风险审查或仅审实验章节。

它规定以下分流：

- TeX-safe 表达润色、校对、翻译或 preservation checking 由 `paper-polisher` 负责；
- idea novelty、危险 baseline、reviewer attack 和 contribution defensibility 先由 `idea-novelty-auditor` 负责；
- 文献综述、背景、研究 gap、引用选择和直接竞争者覆盖由 `problem-driven-literature-review` 负责；
- 实验集最小性、消融充分性、资源可行性和结果叙述审查由 `experiment-section-auditor` 负责。

如果用户同时要求 novelty audit、literature review 和 manuscript reconstruction，应先审查新颖性，再构建相关工作证据，最后只重构已经可防守的主张。这个顺序和当前清洗中的“先实读来源、再比较、再写边界”一致。

## Verification mode 与不可协商规则

默认模式会根据问题重构论证；若输入是另一工具或技能已经起草/重写的 argument 或 section，则切换到 verification mode：不覆盖其他工具的措辞，逐项检查 claim boundaries、contribution-to-evidence alignment 以及是否有超出 source 支持范围的强化，只报告偏差及位置；只有硬规则被破坏时才原位收紧一处。目标是 faithful, bounded output，而不是生成另一篇竞争稿。

技能的不可协商规则是：

- 不得捏造 contribution、experiment、result、theory、guarantee、deployment value、limitation 或 related-work fact；
- 保留已有 TeX 结构、command key、equation、citation、label、variable、数值、dataset、metric、baseline 和 reported result；
- 不得把稿件改写成比 source 更强的 claim；
- 不能把算法族、solver 或标准 pipeline component 当作新贡献，除非 source 明确支持该定位；
- novelty 或 related-work 事实不确定时，使用谨慎措辞或请求/搜索证据，不能直接写 priority。

## 核心问题驱动链条

技能要求先识别核心 research problem、应用情景、技术瓶颈和主张，再把论文沿以下链条组织：

```text
Real-world demand → Technical bottleneck → Limitation of existing methods → Required capability → Proposed framework → Mechanism → Evidence → Implication
```

方法密集型工作可以使用局部链条：

```text
Core problem → Specific challenge → Required capability → Proposed module → Mechanism → Evidence → Implication
```

每个段落、模块、公式和实验都应回答或支撑论文试图解决的问题。避免“介绍模块 A、介绍模块 B、介绍模块 C、最后做实验”的目录式故事；应先写具体挑战和所需能力，再说明模块如何提供能力、机制如何缓解剩余限制、证据如何检验核心主张。段落若没有清楚的 function，应合并、移动或重写。

## 段落功能、贡献与章节目标

重写前给每段标记一个功能：应用背景、核心问题、技术 gap、方法动机、模块机制、公式定义、理论分析、实验设置、结果观察、结果解释、限制、实践含义或过渡。贡献陈述必须回答前文已经建立的 gap，例如“解决某具体缺口的 capability formulation”“缓解某失败机制的 module”“在指定条件下验证某主张的 targeted evaluation”；不要只列“提出 A、提出 B、做实验”。

章节目标按如下边界执行：

- **标题**识别技术对象、关键能力和应用情景，不写模块清单或宽泛承诺；
- **摘要**依次给出背景、具体 gap/失败模式、方法和机制、证据及有边界的含义；
- **引言**从需求、瓶颈、已有局限、所需能力、方法、贡献和文章结构推进，结尾贡献不能让读者意外；
- **相关工作**按方法族、假设或限制组织，避免时间顺序罗列引用，不在重构中发明文献事实；
- **方法**从问题需求引出每个模块，说明输入/输出、机制、与其他模块关系、假设和限制；
- **公式说明**先说公式为何需要，再定义符号并解释其机制作用，避免孤立的 formula dump；
- **理论/证明**说明假设、命题意义、推导逻辑、结论、适用范围和限制，不能扩大证明量词；
- **实验**为每个实验绑定被测 claim、场景、baseline、metric、诊断价值和限制；
- **结果/讨论**按观察、比较、机制解释、与主张的关系和必要限制写，不简单复述表格；
- **结论**回到核心问题，总结机制和证据，陈述有边界的后续工作，不引入未评估的新主张或应用。

## Claim-to-evidence 对齐与常见缺口

诊断应建立表格：`Claim | Required evidence | Existing experiment | Missing evidence | Risk`。典型缺口包括：模块声称重要却没有 ablation；方法声称 robust 却只测 easy cases；real-time/deployment 声称没有 runtime/resource analysis；安全或可靠性声称没有 failure-case analysis；superiority 声称没有比较危险 baseline。

这类表格在当前 UM 存档中应进一步标出 claim_type（定义、定理、条件结果、反例、障碍、有限检查、猜想）、对象/来源/evidence refs、模型量词和下一步。一个 exact finite audit 可以支持有限检查或反例证据，但不能替代一般证明、sound `FAIL`、完整整数 schedule、decoder 或位复杂度。一个 source-bound 文献说明可以支持来源一致性，但不能升级为外部 priority；一段可读 prose 不能代替程序运行或 PDF/HTML 可见渲染。

## 与相邻资料的去重与互补

本技能和已归档资料的边界如下：

| 对象 | 它解决的主要问题 | 本技能新增或不同之处 |
| --- | --- | --- |
| `创新性审查技能` | 直接/相邻/经典/危险工作比较、reviewer attack、三档贡献和 novelty risk | novelty 已有边界后，重建段落与章节论证，不重新宣称新颖性 |
| `创新框架候选` | 一句话主张、重要性、已有覆盖、gap、证据和 falsifier 的候选合同 | 把候选转成 problem→mechanism→evidence→implication 的稿件链条 |
| `反防御功能审计` | 逐句判断 Keep/Rewrite/Compress/Delete/Flag，保护定义域、否定和证据限定 | 先保留 source 支持的结构，再让每段承担清楚的论证角色 |
| `UM Route Card` | 稳定 ID、路线、承重义务、blind attack、kill line、oracle/bit complexity、下一动作 | 不改变 Route Card 的数学/工程合同，只在成稿层检查它是否被完整解释 |

这几个对象不能合并成一个“论文已证明”状态。创新性、候选 gap、Route Card 和章节重构分别在不同层级工作；重构也不能把导航、审查或写作资料升级为 accepted edge、定理或外部 priority。

## 对当前 UM 存档的适配

在写一般 unrelated-machines `(2-\varepsilon)` 目标的说明时，问题驱动链条至少应固定：

1. **需求。** 目标是对二进制非负有理 processing times、`∞` 禁边、空任务、零处理时间和任意合法输入，输出完整真实整数 schedule，并统一达到 `C_max ≤ (2-ε) OPT`。
2. **瓶颈。** 逐机 feasibility、配置 LP、给定 support/home/sink、局部矩或有限 probe 不能自动提供共同容量状态、全局任务身份、sound FAIL 或 bit-complexity 闭合。
3. **所需能力。** 任何算法或反面路线都要显式处理共同状态、真实整数输出/decoder、可靠失败证书、统一余量和输入总位长；受限对象应把限制写在主张旁。
4. **方法/机制。** 分别介绍 exact proof、条件桥、有限 audit、反例、障碍和文献基线，说明每个是如何承重或失败，不把它们拼成一个不受限全称结论。
5. **证据。** 证明、原始文献、独立 exact replay、冻结 JSON、source hash、执行边界、渲染检查各有自己的证据层级。
6. **含义。** 只能给出当前输入域和证据支持的结论；开放的 UM-TARGET-v1 仍写 OPEN，并把下一可检验问题和失败路线列出。

这里的适配是写作结构示例，不是本技能对 UM 目标的新证明。若对象属于 Q-CAG-HALF、weighted-congestion 或 facility-games，仍保持独立模型身份，不从共享叙事迁移结论。

## 处置和未覆盖边界

本资料保留为整理论文和长篇审查页的结构资源。它要求在重构前先确认新颖性/相关工作边界，重构中保持 TeX 与数值资产，重构后逐项核对 claim-to-evidence 和缺失证据；但它没有实际运行程序、编译 TeX、验证 PDF/HTML 或执行外部文献搜索。

它不创建 theorem、algorithm、hardness、gap、complexity、counterexample、experiment result 或 priority claim。任何新的结构改写都应保存 source/version、输入稿路径、保持的 protected fields、缺失证据和下一步；若只有模板或摘要，状态仍为资料/候选。正式数学结论继续由对应 state 正文、证明/反例、程序和 evidence 分层承重。
