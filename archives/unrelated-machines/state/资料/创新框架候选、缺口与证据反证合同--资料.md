# 创新框架候选、缺口与证据反证合同

## 来源身份与处置

处置为 `integrated` 资料资源。该参考不定义机器、任务、调度、近似比或复杂度，也没有外部文献结论；它提供的是候选创新 framing 的最小证据合同。其内容已和本仓库的 Route Card、反防御写作审计、2.5 资产登记以及 Research runtime 的 claim/status 规范逐项比较，并整理成适合现有清洗与后续研究的操作边界。处置为 integrated 只表示写作与研究流程吸收了这条合同，不表示任何候选因此变成已接受数学命题。

## 候选 framing 的六个必填部件

源文要求每个 candidate framing 同时回答六个问题：

1. **一句话主张。** 用可检验、范围足够窄的句子说清楚新主张是什么，避免用流行方向名词替代对象和关系。
2. **为什么重要。** 说明该主张对问题、模型或读者的影响；意义不能用“大家都关心”代替具体承重义务。
3. **已有工作覆盖什么。** 指出已知定理、基线、算法、反例或已有实验已经承担的部分，防止把换名、重新包装或局部特例冒充新颖性。
4. **缺口在哪里。** 指明尚未解决的对象、量词、模型转换、证据层级或失败方向。Gap 必须可定位，不是泛泛说“缺少研究”。
5. **需要什么证据。** 预先给出可审计的证明、反例、有限 exact audit、真实执行、来源核对或可见渲染路径；证据类型要和主张强度相匹配。
6. **什么会反证主张。** 写出最小反例、失败路线、边界输入或实验判据，并说明若出现该情形应把 framing 设为候选、修正、阻断或放弃。

这六部件共同形成一个 reviewer-facing contract：主张、动机、已有覆盖、缺口、证据与 falsifier 必须互相对齐。缺少任何一项时，只能登记为想法或候选，不能把它写成已验证贡献。

## 源文的拒绝条件

源文明确拒绝以下 framing：

- 只是复述流行方向，却没有具体 gap、对象或可判别输入；
- 依赖当前不可获得的数据、算力或人工标注，而且没有可行的 fallback；
- 需要捏造、不可核验或无法绑定来源的证据；
- 用户要的是实证论文，却把工作压扁成综述而没有可检验的经验主张。

在 unrelated-machines 上，这些拒绝条件应具体化：不把“低于 2”或“更公平”当作目标而不写出输入域、输出合同和量词；不把未导出的脚本、缺依赖的程序或旧输出当作 fresh execution；不把有限实例的漂亮曲线当作全体机器/任务输入的近似定理；不把文献索引或路线图当作新 hardness 或算法。若依赖未取得的原始文献、求解器、decoder 或外部数据，应保留 blocked/needs-source，而不是用假设性结果填空。

## 偏好的候选风格

源文把可接受 framing 归纳为四点：

- **范围窄到可检验。** 对象、输入族和输出或证据合同应先写清；必要时只推进固定参数、受限资格或有限审计，不能藏掉限制。
- **动机面向审查者。** 用一两句说明该 gap 为什么影响模型、算法或证据可信度，避免只说“新颖”。
- **证据路径事先可知。** 在提出主张时就列出需要的证明、反例、执行、哈希、来源页码或渲染产物；这样失败也有清楚的停线条件。
- **对风险和负结果诚实。** 负结果、失败逆命题、局部障碍或证据不足都可以是交付物，只要 scope 与 falsifier 写得准确。

这里的“候选”是 workflow 状态，不是数学 claim_type。要升级为 `定义`、`定理`、`条件结论`、`反例` 或 `有限实验`，仍须写独立正文、证明/计算或原始 evidence，并由 receipt 记录来源和审查级别。

## 和 UM Route Card 的互补关系

现有 `UM_Route_Card模板与路线量词边界--资料.md` 已规定成熟候选的身份、路线、builder/owner、blind attacker、integrator、唯一承重义务、相比基线的新增信息、最小攻击族、success/fail/kill line、oracle/位复杂度、交付物、状态和下一动作。两份资料的字段可以如下对应：

| Innovation framing | Route Card / 当前清洗字段 | 关系 |
| --- | --- | --- |
| 一句话主张 | Claim/问题入口、ID/version | 需要稳定对象和精确关系，不能只写宣传性摘要 |
| 为什么重要 | 贡献、路线动机、唯一承重义务 | 必须落到模型、复杂度或证据义务 |
| 已有工作覆盖 | LST/ST/configuration-LP 等基线、相关对象 | 防止把已知局部结果重命名为新结果 |
| 缺口 | open boundary、failure mechanism、unknown | 明确对象、量词或转换缺口 |
| 所需证据 | 证明、exact audit、decoder、source/replay/render | 证据层级不能高于实际读取/执行 |
| 反证条件 | blind attack、最小反例、kill line、失败路线 | 先登记可证伪条件，保留负结果 |

Route Card 还提供了该短参考没有的工程字段，例如角色分工和 oracle/位复杂度假设；反过来，短参考更明确要求每个候选同时写“为什么重要”与“什么会反证”。因此两者互补而不应合并成一个数学对象。Route Card 仍是可选导航模板，不是审批门槛、排他认领、用户默认任务或定理证明。

## 和当前清洗及研究运行的边界

与 `prompts/02-clean.md` 比较，本参考强化了以下清洗纪律：实际读取定义域、量词、假设、论证、证据和缺口；保留候选、条件结论、有限实验、障碍和反例的不同状态；不能把一轮代理、一次提交或旧图当成完成。它不改变 clean claim/show/checkpoint/done 的操作顺序，也不替代稳定 ID、source hash 或 receipt。

与 `prompts/02.5-research.md` 比较，六部件正好为登记项提供“当前问题、已知结论、开放边界、证据需求和下一可检验问题”的草稿，但登记表仍只做编号、路由和状态，不能把 candidate relation 写成 accepted edge。与 `prompts/research-runtime.md` 比较，候选必须明确 `route`、`assumptions`、`claim_type`、`status`、采用的对象/证据、失败边界和下一步；若计算工具或来源不可用，应登记 blocked，而不是声称已完成。

与已归档的反防御审计相比，本参考从候选设计阶段前置了一次“证据—反证”检查，反防御审计则在句子级别决定 Keep/Rewrite/Compress/Delete/Flag。两者共同防止删掉定义域、量词、必要否定、失败逆命题、证据类型和模型边界；创新 framing 也不能用模态词把已定结论变弱或把有限观察变强。

## 对当前 UM 目标的适用实例与限制

若未来围绕一般 unrelated-machines `(2-\varepsilon)` 目标提出候选 framing，至少应先写：

- 一句话主张是算法、困难性、条件桥还是障碍；
- 目标输入是否覆盖二进制有理处理时间、`∞` 禁边、空任务、零处理时间和任意平局；
- 输出是实际完整整数 schedule、sound `FAIL`、decoder、有限反例还是只作必要条件的证书；
- 已知 LST/ST、配置 LP、受限资格、给定 support/oracle 结果覆盖了什么；
- 缺口是共同容量、真实整数输出、soundness、统一余量、位复杂度还是物理迁移；
- 何种最小树/共享 sink/tiny 选择/中间 quota 逃逸会立即反证候选。

这些字段让一个 framing 可被后续 exact proof、finite audit 或 blind attack 检查，但不会替代其数学正文。当前 `UM-TARGET-v1` 仍是 OPEN；本资料不能将一个“可能有 gap”的候选升级为一般 `(2-\varepsilon)` 算法或 hardness，也不能把路线卡中的 P0-F/R0-R 当作用户新任务。
