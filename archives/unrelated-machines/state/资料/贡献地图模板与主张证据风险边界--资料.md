# 2. 五组字段的实际语义

## 2.1 `primary_claim`

`primary_claim` 由三个字段组成：

* `statement`：论文或研究对象的主张句。真正使用时应明确对象、输入域、量词、结论方向和证据级别；空模板本身没有这些内容。
* `novelty_type`：模板给出的示例标签包括 `new-method`、`new-benchmark`、`new-taxonomy` 和 `new-synthesis`。它只是对主张类型的分类标签，不是“新颖”事实；选择标签不能替代文献核对或内部证明。
* `gap_evidence`：说明主张填补哪一项已记录缺口，以及依据是什么。缺口必须指向具体旧结果、范围差异、失败机制或缺失的证据；“尚未搜到”不能自动写成全领域不存在。

在不相关机器档案中，`statement` 必须从正式 `state/定义`、`state/定理`、`state/障碍` 或 `state/审查` 对象提取，而不是从模板另造。若主张依赖有限计算、必要条件、给定 oracle、固定参数或特定资格集合，应在句子和 `gap_evidence` 中一起写出这些限制。

## 2.2 `secondary_claims`

每个二级条目有 `statement` 和 `supports_primary`。`supports_primary: true` 表示该条目被设计为支持主张的组成部分；它不表示已被证明，也不保证逻辑上足以推出主张。使用时必须分别指出它是定义、引理、构造、实现证据、有限审计、文献基线还是叙事连接，并把支持关系落实到正式对象或运行证据。

如果某条结果只是并列背景、反例、软件说明或不同模型的比较，不能因为它出现在同一地图中就把 `supports_primary` 填成 `true`。尤其在 UM 档案里，配置 LP、松弛 flow、有限枚举和实际整数调度之间可能只有必要性或接口关系；它们需要各自的 decoder、soundness、位复杂度和输入域说明。

## 2.3 `non_claims`

`non_claims` 是显式排除项。它用来保留“当前工作没有声称什么”，例如没有一般 hardness、没有任意机器数推广、没有外部优先权、没有把有限实验当全称证明、没有从必要条件构造实际 schedule。

这些不是装饰性免责声明。它们在量词或逻辑方向上阻止读者把窄结果扩成宽结果；若某个非主张对应正式反例、失败 converse 或模型边界，应在相关对象中保留其精确方向。另一方面，模板不要求无限添加 `non_claims`：反防御审计建议只保留改变范围、证据或逻辑的排除项，把纯粹预防假想反对意见的重复句压缩或删除。

## 2.4 `risks`

每个风险条目有 `description` 和 `mitigation`。`description` 应写出可能使主张失效或被误读的具体机制，例如定义域遗漏、全称量词越界、证明只给必要条件、有限程序未覆盖全部参数、引用对象版本不一致或外部文献优先权未检查。

`mitigation` 应是可执行的证据动作：补一个假设、建立反例、运行独立精确审计、逐段比较版本、绑定 source SHA、给出 decoder 或把状态降为候选/未认证。单纯“进一步研究”“加强讨论”不是缓解证据。风险字段不能把未解决问题伪装成已经闭合的定理。

## 2.5 `reviewer_objections`

每个条目有 `objection` 和 `preemptive_response`。它适合整理真实、具体的审查问题以及已经存在的定义、证明、程序或文献证据；它不是让作者预先编写一串面向假想读者的防御性段落。

回应应指向可复核对象：相关定理节、反例、输入清单、程序输出、有限范围或文献边界。如果证据不存在，应把问题列为 unresolved/Flag，而不是用语气强弱替代证明。若反对意见触及“逆命题不成立”“只覆盖某个模型”“当前证据只是有限审计”，回应必须保留否定的逻辑力量。

# 3. 定义域、量词与证据责任

这个 YAML 没有任何数学输入域；实际贡献地图必须从正式对象复制而不是自行补全。至少应明确：

* 对象类别和合法输入（机器、任务、资源、资格集合、处理时间/权重的整数或有理编码）；
* 全称、存在、固定参数、有限样本或给定 oracle 的量词；
* 结论是充分条件、必要条件、等价、反例、算法、复杂度、有限运行还是文献事实；
* 证据来自自足证明、作者推导、独立重构、精确程序、随机实验、来源摘要或外部出版物；
* 哪些模型边界、位复杂度、完整分配义务和 decoder 条件仍未覆盖。

`gap_evidence` 和 `risks` 不能反向制造量词。若现有资料只有一个固定实例或参数扫描，地图最多支持“该实例/扫描显示某种模式”；它不能填成“所有输入都有该性质”。若已有 proof 只是在给定支持、给定 home/sink partition 或固定阈值下成立，主张和风险都应保留该条件。

一个合理的地图先做证据绑定，再做叙事压缩。主张句、二级条目、非主张和回应可以相互引用，但每一条都应能回到正式正文或证据路径。模板没有自动的 schema 校验器、依赖图、claim ledger 或 theorem prover；这些仍由项目自己的归档和审查工具承载。

# 4. 与反防御写作审计的关系

本仓库已有的[数学写作反防御功能审计与证据量词边界](数学写作反防御功能审计与证据量词边界--资料.md)规定：先判断句子是否改变合法性、范围、证据、逻辑或必要指引；能正向命名对象/类别时再重写；缺少目的、编码、对象或范围时 `Flag`。贡献地图把同一原则应用到研究叙事层：

* `primary_claim.statement` 应是对象/结果的正向表述，不是围绕假想反对意见组织的段落；
* `non_claims` 保留真正的模型边界、失败 converse 和证据不足；不把所有可能误读都堆成免责声明；
* `risks` 记录会改变结论的机制，`reviewer_objections` 记录可定位的审查问题；二者都必须有证据或明确 unresolved 状态；
* `novelty_type` 只能标记叙事类型，不能让“new-method”等标签代替 `gap_evidence` 和优先权检查。

因此，地图不是反防御审计的替代品：它负责主张与支持关系的结构化；反防御审计负责句子是否保留数学必要内容。两者配合时，主张更短但量词更准确。

# 6. 在 UM 资料中使用贡献地图的安全流程

对一个已经存在的 UM 数学对象，建议按以下顺序填图，而不是先写投稿段落：

1. 从正式对象复制唯一身份、模型、输入域、量词和状态；若这些字段仍不稳定，把地图标为候选或不完整。
2. 将一个可验证的核心结果写入 `primary_claim.statement`，并给出对应证明/反例/程序/文献证据路径。
3. 把真正支撑该结果的引理、构造、解码或有限审计列为 `secondary_claims`；为每条说明支持方向和仍未覆盖的范围。
4. 把容易被读者扩大的相邻命题放入 `non_claims`，但保留必要否定和失败方向，不把全部潜在误读列成清单。
5. 将量词、定义域、版本、位复杂度、外部优先权和有限审计等真实风险逐项写入 `risks`，并给出可复核 mitigation。
6. 将已有 review 中的具体 objections 逐项记录；没有证据的回应标为 unresolved 或 `Flag`。
7. 最后运行数学完整性比较：地图不得扩大定理的输入域、把必要条件写成等价、把有限结果写成全称，或把来源材料写成独立发现。

这个流程不会生成新的 theorem；它只是把已有对象的叙事依赖显式化。若主张状态发生改变，应修改正式对象和证据，再更新地图，不能只改地图字段。

# 7. 失败模式与边界

* 空白模板不能证明任何 claim。填写文字也不能替代定义、证明、程序或文献核验。
* `supports_primary: true` 不是逻辑证明；若二级结果只是必要条件或有限审计，应按其真实方向标注并在风险/非主张中保留缺口。
* `new-method`、`new-benchmark`、`new-taxonomy` 和 `new-synthesis` 是分类标签，不是新颖性认证；外部 priority check 仍需独立完成。
* `preemptive_response` 不是把所有 objections 预先“防掉”的许可。回应必须给出对象、证据和量词；没有这些就保留 objection。
* 地图不能把不同模型、不同版本、不同阈值、不同证据层级拼成单一主张，也不能把历史投稿评估、内部 review 或 finite audit 变成外部同行评审。
* 若 `non_claims` 和 `risks` 需要无穷扩张，说明主张本身可能还没有用正向对象和精确域定义好，应回到正式数学对象重写，而不是继续添加防御句。
