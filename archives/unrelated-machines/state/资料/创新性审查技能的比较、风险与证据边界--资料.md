# 创新性审查技能的比较、风险与证据边界

## 来源身份与处置

本对象完整实读 `research/weighted_congestion_frontier/upstream/polish_skill/idea-novelty-auditor/SKILL.md` 的 4753 字节。clean source ID 为 `22cab4e163bf1c91d11f`，inventory blob 为 `ccf1e57ec22a231ebfa154acb8d4d51c39fe5b99`，原文 SHA-256 为 `64c6674b1f1426dfde2709faf218b4d3416c2feed843111848d7212c6a55a36e`；冻结索引同时列出 `legacy-cleanup` 与 `main`。原字节保存在 [idea_novelty_auditor_skill.md 原文证据](../../tools/evidence/idea-novelty-auditor-20261031/original/idea_novelty_auditor_skill.md)。

处置为 `integrated` 资料资源。技能定义的是论文定位和研究想法审查流程，不是 unrelated-machines 的数学对象、定理、算法或新颖性结论。它的独有增量是：在包装之前对候选想法做跨层相关工作比较，主动寻找会击穿贡献的危险基线，要求 reviewer attack、不可声称/谨慎可声称分层，并把每个主张绑定到实验、消融和失败案例。其流程可辅助当前存档的 candidate/boundary/blocked 判断，但不替代文献原文核查、数学证明、有限 exact audit 或实际执行。

## 适用范围与工具分流

源文把该技能用于以下请求：判断想法是否新颖、可防守、值得写作；定位 contribution 或 paper storyline；预判 reviewer attack；列危险 baselines；决定不能声称什么、需要哪些实验。若用户在新颖性未核查前就要求 packaging，先跑 novelty-risk audit。

它同时规定工具分流：

- 相关工作、文献选择、引用角色和直接竞争者覆盖，适合 `problem-driven-literature-review`；
- 已知可防守主张后的稿件结构与段落重写，适合 `paper-argument-reconstructor`；
- TeX 安全的英文学术润色，适合 `paper-polisher`；
- 已固定 claims、资源和实验计划后的实验章节审查，适合 `experiment-section-auditor`。

这条分流防止把不同任务强行塞进“新颖性”标签。idea auditor 可以指出需要查哪些来源和实验，但不会凭空代替外部文献检索、TeX 编译或实验执行。

## Verification mode 与重写边界

该技能有两种模式。默认模式从头审查想法；如果另一个工具或技能已经拟好 positioning、claim 或 contribution statement，则切换到 verification mode：不覆盖原文，不重新创造竞争性改写，只检查三类偏差——新颖性是否夸大、是否漏掉危险 baseline、主张是否超过证据强度。只有确实破坏 evidence discipline 的 overclaim 才允许在原位收紧。

这个模式与当前清洗的 read-after 规则相容：比较对象版本时保留作者/Exact/Proof/independent review 的身份，不把后审改写成盲审，也不把语言更漂亮误写成数学更强。技能的目标是 bounded, defensible claims，而不是通过多数票或风格偏好制造“新结果”。

## 核心十步审查流程

源文给出的主流程是：

1. 用一句应用层句子重述想法。
2. 去掉应用名词，把问题抽象为通用算法范式。
3. 检查四层相关工作：直接任务/工作流竞争者、结构相似的相邻领域、经典算法范式、会让贡献坍缩的危险 baseline。
4. 对最具威胁的方法建立 similarity matrix，分别列相似处、差异处、威胁程度和必须如何区分。
5. 从 reviewer 角度主动攻击：是不是已有方法的简单变体、为什么不能直接用危险 baseline、在哪些条件失效、核心模块是否只是工程组合。
6. 将想法分为 weakest version、defensible version、strengthened version，避免把尚未验证的增强版倒填到最初实现。
7. 明确 paper must not claim 的内容。
8. 明确在给定条件和证据下 can cautiously claim 的内容。
9. 设计支撑防守性主张的 experiments、baselines、ablations 和 failure-case analysis。
10. 给出 paper positioning 与 next minimum validation；验证不足时停留在候选/风险状态。

这十步先破坏再修补，确保“包装论文故事”不会早于对象、量词、基线和证据边界。它也接受负结果：如果危险 baseline 已经达到同等表现，合理处置可以是收缩 claim、改变问题定义、记录障碍或停止，而不是添加没有证据的宣传性模块。

## 证据纪律和风险语言

技能明确禁止仅凭专门术语或应用背景宣布 novelty。若当前文献准确性会影响判断，应进行 literature search，或要求提供相关工作集；没有检索或来源时，最多报告风险，不应写外部“首次”。标准风险词包括：`high novelty risk`、`likely incremental unless ...`、`defensible only if ...`、`cannot claim ...`、`can cautiously claim ...`。

它还要求把标准 solver、经典范式或 application-specific implementation 与真正新贡献分开。比如把一个现成求解器换到新应用，不能自动成为主 novelty；只有可防守的结构差异、明确 failure case 和公平 baseline 对比，才可能支撑较窄贡献。

转用于 unrelated-machines 时，以下表述属于合法的保守起点：

- “在固定资格/给定 support/有限参数域上观察到一个候选边界”，而不是“一般 UM 有 gap”；
- “已有 LST/ST、configuration LP 或受限 assignment 覆盖了基线”，而不是“首次处理 unrelated scheduling”；
- “需要 sound FAIL、完整整数 decoder 或位复杂度闭合”，而不是“存在一个可实现的转换”；
- “在指定输入族的 exact audit 中没有找到反例/发现反例”，而不是“所有输入都成立/失败”。

## 标准全审计输出及其在本仓库的映射

全审计输出应包括：Idea、Abstract paradigm、Closest classic methods、Dangerous direct/adjacent work、Novelty risk、Weakest version、Defensible version、Strengthened version、Cannot claim、Can cautiously claim、Must-beat baselines、Required experiments and ablations、Recommended paper positioning、Next minimum validation。快速检查只需 risk level、most dangerous baseline、defensible claim 和 minimum experiment。

对应本仓库的稳定对象字段如下：

| Skill 输出 | UM 存档/研究字段 | 证据边界 |
| --- | --- | --- |
| Idea / abstract paradigm | object identity、model、route | 不等于数学定义或已接受路线 |
| Closest / dangerous work | related_objects、source_refs、Route Card baseline | 需要逐源阅读；邻接关系不是结论 |
| Novelty risk | candidate/boundary/blocked/needs-source | 风险词不是外部新颖性证明 |
| Weakest/defensible/strengthened | claim_type、status、scope | 不同量词和版本必须分开 |
| Cannot / cautiously claim | non_claims、failure boundary、truth_status | 保护必要否定和证据等级 |
| Baselines/ablations | evidence_refs、next_questions、audit inputs | 需要实际程序/来源/实验，不能只列名字 |
| Positioning/minimum validation | next action、kill line、proof/audit gate | 完成条件应可复核，不能用摘要代替 |

和上一个 `创新框架候选、缺口与证据反证合同--资料.md` 相比，本技能把“已有覆盖、gap、证据、反证”扩成直接/相邻/经典/危险四层比较、三档贡献判断和系统 reviewer attack；它不重复六字段候选表。和 `UM Route Card` 相比，Route Card 承担稳定 ID、builder/blind attacker/integrator、唯一承重义务、P0-F/R0-R 量词、oracle/bit complexity、kill line 与交付物；idea auditor 提供的是进入 Route Card 前的 novelty-risk gate。和反防御审计相比，本技能审查对象/基线/主张层级，反防御审计审查句子功能并决定 Keep/Rewrite/Compress/Delete/Flag；两者都禁止删掉定义域、量词、必要否定、失败逆命题和证据限定。

## 实验、消融与失败案例边界

技能要求 experiments 直接支撑 defensible claim，而不是只报告最终精度或单个漂亮数字。实验设计应预先绑定：主贡献、对应实验、关键指标、必须比较的 baseline；危险 baseline 若不能公平击败，应收缩主张。消融要隔离真正模块的作用，failure-case analysis 要展示方法在哪些输入、对称结构、边界参数或资源限制下失效。

在当前 UM 语境中，合法的最低验证可以是：给定一个明确输入族，保存 exact 构造、代码、seed/参数、运行输出和失败条件；若主张是 source-bound 或文献定位，则保存原文页码/章节和比较记录；若主张涉及一般量词、sound FAIL、完整整数 schedule、decoder 或 bit complexity，则必须再补证明或独立攻击。一个有限实验、单个反例、旧输出或静态审计都不能替代另一个证据层级。

## 处置决定、未覆盖项与接续

本资料吸收 novelty-risk gate 作为写作和研究运行资源。使用时先做四层相关工作和危险 baseline 比较，再决定候选是 weakest、defensible、strengthened 其中哪一档；随后登记 cannot-claim、cautious-claim、evidence、falsifier、status 和 next minimum validation。没有外部 literature search 的情况下，不能给出“首次”或已解决新颖性判断。

本对象不创建 theorem、algorithm、hardness、gap、复杂度、反例或实验结果；不把 paper positioning 当作 priority certification；不把已有 Route Card、Research Packet 或审查结论当作自动 accepted edge。若未来采用外部文献或新实验，应另建 source/evidence 记录并重新标注最深验证级别。任何与 UM-TARGET-v1、Q-CAG-HALF 或 weighted-congestion 相关的数学结论仍回到对应 canonical 正文、证明/反例和 evidence，而不是从本技能的审查模板反推。
