# 2800B策略数据构造

policy_data(m,p,policy)按深度、同层有序字典序生成全部长度<m的历史，以普通zip配动作；源码不完整验证外部policy的长度/动作合法性，默认入口自己提供的产品枚举则满足域。逆序历史计算counts[h]：先接指定动作，若未到终端则用已算孩子的完整终局计数，否则直接计数。每个h及每个b都在新有序历史下沿同一σ真实完成，没有固定原路径的后继，也没有同计数策略净化。

每条原行用全部非空mask1至2^p−1和Fraction从定义计算，强制/规定当前动作都在终局中占用，所以有分子时分母正。代码以any(row)过滤零行，非零才保边、行和对应(h,b)见证。全类型singleton坐标区分不同当前动作，因此正常非self比较均非零；self行恰为0。程序图只收非零边端点，可能省掉仅有零环的顶点；不能将这个vertices域当成原保全部查询端点的30顶点报告。

sccs是本文件自写的Tarjan式递归：indices/low、栈及on集合，无图包；取同SCC的非零行求Fraction Gaussian秩hr。rank用有理行初等消元，是确切矩阵秩，但它不判断输入策略是否SPE。通用compositions函数及comb/json导入在默认探索中未用，不能从这些名字推断有全部收益顶点秩网格或JSON数据流程。

# 浮点成员测试与真正lineality的条件接口

lineality_rank(rows)把有理行Γ排为A的列并转float；对每条Γ_i调用一次SciPy/HiGHS：
\[
\text{找 }\lambda\ge0\quad A\lambda=-\Gamma_i,
\qquad\text{目标恒0}.
\tag{1}
\]
仅以lp.success选索引，再对这些原Fraction行求精确rank并返回rank/indices。没有保存λ、slack、dual、解释器/库版本，也没有对浮点可行性作有理恢复或逐行精确验证。因此返回的秩是**由浮点状态挑出的有理行集合的准确秩**；不能无条件称原锥lineality已被精确认定。浮点误纳或误漏成员都可能改变被选集合，后续有理消元不会补这个认证。

数学上，若(1)的全部状态能被精确认证，则所选行恰是可逆生成行。因为Γ_i本来在K，−Γ_i∈K等价Γ_i∈lin(K)；若
\[
A\lambda=-\Gamma_i,\quad\lambda\ge0,
\quad\text{则 }t=\lambda+e_i\ge0,\ At=0,\ t_i\ge1
\]
给非负映射零流正支持i；反向若At=0、t≥0且t_i>0，便有−Γ_i=Σ_(f≠i)(t_f/t_i)Γ_f，是(1)的非负解。由[完整双向空间引理](../引理/收益型映射核与真实行锥的完整双向空间--引理.md)，这些行张成整个lin(K)。该条件解释程序目标，未替原浮点success提供缺失证书，也不把SCC像空间等于lin(K)当假设。

代码既不构造非负客户w，也不检查Γw≥0、覆盖、OPT或half。即使某形式策略有额外lineality，仍需合法单位客户输入及全部真实IC才能形成CAG例；非负流表示本身也不支付一般2W−OPT。
