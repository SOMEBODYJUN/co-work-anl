# 四字段原件及其用途

150B原件恰含下列四字段，两个冻结提交同字节。完整JSON与SHA见[原件清单](../../tools/evidence/Boss7-resume-d22-provenance/source-manifest.json)。

| 字段 | 冻结值 | 能说明什么 |
|---|---|---|
| schema | 1 | 这份旧工作室元数据的格式版本 |
| save | customer-attraction | 当时研究来源位于客户吸引家族 |
| actor | R-d22a706a03c5499d941a6a97f94128a8 | 冻结路径中的旧工作区署名 |
| instance | 59a161def4bc48cba40c22ea8e77f750 | 该旧元数据的实例标识 |

文件没有模型、人数、目录、客户输入、完整策略、断言、输出、认证结果、提交回执或执行时间。不能据此给同工作区的每个脚本赋予“已运行/正确”，也不能把同一路径的两个冻结定位说成两份独立数学实现。

该目录中的counterexample、independent_pushforward、parent、exchange及round5各程序有自己的输入合同：有的消费外部终局JSON，有的内嵌客户，有的沿祖先寻找规范包。复现时应按各程序实际读取的路径重建目录和依赖；元数据只帮助定位来源，不保证任意移动后的代码能运行。具体策略、DAG、有理矩阵和原输出的责任由相应程序/计算对象承担，本资源不重复授予那些结论。

本次对照当前根work.py的actor/workspace绑定和[清洗命名规范](../../../../cleanup/OBJECTS.md)：旧来源save不改变当前repository-cleanup任务，旧actor和instance不覆盖本轮Boss7登记。旧UUID迁移与当前明确身份是不同操作，不能因为读到本文件就隐式adopt。原身份也不是本轮子代理新身份。

全部独有字段已保[原始JSON](../../tools/evidence/Boss7-resume-d22-provenance/workspace-original.json)，末换行保留；这次只有读取、来源比较及资源归档，新增数学程序、原入口与认证执行均0。关系为来源定位和运行布局说明，没有元信息到数学命题的推导边；正式超图留第三阶段。
