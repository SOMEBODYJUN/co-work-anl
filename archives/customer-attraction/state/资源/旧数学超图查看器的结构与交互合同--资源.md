# 旧数学超图查看器的结构与交互合同

## 对象、证据与历史定位

`research/build_map.py`读取旧`graph.json`，核对旧命题/审查账本及文件引用，生成一个单HTML的超边卡片查看器。它没有推导数学关系、验证证明或生成当前第三阶段的已接受关系。本页保存其全部验证分支、静态HTML/CSS/JavaScript交互、真实数据形状和一个实际解析覆盖缺口。

两冻结提交中的程序共14,336字节，SHA-256为`160da0e86b53aba6e8f731f37c149a4850c51c921a2398ab7ce4a3a7c4339fbc`。[原程序](../../../../tools/evidence/research-index-builders/original/research/build_map.py)、[真实graph](../../../../tools/evidence/research-index-builders/related/research/graph.json)、[审查账本](../../../../tools/evidence/research-index-builders/related/research/review_status.json)、[命题账本](../../../../tools/evidence/research-index-builders/related/research/current/claims.md)及[生成HTML](../../../../tools/evidence/research-index-builders/related/research/index.html)保留原字节。

本批全文读程序及模板，逐字段、逐记录核对真实JSON结构和引用；没有把1,153个节点和1,353条旧边的数学内容自动当作已读或已接受。本资源放在旧导航载体对应的存档，图中各模型仍独立。

## 命令、根路径及生成字节合同

标准库`argparse/json/pathlib`即可解析程序。`HERE`为脚本真实父目录，`ROOT`为其父目录；它先读`HERE/graph.json`并`validate(data)`，再用`json.dumps(data,ensure_ascii=False,separators=(",",":"))`生成紧凑JSON，并把每个`</`换成`<\/`，避免内容中的闭合标签直接终止脚本元素。该处理不将数学字符串解释成HTML。

模板中的`__GRAPH_DATA__`由该载荷替换，输出`research/index.html`。默认模式覆盖输出；`--check`要求旧文件存在且全文文本等于生成文本，失败提示重新生成。模板之外没有CSS、JS或字体下载依赖；但数据中的引用链接仍依赖旧仓库文件，故“单HTML查看器”不等于全部数学内容离线打包。未在共享树运行默认模式或`--check`。

## 图、节点和边的旧schema

图和审查账本均要求`version=1`。节点及边分别建ID字典，字典长度必须等于列表长度，因此禁止重复ID。`legend`的键集合必须恰等于五关系类型；值是给人的说明，程序不审其数学忠实性。

| 字段 | 允许值或条件 |
| --- | --- |
| 节点`kind` | `definition, lemma, construction, counterexample, claim, source, evidence, obligation, rejected, artifact` |
| 节点及边`track` | `model, local, shared, heterogeneous, computation, extensions, evidence, weighted_congestion, unrelated_machines` |
| 边`kind` | `derives, attacks, checks, implements, limits` |
| 节点正文数据 | `title/detail/refs/status`非空；每个`refs`在旧ROOT下是文件 |
| 边前提 | `premises`非空、无重复，各ID均存在 |
| 边结论 | 单个`conclusion`存在且不在本边前提中 |
| 边说明 | `statement/refs/status`非空；每个引用在旧ROOT下是文件 |

程序不限制边或节点除这些字段外的额外键。实际1,351条边使用标准字段，另2条还有`detail`，查看器未使用该额外字段。实际节点`status`可为任意非空长说明，不是程序证明出的真值。引用存在也没有显式路径规范化/根包含或内容hash核验。

旧程序额外强制两个全局条件：每个`kind=claim`节点必须至少作为一条边的结论出现；所有节点都必须出现在某条边的前提或结论中。它们是旧格式的覆盖要求，不是数学规则。特别是给一个真命题补任意入边不会使其证明成立，把一个资源连接起来也不会使其得到数学用途。

## 命题表解析及五轴标签

`claims.md`只取第一次`## 逻辑使用规则`之前的文本。仅处理以`| `起始的行，取第一格，跳过`ID`表头和`---`分隔行。第一格以字面`" / "`拆别名；某片段若本身是节点ID就直接使用，否则取第一片段最后一个`-`前的前缀补上该片段。此语法是旧表的特定压缩约定，不是通用Markdown解析。

解析出的`declared`必须与审查账本ID集合**恰相等**，每个注册ID的节点种类只能为`claim`或`lemma`。每条审查行的`graph_status`必须与图节点`status`逐字符串相等；五轴必须取以下值。

| 轴 | 允许标签 |
| --- | --- |
| `source_proof` | `complete, source_note, published_lower_plus_sketch, synthesis, new_current_work` |
| `current_proof` | `complete, candidate, conditional, depends_on_claims, direct` |
| `internal_review` | `multiple_audits, current_exact_audit, candidate, self_attack_and_exact_audit` |
| `external_review` | `not_recorded, completed` |
| `implementation` | `implemented, partial, none, not_applicable, finite_example, audit_only` |

这些检查只保证旧账本之间标签相容。`complete`不是检查器读完证明后得出的结论，`implemented`也不说明软件具备全部定理范围；外审标签不会由内部多次核算产生。实际640行的`external_review`全为`not_recorded`。其`current_proof`标签为608 complete、19 candidate、2 depends_on_claims、3 direct、8 conditional；这是原字段分布，非本批认证。

### 实际遗漏：逻辑标题后的一条命题行

完整冻结`claims.md`在逻辑规则段落后还有一条表格行`CA-INCIDENCE-LP-DYNAMIC-BUDGET-v1`。新全文件结构扫描确认它不在图节点，也不在审查账本；原程序却在标题前截断，因此只看到640个注册ID并能满足640=640的集合要求。

该行原始内容是：在CAG模型、任意人数、任意有限共同目录及全部有序历史纯SPE下，按包含极大主题及客户关联类型提出一个**候选**后缀预算界

$$W\ge c+(U-c)\sum_t\frac1{E_t}.$$

行中进一步声称若极大关联分数覆盖数`tau_inc<=2`则得到半覆盖，一般高密度关联时接口不足；其自标“完整解析候选，内部清洗待做，外审/新颖性未认证”，失败只否定证书模板，不否定`Q-CAG-HALF`。这里按原行保留候选身份，未给$c,U,E_t$另造定义或把这一简略行当自足引理；所链`incidence_lp_dynamic_budget.md`不是本批主源，完整数学仍须独立读。

这个发现准确指向**表解析覆盖**：原检查不能发现截断后新增的该行。它不证明候选真假，也不推断作者本意要将其纳入注册集合。可接续修正是先明确账本语法，再完整解析所有指定命题表或明确拒绝规则段后命题行，并给此类布局加覆盖检查。本批没有改写冻结程序、图、账本或当前对象，更没有自动注册这个候选。

## 真实旧图和新增结构核对

实际节点数1,153，按种类为：定义188、引理53、反例6、rejected15、构造16、claim620、artifact20、source20、evidence196、obligation19。实际边数1,353：derives641、attacks18、checks318、implements16、limits360。数量和类别只帮助定位输入，没有接受任何一条旧数学依赖。

新检查发现：节点/边ID无重复、无失踪端点、640注册ID与640审查行集合相等、已登记状态无字符串漂移；旧格式要求下无孤立节点且620个claim均有入边。所有相关结构引用都出现在冻结路径清单中。这是对真实数据的有限结构核对，没有物化所有旧引用文件并调用原`is_file()`，没有验证每条边的共同条件和数学理由。

另以AST读取源程序中的**字面HTML模板**，不用导入或执行程序，按实际原JSON作紧凑序列化及`</`转义。所得1,530,181字节与保存HTML逐字节完全相等，双方SHA-256均为`012dbe9594c8c83f0f96948d0088496dbd9957e2fe46f03d2219b439ab09be11`。这是实际模板和载荷的字节绑定；不表示浏览器交互、可访问性、视觉排版或数学真值通过测试。[完整审计](../../../../tools/evidence/research-index-builders/input-structural-audit.json)保留所有计数和例外。

## HTML外壳与显示语义

页面抬头把左侧多前提解释为共同成立、右侧为单结论。红色用于attacks，黄色用于checks/limits，紫色用于implements；其他边为青色。攻击边的中间符号为`⊣`，其他四类都显示`⇒`，所以仅看箭头形状不能区分推导、检查、实现和限制，必须读边种类与说明。抬头硬编码“共享主定理的完整主稿与现行Markdown全分支重写均经过内部审读”；这只是旧模板文案，不能对今日所有对象或外部同行评审作认证。

桌面布局是主卡片列加270–340像素粘性详情栏，内容最大宽1480像素；850像素以下改为块布局、详情栏静态；570像素以下前提/符号/结论纵排并旋转中间符号。系统字体及CSS有完整保留，本批未新开浏览器或生成截图，因此这些是代码规则，不是当前浏览器视觉PASS。

模板含搜索框、研究分支和关系下拉框、清除选中按钮、匹配数、主卡片容器及`aria-live`详情栏。数据置于`type=application/json`脚本元素。JS用`textContent`建文字、不用`innerHTML`灌入节点/边正文；来源链接统一为`../`加数据路径，新窗口打开并设`noopener`。这控制文字插入方式，但引用路径只受旧数据检查约束，不构成通用恶意输入安全审计。

## 交互的精确范围

页面以`Map`按ID找节点。初始运行`render()`展示全部边，显示“匹配数/总超边数”。所有筛选条件取交集：

1. `track`必须等于边的track，不是按节点track或模型语义计算。
2. `kind`必须等于边种类。
3. 搜索词去首尾空格、转小写，在拼成的单个字符串中作子串匹配。可搜边ID、statement、边refs、结论及前提ID和title；**不搜节点detail、节点refs、审查轴、整篇证明或所有status**。
4. 若已选节点，仅保留以它为前提或结论的边。

下拉菜单的track标签部分为英文：如`extensions`显示`Cost extensions`。实际CAG节点多在该track下；这只是旧分类复用，不表示CAG是设施费用推广，迁移时应按真实模型重新判断。

点击前提或结论按钮，设置选中ID，详情栏显示其title、ID/kind/status/track、detail及全部节点refs，再列incoming和outgoing边的数量及ID/关系/statement链接。关系链接仅跳到现已渲染卡片的`#edgeID`，没有按URL hash恢复选中状态的监听或持久化。当前筛选仍可能隐藏某张相关卡片；点击关系ID本身不会清除筛选。

每张卡片保留前提列表的共同输入、唯一结论、边status、track、statement及所有边refs。无匹配时显示空结果提示。搜索与下拉框监听`input`立即重画。清除按钮只把selected设空、隐藏自身并重画；**不会重置搜索/下拉框，也不会清空或恢复详情栏文字**，所以清除后详情仍可能显示旧节点。这是实际代码行为，不应写成“重置全部界面”。

## 当前第三阶段的明确差别与关系判断

现行[图协议](../../../../map/README.md)使用稳定对象ID、可多源多目标的`source_ids/target_ids`，每条关系须有`kind/explanation/conditions/evidence/status/reviewed_by`及逐边实际斟酌。允许未知或孤立对象，不要求每命题有入边。第三阶段先读整理后的自足对象，再建立全仓、存档、子存档投影；当前草稿种子不直接继承旧图。

因此不能把旧1,153/1,353表直接换键导入：旧边只有单结论，缺少当前独立共同条件、实际审读者和接受状态协议；旧自由status不是accepted；`checks`有限检查不能变成implies；同track、同编号或相邻人数不能替代数学依赖。旧强制连通和claim入边要求尤其必须留在历史合同中，不能拿来要求当前图造边。

这个查看器与[来源解释表](旧路径解释账本的覆盖与生成合同--资源.md)、[资产巡检](旧资产巡检的文件角色与哈希边界--资源.md)共同说明旧导航/结构检查如何工作。已知关系是程序实现旧显示合同、新有限检查绑定实际模板及载荷；对各数学对象的推导关系没有本批新增接受。接续可复用卡片交互思想或字节转义，但需明确采用当前schema、处理孤立对象和多目标，并单独验证新界面，不以旧生成成功承担数学审查。
