# 旧路径解释账本的覆盖与生成合同

## 对象和使用范围

`research/build_crosswalk.py`是旧树“每份原来源如何被保存及解释”的Markdown生成器。它从两个JSON账本建立路径覆盖合同，再把解释文字排成表；它没有读懂被链接的证明，也没有验证解释是否忠实。本文保存该程序的全部分支、实际输入形状和输出边界。资源承载在客户吸引存档，是旧全仓导航的历史位置；表中的设施、拥塞、调度等来源不因此成为客户吸引的子模型。

两冻结提交中的程序同字节，共6,355字节，SHA-256为`6cd25f45abd9faa0c5d3fd06e819643b71e19fea6a756915a261cce37c32d355`。[原程序](../../../../tools/evidence/research-index-builders/original/research/build_crosswalk.py)保留原字节；[真实解释账本](../../../../tools/evidence/research-index-builders/related/research/source_crosswalk.json)、[迁移表](../../../../tools/evidence/research-index-builders/related/research/path_migration.json)及[生成表原件](../../../../tools/evidence/research-index-builders/related/research/source_crosswalk.md)独立保存。原件路径是旧树语义，未为本树改写。

本批全文读程序；对实际JSON逐字段、逐记录作结构和引用核对，读迁移表全部内容，并检查实际680行生成表的字段绑定。此范围不把606份新增来源、其所链数学正文或账本中的主张一并声明为已完成语义清洗。

## 读取、写入和失败方式

程序只用Python标准库`argparse/json/pathlib`。`HERE`取脚本自身解析后的父目录，`ROOT=HERE.parent`，因此它不以调用者工作目录作为数据根。`render()`读取`HERE/source_crosswalk.json`和`HERE/path_migration.json`。默认命令生成并覆盖`HERE/source_crosswalk.md`；`--check`仍先完整计算结果，只在已有输出文件存在且文本逐字符相等时通过，否则抛`ValueError("run research/build_crosswalk.py")`。最终以一个换行结尾。输出不是JSON语义等价比较，旧文件中额外空行或表格排序变化也可触发失败。

原脚本不会运行数学求解器、联网、提交Git或发送消息，但默认写文件，故本批未在共享结果树调用。没有调用冻结程序的`render()`或`main()`来伪装一次完整旧树复现。

## 迁移来源的精确覆盖合同

记`M=migration["moved"]`、`R=migration["retired_code_paths"]`，待覆盖旧路径集合为

$$O=\operatorname{keys}(M)\cup\operatorname{keys}(R).$$

程序把`data["entries"]`按`original`建字典，并要求字典长度等于原列表长度且键集合恰为$O$。这同时禁止旧路径重复和漏登记；**不要求两个迁移字典的键彼此不交**，合并字典`{**M,**R}`若重键会取后者。实际输入无这类覆盖冲突，58条`moved`与10条退役代码共68个原路径。

对每个旧路径，程序要求：

1. `preserved_at`等于迁移表目标。
2. `rewritten_in`以`research/current/`或`research/questions/`开头。
3. `interpretation`非空。
4. 两个目标均满足`(ROOT/path).is_file()`。

这里的“新写解释”由路径前缀、文件存在及非空说明表达，没有证明内容比对，也没有检查内容SHA、作者、审查人、下载记录或数学结论。`is_file()`仅说明该时刻文件存在，不能替代冻结版本绑定；路径拼接本身也没有显式`resolve().is_relative_to(ROOT)`防逃逸检查。不同于本页保存的SHA合同，原生成器不校验hash。

68条按**保存目标**前缀分类，不按原路径、数学模型、结论真假或来源新旧程度分类。固定顺序如下。

| 生成小节 | 保存目标条件 |
| --- | --- |
| 原手稿、笔记、审计与旧路线 | `history/` |
| 输入、证书与冻结记录 | `examples/`或`evidence/` |
| 测试和审查代码 | `tests/` |
| 规范实现 | `facility_spe/` |

各类按原`entries`列表顺序遍历。`accounted`避免同一旧路径重复落表；处理后要求`accounted==O`，所以存在于迁移表却落在四种前缀之外的记录会失败。该列表没有`multi_facility_spe/`或`customer_attraction/`分组；不能凭“规范实现”标题推断覆盖所有后来包。每行输出旧路径、保存位置、新解释位置和判断，旧路径与解释文字中的`|`转成`\|`。链接路径本身没有通用Markdown转义。旧路径以反引号显示，文件链接统一从`research/source_crosswalk.md`经`../`回旧根。

## 不属于旧路径迁移的新增来源

`new_sources`缺省为空。实际输入有606条，每条字段恰为`source/provenance/rewritten_in/interpretation`。其合同是：

- `source`不得在此列表重复，必须在`history/`下；现行解释在`research/current/`或`research/questions/`下。
- `provenance`和`interpretation`非空，源和解释文件都存在。
- 以单独“新增来源（不属于旧路径迁移）”小节输出，不虚构一个曾存在的旧路径或下载记录。

这一分支保留对话摘录等新来源的来源说明和去向，**不检查说明的真实性**，不验证它是否确为新增，也不阻止其与另一小节提到同一实体文件。源路径唯一性仅在该列表内成立。来源文字和解释文字中的竖线会转义，路径和其他Markdown特殊字符并未全面规范化。

实际账本`version=2`，但程序没有检查顶层版本。顶层`sources`数组实际为空，生成器从未读取它；不能把它当作额外覆盖分母。68条迁移记录中66条是四字段，另2条带`archived_original_path`；该额外字段保留于原JSON，但旧生成器不读取或显示。

## 历史编辑判断的独立分支

实际`historical_records`有6条，均含`original/preserved_at/kind/interpretation/related_accounts`。这一分支特意避免把过去的投稿、方向选择或编辑意见当作现行证明：生成表说明相关页仅用于理解背景，不覆盖现行目标、审查或新颖性状态。

程序要求保存路径在本列表唯一、以`history/`开头、文件存在，`kind`恰为`historical_editorial_assessment`，说明和关联解释列表非空；每个关联解释必须在`research/current/`或`research/questions/`下且文件存在。`original`作为历史标签原样显示，不要求旧文件仍存在，也未检验其唯一性或真实性。关联多个背景页只生成多条导航链接，没有把它们合成一个数学推导。它不比较上述历史判断和今日状态是否相符，更不决定新颖性或投稿价值。

## 实际输入与新增有限检查

本批保存了两输入、原生成表及全部主源精确SHA。新写的[结构审计程序](../../../../tools/evidence/research-index-builders/inspect_inputs.py)只在本批证据目录运行一次，不导入旧生成器。它以实际JSON字段构造每一数据行，核对迁移集合、唯一性、目标对应、四类分类及顺序。

| 检查对象 | 实际结果及含义 |
| --- | --- |
| 迁移集合 | 58移动+10退役代码=68；原路径无重复，集合相等，保存目标无不一致 |
| 迁移分类 | 68条均属于四类目标前缀 |
| 新来源、历史判断 | 606条和6条，字段形状全部清点 |
| 生成数据行 | 实际680行与独立构造的680行逐行、顺序完全一致 |
| 其他迁移元数据 | `first_curation_retired`8条、`retired_test_entrypoints`7条、`reestablished_root_docs`3条；不计入本生成器的68条分母 |

本批还把相关JSON的15,535次路径引用、2,754个唯一路径与冻结清单全量核对，未发现清单中缺失项。**这使用精确冻结文件索引，不等于已把2,754份文件全部物化并执行旧脚本的`is_file()`检查**，也不等于逐份数学阅读。完整数据、每字段类型计数、引用明细和检查限定见[审计记录](../../../../tools/evidence/research-index-builders/input-structural-audit.json)。本次没有声称运行原脚本`--check`通过；680行绑定也不是整份Markdown外壳字节相等的声明。

## 与现树及先有资源的关系

[仓库读取地图与退役双来源恢复](../资料/仓库读取地图与退役双来源恢复--资料.md)保存分层导航、资产责任和退役恢复合同。本页补的是其所提来源解释生成器的真实集合、分组、错误边界和输出算法，并未再次处置已经done的`research/README.md`。两者只有导航与来源恢复互补关系。

旧表的`rewritten_in`指向旧树的“现行数学”，不自动迁移为当前三阶段的自足对象，也不构成逐源semantic receipt。当前应先读源和相关数学，保存独有内容，再按真实来源逐条处置；旧表只提供恢复线索。58/68/606等是冻结账本计数，不是本树完成数。若以后迁移生成器，需显式换用新路径及版本协议、保留解释与来源字节，并逐条审查解释是否仍忠实；不能单凭680行结构一致把所有源勾完。

可确认的关系是：这个程序**实现**旧解释表的格式合同，新有限检查**检查**真实数据行与该格式的绑定。尚未逐读680条所链数学，故不为这些数学建立推导、反驳或推广边。当前第三阶段允许孤立对象，不为导航连通制造因果关系。
