# 审查阅读与命题模板的精确合同

这两份短源是作者审查协议和命题写作模板，没有独立数学定理。以下完整保留，并按现行模型解释其可复用部分。旧审查 README 的 active Q-CAG-HALF 是历史任意人数任务；当前 AGENTS 的 Q-CAG-HALF-6 精确六人优先。清洗者/Boss/editor 是旧协作角色，不是数学证明前提，也不自动要求候选先经表决才可保存。

审查的承重问题是：实际对象/量词/全部假设是否一致，证明有无未覆盖反例和退化，算法复杂度按什么编码，软件核查究竟覆盖什么输入，是否真实读取了相同版本。赞同票不能代替证明；旧稿不同既不自动错误，也不能无条件迁移到新模型。source proof/current proof/internal review/external review/implementation 的五轴应保持独立。

claim 模板要求精确输入和上下界量词，特别是下界“每个更小因子有实例”。假设须先合取再给结论；不能把程序、历史文档或审查状态作为数学前提。构造一个因子、证明普遍最优及验证实例达到三个任务分开。复杂度要给有理/整数位长，唯一性、并列点、零端和 gap 不能略去。测试应绑定代码、真实输入、证书与冻结输出；新原材料注明日期及来源。

模板把设施个数/目录等列作示例，不适合作为 CAG 的唯一字段清单。当前正式资源用 cleanup/OBJECTS.md 的平坦 MATEK 元数据；本页保留旧模板语义，不覆盖模板原件，也不把旧 reviewer 判断算作外部同行评审。

```markdown
# 独立检查与清洗记录

当前主攻 **Q-CAG-HALF**，存档 **customer-attraction**。实际检查从[客户吸引审查目录](customer_attraction/)沿对应Claim和正文读取；结果状态在[五轴账本](../review_status.json)，范围在[精确账本](../current/claims.md)。

清洗者负责检查对象、量词、推导、反例、复杂度、证据和真实异议，并将可复用内容写成自足资产入库。检查必须注明所读版本、实际覆盖和未覆盖义务；多票赞同不能替代证明。探索、讨论和候选保存不以审核通过为前置条件。

| 保留审查 | 使用时机 |

| [客户吸引](customer_attraction/) | 当前已证子题、策略计算和失效桥梁 |

```

## 完整原文：research/templates/claim.md

```markdown
# 命题 ID：标题

- **状态与版本：** 候选 / 直接推导 / 外部独立复核 / 已发表事实；记录日期与变更理由。
- **输入类：** 设施数、目录关系、可达结构、客户权重与编码、参与规则、成本函数、局部均衡概念。
- **量词与结论：** 对每个输入、存在何种地点与完整延续、输出什么因子；如为下界，写“对每个更小因子存在实例”的确切量词。
- **不覆盖的情况：** 列出最近的边界实例和不能使用的推广。

## 定义与引理

按顺序列出全部前提；每条引理写自己实际使用的条件。将依赖图中不同来源的条件在结论前合取，不能把测试、程序输出或历史稿当作证明前提。

## 证明或待解决义务

写可以逐式检查的核心论证。未独立验证的环论证、唯一性、位长、边界退化等分别标成明确义务，给出原稿的节号供复核。

## 算法及证书

写输入格式、伪代码、正确性所依赖的引理、算术运算量与位长。区分构造某个因子、求实例最优，以及验证某个实例达到的因子。

## 证据和来源

列规范代码、测试、输入、证书、冻结报告及历史原稿的准确路径。记录审查未覆盖的范围与已知反例；新原始材料放入 history/source/ 并保留日期与来源。
```
