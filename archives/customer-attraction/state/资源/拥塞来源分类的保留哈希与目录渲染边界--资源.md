# 拥塞来源分类的保留哈希与目录渲染边界

## 主源、真实分类及作用

`research/check_wc_assets.py`是旧加权拥塞分支到规范文件的分类检查与FILES.md渲染器。它核来源键覆盖、退役理由、六文件角色、部分后缀的实际hash，再依赖人工目录生成分包清单；它不证明全状态结论、不检查所有论文/代码正确性，也不认证外审。

两个冻结提交的程序同字节，3,453字节，SHA-256=`fb7746a368f6063997a91c29f9f98b09371a847c305a07f06723ebd2ee330fb0`。[原程序](../../../../tools/evidence/active-catalog-checkers/original/research/check_wc_assets.py)全文实读。实际INTEGRATION.json为194,010字节，170 source_files键和170 classification键；真实FILES.md为534,265字节，目录中WC主题501行。JSON逐字段/记录结构及原SHA保留于[证据目录](../../../../tools/evidence/active-catalog-checkers/README.md)，没有把170个源或501项所链数学自动done。

## 导入、根路径、写入与失败

程序用标准库argparse/hashlib/json/pathlib，从同目录`build_catalog`导入load_data、validate、render_topic。ROOT为脚本parent.parent，SCOPE固定research/weighted_congestion_frontier。主流程读取ROOT/SCOPE/INTEGRATION.json；默认模式覆盖FILES.md，`--check`要求现文件文本等于render(data)结果。

主检查大量使用Python `assert`，包括来源集合、角色前缀、hash和最终文本一致；用`python -O`运行会移除这些断言，不能把该模式的打印当同等检查。load/文件读取以及build_catalog.validate中的显式ValueError仍可能失败。普通模式任一断言或读文件错误可直接终止，没有继续产成功报告的恢复分支。本批未执行原程序任一模式，也不运行其模板提到的replay命令。

## 来源键完整性与六种角色

先要求`set(data["source_files"]) == set(data["classification"])`。它保证每个已登记来源键有处置、没有额外分类键；不证明source_files已经枚举所有原分支文件，也不验证branch/commit是否可达、所列hash是否当时真实。

每个classification项若没有path，则必须`disposition="git_history_only"`且reason非空；随后continue，不读取文件、不检查role、不要求旧路径不存在。若有path，则必须以对应role允许前缀起始，随后无论后缀都实际`read_bytes()`，缺文件即失败。

| 分类role | 允许目标前缀 |
| --- | --- |
| audit_code | tests/ |
| frozen_evidence | evidence/ |
| review_record | research/reviews/ |
| candidate_or_obligation | research/questions/ |
| mathematical_account | research/current/ |
| source_or_audit | history/、tests/、evidence/ |

这里只作字符串前缀判断，没有独立规范相对路径/解析后根包含检查。目录路径本身不能被read_bytes作为文件读取；但路径越界或软链接问题并未通过此角色表全面排除。目录生成器对catalog路径另有更强规则，两个检查阶段不能相互混称。

实际164个带path项的角色数量为：audit_code45、frozen_evidence48、review_record27、candidate_or_obligation10、mathematical_account28、source_or_audit6。输出count只统计这164个保留来源路线，不等于164份独立定理、实现、审查或所有数学资产；501目录行来自另一目录输入，两个分母不同。

实际6个git_history_only键依次为旧UNIFORM_COHORT_FAMILY.md、UNIFORM_COHORT_FAMILY_V2.md、independent_parameters.md、integer_family_review.md、旧research/current/weighted_congestion_frontier/README.md和tests/test_wc_asset_roles.py。完整旧路径和各退役理由在原JSON保留；旧参数family/重复导航退出当前树不表示其独有数学可以不读，退役路径也不证明代码失败。

## hash分支的精确范围

只有目标名以`.py`或`.json`结尾时，程序才计算实际bytes的SHA-256，要求该值属于`source_files[old]`所有记录的sha256**值集合**。多个源版本只需其中一个匹配；不要求逐条版本都相同，也不要求与某个指定branch/commit同一条记录绑定。其他后缀（如Markdown）虽实际读字节，却不在该hash分支中比较源hash。

此处与旧总资产检查器不同：旧check_assets只要求运行清单source_sha256字段非空，而本程序对这两个后缀确实重算当前内容。但它没有验证这些内容的语义或运行行为，hash相同不把一个有限审计变成一般证明。source_or_audit允许history/tests/evidence，也不把history中的源码升级为规范实现。

本批新检查识别97个py/json保留项，两个冻结文件索引中的目标hash均属于对应来源hash集合；**这97项是冻结元数据比对，不是把97目标文件全部物化并重跑本程序的实际read/hash**。本批实际读取hash的28退役原件属于活跃路由检查的另一合同，不能借其成功替代这97项。

## 渲染依赖和输出结构

`render(data)`的data参数未用于构造目录正文；它另行`load_data()`读全仓catalog，`validate(catalog)`要求完整旧命名集合和实际文件，然后`render_topic(catalog,"weighted_congestion",SCOPE)`生成WC分包表。INTEGRATION主用于前面的分类/hash，不是501行的直接排版来源。要完整复现，除INTEGRATION还须catalog/assets、被目录必备集合约束的旧文件及真实脚本根；仅给该JSON不足以运行旧`--check`。

输出外壳给出：先读当前WC数学地图，按成果包取正文/问题/边界/实际审查/代码/冻结证据；名称用途来自人工命名登记而非basename猜测；文件角色不代替审查等级；原稿pending标签保留历史时点；原分支/commit/hash/去处/原因在INTEGRATION。它链接CLAIMS、五轴账本、全仓目录，并给`tests/audits/weighted_congestion/replay.py --list`及旧相对布局只在临时目录重建的说明。

这些命令是来源的恢复教程，不是本批实际重放记录。本批没有调用replay、做浮点筛选、有限精确数学检查或一般证明审查。冻结证据仍不覆盖。

外壳结尾明确三项未找到来源：`resource_cone/review.md`、`nonseparable_frontier/proof.md`及所引未见程序、`r2_orbit/review.md`；禁止补造已审/已证明。这里只保存旧快照的“未在已观察分支找到”事实，不升级为今日所有可能分支都不存在，也不覆写别处后来实际交付的证明。原参数旧family和重复导航由不可变提交恢复，不把Git祖先自动当作当前数学认证。

## 新有限核对与完整复现边界

本批全文读该程序与build_catalog，实际INTEGRATION全字段结构和170项处置、目录/资产字段集合均检查。source_files/classification键集相等，164保留、6无path显式退役；新独立静态渲染以真实catalog/assets和字面常量重建全部501行，实际FILES每行及顺序一致。全部2,099行总目录也同样绑定。

新检查没有调用旧render/validate，没有声称FILES全文外壳逐字节相等或原程序`--check`成功。旧完整树未物化，97文件未全读/hash，构建器与子suite未运行；这一边界如实保留，不用替身文件或标记制造PASS。[结构审计](../../../../tools/evidence/active-catalog-checkers/contract-structural-audit.json)逐项存角色、hash元数据匹配和生成行结果。

## 与当前正文、关系及接续

[中文资产目录合同](中文资产目录的命名覆盖与渲染合同--资源.md)是本生成器的真实渲染依赖；[旧资产巡检](旧资产巡检的文件角色与哈希边界--资源.md)又以`--check`调用本程序。这里有程序调用/格式实现/有限检查关系，不是WC定理到CAG半覆盖的数学关系。现阶段不复制旧图或源分类为已接受边，不把同一个包里的证明、候选、review、代码、结果并成一条统一“完成”。

后续如需旧suite复现，应隔离重建全真实依赖，固定解释器是否禁用assert、源commit、输入和输出路径；已有同SHA成功run无疑不重复。本资源已保存程序和真实数据的语义边界，不以当前环境新增PASS为其完成前提。来源缺口、条件结论和外审状态只能由后续实际证据更新，不能由目录生成消除。
