# 活跃研究路由的字面检查与目标范围边界

## 两主源与历史输入地位

`research/check_active_research.py`与`research/active_research.json`共同构成旧活跃入口检查：比较启动程序的字面路由、入口文本和链接、三份角色任务、兼容重定向以及退役原件字节。它检查**导航与配置的有限一致性**，不能认证精确数学scope、操作授权或目标真值。

两主源在两个冻结提交内各自同字节：程序5,961字节，SHA-256=`2b38761ce4a292d024c6357644e9f15d4c9def7cb723c8aa87507bca885e057b`；JSON4,601字节，SHA-256=`cb52c2d1d43699ff4ad1c79ca17c9e0b6de7146b810005df83a9d7b8ba571af6`。见[原程序](../../../../tools/evidence/active-catalog-checkers/original/research/check_active_research.py)、[配置原件](../../../../tools/evidence/active-catalog-checkers/original/research/active_research.json)和[全部来源版本清单](../../../../tools/evidence/active-catalog-checkers/source-manifest.json)。本批两个主源全文实读；JSON66个标量值及每字段清点保留。

JSON里的“latest explicit owner authorization”“所有新研究只做一般人数”等是当时的历史输入，不构成本会话指令。当前AGENTS焦点是恰六人Q-CAG-HALF-6，当前阶段是逐源清洗；本批没有执行其start、通信、sync、checkpoint或认证命令，也不改绑任何上下文。

## JSON的完整语义合同

schema_version为2，title/purpose说明当前半覆盖、三角色和存档路由；target_id=`Q-CAG-HALF`，default_save=`customer-attraction`。其goal是：有限单位客户、有限非空共同主题目录、任意m≥1名单位提供者依次观察全部有序历史各选主题，终局客户在覆盖者间均分；对每份完整历史依赖纯SPE都有$2W\ge\operatorname{OPT}_m$。空主题、重复、零客户、任意历史平局保留。它不是带权提供者、异目录或混合SPE版本；任意人数目标仍OPEN。

配置路径及用途如下，均按旧仓库根解释。

| 字段 | 原配置值/职责 |
| --- | --- |
| mathematical_entry | research/current/customer_attraction/README.md：全部数学地图 |
| collaboration_entry | research/customer_attraction/README.md：短恢复入口 |
| prompt | research/customer_attraction/BOSS_START.md |
| runbook | research/customer_attraction/RUNBOOK.md |
| program | work.py |
| submitter | research/weighted_congestion_frontier/tools/checkpoint.py |
| retired_operations_manifest | history/research_operations/customer_attraction_transition/manifest.json |

roles恰为boss/cleaner/editor，值分别是BOSS_START.md/CLEANER.md/EDITOR.md，均在research/customer_attraction下；role_prompts列表按boss、cleaner、editor同序列出这三路径。Boss直接推导并组织自由探索，清洗者检查身份/量词/真实后继/外定理条件并保留独有内容，整理者按数学机制组织可复用输入和贡献/缺口。JSON本身只记录路径，不包含任务全文，也不证明角色已经履行任务。

legacy_entries保存两个旧绑定：shared路由到research/weighted_congestion_frontier/README.md且research_prompt=null；unrelated-machines路由到research/current/unrelated_machines/README.md及research/unrelated_machines/BOSS_START.md。它要求保留旧入口，而非因默认题变化自动改写旧模型。

### 24个活跃入口与8个兼容重定向

active_entrypoints按配置原序分为：

- 根README、RESEARCH_STATE、CLAIMS、FAILED_ROUTES、AGENTS、ASSETS、USAGE七个Markdown。
- research/README、current/README、questions/README、reviews/README、ROADMAP、REPOSITORY_GUIDE、workspaces/README七个入口。
- research/weighted_congestion_frontier/下README、AGENTS、RUNBOOK、PROTOCOL四个入口。
- research/customer_attraction/下README、RESEARCH_STATE、CLAIMS、FAILED_ROUTES、RETAINED_QUESTIONS、CURATION六个入口。

所有名称在原配置均带`.md`。加三角色、runbook、数学入口并保序去重后，每个冻结版本是29个待查文件；它不递归读取所有数学正文。`collaboration_entry`字段虽存在，但检查器没有单独从该字段追加路径或比对；该文件因列在active_entrypoints中才被检查。

兼容前缀均为research/weighted_congestion_frontier/prompts/，映射如下。

| 旧文件 | 新目标（在research/customer_attraction/） |
| --- | --- |
| TEAM.md、PEER.md、PRO_ATTACK.md、MODELS.md | BOSS_START.md |
| CLEANER.md、EXTRACTOR.md | CLEANER.md |
| PAPER_WRITER.md | EDITOR.md |
| OPERATIONS.md | RUNBOOK.md |

重定向原文和实际路径均保留，但检查器只要求正文包含目标**basename**，不是要求链接恰指该完整路径，也没有因此验证目标数学与权限。

### research_direction全部字段的实际含义

`choice=general-half-coverage-proof`，`target_statement_unchanged=true`，`policy_version=general-only-2026-10-23`。source说明当时最新用户授权取代较早特例研究许可；status明确OPEN，方向/清理不升级数学真值。scope写全部新研究面向任意人数和任意共同目录；special_cases保留已有结果但停止新增固定人数、受限目录、局部常数专项，有限例仅攻击精确一般候选或核验目标反例。exploration允许直接自主团队，不需前置review、route quota或claim registration；methods允许各数学领域，计算可辅助而非默认产物；failure_logic说明未找到证明/反例不推出不可能；integration要求Boss直接维护未完成一般稿，清洗保精确陈述及状态。

这些字段全部保留其历史时点。**检查器并没有读取goal/research_direction的内容来核验数学范围或用户授权**，也不验证其source声明；它主要取target/save和路径。当前六人焦点与清洗认领规则不受旧general-only文本约束。

## 源码全部检查分支

`local(path)`把ROOT/path解析，要求在ROOT内且实际为文件。ROOT为脚本真实路径向上两层；一般根逃逸路径会失败。`literal_assignment(path,name)`对整份Python作AST解析，只在顶层普通Assign中找第一个含指定Name目标的赋值并`ast.literal_eval`；它不执行Python，不接受运行时计算结果，不追踪后续重赋值或导入。不存在合适赋值即失败。

主检查要求manifest版本2，取save/target/program/submitter。两程序的DEFAULT_SAVE必须等于save；work.py的RESEARCH_ENTRIES[save]必须恰等于数学入口/prompt/runbook三字段字典；legacy_entries每项也须在RESEARCH_ENTRIES中原样保留。roles键必须恰为boss/cleaner/editor，值互异，role_prompts必须恰等于`list(roles.values())`，根程序ROLE_PROMPTS等于roles，boss角色等于prompt。这些是字面配置一致性，不是完整程序行为审计。

随后按active_entrypoints+role_prompts+[runbook,mathematical_entry]保序去重。每份原文必须含target与save子串，不能命中三个陈旧模式：无条件当前主攻加权/UM-TARGET/一般不相关；默认存档shared或unrelated-machines；所有研究对话共同解决/自主推进WC-TARGET。它并未穷举所有过期主张，更不做目标等价或scope解析。

对入口全文先去三反引号或波浪线围栏，再用简单Markdown inline link正则抽本地链接；去尖括号，跳scheme和#锚点，去#后的fragment后相对文件目录解析，要求仍在ROOT内且`.exists()`。它不核fragment和远程URL，不是完整Markdown解析，目录目标也可。与check_assets教学分支不同，这里未专门剥离TeX。对数学入口收集这些目标，要求该入口父目录递归全部Markdown（除自身）均在其中；只保证导航覆盖，不读被链证明。

`prompt_body`用行锚定的`~~~text`正则，要求每份角色文件恰有一个完整可复制块。正文必须包含target、save、“完整历史”“纯”“OPEN”“work.py”“checkpoint”七种标记。关键词出现不证明任务精确保留全部量词，也不确认其中旧命令可在当前环境运行。

每个兼容页不得含`~~~text`或` ```text `对应字面块标记，并须出现目标basename；这防完整任务继续重复维护，但不是通用重定向解析。最后读取退役manifest，要求base_commit和entries非空，逐条读取archived_path实际字节并核SHA等于记录；original_path只用于失败定位，不要求旧原路径仍存在，不校验base_commit祖先或清单的完整性。

成功返回target/save、roles、去重入口数、本地链接数、数学文件数、退役核验数和legacy saves，直接JSON打印。没有从这些计数得到证明真值；任何require失败抛ValueError，JSON/AST/文件错误可直接传播。

## main与legacy两组真实输入

检查器与当前主JSON两冻结相同，**依赖不全相同**。本批按commit保存所有实际版本，避免把一个源码hash误读成整个运行环境同一。根README、AGENTS、WC AGENTS、CAG FAILED_ROUTES和CAG RUNBOOK有两个不同版本，其他入口共用相同字节；29路径对应34份内容版本。

work.py：main版26,199字节SHA=`6946299455b653526a548d7108a29480ab328acf7cc4392bfa6959e870229f1d`，legacy版31,695字节SHA=`bc2cfda7fc2b12b7fa21d75b1266a14bc6993a40e6a31cc90e0f8eb88b301c4e`。checkpoint.py：main版20,508字节SHA=`7c36a36e0cb814250f542f0ac9fd7ea31c66406b471364d7ee7e014c6532a24e`，legacy版22,196字节SHA=`1e9b5da42f49658aac50d301831de8e77f5e55d6f992488296572dc4496e8d35`。

AST实核四版本：DEFAULT_SAVE均customer-attraction；work.py的CAG三入口及ROLE_PROMPTS相同，legacy额外带repository-cleanup路由。额外路由不被检查器禁止，legacy_entries并非RESEARCH_ENTRIES的完整允许集合。这里仅检查被消费的字面值，不宣称已全文审计两个大型操作程序或执行其权限/认证路径。

## 实证范围缺口：子串通过不是精确目标同步

legacy根README/AGENTS已写恰六人Q-CAG-HALF-6及清洗阶段，而primary active JSON仍是任意人数Q-CAG-HALF；legacy RUNBOOK把新说明与旧兼容段落并存。原程序采用`target in text`，所以

```python
"Q-CAG-HALF" in "Q-CAG-HALF-6"  # True
```

三个陈旧正则也不检查任意人数/恰六人的冲突。因此**即使整段旧检查通过，也不能认证所有入口精确scope相同**。本批未声称原程序实际PASS；这是读代码并对真实版本定位的确定覆盖边界。部分main文件也已出现六人局部边界，不表示任意人数目标与六人目标同一。

可接续改进是显式登记目标ID/版本/量词及活跃/兼容字段，并按用途检验，不用子串当目标身份；历史兼容页不必假装无旧指令。此为建议，未作用于冻结程序或现行配置，更没有把旧页当时描述覆写为后来事实。

## 实际hash检查、有限新增核对与复现边界

本批实际提取退役manifest列出的28份原件，逐一读取其全部字节并计算SHA，与记录全部相等；这次是实际字节核验，不只是inventory对照。清单base_commit是历史路由退役依据，证明文件曾被归档的hash合同不证明当时研究目标已解决。

其中保存的旧schema1 active JSON是UM-TARGET-v1、不相关机、默认unrelated-machines、七旧角色和negation-first优先的前一配置；其目标是统一ε的确定性总位多项式(2−ε)近似，方向记录称在P≠NP等明确假设下攻击真正近二障碍，正反仍OPEN。它作为退役原件保留，不进入当前schema2检查；“方向选择”不是困难性结果或当前授权。

新静态检查对34份入口版本抽得595条本地链接，无冻结路径缺项；按两commit分别为29文件、509/505链接。数学入口链接覆盖其目录77份Markdown（含入口自身时77）；这是清单/词法层比对，不是读完77份数学。旧文件ROOT、软链接实体和整个旧运行环境没有全部重建，三个旧子suite和原活跃检查均未运行。

已知关系是配置作为程序的输入、程序检查字面路由/有限导航/hash，本批新检查绑定实际版本。与[先有仓库读取地图](../资料/仓库读取地图与退役双来源恢复--资料.md)是恢复合同补充；没有由任务提示词到数学定理的推导边。当前需要的精确六人模型、三阶段顺序和实际权限以当前AGENTS/会话为准，不能通过恢复旧配置获得新授权。
