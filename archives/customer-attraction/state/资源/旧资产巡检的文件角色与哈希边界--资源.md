# 旧资产巡检的文件角色与哈希边界

## 资源身份和实际读审范围

`research/check_assets.py`是旧树的文件、资产角色、命题登记、教学链接、迁移和部分证据hash巡检器。它负责多个元数据合同的交叉连接，不读取数学推导，也不运行所有测试。本文按实际程序全部分支保存条件、真实输入、依赖子程序及成功输出的证明边界。

两个冻结版本的程序同为10,213字节，SHA-256为`b91499b187578b43d5f1c832ed7179974140f485ff70fa50720350f17d16d4cf`。[原程序](../../../../tools/evidence/research-index-builders/original/research/check_assets.py)与[证据索引](../../../../tools/evidence/research-index-builders/README.md)保留原字节、全部真实JSON字段清点、实际输入和限定记录。全文读主程序及其三个子程序；实际JSON全记录结构与引用均检查，33份学习Markdown作真实链接输入核对。本批不额外处置其所链全部数学、每条旧图关系或所有代码实现。

该程序没有`--check`开关：作为脚本运行即调用`check()`。它自己不重写元数据，但读取旧Git工作树并依次启动三个子检查，其中两个以`--check`模式运行。调用者不能把“不带写函数”误读为适合在任意现树完整执行；它预设旧布局，和当前`archives/map/cleanup/tools`结构不同。本批没有执行原主程序或旧子suite。

## 入口、真实输入及异常传播

`ROOT=Path(__file__).resolve().parents[1]`固定在脚本的旧仓库根；`load(name)`只从`ROOT/research/name`读UTF-8 JSON。`require`失败统一抛`ValueError`，JSON/键/类型/文件错误可直接传播。程序没有捕获失败后降级的流程，三个子命令用`check=True`，任一失败使主程序失败。

主流程直接读取`assets.json`的`entries`、`graph.json`、`review_status.json`、`path_migration.json`、`source_crosswalk.json`、`catalog.json`和`learning/manifest.json`，并读取33份学习Markdown、实际引用文件、Git文件清单和固定日期运行清单。实际资产351条、旧图1,153节点/1,353边、审查640条、目录2,099条/35个改名记录、学习33模块。它不检查所有这些JSON的版本号；学习manifest单独要求schema_version=1，图等更深约束分属其他程序，不能因本脚本读取就声称都验证了。

## 教学入口检查与其词法边界

`check_learning(node_ids)`要求manifest版本1、`as_of`和`scope`非空。每个模块路径必须以`learning/`开头、`.md`结尾、不重复且文件存在；`title/role/canonical_readings`非空，`claims`集合包含于旧图节点ID。每项canonical reading必须以`research/current/`开头且是文件。最后，manifest路径集合必须**恰等于**`learning`递归下实际全部`.md`，防止漏列新增学习页。

读取每份内容后先用正则移去三反引号代码块、美元或方括号形式显示数学，再移去美元或圆括号形式行内TeX；这是为避免TeX区间后圆括号被误当链接。随后只识别非转义`[单行文字](无空格且不含右括号目标)`形式的链接。具有scheme前缀或以`#`开头的目标跳过；本地目标在第一个`#`前截为文件名，相对模块目录解析，要求解析结果仍在ROOT内且`.exists()`。

因此它不验证远程URL、页内锚点、图片布局、引用式链接、HTML链接或所有合法Markdown变体；本地目标可以是目录而非`.is_file()`。正则的TeX/代码剥离也不是完整Markdown/TeX语法解析。实际273个被此规则识别的本地文件链接都在冻结索引中，33模块无未知claim ID。这个结果不证明学习数学正确、公式渲染完好或字体可见。前批已记录完整学习HTML的字体规则吞并缺陷；链接巡检不能替代该导出审查，历史可读PNG也不能修复HTML的CSS。

## 图引用与资产路线的角色合同

旧图每个节点和边都必须至少含一个以`research/current/`开头的refs字符串。本脚本在此处只查前缀，并不遍历这些图refs的实际文件；图生成器另有`.is_file()`检查。多一个现行refs不意味着所有所需证明都在其中。

每条资产要求ID在资产表内唯一、claims非空且都是旧图ID，`applies_when/status/produces/proof/sources/limit`非空。逐路径角色要求如下，每一所列路径还必须为实际文件。

| 角色字段 | 允许旧树前缀 |
| --- | --- |
| `implementation` | `facility_spe/`、`multi_facility_spe/`、`customer_attraction/` |
| `proof` | `research/current/` |
| `sources` | `history/` |
| `tests` | `tests/` |
| `records` | `evidence/` |
| `examples` | `examples/`或`evidence/certificates/` |
| `reviews` | `research/reviews/` |
| `candidates` | `research/questions/` |

八角色数组按`entry.get(field,[])`遍历，因此不存在或为空的implementation/tests等不会仅因缺省而失败。实际351项有14种字段形状，其中5项没有implementation；额外`scope_model/source_role/source_scope/source_interpretation/implementation_detail`保留在原JSON和字段清点中，但旧程序不解释这些文本。它不验证测试是否运行、审查是否独立、来源是否忠实、候选是否闭合，`limit`非空也不代表限制写对。

程序随后要求620个`kind=claim`图节点全部出现在review IDs中、全部被某资产claims引用。它不要求所有lemma同样被资产覆盖；review集合精确等于注册表的条件属于旧图生成器。再递归三个规范包下全部非`__init__.py`的`.py`，要求这些路径均被某implementation列出。该条件不禁止额外列入别的实现，也不检查实现行为、位复杂度、输出证书或数学量词。最终打印的“implementations”是被登记的唯一实现路径数，不是定理完整算法数。

## 迁移、原来源解释和根文档

程序要求`moved`和`retired_code_paths`中的旧路径不存在、新目标是文件；前者58条、后者10条。source_crosswalk的68个`original`必须唯一，集合恰等于合并迁移字典的键；每个保存位置等于目标，新解释文件存在且说明非空。与独立`build_crosswalk.py`相比，此处对原68条`rewritten_in`**没有检查current/questions前缀**，故两个检查器合同并不完全相同。

新增来源606条要求history源唯一且存在，来源说明和解释非空，解释在current/questions并存在。此主程序**不遍历**解释账本的6项`historical_records`，那由独立生成器检查。`first_curation_retired`8条另要求旧不存在新存在；`reestablished_root_docs`3条要求旧根路径和归档路径都存在。迁移表的7条`retired_test_entrypoints`虽保存在真实JSON，本主程序未遍历它，不能报告该分支已由此程序核验。

上述“退役”是旧路径合同，不能按名字把原数学材料抹去，也不能拿来删除现树同名新对象。当前正式对象由真实来源和状态判断，旧路径消失不意味着数学失败或已被完整替代。

## Git文件清单及旧层级专用限制

主程序只读调用`git ls-files -z --cached --others --exclude-standard`，从旧仓库索引及未跟踪但非忽略文件汇总路径。它不是对某冻结提交的不可变目录清点，也不含所有被忽略文件。

允许的顶层目录只有`facility_spe/multi_facility_spe/customer_attraction/tests/examples/evidence/history/research/learning`。允许根文档为`.gitignore/work.py/AGENTS.md/README.md/ASSETS.md/USAGE.md/RESEARCH_STATE.md/CLAIMS.md/FAILED_ROUTES.md`，另有三个精确`design/`文档。`docs/proof-review/`只允许已经列入catalog的具体路径，不能泛化为任意docs目录。

任何其他路径触发“unclassified repository files”。同时要求历史manuscripts、历史notes、evidence、examples、research/current五组各至少有一项路径。因此当前`archives/map/cleanup/tools`等新结构会有意不符合旧白名单；这不是当前结果树错误，更不能为让旧检查器通过而移回旧树或删除新对象。完整复现必须在另一个有全部真实旧依赖和合适Git索引的隔离目录进行，不能用空文件替身取得PASS。

## 固定日期运行记录与hash检查的真实力度

程序只遍历`evidence/runs/2026-10-01/*.json`，没有递归其他日期。每份要求schema_version=1，且`python_version/base_commit/replay_commands/source_sha256/limitations`非空。若有`input`或`certificate`键，分别实际读取对应文件并计算SHA-256，必须等于记录中的`input_sha256/certificate_sha256`。

**`source_sha256`在此只要求非空，没有逐个重算所列代码hash。** `base_commit`、重放命令和limitations也不被执行或核实。无input/certificate的记录可以只通过元数据要求；这不是所有运行的可重现性认证。

实际四份记录的内容和限制如下，保留为来源自己的有限结果，没有重跑或升级。

| 记录 | 原件所记有限观测与明确边界 |
| --- | --- |
| `on_path_chord.json` | 布局(0,1)，三共同客户概率39/80，负载277/4与279/4，factor=1，核对9个完整标记布局；仅一个选定C分支及达到续局，不推出普遍存在或实例最优 |
| `sharp_lower_rational.json` | 一个修正整数实例36布局，最优factor=499750/309017，布局(0,4)；渐近有理下界族依赖独立数学证明，不由这一有限求解推出 |
| `sparse_bad_long_cycles.json` | 固定r=7/4，n=1,2,3,10,30,100；最优factor依次237/133、395/223、553/313、1659/943、4819/2743、15879/9043；长环长度2n+2；普遍n及全部r<rho仍需符号不等式和有理稠密性证明 |
| `sparse_high_reach.json` | Fraction、seed6384201，n=2–5共400随机攻击，记录pure_bad2/mixed_bad0/balanced25/ties272/zero_reach31；继承锐下界，固定纯规则的tie负控与全混合NE最优分开；不能证明普遍rho界 |

本批对四记录全部字段作结构清点。其中5项实际input/certificate绑定的期望hash与精确冻结清单相等；没有读取这些输入/证书原字节并重新运行hash分支，故记录明确为**冻结元数据比对**，不是主检查器的实际文件hash重验。`sparse_high_reach`没有这两角色，绑定列表为空不算缺失失败。原sourcehash表及全部观测仍在证据目录，不补造旧日志。

## 三个依赖子程序的实际功能

主程序按下面顺序用当前Python启动子命令；这也说明一次完整旧检查不止上述JSON几份。

| 子程序及调用 | 全文读得的合同和边界 |
| --- | --- |
| `check_active_research.py` | 读取schema2 active_research，解析work.py与submitter的AST字面DEFAULT_SAVE/RESEARCH_ENTRIES/ROLE_PROMPTS并比对目标、默认存档、三个角色；核对活跃入口和角色prompt、runbook、数学入口中的目标/存档文字、陈旧模式及本地链接，要求数学入口链接同目录全部Markdown；角色prompt必须有唯一~~~text块及指定关键词；兼容入口只能重定向，归档退役清单逐文件hash匹配。历史指令仅作输入，不成为本批任务授权 |
| `check_wc_assets.py --check` | 读取WC INTEGRATION与分类键集合，未保留项必须写git_history_only及理由；六角色路径前缀、保留.py/.json的实际hash须出现在源hash值集合；用build_catalog验证catalog并渲染特定WC FILES.md，要求原文件文本完全一致。其文字明确若干候选/锥/非分离证明和未见实现的边界；没有以目录检查补交数学或程序 |
| `build_catalog.py --check` | schema1条目路径规范、不能绝对/空段/./../反斜线/换行/尖括号，解析后在ROOT内且文件唯一；角色/主题在允许集合，人工中文名称不等于basename、purpose有长度及非空泛限制；要求若干研究Markdown和WC保留路径全覆盖、related_paths命名、35改名的旧路径不在新树而新项已登记；按主题/角色顺序渲染CATALOG并逐文本比较。claim_index只从assets路径聚合Claim IDs，不证明数学内容 |

实际active_research输入是旧2026-10-23任意人数一般目录主攻、三角色和旧checkpoint路径；当前AGENTS焦点是恰六人，显式Boss编号与三阶段清洗。JSON内的授权文字、角色任务和旧命令只是历史源，不能覆盖当前会话。三个依赖主源尚待各自独立semantic receipt，本批全文比较只为明确check_assets的真实依赖链，不额外done它们。

## 本批有限核查与可接续范围

新增`inspect_inputs.py`在证据副本上运行一次，递归清点14份真实JSON每个字段/标量类型及路径引用，并静态比对生成输出。保存[字段清点](../../../../tools/evidence/research-index-builders/json-field-census.json)、[逐引用清点](../../../../tools/evidence/research-index-builders/reference-census.json)及[结构结果](../../../../tools/evidence/research-index-builders/input-structural-audit.json)。351资产ID无重复、claim ID无失踪、620个图claim均有资产路线，33学习模块无未知claim。15,535次引用的2,754个路径在冻结索引均存在。

这没有调用原主程序，没有重验旧Git索引白名单、物化全部规范实现、执行三个子程序或运行数学测试，也不声称恢复完整旧环境。冻结文件索引共10,885项，作为路径/SHA证据，不冒充原Git清单。输入及原件完整保存与“依赖全部具备可原suite复现”是不同命题。

已知关系是本巡检**检查**旧资产登记和文件合同，与[来源解释生成器](旧路径解释账本的覆盖与生成合同--资源.md)交叉引用同一68条迁移集合，与[旧超图查看器](旧数学超图查看器的结构与交互合同--资源.md)共同使用节点/审查账本。它不推导任一数学Claim；教学引用、有限计算、软件实现、条件候选和证明各保持原身份。当前第三阶段若复用此代码思想，应将旧路径白名单换成明确的新合同，增加真实版本与hash绑定，并按实际程序、数学证据分别验证，不能把旧成功输出当当前三阶段完成判断。
