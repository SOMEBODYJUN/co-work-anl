# 五人证书到六人嵌套重查询的松弛边界

状态：旧五人 53 行包的独立精确复核通过；同源重查询对六人旧松弛有严格负 slack；437/587 行必要条件松弛的精确值仍低于 1/2；所有这些点都明确标为非 SPE 或未提供完整证书。

## 1. 证书包的比较边界

本组 README 明确区分三份五人材料：44 与 60 的完整新证书字节、系数表和验证器并未作为本批可读附件；因此本批没有冒称重跑它们。可独立重构的是同源末主题重查询的七行局部关系、旧 53 行 K-balanced 变体和六人必要行松弛。

`certificate53_Kzero_recheck.json` 对冻结的五人 53 个正乘子做独立完整域核验：1024 个实际掩码、6144 个条件态、每个第三族 792 个直方图、第二族 15504 个直方图、每族四个菜单角点，最小缩放残差为 0、K 列余项为 0、负案例为 0。它确认 `2W>=OPT_5` 的 K-balanced 表达是精确可核验的五人结果；它没有产生六人证书，也没有把 44/60 的未读整包纳入。

相应的共享变量微检验还保留了一个精确的消元严格差：同一隐藏 g 的两条行先合并得 2，而分别投影只得 3/2。这解释了为何 60 行的同源查询可能增加信息，但也说明行数或正乘子数量本身没有数学强弱序。

对 `six_copy_free_results.json` 的 387 行旧点，m=6、O=1、W=8664083663/21693341273、u_4=21185642969/347093460368、u_6=46719837927/347093460368、K=4363459416/21693341273。把同源七行投影放在实际第四位，50 个 T/Q 查询中有 3 条精确负 slack：

    T=A_6,Q=avg: -1765921895/130160047638,
    T=avg,Q=A_6: -2718797801/260320095276,
    T=off,Q=off: -4111629751/260320095276.

`nested_requery_oldpoint.json` 和独立审计都只主张“新的必要局部不等式排除旧松弛点”；点没有完整 SPE 控制器，所以这不是原模型反例。

把 50 条新行加入 331 行定价系统得 381 行；再对六人所有余 k=3,...,6 源节点加入同源关系得 437 行和 587 行两套精确证书。`refine_with_nested.json` 与 `nested_horizon_refine.json` 均给

## 3. 七行局部表的完整复核范围

`nested_requery.json` 逐格保存五人 9 组和六人实际 12 组 `(p,ell)` 的 phi 表；`nested_requery_horizon.json` 扩展到任意 k。独立 Fraction 审计不导入主方 phi 实现，逐项复算了 12480 个局部类型恒等式、130944 个系数状态、6231 个零余项和 2016 个容量读数，状态为 `EXACT POINTWISE IDENTITIES VERIFIED`；其 scope 是 local formula only，不是完整 44/60 行运行。

六人实际源域中 p=0..3 且 ell∈{p,p+1,p+2}，共 12 组；离轨源的安全放宽域是 4×6=24 组。把五人九组表直接抄到六人会漏掉 p=3 的三组，属于量词错误。

## 4. 失败路线与真实后续义务

`comparison_audit.md`、`saturation` 与 `nested_requery` 共同说明：同源查询确实保留了跨分支身份，且能严格切掉指定旧点；但“局部切掉一个松弛点”不等于得到覆盖半数。要关闭六人或一般 m，必须继续保留更早复制节点、共同目录下可互相查询的同一菜单以及最优索引相关性，再寻找对所有客户类型和共同 K 列非负的统一乘子。

若新行的隐藏变量来自不同真实历史，不能强行共享；若确实来自同一源历史，分别投影又会丢掉可用信用。后续证书必须在这两种情况之间逐行注明身份关系，不能只凭“更深偏离”或“更多行”声称强于旧证书。
