# 四人六主题终局税随机策略锥的原始探针合同

本次完整读源码及必要依赖，未运行任一数学入口、导入、LP、策略IC重放或随机扫描；本批没有实际输出报告或tax_candidate.json。因此以下是实际代码合同和解析解释，不是一次新的阴性搜索或反例认证。

## 1. 真正目标是全终局负载税

采用有限单位客户、共同主题目录、完整有序历史纯策略的原模型。此入口从依赖固定得到n=4名玩家、k=6个主题0,…,5。兴趣类型M遍历1,…,63，权重w_M≥0是客户质量的压缩；若有理点通过全部真实IC和严格目标，通分即可展开为不同单位客户，而不是加权玩家。

固定完整策略σ的实际叶z=(a_1,…,a_4)，令

\[
 c_M(z)=\sum_{i=1}^4\mathbf1_{a_i\in M},\quad
 W(w,z)=\sum_Mw_M\mathbf1_{c_M>0},\quad
 \tau_4(w,z)=\sum_Mw_M\frac{c_M}{c_M+1}.
\tag{1}
\]

程序直接探索

\[
 \operatorname{OPT}_4\le W+\tau_4.
\tag{TAX?}
\]

税计入实际全部四位，没有α=3/4缩放，没有max查询M(q)，也没有把末位从c中删除。0≤τ_4≤4W/5，故TAX?若普遍成立则OPT_4≤9W/5≤2W；这是准确条件推论，源码没有给其普遍证明。

应区分三个其他接口：[末位前缀税](../引理/末位收益税诊断--引理.md)只计前三位b并有OPT_4≤4u_4+Σb/(b+1)；[实际均匀缩放税](../反例/实际均匀缩放负载的弱付款桥--反例.md)用L=3c/4构造M及税；自由静态背景则重新选择全部目录上的次数质量。它们的失败、静态代数或付款预算不自动决定TAX?。本程序也没有计算真正整数混合安全值v或自由分数值t。

## 2. 第一行的真实闭包与副作用

入口用`__file__.replace('random_tax.py','tax_probe.py')`定位相邻文件，将读得文本在第一个字面`if __name__`处切开，以`exec`在当前全局命名空间执行前缀。已实际读到的依赖在该位置恰为main guard，前缀包含：Fraction别名F、product/combinations/lru_cache、json/math/sys、NumPy、SciPy linprog、n/k/masks、12种整数seed、coef/cvec/terminal、默认完整sigma以及optimize。没有导入规范CustomerAttraction包或独立certificate verifier。

该前缀先用seed

`{1:12,2:8,4:4,8:8,17:6,33:6,20:3,36:3,49:6,50:2,52:1,56:2}`

构造默认策略：前三位均选0、末位按seed收益最大且偏向大行动标签的规则选。random_tax随后每轮传入自己生成的sig；默认sigma并非随机入口每轮LP使用的策略。依赖自己的main段不被执行。

random_tax本身没有main guard，作为模块导入也会运行至多100轮搜索。它没有命令行参数解析；任意文件名改动可能影响字符串替换定位。缺相邻依赖、NumPy/SciPy不可用或求解失败都可能使入口不能完成，不能因文件存在就报告可复现成功。

源码每轮向stdout打印iteration、round(−f,9)、比较支持cc、原策略根叶z、累计秒数，flush=True。只有浮点f<−10⁻⁸才进入FOUND分支；那里会以`w`模式覆盖相邻tax_candidate.json。全程没有新候选时，不删除旧candidate文件，也没有最终DONE或成功认证报告。因此单凭该文件后来存在，不能归因本次入口成功；本批也未取得该文件。

## 3. 随机权重只用于生成完整策略

Python RNG初始化为19211，状态同时用于样本选择、整数权重和每个节点的随机平局。偶数轮从63个非空兴趣mask中无放回抽8至24种，每种给1至9个单位客户。奇数轮先放`{1:4,2:1,4:1,8:1}`，再抽2至14种并赋1至9；后一步可能覆盖先放的键和值，所以四个初值并非始终保留。

`policy(ww)`对每个有序前缀h递归求全部六个孩子`end(h+(a,))`。对行动a，使用真实孩子完成叶z计算当前角色收益

\[
 u_a(z;ww)=\sum_Mww_M\frac{\mathbf1_{a\in M}}{c_M(z)}.
\tag{2}
\]

当a∈M时，叶中包含该玩家所选a，分母正；否则coef直接返回0。全部算术使用整数权重和Fraction。节点按`(uv[a], rng.random())`的字典序选最大；第一关键字是真实收益，第二仅打破收益平局。源码注释所称“prefer high root coverage”没有相应的覆盖关键字，不能把注释当实现。

子节点先全部构造，再选择当前行动，所以在生成权重ww下，有限逆归纳确实给一份全历史纯SPE，允许同计数的不同有序历史选择不同平局。策略域恰为深度0至3的全部有序前缀，共1+6+36+216=259行，根键为空元组。`lru_cache`按有序h缓存，不是计数Markov约束。

这只证明生成策略对**原ww**合理。下一步LP允许63种类型全部重新赋质量，包括原随机样本中为0的类型；是否仍为SPE由完整Γ约束决定，不能继承原ww的理性而省略它们。RNG在每个候选行动上均取随机数，包括无平局的节点，故随机权重和策略平局共用同一连续状态，不是每轮重设seed。

## 4. 固定策略锥与十五个比较LP

对每个原有序节点h，规定行动a₀=σ(h)，令z_h是依σ真实完成叶，z_(h,a)是先强制a再依同一σ完成的叶。对全部h和a构造精确Fraction行

\[
 \Gamma_{h,a;M}=
 \frac{\mathbf1_{a_0\in M}}{c_M(z_h)}
 -\frac{\mathbf1_{a\in M}}{c_M(z_{h,a})},
 \qquad \Gamma w\ge0.
\tag{3}
\]

零分子按0处理，非零分母由叶包含该行动保证。代码保留全部259×6=1554行，包括259个自身行动零行和可能重复的其它行；没有只核根、只核实际路径或只核末位。它也没有删除根IC或以投影回放替代真实分支。

所有63列的非负质量归一化为Σ_M w_M=1，**不是W=1**。对六主题中的每个四元素不同标签支持C，定义o_C(M)=1_(M∩C≠∅)，求浮点LP

\[
 \min_{w\ge0}\sum_Mw_M
 \left[\mathbf1_{c_M>0}+\frac{c_M}{c_M+1}-o_C(M)\right],
 \quad \Gamma w\ge0,\quad \sum_Mw_M=1.
\tag{4}
\]

程序的cost正是式(4)，linprog中A_ub=−Γ、b_ub=0、A_eq为全一行、method='highs'。精确行转为NumPy float后交给求解器；没有精确原始/对偶证书。源返回最小成功fun的(f,cc,w)、根叶和原Fraction Γ。

共有C(6,4)=15个比较支持。客户质量非负，任意至多四主题支持都能扩到四个不同标签而不减少覆盖；所以这15种支持覆盖了OPT_4所需的比较，无需另枚举有重复的比较元组。重复行动仍可出现在策略叶中。这里的完整比较支持不等于枚举所有完整策略：每轮只处理刚生成的一份σ。

代码只把success的LP放入opts，再取最小；失败LP没有诊断或重试，全部不success时min空列表会报错。最多100轮且各轮正常完成时，源意图为至多1500次LP调用；259/1554/15/1500均是从真实循环解析得到的域/上界，**不是本轮新执行计数**。若部分比较LP失败，更不能把返回最小值当全部比较的精确最优下界。

## 5. FOUND分支没有自动完成精确认证

当最小浮点f<−10⁻⁸，代码只保留x>10⁻⁸的LP坐标，以Fraction(float(x)).limit_denominator(10⁶)近似，再取所有分母的LCM化为整数wi；没有除GCD，也没有规范Instance构造。阈值过滤和逐坐标近似可能改变IC及严格目标，接近0的保留坐标也可能有理化成0。

然后对原1554个Fraction Γ行计算Γ·wi，并打印`FOUND wi min(vals)`。这项最小值的计算若实际执行，将是完整固定策略行的精确点值检查；但源码**没有要求min(vals)≥0才继续**，也未精确重算式(4)的负目标、W、τ或OPT，未调用独立策略验证器。打印FOUND这个标签不构成通过条件。

无论该最小值符号如何，随后写JSON字段n、k、weights、sigma、comparator、root并break。sigma把259个有序历史键拼成逗号字符串，根键为`''`；整数兴趣mask键经JSON对象序列化成为字符串。JSON没有保存浮点f、原ww、轮次、minGamma、严格gap、LP状态/dual、软件版本或运行回执。

若日后得到实际candidate，必须独立核其完整动作域、所有真实IC和严格正覆盖差；只有这些条件成立，通分后的整数客户才给原模型的反例。当前不能据源码的有理化步骤或FOUND字符串预先授予该认证。本批未提供任何candidate/逐轮stdout，不能说100轮已完成、没有找到反例或已经找到了反例。
