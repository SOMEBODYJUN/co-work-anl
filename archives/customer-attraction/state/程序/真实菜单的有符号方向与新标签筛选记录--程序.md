# 全部实际原件和目标

3816B主码、50773B normal及50790B fresh命名报告，共105379B均正常show后全文读、核size/SHA256/Git blob；两冻结来源同字节不当两次运行。两报告所有600个八字段记录按原case顺序无损阅读，含全部−0.0和五个非零浮点尾差。完整原件及可逆视图见[证据](../../tools/evidence/branch-transport-signed-normal-fresh-three-primary/README.md)。本次没有执行原导入/main/随机policy/收益/Γ/菜单/LP或精确checker。

沿[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：n≥1名单位提供者，共同k标签，有限单位客户在终局覆盖者间均分；完整σ对每个有序历史规定合法动作，空题、重复、零客户、同覆盖不同标签及离轨平局保留。非空兴趣型I的整数质量是不同单位客户。下面允许负号的x只是**辅助方向**，不是负客户输入；编译后的质量必须非负并清分母。

固定同一完整σ的actual路径s。actual位置i强制a后沿σ完成为z_i(a)，删除该叶的**第i位**得到n−1行动计数B_i(a)。菜单M=∪_(i,a){B_i(a)}只在此后按计数去重，不能把σ的有序历史合并。定义
\[
f_B(T;w)=\sum_{I\ni T}{w_I\over1+B(I)},\quad
\operatorname{cap}(M;w)=\max_{p\in\Delta_k}\min_{B\in M}E_p f_B(T;w).
\]
[共同菜单候选](../候选/全部实际节点真实竞争菜单的共同混合--候选.md)是cap(M;w)≤Wσ(w)/n。菜单背景知道查询分布p但不看抽样T；它不是根菜单、所有静态背景、冻结actual后继或同题删位D_T。候选若真给W≥n v_n及OPT≤(2−1/n)W，是half充分加强而非等价。纯查询已有[不可分离界](../引理/实际节点竞争菜单的纯查询不可分离--引理.md)，本程序改用两个或更多额外query标签的固定混合。

# 主码实际策略族与导入闭包

参数core=c、queries=q，k=c+q。前c个标签为core，后q个只作额外查询。对每d=0,…,n−1、每h∈[k]^d，rng在{0,…,c−1}\supp(h)中均匀选σ(h)。它规定全部有序历史（包括过去重复和query历史），每次只选未出现的core动作，**从不规定query标签**。不同同计数历史仍分别抽样。保证这个取样存在的充分域是c≥n≥1、q≥1；CLI没有完整校验，c不足可能在某历史choice空集，q0不能给合法查询分布。

p在core上0、每个query上1/q，固定不优化。程序不是全策略搜索，也不枚举该core-fresh族；query数、core大小及均匀权重均限制攻击域。两个n3/k6报告记录core4，故其中q=2、p=(0,0,0,0,1/2,1/2)，不是默认core3的另一含义。

源按同目录导入3462B actual_menu_probe.py，后者按原parents[5]导入R-3b6的5027B cone_security_search.py，再顶层导入规范包四文件25475B；完整实际源码闭包33964B已在R同SHA。3462/5027本轮均全文读，canonical四件同SHA既有全文上下文复用。signed入口只调用menu_geometry→base.geometry，**不调用**base.make_policy、ExactSPESolver、canonical verify或依赖的交替fixed_p/security_p主循环；未使用导入Fraction/lcm也不构成精确恢复。

geometry从所有有序h和每个真实偏离孩子沿同一σ完成，以lcm整数收益行去重/去零，再除L为float Γ；规范[完整策略锥](../定理/固定完整策略的客户重数锥--定理.md)在精确算术给Γw≥0。menu_geometry丢弃base生成的全静态背景，重新从actual各位置一次真偏离并删当前位置，得到sorted计数bs、R_(B,I)=1/(1+B(I))、兴趣incidence矩阵I、actual覆盖行c。下文用c表示覆盖行，core数写作c_core以免混淆。

# 全型正基为何抵消菜单基准

令u为每个非空兴趣型均质量1的对称输入，共2^k−1位单位客户。[完整新标签引理](../引理/全非空对称客户型下的完整新标签策略--引理.md)已证明：任一每历史fresh策略在k≥n时都是真纯SPE；fresh与fresh的当前收益相等，fresh严格胜repeat。后一点可按只含两比较标签之一的对应兴趣型，逐项比较1/(1+z)与1/(r+1+z)、r≥1得到。core-fresh只是该族的子类，额外query也是合法fresh偏离。

actual选n个互异core，故c·u=2^k−2^(k−n)，每actual玩家收入W_u/n。任一actual强制a若是过去旧动作，叶仅该a有一次重复，删除当前强制者便把重复去掉；若a新，则整个叶已fresh。后继都继续未用core。所以每个B_i(a)都由n−1个互异core组成，query标签在删除强制者后一个也不留。这里源码distinct过滤在合法取样族上不应丢菜单，但保留其实际代码筛法，不把任意σ也称全部distinct。

对任何query T∉B，
\[
f_B(T;u)=2^{k-n}\sum_{j=0}^{n-1}{\binom{n-1}{j}\over j+1}
={2^k-2^{k-n}\over n}=W_u/n.\tag{1}
\]
第一个因子计B和T之外的自由兴趣位；用Σ binom(n−1,j)/(j+1)=(2^n−1)/n。故所有菜单及其固定p混合有同一base值，n3/k6为56/3，actual W_u56。这是全参数对称性论证，不是本次重放assert。

令H_B(I)=R_(B,I)(Ip)_I，ℓ_B=H_B−c/n。式(1)给ℓ_B·u=0。主码用浮点base=Γu、abs(base)<10⁻⁷筛零基行Z，并assert base最小>−10⁻⁷；另用support(B)大小n−1筛distinct菜单H，再assert各H_Bu相同且等于c.sum()/n。数学上的精确零/正分类及等式不由这些容差assert自动认证。

# normal方向LP与严格单位编译的承重条件

在normal（未设置fresh-only）时Z来自**全部真实Γ**中零uniform基值行。方向变量x_I∈[−1,1]，t自由，源实际LP是
\[
\max t\quad\text{s.t. } Zx\ge0,\qquad
t\le(H_B-c/n)x\quad(\forall\text{保留菜单}B).\tag{2}
\]
矩阵A的两块分别[-Z,0]、[c/n−H,1]，目标min−t。没有w≥0、Σx=1或W1归一化；单位盒只给有界方向搜索，任意有限严格方向可缩进盒内。x0/t0是精确可行点，所以精确最优≥0，保存的微负值只能当数值近零，不能反读为负方向定理。

若另取得式(2)内的**精确有理方向x**及严格正有理数t>0，并核全部零基Γx≥0、所有actual菜单ℓ_Bx≥t，则可取
\[
w=\lambda u+x,\quad
\lambda>\max\{1,\max_{\gamma u>0}(-\gamma x)/(\gamma u)\}.
\tag{3}
\]
空的第二最大项可略。所有客户w_I>0，零基IC由Zx≥0，正基IC由λ保证；故原同一完整σ为SPE。对全部B，ℓ_Bw=ℓ_Bx≥t>0，故固定p已经有min_B E_pf_B>Wσ(w)/n，cap更大，严格反共同菜单候选。有限有理λ/x清共同分母成为不同单位clones；全型严格正含各私有客户，使覆盖标签互异，不需退化标签扩展。

这只是有精确严格方向时的充分编译，不是本两报告已经提供的产物。源码若gap>10⁻⁷才保存float方向/完整policy/p/backgrounds并提前break，**没有**Fraction恢复、式(3)λ、单位克隆、全部IC/菜单定义级验收或OPT计算。float成功/正gap也须这些承重检查。反共同菜单不自动反全静态v_n聚合或half，不能把两个“充分桥”反向使用。

# fresh-only的实际省行不能冒完整原策略认证

设置flag后，程序先算完整geometry，再**覆盖G**。设actual路径s，对每i和每个已在s[:i]出现的旧t，从h=s[:i]+(t,)起只沿σ规定动作走到末尾，将这些非终端h记needed。它没有把needed在所有fresh偏离孩子下作闭包。

重建行只对满足“h本身无重复，或h∈needed”的节点，加入所有s∉supp(h)的比较u(σ(h),h)−u(s,h+s)。包括自身动作零行，不去相同行；其余重复历史的fresh比较和全部repeat动作比较都未列。这里u沿原完整policy完成，不能当成已换成可信最佳孩子。

被忽略的repeat比较在uniform基上严格正，有精确有限数据时可由足够λ支付；但遗漏的**fresh比较基值为0**，其方向若负就无法靠增λ修复。故(2)/(3)的“原同一完整σ可编译”结论在fresh-only模式必须补核完整Γ零基行，不能因代码变量仍叫G/Z或行数更多便自动授予。若允许改写未约束子树，还须另证能补全且保持actual菜单及所有必要比较；本程序没有执行这种补全，不能把省行等同完整SPE证书。这里不声称任何可能补全都失败，也没有找到本报告中的坏策略。

本n3/core4/k6特别清楚：所有无重复历史节点为1+6+30，分别产生6、6·5、30·4条含self的fresh比较，共156。needed另含actual首标签的重复两步节点(A,A)，其fresh比较5条，合161。这解释fresh报告所有zero_base_rows161；其它五个(a,a)末位节点的fresh方向比较未由这一分支列入。normal从完整有理差行去重/去零，所以其零基行105…136反而少于161，**行数比较不表示约束更强**。原300份policy未导出，不逐份声称遗漏行独立或已违反。
