# 对象与真实输入

本对象整理3197字节原程序`product_transfer_attack.py`。它针对[全续局产品转移与全部最优元组攻击](../资料/全续局产品转移与全部最优元组攻击--资料.md)的严格充分条件寻找三人组件，既不构造产品大实例，也不输出完整SPE策略。此前资料与[原审查范围](../审查/产品可信最低收益的原始审查范围与后加边界--审查.md)只把2186次阴性检查作为原MD报告；本对象新增原源码合同、 exact依赖身份和一次原入口的真实重放，保留此前“当批未读代码/未重演”的准确历史。

模型是有限非空共同标签目录、单位提供者、不同的单位客户、完整有序历史纯SPE。类型重数表示具有相同兴趣的不同客户。脚本`main`固定三标签A/B/C、三名玩家，按二进制mask 1,…,7给兴趣型排序

\[
A,B,AB,C,AC,BC,ABC.
\]

每型重数独立取0、1、2，略去全零向量，共\(3^7-1=2186\)个输入，客户总数1至14。允许某主题覆盖为空、不同标签覆盖相同和重复行动；没有随机种子或随机采样。空兴趣客户未列入，因为它们不影响任何收益或覆盖。

程序无CLI参数解析，无外部实例/JSON输入，也不写结果文件。`main`受`if __name__=='__main__'`保护；普通导入只导入依赖并定义函数，不自动执行2186域。路径`parents[5]`定位原仓库根，再导入`customer_attraction`。脱离原层级直接移动原脚本可能导入失败；保全原相对层级的隔离重放方式见[证据目录](../../tools/evidence/product-transfer-convexified-optimal-tuple-diagnostic-primary/README.md)。

# 精确可信菜单与一约束凸化

代码依赖规范`Instance`、`CustomerType`、`ExactSPESolver`，收益和所有比较均为Python任意精度`Fraction`。没有浮点、SciPy或LP求解器。依赖的集合值递推保持每个前缀的**全部**完整纯SPE可实现终局，而非固定一份匿名策略；数学合同与证明见[完整历史终局全集](../算法/完整历史纯SPE终局全集--算法.md)。相同计数历史只缓存可实现集合，仍允许在各有序节点独立采用不同子策略。

固定首角色强制标签a，计数\(h=e_a\)。`theta=solver.threshold(h)`是第二角色在真实末位BR后可保证的门槛

\[
\theta(a)=\max_b\min_{c\in BR(a,b)}u_2(a,b,c).
\]

`transfer_value`对每个b，精确比较三个末位行动收益，保留全部末位最佳回复c及平局；每叶记

\[
d=u_1(a,b,c),\qquad v=u_2(a,b,c)-\theta(a),\qquad (b,c).
\]

这里v是**盈余**而非未减门槛的第二人收益。代码不先删去v<0的叶，因为产品组件可以用别的叶正盈余补偿。目标是有限有理LP

\[
\bar L_1(a)=\min\{\sum_j p_jd_j:p_j\ge0,\ \sum_jp_j=1,\ \sum_jp_jv_j\ge0\}.
\]

程序枚举两种候选：每个v≥0的单叶；每对v₀<0<v₁的叶按

\[
q=\frac{v_1}{v_1-v_0},\qquad(q,1-q)
\]

组合，恰有qv₀+(1−q)v₁=0。然后取成本最小的候选，保其有理权重及末两行动，不返回抽象浮点最优值。

这套枚举恰给LP最优值：可行域是单纯形与一个半空间的交；极点若盈余约束不活跃，支持为一个可行叶；若活跃，至多有两个正权重。两叶若都非负，则成本不优于其中一个单叶；若一叶盈余为零也已有单叶；剩下正是严格负/正盈余配对。有限可行域非空，第二角色存在可信SPE叶，故`min(feasible)`有定义。权重表示有限相同组件的确定份数，不是在原博弈里引入混合玩家或随机行为SPE。

`transfer_value`的终局直接补齐a、b、c三次行动，因此只适用于恰三人，函数本身没有另做人数校验。`inspect`虽从实例取m，其后仍硬编码`ls[1]`和`ls[2]`；不能把此接口推广为任意m入口。实际`main`始终构造m=3，域内无此问题。一般人数的凸化和舍入已由既有解析对象证明，本程序不验证该推广。

# 全部actual路径与全部最优有序元组的量词

对每个输入先求O=OPT₃，再列出全部\(3^3=27\)个有序三标签元组中福利等于O的集合\(\mathcal T\)。这不只枚举三个不同主题的六个排列；覆盖退化时，含重复标签的最优元组也保留。

`solver.ordered_outcomes()`遍历**全部可由某份完整纯SPE实现的有序actual路径**z；它不枚举支持同一路径的全部完整策略。只对W(z)<O的路径继续，其余路径不可能给严格正净缺口。对每个实际位置i和强制标签a，取该实际前缀计数kᵢ，计算

\[
L_i(a)=\min_{t\in R(k_i+e_a)}U_a(t).
\]

这是对强制行动后**全部**可信续局取极小，不是沿某一预先指定完整策略的真实偏离收益。每个L行可独立选择达到的子SPE；把这些值当同一固定策略的偏离菜单需要另给证明。

三人时只有首行可以作此下一角色凸化；第二行后只剩末位，故barL₂=L₂，末行直接确定。代码计算

\[
M(z)=\max_{T\in\mathcal T}[\bar L_1(T_1)+L_2(T_2)+L_3(T_3)],
\qquad g(z)=O-W(z)-M(z).
\]

因此g>0才是既有产品舍入归约的严格种子。max覆盖**全部**最优有序元组，不能以只挑一个有利最优排列替代；`max`的元组次键只在值相同后选字典序最大的T作为输出代表。`inspect`在全部亏损actual路径中保g最大者，外层在全部输入中继续保g最大者；相同gap不更新，进展输出只记录严格刷新点。

即使将来发现g>0，结论仍是既有有限舍入定理所述的SM-opt-exists存在桥反例，须按该定理构造足够多副本；它不是直接的half福利反例。五客户双副本\(L(BB)=5/2<3\)的已知见证W=OPT，本来不能满足g>0，见[任意背景两尾过滤](../定理/任意背景两尾产品门槛与可信叶过滤--定理.md)。同质all-big产品的[对角边界](../引理/同质大主题产品的对角最优菜单边界--引理.md)另有解析证明；本2186输入运行不是全m、q的该证明。

# 复用与验证边界

需要小规模精确一门槛凸化时，可复用单叶/正负叶对枚举及所返回的有理份数；需要检验产品SM种子时，必须保留全部actual路径、全部最优有序元组上max、强制行动后全部可信续局极小L。若扩展人数，须重写菜单收集、端点行及路径统计，并仍保持完整历史量词。

此程序依赖规范集合值SPE求解器，不是对该求解器正确性的独立验证，也没有调用`certificate()`或`verify_certificate()`；导入`certificate.py`只因规范包的模块依赖。它没有输出产品完整策略、有限副本数、统一舍入常数或一般福利证书。当前阴性只覆盖上述2186输入及其全部亏损纯SPE路径；不排除域外组件、异质产品、更深耦合，也不证明SM、TB或half。六人half目标不由这次三人诊断解决。
