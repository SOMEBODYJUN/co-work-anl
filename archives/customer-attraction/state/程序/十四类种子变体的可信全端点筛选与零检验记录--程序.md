# 保存的是有限发现合同

1596B源码与137B完整JSON均逐字节核冻结SHA后全文实读。原程序声明只尝试反驳一般ADM，保存结果为`checked=0, records=[]`。本页保具体种子、变体与筛选含义；没有重跑原程序、随机生成、集合值BI、ADM端点或LP，也不把空记录写成已证明某一构造类不可能。

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：有限单位客户，所有提供者共用有限非空目录，全部有序历史上的纯SPE；空题、重复、零客户与任意离轨平局保留。兴趣重数是不同单位客户的个数。源码这份特定发生器只产生正整数重数、m为3/4/5、6或7个标签；它没有穷尽模型的边界，更没有六人覆盖实验。

ADM精确定义与已证表示复用[全端点资源](../资源/可信全端点菜单的别名复核与静态付款下界--资源.md)。固定一份可实现actual路径z和原利润u_i，在actual前缀h_i强制当前a后，取所有完整尾子SPE的终局；其中当前a玩家收益不超过u_i者组成D_ia，D是全部格的并集。强制当前者不在孩子里重证a最优，原cap也不随新尾改变。actual经济行动格同样放开。全部端点恰m槽，查询在其外另加一槽：

\[
K(t,y)=\sum_{x\in t}\frac1{1+c_x(y)},\qquad
M_{adm}=\max_{p\in\Delta(S)}\min_{y\in D}\sum_t p_tK(t,y).
\]

待付款仍为M_adm≤W/m。有限别名拼合、minimax、静态下界OPT_m≤2m M_adm已经另有完整证明；此发生器没有再证明这些，也没有付未证上界。

# 十四类原种子与真实变体

标签0…5可写A,B,T,Q,R,S。程序将以下14类直接写在源码，不读旧JSON、旧证书或12类证明表：

|兴趣标签|人数|兴趣标签|人数|
|---|---:|---|---:|
|0|9|1|9|
|2|13|3|8|
|0,4|1|1,4|4|
|3,4|5|0,5|1|
|1,5|4|3,5|5|
|0,4,5|5|2,4,5|5|
|1,2,4,5|1|1,3,4,5|1|

总数71，正是[两份71输入的二人等价对象](../等价/两份最优遗漏输入的二人收益等价--等价.md)的**14类发现表**。另一12类输入仅在两人收益与两题覆盖接口相同；三人同一终局已可收益不同。因此在本源码m≥3的变体中不能用较简洁12类表替换，不把旧两人SPE的身份自动授予新实例。

顶层创建`Random(63531)`，计划k=0…179共180个变体。每次随机取m∈{3,4,5}；对每类人数w独立取倍率于`[.5,.7,1,1,1.3,1.7,2]`，令新人数`max(1,round(w*倍率))`。1在列表出现两次，故相应抽样权重双倍；使用Python的float乘法和round规则，不能改作另一种有理向上取整。所有原14类仍正。

偶数k保6标签。奇数k加第7标签6：对每个原类型独立以约1/2概率令它也覆盖标签6，再取private∈{0,…,13}，为正才添加只喜欢6的private名不同单位客户。支持主题可为空、可与旧主题同覆盖；源码没有强制覆盖集合两两不同。整个主题仍共同可选，不引入加权玩家或只对处罚者开放的动作。

传入同一个rng的helper还会洗牌候选有序路径；若实际进入这些分支，rng的后续状态亦由其消耗决定。不能只凭63531和14行表，就以另一个不调用helper的发生器冒称逐变体复现。

# 4060B相关helper究竟检查什么

必要依赖`probe_adm.py`已由父方按ID正常取得，4060B及SHA核同后全文实读，保为related而非第五个primary。该helper有main guard；本程序只导入Instance、CustomerType、check，所以不执行helper自己的目录扫描、CLI或额外随机main。导入的规范模块亦为已有同SHA字节，实际接口已经全文核对，见[依赖表](../../tools/evidence/adm-seed-mutations-and-strict-cone-four-primary/dependency-manifest.json)。

`check(ins,name,rng,10)`先以ExactSPESolver求该实例根的全部可实现终局**计数集合**。其集合值BI保留所有子SPE终局，缓存计数不限制完整策略为计数函数；算法数学见[可信续局重构](../算法/可信续局菜单与完整策略重构--算法.md)。

对每个根终局z，helper算实际覆盖W及每个纯查询的额外插入价K(t,z)，再用float筛选

\[
\max_t K(t,z)-W/m>10^{-8}.
\]

精确域中若max K≤W/m，因为z本就在D内，任何p都不能使整个D的最小价格超过W/m，跳过是合法的反例必要过滤。代码实际用了float转换与正容差；未过筛不是由精确对偶认证的一般上界，也不能排除小于容差的正差。

过筛终局按float差降序，只取前10个。每个先生成`ordered_outcomes(z)`的全部可实现**有序路径**，洗牌后取前5条；路径不是完整策略全集。对于所取每条路径，`adm`按全部actual位置、全部强制动作a调用`solver.outcomes(前缀计数+e_a)`，在Fraction域严格按`u_a(y)≤u_i(z)`筛cap，合并终局计数D。计数只合并对收益及插入价格相同的端点，不将原有序策略的动作规定合并。

因此对一条已选路径，D包含全部尾SPE的cap合法终局，而不是任选一份惩罚尾；这部分的量词方向正确。D非空由原路径存在的SPE保证。随后将整个插入矩阵转换float，用HiGHS最大化v，条件`Kp≥v, p≥0, Σp=1`；assert数值success，不恢复精确原始/对偶。

每完成一次这个ADM路径LP才`checked+=1`。best即使gap为负也会保存，只有gap>10⁻⁷才提前返回；外层遇相同正阈值才提前结束变体循环。故源码的上限是每变体10个终局×5条路径，既非所有根路径，也非所有完整策略，更非所有可能变体。

# 137B报告的全部三字段与零计数边界

冻结文件恰三字段：scope是源码首行的英语说明；checked为整数0；records为空数组。它没有保存seed、实际完成变体数、各实例/终局、过筛差、BI统计、LP状态、进程argv、环境、stdout或时间。源码虽然固定180上限，不能补造180份成功执行日志。

在这份check的正常输出合同下，`checked=0`表示没有进入并完成ADM路径LP；它**不表示**没有构造实例或没有运行集合值BI，也不表示“180条候选均通过ADM”。records为空与此一致：任何真正检验过的路径即使负差也会生成best。没有明细可以从报告还原逐变体的筛选结果或精确关闭某个参数族。

源码没有main guard，import就会执行其整个计划、输出进度并覆盖同目录`seed_family_discovery.json`；每20个k含k0打印进度，最终打印BEST。无CLI选项。当前只读文本和解析报告字段，不import、不补跑随机LP来制造日志。四primary只有本源码/本报告及[另一个严格锥探针](完整有序策略的严格裕量与交替菜单浮点记录--程序.md)两件，helper不额外claim或done。

# 可以如何接续

此记录给出一种明确的失衡种子修改方式及实际未产生可用候选的边界，不是新参数族或固定人数阴性定理。成熟ADM说明末两人只给M_adm≤min(u_(m−1),u_m)，前部低收益/末部高收益时尚不足；新机制仍须处理替换尾后祖先cap的丢失，或给确实分离全部D的精确单位客户证书。旧单向插入失衡、二人遗漏36>W35、任意背景预算失败，各自均不等于ADM或half失败。当前五人half有另证，不把原2026-10-24入口的OPEN覆盖为今日五人状态；本四源没有闭合一般或六人half。
