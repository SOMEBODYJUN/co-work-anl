# 全部原件与真实模型

主码5838B、六人packet6692B、七人packet5849B共18379B均正常取得并全文读，逐件核size/SHA256/Git blob。两冻结来源68fad804ec5946cb296f77dc5b336308a66abf12及aefc58eac3fc6eb5d7a47d087dd2c62b5aa9974c同字节，不计双运行。两packet每个保存对象的全部255项weights、query、计数、路径、比例及null字段均完整读；没有因文件名exact授认证。本次未导入/运行原码、LCM收益/全集/SPE/安全LP/Fraction checker或扩样。

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：有限单位客户、共同k≥1标签、r≥3名剩余单位提供者，已有合法有序主题前缀h；其长度B可为0，客户背景负载β_N=Σ_(a∈h)1[a∈N]。非负整数重数w_N是不同单位客户，保重复、空主题、同覆盖不同标签、零客户与任意离轨平局。程序缓存终局集合并不要求给定完整策略在同计数不同排序历史使用同一续局。

剩余终局计数q满足Σq_a=r。选择已占a的单人收益
\[
U_a(q;β)=\sum_{N\ni a}\frac{w_N}{β_N+q(N)}.
\]
有分子时q_a>0，分母正。剩余总利润为P_r=Σ_aq_aU_a；β=0才是覆盖W，β非空时不能把P_r误叫完整客户覆盖。真正静态安全值
\[
v_r(β)=\max_{\pi\in\Delta_k}\min_{c\in\mathbb Z_{\ge0}^k,\ |c|=r-1}
\sum_Nw_N\frac{\sum_{a\in N}\pi_a}{1+β_N+c(N)}
\]
用r−1个不观察查询的整数竞争槽，不是extra-one或自由分数背景。实际前两动作a,c及最终收入u₁,u₂给[PAIR候选](../候选/两步安全链的条件归并与有限探索边界--候选.md)
\[
u_1+u_2+(r-2)v_{r-2}(β+1_a+1_c)-r v_r(β)\ge0.
\tag{1}
\]
源程序只检查随机固定输入上的有限样本，未解决PAIR、强聚合或一般/六人half。

# 整数缩放集合BI到底保证什么

counts(k,n)用可重复组合列全部总数n的非负计数，每个恰一次。screen以K=2^k−1非空mask建立inc，w为int64；prefix经bincount形成合法过去，再令D=lcm(1,…,r+B)。对全部剩余终局q，den_N=β_N+q(N)，正den上shares=D/den，其余置0；pay=(shares*w)@inc为缩放收益，welfare=Σ_aq_a pay_a为缩放P_r。未占a的辅助值不承担收入解释；所有资格/路径求值中的a确被当前选择。

对剩余前缀计数s，R(s)为真实完整纯子SPE终局全集，非终端按
\[
M(s)=\max_a\min_{q\in R(s+e_a)}pay_a(q),\quad
R(s)=\bigcup_a\{q\in R(s+e_a):pay_a(q)\ge M(s)\}.
\tag{2}
\]
终端只保自己。lru_cache保存**整个集合**并按索引排序，不保存一份Markov策略。由[准确全集递推](../算法/完整历史纯SPE终局全集--算法.md)的独立有序孩子拼接，(2)必要充分，等号与任意离轨平局保全。root_outcomes是终局**计数向量数**，不是完整有序路径或完整策略数量。

这里“exact”仅指这个有理收益可LCM整数化及集合递推设计。NumPy shares、w、dot及welfare用int64，源码无溢出检测或任意精度后核；一般r/B/k/重数无界时不保证软件准确。在mask/计数数组本身可表示且可分配的输入上，D·max(1,Σw_N)在int64容量内足以控制这里的非负收益/剩余总利润累加；max中的1同时控制零客户时shares自身的LCM赋值；本生成族重数≤20、两保存例r6/7、B0的系数容量很小，但这不变成无限参数保证。随后int(pay)/D和welfare/D均转浮点输出，非Fraction证书。

代码自己实现(2)，不导入canonical、Space、旧策略库或任何本地helper。实际闭包只有Python标准库及NumPy/SciPy/HiGHS；原环境版本未捕获。本批0导入、0安全LP，不为验证已有单块/零值例重跑。

# 每个可实现前两动作与无序pair的充分压缩

先取R(0)及门槛M(0)。对每个有序a,b，程序保终局t需
\[
t\in R(e_a+e_b),\quad
pay_b(t)\ge M(e_a),\quad
pay_a(t)\ge M(0).
\tag{3}
\]
中间还要求t属于a孩子集合；由(2)与第二式这亦成立。必要性来自真实路径的两次BR；充分性是先在a孩子以b实现t，再给两层其他有序孩子独立贴最低惩罚SPE。故(3)恰刻画某完整SPE可实现的前两有序动作/终局，不是任意排列一个根可行终局。

对key=sort(a,b)只留这些合法实现的最小(pay_a+pay_b)/D及其原有序(a,b,t)。合并不丢最小PAIR：根v固定，同一无序pair的尾背景β+1_a+1_b相同、尾安全值相同，只有两收益和随合法终局变动。因此在准确算术下先对每pair最小化收益，再查尾安全即可覆盖该固定输入的所有完整SPE前两步预算；并不枚举所有完整policy。源码这里先把两项int收益相加再除D为float，并以严格<更新pairmin；容量内也可能把不同有理总和舍入相等而留先到的target。上述是数学压缩的充分性，未把软件浮点比较授为无限精度最小值认证。

first_pair_total是所有保留pair的最小两利润和，first_pair_labels只给无序标签；pairs计pair键而非可实现路径。若某pair进入尾安全LP并改善gap，源码用保存的**有序**a,b和目标t，随后每步选第一个满足t∈相应孩子R且当前pay≥门槛的动作，拼ordered_path及该终局每位收益。准确资格保证路径可扩成某完整有序SPE；源码未输出全树策略、未定义级重核一份完整certificate。

# 安全值剪枝与“数值screen”的边界

security对全部r−1槽计数背景构造浮点查询收益矩阵，用HiGHS解maximin，返回值v及查询π。它没有有理原始/对偶恢复或逐静态背景精确认证。

[固定背景嵌入定理](../定理/真实路径安全值链的嵌入与债务恒等式--定理.md)给
\[
v_{r-2}(β+1_a+1_b)\ge v_r(β).
\]
证明是尾的r−3竞争槽加两个固定动作，只是根r−1竞争槽的子集；对同一π先比较min再max。故若精确两利润和T≥2v_r，则PAIR≥T−2v_r≥0，可免求尾LP。

源码实际用T≥2*v_float−10⁻⁸直接跳过；这包含数值误差/容差，不是严格认证所有被剪pair。对其余pair才解尾r−3槽安全LP并算float gap，tailLP只计这些尾LP，根安全LP不计。best_pair=null可能表示全部被数值剪掉，不等于做过每个尾LP；tail_LPs0也不表示没做BI或根安全LP。

这一设计与旧固定策略锥交替客户LP不同：此处每个随机客户输入固定，(2)/(3)覆盖它的全部SPE相关终局及前两步；安全值仍浮点。它没有对所有客户重数、主题数、人数作统一证明，也没有计算OPT_m；aggregate_ratio<1只是强聚合桥的数值候选，不自动是half反例。
