# 资源对象及输入身份

本资源保全[三人局部势反例及六人实际嵌入](../反例/局部势排除损失的三人反例与六人实际嵌入--反例.md)的原始完整策略、生成与核验程序、原精确报告和父方审查。全部12源通过 `work.py clean show` 导出，原字节按 `original/attack/potential_tax/` 与 `original/review/` 保存于[证据包](../../tools/evidence/local-potential-exclusion-complete-certificates-primary/README.md)。每源ID、字节、SHA-256及两个完整冻结提交定位见其manifest。两个版本内容相同，以一个原件保留，不把相同文件当成独立数学证据。

本例的目录覆盖互异，是当前共同标签模型的子类。客户类型重数展开为不同单位客户；玩家权重全一。终局算术可以按标签计数缓存，但给定策略的域仍是所有有序历史。在全部检验中，每个历史/每个合法当前动作都要沿**同一给定策略**真实续行，不能将不同分支的有利平局拼接。以下不是主动客户设施模型，也不是静态PNE或存在一份好续局的断言。

# 三人重构器不等于仅读证书的核验器

`audit_esm_obstruction.py` 的输入是同目录另一个 `milp_p5_target123_bempty.json`，使用其中 `weights`、`types`、`second_actions`、`last_actions`。它对每个浮点权重执行 `Fraction(w).limit_denominator(1000000)`，统一分母后除整数公因子，省去零重数类型；固定 $p=5,m=3$、根行动0。该发现JSON不在本12源中，不能把本包描述成从头复现MILP发现的自含软件。

重构器直接按每个类型 $(B,w)$ 算 $U_a(z)=\sum_{B\ni a}w/\sum_{t\in z}1_{t\in B}$。对31个有序决策历史各比较五动作，保存规定/偏离终局和精确松弛并断言全部非负；势枚举使用35个无序三槽多重集，强制A只过滤含标签0的元组，保留重复。它另算实际路径的每位置势排除、利润安全差、税和总余额，并检查五标签覆盖两两不同，最终**覆盖写出** `esm_exact_obstruction.json`。

因此它既重构输入也做精确审计，对指定生成包有真实证明价值；但不是不接触发现报告、只读冻结JSON的独立实现。源主稿所称 `verify_exact_obstruction.py` 是另一个名字，不是本程序，本12源未取得其原件；不能把该文字独立性合同倒填给这个重构器。

三人包同时有显式 `strategy` 与根/二位/末位表。父方逐单位核验从后三者建立policy，不直接使用显式列表。本轮逐条核对31项列表与这些表完全一致，并核155条所存IC的历史/动作覆盖唯一、两终局确为同policy的续局；这消除了冗余字段指向两份策略的疑问。所存IC松弛非负是读取已有证据，不冒充本轮重新计算效用。

# 六人构造器与两份核验器

`embed_six.py` 读取三人包，把客户类型保持整数重数，另加只喜欢F的510人；用 `Instance`、`CustomerType` 和 `ExactSPESolver.certificate(on_path=(5,5,5,0,1,2))` 生成六人包。它通过原仓库层级调整 `sys.path`，依赖原 `customer_attraction` 模块；本证据包保留其原代码而不伪造可独立运行的求解器副本。构造的指定路径不自动证明给出的策略是SPE，证明责任由冻结策略及下面两份定义级核验承担。

`verify_six_embedding.py` 只读六人JSON，检查字典无重复历史，历史集合恰为所有长0到5的六字母串，行动为合法整数、客户重数为正整数；保存每个历史的真实完成终局。收益以类型重数与 `Fraction` 精确计算，计数只缓存算术。每个有序节点的全部六行动均实际续行，检查55986个非负松弛；另检查六覆盖互异、实际路径与被检查前缀相符。它用56个三槽多重集算背景势与强制A势，用462个六槽多重集算全覆盖最优，断言局部值为 $(801,754,166,120,1)$，并断言本例满足half。输出报告绑定所读六人JSON的SHA-256。

`verify_six_esm_units.py` 不导入构造器、作者核验器或规范SPE求解器。它将类型展开成1131个客户，保留全部9331条有序策略；先建立全部 $6^6$ 个终局，再按深度从5到0逆序求真实完成终局。每份被用作当前行动的标签在对应终局必有至少一位提供者，均分分母为1到6之一，故乘60后每项份额精确为整数。462个计数键只缓存客户逐名算术，所有有序history仍分别续行和比较，不合并策略。本轮结构检查另确认22个同计数组规定不同动作；该数不冒充原审计报告的字段。

逐单位核验在实际前三F前缀穷尽216个有序三槽后缀，计算全部背景调和势和含A限制，得同样差1；全根OPT用“六槽可选择全部六标签覆盖全部有兴趣客户”直接达到总客户上界1131，而非进行另一次全策略福利搜索。

本轮还把三人31动作表与六人FFF后限制旧五标签的31节点逐项比较，差异恰为七个末位节点：AC的B→E、AE的C→D、BB的C→D、CE的B→D、EA的C→D、EB的C→D、EC的B→D；六人完整历史在每项前加FFF。七个替代动作在三人原IC行均为零松弛，完整六人合法性（包括新增F选项）仍依输入绑定全树审计。实际路径收益/局部势相同不表示两份完整尾动作表相同；差异原记录已写入结构检查JSON。

# 两个逐单位审计报告的信用边界

# 本轮实际检查、复用与接续

本轮完整读取原文本/源代码及全部JSON字段，消费三人31节点、155条所存IC和六人9331节点的每条记录；检查合法历史集合、六人实际路径、三人冗余策略表一致、六人客户恰为原客户加F510，及三份报告的SHA绑定。结构检查保存在 `source-structure-inspection.json`。另仅新算四行F后缀静态势分解，数学公式和枚举域已在反例正文展开。现有精确审计证据充分，没有导入或执行原构造器，没有重跑成熟155/55986项IC、发现MILP或随机搜索。

此前[局部势排除审查](../审查/局部势排除接口的反驳与望远镜范围--审查.md)和 `optimal-kernel-and-exclusion-source-primary` 包仅读并保父方审查原文，未取得上述完整策略和核验程序，故本批为证据与算法合同补全，原准确BELL/TEL和 $r\le2$ 推导复用。全仓相关检索未发现对621/1131例的数值纠错；[相邻双主题候选](../候选/相邻真实双主题的势排除预算--候选.md)保持未证状态，不能由本单步负例改成FALSE。
