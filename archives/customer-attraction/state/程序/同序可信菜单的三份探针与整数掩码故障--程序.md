# 同序可信菜单的三份探针与整数掩码故障

## 1. 来源与共同数学接口

本页完整实读 `theta_probe.py` 2228B、`theta_targeted.py` 1776B、`theta_dp.py` 2429B、`random_search.py` 1020B及150B工作区登记；四脚本都在模块顶层启动循环，没有main guard，故不能为读取函数而直接导入。全部原字节、两冻结版本及逐源SHA见[源清单](../../tools/evidence/ordered-menu-and-source-programs-primary/source-manifest.json)。旧workspace的schema=1、save=customer-attraction、actor=R-b28b3013e6464e70862b4993359a6964、instance=5823cdf320b644dfb9c26513c37226fe只承担来源身份，不改当前Boss3绑定。

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)。目录有p≥1个标签，人数m≥1，客户有限且单位价值；CustomerType将相同兴趣客户按非负整数重数合并。空主题、同覆盖不同标签、重复行动、零客户以及任意离轨历史和平局仍是模型的一部分。随机生成的某个子域不缩减原问题。

规范 `Instance`、`ExactSPESolver` 及证书四模块已按[依赖清单](../../tools/evidence/ordered-menu-and-source-programs-primary/dependency-manifest.json)中的同SHA冻结实现比较。对前缀计数c，`_solve(c)`的真实含义是该子博弈所有可实现纯SPE终局计数集合E(c)：对每个当前行动，取其子博弈可实现终局，再用最大“最坏可信偏离收益”阈值筛选。计数缓存复用子博弈，不表示某一份完整策略必须在同计数历史取同动作。

固定一条可实现的有序实际路径h，令c_i为前i人计数，i=0,…,m−1。三脚本均定义

\[
L_i(a)=\min_{z\in E(c_i+e_a)}u_a(z).
\tag{1}
\]

这里强制当前选a后，取**所有可信后继**中的最小当前收益；没有对当前行动再取最大。若h由某完整SPE实现，实际第i人利润至少L_i(a)，但不同(i,a)达到最小值的后继可以属于不同完整策略。这不是同一份固定σ的菜单，也没有自动给其它来源的入流付款。

欲检查的加强命题是：对相应实际h，以及**每个**达到OPT_m的有序m元比较题组T，

\[
\sum_{i=0}^{m-1}L_i(T_i)\ge OPT_m-W(h).
\tag{2}
\]

它强于“存在一个对齐/匹配可付款”。因此即使找到(2)失败，也还须区分是否只是固定顺序加强版失败，而非half失败。已有[静态证书与同序可信矩阵正文](../资源/最坏分母静态证书与同序可信矩阵的精确边界--资源.md)保留了这一量词差别；本页补回此前未读的实际程序。

## 2. 三份theta探针的真实覆盖范围

|原件|输入与尝试上限|实际路径范围|比较题组范围|
|---|---|---|---|
|theta_probe|seed20261024；p=2…4，m=2…5；客户数n在[p,min(12,4p)]；1000次尝试|全部`outcomes()`，再对每个终局枚举全部`ordered_outcomes(z)`|枚举最优支持并遍历p^m有序题组，精确支持匹配和去重|
|theta_targeted|同seed；p=3，m=6…12；七非空兴趣类型各重数0…15；跳过全零；10000次尝试|全部可实现终局及全部可实现有序路径|预先列出全部3^m题组中的最优者，再取最小菜单和|
|theta_dp|同seed；p=3，m=6…10；七类型各重数0…20；20000次尝试|只看最坏福利终局，每个终局只取`next(ordered_outcomes(z))`这一条路径|意图按最优支持做动态规划；原字面实现先报错，见§3|

第一份的源码注释称“一份canonical assignment”，实际循环仍枚举所有符合精确支持的有序题组，不应照抄注释缩小范围。第二份的 `if O<=2*W: pass` **不会过滤任何实例**，所以它并非只检查疑似half失败者；满足half的实例也进入测试。第三份即使将语法错误修正，也没有枚举同一最坏终局的其它有序路径，更没有枚举全部完整策略。

前两份的菜单与比较用Fraction精确计算。`ordered_outcomes`枚举的是能由某完整SPE实现的行动路径；这比一条canonical路径多，却仍不同于枚举所有离轨动作图。随机兴趣掩码不含空兴趣，但不同题标签仍可能具有相同覆盖，某标签也可能为空。

三脚本都宽泛捕获 `Exception` 后跳过实例。第一份另有成功检查数，尝试1000不能替代成功数；后两份的进度/最终`none`不附完整成功次数。没有本批配套旧stdout、退出事件或逐实例结果，不能以源码上限宣称已完成相应随机实验。第三份的错误还会使其阴性输出完全失去原拟数学含义。

## 3. 整数掩码故障：原函数一次精确定位

`theta_dp.py` 的 `best_opt_dp` 先执行：

```python
welfare = [inst.welfare(tuple(int(j in mask) for j in range(p)))
           for mask in range(1 << p)]
```

`mask`是整数，`j in mask`不是位测试。对p≥1，凡执行到该行都会抛出 `TypeError: argument of type 'int' is not iterable`，在使用ls之前就终止。外层 `try: result=run(inst) / except Exception: continue` 将其吞掉；若循环走完，仍会打印`none`。这个输出不能证明(2)经检查未失败，也不能证明没有实例。

为固定这个具体实现问题，本次只从原SHA `f07d6152e5aa286e39c9e36f227133b6488bf6e3cf0f44fe97b161fda3e4405f`提取**未改写的**函数AST，保留原行号，以真实冻结规范Instance构造六人三标签输入`({0},∅,∅)`，调用一次。ls为空不影响定位，因为错误发生在使用它之前。独立[驱动](../../tools/evidence/ordered-menu-and-source-programs-primary/check_theta_dp_literal_failure.py)及[原错误结果](../../tools/evidence/ordered-menu-and-source-programs-primary/replay/literal-failure.json)保留该TypeError。它是实现错误的有限复现，不是策略反例。

实际[执行事件](../../tools/evidence/ordered-menu-and-source-programs-primary/replay/execution-record.json)：2026-11-02T14:28:29.921434+00:00开始，0.13356166199992003秒；驱动退出0表示预期异常被精确断言，**不表示原数学程序成功**。原函数调用1次，原模块导入、原随机迭代、SPE求解、LP、修正后的DP均0次。没有填入假的辅助求解器或把修补后的结果冒作原输出。

接续修复可将位判断写为`int((mask >> j) & 1)`；本次保留原字节，未执行修正。只有修正、明确范围、记录成功数并给出独立比较后，才可讨论新阴性实验。

## 4. 意图中的支持动态规划为何可用，以及尚未执行什么

给定真正已算出的矩阵L和候选最优支持S，定义d_i(M)为前i个角色使用的标签集合**恰为**M⊆S时，ΣL最小值。初值d_0(∅)=0，其它为∞；转移

\[
d_{i+1}(M\cup\{a\})\gets
\min\{d_{i+1}(M\cup\{a\}),d_i(M)+L_i(a)\},\quad a\in S.
\tag{3}
\]

每个前i+1长度题组唯一分成前i长度题组及末标签，所以归纳证明(3)同时不漏合法题组、不引入不合法题组。终值d_m(S)强制每个S中标签至少出现一次；对覆盖等于OPT的支持取最小，得到所有最优有序m元组的最小值。大小大于m的S不可达而被自然排除；零客户时OPT=0，仍须取可由m次合法行动实现的非空支持，空支持在m≥1时不可达。

这是对代码意图的独立条件性推导，不是修正程序的执行证明，也不消除第三脚本只看首条最坏路径的限制。原 `None`、异常跳过和最终`none`在后续实现中应分别计数。当前六人全历史half目标不因此解决。

## 5. 普通福利随机搜索另是什么

1020B `random_search.py`使用同seed，尝试4000次，p=2…5、m=2…7、n∈[p,min(18,4p+4)]。每次用规范全部SPE终局集合取最小福利mw，再与真正OPT比较，得到Fraction `OPT/mw`。mw=0时源码用999作哨兵，不能把999当真正效率比；生成的正客户、正人数有效实例下需另由模型解释零福利是否可达。

`BEST`只保存输入和最坏终局集合，不附一份完整策略证书。异常被跳过；找到比值>2或累计超过110秒才退出，但时间条件只在一次成功求解之后测试，既不是单次求解超时，也不是硬110秒界。失败迭代直接continue会绕过该条件。没有原stdout或退出事件，本次原入口0次，故不宣称4000样本已完成或110秒未找到反例。
