# 实际输入与程序身份

[原程序](../../tools/evidence/deletion-branch-probe-program/original/deletion_36.py)2574B，SHA-256为 `b1c904461bf89c16ecee9d9e363aebd545d9a7117b5a7de4cf4ae2ff45ed0aef`，两冻结提交同字节。文件名中的36没有给出36名提供者或一份固定36客户输入。源码实际设置n=3、k=6；在六标签全部63种非零客户兴趣类型上优化归一质量，固定完整反组策略而不是从随机客户实例重新求策略。

它只循环一次，依次检查六个纯查询、十五个均匀两题查询和一个六题均匀查询，共22个浮点LP。目标是寻找在此固定SPE策略锥内使

\[
\frac52\min_{i=0,1,2}\mathbb E_{a\sim p} f_{z_{-i}}(a)>W
\tag{A}
\]

的客户质量；z是原实际终局，z₋ᵢ只删除其第i个位置。这里其它两位的主题被冻结为原终局主题，查询不触发他们重新回复。(A)攻击的是**实际删位背景支持的封顶**，不是直接攻击真正静态安全值，也不是完整真实偏离菜单或因果删人策略。

本轮未改原字节、保原文件名隔离执行恰一次，正常完成22个LP调用，stdout为

```text
0 -0.08333333333333315 (0, 3, 4) 0.5
```

完整进程墙钟1.676442691秒，exit0、stderr空，原件及五个依赖前后SHA均不变。未触发正差候选分支。本负数接近−1/12，但原程序没有给精确对偶或保存各LP解，故不把它改写成精确最优值或全查询结论。[执行记录](../../tools/evidence/deletion-branch-probe-program/original-event/execution.json)与[原stdout](../../tools/evidence/deletion-branch-probe-program/original-event/stdout.txt)分别保全；22是由正常完成的原循环得到的调用数，不是逐次solver状态追踪。

# 固定模型、全部策略历史与客户变量

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：有限单位客户、单位提供者、有限非空共同目录，纯策略在全部有序历史有定义。重复动作、空主题、同覆盖异标签、零客户和任意离轨平局均保留。

标签为0至5，分X={0,1,2}、Y={3,4,5}。源码固定策略σ为：根取0；首题在X则第二位取3，否则取0；历史(a,b)之后，末位在b所属组三标签中取未在(a,b)出现的最小标签。每组有三题，前两次最多占两种，故每个重复或离轨历史都有合法动作。全部决策历史数1+6+36=43，实际路径z=(0,3,4)。规则对原完整有序h执行，不把同负载历史强行共用回复。

客户兴趣mask按整数M=1,…,63排序，第a位表示是否接受主题a；设w_M≥0。零mask完全不接受任何题，可删去而不改变收益和覆盖。程序要求Σ_Mw_M=1，因而对非零总量作齐次归一，零客户实例属于另一个平凡边界；w不是63位客户，也不是提供者权重。整数质量展开为单位客户，有理可行质量可统一清分母。浮点有理化后的点必须重新核验才能使用这一实现事实。

对包含该行动者的有序终局y，定义

\[
\rho_M(a,y)=
\begin{cases}
1/\sum_{b\in y}\mathbf1_{b\in M},&a\in M,\\
0,&a\notin M.
\end{cases}
\]

求和按玩家位置计，重复标签各占一个覆盖者。固定σ后，记end(h)为沿同一张完整策略表完成的终局。每个h、每个a产生真实IC系数

\[
\Gamma_{h,a;M}=\rho_M(\sigma(h),end(h))
-\rho_M(a,end(h+a)).
\tag{1}
\]

全部258=43×6行中含43个自身行动比较；其余215个涵盖每个真正不同动作。对给定非负w，Γw≥0与这份完整策略为纯SPE等价；源码没有假定所有客户质量都使该策略为SPE。根覆盖系数为c_M=1{M与{0,3,4}相交}，所以W=c·w。

原Γ及c先由Fraction计算，送入HiGHS前才转NumPy float。每个Γ行末再添一个0，对应下一节的辅助变量t。Γ不因p而改变，22个LP复用的是同一个固定策略锥。

# 删除背景的静态查询LP

三个背景分别是z₋₀=(3,4)、z₋₁=(0,4)、z₋₂=(0,3)。任意静态两槽背景B的查询收益定义为 \(f_B(a)=\sum_Mw_M\rho_M(a,B+a)\)。对查询分布p，设

\[
d_{i,p;M}=\sum_{a=0}^5p_a\rho_M(a,z_{-i}+a),\qquad
D_z(p,w)=\min_i\sum_Mw_Md_{i,p;M}.
\tag{2}
\]

查询最后插入只是静态收益求值，不是宣称查询者在原顺序游戏中移到了末位。对手i可在知道p后选择，但不能看见这次抽到的a再选i；同一p用于全部三行。

对22个p逐个最小化

\[
\min_{w,t}\quad c\cdot w-\frac52t,
\quad \Gamma w\ge0,
\quad t\le d_{i,p}\cdot w\ (i=0,1,2),
\quad w\ge0,\ t\ge0,\quad\sum_Mw_M=1.
\tag{3}
\]

因为目标中t系数为负，精确最优时t取可保证的最小删除查询值D_z。实际矩阵有64变量、258条负Γ行加3条删除行共261条不等式、1条归一化等式；删除行客户列是−d、t列是1。bounds将64个变量都设非负。没有全静态背景约束、额外静态Nash约束或显式OPT比较。

22分布的确切族为

\[
\mathcal P=\{\delta_a:0\le a<6\}
\cup\{(\delta_a+\delta_b)/2:0\le a<b<6\}
\cup\{(1/6,\ldots,1/6)\}.
\]

它不是整个分布单纯形，遗漏非均匀两题、一般三至五题及非均匀六题查询。一次没有正差只涉及这22个固定p，不量化全部p，也不扫描其它完整策略。

每个精确LP都非空且有界：把单位质量全放M=63，所有主题覆盖同一客户，任意三人终局各得1/3，全部Γ=0；可取t=1/3、W=1。一般归一质量给d≤1，因此0≤t≤1，w位于紧单纯形。这是解析可行性说明，不能代替原求解器各次success或精确最优证书。

# 与真正安全值、36客户例和已有固定策略证书的区别

真正安全值使用所有合法两槽背景：

\[
v_3(w)=\max_{p}\min_{B\in[6]^2}\mathbb E_p f_B(a).
\]

三实际删除背景只是其子集，故对每个p，\(\min_B E_pf_B\le D_z(p,w)\)。若能对所有p证明W≥(5/2)D_z(p,w)，即可得到相应真正弱安全聚合预算；反过来，仅某个p使(A)成立，即受限封顶失败，也不能推出W<(5/2)v₃。一般静态安全值与half的充分链见[锐目录计数界](../定理/静态混合安全值的锐目录计数界--定理.md)。

[36客户删除支持障碍](../引理/不交复制的安全值稀释与实际删除支持障碍--引理.md)使用同一反组策略：跨组二题客户各1、两X两Y四题客户各3，实际收益(10,12,12)、W=34。纯查询5在三个删除背景都得12，故实际删除支持无法支付更强的W/3封顶；但本程序检查的较弱阈值是W/(5/2)=68/5，12<68/5。该36客户点的(5/2)D−W为−4，不是本入口的归一客户输入，也不是本轮float最优点。

更重要的是，同一固定43历史策略的整个非负客户锥已有[共同静态安全对偶](../定理/三人六标签固定分组策略的共同静态安全对偶--定理.md)：Q在背景01、02、03各取1/3，可对所有查询给E_Qf≤W/3。01和02并不在实际删除支持{34,04,03}内。该证书因此能证明这份策略的真正安全值预算，而不能据此假设本受限三背景也有同样封顶；反之，本探针若找到受限支持失败，也不反驳这个自由Q证书。

[安全最优查询面无悔候选](../候选/安全最优查询面的聚合静态无悔预算--候选.md)还另要求存在安全最优p使**所有删位费用之和**不超过W。本程序固定22个p、使用三个费用的最小值、系数5/2，且未约束p安全最优，不能与该候选的存在量词和求和预算互换。[经验iid核反例](../反例/实际终局经验独立核封顶--反例.md)也使用不同的对手支持和相关结构，不能冒充这里三删位菜单的失败。

# best与候选导出的真实合同及路径错误

best从(−10⁹,None)开始，成功LP若−res.fun更大就保存(p,res.x)，因此本源best确实是成功求解中最大的浮点违反值，和另一类“初始化0不更新”的探针不同。程序不保存每个LP状态或值；某次不success就静默跳过。当前best为负且不是初始值，至少有成功求解；不能从单行stdout认定22次各自都有精确证书。

若best>10⁻⁸，源码对res.x前63个客户坐标保留x>10⁻⁸者，再分别做`Fraction(float(x)).limit_denominator(1000000)`，清公共分母得到整数wi。第64个t由zip截断而不保存；打印按wi重算的minGamma，却没有assert其非负，也不重算删除查询缺口、归一化或OPT。候选JSON只含n、k、weights、完整sigma、p与root；根历史用空字符串，其他历史逗号连接，分布值为分数字符串。它本来只能是待精确复验的候选。

还存在本源独有的输出路径错误：最后一行用

```python
__file__.replace('deletion_probe.py','deletion_candidate.json')
```

而实际文件名是deletion_36.py，替换不会发生，`open(...,'w')`会把正在执行的脚本覆盖为候选JSON。它不是相邻deletion_probe.py中有效的候选命名。原字节必须保留这个事实，不能悄悄把修正后的脚本当作历史原程序。本轮在隔离目录保原名执行，因未命中正阈值没有发生覆盖；未通过模拟命中另跑该分支。
