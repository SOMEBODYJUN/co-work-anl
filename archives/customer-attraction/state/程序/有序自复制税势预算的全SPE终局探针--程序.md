# 输入、精确尺度和所有终局量

数学合同为整数 $m\ge1,k\ge1$，共同标签目录 $0,\ldots,k-1$，长度恰 $2^k-1$ 的非负整数数组 $w$。坐标 `mask-1` 对应非空兴趣集合 $B=\{a:(mask\mathbin{\gg}a)\&1=1\}$，**主题0是最低二进制位**；这不同于其它程序的六元bit词典序。每个 $w_B$ 表示 $w_B$ 位不同单位客户，提供者均为单位权重。空兴趣客户不影响任何值而被省去；全零客户、空覆盖主题、相同覆盖的不同标签、重复行动没有被源码排除。

对有序终局 $p=(a_0,\ldots,a_{m-1})$，令 $c_B(p)=\sum_i\mathbf1_{a_i\in B}$。程序先枚举全部 $k^m$ 个有序终局并算

\[
u_i(p)=\sum_{B:a_i\in B}\frac{w_B}{c_B(p)},\qquad
\Phi(p)=\sum_Bw_B H_{c_B(p)},\qquad H_0=0,\quad H_t=\sum_{j=1}^t\frac1j.
\]

只有所选主题在客户兴趣集合中才计算该客户收益，故分母至少1。`scale=L=lcm(1,...,m)`；内部 `payoff` 和 `phi` 是 $L u_i,L\Phi$，不是未缩放原值。客户最终负载以及下文的自复制分母都在 $1,\ldots,m$ 内，所以非负整数重数域的每一次 `//` 都整除，既无浮点容差也无向下取整误差。Python整数没有固定64位溢出上限。

`one` 没有运行时类型、长度、符号或正人数校验。任意实数/分数权重不因“weights”这个参数名获得支持；不先清分母就用 `//` 会改变数学量。负数不是合法客户重数，长度错误可能截断或越界，空目录也不属于本合同。CLI生成的数组满足上述非负整数长度要求。源码并未读取背景负载，因此本实现不直接核合法非零前缀的 $P_r(b)$，更不能把测试输出当任意实数背景结论。

# 全有序历史的终局集合递推

每个完整有序前缀 $h$ 都有自己的字典键；程序没有把同计数的不同历史绑为同一破平局策略。终端 $p$ 置 $R(p)=\{p\}$。长度 $i$ 的决策节点定义

\[
M(h)=\max_{a<k}\min_{p\in R(h a)}u_i(p),\qquad
R(h)=\bigcup_{a<k}\{p\in R(h a):u_i(p)\ge M(h)\}.
\tag{1}
\]

源码使用统一乘 $L$ 后的整数收益。式(1)精确描述从该前缀能够由**某份完整历史纯SPE**实现的有序终局，不是只沿某条在轨路径的最优性，也不是静态NE，更不是强制计数策略。其证明与[完整历史纯SPE终局全集](../算法/完整历史纯SPE终局全集--算法.md)一致：任何实际孩子的收益须至少达到每个离轨孩子可实现收益的最小值，给必要性；反向在选中孩子保留目标终局，在其余不同有序孩子分别选使当前玩家收益最小的子SPE，可独立拼接，给充分性。有限集合保证极值达到；取实现最大孩子下界的行动保证每层非空。全零与所有平局仍适用。

程序枚举的是每条**可实现有序路径**，不是所有实现该路径的完整策略。每条路径在每层只有自己的唯一前缀，孩子集合互不重叠；列表构造因此不因不同子SPE实现数而重复计数。`len(realizable[()])` 是根可实现路径数，不是完整SPE策略数。源码不保存式(1)的孩子实现选择，也不导出全历史策略证书；若发现负余量，仍须展开兼容的各离轨子策略并逐历史验证，才能交付通常所需的完整见证载体。递推正确性的解析证明不等于程序已经保存了该载体。

# 被攻击的预算与其有限极小值

在一个根可实现路径 $p$ 上，第 $i$ 位之前的客户负载为

\[
b_{B,i}=\sum_{j<i}\mathbf1_{a_j\in B},\qquad r_i=m-i,
\qquad s_i(p)=\sum_{B:a_i\in B}\frac{w_B}{b_{B,i}+r_i}.
\]

源码 `safe` 为 $L\sum_i s_i$，不是最优静态安全值 $v_m$，也不是某个共同混合查询的保证。对于该实际玩家覆盖的客户，真实终局负载不超过 $b_{B,i}+r_i$，故逐项 $u_i(p)\ge s_i(p)$，从而 $\sum_i s_i\le W(p)=\sum_i u_i(p)$。这里仅用实际路径的份额界；没有把未来真的改成全部复制该主题。

按行动到达顺序展开谐和势，得到有序自复制税

\[
C(p)=\Phi(p)-\sum_i s_i(p)
=\sum_i\sum_{B:a_i\in B}w_B
\left(\frac1{b_{B,i}+1}-\frac1{b_{B,i}+r_i}\right)\ge0.
\]

`pmax` 在**全部** $k^m$ 终局上取 $L P_m(0)$，其中 $P_m(0)=\max_q\Phi(q)$，不是只对SPE取最大，也不是 $OPT_m$。程序对根集合求

\[
\operatorname{margin}(p)=L\,[\Phi(p)+W(p)-\sum_i s_i(p)-P_m(0)]
=L\,[W(p)+C(p)-P_m(0)].
\tag{2}
\]

因此对于当前固定客户向量，一次 `one` 精确检查全部完整纯SPE的目标终局：负最小值说明该实例确有可实现路径违反预算；非负只说明该实例的所有SPE路径通过。普遍候选仍是

\[
\forall\,\text{合法实例}\quad\forall\,\text{完整纯SPE}\qquad
P_m(0)\le W+C.\tag{P0?}
\]

一个随机样本或有限客户集不能替代此前两个全称量词。原六人目标只对应其 $m=6$ 切片。

返回值的完整结构为 `((margin, p, L*W, L*Phi, L*sum_s), L*P_m, number_of_root_paths, L)`。当余量打平，`best` 只在严格改善时替换，故保留有序枚举中的首条路径；平局没有从可实现集合中被删除。这个元组未直接给 $C$、$OPT$、效率比或完整策略，不能从字段位置自行添加不存在的输出。

# CLI随机域与日志局限

每个客户类型独立从 `[0,0,0,0,0,1,2,3,5,8,13,21,34]` 选重数：0的概率5/13，其余八个正值各1/13，允许样本重复。这不是在所有固定总客户数的实例上均匀抽样。默认至多1000个三人五主题向量，只在严格更新跨样本最小**缩放余量**时打印一行JSON，字段为 trial（从0起）、weights 和上述 result。出现首个负余量立即停止；相等记录与不改善样本都不打印。初始化的 `10**100` 是有限哨兵，不是数学无穷；它不影响本次有限输入，但不宜用其初始化逻辑承诺无限参数范围。

程序没有最终summary、实际已完成trial总数、stderr报告或落盘结果，也不把 m/k/seed/源SHA写入每一条JSON。`trials<=0` 会没有样本和stdout，不能作阴性证书。单凭最后一条改善行的trial编号不能推断总运行次数。原研究工作区要求保存seed、版本和精确证书；本程序的日志合同本身不满足这些全部记录要求，使用者须另保真实命令和事件。任意目录/人数下的有限诊断不是恰六人half证明。

此实现在终局和逐根路径上计算全部 $2^k-1$ 类型，粗略算术工作量为 $O(m2^k k^m)$。每条完整路径在各层前缀集合出现一次，集合元素总量至多 $(m+1)k^m$；加收益表后的存储量为 $O(mk^m+2^k)$，不计整数位长。它没有规范实现的计数集合缓存，较大参数会迅速昂贵；输出路径数也不能当作遍历完整策略树的数量。

# 与后续材料的准确关系

本次全文比较了下列自足对象；这些材料的成熟核验均未重跑。

1. [相邻真实双主题的势排除预算](../候选/相邻真实双主题的势排除预算--候选.md)给出 $C=\Phi-\sum_i s_i$ 与本式逐项相同，说明真实相邻pair义务如何条件归约到六人P0；一般pair仍未证。本程序既不核pair差，也不检每个合法前缀的预算。
2. [六客户逐分支归纳边界](../反例/调和复制税逐分支归纳的六客户边界--反例.md)反驳更强BRANCH-MONO，所给三人SPE仍有 $P_3\le W+C$；不能把该负例写成本探针目标已假。
3. [全混合终局势预算的静态行族不足](../障碍/全混合终局势预算的静态行族不足--障碍.md)的1363/2292行静态点说明即便假设P0与若干其它行也不足以完成half。那些点没有完整SPE，不反驳P0的SPE有效性；本程序恰是在另一接口上用真实可实现终局检查它。
4. [十一客户调和势反例](../反例/三人均衡调和势低于最优覆盖的十一客户证书--反例.md)及[五客户无拥挤负载障碍](../反例/五客户无拥挤SPE负载桥障碍--反例.md)针对 $\Phi(actual)\ge OPT$ 或规范化单纯负载势。式(2)另有 $W-\sum s_i$，不能将这些已失败加强和本P0等同。

即使P0成立，也只因 $OPT_m\le P_m(0)$ 得 $OPT_m\le W+C$，不能直接得到half，因为 $C\le W$ 不普遍成立。一个单位客户、一个覆盖该客户的合法主题、六人全部选择它即是解析例子：唯一策略是完整SPE，$W=1$、$\Phi=H_6=49/20$、$\sum s_i=1$，所以 $C=29/20>W$，而P0恰取等号。这是公式的直接代入，不是本次新增程序样本或half反例。

# 接续用途与尚缺的工作

程序适合对一个给定非负整数客户向量检验所有可实现SPE路径的根P0；或者用显式记录的随机域寻找负候选。若找到负值，应保原权重/参数/全部缩放语义，从集合递推选择离轨实现并导出完整策略，再以单位客户定义逐节点审计，并只按对应人数声明反例。若希望证明P0，则需要跨实例的解析论证或全域证书；后续pair、真实多枝共同付款的缺口仍在。若还要推出half，则必须处理 $C$ 与覆盖预算的差，不能在数值非负或P0成立后省去该环节。
