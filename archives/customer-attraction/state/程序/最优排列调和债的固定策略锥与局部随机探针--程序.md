# 五个入口的共同模型和精确目标

五原程序共9141B均全文实读，两个冻结提交逐字节相同，原字节和两个commit/path定位见[来源清单](../../tools/evidence/h4-five-attacks-and-threshold-primary/source-manifest.json)。源码分别保存在该证据目录original/<source-id>/下。它们针对[有限单位客户共同目录模型](../定义/共同目录完整历史模型--定义.md)，但有限输入和实数LP松弛不能替代全部目录、人数和完整历史SPE的量词。

固定一份完整有序策略σ及其actual叶q=(q₁,…,q_m)，actual客户负载c_x，福利W。每个位置i在原actual前缀q_<i改选合法整主题T，沿同一σ全部新后继完成，利润记d_i(T)。不能冻结actual尾部，也不能另挑可信后继。记

\[
 e_T=\sum_{x\in T}\frac1{c_x+1},\quad
 g_i=\sum_{x\in q_i}\frac1{c_x(c_x+1)},\quad
 G=\sum_{c_x>0}\frac1{c_x+1}=\sum_i g_i,\quad
 \Delta_i(T)=e_T-d_i(T).
\]

真实IC仅给d_i(T)≤u_i(actual)，故Σ_i d_i(T_i)≤W。对于比较m元组并集U、覆盖O，逐客户不等式1_(k_x>0)≤(c_x+k_x)/(1+c_x)给

\[
 O\le W-G+\sum_i e_{T_i}
 \le2W-G+\sum_i\Delta_i(T_i).
\]

标准H4要求对每个实例、每份完整SPE，存在一个覆盖达到OPT_m的m元组及一个共同排列，使ΣΔ≤G。若成立则推出half。owner只去掉比较重复信用，不会自动支付实际覆盖在U外的分数信用；完整层级已在[最优排列与归属端点边界](../资料/最优排列调和债与归属端点薄化的边界--资料.md)证明，本程序不把净差、owner或标准H4混为同一个目标。

四种锥目标分别是：

|程序|最大化的违反量|它实际攻击的断言|
|---|---|---|
|attack_endpoint_max.py|m e_T−W−G，对每个T|m max_T e_T≤W+G；这是half的充分桥，不声明蕴含H4|
|attack_same_query_debt.py|m e_T−Σ_i d_i(T)−G，对每个T|任意同一查询重复m次的总债≤G|
|attack_local_debt.py|e_T−d_i(T)−g_i，对每个(i,T)|逐位置Δ_i(T)≤g_i|
|attack_h4_cone.py|全部比较支持/排列共享的正间隔t|下节的唯一最优支持内，全部共同排列都违反H4|

逐位置界若对全部i,T成立则给任意同query及任意比较元组/排列；任意同query界配合IC给端点最大桥。端点最大桥成立也足以用m maxe覆盖任意比较元组而给half。不过这些并非H4的等价重写，某一最强界失败不能反H4的存在型最优元组量词。local_debt与same_query的文件头还复用“endpoint-max”文字，实际数学目标应以循环中的gap为准。

# H4锥怎样保住最优元组的存在量词

h4_cone对K个标签的所有m个**不同**标签组合T逐一测试，变量另加t≥0。对每个不同m支持U≠T加

\[
 \operatorname{cov}(U)-\operatorname{cov}(T)+t\le0.
\]

对T的每个排列π加

\[
 t\le\sum_{i=1}^m[e_{\pi(i)}-d_i(\pi(i))]-G.
\]

在同一完整IC锥、W=1上最大化t。若精确t>0，则T在所有m个不同标签支持中严格唯一最优，且每个共同排列债务都超过G。这与只找到一个坏排列不同。

源码没有直接枚举含重复标签的m元组。对本main的三个输入，K=6且m=3、3、4，故K>m；此时严格支持条件确实足以补全存在量词，证明如下。任意至多m标签支持S可补到某个m支持V，单调性给cov(S)≤cov(V)≤cov(T)，所以T全域最优。若S不包含于T，则补出的V必不等T，严格间隔使其不能最优；若S真包含于T，取a∈T\S及b∉T（K>m保证存在），则V=(T\{a})∪{b}覆盖S而V≠T，同样得cov(S)<cov(T)。因此任意最优m槽元组的支持只能恰为T，只能每标签一次，全部可能元组正是已加的m!排列。

这个论证用的是**严格t>0与K>m**。一般调用若K=m，没有另一m支持，重复元组或T的真子支持可能同为最优，而程序只压T排列，不能直接宣称反存在H4；若K<m则组合列表为空，程序本身不测试目标。原main每个目标的LP数为20、20、15；每个目标加入的排列约束分别6、6、24。它们是源码结构/输入元数据推出的**计划范围**，不是已经发生并保存的55次运行事件。

浮点成功且t>10^−8只打印并收集正提案，最终JSON仅到stdout，含topics、players、target、margin、正weights、完整actions与terminal。代码头要求阳性有理化并精确检查全部历史，但实现没有执行这些步骤。完整actions随提案输出便于后来认证，不代表认证已经完成。原5源包没有这份stdout、LP报告或精确阳性证书，本次没有制造一份新的空结果替代它。

# 随机局部入口的精确性与有限边界

attack_local_random独立使用标准库random和Fraction，不导入任何规范求解器或NumPy/SciPy。固定K=m=4、随机种子260624，对15个非空兴趣类型每次各独立取整数重数0,…,20，至多2000次。一次walk递归遍历完整四叉树：先为每个孩子递归选完真实后继，以Fraction计算当前整人利润，再在全部最大值标签中random.choice，保存该有序历史动作。由终层向根归纳，这会生成一份完整纯SPE，保留所有85个决策历史、256个终叶的真实后继；它不枚举所有平局选择或所有SPE，声明的cache字典未使用。

随后对16个(i,T)逐项用Fraction计算e、d、g；首个e−d−g>0时输出完整动作表、整数weights、q、位置/主题及全部分数并退出。若走完2000次只打印有限阴性句子。该入口无写文件逻辑，原源包没有相应stdout，因此源码上限2000不能冒成已完成2000次、实际32000项检查或发现次数。原README将其称随机精确BI阴性仅是旧Markdown报告，不补精确运行时序。

这种局部阳性若实际产生，整数客户与精确递归能给相应逐行界的候选真证书；仍应保完整输出并独立核动作覆盖和所有IC。它不会自动反同query总预算、最优排列H4或half。当前本批未运行它，不能以“精确算法”一词创造一份不存在的原报告。
