# 每个history的full-v数据与最大取消

令actual叶Z及实际u固定。h深i、规定动作a时，原规定叶B=finish(h)，reset叶A=finish(Z_<i,a)，v=u_i(B)、D=u_i(A)。代码先核完整SPE的所有当前偏离，并核D≤u_i。对每个x∈a，A/B中除当前之外的coverer分别J_A,J_B；新增coverer各产生正边1/(c_Ac_B)，消失coverer同价计N。所有正边合P，置

\[
 F=N+u_i-D,\qquad v=u_i+P-F,\qquad0\le F\le u_i.
\]

这些都是同一个context的完整利润v核。它不计算仅鲜利润ν、C外客户筛选、fresh图、源时间HIT、角色价格或可信换位门槛。peer列出的那些一般组件有各自解析正文，不能因本审计验证3635条IC便称全已由此程序动态测试。

取消量c=min(P,F)，对正边按(past先、角色递增、单位客户编号递增)顺序删除至总c；future在past之后。每条保留q′≤q，精确有

\[
 P'=P-c=(v-u_i)_+,\qquad \min(v,u_i)+P'=v.
\]

`contexts_with_nonzero_scalar_cancellation`计P>0且F>0的context，即c>0；不计删掉多少客户边、金额或某最优路由次数。选这一个past优先最大取消，不是求解全部controlled-positive流或共同cap的LP。

# 相同注入，三份实际重算的流

每个v_h>0的history直接注入一单位**利润质量**，其它不注入。它不来自比较OPT客户owner INIT、也不等于合法残R源或TOTAL-TRIM。原六正客户游戏每context均正，所以source总量就是619 histories；各例仍独立，不能把619当一个新游戏人数。

每mode独立初始化mass，再按history长度递增处理。β_h=mass_h/v_h，future正边到A_<j，断言目标更深且finish(目标)=A；past边直接到实际(j,x)且核x∈Z_j。保全部有序context，不按count或主题合并。三种current金额分别为

\[
 \mathrm{gross}:\ \beta u_i,\qquad
 \mathrm{net}:\ \beta(u_i-N-(u_i-D))=\beta(D-N),
\]
\[
 \mathrm{clip}:\ \beta\min(v,u_i).
\]

gross/net用原正边q，clip用q′。current金额按current/u_i统一分配到actual角色i所有客户份额1/c_Z(x)，这不是按客户重权当前IC。past保持原客户券标签。访问的正mass要求v,u_i>0；空/零利润无正seed，正边也须有合法正目标，故不取0/0。本固定六例没有另生成零客户/单人边界。

net行的current+全部外送为β[(D−N)+P]=βv，clip行由上式也为βv；future中间流消去，故两份终点总量都等同一源量。gross行则多βF，可能大于源量，不应称gross总量也守恒。

相同正边/相同分母使gross和net的β相同；clip删边后按严格future归纳β_clip≤β_gross。current clip系数≤β_clip，past金额β_clip q′≤β_gross q，因此全部actual货币坐标out_clip≤out_gross。这里out是实际客户券上的**金额**，不是已经对份额归一的cap1负载。

然而取消使本地current增加，重新解图后不保证out_clip≤out_net。程序专门统计strict above old net的坐标，六例共124，见[完整计算记录](../计算/六旧策略的剪枝报告与组合匹配例的逐点核验--计算.md)。它是旧净负载单调性的范围边界，不是half、实际钱包cap或所有剪枝选择不可行的反例。
