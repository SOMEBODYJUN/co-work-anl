# 程序实际新增什么

主源 `cd5e6005172bdbc1524f` 的[4371字节原程序](../../tools/evidence/cross-source-graph-program/original/cross_source_graph.py)已由冻结源全文读取并原字节保全，SHA-256为 `295b4f11935a8ca241cef50541b30078000f8e67bea4f2301a2032914e3cc249`。它调用[拆分基础图](对角回复预算拆分的基础图程序--程序.md)取得3945行、1905列，再添加旧显式回复在不同实际源处必须满足的价格与容量约束。列、目标、归一化保持原接口，新增行只使用K和hist列，全部joint-reply及overlap列系数为零。

这不是重新定义旧B/C主题，也不是发现旧702行错误：同一个合法旧回复在其它真实源处同样可被查询，早期图没有把这些身份之间的全部条件写入。程序的行公式适用于其数学条件下的所有客户型；主入口却只使用继承的16个旧直方图支持。两种范围须分别保留。

# 完整历史、标签和客户坐标

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：有限单位客户，有限非空共同主题目录，六名单位提供者依全部有序历史行动，客户在终局覆盖者间均分。固定任一完整历史纯SPE \(\sigma\)，实际行动 \(A_1,\ldots,A_6\)，六个合法比较标签 \(T_1,\ldots,T_6\)。允许空主题、重复行动、同覆盖标签、零客户及全部离轨平局。令 \(h=(A_1,A_2,A_3)\)，强制第四位为 \(T_j\) 后的真第五、六行动为 \(B_j,C_j\)，全部来自这同一策略、同一目录。

对客户x，记实际会员位 \(a_0,\ldots,a_5\)，\(s=\sum a_i\)，\(p_i=\sum_{k<i}a_k\)，\(\ell=\sum_{k<5}a_k\)。比较会员词为 \(w_j=(t_j,b_j,c_j)\)，八桶hist按三位词字典序计六个索引，\(d=\sum_jt_j\)。\(n_B=\sum_jb_j,n_C=\sum_jc_j\)。份额 \(a_i/s\) 在分子0时按0定义；客户覆盖指标是 \(1[s>0]\)，故总实际福利 \(W=\sum_i u_i\)。共同容量 \(K=\max_{F\in\mathcal T}|F|\) 只是一份公共预算，不可各行免费重置。

把词展开为六项只用于计算对索引对称的和，不限制 \(\sigma\) 为计数策略，也不要求不同源的后继相同。尤其这里在实际第i位强制旧 \(B_j/C_j\) 后的新隐藏尾，不自动等于最初定义该旧标签的那条尾。

# 12条安全报价与2条容量

实际位置i从0计，强制合法Q后，Q内每个客户的终局分母不超过 \(p_i+6-i\)。源节点IC因此给
\[
u_{i+1}\ge\sum_{x\in Q}\frac1{p_i(x)+6-i}.
\]
分别对六个 \(B_j\) 或六个 \(C_j\) 求和，代码hist系数为
\[
6a_i/s-\frac{n_Q}{p_i+6-i},\qquad i=0,\ldots,5,
\]
共12行。i=5是实际末位的精确共同报价，没有隐藏后继。另两行 \(6K-\sum_j|B_j|\ge0\) 及C族同式，K列系数6、hist系数分别 \(-n_B,-n_C\)。基本14行只需两族总数；后面的投影还需要同索引三位词的联合信息。

# 960条有限参数隐藏回复投影

实际源i取0到3，强制 \(F=B_j\) 或 \(C_j\)，末位查询Q取同索引的 \(T_j,B_j,C_j\)。剩余后继人数 \(r=5-i\)。对客户令强制会员t、查询会员q、真实隐藏尾会员 \(f_1,\ldots,f_r\)，末位g=f_r，\(z=p_i+t+\sum f\)。一般局部系数为
\[
H(f)=\frac{t}{z}+\sum_{v=1}^{r}\left(\beta_v+\frac{\alpha_v}{\ell+1}\right)f_v
-\mu\frac{g}{z}+\mu\frac{q}{p_i+t+\sum_{v<r}f_v+1},
\quad\psi=\min_{f\in\{0,1\}^r}H(f).
\]
其中 \(\alpha,\beta,\mu\) 非负有理。源IC、实际末位对每个真实后继的共同报价、共同容量、分支末位对Q的IC及逐客户 \(H-\psi\ge0\) 相加，得到
\[
u_{i+1}+(\sum\alpha_v)u_6+(\sum\beta_v)K\ge\sum_x\psi(x).
\]
强制F仅需合法，未把强制者当作该分支最佳回复。Q的末位查询发生在该真实隐藏尾的末节点；对不同j求和仍共享同一actual利润和价格，不能把不同分支利润算进实际福利。

本程序只选 \(\beta=0\)，\(\alpha\)全项相等或仅末项非零，数值 \(a\in\{0,1/8,1/4,1/2,1\}\)，\(\mu\in\{0,1/2,1,2\}\)。对六个j求和后的hist系数恰为
\[
6a_i/s+6(\sum\alpha_v)a_5/s
-\sum_{j=1}^{6}\psi(p_i,\ell,w_j[tcol],w_j[qcol],\alpha,0,\mu).
\]
循环计数为 \(4\cdot2\cdot3\cdot2\cdot5\cdot4=960\)。相同索引上的t和q不可拆成独立边缘平均。

已全文读取并保全的[2908B价格helper](../../tools/evidence/cross-source-graph-program/related/priced_hidden_reply.py)拒绝浮点价格，校验非负整数背景、二元会员和非负有理乘子。它令 \(c_v=\beta_v+\alpha_v/(\ell+1)\)，把前r−1项成本排序，以C_b表示b项最小成本之和，再取
\[
\min_{0\le b<r,\ g\in\{0,1\}}
\left[\frac{t}{p_i+t+b+g}-\mu\frac{g}{p_i+t+b+g}
+C_b+c_rg+\mu\frac{q}{p_i+t+b+1}\right].
\]
非线性项仅依赖人数b和末位g，所以是精确的2r候选压缩。若加入身份相关交叉项，这个排序理由不能直接继承。完整非负分解及更一般参数见[共同末位投影引理](../引理/共同末位报价与隐藏回复投影--引理.md)。

# 8条最优单换的条件与缩放

只有 `--optimum` 才启用这一族，额外要求 \(T_1,\ldots,T_6\) 真正达到 \(\operatorname{OPT}_6\)。令 \(O=\bigcup T_j\)，P为恰属一个T_j的客户。对任意合法F，将第j槽T_j替换为F，最优性给 \(|F\setminus O|\le|P_j\setminus F|\)。六式相加为
\[
|P|-|F\cap P|-6|F\setminus O|\ge0.
\]
代码对六个actual主题各取**该式的6倍**；B族、C族各取六个F的**和**，即族平均的6倍。其统一hist系数
\[
6\,1[d=1]-r_F\,1[d=1]-6r_F\,1[d=0],
\quad r_F=6a_i\ (F=A_{i+1}),\quad r_B=n_B,\ r_C=n_C.
\]
d≥2时系数0。此处P是比较元组的单覆盖集，非共同目录全局私有块；任意合法而非最优比较元组不保证该不等式。旧引理的“族平均”表述须配合本程序的共同6倍缩放理解，非差一族系数。

# 原主入口、依赖和证据级别

`build()` 调用 `split_basic_graph.build()`，继承其旧hist支持、列顺序及3945行；又从 `new_reply_budget` 读三位词次序与零分子份额约定。`full_new_reply_closure.exact_point` 只在优化成功后用于恢复。三份依赖已全文读取；其下层原702/3889等行由各自对象承担，本页不把读入依赖或执行继承代码冒充逐条证明。

`--verify` 重建当前模式矩阵，读同目录相应 `*_exact.json`，把columns里的weight按顺序转Fraction，断言长度匹配、非负、归一化1、每行余量非负，以及W等于保存值且小于1/2。它没有逐项比较JSON列描述符、原报告行数或冻结SHA，故正确坐标顺序与版本仍是输入合同；必须开启assert。取得的相配原文件为 `cross_source_priced_optimum_exact.json`，不能据此声称其它三个模式的exact文件已取得。

默认优化把矩阵转float，按每行最大绝对系数缩放，HiGHS最小化W，约束非负、O=1，原始/对偶可行容差均1e−9。成功且浮点W<1/2时，恢复器取浮点值>1e−9的支持及相对近紧行，再用精确消元求候选；之后对全部原有理行、非负、归一化和W<1/2断言，才写exact。它不是把float直接称证书，也不保证一定恢复成功；只有精确可行性，没有匹配对偶证明精确最优。默认写status及可能的exact；未写出新exact时，旧磁盘文件不变成新产物。

本轮没有再次执行原cross CLI、优化或独立完整4927图。实读同批[唯一联合图原入口记录](../../tools/evidence/combined-branch-master-program/rerun/execution.json)及[stdout](../../tools/evidence/combined-branch-master-program/rerun/stdout.txt)：未修改的 `combined_branch_master.py --verify` 在隔离原目录执行，assert开启、退出0、stderr为空，确经原cross.build并带 `--priced --optimum`，总5108行、1905列、最小余量0。**它验证的是另一份联合图点**，不是下面536a旧cross点的全4927行重验。其后续旗标域及完整依赖重放由[联合程序对象](索引主题与实际第四步B分支的联合必要图程序--程序.md)说明。

# 与既有成果的区别和接续用途

[旧共同报价引理](../引理/旧回复跨实际源的共同报价与最优单换--引理.md)已解释14行、有限960参数和8单换，但明示当批未读代码或JSON。这里补上原程序真实接口、OPT缩放、原字节、完整新增行的当前精确系数核及两个固定点余量；没有改写旧审查当时的范围。[阶段账本](../资源/显式回复主图的阶段点与未闭报价账本--资源.md)区分4927、4987、9311、5108、10344和后续5277点，本程序4927仍缺全ZZ与新新PAIR，不能因为另一个图更大就合并成一次点认证。

后继可保本共享标签、有限行族、同一K预算及精确坐标合同，加入新的合法查询或扩支持，再在新点共同验证。固定16支持的低点只说明所列必要条件容许低值；精确图点、共同会员实现、完整目录游戏、全部有序历史SPE各有独立义务。即使固定支持优化不可行，也不能推出全客户域half。程序没有给出一般六人half证明、SPE反例或精确最优值。

本页已按实际阅读明确继承、实现、输入和有限检查关系，第三阶段再据这些条件建立解释性超边，不复制旧图。冻结定位、共享依赖和重放命令见[证据说明](../../tools/evidence/cross-source-graph-program/README.md)及[来源清单](../../tools/evidence/cross-source-graph-program/source-manifest.json)。
