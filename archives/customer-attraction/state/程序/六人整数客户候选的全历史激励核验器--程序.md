# 原件、用途与数学模型

主源 `1b7f005abf2fb92f064a` 是[4012B标准库程序](../../tools/evidence/six-provider-policy-candidate-verifier/original/verify_policy_candidate.py)，SHA-256 `80657032a9aef3f6000634fee03f87b4666e98ef13cba84becc77f88bd2f56cc`，两冻结提交同字节。完整源含compositions及main，依赖argparse、json、math、Fraction、Path、combinations，不导入相邻搜索器或仓库求解器。

它核验的是一份**给定完整策略与重新构造出的整数客户实例**，不搜索全部策略或提供全称上界。模型为六位单位提供者依次观察全部有序历史，从同一有限非空主题目录选题，终局客户价值在覆盖者间均分。重复行动、空主题、零客户、零兴趣客户和任意离轨平局均保留。源以可区分主题标签0,…,k−1编码；其最终strict标志另要求正客户上的覆盖两两不同。

同目录[历史依赖策略锥搜索器](历史依赖策略锥的搜索程序--程序.md)只产生浮点候选，可能用近似平局、裁剪微小质量或只优化固定比较集合J。这个4012B入口重新算真实全历史IC和实际OPT6；搜索字段ratio_comparison、terminal及声称的LP状态均不参与认证。历史README只说扫描再现11/6且没有严格>2候选，被删除候选没有在本任务补造。

# 输入、逐项有理化和有限单位化

CLI为 `verify_policy_candidate.py candidate [--denominator D] [--output path]`。D默认1000000，应为正整数；源只由Fraction调用限制其合法性。candidate JSON使用：

| 输入字段 | 实际合同 |
| --- | --- |
| k、m | k≥1个共同标签，m必须为6；m==6通过assert强制，不可关assert或外推其它人数 |
| weights | 以兴趣mask字符串为键、数值或有理字符串为值；预期0≤mask<2^k |
| policy | 没有ordered_policy时使用；键为`q0,q1,...`，对全部总数0至5的非负计数状态给动作0,…,k−1 |
| ordered_policy | 存在时优先使用；层键`0`至`5`，第t层长度k^t，每个有序历史单独给动作；无需也不读取policy |

源码对每个输入v作 \(\widehat v=\operatorname{Fraction}(v).\operatorname{limit\_denominator}(D)\)。JSON float先变其精确二进制有理数再限分母，有理字符串则先按其精确值解析。然后取这些分母的公倍数L，把**正**的 \(\widehat v\) 变整数，再以全部正整数的gcd约去公因子。输出integer_weights才是本次被核的单位客户重数。

非正近似值被丢弃，源不报告裁剪前后的误差，也不保证旧W归一化、区别质量或IC保持。因此通过时认证的是这个正整数实例，不能把结论搬回未经检查的原浮点权。空weights时lcm空集为1、gcd空集为0，但空字典没有执行除0项；程序可以处理本轮已测的零客户实例。

mask0的正重数不会被删：它表示对任何主题都无兴趣的不同单位客户，计入unit_customers，收益和覆盖贡献为0。当前输入合同没有显式校验k正整数、mask域、重复整数键别名、所有动作范围或多余键；缺失策略键、长度不符等可能抛异常。不能把成功解析当通用schema验证。本次所有新控制输入均满足上述合法域。

# 60倍整数收益为何精确

对六次终局计数q及兴趣型B，负载 \(d_B(q)=\sum_{j\in B}q_j\in\{0,\ldots,6\}\)。每个重数w_B代表w_B个不同单位客户。已选题j的某位玩家获得
\[
u_j(q)=\sum_{B\ni j}\frac{w_B}{d_B(q)},\qquad
60u_j(q)=\sum_{B\ni j}w_B\frac{60}{d_B(q)}.
\]
该玩家已经选了j，分母必正；60被1,…,6的每个负载整除。所以源码的 `60//load` 在这些实际查询处是精确整数除法，没有浮点容差。无覆盖的客户直接跳过。

程序先枚举全部 \(\binom{k+5}{k-1}\) 个六次计数，保存每题收益数组和总覆盖W(q)。数组中一个**未被该终局选择**的题j的值，不是另加第七位玩家的收益；真正IC总是重走当前偏离后的终局，且该当前玩家的题已在该终局出现。不能拿未占用坐标当独立偏离报价。

# 两种策略输入都要覆盖离轨历史

计数policy从第5层往根计算 \(T(q)=T(q+e_{a(q)})\)，并对每个替代b计算真实孩子终局 \(T(q+e_b)\)。相应比较为
\[
60u_{a(q)}(T(q))-60u_b(T(q+e_b))\ge0.\tag{IC}
\]
这不是只检查根路径。由于固定策略只依计数，两个同计数历史的后继动作、终局计数及IC由归纳相同，所以逐计数检查等于对其所提升的完整有序策略逐历史检查。它不证明任意SPE都可净化为计数策略，见[固定完整策略锥](../定理/固定完整策略的客户重数锥--定理.md)。

ordered_policy按历史字典序展开：t层第idx个节点的k个孩子是下一层连续的k·idx,…,k·idx+k−1。同计数向量在列表中重复出现，**位置仍不同**，孩子的后继终局也独立保留。因此它支持同计数不同次序取不同动作，而非在内部把完整策略压回计数策略。每层assert动作数组长度正确；所有历史的自身动作被跳过，任意平局用slack=0接受。

只要合法策略及整数重数下所有(IC)非负，这份给定完整策略就是纯SPE：每位玩家只在自己的阶段行动一次，任一子博弈中的单方改变在其到达节点就是换一个动作，其后其它玩家仍沿同一策略。反向，完整SPE当然满足所有这些真实比较。这正是[完整SPE重数锥定理](../定理/固定完整策略的客户重数锥--定理.md)的整数实例，不靠扫描有限样本来证明。

合法动作时，计数模式比较数为
\[
(k-1)\sum_{t=0}^{5}\binom{t+k-1}{k-1}=(k-1)\binom{k+5}{5},
\]
有序模式为 \((k-1)\sum_{t=0}^{5}k^t=k^6-1\)。k=1时两者均0，平局/单主题在数学上不被删；默认脚本未对所有边界作额外输入诊断。

# 实际最优覆盖、不同覆盖标志与15个输出字段

代码枚举1至min(6,k)个**不同标签**的所有组合求覆盖最大值。任意六次可重复选题的并集只有至多六个不同标签；较短组合可重复补足六次，故这恰是原模型的OPT6，不是搜索器的某个固定J。空题或重复覆盖不改变这个论证，零客户时OPT6为0。

distinct_topic_sets逐对检查是否存在正重数客户区分两题；它没有实际删题、取商或改完整策略。数学模型中的重复行动一直合法。对同覆盖标签的额外处理须用[有序历史商程序](重复覆盖主题的有序历史商程序--程序.md)及相应定理，本核验器不执行它。

| 原输出字段 | 含义 |
| --- | --- |
| m、topics | 六位及k标签 |
| distinct_topic_sets | 正客户上是否每两题覆盖不同 |
| unit_customers、support_types | 构造后总单位客户数、正整数兴趣型数；前者含mask0 |
| checked_IC | 按上述所选策略表示实际检查的非自身比较数 |
| negative_IC_count、first_negative_IC | 全部负比较数，及遍历原序前5项；slack均已乘60 |
| actual_counts | 从空历史沿给定策略完成的真实六次计数 |
| welfare、OPT6、optimal_topics | 实际根覆盖、最大六主题覆盖、一个达到组合；全零时最后为null |
| ratio | **OPT6/W**的精确分数字符串；W=0时为null，不是W/OPT6 |
| strict_original_counterexample | distinct为真、无负IC且OPT6>2W的合取；额外要求覆盖不同，是该脚本的认证门槛 |
| integer_weights | 本次实际核验的正整数客户重数 |

原程序即使发现负IC，也正常返回、打印报告；**exit0不是SPE通过**。strict标志对合法完整输入为真时足以给原模型反例，但仅该标志为假不区分没有坏比、IC失败或覆盖重复。普通SPE验证应直接读negative_IC_count；它不要求严格区别覆盖。程序没有原候选SHA、全IC余量或完整策略输出，所以复用证书仍应保输入JSON及版本。

main只在直接执行时运行。默认只读输入并打印JSON；--output另写同报告，没有stdout最后的换行，可覆盖给定路径。本次控制运行核了这个输出分支。assert要开启，尤其m==6和有序层长度；否则60整除及完整层合同不再受原守卫约束。

# 六个新受控实例与真正失效机制

本轮没有可供原样复放的历史阳性候选。保存的是[六份明确的新控制输入及原输出](../../tools/evidence/six-provider-policy-candidate-verifier/controlled-runs/execution.json)，各运行未改原CLI一次，Python隔离模式-I/-B、assert开启，退出0且stderr空。独立oracle展开最多4个真实单位客户，用Fraction按完整行动序列的终局均分算每个历史，而不调用原程序或60//load表；每例都核63个有序历史比较，计数输入另核同计数类的比较确实相同。

| 控制输入 | 客户数 | 原checked IC | 负IC | 实际计数 | W；OPT6 |
| --- | ---: | ---: | ---: | --- | --- |
| 零客户，计数恒选0 |0|21|0|(6,0)|0；0|
| 3个零兴趣客户及1个仅喜欢题0的客户，有序恒选0；题1为空 |4|63|0|(6,0)|1；1|
| 两类质量1/3、2/3，给定其1:2整数实例的完整计数SPE，默认D |3|21|0|(2,4)|3；3|
| 同一输入和同一策略，D改为2 |2|21|4|(2,4)|2；2|
| 两题分别有1、3名专属客户，却规定所有历史恒选0 |4|21|20|(6,0)|1；4|
| 两标签覆盖同一客户，给真正依次序的有序策略 |1|63|0|(5,1)|1；1|

最后一例在历史01与10（计数同为(1,1)）规定不同动作，完整保离轨身份。所有客户都被六位均分，所以任意策略都理性；其distinct标志为假，不表示SPE失败。

第三与第四例说明逐项限分母可以改变激励：D=2把1/3、2/3都近似成1/2，清分母/gcd后客户从(1,2)变(1,1)，旧策略出现4处严格负IC。它不是原1:2实例的整数认证失败，而是**实例已改变**。第五例虽有OPT6/W=4，根偏离收益3大于遵从的1/6，故非SPE，负根slack为60(1/6−3)=−170；程序正确将strict标志置假，但退出码仍0。

原六次合计210个表示层比较；独立oracle合计378个全历史比较，每份输出全部15字段（达到组合按其实际覆盖检查）一致。六个strict标志均假；这些输入验证代码合同和错误机制，不是一个六人half反例。原源与输入前后字节未变，临时布局删除；--output字节与stdout仅末换行不同。复现脚本对新输出目录独占创建，避免覆盖已有事件。

# 与搜索器、理论及接续的关系

数值锥搜索固定一份形式策略后寻找质量；这里按恢复后的整数质量检查该策略的全部真实IC。搜索器固定J、浮点近似平局及裁剪读数不替代本核验，反过来本核验一次成功也只认证一个具体整数点及策略，不提供固定锥对偶，更不覆盖全部策略和目录。

如果得到新阳性候选，保完整策略输入、分母参数、实际整数重数和全部运行身份，核负IC为0及实际OPT6/W，再准确处理覆盖重复的标签合同。改变分母或支撑必须重核。没有阳性或若干小控制通过不构成普遍half证明。关系的发现→整数恢复→完整历史IC→实际覆盖，及与商程序的身份区别已说明，三级超图留后续阶段。
