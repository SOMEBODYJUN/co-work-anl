# 二关联目录的精确终局探针与内部子题边界

本页处理 `rank_two_probe.py`、其三份报告、`rank_two_internal_probe.py` 及其一份报告，共六主源。五个本批程序及十一 JSON 总计 26868 字节均全文实读；这里只讨论这六源的数学与执行合同，其余策略锥和五环松弛见[另一程序页](二关联完整策略锥与后继保底松弛的有限合同--程序.md)。所有原字节、完整双冻结定位、SHA 和导出记录在[证据入口](../../tools/evidence/ra0-incidence-geometry-primary/README.md)。本批没有执行两个随机 main。

## 模型、门槛与程序真正遍历的对象

共同目录是有限非空的带标签行动集 `[k]`；同覆盖标签仍是不同动作。客户兴趣 `S` 的正整数重数表示不同单位客户。对完整有序叶 `z`，选题 `a=z_i` 的玩家收益和社会福利分别为

\[
 u_i(z)=\sum_{S\ni a}\frac{w_S}{\sum_{j=1}^m\mathbf1_{z_j\in S}},
 \qquad W(z)=\sum_{S:S\cap\{z_1,\ldots,z_m\}\ne\varnothing}w_S.
\]

完整纯策略在每个长度 `0,…,m−1` 的有序历史指定一个标签。完整纯 SPE 要在全部这些历史与任意强制动作后，沿同一策略的真实后继比较当前玩家收益；平局都合法，不把任一历史删除。程序调用的规范 `ExactSPESolver` 按[完整终局全集算法](../算法/完整历史纯SPE终局全集--算法.md)计算每个前缀计数的全部可实现终局计数。缓存的是**可实现集合**；它不要求不同有序历史但相同计数采用同一行动。

记根可实现终局计数集为 `R_I(0)`，定义

\[
 W_{\min}(I)=\min_{q\in R_I(0)}W_I(q),\quad
 T_1(I)=\min_{\sigma\;\text{complete pure SPE}}u_1(z_\sigma),
\]

以及拥有 `m−1` 个整数竞争槽、允许重复主题的静态末位门槛

\[
 \theta_m(I)=\min_{b\in\mathbb Z_{\ge0}^k:\sum b=m-1}
       \max_{a\in[k]}\sum_{S\ni a}
       \frac{w_S}{1+\sum_{t\in S}b_t}.
 \tag{1}
\]

规范根 `threshold((0,)*k)` 恰为 `T_1`，并非 `(1)` 的静态 min–max。基础探针分别问

\[
 W_{\min}\ge m\theta_m,\qquad T_1\ge\theta_m,
 \qquad 2W_{\min}\ge\operatorname{OPT}_m. \tag{2}
\]

它没有逐一检查所有玩家的收益。用根最低值检查第二式，等价于覆盖该**固定输入**所有完整 SPE 的首位收益；用所有根终局求最小福利，等价于覆盖该固定输入所有完整 SPE 的福利。它仍然只检查实际生成的有限输入，不能从这一有限全策略性质推出任意输入的全称命题。

## 基础二关联探针的完整生成顺序

`rank_two_probe.py` 固定默认 `random.Random(381097)`，默认 `--cases 1000`；每次先抽 `k=randrange(3,7)`、`m=randrange(3,6)`，然后先单标签、后双标签，按 `combinations(range(k),size)` 顺序，对每个兴趣类型从

`[0,0,0,1,2,3,5,8,13,21]`

等概率抽一个质量，零质量类型不加入实例。它确实生成**全部目录标签关联度至多二**的客户，而非仅基础极大主题关联至多二。某个主题可为空覆盖，两个标签可同覆盖；客户列表也可能为空。没有生成空兴趣客户，但零客户仍是合法程序输入。程序不先将覆盖等价标签商掉。

每输入先求全部根终局及最小福利，再用精确 `Fraction` 穷尽所有 `m−1` 槽弱组合计算 `(1)`，调用根 `threshold`，再求全目录 `OPT_m`。`worst` 初始为 1，只有 `OPT/W_min` 严格大于此前最大值才保存整份输入；`W_min=0` 时软件把比值设为 1。合法非负游戏中 `W_min=0` 不会形成一个遗漏的严格正最优/零福利反例：根可选最大裸主题，任意后续至多将其分享 `m` 份，故非空客户时根收益正；全客户为零则 `OPT=0`。但软件字段本身仍应按其分支解释，不能把初始 1 当实际取得的正分母等号样本。

三类失败分别保存：聚合失败保存输入、静态 `theta`、最小福利、OPT 及所有达到最小福利的终局计数；根失败保存输入、`theta`、根最低值和福利/OPT；half 失败向数组追加当时的 `worst_ratio` 对象。最后一点有一个实际追溯限制：当一个新 half 失败未刷新此前最坏比时，追加的是此前最坏输入，不必是当前 `case`；本三报告的 half 数组都为空，没有发生可核的此类阳性。

每轮 `cases` 增一，程序没有因任何失败早停。`--output` 可省，省略则打印完整 JSON；提供路径时用 `open('x')`，输出已存在会报错，不创建缺失的父目录，不覆盖原件。

| 冻结报告 | requested / cases | 保存最坏输入 | 最坏 `OPT/W_min` | 明确保存的失败数组 |
|---|---:|---:|---:|---|
| `rank_two_probe_300.json` | 300 / 300 | case 143，五题三人，71 客户 | 69/51 = 23/17 | aggregate、half 皆空 |
| `rank_two_probe_20000.json` | 20000 / 20000 | case 779，六题三人，88 客户 | 81/50 | aggregate、half 皆空 |
| `rank_two_probe_root_5000.json` | 5000 / 5000 | 与上一份的 `worst_ratio` 整对象相同 | 81/50 | aggregate、root、half 皆空 |

三者均保存相同 seed、质量池、人数范围 `[3,5]`、题数范围 `[3,6]`、`rank_bound:2`。它们没有保存逐输入列表、实际抽样轨迹、根全集明细、完整策略或历史 stdout。前两报告**没有 `root_theta_failures` 字段**，而当前冻结源码无条件初始化并输出该字段，故不能把这两个 JSON 说成当前源码字节可直接重产的完整报告，更不能把字段不存在当根门槛已核阴性。这里只保它们明确记录的旧字段与有限声明。第三报告包含该字段，可以保其 5000 例根阴性记录，但也没有原命令、版本、stdout 或过程元数据。

相同 seed 和 case 779 输入吻合，与 5000 例作为 20000 例前缀的关系相容；这不认证历史生产进程或无字段旧源码。300、5000、20000 不是三个已经认证互不重叠的样本批，不相加成 25300 个不同游戏。20,000 是旧最大计划记录，不是本次新运行量。两份不同的保存输入已在[固定计算页](../计算/二关联保存点的两份常值三人策略--计算.md)补全精确终局与策略，这不把新证据倒填成旧随机过程的 stdout。

## 两个内部子题：基础二关联不等于全部标签二关联

`rank_two_internal_probe.py` 默认 seed `413017`、cases `3000`。每输入抽基础标签数 `s=3,…,5`、人数 `n=3,4`。每基础单标签质量从 `[1,2,3,5,8]` 抽，基础双标签质量从 `[0,0,1,2,3,5,8]` 抽。每个单位客户实际逐个展开；两个内部标签分别先抽一个 `container` 基础标签，对属于该基础主题的每个单位客户独立以概率 1/2 加入相应内部标签。容器可以相同，内部标签可为空、可同覆盖，也可能等于其容器。

基础私有块为正保证**基础主题之间**互异、互不包含。它不保证全目录的极大标签恰为 `s` 个：内部标签若恰等于容器，带标签极大集合会有覆盖别名；按严格不同覆盖集合去重后极大覆盖集仍由基础主题代表。每客户在基础主题中至多出现两次，在含两个内部动作的全目录中可出现最多四次。因此本报告不是全标签关联秩二样本。目录实际有 `s+2=5,…,7` 个标签，规范 SPE solver 完整保留它们。

源码计算 `theta` 时却只枚举基础主题上的 `n−1` 槽 `combinations_with_replacement`，并只允许查询基础主题。这个静态缩减是正确的。对固定任何合法背景，内部题 `T⊆A` 的加入收益不超过容器 `A` 的加入收益，所以全目录最大查询值与基础最大值相等；把任一内部竞争槽换成其基础容器，只增加每客户的竞争负载，从而使所有查询收益不增。于是限制竞争槽为基础题得到的最小值不大于任意全目录背景的值；基础背景又是全目录背景子域，反向不等式成立，故两者最小值相等。允许重复槽、空题、同覆盖和同容器两个子题均不破坏这个论证。

这只是静态式 `(1)` 的支配缩减。删除内部动作会删掉有序历史和依赖这些历史的可信续局选择，不能据此将完整 SPE 动态目录缩成基础题。这与[前一工作区静态缩减](二关联根门槛探针与人工停止记录的定义域--程序.md)是同一个逐客户原理，输入生成法不同：前一程序允许随机已发生背景并用固定基础题数表，本程序只查空根、随机抽基础题数，必须分别保源。

每输入求全目录根全集、根最低值及最低福利，只检查前两项 `(2)`，没有计算 OPT，也没有检查 half。失败 info 保存 case、完整实例、两个容器、theta、root_threshold、minimum_welfare；未保存完整策略。两类失败中任一出现即在该轮增加 `cases` 后停；无失败才跑完配额。用 `open('x')` 写必需输出路径。

231 字节报告实际全部内容是 cases=requested_cases=3000、seed413017、基础范围 `[3,5]`、人数 `[3,4]`、两个内部子题及两个空失败数组。它没有任何实际输入或策略。由 frozen main 的结束规则看，这是与完成 3000 例相容的有限阴性；不能补造 3000 份全标签 rank-two 游戏、最坏比、half 阴性或每例节点数。

## 现行纠错、依赖和可继续工作的边界

现有[七环完整反例](../反例/七环二关联目录的逐人末位值与静态安全值反例--反例.md)是七个全标签二关联主题、四位玩家的真实完整 SPE，`u1=1<theta4=3/2`，也低于该例的静态安全值；它已经否定一般二关联首位门槛。基础随机探针最多六个标签，内部探针即使全目录有七标签，其基础最多五个，不能把两种“七标签”混同，更不能以这些阴性继续宣布普遍根门槛未被反驳。

七环没有由这两个程序给出二关联聚合 `W≥m theta_m` 或 half 的反例。另一[五环保底障碍](../障碍/后继末位保底不足以保护当前人的五环障碍--障碍.md)的坏续局不是 SPE，亦不能混用。局部[最大计数差与逐边交换](../引理/二关联客户的最大计数差与逐边交换--引理.md)证明没有自动给出跨历史首位保底。不同后续结论逐一链接，保留原有限数据的实际用途。

规范依赖四文件共 25475 字节完整读过并核 SHA，见[依赖清单](../../tools/evidence/ra0-incidence-geometry-primary/reused-dependencies.json)。原程序根据 `__file__.parents[5]` 放入 `sys.path`；把散置原件直接当脚本跑并不能保证导入同一包，本页不冒认旧运行版本。两个随机 main、原完整随机扫描和旧七环/五环成功审计本批运行量均为 0；本批仅对两个保存输入的新固定审核有真实执行事件。
