# 真正攻击的量词与数据来源

两源6126/5886B全文及五原报告全读，程序原件保持冻结字节。[报告资源](<../../../../tools/evidence/phase25-material-attachments/20261103-boss6-triage/983794d4f788110476f3.md>)保完整参数/字段边界。原候选一般写PB-strong：任意合法背景b、余n≥2人、每份完整纯SPE，前两位最终利润和至少2v_n(b)，静态对手有n−1槽。**本两程序没有背景参数，实际只搜b=0根的这个强候选**，不搜任意巨大合法背景，也不把n−1偷换成PB-extra的n槽。

模型仍是[单位客户共同目录完整历史博弈](../定义/共同目录完整历史模型--定义.md)。用n≥2表示玩家数、k≥1为共同标签数。客户类型遍历非空兴趣T⊆{0,…,k−1}，LP中w_T是非负实质量，发现后才可能恢复正整数重数代表不同单位客户；不是加权提供者或混合SPE。空兴趣客户对利润/静态值无影响，可省去。标签可空覆盖、可同覆盖，行动可重复；一般模型的任意有序平局不被程序发现子类限制。

无固定外部游戏JSON。count版每trial随机造类型整数权重（以1/2概率取0…10，否则0；全零时补第一类1），用浮点收益产生一个count策略。full版每类型以约0.3概率取1…3，否则0，全零跳过；用规范精确求解器生成一个完整有序策略。原tries是循环预算，不是去重策略数或成功LP数，未输出跳过/不可行/重复次数。

# 同一固定query、固定σ的线性锥

对终局计数c、被选择标签a，逐类型份额系数为

\[
 \phi_{c,a;T}=\begin{cases}1/(\sum_{b\in T}c_b),&a\in T,\\0,&a\notin T.\end{cases}
\]

只在c_a>0使用，正分子时分母正。完整形式策略σ的每节点h、每个合法偏离a（含自身）给真实完成计数z_h与z_(h,a)，

\[
 \Gamma_{h,a;T}=\phi_{z_h,\sigma(h);T}-\phi_{z_{h,a},a;T}.
\]

不冻结改变后的后继。令d_T为实际首两位的φ之和，即使二人同标签也计两份。固定合法query分布p，每个静态背景计数q、Σq=n−1，定义

\[
 s_{q,T}=\frac{\sum_{a\in T}p_a}{1+\sum_{a\in T}q_a}.
\]

p在一次LP内不随客户质量或静态对手实现变化；不同trial可重新抽p。实际浮点LP为

\[
 \min_{w\ge0}d\cdot w\quad
 \text{s.t. }\Gamma w\ge0,\quad s_q\cdot w\ge1\quad\forall q.
\tag{LP}
\]

Γ、s的理论系数均有理，求解器输入转换为NumPy浮点。一个合法恢复点若首对<2sec，sec=min_q s_q·w，则同一个p保证v_n(0)≥sec，足以反该输入首对桥；即使如此也不反half。固定p只给一个静态保证，不证明它安全最优；阴性LP也不覆盖所有p/σ。

LP本身的理想精确对偶可写α,β≥0、Γᵀα+Sᵀβ≤d，目标maxΣ_qβ_q。若某一固定系统给精确α/β和逐类型非负余项，才是该归一化系统的下界证书。源码普通模式不输出这种精确对偶；full诊断只保截断浮点support，不具这份证书身份。

# count版：完整的count策略子类，不是一般模型压缩

`compositions`列所有总数n的k维非负整数终局及总数n−1静态背景。自写`solve(q)`对每个count state递归所有动作，以当前标签在完整后继终局的浮点利润最大、随机数打破平局，固定一个action[q]及所有children[q,a]。终局收益表源自最初随机整数类型质量，但优化后的w会改变收益；重新核Γ才是后来点使同σ可信的依据，不需它继续是生成时“最小首对”或最坏根。

对每个非终端q及每动作建立Γ。把action提升为每有序history h取action[counts(h)]，就有一份完整有序策略；同count的所有历史在这份策略下确给相同真实计数续局，因此这些Γ约束覆盖它的全部有序IC，只是合并重复行。它是合法策略**子类**，不是要求全部SPE都匿名。

例如n4/k6有84个非终端count state、504含自身行，静态背景56、类型63；提升后的完整树259节点1554比较被重复行代表。n5/k6有210 state、1260行、静态126。这里是有限计数式的解析说明，不是当前执行计数。比较full版的1554行不能说count版漏掉离轨历史。

每三trial一次uniform p，其余p由0…12随机整数质量归一，全零则补首标签。现版没有“全程uniform query”的CLI开关。默认players4/topics6/tries100/seed41023只是源码默认值，不是旧JSON实际argv证明。

# full-history版：规范全集、固定路径和最低回复选择器

代码通过`Path(__file__).resolve().parents[6]`把原项目根加入sys.path，导规范`CustomerType/Instance/ExactSPESolver`，再从peer `attack_two_block`导compositions。已全文核四依赖：691B __init__、8640B model、9943B exact、6201B certificate，合25475B，均与冻结inventory SHA一致；只绑定已发布原bytes，不再次复制或执行。包入口只导出接口，规范方法不因被import就自动搜索。

规范全集对count缓存**全部可实现结果**，阈值max_A min_(child outcome) u_A，既保任意有序平局又避免把一个选择器当全集。`ordered_outcomes()`枚举全部可实现有序根路径，不是所有完整策略映射。程序在一次随机整数实例中选首对利润最小的路径，再`certificate(on_path=path,...)`展开全history map。

这里有一项具体限制：canonical certificate固定所选路径；每个真正离轨孩子只从使当时玩家收益**最低**的可信终局中取minimizer，continuation_selector只在这些minimizers里随机；action_selector则在实现所需终局的admissible actions中随机。两回调按各有序history分别调用，同count可有不同平局，确比count单选择器更自由，但**不枚举全部非最小惩罚的完整菜单**。最低回复属性只针对生成时的随机整数实例；随后LP改变客户质量，不要求原孩子继续最低，只要求同一σ全部IC成立，不能给整个策略锥再附一个未写的最低性限制。源码/入口“full history ties”不能提升成穷尽全部SPE。

然后`follow(h)`沿cert.actions真实完成、逐所有已生成history/合法行动建Γ，不调用规范`verify_certificate`。完整性来自已核canonical递归展开每个孩子；本脚本没有独立再验证keys集合。默认n4/k6该生成器有259节点、1554含自身行。每两trial一次uniform query，其余同样随机整数query。默认50/seed441023只是代码默认，原报告未绑定seed。

# 有理后核：尺度不变及真实缺项

两版仅在浮点LP目标<2−10^−7时尝试恢复w，分母上限count为10^7、full为10^8。恢复后逐Γ行恰核非负，重新以Fraction求sec=min_q s_q·w及pair=d·w，仅在pair<2sec时输出候选。count导出非零类型有理权重、count-policy全部动作、根计数/首两标签、p/pair/sec/seed/trial；full导出有理权重、path、完整cert.to_dict()及相同主要数。

**没有显式重核恢复w_T≥0。** 浮点LP的bounds≥0不替代有理后核；若未来真有阳性包，须确认全部恢复质量非负，再清分母成为单位客户整数重数。原码未将恢复w重新构造成严格整数Instance，也未输出清分母后的单位客户证书。本批五报告没有这样的阳性包，不把一个潜在后核缺项说成已出现错误反例。

另一方面，恢复后没有重核每个s_q·w≥1并非单独致命：最后pair<2sec是齐次判别，允许恢复点换归一尺度。只要w≥0，pair≥0使严格判别自动推出sec>0；同一p真正保证sec，便已足分离。不能把冗余的原LP归一检查称为额外必须漏洞，也不能因sec不是精确安全最优值就拒绝合法下界见证。

如果精确IC、非负质量和严格差均成立，乘统一正整数清所有分母，完整纯策略与全部IC、p的下界和pair<2sec同时等比保持；每类型整数重数展开成不同单位客户即可。该齐次论证说明怎样使未来包合法，没有在本批实际恢复/展开任何新实例。

# 状态、诊断与CLI的真实口径

count `best=2.0`，只在新值小于best−10^−8时更新；所以输出2可能是未改善、微小改善被忽略、所有可行目标>2或无成功LP，不是精确最优值，更不是每个trial最低值。full `best=None`后取成功LP浮点min，没有2截断；同样无有理下界或全范围结论。

full `diagnostic=True`在第一个成功LP后立刻返回，先于best更新和有理分离检查。它只保目标、path/query、阈值10^−7过滤后的负marginal support转正，未保完整Γ、原始w、非负变量的lower dual、逐类型余项或精确目标相等。不能从其几行历史标签恢复一般Farkas付款。

两源均有main guard；正常import只加载依赖/定义，不调用run；`--help`先import后在argparse退出，不探索。main接受players/topics/tries/seed/output，full另有diagnostic；未验证n≥2/k≥1，首对算法只在此自然域有合同，不能声称测试了单人/空目录。output用`write_text`可覆盖目标，不独占、不自动建父目录；无output只stdout。两版还可打印进度JSON行，因此stdout不必是一份单独JSON。

原程序未在本任务import、执行、重演规范solver或LP；无新策略/客户/查询扫描。四依赖和既有[规范求解器资源](../计算/完整历史求解器的精确复现--计算.md)的旧测试成功不成为这两攻击入口的本次成功。当前一般任意背景PB已由另一个[解析子SPE反例](../反例/任意合法背景的前两人额外槽安全值--反例.md)否定，不让这些旧根零背景阴性与其数学矛盾，也不因此重新启动失效候选探索。
