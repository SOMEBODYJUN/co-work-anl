# 四源和三种不可混用的预算

四主源为2747B、13078B、3681B、634B，共20140B。两源码、DB全部32行（含完整有理p、D、min_column和exact_gap）及C预算三行全部字段均已读。[原件及读取清单](../../tools/evidence/population-deletion-strict-tail-and-query-diagnostics-primary/README.md)保完整冻结身份。本次没有运行两个原入口、import、LP或新数学checker，旧有限阴性不重新扩样。

模型是有限单位客户共同目录、单位提供者、完整有序历史纯SPE；重复行动、空主题及离轨平局保留。固定完整σ、实际有序叶z及第i位的实际前缀h_i。强制当前a后沿**同一σ**完成全局n槽叶Z_i(a)，不是冻结原实际后继。

| 对象 | 竞争列/费用 | 哪些人随当前偏离改变 |
|---|---|---|
| 本DB探针 | 全Z_i(a)的n槽仍含当前a及过去，再加独立查询T | 后继沿原σ真实改变 |
| 本C预算探针 | Z_i(a)删当前位置i后的n−1槽 | 后继沿原σ真实改变 |
| SSR静态费用 | 原实际叶z删i后插T | 其余行动冻结为原实际叶 |

因此安全最优C预算不等于[SSR的实际终局静态删除](../候选/安全最优查询面的聚合静态无悔预算--候选.md)。一般SSR后来已被31客户唯一最优查询反例否定，不可据此自动判本C预算同真值；旧DB一般OPEN也已由不同银行输入反驳。

# 自由完整端点对角预算的定义级LP

给定实际前缀h，令Z(a)=Z_i(a)，当前真实偏离收益d_a=u_i(Z(a))。定义额外查询的完整列矩阵

\[
K_{T,a}=\sum_{x\in T}\frac1{1+c_x(Z(a))},\quad
D(p)=\sum_Tp_Td_T,\quad
\psi(p)=\min_a\sum_Tp_TK_{T,a}.
\]

全局Z(a)包含过去，所以其负载也包含过去；这等价于固定旧负载后保留当前和全部剩余槽，不可再次删去过去或删当前。代码的`extra=1`恰是加入独立查询的一份。DB问所有p是否ψ(p)≤D(p)。它不同于同分布平均列费用，也不同于n−1槽真安全值直接比较根收益。

源码为每列a建立N_(T,a)=K_(T,a)−d_T，然后求

\[
\max_{p,v}v,\qquad
p\ge0,\ \sum_Tp_T=1,\quad
v\le\sum_Tp_TN_{T,a}\quad(\forall a).
\]

理论目标是max_p[ψ(p)−D(p)]，减的是行T对应的d_T，不是只改矩阵对角元。有限等价及末两层解析成立范围在[完整端点DB引理](../引理/自由完整端点对角预算的有限等价与末两层--引理.md)；本程序只是固定输入上的浮点发现器。

LP后将每个概率以`Fraction(float(x)).limit_denominator(10000000)`恢复，再重新归一。随后从原单位客户按Fraction重算D、所有完整列及min_column−D。逐分量分母限10⁷不限制再归一后的总分母，故原报告中出现很大的有理分母并非另一个有理LP求解器。此计算只核给定恢复p的值，没有精确对偶证明LP最优或一般ψ≤D；源码亦未显式校验恢复后的概率非负，故新正候选仍须完整概率及SPE验收。

# 安全最优p/Q固定切片的真实去相关预算

第二程序固定三个既有完整**形式策略**及其保存的静态安全鞍点p,Q。令B_i(a)为Z_i(a)删去当前槽；定义

\[
C_i(p;w)=\sum_a p_a\sum_Tp_T\sum_{x\in T}\frac1{1+c_x(B_i(a))}.
\]

a与T独立按同一p抽样。过去动作仍在竞争列中，仅删当前位置；代码不把真实后继冻结为原z。目标为Σ_i C_i(p;w)−W(w)，正值才违背这个指定查询的预算。

客户变量是全部2^k−1个非空兴趣类型的w≥0，并附自由v，归一**Σw=1**。它不保原客户入射支持或原重数，只从原example取n/k、从certificate取完整σ与p,Q。非负实质量是探索域；有理质量可清共同分母展开为不同单位客户，全部收益、福利、IC及严格差同比例缩放。重权可使不同标签覆盖相同甚至为空，因此此LP先属于固定带标签目录的软件扩展；若提出原集合目录的正见证，还须检查主题身份或合法合并并重新验证策略，不能将重复覆盖标签自动当不同集合。全部真实IC以Fraction系数重建并按完整向量精确去重，省去恒零行，再转浮点LP。静态约束为

\[
\Gamma w\ge0,\quad
\beta_B(p)w\ge v\ (\forall B),\quad
\alpha_T(Q)w\le v\ (\forall T),
\]

其中β是p面对合法n−1槽背景的收益，α是固定Q面对纯查询的收益。在p,Q确为概率的前提下，两侧相夹使它们在新w下仍为安全鞍点；这比只保σ的客户锥多一组固定鞍点切片条件。

该归一不是另一[实际路径固定鞍点探针](../资源/实际路径安全最优查询的固定鞍点预算探针--资源.md)的W=1。两脚本即使使用同一σ/p/Q也不能据相同数值0合并为同一次运行或同一归一的最优值。

# 正候选分支、缺失认证和正确当前状态

若浮点目标>10⁻⁸，第二程序尝试将w,v逐分量限分母10⁷，并重算所有Γ、静态原始/对偶约束；残差非负时写一个witness文件。它**未**在这个分支另查恢复w≥0、Σw=1或恢复后gap严格为正；`EXACT POSITIVE`打印标签不能替代这些必要检查。当前三个结果均无正点，没有这样的witness文件被本四源交付，也没有本次补造它。

即便未来交付精确正点，也先只否定该指定安全最优p的C预算。要否定“存在某个安全最优查询可付款”，还须排除整个安全最优面或证明唯一性；要否定真正W≥nv_n或half，尚须分别比较nv_n和OPT。三个浮点零值也不能反向证明这些普遍结论。

两源码均有main guard，无项目模型/solver导入，但需要NumPy/SciPy和原examples/certificates文件。第二程序逐输入覆盖中间报告，最后再写全报告；中断可留下部分列表。现冻结列表有三个完整指定结果，不倒填实际原命令、环境、耗时或中断日志。

关系判断：两程序实现不同真实菜单/预算目标；32行和三行是有限历史资源；已有DB银行反例校正一般真值；SSR31客户反例用于区分合同，不能接成同一预算的反证。本对象不生成第三阶段图，不从文件名“optimal”“exact”或没有候选推导一般证明。
