# 程序身份与准确职责

主源 `48e907edcc1b4908d039` 的[4563B原程序](../../tools/evidence/split-basic-graph-program/original/split_basic_graph.py)已用 `clean show` 全文读取，SHA-256为 `649ea591b5c15c076246d72f4b13920caeade77d1b87c59530ac492f3e50b1dc`，两冻结提交同字节。它在旧 `attractive_nested` 的3889行、1905列图上增加56行，返回3945行及原列、目标和归一化向量；没有新增客户或回复变量。

旧变量本来就区分回复族、两个比较索引是否相同及各自会员词，但C族的16条R基础行、12条Z基础行各把全部36个有序索引对合在一起。此程序分别取 \(i\ne j\) 的30项和 \(i=j\) 的6项，各行独立要求非负。它不把会员词相同误作索引相同，也不删除重复主题或任意平局。

源码断言每对新行逐列相加恰回旧行。因此相对于保留的28条合行，新增约束至多提供28个额外线性方向；程序没有计算严格行秩，不能把这条恒等式冒作“新增秩恰28”的独立证明。拆分有效是因为每个被相加的真实偏离/查询/容量本来分别成立，不是因为任意一条非负合行都能无条件拆成两条非负行。

# 这些行来自同一完整策略的哪些历史

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)，先固定任意六人完整历史纯SPE \(\sigma\)、实际路径 \(A_1,\ldots,A_6\) 及六个合法比较主题 \(T_i\)。令 \(h=(A_1,A_2,A_3)\)，强制第四位选 \(T_i\) 后的真实第五、六主题为 \(B_i,C_i\)。本程序拆的C族是
\[
R_{ij}=\sigma_6(h,T_i,C_j),\qquad
Z_{ij}=\sigma_6(A_1,A_2,A_3,A_4,R_{ij}),\quad1\le i,j\le6.
\]
R、Z在其各自末位节点可使用真实最佳回复比较。强制第五位选 \(C_j\) 或 \(R_{ij}\) 的收益则由偏离前的第五位IC约束，不把强制者当作新节点的最优行动。B族 \(R_{0,i,j}=\sigma_6(h,T_i,B_j)\) 原定义只取 \(i\ne j\)，其旧行仍由依赖图保留，本程序没有重新拆它。

逐客户记实际会员位为 \(a_1,\ldots,a_6\)，比较词为 \(w_i=(t_i,b_i,c_i)\)，当前回复位为 \(r,z\)。写
\[
p=\sum_{k\le3}a_k,\quad p_a=\sum_{k\le4}a_k,\quad
\ell=\sum_{k\le5}a_k,\quad L=\sum_{k\le6}a_k,
\]
\[
d_R=p+t_i+c_j+1,\quad D=(p_a+1)(p_a+2),\quad
u_5=a_5/L,\quad u_6=a_6/L.
\]
含零分母的份额只在分子为零时出现，按原 `share` 约定取0。令
\[
\beta_i=\frac{b_i}{p+t_i+b_i+c_i},\quad
\gamma_i=\frac{c_i}{p+t_i+b_i+c_i},\quad
v_Z=\frac{z}{p_a+r+z},\quad H=u_5+u_6+\frac{a_5}{D}.
\]
下表给每个客户对一条索引边的系数，实际约束必须对全部客户求和；这些局部系数本身可以为负。每类再分别对30或6条边求和。

| R行名及数目 | 客户系数 | 全局非负原因 |
| --- | --- | --- |
| source，1条 | \(\beta_i-c_j/(p+t_i+c_j+r)\) | 历史 \((h,T_i)\) 的第五位从B_i改C_j，沿同一策略接R_ij |
| terminal_*，12条 | \((r-q)/d_R\) | R_ij在历史 \((h,T_i,C_j)\) 查询合法主题；q依次为b_i、c_i、t_i、d/6、六个a_k、n_B/6、n_C/6 |
| reverse_terminal，1条 | \(\gamma_i-r/(p+t_i+b_i+1)\) | 原C_i在历史 \((h,T_i,B_i)\) 查询R_ij |
| price，1条 | \(u_6-r/(\ell+1)\) | 实际末位查询合法R_ij |
| capacity，1条 | \(-r\)，另加每边K | \(|R_{ij}|\le K\)，K为共同目录最大主题大小 |

这里 \(d=\sum_k t_k\)、\(n_B=\sum_k b_k\)、\(n_C=\sum_k c_k\)。三个平均查询使用相同分母，对六个合法主题的末位IC平均后得到，不把分数会员当新主题。

| Z行名及数目 | 客户系数 | 全局非负原因 |
| --- | --- | --- |
| source，1条 | \(u_5-r/(p_a+r+z)\) | 实际第五位改R_ij后沿同一策略接Z_ij |
| pair，1条 | \(H-(r+z)/(p_a+1)+rz/D\) | 实际末两人处对合法主题R_ij、Z_ij使用强PAIR |
| price，1条 | \(u_6-z/(\ell+1)\) | 实际末位查询Z_ij |
| capacity，1条 | \(-z\)，另加每边K | \(|Z_{ij}|\le K\) |
| actual0至actual5，6条 | \(v_Z-a_k/(p_a+r+1)\) | Z_ij在历史 \((A_1,\ldots,A_4,R_{ij})\) 查询A_k |
| ownR，1条 | \(v_Z-r/(p_a+r+1)\) | 同节点查询R_ij，重复主题仍按两名提供者计负载 |
| reverseR，1条 | \((r-z)/d_R\) | 原R_ij在历史 \((h,T_i,C_j)\) 查询Z_ij |

[共同末位报价与隐藏回复投影](../引理/共同末位报价与隐藏回复投影--引理.md)给上述实际价格、容量和强PAIR的准确条件。强PAIR控制 \(F(Q)+F(Q')-G(Q,Q')\)，必须保交叠项，不能换成两个查询者利润和或根福利；这里 \(H=u_5+u_6+G(A_5,A_5)\) 的源背景是固定实际前四位。

# 从局部系数到56条矩阵行

程序从旧 `attractive_nested_exact.json` 仅抽16个hist作为固定支持。每个hist含实际六位及八个 \((T,B,C)\) 会员桶的六索引计数，另保比较重数d。它把这些桶展开成六个词，字面遍历全部36个有序 \((i,j)\)。这种遍历只压缩对称客户系数；不是把完整有序历史策略限制为计数函数，也不枚举全部六人游戏。

旧列结构为1个K、16个hist、582个joint-reply及1306个R-R交叠，合1905列。194个回复组各有01、10、11三个质量；00质量由hist质量减去三者得到，旧 `joint-state-upper` 行确保其非负。若某局部系数为 \(v(r,z)\)，当前线性化是
\[
v(0,0)h+\sum_{s\in\{01,10,11\}}[v(s)-v(0,0)]y_s.
\]
因此即使pair含rz、source分母含r/z，四状态保留后仍可精确线性化，无需假设R、Z独立。新行的1306个交叠列全为零，继承图的其它行继续使用它们。

容量行的K列专门写30和6，合为旧36K。其余新行K列为0。列中的 `hist_column_old` 是早期变换前的地址，实际代码按最近出现的hist归属；本轮核对当前组、状态与非负00质量，未把旧地址当当前数组下标。

最终 `build()` 保原3889行并追加56行，没移除28条冗余合行。它以 `702+5+nr.NF` 定位旧C族R基础行，以 `702+nr.NW+len(cl.EXTRA_NAMES)` 加 `nest.NI` 定位Z基础行，逐列Fraction断言拆分之和等于相应旧行。这些硬编码偏移使正确版本的依赖列顺序成为承重条件。

# 参数、依赖和实际运行边界

| 入口 | 实际行为与产物 |
| --- | --- |
| import模块 | 定义SPLIT/SI并导入依赖；不运行main或优化 |
| `build()` | 无参数；读取旧hist支持、构造3945行，核28个逐列合回恒等式，返回cols/names/m/obj/norm |
| `--verify` | 重建图，读取同目录split_basic_exact.json的weight，核非负、全部构造行余量、O=1、W与保存值相等且小于1/2；只打印结果 |
| 默认main | NumPy转浮点、按行最大绝对系数缩放，HiGHS最小化W，变量非负、O=1，两种容差1e-9；写status，成功且浮点W<1/2时尝试精确恢复 |

参数是检查 `sys.argv` 是否含 `--verify`，没有独立参数解析器；其它字串不会为本程序选择新图。默认优化由 `cl.exact_point` 选浮点正支持及近紧行，以Fraction消元恢复，再验证所有行、非负和归一化；不是简单小分母舍入。返回的精确可行点没有最优对偶证书，不能宣称精确最优。默认不会删除已有exact文件；若本次没有写出新exact，不能把目录中旧证书当本次优化输出。

原 `--verify` 对权重与行使用zip，未显式认证向量长度和完整列描述符。本轮新增审计另核两个冻结点均1905列、非weight描述符逐项相同、194组状态完整，避免把这一接口缺口混同于已核当前输入。

下层链为 `an.build → nest.build → cl.build → nr.old_system`。旧702行再从joint_system、fourth_indexed_projection以及same-menu、strong-pair、free-joint、nested-horizon、six-copy、six-stress生成。实际默认路径读取固定历史cut JSON，包含存在时才加入的 `target_joint.json`，不能为缩短依赖而省略它。主源及13份下层Python源码已全文实读；含本split点在内的28份源共2128016B已逐个取得并核SHA。下层旧cut的逐条证明与独立审查不因“为复跑取得文件”自动完成，本对象只承担本源新增56行的自足数学解释。可复现依赖路由见[清单](../../tools/evidence/split-basic-graph-program/source-manifest.json)，大旧输入共用同批联合图证据，避免重复保全。

本轮同批[联合图执行记录](../../tools/evidence/combined-branch-master-program/rerun/execution.json)已实读：未修改的 `combined_branch_master.py --verify` 唯一执行一次，Python 3.12.14、NumPy 2.3.5、SciPy 1.17.0、assert开启，退出0、stderr为空，5108行/1905列、最小余量0。该真实调用经过原split.build及全部逐列合回断言，故覆盖本源构造阶段；它验证的是联合图点，不是下面旧split点的完整3945行。本任务未再执行原默认优化、原split CLI或完整图build。

# 本轮独立系数核验和冻结点范围

[独立脚本](../../tools/evidence/split-basic-graph-program/verify_split_rows.py)直接按客户均分定义、真实历史及强PAIR表达式写另一份系数实现。为逐项比较，它只用AST提取原源码中的 `values(r,z)` 标量函数，不导入原图构造或求解器；继承的R/Z名称次序从两份原源码读取并检查。

完整核遍64种实际会员位、同/异索引兼容的词对、四种R/Z状态；其余比较词只通过三个线性菜单平均进入，分别选全零和三个坐标基填充，覆盖该仿射依赖。共73728种标量情况、2064384个系数严格相等。此项是系数恒等式检查，允许局部负系数，不是假装这些状态都构成完整SPE。

随后对冻结16hist和194回复组按四状态质量构造56条完整行，与原标量表达式的仿射展开比较全部 \(56\times1905=106680\) 个有理系数；全部相等。对[冻结split点](../../tools/evidence/split-basic-graph-program/related/split_basic_exact.json)的全部56个新增行余量均非负、最小0，且
\[
O=1,\qquad W=\frac{77122220724026571141557320969163}{161324472800190691224726909402699}<\frac12.
\]
该814800B点SHA-256为 `b12c4aa6b3cd106f3fb8e8a56be7469988456c0cb6e02b1741db8c09d587b34a`。其原元数据报告3945行、165正列；本任务没有另验此旧点的其余3889行，所以不把原全图报告改称当前独立3945行认证。全部新增余量和输入字节身份保在[独立报告](../../tools/evidence/split-basic-graph-program/independent-report.json)。

[已有阈值与拆分构造](../构造/回复会员阈值的共同凸抬升与对角预算拆分--构造.md)已解析解释对角预算，但明示当批未读原程序/JSON；本页增加真实代码和当前系数证据。原README的五条负拆分行是在3949阈值点上检查，不能挪称本3889输入点的五条负值。后来的4005/7931完成和5108/10344点属[不同阶段](../资源/显式回复主图的阶段点与未闭报价账本--资源.md)，其可行性不能混成同一输入。

程序可作为后续必要图的基础构造，必须保同一组版本与列顺序。固定16hist的低点表明这些已列必要行仍容许低于half的松弛值；它不构成共同目录完整SPE，未解决一般六人half，也没有从默认浮点失败推出全客户域不可行。来源、继承、行拆分与有限检查的关系在此据实说明，三级超图留第三阶段。
