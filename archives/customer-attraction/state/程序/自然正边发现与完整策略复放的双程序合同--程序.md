# probe：精确逆向归纳，返回条件只有正边

`probe_positive_fresh.py`只导标准库Fraction、itertools、math、Path、json、random，没有外部实例/规范求解器。固定m4、k5、seed240244，效用乘den=lcm(1,2,3,4)=12。每个trial权重为`[0]+31个randrange(0,31)`，即各非空兴趣mask有0至30名单位客户。

对**每个有序前缀**递归生成五个完整孩子，最大化当前角色的scaled整数效用；平局由同一rng随机选。`w*12//count`精确，因为coverer数1至4都整除12。终局效用缓存键为(sorted(z),z[i])：单位匿名玩家选择同一主题时在同一终局等收益，故只压缩效用求值；它没有按计数识别策略history或强迫不同前缀同平局。

同一rng先生成权重，再在全部子树的每个节点调用`rng.choice(choices)`，包括最优集合只有一个元素时，之后才进入下一trial；不能只用seed与trial编号跳过这些调用而称得到同一输入。保存的candidate已含实际完整策略，审计不需重做发现随机过程。

得actual Z后，fresh类型是在Z任何主题都不被覆盖且重数正的mask。若非空，按i递增、g字典序、j>i递增扫描，计算

\[
q_{ij}(g)=\sum_{b\in fresh:\ b\text{接受}B_i,A_j\text{但不接受}B_j}
\frac{w_b}{c_A(b)c_B(b)},\quad
B=finish(g),\ A=finish(Z_{<i},B_i).
\]

遇任意q>0立即返回完整candidate。虽docstring提研究目标“从ell≥0限制共同Λ≤1”，实际程序不形成多来源h/β、Λ列、ell约束、初始化或角色cap，也不检验Λ>1。其positive仅是**后续共同列攻击的必要非零种子**，不是所述候选的反例。

外层至多20000次，首次返回便写`positive_fresh_candidate.json`并break。冻结candidate的12个顶层字段是players/topics/weights/strategy/actual/context/i/j/B/A/q/trial；trial4409为零起始标签，按该循环是第4410次尝试处保存，不能叫本次新扫描或4410份均衡全域证明。本次**不运行发现入口**，未核整个早期随机序列；保原脚本、完整实际种子及此准确历史范围。

# audit：唯一外部游戏输入是完整candidate

`audit_positive_fresh.py`只导标准库，不导probe、canonical模型或其它研究程序。它从自身目录只读`positive_fresh_candidate.json`；以其中players/topics/weights/strategy建立原有序σ。`finish`反复查询原σ，`payoff`用Fraction对整数重数逐类型求和。客户重数与逐单位展开在这个加性分享模型下完全等价，不改客户价值或玩家权重。

对四个角色全部长度0至3有序前缀，逐个核五合法动作的真实完成IC，共780项含156self。它另遍历C(8,4)=70个无序四槽可重复组合求覆盖OPT（覆盖不依顺序；SPE策略仍依顺序），取第一个达到最大者作`one_optimal_tuple`。

从candidate读i/j/context，再从σ**重算**V、规定a、actual-prefix A和旧g返回actual动作的back，计算fresh ν、D_fresh、P/N、正future边、ell和g上全部目录查询利润。随后断言总fresh数量19≤每个actual u，给R-only所有owner极大current的无future充分理由；再遍历全部最优多重集的不同排列中T₀=0者，用原坐标正价公式计算首行余库存并断言≤u₀。该循环并不构建任意初始化/全传播图，不测试非极大current。

原audit没有单独断言candidate中冗余actual/B/A/q字段等于重算值；本次读后补展显式逐字段核同，包括q对应保存j的正边。补展还核32个非负整数权重、156个互异且恰穷尽合法前缀的行动、合法动作域，提取完整表和70覆盖值，确认唯一最优多重集。这是已知输入后的数据/覆盖展开，不是第二次original audit、独立盲实现或新SPE搜索；它不调用finish/payoff/BI，不重做780项IC。
