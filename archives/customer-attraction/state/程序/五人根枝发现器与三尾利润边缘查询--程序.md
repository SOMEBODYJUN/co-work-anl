# 五人根枝发现器与三尾利润边缘查询

本页八主源是三个浮点发现程序及四份报告，另加 `probe_three_profit.py`。全部实读，所有positive_primal、active_rows、equality_dual和原scope保全。三份浮点程序**没有main guard**，导入即构矩阵、跑LP，并在成功时覆盖相邻JSON；本批没有导入或执行它们。原件、依赖和本次唯一四点精确核见[证据入口](../../tools/evidence/ra277-five-closure-primary/README.md)。

## 一、四个明确有限系统的共用坐标

所有人数固定5。令命名主题成员位为 `(T,Q,B2,B3,B4,B5)`，另按模型添加C或C,D,E。每个独立二值型b有非负质量x_b，另有非负变量u，代表假定实际根利润；它不是该根强制枝上首人的利润r。全二值域包括全零型，不筛重复或覆盖别名。程序没有给这些命名主题之外的完整目录及全部历史策略，故一个可行点不自动是游戏或SPE。

原根强制T后路径P=`(T,B2,B3,B4,B5)`。对路径P及位置i，定义逐客户真实终局份额并对质量求和得到v_i(P)。任一非零分子有正负载，零分子按0。程序归一化

\[
 \delta=5u-|T|=1,
 \qquad \max(F_T(Q)-u),\quad F_T(Q)=\sum_b x_b\frac{b_Q}{1+4b_T}. \tag{1}
\]

这是根缺口斜率截面，不是总客户质量1或福利1。只对delta>0可齐次缩成此截面；delta0由已证根刚性另处理，不能把空截面代码当该边界证明。

共同有效行是根IC `u−v1(P)≥0`、每个命名主题大小cap `5u−|S|≥0`，以及原枝后继各真节点的保底行：若此前客户负载为p、含当前尚有r人，当前利润至少 `sum_(x in Q)1/(p_x+r)`。偏离后的后继仍可改变，式子只用最大负载r，不冻结旧路径。

最后两人实际为(A,B)、过去负载p时，代码使用

\[
 H_p(A,B)=U_p(A,B)+U_p(B,A)
       +\sum_{x\in A}\frac1{(p_x+1)(p_x+2)},
\]

\[
 H_p(A,B)\ge\sum_x\left[
 \frac{\mathbf1_X+\mathbf1_Y}{p_x+1}
 -\frac{\mathbf1_X\mathbf1_Y}{(p_x+1)(p_x+2)}\right]. \tag{PAIR}
\]

标准[强PAIR](../引理/末两人重叠比较与任意索引聚合--引理.md)要求这两人构成同一原策略中的真正完整两人SPE；其证明含第一尾的IC，不能只见两个末主题就自动套用。比较主题允许重复，代码枚举无序含重复对。

## 二、probe_middle：两个65变量模型

六位给64质量，加u共65变量。原枝的根IC1条、六大小cap、四个后继位置各六保底，共31条。False模式只用这31条；True模式再加原枝真末两人对六主题的21条PAIR，共52条。两个模式都使用 `(1)`，每个各一次SciPy/HiGHS LP。

所有这些行在真实原策略对应节点上合法，但它们不是完整SPE的充分刻画。原source将value称slope，只是这份必要条件系统的数值目标，不是已证真实SPE域最优斜率。

两报告保相同七个active行：根IC、B2/B3/B4/B5大小、第四位对B5保底、原末位对Q。小分母值对应 `311/21,1/2,1/2,31/42,37/42,5/21,1`，恰为已证明[113/21合同](../引理/五人共同大小根刚性加强--引理.md)。PAIR行未在阈值筛出的对偶支持中出现。两份positive_primal不同，不能据相同斜率称同一点；本次精确恢复见[计算页](../计算/五人根刚性四个有限松弛的精确取等点--计算.md)。

| 原报告 | 浮点slope | equality_dual | 保存正质量型数／u |
|---|---:|---:|---|
| False | 5.380952380952381 | −5.38095238095238 | 8型及u≈2 |
| True | 5.380952380952383 | −5.38095238095238 | 8型及u≈2.3142857142857127 |

active阈值1e−8，positive_primal阈值1e−8。没有保存全部原x、全部marginals、矩阵、误差、环境或solver状态对象，未列坐标可能是零或很小；不能称“原浮点完整向量恰是下面有理向量”。程序成功时覆盖两个不同文件，失败则打印message且不写该文件，仍可能继续下个模式；留下旧JSON不能当本次成功运行。

## 三、probe_copy_reply：129变量及28条未闭合额外行

七位加回复C，原sigma的两路径为

\[
 P=(T,B_2,B_3,B_4,B_5),\qquad
 P_4'=(T,B_2,B_3,B_5,C).
\]

第四位在原P是真优化者，强制改B5后末位C沿原sigma真最佳回复。加入真实第四位IC `v4(P)−v4(P4')≥0`；新末位在P4'对全部七主题的精确BR共七条。原枝31型行扩成根1、大小7、四阶段×7保底28，共36条；复制IC和七末BR后为44条。原枝真末两人对七题的28条PAIR合法，形成**72条已闭合合同**。

源码还对P4'的末两位加28条PAIR，合100条、129变量。问题在于P4'第四位B5是被强制的，不自动是该两人子局的首位BR；标准PAIR的第一尾IC不能直接获得。原B5在P上是末位BR，可能提供其它关系，但本源没有给把这些信息转换成P4'强PAIR的完整替代推导。因此这里将这28条记为**额外代数行，原CAG必要性未闭合**，不称它们已假，也不把含它们的100行系统整体授为可靠必要条件松弛。

这一缺口不损害已证COPY：保存对偶只用以下九行，没有任何PAIR，更没有用这28条：

| 行 | 精确权 |
|---|---:|
| 根IC | 44/3 |
| B2、B3大小 | 各1/2 |
| B4、B5大小 | 11/15、13/15 |
| 原末位比Q、比C | 14/15、2/15 |
| 原第四位复制B5，保真回复C | 4/15 |
| 复制枝真末位C比Q | 1/15 |

它们正是[真实回复COPY证明](../引理/五人根复制真实末回复刚性--引理.md)的九个非负合同。源码另对T、Q、C给大小cap，但这些权不在该上界支持中；主证明不需要C的大小cap。

2047B报告保存slope5.333333333333332、equality_dual同负号、九active行、八正质量型和u≈8/3。active阈值1e−7、positive阈值1e−8。本次另恢复精确点并查全部100条；它也当然满足删除28额外行后的72条。故两份**明确代数系统**的最优均16/3，后者有可靠原模型合同解释；前者的有限精确最优不修复额外行的博弈证明缺口。

## 四、probe_three_tail_copy：第三位偏离及真正两尾

九位加D,E，保三路径

\[
 P=(T,B_2,B_3,B_4,B_5),\quad
 P_4'=(T,B_2,B_3,B_5,C),\quad
 P_3'=(T,B_2,B_5,D,E).
\]

新增IC来自P的第三位强制B5后跟原sigma的D,E；它不是将第三位本身当新枝BR。P3'的最后D,E两位才是真正两人SPE，所以其强PAIR合法。代码有意没有给P4'加PAIR。

完整行数为根1+九大小cap9+两条原第三/第四复制IC2+原枝4×9保底36+P4'末位9+P3'后两位2×9保底18+P及P3'两组各45条PAIR90，合165条，513变量。模型全使用 `(1)`，不是穷尽所有第三位偏离、全部真实后继菜单或整个完整树。

2959B报告保存slope5.3333333333333375、equality_dual−5.333333333333332、九active行和十二正质量型加u。九active行仅是上一COPY九合同重命名，新第三位IC、D/E行和两组PAIR都不在此上界支持中。不能由这个支持或数值未改进推论“一切三尾信息无用”。本次有理恢复确证这**一个指定165行系统**仍有16/3取等点，并给出其对原七位点的精确投影。

三个程序都是固定单次构造，不做随机样本；middle连续解False/True两LP，copy与three_tail各一LP。NumPy/SciPy版本未冻结。没有main guard，执行/导入即求解；success时写相邻JSON，失败只打印message，可能正常退出而留下旧报告。旧报告的scope正确保“floating / not theorem”；它们没有完整SPE、实际福利或OPT字段，不能从positive_primal构造声称已核的真实均衡。

## 六、probe_three_profit：只算独立边缘，不运行游戏

这份2112B代码只用标准库，必须给argv[1] JSON路径，没有默认输入、无输出文件，main仅stdout。ROOT虽计算却未使用；它不导入旧定价器、LP或游戏solver。原README只称旧点的Cartesian查询有大松弛，没有保存实际argv/stdout，所以本批不补造其最小值或负行数。

输入至少要非空atoms，每原子含十位 `ABCDEUVWXY`、8格AB_hist、8格AE_hist、16格second_hist、menus_lh和exact_mass。前三直方图按二/四位二进制字典序，counts以5为分母。程序定义固定十题的0/1查询概率；T由AB_hist首位边缘给；AB.R/S、AE.R/S、SB.H/I/J由对应直方图边缘给；每个menus_lh只用l/5，h虽然读出但不参与计算。

对于背景p和三个独立查询命中概率 `(q1,q2,q3)`，精确计算

\[
 E_p(q_1,q_2,q_3)=\sum_{v\in\{0,1\}^3}
 \frac{|v|}{p+|v|}\prod_{j=1}^3q_j^{v_j}(1-q_j)^{1-v_j},
\]

零命中份额记0。重复查询名仍按三个独立抽样使用同一边缘概率，不能改成同一次抽样复制三次。输入来源利润为：AB背景A+B、实际尾CDE；AE背景A+E、实际尾UVW；SB按second_hist的每个 `(t,h,i,j)` 权n/5取背景A+t、尾HIJ。逐质量累加 `5V/3−E_p`，按所有无序含重复查询三元组取最小，打印每来源的minimum、float展示、queries及negative_rows。

这正是[固定背景三人5/3利润界](../定理/固定背景三人利润界--定理.md)对合法查询分布的平均形式；前提仍须是真实三人子SPE和合法主题抽样。程序本身只读边缘表，不构造这些全历史或跨原子共同主题，因而对必要条件松弛的计算不是原游戏定理的新证明。

现有同源旧557点可作为**相容输入**复用，准确SHA/路径见[依赖清单](../../tools/evidence/ra277-five-closure-primary/reused-dependencies.json)。本批完整读其60原子的六字段及范围元数据；未读/未认证其557个旧slacks或basis行语义。该输入含三个menus_lh，故查询名为21个、每来源无序三元组为binom(23,3)=1771；这是代码与输入结构的解析计数，不是本次运行1771行。没有冻结argv证明它就是历史实际调用的唯一文件，更没有把旧comparison_cover称全目录OPT。当前原CLI及这份旧输入枚举均0次。
