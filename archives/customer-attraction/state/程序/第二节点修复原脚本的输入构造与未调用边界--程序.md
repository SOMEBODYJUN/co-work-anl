# 内部两组单位输入的完整算术

每轮旧主题为A={0,…,m−1}、B={m,…,m+m(m+1)−1}，大小m和m(m+1)，互不交。银行容量为(2,m−2,1,…,1)，按该次序在旧客户编号之后接入连续不交单位块；总银行客户2m−2。topics按“旧主题先、银行后”的顺序列举a∪b，k=2m。

对每个单位客户x，masks[x]=Σ_(a:x∈topics[a])2^a，是成员关系位掩码；原码没有调用任何后续模块消费这个数组。下面表由原集合定义手工展开，**不是一次程序运行输出**。

# 三个未调用函数实际表达什么

`bc(h)`以有序银行行动tuple h为缓存键。若len(h)==m直接返回终局h；否则追加ba(h)后递归。`ba(h)`也按完整h缓存，列出`h.count(a)<caps[a]`的全部未满银行资源，断言free非空；对每个a递归完成bc(h+(a,))，最大化

\[
\left(\frac{caps[a]}{\#_a\,bc(h+(a,))},-a,a\right).
\]

收益用Fraction，平局优先较小行动编号。它只计算银行坐标的一份有序BI选择，不读取旧主题。已满资源被排除的理论理由是[银行完整历史容量下限](../定理/仅第二节点缺陷的祖先回退保险与四倍精确损失--定理.md)：合法非终端前缀总有未满core能保收益至少1，已满动作自身严格低于1。这一理由由解析证明承担；原程序没有调用函数以验证它。

`core(h)`在完整前缀只含X/Y且两负载未过cap时，X未满就选X，否则选Y；包含Z或已过填时返回ba(h)。first-dirty记录留在整个有序前缀里，后来不会再变clean，因此它表达core-fill/银行BI的一个实现草稿。bc/ba/core的意图域是合法银行非终端历史（bc另外识别恰长m终局）；core未单独阻止终局调用，不能当任意长度输入的公开验证API。

原函数没有实现H/L_X/L_Y/L_Z、按整个联合第二动作选模、R_A旧fallback、根/第二联合偏离、共同复制或OPT逐槽相加；也没有把core作为独立求解器和真正产品树组合。文件头“不导canonical verifier/oracle”准确指代码没有这种导入，并不说明有另一套完整验证已经运行。
