# 资源身份与模型

[五原件、来源清单和复核入口](../../tools/evidence/aggregate-static-security-cone-four-snapshots-primary/README.md)分别保留3037B脚本、710B/3260B/1931B/52038B四个JSON。两冻结提交`68fad804ec5946cb296f77dc5b336308a66abf12`和`aefc58eac3fc6eb5d7a47d087dd2c62b5aa9974c`的对应文件同字节，不算两份独立实现。原件在`clean show`后按冻结SHA-256核对；7_5的3082行分三片读到最后一个策略节点及闭括号。基于`rg --files`列出的57136个路径，对本新增包外文件作大小筛选后SHA-256比较，没有发现这五主源的同哈希既有保全件，故本包补录原件，不重写已成文CCE数学。

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)。此处k为标签数，m为提供者数，标签为0至k−1。客户兴趣由非空mask T⊆[k]表示，质量为r_T≥0；脚本归一Σr_T=1。对完整终局z，客户负载c_T(z)=Σ_i 1[z_i∈T]，玩家i收益与福利为

\[
u_i(z;r)=\sum_{T\ni z_i}\frac{r_T}{c_T(z)},\qquad
W(z;r)=\sum_{T:c_T(z)>0}r_T.
\]

收益求和中z_i∈T保证分母正，未覆盖客户不作0/0。mask0遗漏不影响任何收益或覆盖；它没有从目录删除空主题。全历史纯策略σ在每个有序h∈[k]^{<m}给一个行动；任意偏离后沿同一σ的真实后继继续。重复、空覆盖标签、同覆盖异标签和所有离轨平局均合法。脚本的浮点质量不是已经交付的单位客户证书；下文的有理恢复以共同分母扩大成不同单位客户，正比例缩放保全所有激励及比较。

# 真正静态安全值和待检验的动态目标

竞争者在得知查询分布p后、看不到本次抽出的查询标签a时，共同选m−1槽背景b。令

\[
F_b(a;r)=\sum_{T\ni a}\frac{r_T}{1+c_T(b)},\qquad
v_m(r)=\max_{p\in\Delta_k}\min_{b\in[k]^{m-1}}\sum_a p_aF_b(a;r).
\tag{1}
\]

背景可重复，不要求独立同分布，也不要求来自σ的真实回复。由于F只依赖背景各标签计数，枚举排序多重集等价覆盖全部有序背景；不是限制真实策略为计数策略。令β_(b,a,T)=1[a∈T]/(1+c_T(b))，脚本`security_data`构造的数组恰为这些系数，形状为`(C(k+m−2,m−1), k, 2^k−1)`。

`security(r,beta)`解最大化t的LP：p≥0、Σp=1，且对每个b，t≤Σ_(a,T) p_a β_(b,a,T)r_T。它返回最优查询p和浮点值t。这是(1)的静态maximin；没有使用SPE激励行。

真正待发现的正差是

\[
G(r,\sigma)=m v_m(r)-W(z_\sigma;r)>0.
\tag{2}
\]

它若配有合法单位客户及完整SPE，才反驳强聚合付款桥W≥m v_m。静态的[锐安全界](../定理/静态混合安全值的锐目录计数界--定理.md)给v_m≥OPT_m/(2m−1)，但没有给动态W的付款。(2)的正差本身也未必是half反例；half反例另需OPT_m>2W。此程序没有证明全称聚合桥，也没有处理恰六人的全部实例。

# 原程序逐步合同

运行依赖Python、NumPy、SciPy/HiGHS和同目录可导入的`search_cce`。其[冻结依赖原件](../../tools/evidence/security-cce-search-program-primary/original/search_cce.py)为4806B、SHA-256 `bf868944a4c4400b408db663626b3cb9223fb4acd9a5cbe99bc83590a888cc26`。本次全文核对了实际`data`和`solve_spe`：前者枚举终局计数并返回`masks, profiles, counts, ix, uc, wc, g`；后者按计数缓存可实现SPE终局集合，取最低福利的计数代表，再展开所有有序历史，给完整σ及每节点每行动的收益差行Γ。其可实现判断含`1e-9`容差。它允许相同计数的不同历史使用不同平局回复；并未只构建一条路径。

设z为所选终局计数代表、w_z为其覆盖向量。每个trial先从每类型0至7整数抽样，以0.35概率保留，跳过全零，再归一r；只在这里调用一次`solve_spe`。之后最多15个内层step固定σ、Γ和z：

1. 对当前r解(1)，计算G=m·val−w_z·r。
2. 若G比全运行`best`大超过`1e-9`，先打印含trial、step、gap、W、v的一行JSON，再以缩进JSON覆盖`--out`。
3. 若G>`1e-7`立即结束全部搜索；这只是浮点发现阈值。
4. 固定刚得的p，令q_b=Σ_a p_aβ_(b,a,·)，求

\[
\min_{r',t}\ w_z\cdot r'-m t,
\quad r'\ge0,\quad\sum_T r'_T=1,\quad
\Gamma r'\ge0,\quad t\le q_b\cdot r'\ \ (\text{每个}b).
\tag{3}
\]

5. 若LP失败或新旧r的欧氏距离<`1e-8`，结束该trial内层；否则更新r并继续。第15步后亦进入下一trial。

Γ来自完整有序树，所以在精确可行算术下(3)保σ的SPE激励；客户改变后未重求所有SPE，z也不再保证是新r的全局最坏SPE。有限随机初点、每树固定锥及交替LP均没有穷尽所有策略或客户。原程序不作有理恢复、逐历史精确复核或安全值有理对偶认证。

CLI参数为`--k 4 --m 3 --trials 1000 --seed 1`及必填`--out PATH`；程序未验证一般整数参数域，数学合同取k,m≥1。它不创建输出父目录，输出已有文件会被覆盖；若没有有效初点可没有输出。四个保存点各只有`k,m,gap,masks,r,target,query_p,sigma`八字段，未存试验数、随机种子、step、软件版本、W、v或静态对偶。它们与本程序格式兼容，但没有足够元数据还原各自原运行，不能由文件名推导搜索范围或无正差次数。

# 安全值的精确两侧与全历史核验

四份查询p对所有排序静态背景的期望至少表中v。另一方面分别固定以下一个合法背景，就使每个纯查询至多v：

| 文件 | 对偶纯背景，概率1 | 该背景的各纯查询值 |
|---|---|---|
| 4_3 | (0,0) | (19/60,7/30,1/6,0) |
| 5_4 | (2,2,2) | (1/7,1/7,1/7,1/7,1/7) |
| 6_3 | (1,1) | 六项全1/7 |
| 7_5 | (1,1,1,1) | 七项全1/7 |

原始查询的逐背景下界与对偶背景的逐纯查询上界匹配，才认证v的锐值。没有把某个可行查询的保证误作已求最大值，也没有把对偶背景限制为真实续局。前述276个静态背景分别为10、35、21、210；完整报告逐行保存βr及p期望，复验只需标准库Fraction，不依赖浮点LP。

独立`verify_snapshots.py`不导入原发现器、`search_cce`或任何均衡求解器。它检查σ恰覆盖每个h∈[k]^{<m}且动作合法，从定义递归真实终局；对每个h和每个a比较指定行动收益与改选a后同σ续局的收益，包含自身比较。四例分别核21/156/43/2801节点及84/780/258/19607比较，共3021节点20729比较；有理恢复的所有slack≥0，各层最小值均0。每位仅行动一次，每节点这些比较即给完整纯SPE。原20客户和7客户均分可直接由恢复质量正比例放大。

还对原JSON每个十进制按其**精确十进制分数**复核完整σ，结果前三例仍无负slack；7_5存在真实负slack。原件r₁=r₃₂=0.14285714285714288，r₉₄=0.7142857142857143，根指定2得r₉₄/5，而根偏离0或5沿原σ得r₁。因此

\[
u_1(\text{指定2})-u_1(\text{偏离0})
=-\frac1{50\,000\,000\,000\,000\,000}<0.
\]

故不能宣称7_5原十进制是精确SPE；原`gap=−1.1102230246251565e−16`也只是浮点字段。有理恢复把r₉₄/5与r₁同时改为1/7后，所有20729比较和四个安全原始/对偶证书才给本页的精确结论。恢复误差小本身不保证平局激励保持，这次依赖的是重新穷尽全部节点。

# 与全仓后续结果的比较、关系和接续

已读[真实菜单障碍](../障碍/自适应后继与真实菜单安全值--障碍.md)和[extra-one边界](../问题/自由extra-one与iid安全值边界--问题.md)：前者的观察查询真实后继、受限菜单值，后者的额外一槽/分数门槛，均有不同量词及后续失败。它们不能替换(1)。[指定策略锥证书](../审查/指定完整策略锥安全证书与预算边界--审查.md)通过共同Q和Γ乘子的全类型恒等式支付整棵固定锥；本批只认证四个固定恢复点，没有全锥乘子，不能由四个等号升级为四个整个策略锥都成立。

关系判断：本程序实现静态(1)和固定完整策略锥上的交替发现；导入`search_cce`的`data/solve_spe`是程序依赖。四JSON保留具体客户、p、全部σ及浮点状态，提供有限输入；本页有理恢复及定义级核验给四个独立指定点的有限证据，不给任意策略推导。与静态安全锐界是定义/比较关系，与CCE及菜单障碍是不同桥的边界比较。本批不生成第三阶段超图，也不把来源位置或同一实现变体计作独立外审。

接续可复用原完整σ和四份单位客户等号实例作回归，特别检查target次序与小误差平局。要寻找(2)反例须另给正差的精确上下界和完整SPE；要证明全锥付款须提供全部类型的共同背景证书；要解决恰六人half仍须保全六人、任意合法目录/客户、所有有序历史和平局的全称范围。本页均未完成这些另外的目标。
