# 对象和范围

这些源来自 `R-486bb9adb8cd4d9a940dbf3b1ab0b1de/terminal`。三、四人探针都在六个主题的完整策略锥上工作：客户质量按非空主题 mask 编号，终局付款用 `Engine` 的整数最小公倍数缩放。探针先以浮点逆向递推选取一个可实现终局，再从该终局的有序历史偏离行构造固定策略锥；LP 的归一式是实际终局覆盖向量与质量向量的内积为 1。它不是跨所有纯 SPE、所有策略或所有客户输入的联合优化。

`search_mass_two.py` 使用相邻冻结的 `three_price_template_weak.py`，`search_uniform_mass_three_halves.py` 则自行定义 `raw`，二者生成五个二进制位 `(a,b,c,q,r)` 与五个 `(d,l)` 状态的代数行。该 helper 是独立源版本；本页只把它作为复现依赖，不把 helper 的未处理文件冒充本批来源。

# 三人、四人价格锥攻击

`probe_four_price.py` 固定 `m=4,p=6,seed=602617`，最多 300 次；`probe_three_price.py` 固定 `m=3,p=6`、同一 seed、最多 150 次。每次先由 `Engine.solve` 以容差 `max(1,\sum r)10^{-10}` 做浮点 Bellman 递推，再由 `strategy` 在每个有序历史选择规定孩子和离轨最小回复，生成差行 `G`。LP 以根终局覆盖 `cov[target]·r=1`，在 `G r\ge0` 下最大化由有限主题查询组成的目标；候选若为正，代码才尝试 Fraction 恢复、整数化，并调用 canonical `verify_canonical` 检查完整有序 IC。

冻结四人报告的内容是：`scope = finite cone attack, no universal proof`，`best=-0.0`，记录恰为 `it=0,...,299`；没有 `instance`、`certificate` 或正分离项。冻结三人脚本没有把报告作为本源文件，但在同一依赖布局重放得到 `best=-0.0`、150 条记录，且 stdout 未出现正候选。四人报告重放文件与冻结 JSON 的 SHA-256 完全相同，说明这次重放没有改变冻结报告字节；三人重放只证明同一有限程序在当前依赖闭包下仍停在零分离。

这两个结果只能说明指定 seed、人数、六主题和 300/150 次有限锥搜索没有产生正候选。浮点门槛、固定策略锥、随机起点、未保存的完整行和未生成的精确对偶都阻止把 `best=-0.0` 解释为一般价格不等式或半覆盖证明。即使 `exact_recover` 成功，也只会认证一个固定锥中的完整策略，不会自动认证全模型；本轮没有进入该分支。

# `search_mass_two.py` 的两个有限乘子系统

脚本将 `tau=2`、背景参数 `pbg=0,1,\ldots,100` 的每个 32 个 bit 状态与五个 `(d,l)` 取值组合成 16,160 行。它分别累积 `discounted` 和 `W` 两种右端，并用 SciPy/HiGHS 求七个非负乘子；最终输出（将浮点结果用 `Fraction.limit_denominator(10^6)` 显示）为

| 目标右端 | 七个乘子 |
|---|---|
| `discounted` | `(7/36, 1/3, 5/9, 5/72, 5/18, 1/3, 1/6)` |
| `W` | `(134/2421, 536/2421, 14231/21789, 2573/43578, 5146/21789, 2144/2421, 268/2421)` |

我用独立 Fraction 程序按脚本的行公式重新生成全部 16,160 行，逐项计算 `rhs - row·lambda`。两个乘子组的最小 slack 都是 0，负 slack 数均为 0；最大 slack 分别为 `13/9` 和 `3511/2421`。这是一个有限辅助行系统的精确可行性复核。它没有证明 SciPy 返回值是全局最优，也没有给出这些行到完整 SPE 福利/六人目标的保持映射。

# `tau=3/2` 的 800 行有理证书

`search_uniform_mass_three_halves.py` 取 `tau=3/2`。对 32 个 bit 状态和五个 `(d,l)` 组合，先加入 `p=0` 行，再将清分母后 `p=1,2,3,4` 四个取值的零至三阶前向差分加入，因此总行数是 `32×5×(1+4)=800`。LP 的八个变量由七个行系数及最后一个标量组成；输出

\[
\lambda=(0,0,20/23,0,6/23,21/23,0,43/46),
\qquad \min\operatorname{slack}=0.
\]

源程序用有理数构造行、把 LP 值限分母后再计算 slack；`exact_nonnegative=true` 只表示这 800 行的非负余量。该证书可以作为后续证明的局部乘子模板，但当前源没有说明一个从该模板到完整终局策略、真实客户计数或 `OPT_m\le2W` 的全称归纳。不能把 `3/2` 标签升级为一般三人、四人或六人半覆盖常数。
