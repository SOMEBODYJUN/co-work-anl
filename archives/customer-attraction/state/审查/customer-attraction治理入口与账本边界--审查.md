# customer-attraction 治理入口、账本与库存边界

本批 19 个来源均属于研究入口、角色说明、失败路线账本、成果总账、接续材料或机器库存 JSON；没有新的客户目录、SPE 策略、证明行或可独立审计的数学证书。完整原字节和冻结来源见 `archives/customer-attraction/tools/evidence/governance-customer-attraction/source-manifest.json`。

逐源处置如下：

- `BOSS_START.md`、`CLEANER.md`、`EDITOR.md`、`README.md`、两版 `RUNBOOK.md`：角色、启动、交接和入库规则；治理重复。
- `CLAIMS.md`、`RESEARCH_STATE.md`、`RESULTS_LEDGER.md`、`FAILED_ROUTES.md` 两冻结版本、`SYNTHESIS.md` 两冻结版本、`RETAINED_QUESTIONS.md`、`PRO_N6_PACKET_INDEX.md`、`WORKSPACE_RESULTS.md`：状态/失败/接续导航。它们的数学断言必须回指现行 `archives/customer-attraction/state` 正文；本批不把摘要当证明。
- `CURATION.md`：清理记录和状态修正，保留其截止日期与“入口盘点不等于全仓重审”的限制。
- `context_inventory.json` 与 `workspace_results_inventory.json`：机器库存；逐条解析记录数、路径、ID、哈希和状态字段，原 JSON 不改写。库存字段检查不能代替数学阅读。

当前主目标仍为任意人数、任意有限共同目录、每个完整历史纯 SPE 的 `2W≥OPT_m`；本批没有改变 OPEN/FALSE/条件性标签。后续引用账本时必须读取对应 state 正文和 evidence manifest，不能从本批导航文件单独推导新结论。
