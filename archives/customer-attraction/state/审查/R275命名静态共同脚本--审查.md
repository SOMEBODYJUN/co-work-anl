# `Fast` 的数学对象

`Fast(p,n)` 枚举长度为 `n` 的主题计数向量和全部非空客户兴趣掩码。对客户类型 `T` 与终局计数 `z`，`den[z,T]` 是 `T` 中被选择的总次数，`coefs[z,a,T]` 是主题 `a` 为该客户带来的均分份额，零负载时份额为 0。`Fast.run(w)` 用递归后向归纳建立可行终局菜单：叶节点只有自身计数；内部状态先取各行动孩子的最小当前收益，再保留达到该阈值的孩子。递归使用 `1e-8` 浮点容差，因此它是有限数值筛选，不是 Fraction 级证明。

`named_static_common.py` 不调用 `Fast.run`，而是复用 `Fast` 的 `coefs`、`den` 和客户掩码来处理外部策略 JSON。每个 JSON 的 `actions` 映射完整历史到动作；脚本从动作表得到 `p`（主题数）、`n`（历史深度加一）和根终局 `target`。

# 固定策略锥与共同静态目标

对每个完整历史 `h`、规定动作 `a` 和偏离动作 `b≠a`，代码形成一行

`gamma[h,a,b,T] = coefs[terminal(h),a,T] - coefs[terminal(h+(b,)),b,T]`。

令 `gamma` 的行集合为 `G`，则浮点激励锥候选是 `G w ≥ 0`、`w ≥ 0`。`loads=den[target]`，`covered=1_{loads>0}`；等式 `covered·w=1` 把终局已覆盖客户质量归一化为 1。该锥只针对 JSON 中那一份完整动作表；它不量化所有完整纯 SPE，也不检查外部 JSON 是否真的包含每个离轨子树的独立最优策略。

对于每个查询主题 `a`，脚本构造目标向量

`objective_a = covered + covered/(1+(n-1)loads/n) - F_a`,

其中 `F_a` 是 `Fast.M`（客户类型是否包含主题 `a`）按 `(n+1)/(loads+1)` 或 `n` 缩放后的行。随后用 SciPy `linprog` 最小化 `objective_a·w`，约束为 `G w≥0`、`covered·w=1`、`w≥0`。若最优值小于当前 `best`，脚本保存策略名、权重、根终局、动作和 slack；若 `best < -1e-7`，打印 `BRIDGE FAIL` 并停止。

这是一种固定策略上的共同静态目标扫描。它没有有理恢复、对偶证书、客户实例重建或逐历史 Fraction 重算；负值也只能先作为该固定策略锥和该目标模板的数值候选。
