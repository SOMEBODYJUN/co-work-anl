# R-3e17a9 推广首位回复与联合原子松弛审查

## 1. 研究对象与结论等级

本批四源研究同一局部路线：在一个既有完整策略/原子支持点上，把同一来源的首位回复提升到新分支，检查局部真实必要行是否仍可由旧报价支付，再将旧 R/Z 原子与新 B→D,E 推广行放进一个联合线性松弛。源文件自身把目标限定为局部 separation 或 necessary-system 诊断；没有把输出称为客户实例、完整历史纯 SPE 或 Q-CAG-HALF 反例。

必须区分三层对象：

1. early_reply_promotion.py 的行系统是固定旧支持点上的必要行；
2. early_reply_promotion_exact.json 是一个指定 lifted point 的 Fraction 公式核验和严格负 slack；
3. promotion_joint_atoms_exact.json 是 restricted 16 histograms 的 exact 可行必要系统点，不是从客户和全历史策略生成的博弈。

## 2. 首位回复推广的局部精确分离

early_reply_promotion.py 读取旧 R-c4f1…/six_astra/attractive_nested_exact.json，构造实际四位前缀、旧/新共享预算、末位价格、容量和实际 pair 行。其 NAMES 包含 source、oldpair-newpair、旧 C、新 E、pair、price、capacity、actualpair 等行族；每个支持点和四个配置变量 (s,b,c,v) 展开成局部列，再用 SciPy LP 搜索共享上界。

本批没有把缺失的旧输入冒充为已读或重新运行；冻结 exact JSON 自报 2,560 个局部 identity checks、6 个 query indices，给出：

    left  = 798702964492060907464900002268748739 /
            21722188083558433386371840226644560
    right = 434315048811318573228172128726166319 /
            10861094041779216693185920113322280
    raw_slack = left − right
              = −69927133130576238991444255183583899 /
                21722188083558433386371840226644560 < 0.

raw_slack 约为 −3.21916；按源中除以 74 的缩放约为 −0.0435021。该负值证明指定 lifted point 不满足那套局部共同上界，因而排除了该点的原候选行系统；它没有给出真实客户重数、完整策略动作表或全树 IC。exact JSON 的 status 也明确写着 “strict separation of specified lifted point; not a half proof”。

## 3. 联合旧/新原子松弛

promotion_joint_atoms.py 将：

* 旧 joint_atoms 的 1,143 个 raw families；
* promotion 的完整 88 个 raw rows；
* 每个有限 histogram 的 promotion-state upper bounds；

放入一个稀疏必要系统。代码固定原有 16 个 histogram，先加载冻结旧 atoms，再加入每个组的二元 R/Z 位和随机初始原子，以 SciPy LP 做列生成。若找到低于一半的可行点，recover() 只重建 Fraction 行、检查非负 slack 和质量归一，仍把结果标为 exact feasible necessary-system point。

promotion_joint_atoms_exact.json 的字段逐项核对为：

    scope: exact feasible necessary-system point;
           1143 old raw families + full 88 promotion raw rows
           and state-mass bounds; not a game/SPE/half result
    O = 1
    W = 62639914980892951648306747072697141151134151554374880507144 /
        126208720217724762225533804965567209821942870207757303886307
      ≈ 0.49632002347
    K ≈ 0.24062550904
    rows = 1269
    minimum_slack = 0
    RZ_atoms = 29
    promotion_states = 21.

因此这个必要系统允许一个 W<1/2 的 exact 松弛点；它只能说明当前有限行集合不足以推出半覆盖，不能说明存在同 W 的单位客户实例或完整 SPE。29 个 RZ atoms 与 21 个 promotion states 是隐藏位的松弛质量，不能把正质量原子直接相加成客户，也不能把其 histogram 组合误读成同一份有序历史策略。

## 4. 与既有对象的关系

既有“根回复支撑入口与全比较覆盖交换点的输入边界”已经保留 4095e0… JSON 的输入范围、16 histograms、29 atoms、21 states、rows=1269 和 W/K 字段；本审查新增的是把该 JSON 与另外三个未合并脚本/报告放在同一量词框架下，逐项说明 local separation 与 necessary-system relaxation 的区别。4095e0…在本批 receipt 中仍指向本页及既有入口，避免把同一原子 JSON重复当成两份数学证据。

R915 固定点诊断只处理另一组 196 个 target/query 情形；本批的 2,560 identity checks 和 16-histogram joint relaxation 不能互相替代，也不能把任一局部 separation 解释成支付定理。两批共同的边界是：推广行和容量行仍是必要条件，缺少从行系统回到整数客户类型、所有有序历史动作和完整 SPE 的充分实现。

## 5. 结论、障碍和后续义务

**已确认。** 指定 lifted point 的局部共同上界有 exact 负 slack；联合旧/新原子必要系统有 exact W≈0.49632 的低于一半松弛点；两项都严格记录了有限 histogram、行数和隐藏状态范围。

**有限实验。** Python 程序依赖外部旧输入和 SciPy；本批对两个脚本做全文读取，对两个 JSON 做完整字段/分数读取，未声称重新运行 promotion_joint_atoms.py，也未把历史运行日志变成新的全局证明。

**障碍。** 低于一半的 necessary-system 点没有客户级 realizability，minimum_slack=0 不是完整 IC slack 证书；局部负分离只否定给定点/给定行集合。不能把两者升级为纯 SPE 福利反例，也不能从有限行集合缺口推出任意模型路线不可能。

**未决。** 若要把该路线推进到 Q-CAG-HALF，需要显式给出：整数客户输入、全历史动作映射、每个偏离后继的 exact 收益比较，以及把新增 promotion rows 与旧 rows 同时实现的充分构造。当前一般六人目标仍 OPEN。
