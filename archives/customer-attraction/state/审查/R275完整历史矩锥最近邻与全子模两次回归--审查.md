# R275 完整历史矩锥的最近邻与全子模两次回归

## 1. 程序合同和三份源的关系

`full_history_walk.py` 在五个玩家、七个主题的抽象客户矩空间上工作。它把每个非空主题掩码映到一个 Shapley 型公共矩坐标，以 `--global-submodular` 决定保留所有阶的坐标或只保留至玩家数的截断阶；然后用 `ExactSPESolver` 的集合值递归生成完整任意历史纯 SPE 的终局集合。每轮从一个随机或重启的抽象矩向量出发，构造一份完整动作树，逐历史检查所有动作偏离，再在当前策略锥上解浮点 LP。

这三份源不是同一份运行的重复副本：

- `full_history_walk.py` 是可配置程序，参数包括 `rounds`、`continuations`、`global_submodular` 和 `root_selection`；
- `full_history_walk_nearest.json` 是 `continuation_policy=nearest` 的 48 轮冻结输出；
- `global_submodular_walk.json` 是 `global_submodular=true` 的 72 轮冻结输出。

两个 JSON 都明确给出 `scope` 为抽象单调子模共同矩、完整任意历史纯 SPE、未声明客户正性，并把 `Q_CAG_HALF` 写成 `OPEN`。因此它们不是单位客户目录的完整反例，也不是六人半覆盖命题的证明。

## 2. 最近邻输出：48 轮、13 个锥

`full_history_walk_nearest.json` 的冻结字段为 `n=5,p=7,seed=9201773,rounds_requested=48,rounds_completed=48,distinct_full_tree_cones=13`，最佳精确可行比率为 `2`。最佳记录在 round 2，根计数为 `[0,0,5,0,0,0,0]`，目标掩码编号为 115，动作表有 2801 个非终端有序历史，抽象矩坐标的非零数为 119，且 `customer_realizability=not_claimed`。

每轮都记录 19,607 个有序比较；唯一 `gamma` 行数在 1,260 到 1,749 之间。48 轮中有 3 轮标记 `LP_exact_recovery=failed_or_not_solved`，所以最佳比率只来自其余成功恢复的有限抽象 LP 点。`SPE_outcomes` 的取值包含 1、3、5、6、7、11、17、31、81 和 161；这说明递归输出不是一个固定大小的策略空间，不能把某一轮的最佳值解释成所有策略的最差值。

`best_exact_feasible_ratio=2` 是对抽象目标矩坐标的比率，不是 `W/OPT` 的客户福利比率。最佳见证的 2801 个动作和 119 个矩值在 JSON 中完整保存，但没有客户类型正性实现，所以它不能直接变成单位客户目录。

## 3. 全子模输出：72 轮、15 个锥

`global_submodular_walk.json` 打开 `global_submodular=true`，保留 127 个非空七主题掩码坐标；冻结字段为 `rounds_requested=72,rounds_completed=72,distinct_full_tree_cones=15`，最佳精确可行比率为 `9/5`。最佳见证在 round 0，根计数 `[5,0,0,0,0,0,0]`，目标掩码编号 115，动作表同样有 2801 个非终端历史，矩坐标非零数为 127，客户正性仍为 `not_claimed`。

每轮仍有 19,607 个有序比较，唯一 `gamma` 行数在 1,260 到 1,758 之间，72 轮中有 1 轮标记 exact LP recovery 失败。`SPE_outcomes` 包含 1、5、6、7、10、11、12、21、26、31、81 和 266 等大小；全子模矩空间的最优可行点不是同一份计数状态或同一份目录客户的枚举。

与最近邻输出相比，全子模版本的坐标更多、锥数更多，但 `9/5` 仍是抽象矩目标的有限候选值。它没有构造六人目录、单位客户多重集或终局均分支付。

## 4. 与前一批相邻锥审计的比较

前一批 `full_history_walk.json` 36 轮摘要记录了 `best_exact_feasible_ratio=7/5`、`customer_realizability=not_claimed` 和 `Q_CAG_HALF=OPEN`。本批两个更大的冻结输出新增了最近邻 48 轮和全子模 72 轮的完整历史字段，但保留相同的证据分层：程序层检查完整有序历史和固定抽象策略锥，输入层是矩坐标，输出层是有限 LP 比率，客户模型层仍未实现。

同样要区分 R275 分数策略锥对象的 `p=7,n=5` 浮点 LP。那一对象以非负掩码权重和计数状态目标构造固定锥；这里则先生成公共子模矩向量，再将完整动作树的 IC 行接入矩坐标。两者都不允许从一个固定锥的有限正值推出所有纯 SPE 的安全桥。

## 5. 运行边界、缺口和接续

本批逐字段读取程序与两个大 JSON，并从冻结字段生成证据目录的 summary；没有在当前回合重新运行 48/72 轮浮点 walk，也不把旧 stdout 或摘要当作新运行。程序本身的可配置参数与 JSON 的 `continuation_policy`、`global_submodular`、`root_selection` 已保留，未来重放必须显式传入相同参数和依赖版本。

要把该对象升级为数学结论，至少还需：

1. 给出抽象矩向量到非负单位客户类型的显式实现，并验证所有坐标和每个完整历史的客户均分收益；
2. 保存每轮 LP 的有理行、对偶和恢复误差，而不是只保存 `exact_feasible_ratio`；
3. 证明随机重启所见锥覆盖了目标策略空间，或把结论严格限制在列出的 13/15 个锥；
4. 重新连接六人目标的量词、空主题/重复主题/任意平局和客户覆盖 OPT。

因此本批的准确处置是：两套更大规模完整历史抽象矩回归已经读清、保全并互相比较；它们提供有限候选和障碍线索，不能替代单位客户纯 SPE 证书，也不改变 `Q-CAG-HALF` 仍开放的状态。
