## 两份均匀质量脚本的实际行系统

两个脚本枚举

\[
(a,b,c,q,r)\in\{0,1\}^5,
\qquad(d,\ell)\in\{(0,0),(1,0),(1,2),(2,0),(2,2)\}.
\]

令 (s=a+b+c)。对整数背景 (p\ge0)，代码使用

\[
 \alpha=\frac a{p+s},\quad
 \beta=\frac b{p+s},\quad
 \gamma=\frac c{p+s},
\]

零分子按0处理，并定义

\[
 u(v;o_1,\ldots,o_t)=
 \begin{cases}\displaystyle\frac{v}{p+\sum_j o_j+v},&v=1,\\0,&v=0,\end{cases}
 \qquad D=(p+1+a)(p+2+a).
\]

每个状态产生七个列系数

\[
\begin{aligned}
R_1&=3\alpha-\frac{3q}{p+3},&
R_2&=3\alpha-\frac{3r}{p+3},\\
R_3&=2\gamma-\frac d{p+1+a+b},&
R_4&=2\gamma-\frac \ell{p+1+a+b},\\
R_5&=2\beta-\frac d{p+1+a}+\frac{d\ell}{2D},\\
R_6&=\alpha-u(c;q,r),&
R_7&=2u(r;c,q)-\frac d{p+1+c+q}.
\end{aligned}
\]

目标右端是

\[
 B=2\alpha+\mathbf1_{p+s>0}-\min(1,d).
\tag{UM2}
\]

在 (p=0) 直接加入一行；对 (p=1,2,3,4) 将整行和 (B) 乘

\[
 L_p=(p+1)(p+2)(p+3),
\]

随后对 (p=1,2,3,4) 的四个缩放行取从零阶到三阶的前向差分。分母清除后这些是关于 (p) 的至多三次多项式系数；因此脚本实际放入的是 (32\times5\) 个 (p=0) 行加 (32\times5\times4) 个差分行，共 **800 行**。它没有枚举客户、策略或完整历史，状态只由上述五个二值位和 ((d,\ell)) 给出。

第一次脚本寻找非负七维乘子 (lambda)，使每一行满足

\[
 \lambda\cdot R\le B.
\]

SciPy 只寻找浮点候选；本批将结果还原为 `Fraction`，再在原有理行上逐行计算余量。得到

\[
\lambda_{\rm UM2}=
\left(\frac{12}{215},\frac{48}{215},\frac{141}{215},
\frac5{86},\frac{10}{43},\frac{192}{215},\frac{24}{215}\right),
\]

800 行最小精确余量为0，全部余量非负。复现 stdout、JSON 和原件见证据目录。这里的“精确”只指这800行合同的有理代入，不能把它改写为所有真实CAG节点都存在相同列。

第二次脚本在每行末尾增加 (alpha) 列，并寻找

\[
 \lambda\cdot R+\kappa\alpha\le B,
 \qquad 0\le\kappa\le1,
\]

最大化 (kappa)。它返回

\[
\begin{aligned}
\lambda_{\rm UM2\kappa}&=\left(\frac8{411},\frac{32}{411},\frac{91}{137},
\frac{61}{822},\frac{122}{411},\frac{532}{411},\frac{16}{411}\right),\\
\kappa&=\frac{262}{411}.
\end{aligned}
\]

同样是800行、最小精确余量0、全部余量非负。`(kappa)` 是这套抽象列合同中 (alpha) 的可支付系数，不是任意玩家收益、客户质量或主问题福利常数。

前向差分只证明“清分母后的多项式在该差分基下各系数有非负乘子支配”；要迁移为数学对象，仍须给出每一列对应的真实行动、每个 (p) 的合法前缀和从列到客户支付的映射。本五源没有这些映射，所以本页把它作为固定有限合同证据，和已有真实末位支付恒等式分层保存。

## `three_price` 三份输出的边界

### `three_price_best.json`

该文件是一轮搜索器发现的当前最佳记录，不是搜索器源码。顶层为 `it=0`、`round=0`、`score=-0.0`，候选实际终局计数为

\[
 (0,2,0,1,0,0),
\]

根动作是3，`z=[0,1,0,0,0,0]`，`clones` 长度63且只有索引46的单位质量为1。保存的 `instance` 为3名玩家、6个主题、一个兴趣集 ({0,1,2,3,5}) 的单位客户；`certificate` 含43个有序历史动作及终局计数。文件因此有一个明确的有限候选身份和完整动作表，适合作为复现/接续输入。

它不包含生成器、收益重算器或独立验证日志。本批没有把 `certificate` 字段当作已重放的SPE证明，也没有从一个 JSON 候选推出任何普遍价格界。若后续要采用该候选，必须在同一客户模型下重新展开43个节点、258项含自身比较，并核对真实偏离后的完整后缀。

### `three_price_report.json`

报告明确把范围写为 `finite cone attack, no universal proof`，保存150个搜索迭代记录；每条记录的 `best` 都为 `-0.0`，最终 `best=-0.0`。这表示该有限搜索没有找到正的目标值，不能说明不存在正值，也不能说明模板或主模型的普遍安全性。搜索的随机种子、求解器设置和候选生成代码不在这份报告内，本批不虚称重放150轮。

### `three_price_template.json`

这是强模板程序的冻结输出。按 JSON 字段，

| (	au) | HiGHS 状态 | 输出的七维字符串 |
|---:|---|---|
| (1) | success | ((0,0,1,0,0,0,0)) |
| (3/2) | success | ((11/216,1/12,17/24,17/216,17/72,1/3,1/18)) |
| (2,3,4,6,10,30,100) | infeasible | 无 |

这些是浮点 LP 的运行状态和有界分母字符串，不是有理逐行证书；“infeasible”也只属于该有限模型和该次 HiGHS 调用。既有六源审查中的弱模板另有 (	au=2) 可行记录，不能把强/弱右端或向量混用。本增量因此将强输出按原字段保留，并已修正既有审查中把强模板的 (	au=2) 误写成可行的句子。

## 与现有数学对象的衔接

现有[完整终局推送的自身折扣与末两位储备](../资源/完整终局推送的自身折扣与末两位储备--资源.md)给出真实完整策略上的 (P_i,C_i,D_i) 恒等式以及早期债务缺口；本批 UM2 行没有真实策略映射，不能替代该恒等式。现有[三价模板与均匀质量证书的范围审查](三价模板与均匀质量证书的范围审查--审查.md)承载强/弱模板和三份 JSON 证书的原始身份；本页补充其尚未处置的脚本与三份输出，并保留两个对象的不同量词。

证书可作为后续“共同早期乘子锥”工作的固定抽象行样例：它展示了一个共享非负 (lambda) 和有理零余量的存在，但没有行到真实历史的映射、客户非负实现或完整SPE补全。`three_price` 候选与零差搜索也只提供有限实验边界。它们都不证明任意人数、任意共同目录、所有纯SPE的半覆盖，也不构成六人 Q-CAG-HALF-6 的反例。

## 可复现边界

增量证据目录保留五份源原件及两个脚本的实际 stdout/JSON。复现 UM2 两脚本需要 Python、NumPy、SciPy/HiGHS；本批执行各一次，均 `success=True`、最小精确余量0。强模板 JSON 是冻结输出，本批没有再跑其缺失的搜索器；`three_price_best/report` 也未重跑原发现器。若未来复现候选，必须另建隔离目录并记录依赖版本，不覆盖冻结输出。

本页的“完成”只表示五源的实际阅读、数学边界和独有内容去向已记录；开放的一般价格付款问题和六人半覆盖目标仍保持开放。
