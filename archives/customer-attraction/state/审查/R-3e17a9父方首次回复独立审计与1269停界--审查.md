# R-3e17a9 父方首位回复独立审计与 1269 行停界审查

## 1. 范围

FRONTIER.md 把问题固定为恰六名提供者、任意有限客户与共同目录、全部有序历史纯 SPE，Q-CAG-HALF 仍 OPEN。它记录同一剩余三人源上先强制 T 得到 (B,C)，再强制 B 得到 (D,E) 的首位回复推广；新增信息包括新的末位行、强 PAIR 行、共同末位价格和最大主题 K。源文同时声明：旧 1143 行沿用既有冻结生成器；父方审计独立重建新增 88 行和全部条件质量界，并不把该必要系统当作游戏策略。

本批五源分为两项 exact 审计：

* audit_promoted_follower.py/json：全部六人 membership coefficient states 的局部恒等式，外加冻结 3889-row 必要点的严格分离；
* audit_joint_promotion.py/json：对既有 1269 点独立重建新 88 行、38 个条件质量界，并复核旧 1143 行依赖。

## 2. 首位回复局部审计

audit_promoted_follower.py 不导入作者 discovery 代码。它对六个实际位、两个中间位和两个推广位的所有二元 membership 组合枚举：

    coefficient_states = 1024
    projected_states = 256

每个状态直接以 Fraction 计算 H、r、v 和 raw_without_K，并断言：

    35r + 22v − H = raw_without_K.

随后读取冻结旧输入 attractive_nested_exact.json（该输入属于 R-c4f1…/six_astra），在 23 个正质量 histogram terms 上汇总，形成共同的六人左/右比较。exact JSON 和父审计都给出同一冻结点 SHA；输出状态为 EXACT_LOCAL_IDENTITY_AND_SPECIFIED_POINT_SEPARATION，target_status=OPEN。

精确量为：

    lhs = 798702964492060907464900002268748739 /
          21722188083558433386371840226644560
    rhs = 434315048811318573228172128726166319 /
          10861094041779216693185920113322280
    lhs − rhs
      = −69927133130576238991444255183583899 /
        21722188083558433386371840226644560 < 0.

归一化到源使用的 /74 后为同分子、分母 1607441918183324070591516176771697440，约 −0.0435021。这个负 slack 严格分离指定的 3889-row necessary point；它不提供客户重数、完整历史动作、终局福利或 SPE 实现。

## 3. 1269 行联合必要系统的父审计

audit_joint_promotion.py 读取既有 promotion_joint_atoms_exact.json，先从 29 个 R/Z atoms 重建各 histogram mass，再将每个正质量组的 DE 菜单状态耦合。它独立计算：

* 新 promotion raw rows：88；
* 条件 DE 质量界：38；
* 旧 raw rows：1143，明确作为旧实现复用，不冒称独立重构；
* 总必要系统行数：1269。

对每个 histogram，代码验证所有 DE 状态质量非负且总和为该组质量，默认 (0,0) 质量由余量补齐；对每个新行以 Fraction 计算全部正质量 histogram 和非零 hist word。JSON/脚本一致报告：

    status = EXACT_FEASIBLE_SPECIFIED_NECESSARY_SYSTEM_NOT_SPE
    target_status = OPEN
    RZ_atoms = 29
    positive_nonzero_DE_states = 21
    old_raw_rows_reused = 1143
    new_raw_rows_independently_rebuilt = 88
    conditional_mass_bounds = 38
    total_rows = 1269
    minimum_old_slack = 0
    minimum_new_slack = 0
    minimum_unassigned_00_mass = 0
    O = 1

共同点福利为：

    W =
    62639914980892951648306747072697141151134151554374880507144 /
    126208720217724762225533804965567209821942870207757303886307
      ≈ 0.4963200234724811,

并且 1−2W 为严格正分数。代码说明，各正质量 histogram 的 R/Z 分布与 DE 条件菜单可以取条件乘积，保持列出边际和所有行；这只证明一个共同客户 membership 分布可实现，仍不等于某份完整历史 SPE 策略。

## 4. 与本批首位推广对象的边界

本对象补充上一页 R-3e17a9 推广首位回复与联合原子松弛审查：

* 上一页解释作者 early_reply_promotion_exact.json 的 2,560 个局部 identity checks 和指定 lifted point 的负 slack；
* 本页给出父方独立 Fraction 重建，确认 1,024 个系数状态、256 个投影状态，以及新 88 行和 38 个质量界的 exact 验证；
* 两页都保留 1269 点的 necessary-system 语义，不把 W<1/2 松弛点冒称整数客户或 SPE。

4095e0… 的巨型 JSON 已在“根回复支撑入口与全比较覆盖交换点的输入边界”对象中保留原字段和来源 SHA；本页不复制 29 个 atoms 的全部隐藏位，而只核其计数、质量和行层级。R915、R23 等其他 promotion 路线的有限 separation 也不与本页的 1024/1269 量词混合。

## 5. 前沿、障碍和后续

**已确认。** 首位回复行在六人 membership 域的局部恒等式完整通过；冻结必要点被严格分离；新增 88 行、38 质量界和既有 1143 行在指定 16 histogram 上形成 exact W≈0.49632 的共同必要系统点；全部最小行 slack 可为 0。

**障碍。** 1269 行点没有完整历史行动映射、终局客户类型、每个偏离的真实后继或 SPE 收益。因此即使其 W<1/2，也不能作为 Q-CAG-HALF 反例。负局部分离只排除指定旧点和给定行集合，不能证明所有 promotion 系统不可能。

**下一项义务。** 将父审计通式用于实际第三位的完整三人尾，保留不同源的主题身份和共同 u3/u4/u6 预算，并把所有隐藏位先联立后消元。只有在输出整数客户输入、全部有序历史策略和 exact IC 证据后，才能把必要系统低点升级为原模型对象；当前六人一般目标仍 OPEN。


## 6. Verify 源的独立重放范围

verify_early_reply_promotion.py 不调用作者 LP 或 branch projection；它逐字面枚举 p=0..9、五个二元位和 π∈{0,1/7,1/6,1/5,1/4,1/3,1/2,1}，共 2,560 个局部公式恒等式，断言 literal + hval = 0。随后从同一冻结 nested 输入重算 six-player point，必须与 early_reply_promotion.json 的 exact slack/point SHA 一致。它验证的是局部公式和指定点分离，不提供新的客户或 SPE。

promotion_joint_atoms_verify.py 是不导入作者新实现的 exact replay：旧 1,143 行复用冻结 old generator，新 88 行由标记 query/pair 定义逐字展开；它独立检查 38 个条件质量界的余量、所有 16 histogram、29 个 R/Z atom 和 21 个正 promotion state。对应 JSON 的字段为：

    old_rows=1143, new_rows=88, state_mass_bounds=38,
    total_rows=1269, literal_new_state_cases=59,
    minimum_slack=0, O=1, W<1/2.

其 status 明确是 exact feasible necessary point verified; no game/SPE or half theorem。因而这份 verify JSON 是前述 parent audit 的独立重放边界，不是第二份客户福利证据。

## 7. 实际第三位再查询的有限停界

third_requery_old_early.py 把旧实际第四位分支的 B_i 前移到实际第三位，保留真实 D/E/F 三人尾；对 153 个行族、每个固定 histogram/word 的 8 个 XYZ 配置建立 200×178 的必要系统。它对所有 hidden bits 保留 source、first、last、newpair、newthree、oldC、oldpair、price、capacity 和 actualpair 行，使用 SciPy LP 仅作发现；浮点输出不被当作结论。

冻结 third_requery_old_early_separation.json 报告：

    rows = 153
    shape = [200, 178]
    status = HiGHS optimal
    slack_float = −0.00392247693159746.

它随后以 Fraction 恢复一个 exact 负 slack：

    exact_slack =
    −3010403876006047472114228536208315664715837402292544582238769 /
    767475227643984279093471067995614202927234593733372164932632867 < 0.

非零候选权集中在 source、newpair(C,a5)、price(D,5)、price(E,5)、capacity(F) 等行；JSON 同时保留所有精确权重。该 separation 只排除指定的“第三位重查询 + 旧前四位背景”必要点，仍不是整数客户输入、完整有序历史策略或 half 反例。

FRONTIER.md 将下一义务说明为把第三位通式用于完整三人尾，保留不同来源的主题身份和共同 u3/u4/u6 预算；新的联合系统尚未闭合。此前 1269 点证据应保持冻结，不能因第三位负 separation 就把主问题宣称完成。

## 8. 十源合并结论

本页现在覆盖父方五源与 verify/third_requery 五源，共十个独立 ID。独有去向如下：

* 父方两份 audit 程序/JSON：重建 88 行、38 质量界和 1024/256 局部状态，确认 1269 必要系统低点；
* verify 两源：排除作者实现复用误读，逐字重算 2,560 局部恒等式和 59 个新增状态案例；
* third_requery 两源：给出实际第三位前移的 153 行、200×178 系统和 exact 负 separation；
* FRONTIER：记录恰六人 OPEN 状态、下一义务和各有限对象的量词边界。

所有低点和负 separation 都停留在 necessary-system / fixed-point 层级。只有同时给出整数客户重数、完整动作映射、每个有序历史偏离后继和 exact SPE 收益，才可能把它们升级为原模型对象；当前 Q-CAG-HALF 仍 OPEN。
