# 2. 三人 36 客户小见证：\(W<3\theta_3\) 的完整有限复核

普通与认证 JSON 都声明 `claim=CA-AGGREGATE-LAST-FLOOR-NO`、`all_exact_checks_passed=true`、`half_coverage_refuted=false`。共同 witness 为：3 位提供者、6 个主题、36 个单位客户，43 个有序决策历史、258 个动作比较，根终局 `[0,3,4]`，实际收益 `(10,12,12)`，福利 `W=34`，最优覆盖 `OPT=36`，末位最坏回复值 `theta=12`。

因此
\[
W=34<36=3\theta_3,
\qquad 2W-\operatorname{OPT}_3=32>0.
\]
这正是“把末两位的最坏末位保底无损相加”桥的反例；它仍严格满足 half 覆盖。终局 payoff table 还保留了 `(0,0,0)=(7,7,7)`、`(0,0,1)=(9,9,15)`、`(0,0,3)=(25/3,25/3,37/3)`、`(0,1,2)=(12,12,12)` 等代表行，故不只记录在轨路径。

`partition_family_regressions` 的三条记录分别为 n=3/4/5、主题 6/8/10，受限历史/比较为 (37,156)、(401,2080)、(5861,36100)，`fresh_theta=1`、`signed_root_sum=2/3/4`。文件明确写出这是 signed algebra 与 no-repeat policy 的 regression，**不是独立合法输入**；不能把这三条回归当作“每个 n 的原模型证书”。每个 n 的一般合法构造由既有正编译正文承担，三人 36 客户则是本批完整小见证。

认证版还给出 `optimizer_dependency=false`、Python 3.12.14、审计脚本/实例/证书 SHA 和唯一 replay command `python3 tests/audits/customer_attraction_aggregate_theta.py`。这些字段证明来源链和复现入口，不改变 witness 的数学量词。

# 3. 12 主题上传大实例：逐人 theta 失败但 half 保持

上传 JSON 声明 scope 为“一份保存的完整 history-dependent SPE 与有限实现交叉核对”，`universal_half_coverage_proved=false`、`half_coverage_refuted=false`、无外部 review/novelty claim。参数为 4 位提供者、12 个主题、4,095 个非空兴趣 mask、26,171,145 个单位客户；每种类型重数至少 1、最多 15,091，Möbius 对称偏置为 6,391。

完整树层面：1,885 个有序历史；保存策略重放含 22,620 个（含指定动作）比较、20,735 个真实替代动作；最小严格激励差为 1，含指定动作平局计数 6,440。根 12 个行动的第一位收益依次为：标签 0–3 为 6,135,344，4–7 为 6,135,342，8–11 为 6,135,345；保存根动作 8 的终局为 `(8,4,5,0)`。

末位最坏静态值与福利字段为
\[
\theta=6{,}135{,}346,\quad
u=(6{,}135{,}345,6{,}135{,}380,6{,}135{,}380,6{,}135{,}371),
\]
\[
W=24{,}541{,}476,\qquad
\operatorname{OPT}_4=24{,}541{,}532,qquad
2W-\operatorname{OPT}_4=24{,}541{,}420>0.
\]
第一位恰有 \(u_1=\theta-1\)，所以该实例否定“每位提供者收益至少 theta”的逐人桥；而 half margin 极大，不能把逐人失败升级为福利反例。完整终局计数为 1,365 个，唯一最优计数向量为每个主题 0–3 各一次；`theta_prefix_count=364`、`theta_minimizer_count=4` 记录末位背景穷举的精确范围。

`saved_policy_replay` 保存了所有根行动的 continuation terminal 与 root utility，且 saved path utilities 为 `(6135345,6135380,6135380,6135371)`。这一步很关键：根行动比较使用真实保存策略的完整续局，不把“根改行动后仍沿原路径”当成一个冻结游戏。上传 JSON 另给 `uploaded_root_spe_terminal_count=97`，表示上传报告中的根 SPE 终局计数；不能将它与 1,365 个静态终局配置混称。

`tiny_independent_crosschecks` 记录 209 个小实例、14,094 个完整策略映射、1,350 个 accepted policy maps、1,793 个 uploaded canonical prefix sets；比较器包括 direct unit-clone full ordered-policy enumeration、uploaded NumPy integer Game、canonical Fraction ExactSPESolver 和 audit search exact_outcomes with integer LCM scaling。输入覆盖每个 n=1,2,3 的 27 个二主题 multiplicity 0/1/2 案例及 n=2 的 128 个三主题 presence/absence 案例。
