## 2. 三个指定源各自承载什么

### 2.1 `audit_padded_residual_dag.py`：有限六人完整历史审计

我实际读取了预取的 5740B 源码。其 docstring 明确声明“独立定义级审计”、不导入 canonical solver/verifier，使用 `fractions.Fraction` 和 `itertools.combinations`，默认输入是同级上层 `direct_global/padded_residual_m6_dag.json`。源码的 `check(path)` 先读原始 JSON，再由 `instance.customers` 的主题集合与重数展开 30 名单位客户；`payoff(a,c)` 对每个喜欢主题 (a) 的客户按终局负载求精确分数。相邻冻结正文 `security_global/padded_residual_m6_review.md`（本地保全 ID `61534f23b5e3d32cbef6`）说明了该程序的数学职责。源码实际执行的检查合同包括：

- 每个节点的前缀计数和六槽终局目标都是合法非负向量；
- 每个决策节点拥有九个观察动作孩子，行动 \(a\) 的孩子前缀恰为父前缀加 \(e_a\)；
- 规定行动孩子的目标等于父目标，叶节点前缀等于目标；
- 用父节点目标计算规定收益，并与九个孩子目标下的真实收益逐项比较；
- 全部节点从根可达，深度 (d) 的有序历史质量为 (9^d)。

源码随后沿根的规定动作重放实际路径，枚举所有至多六个主题的组合求 \(OPT\)，计算遗漏主题 \(T\) 的冻结查询 \(Fquery\)，并以 \(\alpha=5/6\) 计算 \(G\)、九个 \(g\) 值；还固定合法背景 \((P_0,P_1,P_2,P_3,D)\) 给出一个静态安全值上界。最后把 source_sha256 写入报告并断言 \(Fquery > W + \min(pay)\)。它支持的是一个保存 DAG 的完整历史 SPE 和若干静态代数，不是一般人数证明。

历史 review 自报的有限输出是 5440 节点（2437 决策、3003 叶）、21933 项含自身比较（14160 严格、7773 平局）、66430 个非终端有序历史和 531441 个六步叶。旧 review 同时把旧候选中的 `OPT=30` 更正为 `OPT_6=26`：30 是客户总数，六个主题的最优并集只能达到 26。目标路径为

\[
(P_0,P_1,P_2,P_3,A,B),\qquad u=(4,4,4,4,4,5),\quad W=25.
\]

路径遗漏主题 \(T\) 的五名客户；把每位角色的实际终局动作分别冻结为 \(T\) 得到 \(F(T)=30\)，而 \(W+\min_i u_i=29\)，所以被否定的是辅助桥

\[
F(T)\le W+\min_i u_i.
\tag{CQ-min}
\]

这只是一个六人、九主题、30 单位客户的有限完整-SPE 实例。它的半覆盖余量为 \(2W-\operatorname{OPT}_6=24\)，所以不是六人 half 反例；同样也没有由该失败推出真正静态混合安全值或一般精确税桥失败。

我没有运行该源码的原输入：`direct_global/padded_residual_m6_dag.json` 不在当前 clone 或 `tmp/claimed/`，直接运行默认入口实际以 `FileNotFoundError` 失败。因此上面的节点、严格/平局计数虽然随后由精确 JSON sidecar 逐字段读到，但本轮仍不能把它们说成重新运行旧 DAG 的结果，也不能把旧的 14160/7773 倒填到后来的新 DAG。

### 2.2 `audit_pair_common_query.py`：两人代数的有限 membership 回归

相邻冻结正文 `pair_common_query.md`（本地保全 ID `171d1eb9926a6dce681d`）给出真正承重的解析命题。固定任意非负背景 (b_x)，恰剩两位单位提供者，原完整纯 SPE 的行动为 (A,B)，并令

\[
q_b(U,V)=\sum_{x\in U}\frac1{b_x+1+\mathbf 1_{x\in V}},\quad
a=q_b(A,B),\quad d=q_b(B,A).
\]

冻结另一个人的实际终局动作后，对任意共同查询主题 \(T\) 定义

\[
F_b(T)=q_b(T,A)+q_b(T,B),\qquad R=a+d.
\]

逐客户 membership 代数给出

\[
q_b(T,A)+q_b(T,B)\le2q_b(T,D)+q_b(D,A),\tag{P1}
\]
\[
q_b(T,B)-q_b(T,A)\le q_b(A,B).\tag{P2}
\]

令 \(D\) 为第一位强制改选 \(T\) 后、原完整策略在真实离轨历史给第二位的回复；第一位 SPE 最优性及末位最佳回应给出 \(q_b(T,D)\le a\)、\(q_b(D,A)\le d\)、\(q_b(T,A)\le d\)。代入两式并取较小者，得到对每个合法 \(T\) 的普遍二人结论

\[
\boxed{F_b(T)\le R+\min(a,d)}.
\tag{pair}
\]

它允许任意非负实背景、任意历史依赖平局和空/重复主题；非零背景时 \(R\) 是两位剩余者收益，通常不是完整根福利。audit_pair_common_query.py 只有 587B，按 README 说明是独立 Fraction membership 核验，不是求解器、SPE 枚举或一般人数证明；原 blob 曾不在 clone，后来由 tmp/claimed/ 预取并核 hash 后读取。

我随后直接运行预取的 python tmp/claimed/audit_pair_common_query.py，实际输出为 {'pointwise_checks': 160, 'status': 'pass', 'scope': 'finite exact membership audit; universal proof in Markdown'}。一次替代标准库程序 check_static_query_and_optimizer.py 也实际通过，核了 \(b=0,\frac12,1,2,10^{40}\) 下 P1 的 80 行和 P2 的 40 行 membership，并另核中央删除预算等有限身份；它明确记录 original_entries=0、LP_MILP_calls=0、new_SPE_checks=0。这些都是有限回归，不替代 (P1)、(P2) 对任意实 \(b\) 的解析证明。

## 4. 量词、模型身份和后续纠错

### 4.1 六人九主题实例的精确范围

共同目录模型是：有限单位客户、有限非空主题目录、\(m\) 名单位提供者按固定顺序观察全部有序历史各选一次；最终客户在覆盖者间均分；纯策略可以依赖完整有序历史，完整纯 SPE 在每个合法离轨节点满足真实单步偏离不等式。压缩的客户重数只用于收益计算，不能把策略误写成计数 Markov 策略。

九主题实例的单位客户类型为 \(AD:2, AE:2, B:3, T:3, BDE:2, TDE:2\)，以及各含 4 名私有客户的 \(P_0,\ldots,P_3\)。目标路径的 30 名客户中 25 名被覆盖；四个私块加 \(B,T\) 可覆盖 26，证明 \(\operatorname{OPT}_6=26\)。这说明 CQ-min 失败与当前六人 half 目标是不同命题：前者差 1，后者仍有 24 的半覆盖余量。

### 4.2 私有四客户族的全历史 floor 不能替代路径证书

后续 私有四客户填充族的全历史收益下界--引理.md 对固定核心加任意 \(k\) 个四客户私块证明每个合法历史、每份 SPE 的当前人收益至少 4，从而 \(W\ge4m\)。它明确没有证明固定路径 \(P_0,\ldots,P_{k-1},A,B\) 对每个 \(k\) 都能完成；只有 \(k=4,m=6\) 的有限 DAG 证书给出该路径。不能把这一解析 floor 当作缺失审计程序的替代。

### 4.3 17 主题共享索引族不是九主题完整 SPE

README 还讨论了 \((m-1)\) 个共享索引的 \((3m-1)\) 主题族。其 \(m=6\) 版本同样有 30 名客户、\(W=25\)、静态 \(F(T)=30\)，但目录是 17 主题，只有静态代数和背景上界，`SPE_claim=false`；九主题 DAG 不能认证它。后续静态核对给该族 \(v_6\le10/3\)，而九主题合法不观察背景给 \(v_6\le4\)。两者数字相似不代表策略、回复或 SPE 证书相同。

### 4.4 分数桥的后来反例改写了 README 的“未证”状态

早期 `security_global/README.md` 把精确分数税桥

\[
m\max_T g_{\alpha}(T)\le W+G_{\alpha},\qquad \alpha=(m-1)/m
\]

列为未证候选，并正确警告九主题 CQ-min 失败不能直接否定它。后续完整十三人自动机和精确算术已经改变全仓状态：

\[
W=33,\quad M=3,\quad G=708669/123025,\quad 13M-W-G=29481/123025>0.
\]

因此该分数桥的全称版本已被独立完整证书否定；这不是本三源审计的新运行，也不把九主题六人实例升级为十三人反例。真正静态混合安全值的聚合上界和恰六人 half 仍是不同问题，均不能从这些辅助桥的成败直接推出。

## 6. 未解决缺口和可安全复用的结论

仍未解决的缺口是：

1. 三个源 blob 在当前 clone 中因 promisor fetch 失败；哈希核对的临时副本现已可读，但旧 DAG 输入文件本身仍不可得。没有旧 DAG 证书的原命令重放和旧 SHA 对比；若未来恢复输入，必须重新执行 clean show/审计。
2. 旧报告的 14160 严格和 7773 平局计数现在已从哈希核对的 1433B JSON 逐字段读取，但没有旧 DAG 输入可供程序重放；新 Root DAG 没有这些字段，不能把新运行的 19496 non-self 比较或新文件 SHA 反写为旧报告字段。
3. 一般 \(m\) 的指定路径存在性、真正静态安全值聚合、以及恰六人 \(2W\ge\operatorname{OPT}_6\) 仍不由本页关闭。私块收益 floor、两人共同查询引理和九主题辅助桥反例各自有不同量词。
4. 历史 README 中的浮点随机/策略锥阴性扫描（例如随机五人七主题 1000/5000 次及有限 policy iteration）只是有限探索；本页没有取得或重跑其原 JSON，也没有把“未见 separator”写成普遍证明。

可安全复用的结论是：二人任意非负实背景的 pair 预算 (pair)；九主题六人实例对 CQ-min 的有限完整反例（由新定义级重构重新确认）；以及后续十三人完整证书对精确分数桥全称版本的否定。每一项都应保留其模型、历史量词和证据来源，不跨模型迁移。
