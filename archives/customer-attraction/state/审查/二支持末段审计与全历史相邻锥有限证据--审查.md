# 二支持末段审计与全历史相邻锥有限证据

## 结论先行

这三个冻结源属于两个不同层次。

* `terminal_pair/audit.py` 是逐客户成员关系的 Fraction 代数审计器，配套 JSON 报告 `exact_audit_passed`。它对明确的有限参数网格重建三条末两人 SPE 比较、四块系数恒等式、凸合与正行列式；其全参数意义来自代码所核对的符号恒等式与正分子，而不是来自 1603 个参数点的归纳。它支撑已有“实际只出现两个不同覆盖且末两位为 A、B 时严格二以下”的解析定理，不扩大该定理的结构假设。
* `tree_coupling/round2/full_history_walk.json` 是全历史相邻策略锥的一次有限搜索输出。其抽象对象是五名玩家、七个主题上的共同 Shapley 矩向量，策略要求在每个有序历史满足纯 SPE；输出的最佳精确可行比为 (7/5)。输出明示 `customer_realizability: not_claimed`，范围明示“截断单调次模共同矩、完整任意历史纯 SPE；无客户正性声明”，并保留 `Q_CAG_HALF: OPEN`。
* 因而本对象不能声称发现原客户模型的反例，也不能声称证明普适 SPE、普适 half 或全域共同次模上界。它只交付可复核的有限审计与有限 walk 证据。

三份原件在冻结提交 `68fad804ec5946cb296f77dc5b336308a66abf12`（legacy-cleanup）与 `aefc58eac3fc6eb5d7a47d087dd2c62b5aa9974c`（main）同路径保存。由于本轮命令行 promisor fetch 受 `browser-proxy:8889` 不可达影响，全文使用 `aefc58eac3fc6eb5d7a47d087dd2c62b5aa9974c` 的只读 raw 页面读取；原件指纹、逐轮摘要及逐字复制的审计程序/JSON保存在[证据目录](../../tools/evidence/terminal-pair-and-full-history-walk-primary/)。其中大 JSON 不被压缩摘要冒充原文：摘要明确写出原字节数与 SHA，并保留顶层合同、全部36轮记录和最佳见证概要。

## 二、`terminal_pair/audit.py`：程序、输入、输出和可推导结论

### 2.1 输入域与逐客户恒等式

程序没有读取客户文件或规范求解器。`check(k,l)` 令 (m=k+l)，并遍历

[
(k,l)in{1,ldots,40}^2cup{(1,10000),(10000,1),(127,991)},
]

共 (1603) 个频次对。每个频次对又遍历 (a,b,t,rin{0,1}) 的 (16) 个成员状态，总计 (1603	imes16=25648) 次逐客户检查。这里 (a,b) 表示该客户是否在实际末两覆盖 (A,B)，(t,r) 表示比较主题与真实离轨末回复的成员关系；不是客户数量，也不是一个完整策略的编码。

程序设
[
 p=(k-1)a+(l-1)b,qquad u(x,y)=\frac{x}{p+1+y},
]
并取实际两末位收益 (u_A=u(a,b))、(u_B=u(b,a))。三条 SPE 差值为
[
 s_1=u(a,b)-u(t,r),quad
 s_2=u(r,t)-u(b,t),quad
 s_3=u(b,a)-u(r,a).
]
同时定义
[
 R=\frac{a(1-r)}{(p+1)(p+2)}.
]
根据 (a,b,t,r) 的分支，程序构造比较主题权重 `t_weight` 与常数 `constant`，并断言
[
 \texttt{constant}-\texttt{t\_weight}=s_1+s_2+s_3+R,qquad R\ge0.
]
它还独立用末位前背景 (ka+(l-1)b) 重建最后查询值，断言与四块分支权重完全相同。这个第二重断言检查了“实际末位前”与“实际末两位前”分母没有被混淆。

### 2.2 凸合与严格性

每个 (k,l) 完成成员循环后，程序定义
[
 X=\frac{l(k+2)-1}{k(k+1)},quad Y=\frac{k-1}{l},quad
 Z=\frac{k+2}{k+1},quad V=\frac{l+2}{l+1},
]
并计算
[
 \det=ZV-XY
 =\frac{l(k+2)(k+l+1)+(k-1)(l+1)}{kl(k+1)(l+1)}.
]
程序断言该闭式恒等式、
[
 \lambda=\frac{Y+Z}{X+Y+Z+V}in(0,1),qquad
 \delta=\frac{ZV-XY}{X+Y+Z+V}>0,
]
以及两组块系数在 (lambda) 与 (1-lambda) 的凸合后都等于 (gamma=2-delta)。另外四个断言把 (P,L) 两组系数恢复为原始单主题权重，防止只检验一个已简化的输出常数。程序最后以 `F(0)==sum(F(0) for _ in range(4))` 记录零人口边界。

这解释了为何 JSON 中的有限结果能给出 `status: exact_audit_passed`，但仍不能把“1603个频次点”说成普遍证明。普遍 (delta>0) 由上式的正分子（(l(k+2)(k+l+1)>0) 且第二项非负）直接推出；程序是对该解析恒等式和边界分支的有限机械核验。

## 三、`full_history_walk`：程序合同与运行输出

### 3.1 程序实际做什么

为理解 JSON，全文读取了同目录的 `full_history_walk.py`（该程序不是本批认领源，但决定输出语义）。程序建立 (n) 名玩家、(p) 个主题的计数终局，默认 (n=5,p=7)。`moment_order=p` 仅在 `--global-submodular` 时启用；否则取 (n)，因此当前输出的 `scope`“truncated”表示只保留至五阶的共同矩，而不是七阶全局集合函数。

它用 `ExactSPESolver(template)` 生成每个计数前缀可实现的**全部纯 SPE 终局集合**，再以抽象共同 Shapley 矩 (c) 计算每个终局的玩家收益表。每个非最小可信续局（源码选项 `nearest`/`highest`）都要满足偏离者收益不超过当前动作收益；最终 `actions` 覆盖全部有序历史 (h)，数量应为
[
sum_{j=0}^{4}7^j=2801.
]
程序逐节点逐行动检查 SPE 差值，并收集行向量 (Gamma)，输出 `ordered_comparisons=19607=2801\times7`。在每轮中，它先调用 SciPy `linprog` 做浮点 LP，再把结果按分母上限 (10^8) 恢复为 `Fraction`，随后用 Fraction 重新检查非负性、根归一化和所有 (Gamma) 行。第二次随机目标探索同一最优面后，候选矩会作为下一轮步行状态；周期性重启用随机次模容量函数。

该程序与客户吸引模型的接口在这里被有意切断：`Instance` 只提供计数/历史验证，矩量 (c) 没有转换成非负单位客户质量的步骤。源码 docstring 与输出 `customer_realizability` 均明确这一点。

### 3.3 运行身份缺口

当前 `full_history_walk.py` 的写出代码会把 `continuation_policy`、`global_submodular` 和 `root_selection` 写入报告；冻结 `full_history_walk.json` 的顶层实际没有这三个字段。README 又把初始 JSON 描述为“random-minimal continuation search”，而该输出出现多个 `SPE_outcomes`（例如161、266、35），与“每轮只保最小续局”的字面描述不能直接等同。故本对象只采用 JSON 自身可见的 `scope`、轮数、比值、历史计数和 `Q_CAG_HALF` 字段；不从缺失的 invocation metadata 猜测 `--continuations`、`--global-submodular` 或 `--root-selection`，也不把当前源码版本反写成这份输出的运行命令。

这一不一致不改变有限输出的数值记录，却限制了可复现性：没有完整命令行、依赖包版本、输入实例和输出写入时点，不能把该 JSON 认证为当前源码的一次可重放运行。证据摘要保留这个缺口。

## 五、证据缺口、可接续工作与最终处置

* `audit.py` 与 `audit.json` 的原件已逐字保全并用源 SHA 自检。本轮在全新本地临时路径实际重放一次：exit 0、stderr 为空，stdout 与新输出文件相同，且新输出与冻结 `audit.json` 逐字相同；运行元数据保存在[重放记录](../../tools/evidence/terminal-pair-and-full-history-walk-primary/terminal_pair_replay_metadata.json)。这只确认脚本实现和冻结报告的有限字节一致，不把它扩大为新的普遍定理。
* `full_history_walk.json` 已全文解析；本地保全是结构摘要而非317,303字节原文副本，源 SHA/大小和逐轮数据已保留。若恢复 Git fetch，应以冻结 blob 重新导出全文，与摘要逐字段核对，不能从摘要反向生成“原件”。
* full-history walk 的候选矩首先来自浮点 LP，再经有限分母的 Fraction 恢复和逐行检查；这能认证已接受候选在该行集上的有理可行性，不能认证 SciPy 搜索没有漏掉其它 LP 顶点或相邻锥。
* 36轮、一个 seed、有限重启、缺失 invocation metadata 的输出既不是全锥穷举，也不是“全局次模”搜索；要研究全域 (p=7) 的共同集合函数，须另行取得带 `--global-submodular` 的输出与完整命令绑定。
* 抽象矩到真实客户的非负整数/有理质量表示尚未给出；因此不产生原客户模型反例、不否定已证五人结论、不证明六人 half，也不把 (7/5) 解释成任何单位客户福利比。

本审查对象的准确状态是：`terminal_pair` 的程序/输出为“有限代数审计通过，支持既有结构定理”；`full_history_walk` 的程序/输出为“有限相邻锥 walk 中发现抽象有理候选，最大记录7/5，仍 OPEN”；三源均不提供普适 SPE 或 half 证明。后续可将证据摘要交给第三阶段关系审查，但必须沿用上述量词、模型和运行缺口。
