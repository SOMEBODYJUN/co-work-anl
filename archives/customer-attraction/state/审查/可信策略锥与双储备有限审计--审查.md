# 来源与程序语义

完整读取 `e5326aa2a4308ffcdde7`：冻结路径为
`research/workspaces/customer-attraction/R-171cd7d518434f36a48cd50df29c9303/credible/policy_walk.py`，字节 SHA-256 为
`23e57905524f77627f8de06c6c1f64d0e6d71c51d37d3cab602ee26774914105`。脚本的默认探针在 `p=7,m=5` 上以 `steps=20` 迭代：先由 `ExactSPESolver` 生成有限实例的 SPE outcomes，再用 `credible_cone` 构造候选策略锥；LP 只提出 multiplicity 点，随后 `integer_clones` 转成整数客户重数，并以 `StrategyCertificate`/`verify_certificate` 做完整历史精确接受。脚本自身明确没有把 count-Markov 选择器当作覆盖全部 SPE 策略。

程序可切换随机重启、低福利筛选、回复种子和不同模式；这些选项改变有限探针的输入，不改变其证据等级。它没有将浮点 LP 的可行性直接当作数学证明。

# 处置与边界

这些来源的独有内容是“LP 候选 → 整数重数 → 全历史精确验证”的可复现有限工作流，以及双储备族的保存输出。它们支持候选机制和有限实例比较，但不证明所有可信策略锥、所有完整 SPE、一般人数、全局效率上界或六人半覆盖。没有构造低福利完整 SPE，也没有证明 `Q-CAG-HALF`。后续若把某一有限行提升为正式定理，必须另给全称数学证明并保留真实历史量词；不能把随机重启数量、未命中次数或浮点 LP 目标当作数学证据。
