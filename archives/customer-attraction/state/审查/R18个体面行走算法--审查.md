# 来源与运行合同

主源 `1fdfd29b852ce1924989` 是 4,916 字节的 Python 探索脚本，冻结 SHA-256 为 `4ee1f541fbe2f3ca7a3ee16faf9a63ea1851d1a9adf9138554861ef83e89bbcc`。它导入 `counterexample_search/cone_walk.py` 的 `Engine`、`baseline` 和 `verify_canonical`，后者再调用有限客户目录的精确纯 SPE 模型。依赖副本和哈希保存在证据目录；依赖不是本条来源的新增语义。

脚本命题范围是一个完整有序历史上的纯 SPE 策略和一个指定玩家动作 `a`。它探测单人效用 `u` 与实例最优覆盖福利 `OPT` 的比值 `OPT/u` 是否至少达到 `2n−1`。这只是一个桥接候选，不能替换六人完整历史半覆盖命题的量词。

# 浮点提案、面行走与精确恢复

给定玩家数 `n`、主题数 `p` 和客户权重向量 `r`，`Engine.solve` 计算所有终局计数的客户收益、福利及纯 SPE 递归可行集合；它选择最低福利的根终局。`Engine.strategy` 从该根终局向全部偏离历史递归，生成一个有序全历史策略和约束矩阵 `G`。脚本随后对两个客户主题组合 `J` 解浮点 LP：目标最大化 `v_J·x`，约束是 `Gx≥0`，并以目标终局福利归一化 `w·x=1`。

浮点 LP 只负责提出候选面点。`recover` 根据支持集、活跃行和有理高斯消元恢复整数客户重数，并逐行检查 `G` 的非负性；`verify_canonical` 再用完整策略证书核验每个有序历史的纯 SPE 合法性。只有恢复和核验都通过，脚本才写入 `*_best.json`。因此“exact”指候选点后的有限整数/证书核验，不指对所有输入或所有策略的穷尽。

# 30 步重放

在隔离目录运行：

```text
PYTHONPATH=archives/customer-attraction/tools/evidence/R18-global-walk-agent \
python3 individual_face_walk.py --players 5 --topics 7 --steps 30 --seed 68111
```

程序退出码为 0。第 0 步就得到当前精确最好值 `OPT/u=9`；阈值 `2n−1=9`，所以是等号而非桥反例。保存实例有 `n=5,p=7`、终局计数 `(5,0,0,0,0,0,0)`、动作 `a=0`、该动作效用 `u=1`、终局福利 `W=5`、实例最优福利 `OPT=9`。完整全历史策略证书在 `individual_face_walk_n5p7_best.json`，30 步记录在 `individual_face_walk_n5p7_run.json`；`G` 行数在首个记录为 1,260。

重放还记录了后续有限面行走的候选记录，但没有出现 `OPT/u>9` 的已核验点，也没有执行超过 30 步的全量搜索。浮点提案中的未恢复点不会被当作证书；本次输出没有声称随机种子对其他种子具有代表性。

# 可复用边界与接续

可复用的是“浮点锥提案 → 有理客户重数恢复 → 全历史证书核验”的实验接口，以及把个体效用桥接到 `OPT/(2n−1)` 的明确检测量。它适合在小 `n,p` 上生成可复核候选和有限等号实例。

仍缺少对所有客户权重、所有纯 SPE 终局、所有有序历史和六人模型的证明。后续若要推进，应把候选面约束转为有理多面体的穷尽分类，并独立证明从单人 `u` 到终局覆盖的一般桥；不能把这次 `OPT/u=9` 等号重放升级为普遍半覆盖定理。
