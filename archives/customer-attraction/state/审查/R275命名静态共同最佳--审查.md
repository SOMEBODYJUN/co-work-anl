# 来源与对象

主源 `f33ccbb3431f96f3ee85` 是 2,390 字节 JSON，SHA-256 为 `f44f8c4c25e991f82e69c426d5deeca50d942a7a01e18b5d34f9bebf63392d6a`。它的 `name` 是 `fractional_actual_load_failure`，参数为 `p=4,n=4`，权重坐标对应四主题的 15 个非空客户掩码。`policy` 含 `1+4+16+64=85` 个有序历史动作，`target=[1,3,0,0]` 是终局计数，检测动作 `a=2`。

这个对象不是概率分布：权重总和为 `1.0625`，生成器的归一化约束是目标终局覆盖质量 `covered·x=1`，而不是 `sum(x)=1`。因此不能把 JSON 的权重直接解释为客户总质量或概率。

# 生成器的检验语义

`named_static_common.py` 读取一组命名的完整策略证书。对每个策略，它用 `floor_scan.Fast` 枚举四主题、四玩家的所有计数终局，计算客户在被选主题之间均分的系数矩阵，并从动作表递归得到终局。由策略每个历史的遵循动作与偏离动作构造收益差矩阵 `gamma`，约束 `gamma·x≥0` 表示这份固定策略对当前客户掩码权重的弱纯 SPE 条件。

对每个动作 `a`，脚本在线性规划中最小化

`covered + gc − F[a]`

并同时满足 `gamma·x≥0` 与 `covered·x=1`。其中 `covered` 是终局覆盖指示，`gc` 是以终局负载修正的静态共同收费向量，`F[a]` 来自 `floor_scan` 的动作收益系数。脚本把最小目标值保存为 JSON 的 `slack`；它是某个固定策略、固定客户掩码锥下的数值目标，不是任意策略或任意客户分布的定理。

# 候选记录的实际数值

独立核对得到：

- `slack=0.1861263736263737>0`；
- 15 个权重坐标中有 4 个非零坐标，非零值为 `0.1875, 0.0625, 0.0625, 0.75`；
- 完整历史动作表含 85 个互异历史；
- 终局计数为 `(1,3,0,0)`，检测动作是主题 `2`。

正的 `slack` 表示这份保存候选没有找到该目标下的负桥值。文件名中的 `failure` 是候选命名，不等于失败证书；也不能据此推出“没有其他客户锥或其他策略会失败”。浮点 LP 的可行性和结果还需要有理化、逐历史收益复核和独立策略证书才能升级。

# 可复用边界与接续

可复用的是：对已经给定的完整历史策略，把客户类型压缩为非空掩码权重，用收益差锥约束筛选弱 SPE，再检验一个明确的静态共同收费目标。它适合作为小 `p,n` 的有限候选生成器。

尚未解决的是客户权重的整数化/有理化、所有离轨历史的严格核验、浮点容差对 `gamma` 的影响，以及对所有完整纯 SPE 和 Q-CAG-HALF-6 六人模型的量词。下一步应把该候选恢复为整数客户实例，逐历史重算收益差并与 direct_global 其他命名对象分开比较。
