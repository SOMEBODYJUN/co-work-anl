# 1. 这批来源的共同语义

本批属于 R-275 的 `background_exchange` 与 `round2`。它们把完整有序历史纯 SPE 必须满足的客户 incidence、actual-path、末位 best-reply、penultimate floor 和 true-reply overlap 行投影到非负原子质量 LP。每个源都在正文或 JSON 中明确写有 `NOT A FULL SPE CERTIFICATE`、`PROJECTION ONLY` 或 `necessary projection`；因此本页把精确恒等式、LP optimum、infeasible 分支和缺失依赖分开，绝不把投影原子当真实客户 SPE。

冻结 SHA、commit、大小和逐源绑定见 [source-manifest](../../tools/evidence/R275-background-exchange-20261031/source-manifest.json)。本批实际运行输出见 [evidence README](../../tools/evidence/R275-background-exchange-20261031/README.md)。

# 2. 精确六组 projection 证书

## 2.1 penultimate exchange

`audit_penultimate_exchange.py/json` 对六组原子和形式式做 Fraction 审计，完整检查 $m=3,4,\ldots,100$ 共 98 个整数。JSON 的 scope 明确不是 full SPE certificate。代表系数与 slack 为：

| $m$ | coefficient | $E$ | floor slacks | terminal BR slacks |
|---|---:|---:|---|---|
| 3 | $4$ | 16 | $16/3,16/3,0,0$ | $64/3,64/3,0,0$ |
| 4 | $95/11$ | 44 | $27,21,0,0$ | $81,77,0,0$ |
| 5 | $311/21$ | 84 | $384/5,264/5,0,0$ | $1024/5,924/5,0,0$ |
| 6 | $769/34$ | 136 | $500/3,320/3,0,0$ | $1250/3,1088/3,0,0$ |

源代码的系数恒等式用 $H=3m^2-7m+2$ 和 $q-K=cE$，并逐类检查 floor 与 terminal best response；这验证的是该六组 projection 的代数接口，不验证存在一棵完整策略树。

## 2.2 十条保留税行

`audit_tax_projection_polynomials.json`/`.py` 以 $z=m-3$ 展开十个无序主题对。公共正倍数为 $2m(m-1)$；每行的升幂系数均非负，例如

$$CC:(320,904,984,522,136,14),\qquad
CP:(320,808,808,402,100,10),$$

而 $CL=(64,264,344,202,56,6)$、$CD=(64,168,204,124,36,4)$，其余六行同样逐系数非负。程序实际退出 0，未调用 solver。结论是所有这些**投影 tax rows** 在整数 $m\ge3$ 非负，不是任意完整 SPE 的支付定理。

## 2.3 exact strengthened projection

`exact_strengthened_projection.json` 的范围是“aggregating listed actual-node necessary conditions 的 exact obstruction; NOT SPE counterexample”，固定 $m=5$，总质量 $W=1$，`comparison_union=1029888020062/463330867145`，超过 $2W$ 的差为 `103226285772/463330867145`。它还记录 `coefficient=311/21`、实际节点和四类 checked rows 的最小 slack。

这个正投影点只满足列出的 necessary rows，未给出完整历史动作、每个偏离后的 continuation、客户目录和均分 SPE；因此它是把某些行直接聚合会失效的**障碍**，不是 half 反例。

# 3. 末位、倒二和独立回复投影

## 3.1 terminal/middle floor

`exact_terminal_projection.json` 对 $m=2,\ldots,8$ 逐一解 terminal-root exchange LP，输出均 `status=0`；例如 $m=2$ coefficient $1$, $K=2$, $v=3/2$，$m=3$ coefficient $4$, $K=2$, $v=1$。`middle_floor_projection.json` 在 $m=2,\ldots,9$ 的 `last`、`lasttwo`、`all` 模式逐行运行，保留了每个模式的 positive atoms、dual 和 coefficient。两个程序实际退出 0；这些是非负 incidence projection 的有限值，不代表中间策略可以同时实现。

## 3.2 true-reply cap 与两轮回复

`audit_reply_cap.json` 记录两个已知完整实例：34 客户 `individual_security_failure` 的根路径 $(0,3,4)$、$W=32$、reply-cap 126 行、最小 slack $1/2$；36 客户 `aggregate_theta_failure` 的路径同为 $(0,3,4)$、$W=34$、最小 slack 0。它还保存 sharp projection family 的 98 个 $m$ 值（头部 gap 为 $0,14/3,11$）。这些输出支持“reply cap 行本身可成立而 harmonic lift 仍可能失败”，不产生新 Q-CAG-HALF 反例。

`audit_reply_cap.py` 的独立 Fraction checker 逐历史构造 258 个 SPE 比较和 126 个 reply rows；当前 clone 没有它要求的 `examples/customer-attraction/*.json`，所以未伪造运行。已有 JSON 作为冻结输出保留，运行缺口写入证据目录。

## 3.3 fresh maxima、size maxima 与 overlap

- `fresh_maxima_projection_m5.json`：$m=5$、4095 个变量、798 行，HiGHS optimal，necessary projection objective `2.084593514818204`。
- `overlap_consistency_projection_beta2_m5.json`：4095 变量、954 行、objective `2.084593514818203`，加入 true-reply 三主题 overlap 行；scope 仍是 `NOT SPE`。
- `full_actual_reply_cap_m5.json`：六个 `maximizer_f_at_penultimate`/`maximizer_size` 组合，均记录 full-atom necessary projection；不是 strategy certificate。
- `max_f_reply_projection.json`：六个 m=5 最大 $f$ 选择的 LP 全部 infeasible（status 2），说明该更强 row family 不能在这些参数下由同一投影实现；它不是一般不可能性。

本批实际运行 `fresh_maxima_projection.py` 与其 overlap 适配，退出码均为 0，objective 分别为上列两个数；其余 JSON 的状态、原子质量和 dual 原样保留。

# 4. 统一结论和缺口

1. **已闭合的局部内容**：六组 projection 的 98 个整数参数 exact audit、十条保留税行的非负整数多项式、terminal/middle projection 的有限 LP 值和 reply-cap 两实例审计。
2. **明确障碍**：把 actual-node necessary rows 聚合成 `exact_strengthened_projection` 会出现 $>2W$ 的投影点；更强 `max_f_reply` 行族在 m=5 的六个选择全部 infeasible；但这些都只说明行系统层的边界。
3. **仍缺的数学桥**：从非负原子 projection 恢复真实客户目录、从每个节点的 row 恢复同一完整策略和所有离轨 continuation、再把 payment/tax 行加总成客户覆盖。没有这三步，不能把任何 `optimum_float`、projection atom 或 dual multiplier 称为 SPE/half 结果。
4. 与已存在的“保留重叠税十条形式恒等式与第二轮回复边界”“背景交换的五人必要投影声明与版本证据边界”正文衔接：本批把原先缺 blob 的具体 JSON/Python 取回并实读，但仍遵守其原有“不升级 projection 为 SPE”的边界。Q-CAG-HALF 仍为 OPEN。
