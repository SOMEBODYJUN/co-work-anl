# 输入与代码边界

冻结源是 2737 字节的标准库 Python。客户类型由 13 个六位掩码及其有理重数给出；主题分成两组三个标签，`O={0,1,3,4}` 为普通标签，`S={2,5}` 为特殊标签。代码只定义收益函数
[
u(a;B)=\sum_{T\ni a}\frac{w_T}{1+\#\{b\in B:T\ni b\}},
]
并检查预定的两步/三步局部回复恒等式。没有调用求解器、没有导入博弈实现，也没有枚举全部 43 个历史。因此，任意模块的完整纯 SPE 仍由书面归纳证明承担；本程序只作定义级有理核验。

# 精确重放结果

直接运行冻结源码通过全部断言，输出 `status: exact local identities verified`。六个首动作的 pair rows 为：

|首动作类|回复|首位收益|第二位收益|末位上界|
|---|---|---:|---:|---:|
|0↔1、3↔4|普通组内回复|16|16|32/3|
|2、5|普通组内回复|31/2|35/2|67/6|

三人局部 rows 对根动作 (a=0,1,2) 给第二人 (67/6)，对 (a=3,4,5) 对称；当根动作为特殊标签 2 或 5 时第二人收益为 (35/3)。六个根动作的根收益均为 (29/3)，末位在指定三步后的收益与第二位相等。代码还逐一检查所有 36 个第三动作偏离的末位最佳回复，以及所有 36×36 的 pair/triple 低值条件；所有 Fraction 断言通过。

这组输出与已入库的 34 客户六主题完整 SPE（根路径 `(0,3,4)`、收益 `(29/3,67/6,67/6)`、(W=32)、(OPT_3=34)）的局部数值一致，但它不替代该对象已有的 43 历史、258 项偏离完整审计。它也不把 pair/triple 行表误称为任意模块全树证明。

# 数学关系与限制

`state/定理/可用模块的收益保底与全深度递归松弛--定理.md` 已用状态归纳证明：在不交等大可用模块条件下，全部完整纯 SPE 每位收益为模块大小；该定理的量词和证明不依赖本次代码。当前程序的六主题权重向量不是对任意模块参数的扫描，也没有检查模块不交条件的全部输入规范；它只验证一个具体六主题局部合同。

因此本源的独有内容是可复现的 exact local identities：普通/特殊根的 pair admission 值、三步根/第二/末位值，以及全局 local deviation 断言。它支持后人检查文字推导和 34 客户反例的数值，但不能新建“EO 普遍成立”或“六人 half”结论。相关源码、stdout 和 SHA 清单保存在 `archives/customer-attraction/tools/evidence/r3d253-eo-module-contract-Boss8/`。
