主源 `d2776cfe97e39348f7d3` 是 3,067 字节的 Python 诊断程序，依赖另一个冻结输入 `62b9a6c6d47995ee269d` 的 `combined_702.json`。输入给出 `m=6`、12 个支持点、共同常数 `K` 以及每个支持点的 `actual_bits`、`d`、`weight`。程序先由支持点权重计算各位置的 `u_i`，再对 `i=0,…,m−3`、`target∈{optimal,0,…,m−1}`、`query∈{same,0,…,m−1}` 枚举局部情形。

对每个情形，`local_coeff` 生成六类源/内部/终端线性不等式；程序把每个支持点和四个配置变量 `(s,b,c,v)` 展开成列，用 SciPy `linprog` 最小化一个共享上界变量 `z`，并要求每组权重质量保持输入 `w`。因此它检验的是固定浮点支持和局部不等式的可行分离，不是重新寻找客户分布、福利最优或均衡策略。

我在隔离副本中把依赖 JSON 接回后重放 196 个情形。最大 `phase_one_slack` 为 `0.00011461426178907735`，唯一正分离出现在 `source=2, remaining=5, target=4, query=5`；其余情形没有正 slack。源代码开头已经声明需要 exact recovery 才能把正分离升级为结果，本次没有执行有理化、整数客户重数恢复、完整历史节点核验或纯 SPE 检查。

这个对象的可复用内容是局部六类不等式和 target/query 枚举接口，可用于后续把浮点分离转成有理证书。现阶段它只能作为 R915 推广末回复路线的有限固定点诊断；不能称作支付定理、SPE 反例、福利 LP 结论或 Q-CAG-HALF-6 结果。与已有 R23 带价 promoted fork 审查的关系只作比较和输入来源，不把本诊断倒写为 R23 的证明。
