# 总税搜索与首步桥增量证据

## 1. 先固定共同模型和处置原则

这三份来源都使用单位客户/单位提供者、共同目录和完整历史纯 SPE 的 CAG 语言；与 shared facility、unrelated-machines 或一般设施盒模型不同。`e1a8...` 和 `f128...` 不是新定理：它们分别重放已有的[非零背景总税反例](../反例/非零背景总税--反例.md)与[首步机会成本税桥反例](../反例/首步机会成本税桥--反例.md)。本页保存新运行的精确字段、比较范围和处置理由，避免把重复审计误写成新数学对象。

## 2. 非零背景总税的独立重放

`e1a8bae8e41d61519496` 声明算术为 `fractions.Fraction`，范围是两个 fixed-background total-tax counterexamples，且明确“不反驳 root half coverage 或 root total tax”。

### 九客户、七提供者例

固定前缀为 `[0,0,0]`，剩余四人；子局完整检查 40 个 histories 与 80 个 deviations，最小激励余量为 0。根检查 1093 个 histories、2186 个 deviations。实际剩余总利润为 4，末位前税为 \(3/4\)，比较函数 \(F_4=24/5\)，所以总税缺口为
\[
\frac{24}{5}-\left(4+\frac34\right)=\frac1{20}.
\]
最大比较计数为 \((2,1,1)\)，按大主题 A 的计数分类最大值是 \(2,15/4,24/5,9/2,4\)。根 welfare 为 7，\(\operatorname{OPT}=9\)，故半覆盖在该例成立。

### 九十六客户伴随例

该伴随例有 96 个单位客户、14 位提供者、十步固定前缀和四位剩余者。子局仍检查 40 个 histories、80 个 deviations；根全树没有再次枚举（字段为 `null`），而是沿用参数化收益比较。实际剩余总利润 24，税为 \(18/11\)，\(F_4=26\)，缺口为 \(4/11\)；按 A 计数的类内最大值为 \(12,216/11,26,330/13,24\)，根 welfare 84、最优 96，半覆盖仍成立。

这两个字段级重放与已有反例正文的参数族一致：被否定的是某个固定背景税式的全称量词，不是根 half 目标。处置为 `integrated`，目标正文和完整 Fraction 审计仍是已有对象；本批 raw JSON 只承担版本证据。

## 3. 首步机会成本税桥的重复但更完整审计

`f1284ade3f4441b7dd50` 使用 15 个不同单位客户、空前缀、恰三位剩余提供者，完整策略在 21 个 decision histories 恒选主题 1；验证 63 个实际 continuation deviations 和 48 个 weak-dominance checks，实际路径 `[1,1,1]`，每位 payoff 3，福利 9。

根最优值精确为 \(F_1=9,F_2=11,F_3=15\)。选择首主题 1 后，\(F_2=7\)，再两次选择后 \(F_1=3\)，首步税为 \(9/2\)。因此首步桥右侧为
\[
3+\frac92+7=\frac{29}{2},\qquad F_3=15,
\]
缺口为 \(1/2\)。同时整条根税为 6、总税右侧为 15，字段 `total_tax_is_equality=true`；主 half 目标在该例也满足。完整节点收益表和所有主题对的 \(F_2\) 均在 JSON 中保存。

这正是已有首步桥反例的独立 Fraction 重放：它证明局部 Bridge 全称式失败，但不能被改写为“总税恒等式失败”，也不能单凭本例否定六人 half。处置为 `duplicate`/`integrated`：不新增反例对象，只把 raw 版本放入本批证据目录并链接已有正文。

## 4. 27136 实例的有限 CAG 搜索

`912c92b9572c9c92ca11` 是 sequential customer-attraction finite search，算术为整数 payoff 按 \(\operatorname{lcm}(1,\ldots,m)\) 缩放后取有理比，均衡对象为“所有纯 history-dependent SPE terminal outcomes”。递推明确写成
\[
E(c)=\bigcup_a\{q\in E(c+e_a):U_a(q)\ge\max_b\min_{r\in E(c+e_b)}U_b(r)\}.
\]

总实例数为 27136，`universal_claim_proved=false`。全批最小 \(\mathrm{SPE\ welfare}/\mathrm{OPT}\) 比为 \(5/9\)，最坏实例是 catalog size 6、players 5、10 个单位客户、\(\operatorname{OPT}=9\)、最小 SPE welfare 5；最坏终局计数为五位都选同一目录。该实例的所有 SPE terminal count 还列出五种其他计数组合，说明搜索枚举的是 outcome set 而非单一 tie rule。`residual_lemma_counterexamples=[]`，并对 13 个 stage 的最坏实例做 canonical independent crosschecks，全部报告 `all_outcome_sets_equal`。

分阶段范围包括：catalog size 3 的 multiplicity 0--2 全部行动置换轨道、catalog size 4 的 multiplicity 0--1 全部轨道、k=4/5/6 的 seeded random 样本，以及 k=3,m=8；k=4,m=6/8；k=5,m=6；k=6,m=6；k=7,m=5/6 等 extended residual 样本和 large-vs-disjoint-small 构造。有限搜索未发现 half violation，反而找到了 5/9 的最低比；但这仍只对列出的目录规模、重数和随机种子成立。它没有证明任意目录/任意客户重数/六人目标的全称命题，也没有把“没有 residual lemma 反例”升级为引理。

## 5. 与现有正文的关系和下一步

原始三份 JSON 已冻结到 `archives/customer-attraction/tools/evidence/incremental-tax-search/`，`manifest.json` 记录 source ref、raw hash、解析状态和读取范围。`e1a8` 与已有总税反例合并；`f128` 与已有首步桥反例重复并保留作为独立版本审计；`912` 作为有限搜索的增量审查保留，链接到[一般半覆盖方向复核](一般半覆盖研究方向复核--审查.md)，不创建“搜索定理”。

这些来源给第三阶段的明确关系是：税桥反例 → 局部递推障碍；总税反例 → 非零背景全称式障碍；有限搜索 → 现有候选在指定有限域的支持证据与量词缺口。它们都不提供六人 Q-CAG-HALF 的完整证明或真正反例。任何后续使用 `5/9` 时必须同时写出“有限实例搜索中的最小比”，不得把它当普遍下界。
