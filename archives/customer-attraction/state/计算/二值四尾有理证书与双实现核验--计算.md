# 二值四尾有理证书与原双实现核验

## 1. 证书证明什么

数学正文见[二值背景四人利润重权界](../定理/二值背景四人利润重权界--定理.md)。在原五人共同目录单位模型中，固定任意合法单提供者有序前缀，之后四人沿给定完整纯SPE继续，得到同背景比较利润界

\[
F_4(p)\le\frac{22869393}{11445824}V_4,\qquad p_x\in\{0,1\}.
\]

空主题、重复选择、零客户和全部离轨平局保留。有限的256状态枚举穷尽的是证明所使用的七个主题会员位及二值背景；客户数、目录大小均没有上界。数学结论还依赖十二个全局slack来自同一原策略的合法节点。代码核验不能替代这个SPE量词论证，剩余利润也不等于完整根覆盖。

这是一份原十二行机制的限制域重权证书，另有在p0/1中省聚合校正的版本。它没有证明五人根half、任意更大背景的相同界或任何最优性。五人根half当前已由另一份更强证书成立，本页只整理本辅助机制的独有资料。

## 3. 浮点发现与精确证明的界线

生成器构造每种客户型的十二行系数r与实际利润V，约束为r·λ−βV≤0，另有λE+λP=1和变量非负。浮点目标仅最小化β，并以绝对误差10^−8筛选候选活跃行。随后选13个线性独立方程，完全使用Fraction消元求出12乘子和β；最后在全部256状态重新进行精确有理判号。

因此浮点成功只帮助找出候选常数，定理不依赖浮点容差决定余项正负。交付的确切β、12权重及所有非负余项构成可独立检查的证书；可行证书不认证在该行锥内最优。早期206549/103375限分母近似没有进入最终有理证明。

独审的第一路从旧公共分母D4除以相应分母重建每行，第二路从均分终局收益及δ2/δ3直接重建。256×12=3072系数逐项相等。它还直接枚举四个比较会员位并求六对，而非只信任重数压缩式：校正版P检查96状态，E检查128状态，两最小值都为零。省校正版另检查30+40=70个p,v,e状态。

校正版256余项全非负，17项为零；p=0、1的最小正值分别为22255/34337472、4774397/103012416。省校正版仍有17个零项，并在全部256状态满足

\[
\rho^{\mathrm u}=\rho^{\mathrm c}+\lambda_P\mathbf1_{a+b=2}\frac{2p^2}{3D_4(p)}
+\lambda_E\mathbf1_{a+b+c=3}\frac{p^2+p}{D_4(p)}.
\]

本轮从原两生成器重新发现并精确恢复的两份JSON，与各自冻结原件**字节指纹完全一致**；标准库独审原程序输出的全部字段也与原报告完全一致。两生成器不是两名独立数学审查者；原direct审查与实现相对生成器独立，本轮只是原实现重放，没有新增独立审稿人。

## 4. 重放方法与输出

仅验证已交付有理证书需要Python标准库，无需安装优化器。从结果仓库根执行：

```sh
python3 archives/customer-attraction/tools/evidence/binary-four-tail/replay.py
```

若还要重复原浮点选活跃行、Fraction恢复的发现过程，需要NumPy和SciPy：

```sh
python3 archives/customer-attraction/tools/evidence/binary-four-tail/replay.py --rediscover
```

本轮实际执行了带--rediscover的命令，成功后另有[reconciliation.json](../../tools/evidence/binary-four-tail/replay/reconciliation.json)记录三份报告的完整一致性、两证书字节指纹、两版256状态余项关系及16实际四位下对qrs取最小的准确表。后者就是正式定理中的完整最小余项表，必须与当前β和权重共同使用。

- [校正版重放](../../tools/evidence/binary-four-tail/replay/binary_four_tail_certificate.json)。
- [省校正版重放](../../tools/evidence/binary-four-tail/replay/binary_four_tail_uncorrected_certificate.json)。
- [独审原实现重放](../../tools/evidence/binary-four-tail/replay/audit_binary_four_tail_independent.json)。

默认模式从冻结证书原件重建临时布局，用独审原程序重算所有系数；--rediscover模式还执行两生成器，之后以相同标准库程序复核。未来不同优化器选出的活跃基可能变化；发现器并非逻辑前提，已交付有理数据的标准库核验才是直接证明接口。
