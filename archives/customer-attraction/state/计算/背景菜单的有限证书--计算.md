# 报告实际证明的对象

主源 `b9595537628e7f8219f5` 的[186B完整原表](../../tools/evidence/background-menu-certificate-data/original/background_menu_certificate.json)已 `clean show` 全文读取，SHA-256为 `db25a2460aa58d9a8438f7aea0e20445c12264f717c587cafdd9974338d58689`，两冻结提交同字节。它不是客户输入、完整策略表或384个游戏的运行结果，而是一份由四个非负乘子组成的逐客户证书。

原生成器有39个可用SPE行，保存四个非零乘子，其余35个为零。本轮独立从真实均分收益重构384个系数行，共14976个有理IC系数，按保存乘子得到80个零余项、304个正余项，最小值0。下文进一步给出余项的显式非负分解；旧客户部分清分母后对背景p仿射，因此得到全部整数p≥1的条件结论，依靠的是代数证明，不能把有限检查本身称作全模型搜索。

准确结论是：若合法前缀为同一目录主题H重复L≥1次，之后恰余两人，固定原完整纯SPE在该子博弈的实际主题A、B，令P为这两人的总利润、Δ为他们新增覆盖的客户数，则

\[
P+\Delta\ge\operatorname{freshOPT}_2.
\tag{C}
\]

这里比较最优值只数前缀未覆盖客户，且只用两个合法主题。任意合法前缀版本的(C)已经被52客户完整SPE反例否定；本证书所需的合法背景主题H不能删除。

# 模型、合法背景和完整策略量词

采用[共同目录完整历史模型](../定义/共同目录完整历史模型--定义.md)：客户有限且单位价值，共同主题目录有限非空，单位提供者依次观察全部有序历史选题；每位覆盖者均分该客户价值。空主题、重复行动、零客户和任意离轨平局均保留。固定任意一份完整纯SPE，在任何合法有序前缀后的真实子树仍是同一策略的纯SPE；不同同负载历史不要求相同回复。

原程序设前缀为 \(H^L\)，H必须是共同目录中的合法主题，L≥1。对客户x记h=1_H(x)，于是背景负载

\[
p_x=Lh_x,
\quad F=\{x:h_x=0\},\quad O=\{x:h_x=1\}.
\]

F为新客户，O为旧客户；H同时是可偏离的目录主题和旧客户集合，这两重身份是证书的承重条件。此合法前缀可以离开根实际路径，证书只使用其后两人子博弈的最优性，不额外要求过去L个选择H在根实际发生。

令A为该子博弈首位按策略选择的题，B为随后真实末回复。任取合法比较题T、S；可重复，可与A、B、H相同。按同一策略定义Q、R、V分别是首位改选T、S、H之后的真实末回复。代码八标签分别为A、B、T、S、Q、R、H、V；全39候选行保留这些真实历史。

固定背景p，定义

\[
U_p(X;Y)=\sum_{x\in X}\frac1{p_x+1+1_Y(x)},\qquad
u_A=U_p(A;B),\quad u_B=U_p(B;A),\quad P=u_A+u_B.
\]

新覆盖为 \(\Delta=|(A\cup B)\cap F|\)，任意两题的新覆盖为 \(C_F(T,S)=|(T\cup S)\cap F|\)。记旧客户给末两人的利润为

\[
P_O=\sum_{x\in O}\frac{1_A(x)+1_B(x)}{p_x+1_A(x)+1_B(x)}.
\]

零分子份额取0。新客户上实际两尾的总利润就是新增覆盖，故 \(P=\Delta+P_O\)。非零背景中的P一般不是整局覆盖，也不是Δ。

# 39候选行及四个真正活跃的合同

完整候选池包括3条首位真偏离行、8条首位安全保底和4组各7条末位查询，合计39：

| 家族 | 行与真实节点 |
| --- | --- |
| root_T_Q、root_S_R、root_H_V | \(u_A-U_p(T;Q)\)、\(u_A-U_p(S;R)\)、\(u_A-U_p(H;V)\)，在原首位节点使用原真实后继 |
| floor_X，X遍历八标签 | \(u_A-\sum_x1_X(x)/(p_x+2)\)，首位改合法X后总分母至多p+2，再由源IC给保底 |
| last_chosen_prior_other | 四个真实末位节点 `(prior,chosen)=(A,B),(T,Q),(S,R),(H,V)` 对其余七标签查询，\(U_p(chosen;prior)-U_p(other;prior)\) |

这些是全客户求和后非负的SPE行，其单客户系数可以为负。本原证书只使用以下四条：

\[
\begin{aligned}
C_B&=u_A-\sum_x\frac{1_B(x)}{p_x+2}\ge0,\\
C_H&=u_A-\sum_x\frac{1_H(x)}{p_x+2}\ge0,\\
L_T&=u_B-U_p(T;A)\ge0,\\
L_S&=u_B-U_p(S;A)\ge0.
\end{aligned}
\]

它们的组合为 \(\tfrac12C_B+C_H+L_T+L_S\ge0\)。首位可合法复制主题B和选择H，实际末位在同一个A之后查询T、S；没有把不同末位节点的收益搬到同一个节点，也没有冻结偏离后继。Q、R、V相关行的乘子全为0，所以这份稀疏证书本身没有用到更大的真实回复菜单能力。不能因标签串包含Q/R/V便宣称它们为结论提供了独立信用。

# 清分母后的384行与真正证明目标

逐客户记 \(a,b,t,s,h\in\{0,1\}\)，令

\[
D(p)=(p+1)(p+2)>0.
\]

原 `u(X,Y)=1_X(p+2-1_Y)` 正好等于 \(D(p)U_{p,x}(X;Y)\)，因为会员位是0/1；不是另一个收费模型。四个活跃IC的清分母系数分别为

\[
\begin{aligned}
c_B&=a(p+2-b)-b(p+1),\\
c_H&=a(p+2-b)-h(p+1),\\
\ell_T&=(b-t)(p+2-a),\\
\ell_S&=(b-s)(p+2-a).
\end{aligned}
\]

生成器target为

\[
\tau(a,b,t,s,h,p)=
\begin{cases}
2[2(a+b-ab)-(t+s-ts)],&h=0,\ p=0,\\
(p+2)(a+b)-2ab,&h=1,\ p\ge1.
\end{cases}
\]

fresh时D=2，故target/D是 \(2\cdot1_{A\cup B}-1_{T\cup S}\)。旧客户上target/D则是末两人的真实总利润 \((a+b)/(p+a+b)\)，并不是旧客户覆盖的整数计数。因此

\[
\sum_x\frac{\tau_x}{D(p_x)}=2\Delta-C_F(T,S)+P_O
=P+\Delta-C_F(T,S).
\tag{1}
\]

枚举八会员位共256种。H=0的128种只放p=0行；H=1的128种各放p=1行，以及p=2系数减p=1系数的**斜率行**。后者不是另一个可实现客户类型，也不表示只验证了两个背景游戏。清分母后所有表达式对p均仿射；所以旧客户的任意p≥1行是p=1行加(p−1)倍斜率行。

本原表384行是 \(128+2\times128\)，不是384个不同背景长度、384完整SPE或客户数的扫描。Q、R、V不进入四活跃项和target，故对证书余项只有48个有效 `(类别,A,B,T,S)` 组合，每个在完整384表中重复8次。

# 从保存乘子到全背景长度的显式非负余项

令

\[
\rho=\tau-\tfrac12c_B-c_H-\ell_T-\ell_S.
\]

本轮从原始分母独立展开得fresh的完整公式

\[
\begin{aligned}
\rho_F
&=a(1-t-s)+\tfrac12(1-a)b+2ts\\
&=a[(1-t)(1-s)+ts]+(1-a)[b/2+2ts]\ge0.
\end{aligned}
\tag{2}
\]

旧客户在p=1的余项和仿射斜率为

\[
\rho_1=(1-b)(2-3a/2)+(t+s)(3-a)\ge0,
\tag{3}
\]
\[
\rho_{\rm slope}=1-(a+b)/2+t+s\ge0.
\tag{4}
\]

于是对每个p≥1，

\[
\rho_O(p)=\rho_1+(p-1)\rho_{\rm slope}\ge0.
\tag{5}
\]

这些式子的非负性直接由a、b、t、s为二元位及p−1≥0成立，不依赖在大p上的抽样。按D(p)逐客户除回再求和，有完整证书恒等式

\[
\boxed{
P+\Delta-C_F(T,S)
=\tfrac12C_B+C_H+L_T+L_S
+\sum_x\frac{\rho_x}{D(p_x)}\ge0.}
\tag{6}
\]

注意D可能因客户而异；非负乘子始终是同一组1/2、1、1、1，所以除回后确为四条完整IC的非负组合，而非擅自对每条IC加任意客户权。取任意合法T、S，最后再取最大值，得到(C)。这既解释了原证书能如何复用，也明确了它为何需要H为合法菜单题。

原重复H前缀属于此结论。式(2)至(5)还说明一个明确的条件扩展：只要**前缀已覆盖客户的并集本身恰是一道合法目录题H**，便可让各旧客户有不同正整数p，仍逐客户使用(5)并得(6)。这个扩展来自显示的符号恒等式，不是原有限报告额外扫描的结果；一般合法前缀的并集不一定属于目录，不能省略这项条件。

# 原生成流程及报告没有认证的内容

原main没有外部输入，按八位全部组合构造384行，39个乘子非负，以它们的和为浮点LP目标，约束 `rows·λ≤target`。HiGHS成功后把每个浮点数用 `Fraction(float).limit_denominator(1000000)` 转为有理数，并精确检查全部target−row·λ≥0；只输出非零乘子。LP失败时另写 `background_menu_certificate_status.json`，不是本成功表。原函数有main保护，导入不自动优化；实际main会覆盖同目录证书，不能当作只读入口。

源码没有在有理化后单独检查乘子非负；本冻结表四项严格正、其余零已由当前独立审计确认，所以本表合法性不靠浮点容差。success也不包含精确最优性、支持极小性、外审或新颖性认证。乘子发现与有理验证是不同步骤，不把发现LP本身当成普遍定理。

原表不含完整客户分布或完整σ。384种局部位型无需能同时成为一份SPE；它们作为全部客户系数的覆盖域已足够用于恒等式证明，但不能以其枚举构造策略。也没有任何关于三人以上剩余局的证书；将更长后继当作一个末位会改变分母、可用IC和目标。

# 与已知反例、一般尾界及其它背景菜单的关系

该例A、B不交，已有覆盖并集含34客户，而六个合法主题大小分别16、18、9、9、16、16，没有题H恰等于这个并集。不能把H免费加入目录：该背景上每个旧客户p=1，若H可选，本证书所用首位floor_H已要求 \(u_A=8\ge34/3\)，立即违反。新增H会改变原SPE，而非补一个无影响的证书标签。这给本证书合法H条件与一般反例之间的精确分界。
