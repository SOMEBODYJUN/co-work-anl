# 原程序、报告与真正有限域

四主源合12301B：作者程序3170B/冻结报告1297B，fresh独立程序5288B/冻结报告2546B。两份代码和报告完整逐项主读。独立文件明确non-blind：审查先见父程序，再自建单位客户利润/分配/完整历史验证；不导父程序、规范model/solver/verifier。它是知情独立实现，不是无提示发现或外审。原报告各写PASS，当前新执行身份只以本批真实entry journal为准，不能用冻结PASS代替新run。

原模型为有限单位客户/有限非空共同目录、角色顺序观察全部有序历史、全历史纯SPE，保空主题、重复选择、全部平局。辅助priority只在分析中分配客户，原策略没有观察彩票；adaptive query是被检验的付款选择，不是新有信号博弈均衡。

两实现运行时都只使用内部literal四输入，**没有外部文件输入依赖**。代码分别导stdlib Fraction、itertools permutations/product（作者另导未使用combinations）、Path/json，无项目导入、无main guard；import模块本身会执行全部测试并写`Path(__file__).with_suffix('.json')`再打印报告。所以不能为了调用helper而先import形成隐性重复entry。原冻结JSON需单独保，真实运行应置新的空replay目录，原代码字节不改。

# 自建收益、winner和完整历史IC

作者`audit(topics,m,policy)`内部follow沿原有序policy补完，pay逐不同单位客户找所有coverer并均分；winner按同一排列rank把客户给最早coverer。独立实现以utilities/allocation/verify分开定义，同样按客户找到第一个priority coverer；两者在每个固定终局的两排列平均应回原均分利润。空客户/没人覆盖时不求1/0。

IC循环枚举depth i的**全部**有序前缀、全部合法当前query，再沿同一原policy完成，断言遵从当前利润≥偏离当前利润；含own-action比较。不只actual Nash，也不冻结后继。给定每人只行动一次，全部这种节点比较正是完整纯SPE条件。

每份原程序一次正常走完会调用通用验证helper四次，但只验证以下四个literal输入，不量化该通用函数参数的所有游戏。内部follow/pay/winner或utilities/allocation多次调用，未逐函数instrument，不能报告源函数0或只算script函数定义未调用。
