## 作者程序的固定实例检查

作者源码2908字节，标准库 Fraction 精确计算。固定12类客户的重数是参数族 \(k=3\) 的值；程序展开71个不同客户编号，然后逐客户求 \(1/\text{终局覆盖人数}\)。

它没有导入规范SPE求解器、作者发现优化器或独立实现。HERE常量虽然定义，但没有用于读取文件；程序实际没有外部输入，没有命令行参数解析，只将JSON输出到stdout。

全部数学检查包括：

- 六个首动作历史下第二人的六种选择，即36项回复比较；在指定真实回复下比较六种首动作，共42项含自身动作的比较。
- 全部21个无序主题对，允许重复主题，验证最优值38以及唯一最优对 \(TQ\)。
- 实际覆盖、遗漏、实际独有及交集 \((W,L,E,I)=(35,36,33,2)\)，并检查 \(L>W\)、\(\operatorname{OPT}-W=L-E=3\) 和半覆盖余量32。

1791字节原报告完整保存末位6×6收益表、六个根偏离收益、全部21个覆盖数及上述标量。42是七节点各六动作，包括七个自身动作；不能写成42个非自身偏离。该程序只认证 \(k=3\)，全参数结论有另外的解析及线性证书。

## 独立实现的全参数证书为何不是有限抽样

原审查声明只读取兴趣重数表、完整策略及命题陈述，没有读取或导入作者审计、候选JSON、发现优化器或规范SPE引擎。检查源码与该声明相符：它独立写出12类线性重数、单位客户求和、线性多项式运算和完整比较。这里保留的是原内部审查身份；本轮重放不产生新的盲审，也不声称外部同行评议或独立发现了原反例。

源码8230字节分成两个相关但不同的核验层。

第一层在 \(k=3\) 实际展开71名客户，分别形成六个客户ID集合。它逐客户重算末位矩阵、根真实回复、全部42项比较、21个集合并集及最优遗漏。六个主题集合两两不同被显式检查；大小向量 \((16,19,19,19,22,22)\) 并不两两不同。

第二层把每类重数写为 \((\beta,\alpha)\)，代表 \(\beta+\alpha k\)。给定动作组合时每类客户的分母固定为1或2，所以收益、并集及比较差仍是线性多项式。对每个待证差 \(f(k)\)，代码检查

\[
\alpha\ge0,\qquad f(3)=\beta+3\alpha\ge0.
\tag{1}
\]

于是对所有实数 \(k\ge3\)，

\[
f(k)=f(3)+\alpha(k-3)\ge0.
\]

若需要严格性，则检查 \(f(3)>0\)。这个有限长度的系数证书证明了整个参数范围，并非只测试了几个整数。合法单位客户实例再将参数限制为整数 \(k\ge3\)。

具体检查对象如下：

| 对象 | 全参数检查内容 |
| --- | --- |
| 12类重数 | 每类斜率非负、\(k=3\) 严格正，整数参数下均为正整数 |
| 36个末位差 | 指定回复减每种选择的常数、斜率与起点值；按式(1)认证 |
| 6个根差 | 每个均精确等于零多项式，沿真实指定回复计算 |
| 21个主题对 | 覆盖多项式与 \(TQ\) 的差；\(TQ\) 自差为零，其余20个差全域严格正 |
| 命名量 | 客户总数、实际覆盖、最优覆盖、遗漏、实际独有、交集全部从类型重新求和 |
| 72个收益交叉项 | \(6^2\) 个有序终局×两名玩家的逐客户值等于独立线性式在 \(k=3\) 的值 |

命名多项式的完整系数为：

| 名称 | 常数 \(\beta\) | 斜率 \(\alpha\) |
| --- | ---: | ---: |
| 总客户数 | \(-10\) | 27 |
| \(W\) | \(-4\) | 13 |
| \(\operatorname{OPT}_2\) | \(-4\) | 14 |
| \(L\)（原报告名U） | \(-6\) | 14 |

原报告12630字节不仅给“通过”状态，还保存42个差的历史、查询、常数、斜率和起点值，以及21个主题对的覆盖和最优差多项式。它没有保存完整优化搜索过程，也没有枚举所有SPE；这些均不是该符号证书要承担的义务。

## 发现输入和证明输入的实质比较

原候选JSON1475字节给14类客户、players=2、根编号0、回复编号 \((1,5,4,5,5,4)\) 和优化器历史状态。正式作者程序却有12类客户；不能因二者都为71人就把候选标为逐字重复。

[输入等价正文](../等价/两份最优遗漏输入的二人收益等价--等价.md)列出两份完整表及共同交集矩阵。新写的精确比较程序只读取候选和作者源码中的字面GROUPS，不调用任何旧审计或优化器。唯一一次运行通过：每份输入各有完整42项激励，全部72项两人终局收益相同，21个主题对覆盖相同，且同有 \(L=36>W=35\)。但三重交集 \(BRS\) 为2与6，三人动作 \((B,R,S)\) 中 \(B\) 收益为 \(41/3\) 与15，已经不同。

这份新计算既保留原发现输入的独有高阶结构，也防止将两人等价误用于六人。其[输出](../../tools/evidence/optimal-omission/replay/candidate-comparison.json)和[运行元数据](../../tools/evidence/optimal-omission/replay/candidate-comparison-manifest.json)与两份原审计分开，源代码哈希和输入指纹可核查。

## 关系、用途及剩余范围

本批完整比较了已整理的[27客户零根保护反例](../反例/零背景保护遗漏与超额利润价格--反例.md)及其[双版本核验](保护遗漏反例的零根与合法背景核验--计算.md)，确认旧例只能直接否定每个最优组合的支付，本族进一步否定存在有利最优组合的支付。另与[半因子勘误](../障碍/遗漏份额支付的半因子勘误--障碍.md)核对同一净额 \(L-E\)，没有把标量预算不足改称原模型反例。

独立线性证书证明这个明示无限族；它不声称客户数最少、最坏遗漏比例、六人结论、所有输入的某种分类或所有SPE枚举。发现优化器的成功字符串不能补足这些缺口。后续可复用全部客户、策略和严格最优差来测试新预算，但应保留实际独有客户账户和真实回复依赖。
