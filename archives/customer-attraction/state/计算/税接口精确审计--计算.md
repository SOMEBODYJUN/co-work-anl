# 税接口精确审计

## 本包证明什么、怎样读取

数学正文分别为[首步税桥](../反例/首步机会成本税桥--反例.md)、[背景总税](../反例/非零背景总税--反例.md)、[实际根总税](../反例/四人实际根总税--反例.md)。它们各有显式有限输入和完整策略。对一个给定有限策略，穷尽全部有序历史并核验真实续局偏离，可以严格证实它满足 SPE 定义；这是全称桥的显式反例证书，而非以“有限搜索未见反例”证明一般命题。

参数族和[同主题根界](../定理/同主题终局根覆盖界--定理.md)依靠正文公式推导，不依靠有限检查数量。本包没有解决一般或恰六人半覆盖，也不核验所有可能 SPE。

## 入口、环境与重放

从仓库根运行，输出目录须尚不存在：

```sh
python3 archives/customer-attraction/tools/tax-interfaces/run_audits.py --output-dir /tmp/tax-interface-replay
```

只需 Python 标准库，无 LP、规范 SPE 求解器或外部模型；本轮实际使用 Python 3.12.14。全部数学运算用整数和 `fractions.Fraction`，确定性执行，无 seed、浮点精度或误差容忍参数。使用普通解释器，不能加 `-O`，入口会拒绝关闭断言的执行方式。

已保存本轮[完整结果目录](../../evidence/tax-interfaces/replay/)及[摘要](../../evidence/tax-interfaces/replay/summary.json)。摘要记录运行 UTC 时间、实际 Git 基线提交、Python 版本和所有程序/输入 SHA-256；源身份另见[来源清单](../../tools/tax-interfaces/provenance.json)。复现时基线提交、代码哈希或输出路径可变，数学字段须一致。

## 原实现、独立性与路径适配

三份源审计程序均已阅读全文，理解其输入、分母、真实续局构造和枚举范围。程序原本属于旧目录树；新位置仅做以下明确适配，实际对应字节与目标哈希逐份记在 `provenance.json`：

1. 首步与背景程序的根定位改为当前客户吸引存档，输入路径改到 `evidence/tax-interfaces/inputs/`。收益、策略、最优值和断言算法不变。
2. 背景程序输出的旧状态描述改成“这两个例只否定背景总税；根税已有另一个反例”。不让过期状态混入复现报告。
3. 独立根税程序修正运行说明，删除已失效的临时上传文档路径哈希读取，改指向来源清单；客户表、全终局计算、策略构建、偏离检查、静态证书和边界算法不变。
4. 原稿代码来自冻结Markdown中的唯一Python代码块，没有拿它替代独立根税实现。统一入口额外核对所保留JSON与两份程序嵌入客户表一致。

“独立”描述原内部实现的代码边界：单位客户根审计不导入或执行原稿代码，也不导入规范求解器/优化器；首步和背景审计同样直接按定义计算。**本轮运行这些既有实现是重放，不是再新增一份盲独立审查。** 外部同行评审和全球新颖性均未认证。

旧内审记录的上传文档摘要为 `9a6894927a426256d8d87cb5169a3c0888961d1e72e3d3f0b02bfcc012ac9e00`。本轮直接计算冻结 `root_tax_source.md` 的字节SHA-256，得到**完全相同**的值；两个来源位置对应同一字节内容。来源清单明确记录这一一致性，不凭路径不同推断内容不同。先前清洗稿将两者措辞写得仿佛不同，已据实际散列更正；数学证明与审计算法没有变化。清洗不复制旧临时绝对路径或失效下载链接。

## 保存的输出及用途

`replay/bridge.json` 保留全部节点分支终局、收益、最优组合、10个两主题多重集值和弱占优核验；`general.json` 保留两例类内最大值、根/子局范围、最优计数与精确税差。`root_original.stdout.txt` 保留原稿重放输出。

`replay/root_independent/` 含259行节点表、1295行偏离表、216行末位回复表、21对全部六行动值、74项数值记录、56个安全值原始约束和机器摘要。完整表由代码重建，没有因新正文使用合并表而丢掉独有证据。

背景输入与40节点证书按原字节保留，根输入与星形输入也按原字节保留。输入重数始终展开为不同单位客户。代码不枚举一般所有SPE；它验证明确指定的完整策略，不能据此宣布一般根税以外的猜想真或假。

## 比较过的相关正文与剩余范围

除12项本批来源，实际阅读全文比较了冻结 `two_remaining_tax.md`、`oblivious_security.md`、`optimal_last_query_counterexample.md` 和 `customer_attraction_root_security_uploads.py`：分别用于区分仍成立两人税/末节点接口、静态不观察查询的量词、后续唯一最优查询收费失败，以及压缩类型重放与单位客户实现的独立边界。全仓关键词检索另查到后续全部终局税及新预算路线，但未把检索命中当作这些方向已经审完或已经证真。

两个主要冻结版本中，本批12个源路径均各自同内容，`inventory.jsonl`已合并定位；没有忽略同路径异内容版本。仅这些12项可以由本批逐份记录完成。相关的两人税、其他审计/证书/历史研究、1651客户例及新的预算路线仍有各自来源待领取或待处置。

本轮没有新增数学超边。正文已记录“定义共同前提—三个不同桥—各反例—保留的同主题界—实现/有限核验”的证据，留给第三阶段按精确对象建立关系，不声称地图完成。
