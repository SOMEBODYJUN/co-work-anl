# R-3b942 查询行有限策略锥扫描与证据范围

## 读取的脚本和数据

完整读取 8019 字节 `attack_row.py`：它枚举 composition 计数拓扑，计算每个客户类型的覆盖核；递归求每个 child-SPE 的终局集合和最低当前收益；保留实际孩子并把所有严格后继 IC 写成线性约束；最后用 SciPy `linprog` 最小化 RF-END 行。`--cones` 可进一步对同一后继策略锥求 LP，`--empty` 把含某标签的客户权重设为零，`--optimal_comparator` 将比较并集换成静态最优覆盖。

完整读取五个 JSON 对象。其中 `cone_discovery.json` 与 `row_discovery.json` 的 SHA/字节相同，均为 `(m,k)=(4,6)`，`gap=13`, 实际计数 `[0,0,0,1,0,3]`，比较计数 `[1,1,0,2,0,0]`，实际福利26、比较覆盖31，父动作不是最优。`empty_cone_discovery.json` 为 `(m,k)=(4,7)`，`gap=11`，实际福利44、比较覆盖44，空主题权重约束已启用。`cone_discovery_m5.json` 为 `(m,k)=(5,7)`，`gap=78.46666666666667`，实际福利109、比较覆盖105。所有 gap 均正，因而这些记录没有发现 RF-END 负分离。

## 证据等级

这些结果是**有限浮点发现记录**：使用整数随机客户权重、有限 composition 拓扑和容差 `1e-8` 的最低收益筛选；没有 exact Fraction 重放、LP 对偶证书、全部有序历史的独立策略核验，也没有统一任意平局量词。正 gap 只说明记录中的行目标未越界，不是一般 ROW? 或 RF-ROW? 的证明；父动作 `parent_is_optimal=false` 也说明扫描同时覆盖了非根最优节点，不能把结果当完整根 SPE。

`cone_discovery.json` 和 `row_discovery.json` 内容逐字节相同，应只保留一个数学数据对象，另一源作 `duplicate`；它们来自不同路径但同一冻结 blob。脚本本身保留为可复现程序资源，待未来从来源分支恢复其 SciPy 运行依赖后再做有理化与全历史证书。
