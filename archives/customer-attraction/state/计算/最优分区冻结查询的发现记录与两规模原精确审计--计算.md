# PFR的精确存在量词

在[原共同目录模型](../定义/共同目录完整历史模型--定义.md)固定完整纯SPE实际动作 $S_1,\ldots,S_m$，客户实际负载c、覆盖W。PFR-OPT-v1要求存在一份真最优m槽比较元组T、槽匹配π及不交owner分区 $P_j\subseteq T_j$，使

\[
R(\pi,P)=\sum_i\sum_{x\in P_{\pi(i)}}
\frac1{c_x+1-\mathbf1_{x\in S_i}}\le W.
\tag{PFR}
\]

比较重复槽、空题和任意平局保留。owner分区不用是目录主题；这是冻住其它实际覆盖、删去对应实际玩家再添加查询的静态费用，不是偏离后按真后继行动所得利润。

两见证都恰两人、六个共同覆盖集合A/B/T/S/Q/R（标签0..5），六集合互异。完整策略为根0，末位在根强制0..5后依次回复(1,4,4,5,5,4)，含全部7个有序决策节点。唯一最优无序支持是{2,3}，且两题不交，因此每名比较客户只有唯一eligible owner；两种最优顺序和两种匹配只形成两种不同“哪个主题分配给实际槽”的费用。核这两项即穷尽全部最优元组/匹配/分区，而非只找到一个坏分派。

# 发现器：明确的辅助目标与有限旧记录

probe.py只用NumPy/SciPy浮点求解。63个类型按 `product((0,1),repeat=6)[1:]` 的词典序；第一坐标是主题0，故不能当作“整数mask第0位是主题0”的little-endian顺序套用。每个变量是不同单位客户类型的非负质量，不是加权提供者。

`utility(a,b,player)`第三参数在调用中实际是所选**主题标签**，并非第几名玩家。固定reply后，程序加36个末位（含self）及6个根（含self）弱IC；根实际路径0,1，所有偏离沿各自reply完成。令actual为A∪B、opt为T∪S，以W=1归一，最大化共同余量δ：δ不超过14个其它不同标签对的OPT覆盖差，也不超过两个匹配的逐客户最小分区费减W。δ无额外非负下界；正浮点δ只是发现线索，不能独自认SPE或全部重复比较最优。

main种子64220261021，先建固定reply(1,4,4,5,5,4)，另生成500个随机reply（根后回复固定1），然后逐个solve；第一次成功gap>10⁻⁷即停。原probe.json全字段为scope=`finite floating fixed-policy attack, not a proof`，best.iteration0、上列reply、margin0.1267605633802817、完整63权重，以及checked1。故它记录首个固定policy便有正浮点点，**不是已求解500随机策略**；源码虽预生成500元组，checked不等生成次数。失败LP直接跳过，不给一般阴性证书。

本批未运行或import发现器，没有新增随机/LP。旧记录没源码SHA、版本、标准流或事件信息；不把新精确核验改写为它当时的浮点运行。

# 原exact_audit的实际恢复与全行检查

原审计只用标准库Fraction、集合、product和带重复组合，不导入probe/LP/SPE solver/其它verifier。有main guard，`--source`默认probe.json，或读取integer_simplification.json；只取best（若存在）中的weights/reply。每浮点权重用分母上限10000恢复有理数，再乘共同分母，**不**另除GCD，断言所有整数质量非负。实际两输入均63坐标；它的zip没有通用长度校验，因此本批另完整绑定长度/顺序，不能把任意畸形向量的行为当合法输入。

将质量实际展开成不同单位客户，构造六个字面集合，断六集合互异。末位6×6收益表逐项用单位份额求，再核每行指定reply最大；根六个真实偏离利润同算并核0最大。它不冻结偏离后的原末位动作，故42项含self（35非self）的比较确证完整两人纯SPE，不只在轨NE。

随后穷举21个无序含重复主题对，证明最优支持恰[(2,3)]；这等价于检查全部36个有序两槽的覆盖最优。对两个匹配，逐比较客户在所有eligible比较题/实际槽中取最低替换费用并求和，断两项的最小值仍严格大于实际覆盖。这里实际T/S不交，逐客户最小已经穷尽owner选择。

## 两规模的其它预算不能混用

两点都满足half，余量分别142−88=54、16−10=6。实际AB各不交，终局税 $\sum_xc_x/(c_x+1)$ 分别71/2和4，亦有OPT≤W+税。

本次从完整恢复类型作直接算术比较：不删除实际覆盖者的添加查询费 $A=\sum_{x\in T\cup S}1/(c_x+1)$，大点是56+32/2=72>W71，小点是6+4/2=8=W8。此字段不是原exact报告的输出，而是包内向量绑定记录的明确新解析比较；不能把14点“添加查询仍等W”的性质复制给127点。大点也不是旧71总客户/W35的另一唯一遗漏族，二者客户数和策略不同。
