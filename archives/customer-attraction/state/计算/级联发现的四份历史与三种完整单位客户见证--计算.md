# 本轮一次独立定义检查

[检查器](../../tools/evidence/cascade-original-nine-boss3/audit_saved_certificates.py)只用标准库，不导入原Engine、规范solver/证书验证器或优化库。逐件核原件SHA、全部客户类型与正整数重数、每个原动作记录，检查有序键域恰等全部长度0…4的p进制历史、无重复键且动作合法，再沿原动作表重建每个规定和强制偏离终局。

对某历史h的当前角色、被选标签a与真实完成的终局z，直接计算

\[
u_a(z)=\sum_{B\ni a}\frac{n_B}{\sum_{b\in B}z_b},
\qquad
u_{a(h)}(z_\sigma(h))-u_b(z_\sigma(hb)).
\]

全部比较用Fraction且非负，故三张**给定完整策略**是其整数客户实例的真SPE。这不是只检查实际路径、只信原note或将浮点点四舍五入后直接接受。

# 九客户点：三个标签同覆盖，不能错数末主题

目录标签0、1、2都覆盖同一个5客户块A；标签3、4、5、6各覆盖一个不同单客户，彼此及A不交。共9名单位客户、5个不同物理覆盖集。原路径为(0,0,0,1,1)，每人收益1、W5；J=(2,3,4,5,6)覆盖全部9客户，所以OPT₅/W=9/5。

末标签1的计数只有2，但末客户集合A在实际路径出现5次。这正是[末覆盖重数](../定理/末覆盖重数与前缀缺席的半覆盖判据--定理.md)要求按集合而非标签计数的边界。原七标签策略完整保留，不删除0/1/2后继续宣称2801节点表原样有效。

它是已有全选大主题m5例的带别名表示，不是新的half反例。若要商成五个不同集合，可以另取全历史恒选A的策略：已有ℓ名非A玩家时，遵从得到5/(5−ℓ)≥1，改单客户至多1，改空题若加入也仅0，所有历史成立。任一SPE实际路径至少覆盖A；否则在实际末节点改A能独获5，严格胜过任何单题至多1。故这个简单实例的min_SPE_W确为5、最坏效率确为9/5，这是解析论证而非本轮BI结果。原保存图本身仍以完整逐行核验认证。

# 处置与下一步

三份保存点都属于原单位客户完整SPE模型，且给定策略比均小于2；它们不同于仅通过必要行的伪矩点。当前[五人half](../定理/五人半覆盖--定理.md)另有一般证明，历史“五人起”的发现任务不是当前五人仍开放的依据。恰六人的全部完整历史目标未被这三点解决。

可继续复用的是原完整图、三份整数客户、目录私有条件、确切历史/版本边界与按定义可重复的全部IC检查。欲声称某个锥最优，需要相应精确对偶；欲声称该输入最坏SPE，需要全续局求解或证明；欲声称全族/全部六人结论，需要覆盖剩余量词，不能用109条摘要、输出文件名或相同效率比代替。
