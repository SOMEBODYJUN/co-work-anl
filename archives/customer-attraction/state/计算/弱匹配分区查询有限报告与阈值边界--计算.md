# 分区查询的程序语义

这三份 JSON 是同一 `probe.py` 的 `query_mode=partition` 输出。对一个固定完整历史策略锥、一个目标主题排列和一个非空客户主题掩码 (S)，脚本把分配给该掩码的目标主题拥有者集合记为 (I_S)，并使用

\[
 q_S=\min_{i\in I_S}\frac{1}{c_S+1-\mathbf 1\{S\ni a_i\}},
\]

其中 (c_S) 是实际根动作中落入 (S) 的次数，(a_i) 是被替换的第 (i) 个根动作。这个 `query` 向量进入固定策略锥的线性约束；覆盖质量归一化为 1，LP 最大化一个统一的分区查询下界。对 `partition` 模式，脚本的分离阈值是 1；若结果超过 (1+10^{-7}) 才提前报告 `floating_candidate_requires_exact_audit`。因此报告中低于 1 的成功值是可行锥的查询下界，不能解释成福利负缺口。

与上一批 `full` 查询对象相比，`full` 模式的阈值是 (1+1/m)，并按真实终局 `actual` 和新主题重算客户收益。`partition` 模式只保留掩码分区的最坏拥有者份额，不重建全部真实后继客户价值；两者的数值不能相加，也不能把 `partition` 的 1 当作 (W/\operatorname{OPT}) 或主问题半覆盖阈值。

# 重放与来源边界

三份原始 JSON 均逐字节保存在证据包，源 SHA 分别为：examples `ef35c725…`（62093 字节）、p6 `c19849a3…`（207963 字节）、p7 `fc4ddd68…`（476792 字节）。复用已审计的 `probe.py` 和 canonical 依赖做一局 p6 与一局 p7 的 `partition` 重放，均返回 0 且 stderr 为空；一局最大值分别为 (0.8139652648) 和 (0.7999822727)。独立检查器核对三份源哈希、参数、去重策略锥数、成功/不可行计数、最大字段、完整历史动作数、阈值边界和两次重放，返回 `PASS`。

样本生成仍使用双精度 `linprog`、`unique_margin=10^{-6}` 和固定策略锥。JSON 没有保存所有原始随机客户权重、离轨终局项或 LP 对偶；canonical examples 批的 `source=None` 也只表示来自本地示例枚举，不是外部整数客户证明。这个证据包因此只能支持有限分区查询样本的“无分离器观察”。

# 与弱匹配主线的关系

上一对象的 p6/p7 `full` 报告在阈值 (5/4) 与 (6/5) 下记录了另一种真实后继查询；本对象的 `partition` 查询使用阈值 1，属于较弱且不同的接口。两者都保留完整历史策略动作表，但都只在有限固定锥和浮点 LP 上工作。它们没有合并成弱匹配存在性定理，也没有恢复整数客户多重集、精确 Fraction 对偶或任意平局下的全称 SPE 量词。

继续推进需要保存生成每个策略锥时的全部离轨项和原始权重，再对分区 query 与真实客户 query 做逐历史 Fraction 对齐；只有在整数化和完整后继 IC 都通过后，才能讨论任意共同目录或六人 Q-CAG-HALF。当前结论停留在三份 `partition` 冻结报告和两次局部重放的有限证据层级。
