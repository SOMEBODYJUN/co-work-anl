本页处置的是 `direct_global` 的两份直接来源，而非同目录的命名脚本。`static_common_attack.py` 的 source ID 为 `6ba99015cb5ee1e1d5fb`，1354 字节，SHA-256 为 `d707d5d70afac70e96420f6a58c542bd285c6afed6ab84e14a2f06846247b9fd`；`static_common_best.json` 的 source ID 为 `7fd962b12560d5e640b7`，80604 字节，SHA-256 为 `b7d4fb878fd95ea812cef1ffdd16bb11245ba87eeabb7af0307262868c222914`。两者均来自冻结提交 `68fad804ec5946cb296f77dc5b336308a66abf12`。驱动器通过 `cone_floor_attack.py`（source ID `dbf018232df702a3cfaf`，2986 字节，SHA-256 `af4f1f7f4e65a9c27d6b433e24dd1e3ff2cd7819cfd09dc140a580833d85ddb0`）间接导入 `floor_scan.py`（source ID `90578ba48285bc04f0c3`，1817 字节，SHA-256 `ba406363e5a12959096613530441ae171df58ca9cd18a182cfc49d5dd1dbc66d`）。四个原文件逐字节保存在[证据目录](../../tools/evidence/R275-static-common-20261031/)。

`static_common_attack.py` 的入口没有读外部客户 JSON，也没有导入完整 SPE 求解器。它使用 `numpy.random.default_rng(8932)`，依次测试

\[
 (p,n,N)=(5,3,20),(6,4,20),(7,5,20),
\]

每轮从 `[0,0,0,1,2,4,8,16]` 独立抽取长度 (2^p-1) 的浮点向量。每个向量只取计数状态递归根集合按 `cov[z]@w` 排序后的前三个目标终局；对每个目标遍历 (a=0,\ldots,p-1)，即至多 (60\times3\times p) 个 LP（实际每组目标数由根集合决定）。发现更小的 `out.fun` 才覆盖 JSON；若当前最小值小于 (-10^{-7})，打印 `BRIDGE FAIL` 并提前结束。冻结运行没有触发该分支。

# 计数状态对象和固定策略锥

令 ([p]=\{0,\ldots,p-1\})。`floor_scan.Fast` 枚举

\[
 \mathcal C_{p,n}=\{c\in\mathbb Z_{\ge0}^{p}:\sum_{a=0}^{p-1}c_a=n\}
\]

并按非空掩码 (S\subseteq[p]) 建立矩阵 (M_{S,a}=1_{a\in S})。对终局计数 (c)，代码的负载和单客户系数为

\[
 d_S(c)=\sum_{a\in S}c_a,
 \qquad
 P_{a,S}(c)=
 \begin{cases}
 1/d_S(c),&a\in S, d_S(c)>0,\\
 0,&\text{否则}.
 \end{cases}
\]

给非负掩码质量 (w_S)，终局动作收益是 (U_a(c;w)=\sum_SP_{a,S}(c)w_S)，覆盖指示是 (q_S(c)=1_{d_S(c)>0})，覆盖总质量为 (q(c)\cdot w)。这里的 (w_S) 是有限 LP 中的实数质量；代码没有把它解释成已经核验过的整数单位客户列表。

`Cone.R(k)` 只把计数向量 (k) 当作状态。它先递归每个孩子 (k+e_a)，令

\[
 \theta(k)=\max_a\min_{z\in R(k+e_a)}U_a(z;w),
\]

然后保留满足 (U_a(z;w)\ge\theta(k)-10^{-8}) 的孩子终局并集。于是 (R(k)) 是该**计数状态 DAG** 的有限可达终局集合；同一计数下不同有序历史在这里被合并。原客户吸引模型允许每个完整有序历史拥有独立离轨续局，所以这个递归不是“所有完整策略”的递归，更不是对任意平局选择的全称量词。

`Cone.policy(target)` 随后展开所有长度小于 (n) 的有序历史。它在历史 (h) 的孩子中选择第一个仍可到达 `target`、并达到 (\theta(k)) 的动作；每个偏离动作选择其孩子集合中该动作收益最小的终局。设遵循动作是 (a_h)，偏离 (b\ne a_h) 选到终局 (z_{h,b})，则 LP 中的行是

\[
 \Gamma_{h,b;S}=P_{a_h,S}(z_{h,a_h})-P_{b,S}(z_{h,b}),
 \qquad \Gamma w\ge0.
\]

这只是一个由当时浮点权重产生的固定动作表和固定孩子终局表的激励锥。它没有合并所有策略、所有平局或所有完整有序历史的续局量词。

# `static_common_attack.py` 的目标

设目标终局为 (z)，(d_S=d_S(z))，(q_S=1_{d_S>0})，(n) 为提供者数，\(\alpha=(n-1)/n\)。源代码构造

\[
 g^c_S=\frac{q_S}{1+\alpha d_S},
 \qquad
 F_{a,S}=1_{a\in S}
 \begin{cases}
 (n+1)/(d_S+1),&d_S>0,\\
 n,&d_S=0.
 \end{cases}
\]

其 LP 对每个动作 (a) 为

\[
 \begin{aligned}
 \min_{w\ge0}\quad & \sum_S(q_S+g^c_S-F_{a,S})w_S,\\
 \text{s.t.}\quad & \Gamma w\ge0,\qquad q\cdot w=1.
 \end{aligned}
 \tag{SC-LP}
\]

`q·w=1` 只把目标终局触及的质量归一化；即使某次候选恰好满足 `sum(weights)=1`，也不能把这条等式理解成一般客户总数、概率分布或福利归一化。目标 (q+g^c-F_a) 是该脚本的静态共同量模板，不自动等于真实终局福利、(\operatorname{OPT}) 或 (W/\operatorname{OPT})。SciPy/HiGHS 以双精度求解，源文件没有保存 LP 对偶、精确行的有理化或整数客户重数。

# 冻结候选的精确字段和数值复核

JSON 顶层恰有 `p,n,weights,target,a,slack,policy` 七个字段：

* `p=7`、`n=5`；`target=[1,1,0,2,1,0,0]`，其和为5；`a=0`；`slack=0.19999999999999996`。
* `weights` 长度为 (2^7-1=127)，唯一非零坐标是 Python 下标90，即掩码 (91=1+2+8+16+64)，兴趣集合 (S=\{0,1,3,4,6\})，质量为1；其余126坐标序列化为 `0.0` 或 `-0.0`。
* `policy` 有 (2801=\sum_{j=0}^{4}7^j) 条历史，分层数为长度0、1、2、3、4的 (1,7,49,343,2401) 条；每条保存 `h` 和选定动作 `a`，动作都在0至6。JSON 不保存偏离动作的子终局 `terms`。

在该唯一支持掩码上，目标负载

\[
 d_S(z)=1+1+2+1=5,
 \qquad \alpha=4/5.
\]

因此 (q_S=1)、(g^c_S=1/(1+4)=1/5)，而 (F_{0,S}=6/(5+1)=1)。目标坐标系数为

\[
 1+\frac15-1=\frac15.
\]

所以保存点满足

\[
 q\cdot w=1,
 \qquad (q+g^c-F_0)\cdot w=\frac15,
\]

与小数 `slack` 相符。证据目录中的 `verify_static_common.py` 用 `Fraction` 独立重算这一点，并核对四个源文件的字节数与 SHA；`verification.json` 返回 `PASS`。

# 复现和序列化纠错

把四份原文件复制到新目录后，重新运行完整入口：

```text
5 3 0 slack/W 0.33333333333333326 target [0, 1, 1, 1, 0] a 0
6 4 0 slack/W 0.25 target [2, 0, 1, 1, 0, 0] a 0
7 5 0 slack/W 0.19999999999999996 target [1, 1, 0, 2, 1, 0, 0] a 0
DONE 0.19999999999999996
```

stderr 为空，生成的 `static_common_best.json` 与冻结 JSON 逐字节一致。命令、解释器和 stdout/stderr 指纹见 `replay/full_driver_metadata.json`；这证明当前环境下该**有限浮点搜索**可重复，不证明搜索域外的值不存在。

有一项必须保留的后续纠错：驱动器先用随机权重 `w` 调用 `policy(target)` 生成 `nodes` 和隐含的 `terms`，再用 LP 的新解 `out.x` 覆盖 JSON 中的 `weights`。因此不能用保存的候选权重直接重建原始 \(\Gamma\)。诊断性重建显示，用 JSON 的 `weights` 重新调用 `Cone.policy` 得到的2801个历史中有2797条动作与保存表不同（见 `replay/serialization_policy_comparison.json`）；该比较不是新的 SPE 检验，而是明确说明 JSON 的序列化不足。

# 结论层级、相关纠错与未决缺口

本对象的“无失败”只表示：在固定随机种子、三组 ((p,n))、每组20个随机质量向量、每向量前三个根目标及每个查询动作的这批 LP 中，最小 `out.fun` 没有低于 `-10^{-7}`。`slack=1/5` 是一个保存的浮点候选值；它不是“所有策略锥均有正 slack”，也不是 `BRIDGE FAIL` 的反例。

必须区分以下几层对象。

1. **计数状态锥。** `R(k)` 合并同计数的历史，只是有限状态压缩。`policy` 展开的历史数虽为全部 (7^0+\cdots+7^4)，其每个离轨终局来自这个压缩递归，而非每个历史独立求解的完整续局。
2. **固定浮点 LP。** `Γw≥0` 只针对一次生成的动作和子终局选择；双精度容差 (10^{-8}) 可能改变边界平局。没有 LP 对偶、Fraction 行证书或整数客户实例，所以不能把正 slack 当精确 SPE 证书。
3. **候选与失败。** JSON 文件名和 `slack` 记录是候选保存点；驱动器未打印 `BRIDGE FAIL`，但没有对未抽样权重、其他目标、其他 (p,n)、其他策略或所有平局做穷举。即使某个固定锥出现负值，也首先只是该锥的数值候选，仍需恢复真实客户并逐历史核验。
4. **主问题量词。** 当前六提供者 half 命题要求对有限单位客户、任意有限非空共同目录、每份完整有序历史纯 SPE（含重复、空主题、零客户和离轨平局）量化 (2W\ge\operatorname{OPT}_6)。本源既未证明也未反驳这一全称命题。

与本源最接近的《R275 分数策略锥攻击有限阴性记录》和《R275 固定策略锥与地板扫描有限记录》使用相同的计数状态依赖，但目标模板不同；不能把三者的正值拼成统一定理。《R275 命名静态共同脚本/最佳》处理外部命名策略 JSON（(p=n=4) 的另一批输入），也不能替代本源的随机策略锥。相反，《六人共同静态查询最小收益桥的三十客户反例》已经有完整有序历史的独立证书，但它只反驳一个辅助共同查询桥且仍满足 half；把该反例或本 LP 的候选与六人 half 直接等同都会越过模型和量词边界。

若要升级为可引用的数学证书，至少还需保存生成策略时的原始随机权重和每个偏离终局 `terms`，以便逐行恢复 \(\Gamma\)；随后用 Fraction 重算全部有序历史的 IC、把非负质量恢复为整数客户重数或给出明确的分数模型定理，并单独计算真实 (W)、\(\operatorname{OPT}_6) 和所有平局/离轨续局。当前证据的正确状态是：**有限、浮点、固定计数锥、候选重放通过；无 `BRIDGE FAIL` 观察；没有完整 SPE 证书，也没有六人 half 全称结论。**
