# 计算对象

这两份 `new_representation` 源文件精确审计一个抽象的三玩家环菜单桥。对每个 `k\in\{9,10,11,12\}`，主题 `i` 的菜单是

\[
 A_i=\{i-1,i,i+1\}\pmod k.
\]

客户在这个对象中由环位置表示；给定三动作多重集 `profile`，动作 `a` 的收益是其菜单中每个客户的 `1/(该客户被 profile 中多少菜单覆盖)` 之和。脚本用 `Fraction` 和 `combinations_with_replacement`，没有调用 SPE oracle、LP 或完整历史求解器。它先枚举三动作组合的覆盖并集，得到 `OPT_3=9`，再把阈值固定成 `OPT_3/(2\cdot3)=3/2`。

对于每个根 `r`，被审计的顺序菜单是

\[
 (A_r,A_{r-1},A_{r+1}).
\]

前三个菜单的负载沿其并集为 `(1,2,3,2,1)`，所以根收益和两个尾收益分别是

\[
 u_r=\frac12+\frac13+\frac12=\frac43,
 \qquad
 u_{r-1}=u_{r+1}=1+\frac12+\frac13=\frac{11}{6}.
\]

这给出 `u_r<3/2<11/6`。随后脚本把每一个 `a\in\{0,\ldots,k-1\}` 都作为第三动作检查；`a=r+3` 的三窗与前两个窗口的并集不交，因此第三位获得三个新客户，每个客户负载为一，收益是 `3`。它满足

\[
 3-\frac{11}{6}=\frac76>0.
\]

所以这 42 个根菜单（四个 `k` 值的根数总和 `9+10+11+12=42`）都不是完整纯 SPE 的终局历史。这里的数学结论是抽象 root-tail threshold bridge 失败：尾玩家即使已经高于门槛，也可能有一个远处动作获得更高收益。`W=5` 的前三窗覆盖福利仍有 `2W=10\ge OPT_3=9`；该局部对象没有给出 half 反例。

# 量词和模型边界

这份脚本没有定义一个从每个完整有序历史到后续菜单的策略。它只检查一组三动作顺序和第三位在该前缀后的即时偏离；因此“不是完整 SPE”是对给定终局前缀的局部否定，而不是对所有可能历史的 SPE 反例构造。源文本中的 `profile` 还按三动作多重集求 `OPT`，没有将不同顺序历史当作不同策略分支。

环位置在这里同时承担客户和主题标签的角色，且每个客户是单位权重。该表示没有把它接回六人模型要求的任意有限非空共同目录、重复主题、空主题、零客户、离轨历史和任意平局。也没有给出终局客户价值在覆盖者之间均分后的六人 `W`、`OPT_6` 或完整纯 SPE 证书。它只能作为一个精确的局部障碍：任何想用“根低于阈值、尾高于阈值”直接拼接全树策略的证明，都必须额外处理后续玩家的远窗偏离。

与 `R29三窗菜单与54客户观察者PNE辅助桥` 的关系是扩展而非替换：后者记录另一份局部环说明和固定旧玩家的 54 客户尾 PNE 枚举；本对象在 `k=9..12` 对所有根和所有第三动作做了统一 Fraction 检查，但仍没有建立完整根策略。与 R29 固定完整 SPE 锥的有限复核相比，本对象没有策略锥、整数客户恢复或覆盖门槛全称量词，不能互相拼接成一般定理。

# 接续

若要把该障碍用于完整博弈，必须先给出前两位在每个历史下的动作和所有离轨后缀，再逐历史检查第三位及后续玩家的 IC；同时要把环窗口映射为允许的共同目录和实际单位客户。当前可复用的精确事实是 `OPT_3=9`、阈值 `3/2`、根/尾收益 `4/3,11/6`、远窗收益 `3` 及增益 `7/6`，以及四个 `k` 的 42 次完整末位动作检查。任何“全 SPE”“六人 half”“整数客户反例”表述都超出本源证据。
