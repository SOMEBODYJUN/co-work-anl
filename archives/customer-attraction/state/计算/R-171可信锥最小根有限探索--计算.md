# R-171 可信锥最小根有限探索

## 1. 搜索对象

源程序完整实读 2,925 B，SHA-256 `8aa093cb8d7f37b639c78e0ce466d4e24ba9f3495d0abb62dd44eae570f5c3a4`，稳定 ID `bce1cf4e732bc5d5309f`，blob `52db35fca1ab1456d19d10434aa8a569204087c6`。它固定 (p=7,m=5)，初始客户质量为 mask 48 和 80 各 12，singleton masks 1,2,4,8 分别 4,5,6,7，及 masks 97,98,100,104 各 4；目标终局是 `(0,0,0,1,1,1,2)`。

每一步用 `credible_cone` 从固定目标和随机 mode 生成完整有序策略锥。首动作固定选择目标 payoff 最小的动作，之后按随机 choice 递归。对策略锥 welfare 归一化 (w_{welfare}=1)，LP 最小化首位动作的 `payoff_row`。浮点解先有理恢复；若策略锥行或福利归一化失败，则尝试 `recover_vertex`，仍不通过就丢弃。接受点转换为整数克隆，随后调用 `verify_certificate` 和 `independently_verify`。

脚本没有 CLI 参数，固定 seed `128420` 和 12 步；每个接受记录还计算该实例的 `W`、`OPT` 和根份额。`minimum_root_best.json` 只保存当前最小根份额的最后一个最佳端点，不代表全局最小。

## 3. 与其他 credible 对象的关系

`low_root_discovery.py` 在已知 `W=43,OPT=43` 的种子上枚举主题组合并尝试继续降低 `OPT/W`；本脚本固定目标终局，直接最小化第一位份额。`finite_attempt_summary.json` 的三组 walk 中最高 `OPT/W=171/100`，但那些是不同 seed/参数和完整策略端点；本 12 步结果全部 `W=OPT`，不能互相替代。

`count_milp.py` 的 count-Markov 共享状态会限制候选策略，本脚本则每个 credible mode 直接构造有序历史锥；两者都在接受阶段执行 exact certificate，但生成量词不同。R-171 稀疏租金、动态信用和完整 SPE 障碍对象仍指出，局部低根或有限锥搜索没有支付全树误差的通用桥。

## 4. 处置

本对象作为 integrated 的有限可信锥根份额探索保存。它的唯一可复用内容是目标/种子/12 步的精确接受记录和根份额序列；没有一般最小根定理、全策略下界、Q-CAG-HALF 反例、算法/hardness 或 unrelated-machines 结论。
