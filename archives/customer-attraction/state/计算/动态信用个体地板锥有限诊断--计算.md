## 2. 程序实际优化对象

对每个可解析例子，程序令 (k) 为主题数、(m) 为玩家数，只保留 (kle6,mle4)。它用 `ExactSPESolver` 枚举可实现终局，按福利和目标中最小主题支付排序取前两个目标 `target`。目标是一个固定完整策略证书的有序动作元组，不是任意 SPE 的并集。

对每个目标，`StrategyCone(k,m,cert.actions)` 从全部有序历史上的固定动作表构造策略锥。每个锥行是某个历史处按策略动作与单次替代动作的客户支付差；LP 变量是非负客户类型质量 (w_T)，约束为全部锥行 (G wge0) 和实际福利归一化 (w_{
m welfare}=1)。因此可行域是**一个固定策略的 SPE 客户质量锥**，不是对所有策略、所有平局或所有完整历史证书同时量化。

对目标中实际使用的主题位置 (t)，程序取 `payoff_row(k,target,t)`，再对支持集合 (S)（大小为 (min(k,m)) 的主题子集）定义

[
  c_S(T)-(2m-1)u_t(T),
]

其中 (c_S(T)) 表示客户类型 (T) 被支持主题覆盖，(u_t(T)) 是目标第 (t) 位玩家在该类型上的分数份额。LP 最大化这行在锥内的值。若浮点值为正，程序才继续用有理近似、锥行精确检查、整数克隆和 `verify_certificate` 建立一个候选实例；非正值不会生成反例 JSON。

本次归档示例只产生两个目标候选。最优值显示为约 (1.1102230246251565\times10^{-16})，支持 ((1,2))，目标 `(1,0,1,0,0)`，玩家位置 0；这是数值零附近的 LP 舍入残差，不能记作正 floor violation。程序没有写出 `floor_cone_counterexample.json`，也没有通过“正值—有理恢复—整数克隆—完整证书”链。

## 3. 与已有动态信用对象的关系

既有 `动态信用固定策略floor LP探针` 固定一份 (m=3,k=6) 策略表并在有限浮点 LP 中报告负的 best score；它不是本程序的同一锥。当前源把策略锥从一个固定表改成由 `ExactSPESolver.certificate(target)` 得到的目标策略，并尝试把正 LP 值转成整数客户克隆和完整证书；在归档示例中该升级路径没有找到正值。

既有 `动态信用一步闭合随机LP探针` 与 `动态信用一步覆盖LP探针` 都在 (r=3,k=4) 的随机 response map 上寻找局部投影分离（分别报告过 (1/16) 与 (1/5) 的有限浮点 gap）。那些脚本的约束是局部根/尾利润或覆盖行；本源约束的是一个完整固定策略锥的全部历史偏离行，目标也改成个体 `OPT/(2m-1)` floor。三个结果不能拼成一个通用地板或半覆盖定理。

与 `动态信用一步闭合标量反例` 的精确 JSON 对照时，后者明确 `not an SPE`，其 (W=14,mathrm{OPT}=30,2W-mathrm{OPT}=-2) 只否定两个标量的投影闭合规则。当前脚本若找到正值仍只会给固定锥上的整数克隆候选，且需要 `verify_certificate` 过完整历史；本次没有达到该阶段。

## 4. 结论与缺口

本对象保留的是一个有限、依赖受限的策略锥 LP 诊断及其“无正 witness”输出。它没有证明任意完整 SPE 满足 (Wgemathrm{OPT}/(2m-1))，没有证明 Q-CAG-HALF，也没有证明某个策略的统一 floor；它也没有反驳任何上述命题。缺口包括：原始工作区中未随冻结源一同导出的其他 `examples/customer_attraction` 输入、浮点 LP 到有理证书的全局覆盖、任意策略/平局和人数的量词，以及完整 dynamic-credit 预算望远镜。结果仅留在 customer-attraction 的计算层，不迁移到 unrelated-machines。
