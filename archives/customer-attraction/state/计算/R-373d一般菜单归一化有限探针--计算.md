# 对象与程序语义

该源只有一个 837 字节的 Python 程序。它把一个状态写成三元计数 (q=(a,b,c))，并定义三种候选动作的归一化收益

\[
 u(q,0)=\frac1{a+b}+\frac1{a+c},\quad
 u(q,1)=\frac1{a+b}+\frac1{m b},\quad
 u(q,2)=\frac1{a+c}+\frac1{m c}.
\]

程序枚举 (m=2,\ldots,60)。对每个前缀总数 (n=0,\ldots,m-2)，枚举所有
\(q\) 满足 (a+b+c=n)。对每个候选当前动作 (j)，先把 (q_j) 加一；然后 `complete` 把剩余位置全部填成动作 0，再增加一个 `last(q)` 动作。`last` 依据同一个 (u) 取最大值，并使用固定的 `(2,1,0)` 键在平局时优先动作 2、再 1、再 0。最后计算

\[
\operatorname{gap}(q)=u(\operatorname{complete}(q+e_0),0)
 -\max_{j=0,1,2}u(\operatorname{complete}(q+e_j),j).
\]

因此它测试的是“在这一个人为规定的补全规则下，动作 0 是否不劣于另外两个动作”的有限诊断。它没有把所有未来补全、所有平局或所有策略树都枚举出来。

# 实际重放

用 `clean show a419846dab852807c390 --out` 导出冻结文件，导出文件 SHA-256 为
`1300e7f5cf8197c569b1295be7b4e175b51f1ac42f50125caa4411ecc811b611`，与清单一致。原程序使用 `fractions.Fraction`，没有浮点运算。直接运行成功，输出 59 行（(m=2\) 至 (60)）。每一行的最小 gap 都是 `Fraction(0, 1)`，所以在该有限扫描中没有负 gap；程序在 `p[0] < 0` 时才会提前停止，本次没有提前停止。

每个 (m) 的状态数（含空前缀）为
\[
\sum_{n=0}^{m-2}\binom{n+2}{2}=\binom{m+1}{3};
\]
总计 557,845 个 ((m,q)) 状态。作为回放的局部交叉核对，去掉空前缀后，(m=60) 的最小值仍为 0，最早达到该最小值的前缀为 (q=(0,0,1))，三条候选完成分支的收益为
\[
\left(\frac2{59},\frac{119}{3540},\frac{179}{7080}\right),
\]
其第一项等于最大值。原始完整输出和导出脚本保存在本草稿目录；回放输出 SHA-256 为
`20e6a02be6b78fa7268e687895500d4f5d7320c68a9ed615a1728c02046c7469`。

空前缀 (q=(0,0,0)) 对每个 (m) 都给出最小 gap 0；因此“最小值为 0”本身也包含一个结构性平局，不能解释成严格安全余量。非空前缀的独立分析同样没有发现负值，但程序没有输出全量状态表或符号证明。

# 与 R-373d 根菜单材料的关系

同目录的 `review.md` 给出了另一套明确的三动作客户模型（(X,Y,b,c)）及任意 (m\) 的完整纯 SPE 和真实菜单结论。该审查使用客户覆盖者均分收益，例如末位收益含 (m/(a+b+1))；本程序的 (u(q,j)) 使用无客户解释的倒数和，并在动作 1、2 的第二项写成 (1/(m b))、(1/(m c))。源中没有把两套公式等同的映射。因此本程序不能被用来增强 `review.md` 的完整 SPE、(W\)、菜单 cap 或真正静态安全值结论；它只提供一份独立、归一化的有限计算探针。

# 可复用结论、失败机制与边界

- **有限事实**：对程序定义的 (m\le60)、所有 (a+b+c\le m-2) 前缀和该程序唯一的补全/平局规则，`gap<0` 未出现；所有计算为精确有理数。
- **没有推出的命题**：不能推出 (m>60) 的结论，不能推出任意未来补全或任意平局的结论，不能推出动作 0 在完整策略树中是最佳回复，不能推出 CAG-HALF、菜单支付桥或一般安全值不等式。
- **结构性限制**：`complete` 固定了剩余动作，`last` 只选择一个最大动作；因此搜索并非完整 SPE 枚举。`(2,1,0)` 平局顺序是程序选择而非模型公理。输出只保留每个 (m) 的最坏三元组，没有逐状态证书。
- **可接续用途**：若要把它用于数学证明，需先明确 (u) 与客户/终局均分模型的映射，再对所有合法 ordered histories、全部真实后继和任意平局给出符号证明或独立 Fraction 证书。当前最合适的处置是把它作为辅助计算对象整合保存，而不是反例或定理。
