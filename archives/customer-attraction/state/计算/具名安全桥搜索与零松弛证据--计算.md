# 具名安全桥搜索与零松弛证据

## 对象与范围

这三个源文件属于同一个 `R-27557809587746c59216a46867c9eb07` 工作区的 `direct_global` 子目录。它们不是新的客户游戏定义，也不是完整 SPE 证明；它们把一组已经命名的固定完整策略证书送入有限线性规划，寻找一个能支付某种覆盖或遗憾量的非负客户权重。客户类型仍以非空兴趣子集的质量向量表示，目标是保留既有完整历史策略的逐节点激励不等式。空兴趣类型被脚本的覆盖约束排除，重复主题和有序历史是否存在则由输入证书决定。

脚本的输入清单为十个已命名的证书：`fractional_actual_load_failure`、`individual_security_failure`、`root_tax_failure`、`coverage_opportunity_failure`、`residual_counterexample`、`prefix_balance_failure`、`worst_pne_welfare_failure`、`worst_cce_welfare_failure`、`local_security_increment`、`aggregate_theta_failure`。脚本从 `strategy.actions`（或顶层 `actions`）重建有序动作表，不按计数状态替代有序历史；`p` 由动作表中的最大动作推断，`n` 由最大历史长度推断。若 `p**(n-1)>100000` 则跳过该证书，因而程序自身没有覆盖所有可能的输入规模。

## `named_max_utility_gc.py` 的数学程序

对每一份策略表，程序用 `Fast(p,n)` 计算终局客户类型和系数，并递归沿指定行动表求 `terminal(h)`。对每个历史 h 以及每个偏离动作 b≠σ(h)，组成有限的 IC 行
\[
gamma_{h,b}=c(\operatorname{finish}(h),\sigma(h))-
c(\operatorname{finish}(hb),b),
\]
其中 c 是由 `Fast.coefs` 给出的每个客户兴趣类型的份额。

设根终局的类型负载为 `loads`，覆盖指示为
\[
q_T=\mathbf 1_{\{\text{loads}_T>0\}},qquad
g_T=\frac{q_T}{1+(n-1)\,\text{loads}_T/n}.
\]
对于脚本枚举的每个候选行动 a（只在 `Fast.C[target]` 中允许），LP 的目标是最小化
\[
(g-c_{\mathrm{target},a})\cdot w,
\]
满足全部上述 IC 行的 γw≥0、归一化覆盖约束 q·w=1 及 w≥0。这是一种固定策略、固定终局、固定线性约束的浮点分离搜索。脚本另外构造了 `F`（按负载给出的退款系数），但在 `named_max_utility_gc.py` 的目标中没有使用它；不能把变量名 `F` 解读为已经支付的退款。

若当前目标低于历史最优，脚本以 `named_max_utility_gc_best.json` 覆盖保存一个浮点权重、目标、候选行动和完整策略表；若目标低于 `-1e-7` 就打印 `BRIDGE FAIL` 并终止。该阈值、SciPy `linprog(method='highs')`、浮点系数和提前终止规则都属于程序语义，不是精确有理证书。

冻结的最佳 JSON 是 `fractional_actual_load_failure`，p=4,n=4，根终局计数为 `[1,3,0,0]`，候选行动 `a=0`，目标值恰为 `0.0`。权重向量只有第 15 个（从零计数索引 14）坐标为 1，其余为浮点零；JSON 同时保存了 85 个有序历史的动作表。它证明的只是该一次浮点枚举中记录到的零松弛候选，并没有负分离，也没有保存 `linprog` 的对偶乘子或精确可行性检查。特别是它不能推出其他九份证书、任意客户权重、任意完整策略或六人半覆盖目标的定理。

## `named_regret_single.py` 的独立目标

第二个脚本复用相同的十份证书、终局递归和 IC 矩阵，但枚举 incumbent 行动与候选行动的组合，目标改为
\[
q+c_{\mathrm{target},\,\mathrm{incumbent}}-F_a,
\]
仍受 gamma、q·w=1 和非负约束。它的意图是测试单个 regret/退款行能否独立承担当期安全缺口。源文件只包含搜索代码，没有随冻结清单提供 `named_regret_single_best.json` 或 stdout 报告；当前结果分支也没有 `floor_scan.py` 这一依赖的源快照可供同一命令复跑。因此本次可确认的是目标、约束和停止条件，不能虚构其最小值、成功次数或“桥失败”结论。该源保留为未复现的有限探索资源。

## 与已有对象的比较

`named_max_utility_gc.py` 使用的十个证书与[分数负载四主题族的全历史核验](分数负载四主题族的全历史核验--计算.md)、[严格最优覆盖支持的完整策略锥攻击](严格最优覆盖支持的完整策略锥攻击--计算.md)和[指定完整策略锥与全 SPE 正预算的原程序核验](../资料/指定完整策略锥与全SPE正预算的原程序核验--资料.md)有输入交集，但目标不同：已有对象分别核验完整历史、固定策略锥的有理安全证书或严格最优支持 LP；本对象只寻找以实际负载构造的具名 `gc`/单行 regret 预算。不能把已有对象的精确通过结果移植为本脚本的目标值，也不能把本脚本零松弛 JSON 当作已有反例的加强版本。

现有对象已经把 `fractional_actual_load_failure` 的四人 85 节点策略和 `aggregate_theta_failure` 的全历史聚合安全值分开保存；本对象的独有信息是：一套十证书统一搜索入口、`gc` 的具体负载归一化表达式、输出只落到零值的最佳 JSON，以及 regret 版本没有输出文件这一真实边界。程序依赖、源版本与冻结字节应继续通过 `clean show` 对应的 source refs 追溯，不把结果分支中的既有复现当成这三源已经运行。

## 状态、用途与接续

- 数学状态是有限浮点搜索记录，非完整证明、非一般反例、非六人 Q-CAG-HALF 结论。
- `named_max_utility_gc_best.json` 可作为后续精确 Fraction 重建的候选输入；需先补齐 `floor_scan.py`、十份证书的确切来源版本，再逐行重算 IC 与 LP 可行性，并记录有理权重和对偶证书。
- `named_regret_single.py` 只能作为待复现的探索程序保留；若后续获得依赖和 stdout，应把真实最小值、是否提前退出及输入跳过情况另写为新计算对象，不回填本页。
- 与当前六人目标的关系至多是启发/有限验证：零松弛并不证明安全桥，也不反驳 half；任何桥接必须重新证明对全部完整有序历史、所有允许的重复/平局和正确客户量词成立。
