# 动态信用一步闭合标量反例

## 精确记录

完整实读 JSON（6930 B，SHA-256 `d72cada94e17d905aaaa3035815cf84210e267bfab7a0e8b6c5563543f133674`，source ID `bbc50c6f98118dfa5b9a`，blob `bfa00556d8153cf4671109677d0023324bf3afe8`）。文件明确写 `status: not an SPE; exact counterexample only to scalar one-step closure`。

它给出 mask 权重 `2:9,3:1,4:7,5:3,8:7,9:3`，response map，root payoff 5，实际序列 `(0,2,2)`，`W=14`、`OPT=30`、`2W−OPT=-2`。每个首动作子表记录 P、G、F2、M2、profit/coverage slack 和比较 R/new 值。整体负差来自投影标量闭合，而不是已验证的完整 SPE 福利。

## 致命均衡缺口

JSON 的 `fatal_terminal_deviation` 明确指出历史 `[0,2]` 的指定动作 2 只有 `9/2`，偏离到 1 得 `19/2`。因此该 response map 不是完整 SPE。负的 `2W−OPT` 不能登记为原 Q-CAG-HALF 反例；它只精确否定“保留根所有比较与两个子局 half 标量便足以闭合根 half”的信息投影规则。

## 与障碍/探针的关系

配套 `one_step_closure_obstruction.md` 解释同一 30 客户、四主题、r=3 分离，并明确不是 SPE；`one_step_closure_probe.py` 是另一个随机浮点搜索，不是该 JSON 的生成器。`coverage_one_step_probe.py` 也属于动态-credit 但约束不同，不应合并。与 `背景新增覆盖余额与首步分解--引理` 对照，本对象说明局部单步强不等式可能失败，而精确望远镜仍可能由后续余额支付。

本对象不证明/否定六人 half、不提供完整策略反例、不迁移到 unrelated-machines；后续若要升级必须补全真实末位最佳回应和完整历史策略。
