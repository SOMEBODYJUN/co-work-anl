# 同菜单互查独立解析审查

**结论：所审 `same_menu_reply.py` 的最优索引回复平均及跨菜单末位查询没有发现致命相关性错误；该局部必要行投影合法。** 这不证明整松弛等价于 SPE，不证明六人或一般 half，也不认证数值优化的完整闭包。

审查时 `query_closure/README.md` 尚不存在；实际读取 `same_menu_reply.py` 与 `verify_same_menu.py`。本审查不依赖后者的测试结论，重新检查了所有原始行、平均次序与投影方向。所审源码哈希及独立精确枚举结果保存在 `menu_correlation_checks.json`，方便后续代码变化时识别版本。

## 1. 真实对象与唯一随机索引

固定一份完整历史纯 SPE 的实际路径 A₁,…,A₆，固定实际前四位有序历史 h。真实倒二规定者收益为 r=u₅。实际前四位客户负载为 b，实际前五位负载为 ℓ。对每个 j=0,…,5，主题 A_(j+1) 是确定的合法主题，强制其后沿原 σ 得到唯一真实末回复 R_j。给定六个合法比较索引 T₁,…,T₆，取均匀索引 I，并定义 R_*=R_(T_I)。比较索引允许重复，原策略的任意历史平局已固定在 σ 内。

对一名客户，写 `t_i=1_(x∈T_i)`、`r_i=1_(x∈R_(T_i))`、`d=Σt_i`，以及

`p_t=P(t_I=t)`、`z_t=E[1_(t_I=t)r_I]`。

于是 `0≤z_t≤p_t`。最优菜单对应的两个变量 t=0,1 分别保存这两个**联合矩**，没有把回复与同一索引主题的会员位独立化。

## 2. 关键相关项逐式检查

| 真实查询/收益 | 精确客户贡献 | 代码保存方式 |
| --- | --- | --- |
| 最优菜单自己的末位收益 | `E[r_I/(b+t_I+1)]=Σ_t z_t/(b+t+1)` | `one_variable(...,reply=M,t)` 按 t 分开，`follower=1/(b+t+1)` |
| 最优菜单源收益的拥挤折扣 | `E[t_I r_I/((b+t_I)(b+t_I+1))]` | 同一 t 条件变量与 `discount` 相乘 |
| 实际强制菜单 j 的末位查询随机回复 R_* | `E[r_I]/(b+a_j+1)` | 分母由固定实际主题 A_j 决定；对两个 t 条件变量加相同系数 |
| 最优强制菜单的末位查询固定回复 R_q，q< M | `R_q(x)E[1/(b+t_I+1)]` | `queryR,j=M,q< M` 对固定 R_q 变量加两倒数的精确概率平均 |
| 最优强制菜单查询自身比较主题 | `E[t_I/(b+t_I+1)]` | `queryOwn` 保留同一 t |
| 最优强制菜单查询不同比较索引 | `E[(d−t_I)/(5(b+t_I+1))]` | `queryOther` 保留 t 条件；未用 d/6 替代条件均值 |

第四行能够提出 `R_q(x)`，因为 q< M 时它是从固定实际主题 A_q 得到的确定目录主题，完全不依赖抽样索引 I。第三行能够提出分母，因为其源强制行动固定为实际主题 A_j。它们都不是把两个随同一 I 变化的量拆乘。

最危险的 `E[r_I/(b+t_I+1)]` 则没有这样处理。例如 b=0、`t=r=000111` 时正确值为1/4，而错误乘积 `E[r_I]E[1/(b+t_I+1)]` 为3/8。代码由两个 t 条件变量给出前者。

`structure(cross)` 排除了 q=j，所以当前没有“最优菜单查询它自己的随机回复菜单”一行，更没有两个独立随机菜单同时进入同一分母。若未来加入 `queryR,M,M`、对角或异索引最优回复互查，必须显式区分同一索引/独立索引/不同索引并重新保持相应联合矩；当前审查不能自动覆盖这种扩充。

## 3. 原始行符号与共同付款

`variable_coef` 与 `rhs_coef` 使用形式 `Σ c y≤rhs`：

- leader：`−discount·R≤r−base`，即真实源 IC `r−U(T,R)≥0`。
- price/cap：真实回复目录主题的实际末位查询价与共同K容量，分别为 `price·R≤u₆`、`R≤K`。
- queryA/queryO/queryOwn/queryOther：负的真实末位收益≤负的真实合法查询收益。
- queryR：负的自身真实末位收益加真实跨菜单查询收益≤0；前节确认其全部随机平均精确。

每个实际 u₆ 和共同 K 的代价都在最终行中按相应乘子求和。没有把每个菜单各给一份免费的 u₆/K。source leader乘子之和归一化只改变正比例，不影响合法性。

## 4. 隐藏消元方向

对非负乘子 λ，令 C 为全部rhs的加权和（含K列），c_jt为隐藏回复会员变量的加权系数。真实非负行和为

`C−Σ_actual c_j R_j−Σ_t c_*t z_t≥0`。

因 `R_j∈{0,1}`、`0≤z_t≤p_t`，有

`c_jR_j≥min(0,c_j)`、`c_*t z_t≥p_t min(0,c_*t)`。

所以代码返回

`C−Σ_actual min(0,c_j)−Σ_t p_t min(0,c_*t)≥0`，

恰为原真实行和再加非负最小化余项。代码中的 `credit+=prob*min(0,c)` 与此一致。不同回复、同主题标签或相同历史之间的策略一致性被放松，扩大隐藏域只会削弱这条必要行。按客户类型对各客户求和亦保持方向。

## 5. 独立计算与范围

审查额外枚举全部六索引会员串 t、全部六索引回复会员串 r，b=0,…,4、固定实际主题会员位0/1，精确比较表中自己的相关收益及两种跨菜单查询平均。`menu_correlation_checks.json` 记录102400次 Fraction等式检查均通过，并保留上述1/4对3/8的非独立实例。

这些计算校验实现；任意客户、目录及背景的一般合法性来自第1—4节的真实节点和非负恒等式。没有检查所有迭代主LP的精确原始/对偶数据，也没有证明分离器找到全体切面。当前结论限于代码当前的一个随机最优菜单与六个确定实际菜单的投影语义。
