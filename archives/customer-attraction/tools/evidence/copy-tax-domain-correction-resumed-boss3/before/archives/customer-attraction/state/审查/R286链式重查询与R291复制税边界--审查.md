# R286 链式重查询与 R291 复制税边界

## 1. 研究对象和阅读范围

本页合并两个同属客户吸引主线、但证明角色不同的冻结工作区。R286 提供链式回复重查询的局部分解，以及一个六人 Q-CAG-HALF 有限搜索报告；R291 检查“调和势加有序自复制税”的小域候选，并攻击一个更强的逐枝单调归纳接口。15 个来源均通过 `clean show` 导出后逐字阅读；代码实际运行记录和依赖失败保存在 [证据包](../../tools/evidence/R286-chain-R291-copy-tax-20261031/)。

当前模型仍是有限单位客户、共同有限非空目录、提供者依完整有序历史逐一选目录客户子集、终局客户在覆盖者间均分；空主题、重复、零客户、离轨历史和平局保留。这里的 `m=6` 是提供者人数，目录大小另行标记，不能混作“剩余人数”。

## 2. R286：链式回复重查询的两个有限层次

`chain_gap_microcheck.py` 直接枚举 (k=3,L=3) 的二值中间变量，强制链约束 (t_{q+1}=y_q) 后得到最小值 (-1)；解除身份约束的独立最小值为 (-2)，所以保留源—回复身份造成严格增益 (1)。这只说明在这个局部支付表达式中，不能把各枝回复完全独立消元。

`check_chain_reply_requery.py` 对 (k=3,4,5) 与 (L=2,3) 枚举所有局部成员模式，检查带身份约束的行分解。实际运行全部通过。代码中把每行的源份额、末回复份额、后继重查询项、早期价格项和二元成本项分别相减，残差恒按假设非负；这是恒等式/有限域检查，不是对任意 (k,L) 的自动证明。

这两项结果补强既有“同一真实源的末回复链式再查询”引理的局部可信度，但不提供跨根枝共同钱包，也不支付全局 SPE 中真实换子树所需的重置成本。

## 3. R286：六人有限搜索报告及实际复现边界

冻结 JSON 报告的三目录域是全部 (4^7-1=16383) 个非零兴趣重数向量（7 种非空类型、各重数 0..3），报告最小 SPE 福利比为 (9/11)，无 half 违例。四目录域只含单/双兴趣类型的 10 类、各重数 0..2，共 (3^{10}-1=59048) 个实例，报告最小比为 (8/11)，同样无 half 违例，并列出对应最差终局计数向量。

`counterexample_search_m6.py` 的真实递推依赖 `tests/audits/customer_attraction_search.py`。该模块不在当前结果树可导入路径；直接执行返回 `ModuleNotFoundError`，日志完整保留。因此这些比率在本页标为**来源报告/有限候选**，不是本批重新得到的独立证书。它们也未覆盖三点以上兴趣类型、更大目录或一般 (m)，不能推出 Q-CAG-HALF。

## 4. R291：严格分支归纳接口的反例

R291 的单位客户有六个兴趣集合，三主题、三位提供者；`verify_copy_tax_induction_boundary.py` 逐一完成 13 个历史节点的 39 个行动比较，得到最小 IC slack 为 0，规定策略的实际终局为 ((0,0,1))。根提供者的实际 payoff 与在根选主题 2 后的可信离轨 payoff 都为 (3/2)。

实际路径的福利加复制税为
\[
 W+C=17/2,
\]
而离轨根枝要求的后继利润加根到达收益与复制税合计为
\[
 26/3,
\]
二者差为 (1/6>0)。`attack_copy_tax_naive_induction.py` 以整数缩放的同一类三主题模型独立搜索，在 (m=3) 找到缩放后的预算 (51) 与离轨需求 (52)；(m=2) 没找到。这严格否定的是

> 只要实际根行动在 payoff 上最优，它的后继预算就能逐枝支付每个可信离轨根枝的独立需求。

它不否定最大调和势候选、完整 SPE 目标或六人 half；失败量来自不同枝的后继总利润和复制税同时变化。`FAILED_ROUTES.md` 的重试建议准确：必须引入跨枝共同平均、运输/联合消元或新的真实 IC，而不能把首位 IC 逐枝相加。

## 5. 候选仍被保留的有限证据

`exhaust_copy_tax_three_topics.py` 保留每个计数状态的全部可由某个完整有序历史纯 SPE 实现的终局，并为每个终局保留最小复制税。实际运行在以下有限域中未 refute
\[
 \max_q \Phi_m(q)\le W(q)+C(q):
\]

- 三主题、每种非空兴趣类型重数 0..2，(m=2,3,4,5,6)，每个 (2186) 个非零实例；
- 四主题、只取单/双兴趣类型、每类重数 0..1，(m=6)，共 (32767) 个实例。

各域的最大状态数和根终局数量已随生成 JSON 保存。`largest_gap_scaled=0` 只表示搜索中没有正的 refutation gap；它不是一般证明，也不修复上一节的逐枝单调接口。

## 6. 重启价格控制的条件算术审计

`audit_half_restart.py` 对所有二状态确定性核、价格和收益取 ([-2,2]) 的整数值，枚举 2940 个重启案例。`CA-HALF-RESTART-PRICE-CONTROL-v1` 的正向与反向最小 slack 都为 0，故边界等式在该有限域内没有算术错误。反向符号的 Q-input 消去只在 restart 是 full-price 时成立；脚本本身明确这一条件。该审计没有客户类型、完整历史策略或 SPE 完备性，因此只能归为条件引理组件。

## 7. 结论、失败机制与后续接口

本批的完整结论是：链式身份在局部有限枚举中确实产生不可忽略的耦合；复制税候选在指定小域中未被击破；但最自然的逐枝预算单调归纳已被精确三人实例击破。R286 的六人比率搜索尚缺原递推依赖，不能把 JSON 报告升级成复现证据。后续若要推进，应在保留完整历史和平局的前提下建立跨枝共同支付/联合 IC，并将 `customer_attraction_search` 依赖连同版本固定后再重跑六人域。
