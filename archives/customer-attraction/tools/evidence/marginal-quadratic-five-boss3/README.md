## 本批唯一实际算术入口

`check_saved_fields.py`执行1次，exit0、stderr空，实际耗时0.0584582160008722秒。完整argv、cwd、源码hash、stdout/stderr hash及输出hash在`review-event.json`。`review-stdout.txt`保真实摘要，`saved-field-review.json`保全部100条的重算结果以及二次点的完整精确矩阵/支配差/安全上下界。

这次入口执行的是新写的**保存数据标准库算术检查**，不导入或执行任何原main/probe/evaluate，不生成随机样本，不运行集合值BI、LP或一般全策略验证器。历史原报告耗时不算本轮运行耗时。没有失败后成功的重放或未保存输出：本批新入口只有这一次，原两入口实际运行数均0。

100条检查只证明保存的全客户曲线、目标终局动作支付及gap数值吻合；不重认证根终局SPE或前缀可达性，不重算残余曲线。当前源码`(True,)`不可能直接产出100条False记录，明确作为分支/版本差异保存。

二次点的精确结论由6×6矩阵解析推出：动作3对所有两对手背景弱支配、保底14；双对手3给任何查询最多14；恒3在全部有序历史形成完整SPE、三人总支付42，而任意SPE每人至少14。因此该点的真实最差差值为0。程序没有枚举/保存完整动作字典，正式正文的解析证明同时处理全部历史；不把此证明倒填为原浮点LP已精确认证。相同支持两状态总支付42/46还排除共同客户表示。
