# 实际读取与程序结构

`background_security_attack.py` 为 7,204 字节的 Python 程序，两个冻结提交的同一路径指向同一 blob。它只依赖 `numpy`、`scipy.optimize.linprog`、标准库缓存和随机模块；完整源已导出并以 `py_compile` 通过。JSONL 输出为 1,374 字节，两个来源定位也同字节。

程序目标是攻击一个固定背景聚合安全候选，而不是证明它。对每个随机输入，它把 `weights` 解释为非负客户兴趣掩码权重（每个非空掩码一个连续权重），`prefix` 是既有主题计数，`r` 是剩余玩家数。`outcomes(q,left)` 递归枚举终局计数：每个动作的子终局先取当前玩家收益的最小值，保留达到最大 floor 的终局集合。因此它保留多个达到门槛的续局，而不是只保一条路径。

程序随后从保留集合中选一个 `actual`（按总收益点积取最小者），计算实际 `total`；再枚举所有 `r-1` 槽静态背景，解有限零和 LP 得 `value` 和查询分布，记录

`gap = total - r * value`.

当传入 `optimize` 时，它从一个选定终局递归构造一份有序策略：选取达到 floor 的动作，偏离动作取最差威胁；形成客户权重的线性 IC 行，固定查询分布后再解客户权重 LP，并最多六轮交替更新查询。`optimized_gap` 是该固定策略、固定查询和浮点锥中的数值目标，不是原模型全称量词。

# 可复现运行

用 `clean show` 导出的源字节运行：

```text
python3 background_security_attack.py 20 optimize
```

重放输出与冻结 `background_security_attack_output.jsonl` 逐字节一致（SHA-256 `139a86d4c31ad72f0be419dd665b7153d042b80e147e95a43d498d144b653c6a`）；输出四条“best”记录，迭代索引为 0、3、6、11。最初记录为 `p=5,r=3,prefix=(0,0,1,1,3)`、`total≈42.8571`、`value≈13.1430`、`gap≈3.42815`；第4条为 `p=3,r=4,prefix=(1,0,2)`、`total≈18.3333`、`value≈4.58333`、`gap≈−3.6×10⁻¹⁵`。四条记录的 `optimized_gap` 均为 `0.0`。没有候选标记，也没有严格负的优化 gap。

# 证据边界

这是固定随机种子 `90273`、固定抽样规则、20 次重放（默认脚本可运行 500 次，但冻结输出对应 20 次 `optimize`）的有限浮点发现。`weights` 是连续掩码权重，不是单位客户计数；`outcomes` 的门槛递归提供一组候选终局，但程序没有将每个候选完全展开为独立 Fraction 的完整 SPE 证书。LP 使用浮点 SciPy，`1e−9` 阈值可能合并近似平局。

因此：

- 没有得到普遍固定背景安全定理；
- 没有得到任意目录、任意人数的完整 SPE 反例；
- 没有得到六人 Q-CAG-HALF-6 的反例或证明；
- 负 gap 的最后一位是数值近似零，不能称严格候选。

与工作区 `audit/independent_attack_checkpoint.md` 所记“全背景安全值有限压力测试”相符：本探针属于同一候选的随机发现层，不能覆盖其静态余项推导或其它固定策略攻击。后续若要升级，需要把某个候选 `weights` 恢复为整数单位客户，给每个有序历史和离轨偏离生成 Fraction 证书，并独立认证完整 SPE。

# 处置建议

建议 `integrated` 到 `archives/customer-attraction/state/审查/` 的辅助探针对象，并把源程序和 JSONL 保存在对应 `tools/evidence` 包。它的独有内容是这次随机 count-state 递归、固定背景 minimax LP 和固定策略 IC 锥交替搜索；它不覆盖 `fixed_policy_background_attack.py`、其它 audit 输出或静态余项引理，不应与这些对象合并为普遍安全结果。
