# 根菜单尾利润归纳状态的独立检查

2026-10-23。独立重构security_aggregate报告的十客户候选；没有导入其发现器、LP程序或规范SPE求解器。数学结论是所写必要条件不足，不是SPE或Q-CAG-HALF反例。

## Exact statement被否定的接口

对每个根行动a选择一个完整终局Z_a，其首行动为a；从中选根收益最大的实际行动a*。假设每个根分支的尾总利润至少2 v_2(1_a)，并且Z_a的最后行动在其对应前缀上确为最佳回复。上述条件不足以推出实际福利W>=3v_3(0)。本接口量化合法原目录/客户表与菜单，不要求菜单可由完整SPE实现；结论不能扩大到真实聚合安全桥。

## 从客户定义重建

四主题0,1,2,3；兴趣集合{0,1}有2客户，{2}有3客户，{3}有2客户，{0,3}有3客户。主题集合两两不同，主题1允许是0的内部子主题。菜单为

|根a|完整Z_a|根收益|尾总利润|精确v2(1_a)|
|---|---|---|---|---|
|0|(0,0,3)|2|5|5/2|
|1|(1,0,3)|1|6|45/16|
|2|(2,2,0)|3/2|13/2|3|
|3|(3,3,0)|2|5|5/2|

每列尾总均>=2v2；指定最后行动逐个达到四个合法末位动作的最大收益。选择根0满足菜单根最优，W=7，OPT3=10（主题0,2,3覆盖全客户）。

静态查询p=(3,0,4,3)/10对全部10个无序两槽背景保证12/5；反向背景Q在(0,3),(0,2),(2,3)取概率(3,1,1)/5，对全部四个纯查询的收益至多12/5。故v3=12/5，3v3−W=1/5>0。这个算术有匹配原始/对偶，不依赖浮点最优性。

父方另用纯Fraction高斯消元枚举静态有限LP的全部候选顶点，独立重算上述四个v2精确值与v3，结果相符。完整代码与输出在同目录check_menu_independent.py、menu_independent_check.json；有限LP求值只证明这个指定小例的数字，不外推一般福利。

## 致命SPE异议与正确信息价值

根0后的倒二玩家按菜单选0得2；若改选2，末位在(0,2)唯一最佳为3，改者得3，严格改善。因此该根菜单无法由完整SPE支持；其W>=OPT/2仍然成立。可把其余未列出的末位历史全部填成最佳回复，也修复不了这个倒二节点。

这关闭的是只保留根最优、各备选尾局总安全保证和对应末位最佳的标量归纳接口。它没有否定保留全部中继比较的递推；例如既有H_I区间状态保留每个当前合法行动的孩子收益min/max，本例倒二0行动即会被其收益上界不足排除，不能把本例当H_I/G_I反例。

下一步若继续安全聚合，须保留足以区分‘高尾总利润但倒二选择不可信’的真实菜单数据，且给能随人数推广的支付；只对这个m3坏点增加一行不算一般机制。独立内审通过；外审/新颖性未认证。
