# 身份与历史时间点

三份来源都是 facility-games 研究线的内部交接/出版评估，不是新数学证明、外部审稿或录用预测。`facility_journal_handoff` 是 2026-10-02 的研究弧地图；`facility_publication_assessment_2026-10-01` 明确只代表当日状态；`facility_publication_assessment_2026-10-06` 是后来作者级贡献、优先权与投稿组合评估。原件、SHA、manifest 和校验在 [retired-facility-publication-assessment-20261031](../../tools/evidence/retired-facility-publication-assessment-20261031/)。

# 1. 研究弧和模型分栏（handoff）

`b617008feb22473baa8`（9385 bytes，SHA `bd423a4a1a24d2ce9aa78d3e4d0d6768772211634a9c7eaf54af439e921e04a2`）把研究弧分成五条：

1. **SC-PHI-E/A**：两设施共同目录，正原子权、强制服务、完整精确客户 NE 续局；有限 continuation menu、full-catalog response cycles、heavy-pair/anchor 和 local chord 给 (\varphiarphi) 上界及显式 rational bit-time 构造。已知下界属于 IJCAI 2024，来源修正不等于首创下界。
2. **HC-2**：异质目录任意长度，两设施，factor 2 的 four-seed construction 与 near-2 integer lower family；仍标 internal candidate，且不能把原有 general-k upper bound 的 common-location co-location argument 直接用于异目录。
3. **SPARSE-RHO-ALL**：每个合法跨目录 pair 至多一个 common customer、目录长度任意，sharp (
ho=2\cos(\pi/7))；旧 HC-RHO 的“某目录至多两位置”限制已移除。它不覆盖 overlap≥2、多设施或任意 customer NE selection。
4. **SPARSE-BAD-LONG-ALL**：每个 (1\le r<\rho) 有任意长度的 genuinely r-bad exact response-closed cycle；这阻碍常数大小 exact core，但不是 kernelization/complexity lower bound，也不是 (
ho) 处的反例。
5. **Exact computation layer**：support spectrum、DP/MITM、FPT、local weak-NP-hardness 与 `EXACT-KAPPA`，用于 fixed-instance optimization 和可算范围；不等于 global (alpha^*(I)) hardness 或一般 polynomial algorithm。

handoff 强调 shared catalog 与 single-overlap 是 incomparable restrictions；(\varphiarphi,
ho,2) 是条件表而非单一参数层级。所有 upper claims 都是“存在一份完整 continuation”，不是每个 equilibrium selection 都稳定；positive weights、mandatory service、realized linear load cost 和 exact customer NE 量词必须保留。

# 2. 2026-10-01 历史评估：贡献与内部检查

`2f1be26666fdc58f0169`（14967 bytes，SHA `8d1ee7fe9f3a9e15cb8d1d6917757cc3d550594084e4ccfc9ce2714716ffa4ba`）记录“新定理改变了什么”：

- SC-PHI-E/A 关闭共同目录两设施的 sharp (\varphiarphi) upper gap，并给 polynomial-bit certificate；SC-PHI-SHARP 组合既有 lower family，不能把下界当新发现。
- SPARSE-RHO-ALL 移除目录长度限制，在 arbitrary finite nonempty catalogs、one-overlap、固定 reach-and-priority pure rule 下给 sharp (
ho)；full proof 仍需新 submission manuscript。
- HC-2 给异质目录 sharp 2 candidate 和 near-2 lower family，但仍需 author-level proof sign-off。
- SPARSE-BAD-LONG-ALL 只说明 exact response-closed core 不能统一 bounded-size，不是 kernelization hardness。
- EXACT-KAPPA/DP/MITM/FPT/local-hardness 作为 supporting algorithmic layer，不能把 certificate 当 instance-optimal proof。

该评估记录五条独立内部审查线攻击 sparse proof、long-cycle quantifiers、shared/heterogeneous proof chains、paper architecture 和 primary literature；未发现 examined chains 的 surviving fatal objection，但明确这不是 external peer review、novelty certificate 或 acceptance forecast。有限回归包括 753 shared certificates、2406 four-seed checks、500 random+1500 general heterogeneous cases、30 lazy/full comparisons、11 independent verifier tests 和 frozen bad-cycle audit；这些只能证明实现/样本行为。

它还标出两个 priority/mapping 风险：IJCAI 2024 Theorem 5/6 的 lower/hardness 适用域必须准确归属，full-version SAT reduction 使用 (m+2) facilities/heterogeneous catalogs，不能当两设施 shared-catalog hardness；2025 Krogmann dissertation 需要完整读取后才能写定 definitive originality。

# 3. 2026-10-06 扩展评估：作者级组合与投稿门槛

`6a361b6e3191e595e85f`（12375 bytes，SHA `e2bbfb8692f9940fe4d171375504bbf09b0605c86263b7573ab6cde528f8f992`）按成果和投稿组合给出更强判断，但仍写明“不是外部同行评审或绝对优先权认证”。其贡献表将：

- SC-PHI-E/A 定位为共同目录两设施 (\varphiarphi) sharp upper、polynomial bit certificate；
- SC-FIVE-DECa-HARD 定位为固定 (1\le a<\varphi) 的五地点 weak-NP-hardness（不应称 fixed constant gap-hardness）；
- SC-K-2-E 定位为任意 k 共同目录 factor 2，最佳统一常数仍在 ([\varphiarphi,2])；
- SPARSE-RHO-ALL 定位为 arbitrary catalog lengths、one-overlap sharp (
ho)；
- HC-2 定位为 arbitrary heterogeneous catalogs 的 factor-2 candidate，不由该文档自动升级；
- LOCAL-ATOM-WARDROP-k 定位为 fixed-layout atomic-to-splittable gap 工具，不能冒充 all-k SPE。

它推荐把稿件拆为共同目录 (\varphiarphi) 论文与异质 overlap (
ho/2) 论文，exact methods 作为 supporting section。现实主目标是 TEAC、Algorithmica、SIDMA；MOR 是 stretch；SICOMP/JACM/综合顶刊不应当作正常预期。这个判断是 contribution/fit opinion，不是 acceptance probability。

文档还纠正 `MF-PURE-CAP-POLY` 的过宽措辞：超载设施必须只含一个 weight>B 客户，不能再附轻客户；B=2 的强制权重 3、2 加一名可任选权重2客户，才构成弱化版本反例。修正已进入现行账本，主 theorem scope 不受影响。
