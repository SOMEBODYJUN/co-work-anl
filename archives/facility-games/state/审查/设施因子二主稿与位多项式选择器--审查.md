# 对象与范围

本对象合并三份多设施主稿审查记录和一份等权流实现源码。主稿声称的是任意有限共同地点、正实客户权重、`k≥2` 个带标签设施的两阶段模型；客户独立混合且每个 placement 的续局必须是精确 NE，设施只要求因子二的移动收益近似。实现源码是更窄的等权轻客户 on-path 选择器，不能代替主稿的 off-path 续局算法。

## 主定理与证书命题

主稿的 `thm:main`（Theorem 2.7）依赖 `lem:onpath` 和 `lem:deviation`：选定路径上，客户在每个覆盖地点的设施间均匀独立随机化；每个设施负载至少 `R/k`。任一设施单方面移动后，`lem:deviation` 构造纯精确续局，移动设施负载不超过原路径负载的两倍；把所有标签和目标地点的续局同时指定后得到 2-approximate SPE。续局的构造允许源地点消失（`q_u=1`）、空目标以及重单例，因而不能把证明简化成“保持均匀对称”。

`prop:certificate`（Proposition 2.8）只声称有理输入下的**多项式位长存储证书**和 succinct default program：显式保存选定路径与每个单方偏离的续局，其他 placement 用有限改进过程和默认规则描述。审查明确区分“证书长度多项式”与“搜索运行时间多项式”；后者在主稿中仍开放。`lem:capped` 的严格纯改善过程仅依赖有限分配空间和势函数严格下降，不能被宣传为高效搜索算法。

四个底层引理的作用分别是：`lem:transfer` 给占用／空地点的转移预算；`lem:packing` 把至多 `(h+1)a` 的预算装入至多 `h` 个封顶部分或重单例；`lem:capped` 保持移动设施的 `2a` 上界并终止；`lem:deviation` 组合三者完成任一单方移动的纯续局。它们的假设是有限地点、正权、独立混合和期望负载，且不导出一般位多项式算法。

## 编辑精度审查的三个需要修复点

完整编辑审查没有发现必须删除的冗余段，但判定当前文字 `FAIL`，原因是三个可操作的指称缺口：

1. **Case 2 的 packing 输入。** 主稿在 surviving old location `t` 处写“added clients”并立即应用 packing；实际预算是 `W_t+w(K_t)`，应明确输入为地点 `t` 的全部原分配客户端与新加入客户端之并（等价地明确 `J_t∪K_t`），否则读者无法唯一恢复要打包的原子集合。
2. **默认规则的客户端顺序。** 设施标签有 `F={1,…,k}` 的顺序，但客户端仅为有限集合 `I`。规则写“least-index client”前必须在模型或输入约定中固定客户端枚举；修复只需补足这一数据，不需改变势函数或续局逻辑。
3. **描述性别名替代正式编号。** “packing and cap lemmas” 应写成 `Lemmas 2.4 and 2.5`，保留短称作为括号说明即可。该问题影响交接指针精度，不是数学反例。

编辑结论只覆盖必要性和指称精度，不认证数学真值、来源正确性、优先权或外部新颖性。完成上述三项文字修复后，主稿的结构链条可按 `Construction 2.1 → Lemmas 2.2–2.6 → Theorem 2.7 → Proposition 2.8` 复核。

## 等权流源码与位复杂度

`equal_light_flow.py` 实现 `SC-K-EQUAL-LIGHT-FLOW-BOX`。输入为已按非增序排列的正整数 `q`、`c_t∈[0,1]`、所有可移动客户相同的有理 `delta∈(0,1)` 以及非空允许集合 `A_i`；空客户集也允许。实现拒绝浮点和异权，去重每个允许集合，使用精确 `Fraction`。

残量网络含 `n+m+2` 个顶点、`n+2E` 条正向单位弧（`E=Σ_i|A_i|`），恰做 `n` 次单位增广。Bellman–Ford 每次用 `O((n+m+2)(n+E))` 次整数操作；初始网络无负环，负槽成本由整数缩放处理。缩放因子是输入分母最小公倍数与 `lcm(q)` 的乘积，其二进制长度受输入位长总和控制；容量不依赖数值大小，故没有按重数展开的循环。源码显式检查完整盒、home 不等式、所有原始选项的精确 NE、不分割客户、槽前缀以及流目标恒等式。

该实现只提供 normalized on-path selector。仓库的完整 executable continuation 另有有限 off-path 程序，其运行时间不能由此模块的位多项式界推出。实现的算法正确性因此应与主稿的证书命题分开记录：前者是等权子类的可复现选择器，后者是任意正权模型的多项式长度描述。

## 接续与处置

四源均实际阅读并保留独有内容：主定理、证书命题和编辑修复作为 `state/审查` 对象；源码的精确接口与复杂度作为实现证据。第三阶段建立关系时，应把 `equal_light_flow.py` 标为主稿 on-path 选择器的受限实现，并明确它不证明一般异权或 off-path 搜索的多项式时间。
