# 学习定稿构建与分页导出的实际合同

本资源完整处理两个程序及它们的真实输入，区分语义保全、显示资源接线、分页报告和数学证明。实际最终HTML的33节完整数学保存在[逐章正文](完整阅读导出的逐章数学正文--资源.md)，元数据与现行数学身份在[绑定审查](../审查/学习定稿清单与公式审计的证据边界--审查.md)。冻结原件不因本批发现而覆盖。

完整源码为[build_reading.mjs](../../../../tools/evidence/learning-build-export/original/learning/build_reading.mjs)与[render_reading.py](../../../../tools/evidence/learning-build-export/original/learning/render_reading.py)。内容摘要、大小、两个冻结来源和实际字节校验见[source manifest](../../../../tools/evidence/learning-build-export/source-manifest.json)。这些是资源程序，不是客户NE、稳定倍率或算法最坏时间的证明检查器。

## HTML构建的输入、顺序与输出

从源码所在`learning`的父目录取仓库根，命令合同为：

```text
node learning/build_reading.mjs KATEX_DIST_DIR OUTPUT_HTML [GIT_REF]
```

前两个参数必须存在；`GIT_REF`默认字符串`main`。输入需要`marked`、指定目录下的`katex.min.js`、`katex.min.css`及CSS引用的WOFF2字体。注释要求KaTeX 0.16.11，但没有依赖锁或运行时版本断言。`marked`按`CODEX_PRIMARY_RUNTIME_NODE_MODULES`或仓库根解析。传入`GIT_REF`只参与链接及报告；程序没有读取Git以验证该引用绑定所读文件。报告日期固定为2026-10-10。

程序硬编码17个主模块：导读、README、前置、模型、01A、01B、02至12；接着硬编码15份数学附录和AUDIT，共33份。构建器不读取manifest选择或排序模块；manifest由另一个检查器用于集合覆盖比对。因此单独修改manifest不会改变生成正文，必须同步代码的列表。实际最终文件的33个模块与manifest集合相同；顺序以构建器及audit为准，不能把manifest中的顺序当作导出顺序。

对每份Markdown，程序保存原始UTF-8字节数及SHA-256，再用GFM解析标题、正文、表格、代码和数学扩展。块数学支持`$$…$$`及`\[…\]`，行内支持`$…$`及`\(…\)`。每次公式调用增加计数；`katex.renderToString`使用`displayMode`、`throwOnError:true`、`strict:'ignore'`、`trust:false`。解析失败会记录来源、TeX及错误消息，并先返回代码形式占位。

仅用于渲染的三个规范化规则是：将`\mspace{…mu}`换为对应`\mkern…mu`；把`\tag{SPE_\alpha}`改成文字模式的标签；多列`split`换为`aligned`。它们不修改源Markdown。实际audit只有9次mu间距转换：模型1次、任意k1次、工具6次、工作坊1次；其余两类在该次记录中没有触发。新语义绑定比较按同样规范化逐公式、逐位置核对，不能只比较公式总数。

标题锚点用原Markdown标题文本转小写、去HTML及非字母数字等符号、合并空格，同名标题后加计数，再前缀`source-i--`。链接处理保留HTTP/HTTPS、mailto、data；其他链接相对当前源文件规范化。目标属于33份时改为内部章节或精确标题锚点，标题找不到则计入fallback并回退章节入口；目标不在33份时改为指定Git引用下的GitHub源码链接，并添加新窗口及noopener。它不把代码或论文内容下载到HTML。实际323条链接中156条为内部链接；全部513个ID唯一、内链目标存在，fallback为0。其余外链离线不保证可取。

输出次序很关键：先创建目录，写`OUTPUT_HTML.audit.json`，再检查公式错误；有错误就抛出，不写新的HTML。若路径已有旧HTML，这可能留下“新失败audit+旧HTML”的混合文件对，不能仅凭同名文件相信绑定。无错误后才写HTML；没有拒绝覆盖的保护。本次精确绑定的是13,947,168字节、SHA-256为`1077ce9ee86601a3f31f5c7893a57563793e9ecc73e116d2593a90c90a1286aa`的最终HTML。

## 实际字体缺陷：字节存在不等于规则正确

本批从该最终HTML完整抽出369,532字节CSS，并按引号及URL括号边界解析完整font-face规则。结果是：**仅1条`@font-face`，family为`KaTeX_AMS`，内部却有20个src、20个font-style和20个font-weight描述符**，其末尾还混入`line-height`、`text-indent`、`text-rendering`。基础`.katex{font:…KaTeX_Main…}`声明也不存在。完整[CSS](../../../../tools/evidence/learning-build-export/embedded.css)、[完整font-face规则](../../../../tools/evidence/learning-build-export/font-face-rule.css)、[脱去base64后的描述符顺序](../../../../tools/evidence/learning-build-export/font-face-descriptors.txt)及[完整解析](../../../../tools/evidence/learning-build-export/font-face-audit.json)均保留。

20个WOFF2载荷可全部解码，字节数合计259,792，彼此SHA均不同。`fc-scan`实际识别到以下族/样式；这证明字节身份，不证明它们在浏览器中按正确CSS被选中。

| 字体载荷序号 | 实际内部字体族 | 样式 |
| --- | --- | --- |
| 00 | KaTeX_AMS | Regular |
| 01、02 | KaTeX_Caligraphic | Bold、Regular |
| 03、04 | KaTeX_Fraktur | Bold、Regular |
| 05、06、07、08 | KaTeX_Main | Bold、Bold Italic、Italic、Regular |
| 09、10 | KaTeX_Math | Bold Italic、Italic |
| 11、12、13 | KaTeX_SansSerif | Bold、Italic、Regular |
| 14 | KaTeX_Script | Regular |
| 15、16、17、18 | KaTeX_Size1、Size2、Size3、Size4 | 各Regular |
| 19 | KaTeX_Typewriter | Regular |

各载荷的独立文件、完整SHA、声明位置与`fc-scan`结果见[资产清单](../../../../tools/evidence/learning-build-export/assets/manifest.json)。实际CSS把它们全部放在唯一的KaTeX_AMS规则中，没有各自的独立族声明。CSS还留有`0.16.11`版本字符串；这不是当前已安装相同分发包的证明。正文CJK使用Noto Serif CJK SC、Noto Serif SC、Songti SC、SimSun、serif等系统回退名，CJK字体本身未内嵌。

吞并机制对应构建器的这一实际边界：

```javascript
css.replace(/src:([^;]+);/g, (whole, s) => { /* 找WOFF2并替换整个匹配 */ })
```

如果某font-face的src是最后一个描述符且没有末尾分号，`[^;]+`不会在右花括号停止，会继续吞进下一条`@font-face{font-family:…;`。替换整个匹配后，下一字体族及两个规则间的边界消失；最后一个字体src还可能吞进基础`.katex`的font声明。这正好解释实际最终CSS的“20组src并入一条族、基础字体声明消失”结构。由于原KaTeX分发目录未随该批来源交付，机制解释是源码与实际输出相互吻合的推断；不能声称已重跑当年的完整构建环境。

[最小复现程序](../../../../tools/evidence/learning-build-export/font_rewrite_fixture.mjs)本批新运行3个合成CSS输入，使用保留载荷00/01，结果见[JSON](../../../../tools/evidence/learning-build-export/font-rewrite-fixture.json)。src末尾无分号时，实际旧正则确实把2个font-face变成1个，并删除基础KaTeX font声明；src有末尾分号及src后另有描述符的两种对照均保留2个族。它是机制复现，不是全分发包回归或实际视觉复核。

可接续的最小建议是在src匹配边界同时停止于`;`或`}`，并保留所消费的右花括号；复现里使用`/src:([^;}]+)([;}])/g`演示，三个fixture都保留两族及基础字体规则。更稳健的修复应按实际CSS声明解析，再对完整KaTeX分发包和重建HTML逐字体族、样式、载荷及可见公式验收。建议**没有**应用到冻结生成器、冻结HTML或历史视觉图；没有验证完整分发包或新浏览器显示。源码内容、公式注释和数学证明不因显示缺陷被判伪，但“资源全内嵌”“字体规则正确”“公式实际正确显示”是三个不同命题，第二个在此已经有反证，第三个本批未测。

## SVG与页面交互的实际范围

HTML没有img、image、video、object、embed、iframe或canvas。139个SVG全部位于KaTeX公式内，完整字节/结构去重后只有12种：根号横线、宽帽/宽波浪、可伸缩方括号/圆括号、竖线等数学装饰，没有独立示意图。其TeX语义已在9782公式全文中逐一保留，12种具体path与出现次数另保存在资产清单；无需把相同path的139份重复字节当成139项数学新增。独立SVG文件是lxml按HTML序列化的便利副本，`viewbox`/`preserveaspectratio`因此小写，原始精确HTML仍是视觉字节权威。

页面为静态预渲染公式，阅读时不加载KaTeX脚本。固定左侧导航宽280px、正文最大1130px；窄屏把导航转到顶部，表格与代码可横向滚动，公式块也可横滚。打印CSS用A4、上下20mm左右17mm边距、底部页码，隐藏导航/按钮，主章和附录前换页，设置标题、表行及公式避免断页。这是样式意图，不能代替分页视觉检查。

脚本在load/hashchange时解码hash，找相应元素，打开其DETAILS祖先后滚动。实际文档没有details；保留的beforeprint/afterprint代码会记录已打开的details、打印前展开、打印后恢复，但本文件中没有可供该逻辑操作的折叠块。打印按钮直接调用`window.print()`。畸形百分号编码可能使`decodeURIComponent`抛错；本批只读源码，没有声称实际触发器或浏览器交互验证。源代码没有联网请求或服务端数学求值。

## PDF渲染器的另一套输入与适配

渲染器命令合同为四个位置参数：HTML、KaTeX分发目录、CJK字体路径、PDF输出路径。注释要求WeasyPrint 70、lxml，以及与0.16.11字体度量相配的KaTeX TTF。它读取真实HTML，但会在内存DOM中作PDF专用否定符修补，保存的源HTML与TeX annotation不改。

第一种修补定位KaTeX私用字符U+E020覆盖：找其mrel祖先及关系基符号，必要时检查相邻base结构。已知映射包括`=→≠`、`∈→∉`、`∋→∌`、`≤→≰`、`≥→≱`、`<→≮`、`>→≯`、`⊂/⊃/⊆/⊇`对应否定、`∣→∤`、`∥→∦`、`≈→≉`、`≡→≢`及`~/∼→≁`。未知基符或不认识的覆盖结构会抛ValueError，不偷偷删掉斜线。第二种检查mrel里的llap斜线，把识别出的组合改成Unicode否定符。替换节点以显式CJK字体、normal样式显示，并记录替换内容及方法。它处理的是PDF后端的可见字形，不是在数学上删除否定，也不把任何NE条件重新解释。

随后从分发目录的`katex.css`取字体规则，只接受`fonts/*.ttf`路径并改为file URI；取HTML的基础`:root`自定义样式，另用给定CJK字体创建font-face，清除原第一个style，再把新样式交给WeasyPrint。因为原HTML的坏WOFF2规则被清掉、另读TTF样式，历史WeasyPrint代表图即使清晰，也不能反证原浏览器HTML的字体规则无误。

渲染器调用WeasyPrint的实际分页，然后遍历私有`page._page_box`子树，收集h1–h3 BlockBox的页码/ID/标题，以及LineBox右边界超过固定730的“溢出”记录；只保留每行前160字符。这个阈值不是从纸张内容框动态计算，也没有检查每种盒、所有表格边界或字形缺失。`line_overflows=[]`不能推出没有任何可见缺陷。它写PDF后写layout JSON，记录HTML SHA、页数、标题、行溢出、font_source文件名和Unicode否定适配记录；最后删除FontConfiguration的私有`_folder`。两个私有接口均有版本依赖，异常时也没有统一finally清理。

## 本批实际执行和复现边界

两个程序全文已读，33份实际Markdown输入和最终HTML/audit/manifest已核SHA并作全语义比对。本批只新增语义结构/资源审计、完整font-face解析、`fc-scan`字体识别及3个字体替换机制fixture；没有运行原完整构建器、PDF渲染器、数学suite或浏览器。

当前Node可取`marked 17.0.5`及`playwright 1.62.1`；KaTeX分发JS/CSS/TTF不在当前依赖中。默认及主Python均无WeasyPrint；Chromium可执行路径不存在；Noto Serif CJK SC查询退回DejaVu Sans。故当前环境不足以兑现原PDF链或浏览器链。所保WOFF2字节不能冒充渲染器需要的TTF分发及完整CJK字体。旧成功suite没有疑点而重复运行的必要，未执行的动作也不登记PASS；新审计过程及两次早期字体计数断言失败如实见[执行记录](../../../../tools/evidence/learning-build-export/execution.json)。

资源用途是让后续人员能审查输入输出、识别字体接线缺陷、重建正确显示链，并知道哪一种报告只提供结构证据。它既不补全一般盒选择器，也不升级黄金比待审长证明、异构候选、非线性软件或外审状态。
