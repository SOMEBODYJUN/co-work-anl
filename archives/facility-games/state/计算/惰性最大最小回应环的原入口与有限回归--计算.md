# 惰性最大最小回应环的原入口与有限回归

## 源码身份和适用模型

完整读取610字节`cli/lazy_ring.py`及751字节`tests/test_lazy_ring.py`，并完整旁读273行canonical `exact/mitm.py`、原MITM日志、当前半表对象和后续证明状态。两主源与本组README/三个init共6源、3972字节，逐份原字节和双冻结路线见[source-manifest](../../../../tools/evidence/lazy-ring-original-entry/source-manifest.json)。两冻结分支在这六路径内容相同，19项本地增量没有同路径新版本。

设施是两家带标签参与者，从**同一个**有限非空地点目录$S$同时选址；客户有限、权正有理、地点覆盖任意，允许空覆盖、相同地点及重复覆盖关系。覆盖后客户强制选择可达设施，独立混合并最小化包含自身完整重量的条件负载期望。设施收益为期望服务总重。目标选择一个在轨布局及每个有序布局的一份精确客户NE，而非对任意离轨选择都稳定；与CAG顺序六人纯SPE保持独立。

代码只读取`weights/locations`，把全部地点视为共同目录；没有`U1/U2`限制目录的实现，额外给这两个字段也不会生效。程序按上述有效输入假设工作，不提供`bounded_overlap`那样严格的全输入解析。静态读取可见Python索引/集合语义未排除bool和负客户索引，空目录或越界等会走底层异常；不能把研究API宣传为恶意输入验证器。CLI读取JSON十进制token为精确字符串；MITM直接API的`frac`却会把float经`str`转换，和严格拒float的其他API不同。

## 精确威胁剪枝为何成立

固定布局$(s,t)$，令$m(s,t)$是全部独立混合客户NE中第一设施负载最小值，$d(t)=\max_{s\in S}m(s,t)$。局部完整支持与单谷目标的MITM原理见[半表算法](../算法/阈值半表的精确目标与响应剪枝--算法.md)，这里不把它当一个有限纯菜单。

对每个候选目的地s，从私有负载开始，把共同客户按非增权插到当前低负载侧，平局放局部第一方，得到一个纯NE$g_{st}$。其第一负载$U(s,t)$满足

\[
m(s,t)\le U(s,t)\le R_s.
\]

纯NE理由是：若最终高负载侧有共同客户，考察其最后插入的一名、权w。插入前该侧不高，插入瞬间差不超过w；以后只有另一侧可继续增加，因此最终差不超过w，也不超过高侧更早客户的权。高侧客户无严格改善，低侧自动无改善。若高侧没有共同客户则该侧没有战略客户要检查。私有客户负载不改变这一论证。

一列t中按$U$降序扫描，维护已精确计算的最大值D。若$U(s,t)\le D$，就有$m(s,t)\le D$，可跳过指数局部求极小，但保留$g_{st}$作偏离见证。否则用MITM算真正$m$并更新。首项从D=−1开始必计算（有效输入负载非负）。扫描结束D恰$d(t)$，winner为一个真正最大最小回应；每个保留惩罚的第一负载都不超过$d(t)$。因此剪枝正确性不依赖普遍phi定理。

**平局不必给同一条环。** full的`max(range(N),key=...)`取最小编号的并列最大者；lazy按上界tuple逆序精化，在相同上界时较大编号先算，只有严格更大的真实值才替换winner。故两者可有同一d、不同response/path/ring。原测试有意只比较值，没有保证回应图逐字相同。

## 环内精确目标及完整达到

从地点0反复按已算回应前进，首次重访后取环K；访问$r\le|S|$个地点、环长$k\le r$。每个环中t的$d(t)$仍是在**全目录**取最大，并未缩成环内威胁。

对环内每个无序布局（含同址）$(s,t)$，总覆盖重F、客户NE负载差$\Delta$，精确最小化

\[
\max\left\{1,\frac{2d(t)}{F+\Delta},\frac{2d(s)}{F-\Delta}\right\}.
\]

若$d(t)+d(s)>0$，该目标单谷中心为$F(d(t)-d(s))/(d(t)+d(s))$，否则取0。零分子除零按0、正分子除零为不可行无穷；有限值和概率都为精确有理数，`float('inf')`仅作不可行哨兵，不用浮点优化有限候选。原MITM搜索全部合法NE支持，因而得到这个K内的真正最优$\alpha_K$，不是只在纯NE中优化。

若选中$(s,t)$的收益$(x,y)$满足$d(t)\le\alpha_Kx,d(s)\le\alpha_Ky$，每个第一家实际偏离使用`punish[dest,t]`，第二家使用`punish[dest,s]`。两列都已访问，因此全部目的地都有记录；即使该候选被剪，其见证收益也不超过真实d。两家实际偏离的全局有序布局在轨外不交，故可一致指定。其余布局按上述降序贪心给客户纯NE，数学上补成完整规则。

但源码**没有输出`default_continuation`字段、任意布局求值器或全部概率表**。输出保存一个在轨和$2(N-1)$条偏离；默认的上述补全来自数学解释和新核查脚本，不是原CLI已经打印了完整表。达到证书不证明$\alpha_K$或全局$\alpha^*$最优，最优性依赖完整局部搜索及候选域论证。

全局最优满足$\alpha^*\le\alpha_K$；环限制可失去全局更优布局。[显式两领导者多面体例](../定理/显式续局多面体的两领导者倍率最优化--定理.md)证明响应闭核本身不保全局最优，也不单独给统一phi界；没有据此声称已给原子设施模型的数值反例。

最多$Nr$次列极小查询，加$k(k+1)/2$次在轨查询，即$O(Nr+k^2)$；最坏仍$O(N^2)$，局部MITM仍指数依赖包括同址的共同客户数。每列还要计算N个多项式贪心上界。不存在已证的固定剪枝比例、期望运行时或一般多项式总时间。

原函数最后assert `$\alpha_K^2-\alpha_K-1\le0$`；这是候选环phi主张的运行断言，来源日志也明确依主证明。其[后续修订稿仍需定向证明审查](../审查/双设施黄金比稿的五处修订与待审证明域--审查.md)。NE、负载、倍率等许多内部核查也使用assert，`python -O`会移除；本批没有在-O下重跑这些入口，更没有把断言未触发升级为全称证明。

## 原测试实际检查什么

`test_lazy_ring.py`导入同一`mitm.py`的`game_solve`和`lazy_ring_solve`。它是两条全局路径的回归，**不是两份独立局部求解实现**：二者共用`optimize_pair`核心。seed33221生成30个输入，每个8客户、权为1..24的整数、6地点，各客户在每地点独立以0.6概率覆盖；空覆盖和同覆盖站点可出现。

每个输入只有两项显式数学断言：

1. lazy每个访问列的$d(t)$等于full对全布局计算的$d(t)$。
2. full输出倍率不大于lazy环限制倍率。

程序另外累计`pruned_responses`并打印报告；不比较response/ring/布局、概率或证书逐字相同，不检查所有平局规则，不另做独立条件成本/默认布局检查。full/lazy调用中会运行其内部assert，这仍不是测试自己提供的独立checker。

本批在外置canonical最小树真实执行一次原命令`python3 -B tests/test_lazy_ring.py`，exit0、stderr空：

\[
\texttt{lazy\_full\_checks}=30,\quad
\texttt{pruned\_responses}=350,\quad
\texttt{status}=\texttt{passed}.
\]

这些打印字段与历史`evidence/runs/2026-09-30/lazy_ring.json`的对应字段一致。旧报告的scope写NE/deviation两侧核验，本批按当前源码明确限定为调用时内部assert；原测试没有独立第三套证书实现。未修改或抹掉旧报告。

## 原CLI的完整输出及新独立核查

原CLI仅解析一个必填input、`json.load(parse_float=str)`、调用lazy求解、加`elapsed_seconds`并向stdout打印有理序列化JSON；没有`--report/--output`，本次外部捕获stdout/stderr，没有覆盖冻结证书。

实际一次`python3 -B -m facility_spe.cli.lazy_ring examples/shared/tiny.json`，exit0：

| 输出语义 | 本次实际值 |
| --- | --- |
| 状态、在轨倍率 | `exact_ring_restricted`、$\alpha=1$ |
| 访问路径、环 | $[0,4,3]$、$[4,3]$ |
| 访问列全目录d | $d(0)=32,d(4)=33,d(3)=39$ |
| 访问列回应 | $0\mapsto4,4\mapsto3,3\mapsto4$ |
| 在轨布局、收益、gap、score | $[4,3]$、$(39,33)$、6、1 |
| 统计 | 6次exact_pair_calls、12个pruned_responses、3个visited_locations |
| 在轨局部统计 | half_states=2、queries=2、candidates=1 |
| 偏离条目 | 8条，每家4条；保存common、prob_first、loads及可用gap/局部统计 |

`exact_pair_calls`同时计列极小查询与环内在轨查询；6不能读成只算了6个不同物理布局。新CLI与冻结`tiny_lazy_ring.json`对比，除`elapsed_seconds`外所有字段完全一致；本次耗时及旧耗时原数都保留，不用时间波动改写数学差异。

**方向必须保真。** 顶层`layout=[s,t]`的on_path第一负载是全局设施0；偏离条目用`deviator=0/1`，`prob_first`却总是局部`(destination,opponent)`中偏离者的概率，`loads[0]`也是其收益。第二家偏离转成全局`(opponent,destination)`方向时，须同时用$1-p$及反向loads。例如tiny的第二家去0、对手4的记录为`p=[1]`、负载$(17,32)$；全局布局$[4,0]$应是`p=[0]`、负载$(32,17)$。不能把它原样送给`deviator=1/2`、绝对设施1格式的其他检查器。

新[check_saved_lazy.py](../../../../tools/evidence/lazy-ring-original-entry/check_saved_lazy.py)只用标准库Fraction，不导入生产者或MITM核心，实际exit0：重算1个在轨、8个实际偏离的负载和逐客户条件成本，检偏离完整性/唯一性及倍率，再独立用数学贪心补其余16个有序布局，共25个完整规则profile。此默认补全是新检查程序的实际构造，不冒称原输出包含该字段。它只证明该份输入的达到，不认证全部NE最小、最优值、回应图、phi一般定理或一般程序总时间。

精确命令、cwd、exit、耗时及所有原stdout/stderr见[执行记录](../../../../tools/evidence/lazy-ring-original-entry/execution/original-entrypoints.json)与[saved-output-check](../../../../tools/evidence/lazy-ring-original-entry/execution/saved-output-check.json)。隔离树8个canonical文件逐份核原SHA；没有stub、修改测试、禁用断言或重复运行已通过的435/12 MITM自测、前批753/shared三suite及四种子suite。
