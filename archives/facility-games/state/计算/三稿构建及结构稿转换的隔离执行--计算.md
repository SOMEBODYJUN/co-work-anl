## 原统一构建程序的实际控制流

`PAPERS`固定三个键：`shared`映射`research/manuscripts/shared_catalog/main.tex`，`multiple`映射`research/manuscripts/multiple_facilities/main.tex`，`congestion`映射`research/current/weighted_congestion/structural_reconstruction/structural_methods_article.tex`。不是可自由指定任意输入文件的通用编译器。每份稿在源旁建立`.build/`；调用时继承环境，在TeX树存在时向`TEXINPUTS/TFMFONTS/T1FONTS/BSTINPUTS`前置安装树路径，另设`TEXFORMATS/TEXFONTMAPS`。若三个安装map存在，合成局部`pdftex.map`。这只使用已有安装文件，不安装包。

`kpsewhich pdflatex.fmt`若无stdout，先以`pdftex -ini -etex ... pdflatex.ini`生成局部format；只按stdout判断，不独立解释该探测的returncode。随后执行`latexmk -pdf -g -interaction=nonstopmode -halt-on-error -outdir=... source.name`。每个run合并stdout/stderr写完整局部log，非零退出抛出`SystemExit`及最后3000字符。编译成功后读取`${stem}.log`，逐行筛：包含大小写不敏感`undefined`，或行首`!`，或含`LaTeX Warning:`，或含`Overfull`。任何命中都不复制新PDF。

这是一道**字符串诊断门**，不是完整TeX诊断解析器；会拒绝某些非致命LaTeX Warning，也没有把全部可能提示都解释成失败。`Underfull`不在筛选表，因此“脚本exit0”不能表述成“所有warning/排版诊断均0”。只有返回码和该筛选都通过，才将`.build/${stem}.pdf`复制到源旁现存PDF，最后print相对仓库路径。它不改变TeX源，但确会更新PDF；三键循环没有事务回滚。

## 12个真实控制流case与原意的差别

每case为独立外部目录，源文件先记hash、源旁PDF先放旧哨兵，执行后逐一重算复制与源不变性。除结构稿使用真实TeX外，前两份只是明示非数学占位输入，避免假称重读/重编未认领论文。

| case | 原程序exit | 真实观察 |
| --- | ---: | --- |
| 显式`shared multiple congestion` | 0 | 三份目标均复制新哨兵，打印三个canonical相对路径；三源字节不变。 |
| **无参数** | **2** | `argparse`把默认list当一个choice，报`invalid choice: "['shared', 'multiple', 'congestion']"`；没有开始构建，没有复制。 |
| `--help` | 0 | 参数帮助成功，无构建/复制。 |
| 不存在的paper键 | 2 | 参数选择拒绝，无构建/复制。 |
| 探测无format | 0 | 局部format分支实际调用，`format-build.txt`存在，再执行模拟latexmk并复制congestion。 |
| `LaTeX Warning:` | 1 | 编译模拟本身成功，但诊断门拒绝，新目标未覆盖旧PDF。 |
| `Overfull` | 1 | 同上，旧目标PDF保持。 |
| 大写`Undefined` | 1 | lower-case匹配生效，旧目标PDF保持。 |

| 三稿中第二稿失败 | 1 | 第一稿已复制，第二稿旧PDF保持，第三稿未运行；**批次非原子**。 |

原README推荐的显式三键命令在接口层可用；代码想默认构建全部的用法在该Python环境实际失败。保留原代码和失败，不用新改程序冒充旧程序成功，也不为本次清洗擅改共享canonical源。需要调用旧程序时显式写三个键即可绕过这一默认参数问题；若以后修改源脚本，应独立修`nargs='*'`、`choices`与list默认值的交互并重新检查，不把它当数学错误。

每个case最终源文件hash不变；失败不覆盖**当前这一份**目标PDF，但已完成的前一稿不会回滚。没有关于中间目录全局清理、无部分输出或强制官方模板的保证。

## 复现方法与证据解释

可在新的外部工作目录执行下面的新harness；直接使用已保存的6个canonical原件及相邻manifest，不需要临时调度cache。`--repo`只读已保存的实际结构TeX/Bib。`--work`必须不存在，以免覆盖此前fixture：

```sh
python tools/evidence/manuscript-build/replay_interfaces.py \
  --cache /workspace/scratch/37f0f9248cfc/boss4-research/tools/evidence/manuscript-build/original \
  --repo /workspace/scratch/37f0f9248cfc/boss4-research \
  --work /workspace/scratch/37f0f9248cfc/manuscript-build-fresh-replay \
  --evidence /workspace/scratch/37f0f9248cfc/manuscript-build-fresh-evidence
```

本次最终run为`boss4-next-cache/manuscript-build-run-003`，exit0的harness表示其所有预期观察（包括原程序非零失败）都吻合，不能读成17个原程序全exit0。run001先验证控制流；run002将生成TeX复制动作改为只留外部工作树；最终为解除临时调度cache依赖，加入相邻来源manifest回退，用仓库内保留的原件完整执行run003。三次均没有真实编译，最终JSON和交付harness是实际最终版本，未抹除意外成功或原程序失败。

只依赖Python标准库及原两脚本；受控命令通过任务专用`MB_FIXTURE_MODE`和隔离PATH注入，不修改系统工具或安装目录，不把环境/凭据打印入证据。原程序虽读取已有TeX树，模拟后端不会读取用户稿件外私有数据。源码/程序来源与动态结果分别保存，不能拿本harness通过替代原数学证明或生产构建。
