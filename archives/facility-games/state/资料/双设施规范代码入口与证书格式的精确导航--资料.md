# 双设施规范代码入口与证书格式的精确导航

## 被保存的资源及模型

2341字节README完整列九项规范程序，三个包初始化文件各90字节、正文完全相同。所有原字节、SHA256、ID和双冻结commit/path保在[source-manifest.json](../../../../tools/evidence/lazy-ring-original-entry/source-manifest.json)。README表达规范入口及“证明、算法、证据、限制分别说明”的组织合同；它不是九条定理的证明，也不是本结果仓库的运行目录重建。

这些程序主要处理两带标签设施的原子客户模型：有限正权客户、固定地点覆盖，覆盖后强制服役；客户独立混合或由算法选纯NE，以包含自身完整重量的条件负载为成本；设施最大化期望服务权。共同目录和不同目录的算法须分开调用，完整续局是逐合法有序布局选择客户NE。代码包名称不授予CAG共同主题、六名顺序单位提供者、终局客户均分或任意纯SPE半覆盖的量词。

## 原九行入口的精确职责

下面保留README全部九项的独有用途，并链接已按实际证明/源码整理的对象；数学状态以这些对象的承重条件为准。

| 原规范路径 | 可以承接的工作与条件 | 结果/证明边界 |
| --- | --- | --- |
| `shared_phi.py` | 同一有限非空目录的P/E/T/C有限菜单、全目录菜单威胁、完整达到证书 | 实际factor及独立完整规则核验见[接续计算](../计算/共享目录原始输入与四种子入口的接续复核--计算.md)；一般phi与多项式构造仍保持[定向待审层](../审查/双设施黄金比稿的五处修订与待审证明域--审查.md) |
| `shared/four_site_fptas_hardness.py` | 从PARTITION构造两设施、四地点的正整数输入及数值间隙参数 | 只生成实例，不求NE、稳定倍率或源实例YES/NO；见[构造器合同](../计算/小目录硬度构造器与五地点样本的精确合同--计算.md)；“四地点”不是四设施 |
| `heterogeneous_two.py` | 任意两个非空目录的四守卫种子纯NE菜单、菜单回应环及给定实例factor≤2证书 | 输出达到可直接核；一般四种子坏环完备性仍是[独立义务](../计算/异构双目录四种子程序与五输入的精确复现--计算.md)，不能由README标题或有限PASS解除 |
| `local/pure.py` | 有私有底载的纯NE判据、守卫及首次反转即停的最大严格改善修复 | 它是共享局部子程序，纯修复的移动界和默认续局见[纯改善引理](../引理/两设施纯改善的移动界与默认续局--引理.md)；不是一般混合NE枚举器 |
| `local/strong_chord.py` | 精确有理的条件强交叉配额构造 | 限$R\ge r>0,r>\phi R/2,C<qr$等已声明条件；可能返回不可行证据字典，不能把它当任意布局都成功的接口；[最大原子判据](../定理/双地点强交叉配额的最大原子判据--定理.md)与普遍phi环证明分开 |
| `exact/bounded_overlap.py` | 任意双目录、所有合法布局公共客户数$\kappa$下的$3^\kappa$闭支持谱及实例最优 | 有理有限最优达到；指数参数含合法同址；`verify`只核有限达到，见[精确续局算法](../算法/双目录交叠参数下的实例最优续局--算法.md) |
| `exact/single_overlap.py` | 每个$U_1\times U_2$布局至多一名共同客户，包括同址时的完整区间最优 | 不等于“只异址单交叠”，不把受限rho的纯菜单阈值当本混合最优目标；见[区间算法](../算法/全交叉单交叠双目录的区间最优与达到检查--算法.md) |
| `exact/threshold_dp.py` | 正整数共同权下的局部伪多项式完整负载谱 | 时间含总整数重量，不是一般有理权位多项式；权类固定维ILP是另一个未实现方案，见[阈值DP对象](../算法/两设施均衡谱的阈值动态规划与权类参数化--算法.md) |
| `exact/mitm.py` | 有理公共权局部单谷目标的半表优化、共同目录所有布局的真正实例最优 | 指数级$\mathrm{poly}(\kappa)3^{\lceil\kappa/2\rceil}$；惰性入口只求选中回应环内最优，见[半表算法](../算法/阈值半表的精确目标与响应剪枝--算法.md)及[原入口计算](../计算/惰性最大最小回应环的原入口与有限回归--计算.md) |

九行不是冻结快照中全部模块的穷尽清单：`exact/shared_offdiag.py`后来用共同目录同址正规形，只把**不同地点**交叠计入指数；`cli/verify_phi.py`是生产者独立且重建所有默认布局的检查器；`cli/lazy_ring.py`是MITM环限制的薄入口。遗漏在导航表不使这些真实实现不存在，也不把它们自动算成本批新的来源完成项。

## 不可按相似字段混用的证书

README提示“三个主要证书格式保持不同”，但实际接续时还要看具体模块，不能把这个数量当格式穷尽定理：

| 生产者 | 倍率/共同客户字段 | 概率和偏离方向 |
| --- | --- | --- |
| `shared_phi` | `factor/common` | `prob_first`为全局设施1；`deviator`为1/2；独立phi检查器另核完整默认 |
| `heterogeneous_two` | `alpha/common` | 概率严格0/1，为全局设施1；偏离标签1/2；自身checker不解释默认说明 |
| `bounded_overlap`、`shared_offdiag` | `alpha/shared` | 独立混合概率为全局设施1；偏离标签1/2；达到checker不证明最优 |
| `single_overlap` | `alpha/common` | 至多一个共同客户的有理概率为全局设施1；偏离标签1/2；达到checker不验证负报告 |
| `mitm`、`lazy_ring` | 顶层`alpha`、布局在顶层；profile用`common` | 在轨按layout首家；每个偏离profile的`prob_first`和第一负载却指**偏离者**，标签0/1且显式给destination/opponent |

`alpha/common`相同也不足以兼容：异构检查器要求纯0/1和$\alpha\le2$，单交叠检查器允许有理混合并重验全部交叉单交叠。MITM的第二家偏离要反射概率和负载后，才可转成绝对设施1方向。三者都不能仅凭复制字段而通过另一模块的语义合同。

## 三个init和实际导航差异

`facility_spe/__init__.py`、`cli/__init__.py`、`local/__init__.py`完全相同，仅有指向`research/current/claims.md`的英文docstring。SHA256均为`e9632a5ae520c6d48a287c2f4a4e0d89432fc91fba6f6393e2d803b060ff9ea0`；AST没有import、函数、类、重导出或构造执行。它们与前批已读`exact/__init__.py`亦同字节。保存它们是恢复真实Python包路径所需，不是创造三个数学结果；docstring对旧claim表的引用不自动认证该表全部主张。没有用空stub取代它们。

README说输入/输出示例在根`USAGE.md`，但同一冻结快照的真实USAGE现为“使用入口：一般半覆盖与三个角色”，内容是CAG工作流程，已经没有README所指的双设施JSON示例。故本资源按原程序和真实输入对象给入口，不把失配的链接当运行说明。旁读原USAGE、迁移表和GROWTH全文及SHA保在[related-manifest](../../../../tools/evidence/lazy-ring-original-entry/related-manifest.json)，不把它们登记成本批完成来源。

迁移表准确把`astra_ring/mitm_solver.py`、`astra_ring/run_lazy_ring.py`及`astra_ring/check_lazy.py`分别映到`exact/mitm.py`、`cli/lazy_ring.py`及`tests/test_lazy_ring.py`；保原名用于追溯，不恢复第二套可互相覆盖的实现。GROWTH中的命名、证据、有限检查与证明分离原则保作来源背景，本轮以当前结果仓库三阶段协议办理，不执行旧目录重建命令。

本对象的关系是代码资源导航、实现合同及来源迁移，没有新普遍数学推导边。实际新运行及精确剪枝论证在[惰性环计算对象](../计算/惰性最大最小回应环的原入口与有限回归--计算.md)；其他表中对象保持各自审查状态。
