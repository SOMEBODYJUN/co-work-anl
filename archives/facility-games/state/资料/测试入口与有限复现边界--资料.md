# 测试入口与有限复现边界

## 来源性质

本对象完整读取两个冻结基础来源：`tests/README.md` 与 `tests/__init__.py`。前者只有一段运行入口说明，后者只有 Python 包 docstring；它们都不包含模型定义、证明、反例或新的数值结论。两冻结来源的内容按路径保持一致，重复版本不折叠其 source refs。

README 规定从仓库根目录运行四个入口：

```text
python3 -m tests.test_shared_phi
python3 -m tests.test_heterogeneous
python3 -m tests.test_four_seed
python3 -m tests.test_lazy_ring
```

它把这些命令的用途限定为有限精确证书检查和独立小支持比较；更广的审计枚举位于 `tests/audits`。默认运行只打印结果并保持 `evidence/runs/2026-09-30` 冻结记录不变；支持 `--report` 的测试应显式给新报告路径。`tests/__init__.py` 的唯一语义是“可复现检查，记录输出位于 evidence/runs/”。

## 与现有正文和证据的关系

这两个文件是入口导航和证据写入约束，和[双设施规范代码入口与证书格式的精确导航](双设施规范代码入口与证书格式的精确导航--资料.md)中的程序职责表相容；它们没有重复搬运各测试源码的断言细节。具体的 `test_shared_phi`、`test_heterogeneous`、`test_four_seed`、`test_lazy_ring` 源码、输入、运行数量、退出状态及 checker 合同，分别由相应计算对象和 `tools/evidence` 运行记录承载。本对象不把 README 列出的命令视为已经实际执行，也不把任何测试 PASS 解释成其对应数学稿的全称证明。

“冻结运行记录不被默认覆盖”是复现工作流的实质约束：新运行应保存到明确的 `--report` 或独立 evidence 目录，保留输入、程序版本、stdout/stderr、退出码和运行状态。若源码不支持 `--report`，则应由外部执行器捕获输出并单独写执行清单，不能假称 README 已提供持久化接口。

## 处置

两源均 `retained` 到本资料对象，理由是它们为全仓复现提供唯一的四入口列表、审计目录位置和冻结记录保护规则；数学内容本身是导航性重复，没有新增 theorem 或算法。后续清洗测试实现时，必须沿用本页边界：有限样本、证书核验、有限回归、默认规则重算和普遍数学证明分别记载；若测试缺少独立 checker 或只调用生产者内部断言，应在对应计算正文中明确说明。第三阶段可把该资源作为“复现入口—有限证据”节点，不创建到数学定理的自动推导边。
