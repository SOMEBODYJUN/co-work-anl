# 站点字典序搜索、受帽纯改善与完整续局的有限精确实现

## 实现对应的数学问题

[共同目录因子二定理](../定理/共同目录任意设施数因子二存在--定理.md)的存在性允许任意正实权；本实现处理显式客户、正有理权、有限非空共同地点目录和显式设施数。客户是不可拆原子，混合策略独立，覆盖时强制服务，成本包含自身全部重量。

核心 [two_exists.py](../../tools/evidence/factor-two-audit-suite/source/multi_facility_spe/two_exists.py) 给出有限精确构造；[包入口说明](../../tools/evidence/factor-two-audit-suite/source/multi_facility_spe/__init__.py)本身只有文档字符串，无初始化计算或构造器重导出；[命令行模块](../../tools/evidence/factor-two-audit-suite/source/multi_facility_spe/__main__.py)负责实例读取、方法路由和证书写出。三个文件原字节与冻结来源一致。

核心支持 \(k\ge1\)，包含原主定理 \(k\ge2\) 的全部显式输入及单设施简单扩展。全局搜索指数级，纯改善轨迹没有已证多项式步数。程序输出因子二见证，不寻找最小可能稳定倍率，也没有混合 NE 坐标极小值求解器。

## Instance：规范输入边界

Instance 存放四项：有理权元组 weights、各客户可达地点的 frozenset 元组 covers、地点数 \(m\)、设施数 \(k\)。内部构造后检查 \(m,k\ge1\)、客户权/覆盖条数一致、所有权重严格为正及地点编号在 \(0,\ldots,m-1\)。

外部 JSON 应通过 from_json 进入。它另要求：

- 顶层为对象，m、k 的真实 Python 类型为 int，所以布尔值不作为整数接受；
- clients 是显式列表，每项是对象；
- weight 的类型恰为 int 或 str，不接受浮点数或布尔值；字符串交给 Fraction 精确解析，可表示整数、分数及其支持的精确十进制形式；
- sites 是列表，其中每项真实类型为 int，随后去重成 frozenset。

零或负权、分母零、非法地点、非正维数会被拒。空客户列表、不可达客户、重复列出的可达地点均可由上述合同正确处理。直接调用数据类构造器没有 from_json 的全部类型检查；内部调用者应主动提供注解规定的 Fraction 和整数集合。

to_json 输出相同数学实例：权重变成 Fraction 的规范字符串，各客户地点集合按编号排序。它不合并不同客户，即使权重和覆盖完全相同也保留各自原子身份。

## 全局站点搜索及概率转换

site_groups 把布局映为“物理地点—设施标签列表”；可选择略去一个设施，以便得到偏离后的静止设施集合。uniform_profile 将给定合法客户站点分配转换为概率矩阵：被服务客户在本站设施各给 \(1/q_t\)，未服务行全零。pure_profile 把设施赋值转换为 0/1 矩阵。loads 按 \(\sum_iw_ip_{if}\) 计算收益，以 Fraction(0) 起始累加；本核心连零负载也保持精确 Fraction。

这些是内部转换函数，假定传入布局/赋值合法；它们不替代独立证书验证。

search_lexmax 使用 combinations_with_replacement 枚举非降地点元组，再对每个布局枚举每名已覆盖客户的全部可达已占地点，未覆盖者只有 \(-1\)。对每个候选，以各站分配总重除以该站重数形成全部设施收益的升序向量，保留严格更大的向量；平局保留最先遇到的候选。

只枚举非降布局是合法的标签对称性约化：任意带标签布局可重标为其中一个代表，排序目标及合法站点分配不变，所以达到的最优向量与全标签枚举相同。构造最终仍输出一个具体带标签元组，后续实际偏离不再按置换取商。

候选布局数为 \(\binom{k+m-1}{m-1}\)，每布局客户站点分配至多 \(m^n\)。返回的 site_allocations_evaluated 计的是这种代表枚举的候选数，不是 \(m^k\) 个标签布局上的总候选数。独立审计只比较二者最终最优向量，不要求这两个计数相同。

所选候选自动是精确客户 NE，并具全部四个转移预算，依据主定理的可行候选极值证明；搜索函数本身没有先过滤成 NE。不能把一个任意站点分配传进后续偏离函数，就期待同样保证。

## 确定装箱、严格改善及内部不变量

merge_pack 接收客户索引列表、箱数 \(q\ge1\)、阈值 \(a>0\)，要求总重不超过 \((q+1)a\)。从每客户单独成箱开始，每次合并索引顺序最先找到的合重不超过 \(2a\) 的两箱，直到不能再合并。它断言最后箱数至多 \(q\)，每箱至多 \(2a\) 或为单原子。正确性是[原子装箱引理](../引理/原子装箱与受帽纯均衡修复--引理.md)，不调用最优装箱求解器。

pure_improve 先按给定纯分配建立精确负载和每客户可达设施表，并检查每名已覆盖客户确在可达设施、未覆盖客户用 \(-1\)。每步按客户编号扫描，选择第一名有严格改善的客户；在其其他可达设施中选背景负载最小者，以设施编号打破平局。若原设施为 \(h\)、目标为 \(g\)，只有

\[
L_g+w_i<L_h
\]

时才移动。每步断言平方负载和严格降低，更新赋值和两端负载，计数步骤但不保存整条轨迹。

可选参数 cap 提供共同负载上界。若给定 cap，程序识别当前已服务且重量大于 cap 的客户，断言它们各自独占设施、其他设施负载至多 cap，并可断言指定偏离者不在重设施集合中。每步再检查这些重客户位置和独占性不变，普通设施仍保帽。它检查的是“设施只有该重客户”，而非“设施含一个重客户但允许额外人”。

数学上，重客户已付自身重量，不能严格改善；普通客户不能改善加入重设施；普通改善的新目标负载小于旧源负载，故保帽。有限纯分配集和平方势排除循环。cap=None 的默认分支也有限终止，但不带某次偏离的 \(2a\) 上界。断言检查不能将不满足输入合同的任意初态变成已证可修复初态。

## 每项偏离的构造及零覆盖分支

deviation_witness 的输入是由全局搜索得到的布局和站点分配，以及一个真实偏离 \(r\ne s_f\)。它先精确计算偏离者在轨收益 \(a\)，再略去该设施得到各原占地点的静止标签列表。

若 \(a=0\)，它断言所有客户的可达地点集合为空；因为任何正覆盖地点都能通过全同址候选使全局最大者最小负载为正，这正是所需的零覆盖分支。此时直接返回所有客户未服务和零步骤/零重客户统计，不进入除以 \(a\) 或装箱。

若 \(a>0\)，逐客户分类：

1. 原分配地点仍有静止设施：保留物理地点；
2. 原地点消失：若有可达静止地点，取编号最小者；否则能到新目标则先给偏离者；再否则已失去覆盖；
3. 原未覆盖但新目标覆盖：先给偏离者。

各静止地点分别调用 merge_pack，把箱放在该地点的静止标签设施上。四转移预算保证装箱前提；偏离者初始总重另被断言不超过 \(a\)。随后以 cap=\(2a\)、deviator=\(f\) 调用 pure_improve，并最终检查偏离收益不超过 \(2a\)。

返回的是精确纯赋值和实际执行统计：严格改善步数、孤立重客户数、终态负载，以及非零分支的源重数、源是否消失、目标原先是否占用、在轨收益和箱数等。零覆盖分支的统计字段较少；调用方不能假定它含全部非零字段。配套构造审计正是在非零覆盖条件下才累计相应特征。

## 证书结构与完整续局求值

construct 执行全局搜索，在轨生成站内均匀概率，对每个设施和每个不同地点生成一次偏离证书，输出 schema 为 SC-K-2-E/v1 的 JSON 可序列化对象。其内容包括：

- 规范实例和因子字符串 2；
- 在轨带标签布局、客户站点分配、概率字符串矩阵；
- 全部 \(k(m-1)\) 次实际偏离的设施/目标、纯赋值和审计统计；
- 固定默认规则声明；
- 全局搜索统计及“有限穷举、无多项式时间主张”的说明。

evaluate_continuation 读取证书中的规范实例，检查查询布局长度、整数类型和地点范围，然后按次序：

1. 查询恰为在轨布局：返回证书给出的混合概率；
2. 查询等于某个实际偏离布局：返回该条保存纯赋值；
3. 否则：每个被覆盖客户先选最小标签可达设施，调用不带 cap 的严格改善，返回其纯 NE。

这是实际求值所有布局的函数，默认分支会真正运行纯改善，不只是声明存在某个 NE。它的有限性来自模型的平方负载势，不能推成快速默认求值。

**求值器不认证输入证书。** 它未检验证书的全部概率、偏离完整性、因子、默认声明或每条保存策略的 NE 性；在轨和显式偏离分支直接使用给定数据。证书须先由[定义级检查器](../计算/原子条件成本检查与逆向纯均衡枚举--计算.md)另行核验。恶意或损坏外部 JSON 不能因为能调用求值函数就获得数学可信性。

## CLI 的准确接口与方法边界

命令行要求一个实例文件位置和 --output，--method 默认 lexmax；输出路径若已存在，在解析实例和构造之前报错拒绝覆盖。JSON 通过 Instance.from_json，相关 ValueError、KeyError、TypeError、ZeroDivisionError 转为命令行错误；文件系统错误不属于这些输入异常的统一捕获。

lexmax 直接调用本核心 construct。greedy-box 和 equal-light-flow 在被选择后才延迟导入 greedy_box.construct，分别传入 improve-return 或 equal-light-flow 的在轨方法名称。本批核实的是路由，不把未在此清洗的两个算法当作本页证明内容。等轻权方法的输出提示明确区分：其在轨流步骤有相应位多项式结论，而当前离轨/默认仍是有限过程；其他方法统一提示无总多项式时间保证。

所保存包说明原文概括 lexmax 和 greedy-box 两个完整构造均无总多项式保证。它没有通过文档字符串自动导入新方法或改变主存在定理，也不否定某个有条件在轨子步骤的多项式性。
