# 原子条件成本的精确证书检查与逆向纯均衡枚举

## 程序资源及数学任务

本对象配套[共同目录原子客户模型](../定义/共同目录任意设施数模型--定义.md)和[因子二定理](../定理/共同目录任意设施数因子二存在--定理.md)。它保存两条与主构造器分开的验证职责：

- [definition_check.py](../../tools/evidence/factor-two-reverse-review/definition_check.py) 从覆盖、策略概率和包含自身原子重量的成本定义直接核验 NE；还可穷举纯 NE、验证显式实际偏离证书及计算全局站内均匀字典序最优向量。
- [run_reverse_audit.py](../../tools/evidence/factor-two-reverse-review/run_reverse_audit.py) 使用上述定义检查器，但不导入主构造器、装箱函数或严格改善动态。它枚举小输入的所有带标签字典序并列最大候选，再直接枚举各实际偏离子博弈的全部纯 NE，检查是否存在偏离者收益不超过两倍的纯 NE。

两文件以冻结提交 68fad804ec5946cb296f77dc5b336308a66abf12 原字节保存。完整本轮输出、脚本哈希和冻结结果比较见[资源说明](../../tools/evidence/factor-two-reverse-review/README.md)及[比较记录](../../tools/evidence/factor-two-reverse-review/replay_comparison.json)。此处独立性指相对于主构造器的代码路径，不是外部评审。

## 输入前提与精确算术

调用者须提供规范实例：正整数地点数 \(m\)、本档显式 \(k\ge2\)，客户列表及其正有理权重，地点编号在 \(0,\ldots,m-1\) 范围内，每个客户的可达地点显式列出。布局是长度 \(k\) 的地点元组；混合策略为 \(n\times k\) 概率矩阵。纯赋值用设施标签 \(0,\ldots,k-1\)，未覆盖客户使用约定标记 \(-1\)。

权重和概率通过 Python 标准库 Fraction 解析和计算。本次审计数据用整数或精确有理数字符串，比较不使用浮点容差。若调用者自行传入浮点数，Fraction 会解释那个二进制浮点值；这并不保证它等于调用者原本想表示的十进制有理数。

有一个已追踪的表示类型例外：两个 lexmax 枚举函数在某站分配为空时，空和为整数零，再用 Python 除以正重数会产生 0.0；非零负载仍为 Fraction。independent_lexmax 的这个零只进入排序向量及调用者的向量相等比较。逆向程序中的零另外可进入预算右端的整数倍和 \(2L_f\)，结果仍是精确零；没有与非零 Fraction 相加或相乘后传播成非零浮点值。正覆盖输入的所选 lexmax 最小负载严格为正，所以选中见证含 0.0 只发生在零覆盖分支。因而本次检查仍为精确数值比较，但不能把实现描述成“所有中间对象的类型均是 Fraction”。

**这两个文件不是完整的原始输入模式验证器。** definition_check.py 检查了布局、概率维数及下面的数学条件，但没有逐项验证实例权重严格为正、地点/设施计数字段的精确类型或全部客户地点列表是否规范。这些属于上述调用前提。它使用 assert 进行验证；不得用关闭断言的 Python 优化模式运行并仍声称完成验证。标记转概率函数本身也不承担输入格式验证。

## 定义级函数逐项语义

### check_ne：给定布局和混合策略是否为精确客户 NE

对客户 \(i\) 计算可达设施集

\[
A_i(s)=\{f:s_f\text{ 属于客户 }i\text{ 的可达地点}\}.
\]

程序要求概率非负，不可达设施概率为零，已覆盖客户总概率为 1，未覆盖客户总概率为 0。对每个可达设施 \(f\) 直接计算

\[
c_{if}=w_i+\sum_{j\ne i}w_jp_{jf},
\]

并要求每个正概率支持设施都达到该客户可达设施上的最低条件成本。通过后返回设施收益向量

\[
L_f=\sum_iw_ip_{if}.
\]

这一检查直接保留自身完整原子权重、独立随机化和强制服务；没有把期望设施负载当成客户的条件成本。返回的是给定策略的收益，未求解全部混合 NE。

### from_pure 与 brute_pure_equilibria：有限纯 NE 列表

from_pure 将给定赋值转换成 0/1 概率矩阵。brute_pure_equilibria 对每位已覆盖客户列举全部可达设施，对未覆盖客户仅给 \(-1\)，对选项的笛卡尔积逐个调用 check_ne；不满足 NE 断言的分配被丢弃。返回所有通过的 \((\text{赋值},\text{负载})\) 对，并断言列表非空。

在规范正权模型中，非空性由平方负载势的有限严格改善定理保证。该函数对给定有限输入是完整纯 NE 枚举，最坏有 \(k^n\) 个赋值；没有枚举所有混合 NE，也没有多项式运行时间主张。

### check_certificate：一个已显示的因子证书

输入证书提供实例、在轨布局及概率、声称因子 \(\alpha\)、每个实际偏离的偏离设施/目标/纯客户赋值，以及默认规则声明。函数执行：

1. 以 check_ne 核验在轨 NE 及原收益。
2. 构造全部 \(k(m-1)\) 个实际偏离对，检查证书中的集合恰相等且条目数匹配，排除遗漏和重复。
3. 按标签只改一个坐标，检查所有实际偏离布局互异且不同于在轨；重算该子博弈的纯 NE 和收益。
4. 检查 \(\alpha\ge1\) 和每次偏离 \(L_f'\le\alpha L_f\)。若 \(L_f=0\)，不等式仍直接检查，不对零相除。
5. 返回显示证书的观测倍率，即 \(\max(1,L_f'/L_f)\) 在正原收益项上的最大值，以及检查计数。

这里的观测倍率针对**证书给出的那些纯续局**，不是固定布局在全部合法续局中的最优因子。

默认字段必须恰等于源程序的英文字符串 “least-index initial pure assignment, then strict pure best responses”，即“最小编号初始纯分配，随后严格纯最佳反应”。若 all_layouts=False（默认值），函数只检查声明字符串，不执行其余布局。若 all_layouts=True，它会对每个未被实际偏离访问的带标签布局调用 brute_pure_equilibria，以独立穷举确认那里至少有一个纯 NE；**仍不运行主构造器的默认求值函数**，也不检查某份默认函数的执行轨迹。

因此，本函数支持的正确陈述是“在轨和所列偏离证书通过定义检查，且可选地独立验证其余布局可补全”。默认算法的普遍正确性另由势证明；真实求值器的 351 布局执行属于历史 verify_delivery.py 的另一项测试，不能归到本函数头上。

### independent_lexmax：可行候选族的最佳排序向量

该函数枚举所有 \(m^k\) 个带标签布局，以及每布局中全部合法单站客户分配。每个设施收益直接用“该站分配总重除以该站设施数”计算，排序后比较，最后只返回最大升序向量。候选族包含所有可行站点分配，没有先过滤成客户 NE；这正对应证明的极值域。

该函数不返回全部并列候选。逆向审计文件另有 all_lexmax，按相同定义返回所有达到全局最大向量的 \((s,\text{站点分配},L)\)；二者的返回职责不同。

## 逆向审计实际枚举的有限域

run_reverse_audit.py 的 tiny_all_ties 依次生成：

1. \(k\in\{2,3,4,5\}\)、\(m=2\)，两名客户各自权重取 \(\{1,2,5\}\)，可达地点集合各取 \(\varnothing,\{0\},\{1\},\{0,1\}\)。共 \(4\cdot3^2\cdot4^2=576\) 个显式参数组合。
2. 使用固定随机种子 20261003 再生成 36 个三客户输入。\(k\) 取 \(\{2,3,4\}\)，\(m\) 取 \(\{2,3\}\)，每个权重为分子 \(\{1,2,7,31\}\) 与分母 \(\{1,3,5\}\) 中所选数的精确比值；各地点按代码的固定随机过程选入覆盖集合。

合计为 612 个记录输入；后 36 项没有与先前批次或彼此去重的额外保证，因此不可把跨审计批次计数直接相加为互异实例数。

对每个输入，all_lexmax 找出全部并列带标签最大者。对每个最大者：

- 生成站内均匀概率并调用 check_ne，确认所得收益等于枚举值。
- 检查所有设施及全部目标的四种转移预算；源地点重数为一时，显式加入其原客户中覆盖目标的重量。统计交叠源预算和消失源情况。
- 对每个实际偏离，缓存并枚举该标签布局的所有纯 NE，取偏离者最小收益 \(\min_{\text{纯 NE}}L_f'\)，检查其不超过 \(2L_f\)。

纯 NE 是允许的独立混合 NE 的子集。因此找到一个满足界的纯 NE 足以验证这个有限实例的存在性要求；反过来，枚举没有声称其他纯 NE 或混合 NE 都满足界，也没有证明纯极小值等于混合极小值。

代码用所有并列候选检查避免最大者平局选择掩盖问题；用直接纯枚举避免以主构造器正确为检验前提。它没有实际构造主证明的装箱或保帽轨迹，所以不能替代这些代码分支的单独实现验证。

## 对称菜单分支

symmetry_family 对 \(q=3,4,5,8,16,31,63\) 构造[同址对称菜单障碍](../障碍/同址对称续局的无界假威胁--障碍.md)三客户实例，并逐一检查：

- 所给在轨均匀概率是 NE，收益为 \(q\) 个 \((q^2+1)/q\) 加一个 \(q-\frac14\)；
- 每个标签设施的每个不同目标都有显式纯 NE，使偏离者收益为零；
- 指定的对称坏续局是 NE，偏离者收益为 \(q^2\)；
- 当 \(q\le5\) 时，全标签可行候选枚举确认所给排序向量全局最优。

“所有同址对称 NE 都迫使巨原子去偏离者”是障碍正文中的严格成本证明；程序只检查所给对称策略及有限参数，并未连续枚举全部对称混合策略。对任意 \(q\ge3\) 的结论仍依赖数学证明。

## 实际运行与复现

本次第一批已真实运行冻结 run_reverse_audit.py，不在本批重复执行。输出为：

| 检查 | 次数 |
| --- | ---: |
| 记录输入 | 612 |
| 全部带标签并列最大候选 | 1728 |
| 实际偏离纯 NE 最小收益检查 | 6845 |
| 按输入分别缓存的不同子博弈纯 NE 枚举 | 3479 |
| 转移预算检查 | 6845 |
| 正交叠源客户预算 | 83 |
| 消失源检查 | 555 |

| 对称族全部实际偏离见证 | 274 |

“3479 个不同子博弈”是每输入局部缓存数的和；不同原输入中的同名布局没有被当作同一博弈。完整 JSON 与冻结 kfac_two_reverse.json 在仅排除顶层 Python 版本字段后逐内容完全相等。源程序 SHA-256 及输出 SHA-256 均保留在比较记录。

输出的 tiny_records 保存每个输入、最优排序向量、并列候选数量和不同子博弈数量，并不保存枚举出的全部纯 NE 或每个坐标极值见证；这些是在运行中完整枚举并断言检查。symmetry_family 则另外写出每次显式零收益偏离的纯赋值。不能把整份 JSON 称作全部 6845 次极值的独立显式证书集合；要复查这些极值须运行所附穷举程序。

从仓库根可运行：

~~~sh
python3 archives/facility-games/subarchives/common-many/tools/evidence/factor-two-reverse-review/run_reverse_audit.py --output /tmp/factor_two_reverse_new.json
~~~

只需 Python 标准库及同目录检查器。命令行强制给输出路径，会建立父目录，并直接写文件；源脚本没有拒绝覆盖已有输出的保护，所以应使用新路径。不可把另一个交付 CLI 的防覆盖行为移植为此脚本的性质。
