# 因子二构造、布局障碍与交付检查的三种验证职责

## 三条程序不是同一项“独立验证”

本对象整理三个完整源程序，其原字节均保留在[审计源目录](../../tools/evidence/factor-two-audit-suite/README.md)：

| 程序 | 输入与被检对象 | 独立性及本轮状态 |
| --- | --- | --- |
| run_exact_audit.py | 调用有限构造器，检查其输出及指定有限装箱域 | 输出 NE 由独立成本检查器检查；构造本身仍由被检核心提供。本轮全文读过，未执行整批 |
| run_lexmax_barrier_audit.py | 显式坏/好布局及全部实际偏离纯见证 | 不调用主构造器；复用定义检查器与逆向全标签枚举。本轮首次独立执行，全部结果与冻结数据相符 |
| verify_delivery.py | 三批审计、保存证书、默认求值器、原始输入解析和CLI | 集成/交付验证，不是上游结构检查或外部数学审查。本轮全文读过，未执行整套 |

数学前提是[共同目录原子模型](../定义/共同目录任意设施数模型--定义.md)。核心实装的输入合同和函数含义见[有限构造算法](../算法/站点字典序搜索与完整续局有限构造--算法.md)，定义检查和纯 NE 枚举见[对应资源对象](原子条件成本检查与逆向纯均衡枚举--计算.md)。

## 一、构造审计：563 个记录输入及局部独立攻击

run_exact_audit.py 使用 Fraction 构造规范 Instance，主随机种子为 20261002。其输入集合精确分成四部分。

第一部分为两个地点、两名客户的穷举：\(k\in\{2,3,4\}\)，每名客户权重取 \(1,2,5\)，地点菜单取 \(\varnothing,\{0\},\{1\},\{0,1\}\)。共 \(3\cdot3^2\cdot4^2=432\) 个参数组合，每项开启未列布局的纯 NE 存在枚举。

第二部分为七个显式特例：

| 名称 | \(m,k\) | 权重与覆盖 |
| --- | --- | --- |
| heavy-three-sites | \(3,5\) | 权重 \(100,1,20\)，菜单 \(\{0,1\},\{0\},\{2\}\) |
| orphan-overlap | \(3,3\) | 权重 \(5,7,11,1\)，菜单 \(\{0,1\},\{1,2\},\{0,2\},\{0\}\) |
| rational | \(3,4\) | 权重 \(1/97,3/7,11/13,2/5\)，菜单 \(\{0\},\{0,1\},\{1,2\},\{2\}\) |
| single-site | \(1,7\) | 权重 \(100,2,3\)，菜单 \(\{0\},\{0\},\varnothing\) |
| zero-clients | \(3,3\) | 空客户列表 |
| unreachable-only | \(3,3\) | 权重 \(1,100\)，两个菜单均空 |
| one-facility | \(3,1\) | 权重 \(3,7,11\)，菜单 \(\{0\},\{1\},\{0,2\}\) |

七项均开启完整未列布局存在枚举和独立字典序比较。单设施测试对应核心代码 \(k\ge1\) 的扩展，不改变本档主定理原先 \(k\ge2\) 的身份。

第三部分为120个固定种子随机输入：\(m\in\{2,3\}\)，\(k\in\{2,3,4,5,6\}\)，客户数为1至6，权重分子选 \(1,2,3,7,19,101\)，分母从带重复的列表 \((1,1,2,7)\) 中选取；菜单由代码随机生成。仅前15项中满足 \(n\le4,k\le4\) 者开启完整未列布局存在枚举，前12项中满足同样小域条件者开启额外独立比较。

第四部分为 \(k=7,12,25,50\) 的四个增长族输入：三地点、三客户，权重 \(k^2,1,2k\)，菜单 \(\{0,1\},\{0\},\{2\}\)。它们不穷举未列布局，也不开独立全标签字典序枚举。总计 \(432+7+120+4=563\) 条记录。

### 每项实际做什么

每个输入先调用核心 construct，再调用 check_certificate 检查在轨和全部实际偏离策略的真实原子成本及两倍界。按上述开关，部分输入还执行：

- independent_lexmax 枚举全部标签布局和站点分配，比较其最优排序向量与构造器给出的向量；构造器只枚举标签对称代表，故不比较两者枚举计数。
- 当输入开启额外比较且 \(k,n\le4\) 时，对全部实际偏离直接枚举纯 NE，检查偏离者最小收益至多两倍原收益。
- all_layouts=True 时，对未列布局独立枚举纯 NE 确认可补全。这一步不调用实际默认求值器。

非零覆盖分支的源消失/目标是否已占、孤立重客户数、严格移动步数来自构造器返回的 audit 字段。这些特征统计不是另一条独立轨迹重建；独立检查器核验的是最终策略及收益。

### 装箱、损坏证书和保存文件

另以 \(a=1\)、箱数1至6、原子数0至5、原子权从 \(\{1/2,1,2,3,5\}\) 非降取值，筛选总重不超过箱数加1的输入，调用 merge_pack。检查每个客户索引恰出现一次、箱数不超界、每箱总重至多2或为单个超2原子；冻结记录为267个输入。此处只检查装箱，不要求这些临时客户被地点覆盖。

对一份有效证书分别作三种损坏：删除一个偏离条目；把已覆盖大客户在轨概率改全零；把某偏离的该客户改为未服务。三份都应由检查器拒绝，而不是由构造器拒绝。

程序保存四个构造输出于内存，随后读旧的 growing-k-12、heavy-three-sites、orphan-overlap、rational 证书，要求整个 JSON 与新构造输出相等，再检查证书；还要求对应示例 JSON 等于其规范 instance。它不写这些保存证书或示例文件。

程序的 --output 则没有已有文件保护，会直接写入调用者指定输出。这与下面两个审计入口的预先拒绝覆盖不同，应使用新输出路径。

### 可陈述的有限覆盖

冻结构造记录为563输入、2220实际偏离、2770未列布局存在检查、11次独立字典序比较、43次纯 NE 极值比较、267装箱输入及3份损坏证书拒绝。它不是对563个输入全部混合均衡的极值枚举；也不能把有限大 \(k=50\) 测试用作任意 \(k\) 定理证明。本轮读取源码及旧结果，未重跑此整批。

## 二、布局障碍审计：两套显式见证与六次全局枚举

run_lexmax_barrier_audit.py 的全部参数是

\[
k\in\{2,3,4,7,12\},\qquad h\in\{2,7,31,1024\}.
\]

共20个实例，按[固定字典序占用障碍](../障碍/固定字典序占用的二倍极限--障碍.md)生成 \(H,e\) 和私有锚客户，置

\[
a=(h+1)/2,\quad M=3(h+1)/4,\quad\beta=2h/(h+1).
\]

程序验证坏占用 \((0,0,2,\ldots,k-1)\) 的均匀在轨 NE 及收益 \((a,a,M,\ldots,M)\)。仅在 \(k\le4\) 且 \(h\in\{2,7\}\) 时，调用 all_lexmax 完整枚举全部标签候选，确认最优向量相等且每个并列布局都是两家于0、无人于1、各锚一家。故独立全局枚举恰为 \(3\cdot2=6\) 次。

好占用为 \((1,0,2,\ldots,k-1)\)，在轨每客户各选同编号设施。对坏、好两个占用的每一家设施和每个不同目标，程序写出数学证明中的纯赋值并用 check_ne 直接核成本。它额外断言：

- 坏占用两家0设施移至1时，偏离收益倍率恰为 \(\beta\)；
- 好占用1设施移至0时，偏离者仅得重量1；
- 其余实际偏离者收益均为零。

总见证数为

\[
2\cdot4\sum_{k\in\{2,3,4,7,12\}}k(k-1)=1552.
\]

每个结果项保留实例、\(k,h\)、两个布局、公式倍率和全部偏离纯赋值。字段 lexmax_layout_optimum=\(\beta\) 是数学证明给出的精确最优值；程序验证给定见证可达到它，**没有穷举所有在轨混合 NE**来独立求该最优值。所有混合选择下的下界由总质量和严格最佳反应证明承担。

该脚本不依赖主构造器，仅依赖定义检查器和逆向全标签枚举函数。入口在开始执行前拒绝已有 --output 文件，之后建立输出父目录并写JSON。

**本批真实运行。** 使用原字节脚本和已保留的冻结检查器/逆向函数，首次在此次清洗中执行上述20实例；1552次见证与6次全局枚举全部通过。[输出](../../tools/evidence/factor-two-audit-suite/replayed_lexmax_barrier.json)与原冻结 barrier JSON 在只排除 Python 版本后全内容完全相等，见[比较回执](../../tools/evidence/factor-two-audit-suite/barrier_replay_comparison.json)。没有重新执行先前已完成的612输入逆向审计。

## 三、交付检查：真实求值器、接口和版本记录

verify_delivery.py 以脚本位置的 parents[2] 为原仓库根，扫描包目录及 tests/multi_facility 下顶层所有 .py 做 py_compile，再在根目录旁建立临时目录。编译检查只检查Python代码可编译，不等于执行每个模块全部分支。

它以子进程依次运行上述构造审计、逆向审计和布局障碍审计，读取各输出，与根 evidence/runs 的对应冻结 JSON 比较，只删除双方顶层 python 字段；其余所有内容必须相等。随后用默认方法运行包 CLI 的 rational 示例，检查输出证书，再对同一输出路径调用一次CLI并要求返回码非零。第二次检查的直接断言是非零返回码；当前CLI源码本身另明确在输出已存在时预先报错。

### 实际完整续局求值

程序枚举 evidence/certificates/multi_facility 下所有 .json，先检查每份证书；其中 \(k\le5\) 的实例，再遍历全部 \(m^k\) 个标签布局，调用核心 evaluate_continuation，随后用 check_ne 检查返回策略。与原布局的坐标差异数至少为2者计入 default_evaluations：在同一个在轨布局的全部真实单坐标偏离已显式列入证书时，这正是默认分支。

所以此程序确实运行默认纯改善求值器，与 check_certificate(all_layouts=True) 只枚举“该子博弈存在纯 NE”不同。证书数量及求值数量取决于被扫描的实际文件集；不能把旧快照的4证书、351布局、324默认计数无条件套到新增了证书的更大目录。

### 15个原始输入拒绝及错误默认声明

从一个有效输入复制出：

| 类别 | 五个错误值 |
| --- | --- |
| 维数/列表 | m=0，k=0，m=1.5，k=True，clients为空对象而非列表 |
| 权重 | 字符串0、-1、1/0，浮点1.5，布尔True |
| 地点菜单 | \([-1]\)、\([2]\)（目录仅0和1）、\([0.5]\)、\([True]\)、字符串0 |

分别调用 Instance.from_json，要求每个触发 ValueError、TypeError 或 ZeroDivisionError，共15个。再把一份有效证书的默认声明改成未验证行为字符串，要求 check_certificate 拒绝。这是针对明确错误类的有限负例，不是对所有损坏文件或所有模式漏洞的完整检查。

### 报告字段和既有范围不能扩大

报告保存实际扫描程序的SHA-256、三批比较结果、编译数量、证书数量、真实求值数、错误输入数及CLI状态。observed_upstream_main 和“公开commit/main.patch、不是Git fetch”的描述是源码内的固定历史字符串；脚本重新运行不会自行重新观察上游。原仓库结构检查和旧回归没有在此程序中执行，它也不抓取或推送上游。

--output 已存在时，程序在运行前报错拒绝覆盖。本轮没有执行整套交付检查。历史 v2 的8程序哈希有5项与当前冻结源不同，准确比较见[冻结证据对象](因子二冻结审计记录与版本归属--计算.md)；不能因当前脚本同名或其中3个入口哈希相同，就把历史通过搬到新的全部依赖上。

## 四、已验证的19文件固定审计树

不能把这三份源码随意移到新目录就声称都独立可运行。exact和delivery使用相对脚本位置求根，还要求原包、保存证书、输入示例和冻结数据；delivery的文件glob也决定实际检查范围。

因此本批提供明确的[19文件 manifest](../../tools/evidence/factor-two-audit-suite/snapshot_manifest.json)及[重建程序](../../tools/evidence/factor-two-audit-suite/reconstruct_snapshot.py)，每项给原路径、源ID、SHA-256和长度，固定提交为 68fad804ec5946cb296f77dc5b336308a66abf12。入口调用根 work.py clean show，只导出和核哈希，不执行审计，不认领或done，不提交或推送Git。已有文件若与固定哈希不同则拒绝覆盖。

固定树包括8个程序（3核心＋5审计/检查器）、4个历史lexmax证书、对应4个示例、3个冻结审计输出。它是**明确选定的核心审计快照**，不是完整当前源树；不包含其他算法模块及后来的额外证书。默认lexmax CLI和这里三项入口的依赖闭合，greedy-box/equal-light-flow路由不在此快照支持范围。

本轮已实际执行重建入口并逐个验证全部19文件，共1,306,048字节。原相对路径已完整形成，核验记录为[reconstruction_check.json](../../tools/evidence/factor-two-audit-suite/reconstruction_check.json)。该动作不运行审计，尚未逐源清洗的输入/证书/大输出仅作为明确固定依赖引用，未因此自动done。

从结果仓库根可先运行：

~~~sh
python3 archives/facility-games/subarchives/common-many/tools/evidence/factor-two-audit-suite/reconstruct_snapshot.py --work-py work.py --destination cleanup/workspaces/reproduce-facility-core
~~~

然后可按需执行一项，新输出不覆盖历史文件：

~~~sh
python3 cleanup/workspaces/reproduce-facility-core/tests/multi_facility/run_exact_audit.py --output /tmp/facility_exact_new.json
python3 cleanup/workspaces/reproduce-facility-core/tests/multi_facility/run_lexmax_barrier_audit.py --output /tmp/facility_barrier_new.json
python3 cleanup/workspaces/reproduce-facility-core/tests/multi_facility/verify_delivery.py --output /tmp/facility_delivery_new.json
~~~

最后一条会自行执行前三批审计，不能把它视为无运行成本的结构校验；这组命令是可复现入口，不是本轮全部执行日志。当前实际新增运行仅为前节的布局障碍分支，先前逆向结果继续复用。

## 来源处置与关系

三个源的全部输入生成、检查、写读行为和报告字段均已实读，配套原字节源码、明确重建依赖、实际重建核验和新障碍复跑证据一并保存。脚本职责分别是“构造输出与有限对照”“显式障碍见证”“集成和真实续局求值”，不能合并成一次无范围的独立证明。

它们对主定理、障碍及算法对象提供有限实现证据，不参与普遍数学推导；原始数学证明、实际代码路径、历史运行和本轮执行状态各自保留。关系已判断，正式超图留第三阶段建立。
