# 构造审计与布局障碍冻结记录的逐项证据口径

## 数据对象和数学解释范围

两份JSON均来自正有理原子客户、有限共同地点目录、覆盖时强制服务、独立客户混合策略的[共同目录模型](../定义/共同目录任意设施数模型--定义.md)。设施在轨收益是预期总负载；客户纯选择成本是自身全部重量加其他客户在该设施的预期重量。有限记录承载实现证据，不能代替任意客户数、任意设施数的一般证明。

本对象完整清洗两个冻结数据源，原字节保存为 [frozen_exact.json](../../tools/evidence/factor-two-record-inventory/frozen_exact.json) 和 [frozen_lexmax_barrier.json](../../tools/evidence/factor-two-record-inventory/frozen_lexmax_barrier.json)。生成程序已另行全文整理于[三类审计职责](因子二构造审计与交付检查的验证边界--计算.md)，本页解释实际记录了什么、哪些统计可从全部记录恢复、哪些仍是历史运行摘要。

两原文件分别为372,123和527,820字节，Python字段均为3.13.5。SHA-256、逐记录清点及确切来源见[数据清点回执](../../tools/evidence/factor-two-record-inventory/record_inventory.json)。本批用根来源读取器读取全部字节、解析全部记录，并运行数据清点程序；没有重跑构造器或任何均衡搜索。

## 一、563条构造记录的完整范围

第一份顶层claim为 SC-K-2-E，evidence_kind明确为有限精确算术攻击，seed为20261002。full_proof只保存旧证明路径 research/current/multi_facility/uniform_two.md；其已整理的数学身份是[因子二存在定理](../定理/共同目录任意设施数因子二存在--定理.md)，该路径字段不把数据变成证明。

### 输入和计数分解

全部563条记录、1327个客户项均已解析。按生成程序重建输入列表，包括固定随机种子的全部120个输入，逐项与原JSON完全相等：

| 生成块 | 记录数 | 客户项数 | 实际偏离数 | 未列标签布局存在检查 | 开启完整未列布局检查的输入数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 两地点、两客户穷举 | 432 | 864 | 1296 | 2304 | 432 |
| 七个显式边界特例 | 7 | 19 | 38 | 364 | 7 |
| 固定种子随机输入 | 120 | 432 | 698 | 102 | 6 |
| 四个增长设施族 | 4 | 12 | 188 | 0 | 0 |
| 合计 | 563 | 1327 | 2220 | 2770 | 445 |

穷举块取 \(k=2,3,4\)，每名客户权重为 \(1,2,5\)，菜单为两个地点的任意子集。七个特例涵盖重原子、源地点消失后的交叠客户、分数权、单地点、零客户、全不可达及单设施。单设施项属于代码允许 \(k\ge1\) 的扩展，不改变主定理原本 \(k\ge2\) 的陈述。

随机块实际开启未列布局检查的是 random-1、4、8、11、13、14；前四个另开启独立字典序比较。增长族为 \(k=7,12,25,50\)，三客户权重 \(k^2,1,2k\)，菜单 \(\{0,1\},\{0\},\{2\}\)；未运行它们的全部标签布局检查。

当前563份规范JSON在保留客户顺序及地点编号的意义下互不相同。这不等于有563个非同构数学实例：此清点没有对客户/地点重命名取商，也不能据此把不同审计批次的条数相加成互异实例。

### 每条结果的七个字段

| 字段 | 保存的内容和边界 |
| --- | --- |
| name | 生成标签；563个标签各异，不是通用实例的数学ID |
| instance | m、k和全部原子客户的规范有理权及地点菜单 |
| on_path_layout | 搜索选出的具体带标签布局，本批均为非降标签对称代表 |
| lex_key | 全部设施收益的升序向量；不记录收益与设施标签的逐一对应，也不记录客户站点分配 |
| actual_certificate_factor | 检查器针对给定证书实际偏离算出的倍率，至少取1，详见下节 |
| actual_deviations_checked | 所有真实单设施偏离数 \(k(m-1)\) |
| unlisted_labeled_layouts_checked | 开启完整检查时为 \(m^k-1-k(m-1)\)，否则为0 |

最后一个公式来自在轨布局和全部单坐标实际偏离布局两两不同。0既可能表示没有开启完整检查，也可能表示即使开启也没有未列布局，例如单地点或单设施情形。它不是“默认求值器调用次数”：原检查器对这些子博弈枚举纯NE，以确认可以补全，没有运行默认严格改善函数。

本批逐行核对布局长度和编号、向量长度和排序、非负有理数及质量恒等式

\[
\sum_{f=1}^{k}L_f
=\sum_{i:\,A_i\cap\operatorname{im}(s)\ne\varnothing}w_i.
\]

零覆盖输入的向量全零，其余所选字典序向量全部严格正。上述数据一致性不重新认证该布局全局最优或所隐含的客户策略是NE；记录中缺少逐客户概率和站点分配，不能仅凭排序负载补造原证书。

### 实际证书倍率不是声明因子或全局最优倍率

核心证书声明的factor为2；结果中的 actual_certificate_factor 来自检查器另行计算

\[
\widehat\alpha
=\max\left(\{1\}\cup
\left\{\frac{L_f(s^{f\to r},p^{f,r})}{L_f(s,p^0)}:
L_f(s,p^0)>0,\ r\ne s_f\right\}\right).
\]

零基准收益偏离仍要通过 \(L_f'\le2L_f=0\) 的检查，但不进入除法。此量依赖证书已选的在轨和离轨策略；它不是该输入在所有布局、所有NE续局上最小可能的倍率。

563条中530条记录 \(\widehat\alpha=1\)，其余33条大于1，观测最大值为 \(101/52\)，出现在 random-82。该输入有两设施、两地点，客户权重3与101，菜单分别 \(\{1\}\) 与 \(\{0,1\}\)；记录的在轨布局为 \((1,1)\)，收益向量 \((52,52)\)。这里只陈述历史证书的观测值，不把它当全游戏下界或当前重新运行的结果。

四个增长族记录均为 \(\widehat\alpha=1\)，布局在地点0放 \(k-1\) 家、地点2放一家，向量为 \(k-1\) 个 \((k^2+1)/(k-1)\) 及一个 \(2k\)。有限增长族通过不证明任意 \(k\) 的快速构造或最佳常数。

### 独立比较和特征计数的准确单位

11次独立字典序比较来自七个特例及 random-1、4、8、11。满足 \(k\le4\)、客户数不超过4的相关实际偏离共43次纯NE坐标极小值比较；重三地点特例和单地点特例没有进入该小域极值比较。结果没有保存独立枚举的全部最优见证或这些极小值，因此可以从输入/开关恢复次数，不能仅从JSON重查每个数值比较。

顶层 feature_counts 为：

| 特征 | 历史计数 | 正确统计单位 |
| --- | ---: | --- |
| 源地点消失 | 91 | 正覆盖输入中的一次实际偏离 |
| 源地点仍有设施 | 2026 | 同上 |
| 目标原已占用 | 338 | 同上 |
| 目标原未占用 | 1779 | 同上 |
| 孤立超帽重客户 | 1470 | 各偏离构造统计的重客户数之和，可重复计同一输入原子 |
| 严格客户移动 | 885 | 各偏离纯改善步骤数之和 |

前两项与中间两项分别合为2117，而非2220。完整记录中有31个零覆盖输入，对应103次实际偏离；程序只在存在可达客户时累计上述特征，故精确等式是

\[
91+2026=338+1779=2117=2220-103.
\]

这里的零覆盖是所有客户菜单均空，包含零客户实例；不是仅某个任意布局偶然未覆盖。31个输入具体为穷举块27个、显式特例2个、随机块2个。

1470与885只存在于聚合字段，results没有保存各偏离audit或移动轨迹。本批核清了字段、代码义务和计数分母，没有从缺失轨迹独立重建这两个和。267个装箱检查、3份损坏证书拒绝亦仅保存汇总，原逐项对象和失败轨迹未嵌入本JSON；相应有限输入域和三种损坏方式在生成程序对象中完整说明。

## 二、20组布局障碍记录保存了什么

第二份claim为 SC-K-LEXMAX-BARRIER，evidence_kind明确排除把有限攻击当作全 \(k,h\) 证明。参数严格为

\[
k\in\{2,3,4,7,12\},\qquad h\in\{2,7,31,1024\}.
\]

每组有 \(m=k\) 个地点、\(k\) 名客户：重量 \(h\) 的客户可到0和1，重量1客户只到0，其余客户各独占地点 \(j=2,\ldots,k-1\)，重量为 \(3(h+1)/4\)。20组共保存112个客户项。

每组八字段为 instance、k、h、lexmax_occupancy、lexmax_layout_optimum、full_instance_optimum、exact_SPE_layout及witnesses。字段名 lexmax_occupancy 实际保存带标签布局 \((0,0,2,\ldots,k-1)\)，不是各站点设施数构成的占用计数向量；exact_SPE_layout 保存 \((1,0,2,\ldots,k-1)\)。

两个最优值字段分别保存

\[
\beta_h=\frac{2h}{h+1}\in
\left\{\frac43,\frac74,\frac{31}{16},\frac{2048}{1025}\right\},
\qquad 1.
\]

前者指固定坏布局上允许重新选择完整均衡续局的最优倍率，后者指完整实例的最优倍率。它们的最优性来自[固定字典序占用障碍证明](../障碍/固定字典序占用的二倍极限--障碍.md)；JSON和程序给出了达到上界的见证，没有穷举所有在轨混合NE来独立证出下界。

### 每一条实际偏离都明确保存

每组对profile=lexmax及profile=exact分别保存全部 \(k(k-1)\) 个真实偏离，共

\[
2\cdot4\sum_{k\in\{2,3,4,7,12\}}k(k-1)=1552
\]

条。每条包含profile、facility、target、pure_assignment、deviator_load。客户赋值是设施标签，\(-1\)只表示偏离后没有任何可达设施的客户。

本批完整检查1552条的键集合无漏无重、客户赋值长度和覆盖可行性，并直接由权重及赋值重算偏离者总负载。共15584个赋值位置，其中1276个为未服务标记。这些是数据长度和出现次数，不是新增客户数或均衡个数。

| 见证类型 | 条数 | 偏离者负载 |
| --- | ---: | --- |
| 坏布局两家地点0设施各移至1 | 40 | \(h\)，四个h各出现10次 |
| 坏布局其余实际偏离 | 736 | 0 |
| 好布局地点1设施移至0 | 20 | 1 |
| 好布局其余实际偏离 | 756 | 0 |

两种profile各776条。完整的策略向量保存在原JSON，故后续可直接独立核客户NE；这与exact报告只留排序负载及统计摘要的粒度不同。

6次全标签最优枚举对应 \(k=2,3,4\) 与 \(h=2,7\)。源报告只保存次数，没有保存这些枚举的全部并列最大者列表；小域“所有并列者具有坏占用”来自程序实际断言和已有复跑，不能把缺失列表说成JSON内已有。

## 三、本批核读、既有复跑和缺失证据分别保留

第四批已首次实际执行完整布局障碍审计，20组、1552次NE见证检查及6次全标签枚举全部通过。此次将源原JSON逐源清洗，复用那次[实际输出](../../tools/evidence/factor-two-audit-suite/replayed_lexmax_barrier.json)和[全内容比较](../../tools/evidence/factor-two-audit-suite/barrier_replay_comparison.json)：仅Python版本不同，其余JSON完全相等，没有再次运行同一套均衡实验。

本批新执行的[inspect_records.py](../../tools/evidence/factor-two-record-inventory/inspect_records.py)仅用标准库重建输入、检查全部字段、精确有理数据、实际偏离键、覆盖可行性、记录负载及统计恒等式；它不导入构造器、NE检查器或最优枚举模块，不计算最佳反应、全局最优或默认续局。输出是数据清点，不能替代已保存的均衡审计。

完整exact构造审计仍未在此次清洗运行。旧源码版本、旧报告版本以及本轮实际运行各有明确归属；完整依赖可由[19文件固定快照入口](../../tools/evidence/factor-two-audit-suite/README.md)重建，但源数据导出或hash一致不意味着程序已经执行。

两源全部字段与原字节均有正式去向；报告没有保存的证书、装箱细目、极值见证及改善轨迹明确留缺，不能用整理者补造的数据冒充原运行记录。两对象与主定理、布局障碍及实现程序的关系是有限证据、实现输出和来源追溯，不是一般数学推导前提。关系已判断，正式超图留第三阶段建立。
