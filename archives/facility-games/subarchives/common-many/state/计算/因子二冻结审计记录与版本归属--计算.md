## 一、独立抽样器的完整逻辑

程序导入的只有 itertools.product、random.Random、fractions.Fraction 和 json，没有调用交付构造器、定义检查模块、装箱例程或改善动态。它针对本模型的规范正整数权输入，自己编码纯 NE 条件。

### 占站分配及字典序见证

occupied_assignments 取布局中已占物理地点的去重排序列表。对每个客户，列出该列表与其可达菜单的交集；空交集只给 None，表示未覆盖。对各选项的笛卡尔积逐个产生可行客户站点分配。

lex_witnesses 枚举全部带标签布局，再枚举上述站点分配。每站总质量是该站所分配客户整数权之和，重数为布局中该站设施数；每个设施负载用 Fraction(站质量,重数) 精确表示，包括零也保持 Fraction。排序后记录全局最大向量及所有并列 \((\text{布局},\text{站分配},\text{站质量},\text{重数})\) 见证。这里只枚举可行候选，不先要求客户 NE，与主证明的极值域一致。

### 固定偏离布局的纯 NE 极值

min_pure_ne_deviator 对每客户枚举全部可达**标签设施**；无覆盖时仅给 None。对每个纯赋值计算整数负载 \(L_g\)，检查每名已覆盖客户 \(i\) 的现设施 \(a_i\) 对所有其他可达设施 \(j\) 满足

\[
L_{a_i}\le L_j+w_i.
\tag{1}
\]

同一家设施不作为移动目标重复加自重。这正是纯策略下包含自身原子重量的无严格改善条件；对未覆盖客户条件为空。函数遍历全部可行赋值，在所有满足 (1) 的赋值中最小化指定偏离者收益，并断言至少有一个纯 NE。

该最小值是纯 NE 子集上的坐标极小值。它不声称等于全部混合 NE 的极小值，但因纯 NE 本身是合法混合 NE，若该值 \(\le2a\)，已足以证实这个有限输入、这个在轨见证和这个偏离存在所需低收益续局。

### 实际采样域与见证截取

随机种子为 2123。程序对

\[
(m,k,n)\in\{(2,2,3),(3,3,4),(3,4,4),(4,4,5)\}
\]

每组生成 175 次输入。每个权重独立从 \(\{1,2,3,5,8,13,21\}\) 中抽取；每个客户的各地点选项由代码中的二选一随机数决定。共至多 700 次生成，所有菜单均为空的输入跳过，没有跨生成去重。

对每个剩余输入先找到全部字典序见证，再只取其列表中的**前三个，若不足三个则全取**。计数 cases 在这个内层见证循环中自增。每个所选见证中的全部设施/异址目标均检查；在轨收益 \(a>0\) 被断言，偏离纯极小收益 \(b\) 必须满足 \(b\le2a\)。

程序在模块顶层执行并向标准输出打印 JSON；没有命令行参数或输出路径选项。按当前原件复现时，应从仓库根执行：

~~~sh
python3 archives/facility-games/subarchives/common-many/tools/evidence/factor-two-historical-audits/kfac_independent.py > /tmp/kfac_independent_new.json
~~~

需使用新输出路径并保持 Python 断言开启。该过程是有限枚举，不是多项式算法；本轮只阅读并保存程序，没有执行这条命令。

## 二、独立抽样摘要的精确计数

冻结 kfac_independent.json 的全部字段为 schema_version=1、seed=2123、下表五项计数/比值，以及“有限精确检查，不是普遍证明或混合 NE 最优性结论”的限制声明。

| 字段和值 | 由代码确定的单位 |
| --- | --- |
| cases = 1319 | 实例与抽查在轨最优见证的配对次数；不是不同实例数 |
| deviations = 10162 | 所选见证全部实际偏离的检查次数 |
| max_pure_ratio = 28/15 | 所检 \(b/a\) 的最大值，其中 \(b\) 是偏离布局所有纯 NE 的最小偏离收益 |
| singleton_deviations = 1478 | 源物理地点只含一家设施的所检偏离次数 |
| macro_opportunities = 4156 | 对每次偏离累计该输入中 \(w_i>2a\) 的原子数量，不要求这些原子在该布局被服务，也不表示已执行孤立重客户构造 |

该 JSON 不保留 700 次生成的逐输入记录、被跳过次数、全部并列数量或每次偏离的极小值证书。仅凭它不能数出不同实例数或独立重查所有纯极小值。源程序和种子给出可重放路径，但本轮未重放，故不能把这些旧计数报告为新运行输出。

[后续仓库审查对象](../审查/因子二后续仓库审查与研究定位--审查.md)已经纠正原审查把 1319 写作“小实例”的表述。此处保留未改动的原 JSON，避免通过修改历史数据掩盖统计单位差异。

## 三、逆向完整冻结 JSON 的结构及覆盖

原 kfac_two_reverse.json 在本档以 frozen_reverse.json 原字节保留。它的顶层包含主命题 SC-K-2-E、第二命题 SC-K-SYMMETRIC-MENU-OBSTRUCTION、独立路径说明、有限精确证据说明、seed=20261003、python=3.13.5、summary、tiny_records 和 symmetry_family。

本轮读取整个 JSON，逐对象检查全部字段结构，并将其全部内容与已实际复跑输出比较。除顶层 Python 版本由 3.13.5 变为 3.12.14，其余完整内容相等，不只是摘要计数一致。记录见[复跑比较](../../tools/evidence/factor-two-reverse-review/replay_comparison.json)；此比较没有再运行求解审计。

本批新保存的[完整数据结构清点](../../tools/evidence/factor-two-reverse-review/frozen_data_inventory.json)还复核了 1260 个客户条目、1728 个并列候选计数之和、3479 个每输入缓存数之和，以及由各输入 \(k(m-1)\) 与并列数重建的 6845 次实际偏离数。它没有从未保存的逐见证赋值虚构重算预算成功的证据。

### 612 个小输入记录

每条 tiny_records 都恰含 instance、key、lexmax_ties、distinct_subgames；instance 含 k、m、clients；总计 1260 个客户条目都含 weight 和 sites。实际记录域为：

| \(k\) | \(m\) | 客户数 \(n\) | 记录数 |
| ---: | ---: | ---: | ---: |
| 2 | 2 | 2 | 144 |
| 3 | 2 | 2 | 144 |
| 4 | 2 | 2 | 144 |
| 5 | 2 | 2 | 144 |
| 2 | 2 | 3 | 5 |
| 3 | 2 | 3 | 6 |
| 3 | 3 | 3 | 9 |
| 4 | 2 | 3 | 9 |
| 4 | 3 | 3 | 7 |

前四行是两客户权重/覆盖的穷举域，后五行是固定种子生成的 36 个三客户记录实际分布。程序允许的随机域不等于每种参数组合都实际出现，表中没有凭空添加 \(k=2,m=3,n=3\) 的记录。

key 是原程序序列化的升序负载字符串列表；零覆盖例可含 “0.0”。这是[计算资源对象](原子条件成本检查与逆向纯均衡枚举--计算.md)已追清的精确零类型例外，原记录未被规范化改写。lexmax_ties 统计该输入全部最大候选，distinct_subgames 是该输入内缓存的不同实际偏离布局数。

summary 记录 612 输入、1728 个全部并列候选、6845 次实际偏离纯极值及6845次预算检查、3479 个按输入累计的不同子博弈、83 个正交叠源预算和555次消失源检查。tiny_records 并未保存全部候选赋值、纯 NE 列表或每次极小值；这些在原程序/本次复跑中枚举后断言，不应称完整显式证书集合。

## 四、交付 v2 回执究竟核验了什么版本

原 v2 JSON 的 schema_version 为 1、claim 为 SC-K-2-E、Python 为 3.13.5。它记录的 observed_upstream_main 是

~~~text
d196aa294cd2ef6feb75fe1e72f2593029879dab
~~~

紧随其后的说明是观察了公开 commit/main.patch，**不是 Git fetch**。因此这个字段不能证明当时已取得真实 checkout、通过写端点认证或完成推送。文件最后还明确记录初次交付 Git 访问失败，验证脚本本身不拉取或推送上游。

八项历史完整哈希、对应当前完整哈希、源 ID 以及逐项相等判断都保留在[版本对照 JSON](../../tools/evidence/factor-two-historical-audits/delivery_version_comparison.json)。这里比较的是字节身份，不推断不同版本必有错误或相同脚本的外部依赖也相同。尤其三个审计入口相同，不意味着它们导入的主构造器/检查器版本相同。

回执报告的交付检查如下：

| 历史字段 | 记录值与范围 |
| --- | --- |
| frozen_replays | kfac_two_exact、kfac_two_reverse、kfac_lexmax_barrier 三批结果在排除 Python 版本后相符 |

| complete_rule_layout_evaluations | 实际完整规则求值 351 个布局 |
| default_rule_evaluations | 上述求值中的 324 个默认布局 |

这是当时特定哈希程序的历史报告。它不是当前冻结程序全部通过相同测试的证据，也没有在本轮重新执行。默认求值器的 351/324 计数与定义检查器 all_layouts 的纯 NE **存在枚举**不同；防覆盖行为属于此交付 CLI，而非本对象保存的独立抽样器或逆向审计脚本。

原件的五条限制均保留：有限检查不是普遍证明；无多项式时间主张；无外部评审或新颖性认证；未运行原始仓库结构检查和旧回归；脚本不抓取/推送上游且初次 Git 访问失败。后续[真实仓库审查](../审查/因子二后续仓库审查与研究定位--审查.md)描述的是另一交付时点，不能把二者合并为同一次操作。

## 接续、状态与关系

若要复查独立抽样的原计数，运行原字节 kfac_independent.py，输出新文件，再与保留摘要比较，并继续按见证次数解读 1319。若要重放 v2 的整套交付结论，应先恢复该回执八个哈希所指的程序及其依赖；当前冻结版存在五项差异，不能仅因路径同名而直接宣称重放了历史版本。

逆向数据已经有本轮独立代码路径的真实重放，当前无新疑点所以不重复运行。其他两个历史执行的原件虽已完整保留、语义已解释，运行状态仍如实是“来源报告，本轮未运行”。

四个源的独有代码、统计字段、逐输入数据和版本信息均有去向；原 JSON 未被修订成更好看的计数。它们作为有限计算证据和版本来源连接主定理、障碍及审查，不充当普遍证明前提。关系已判断，正式超图留第三阶段逐边建立。
