# 模型身份和已有正文关系

三源属于 budget_nash 的克隆/合并效用模型，不是 customer-attraction、facility-games 或 weighted-congestion 的一般 PNE 定理。当前 `archives/budget-games` 已有三项目克隆反例、共享超梯度判别和 coNP 短证书正文；本批的作用是把两个原型程序和冻结输出逐字段重读、复现，并把有限/浮点证据边界写清楚。

## 1. `cloning_certificate.py`：三项目等预算克隆的 Fraction 证书

来源 ID `f8378a41186c8b785ee4`，大小 1,033 字节，SHA-256 `b516c3ba00ebb32d687257a5e4ec3b82a06457712a9fadf67dcaa6ce6561ba64`。副本为 [`cloning_certificate.py`](../../tools/evidence/retired-topic-selection-budget-nash-20261031/scripts/cloning_certificate.py)。

效用函数为

\[
u(d)=\min\{2d_0+\tfrac32d_2,\;2d_1+\tfrac32d_2\},
\]

旧配置为 \((1/4,1/4,1/2)\)，其效用为 \(5/4\)；合并后的预算配置为 \((0,0,1)\)，效用为 \(3/2\)。代码对两名 clone 各自减少一个坐标预算 \(1/4\)，再在总质量为 \(1/4\) 的网格上枚举所有 \(a/400,b/400,(100-a-b)/400\)，要求每个 clone 的偏离效用不超过旧效用。每名 clone 的网格点数为 5,151，总检查数为 10,302；所有 Fraction 断言通过。

运行输出写出 `old_utility=5/4`、`merged_utility=3/2`、`finite_strategy_checks=10302`，并把“全连续 best-response 证书”留给正文说明，而非冒称网格本身覆盖连续单纯形。源码副本运行后生成的 `cloning_certificate.json` 与该运行输出一致；它不是一个新的一般克隆不变性定理。

这条证书的数学作用是精确保存旧广凹性克隆主张的三项目资金支持反例：两个预算各自把钱放在坐标 0、1，合并后可以把总预算放在坐标 2。已有预算-games 审查已经说明该反例攻击的是已撤回/旧版本的广泛 cloning claim，不反驳修订后的线性、Leontief 或其他受限正类。当前批只复现证书，不重新认证外部论文版本。

## 2. `cloning_recognition_prototype.json`：六个 active-cell 原型手例

来源 ID `74e6dd5c8739e05dbe7b`，大小 6,653 字节，SHA-256 `e85d4e626cfea9f48076603485245390b91acb612891e233503ea3bf7107435e`。该 JSON 明示算术为 `float64 SciPy HiGHS`、正 margin 容差 `1e-9`，并明确“not a proof certificate”。六个 case 的 property 结果为：

| case | property | 关键范围 |
|---|---|---|
| `linear` | true | 1×3 系数 `[1,2,3]` |
| `Leontief_3` | true | 3×3 单位矩阵，7 个 active cells |
| `two_resources_nonsmooth` | true | 2×2 系数 `[[3,1],[1,3]]` |
| `three_resources_common_gradient` | true | `[[2,0,1],[0,2,1]]` |
| `three_resources_failure` | false | `[[2,0,1.5],[0,2,1.5]]`，delta witness `(1/3,1/3,1/3)` |
| `strictly_positive_failure` | false | `[[3,1,2.5],[1,3,2.5]]`，同一均分 witness |

失败 case 的 `examined_cells` 显示单行 active cells 可分别找到共同方向，但两行同时 active 时 `common=false`；这正是已有预算-games 正文中“各 clone 可有不同 active 超梯度，但合并需要一个共同 active 凸组合”的边界。JSON 不是连续域证明，也不应把 `property=false` 改写成所有相似矩阵均失败。

## 3. `cloning_recognition_prototype.py`：active-cell + LP 识别原型

来源 ID `b9d5f58d648f764d242a`，大小 3,118 字节，SHA-256 `837d40939d6b588921fc3e905a8c52cb5244a4dbac5c869817db803bf6143842`。副本为 [`cloning_recognition_prototype.py`](../../tools/evidence/retired-topic-selection-budget-nash-20261031/scripts/cloning_recognition_prototype.py)。

代码对行集合 \(I\) 的所有非空子集枚举 active cells；对每个坐标先用 LP 检查外部行是否能产生严格正 margin，再用 `lp_common_max` 检查所有可访问坐标是否存在一个共同 row-mixture。若某 cell 的共同 LP 不可行，返回 `property=false` 与均分 `delta_witness`。该实现是浮点 HiGHS 原型，使用 1e-9 margin 容差，没有随机采样或 seed。

本批运行六个 hand cases 后，生成 JSON 与冻结 `cloning_recognition_prototype.json` 逐字段相等；两个 failure 都返回均分 witness。这个输出支持算法接口的实际分支和失败位置，但不能替代已有 exact active-cell/共同超梯度证明，也不能给出 coNP-hardness、一般 R 的复杂度或有理位长结论。

## 结论分层、独有内容和后续

**精确有限证书：** 三项目效用旧/新值 `5/4 → 3/2`、10,302 个 Fraction 网格偏离检查和其资金支持机制。它与现有预算-games 反例正文同模型，可作为旧广泛 cloning claim 的复现证据。

**浮点原型：** 六个矩阵手例的 active-cell/共同 LP 分类、两个均分失败 witness；运行后与冻结 JSON 相等，但使用 float64 与容差，只是识别原型。

**未建立：** 没有新的连续效用分类、没有一般 cloning 定理、没有 coNP-hardness/tight complexity，也没有把旧反例推广到修订后 v3 正类。第三阶段应把本批脚本接到已有“共同超梯度合并判别”和“coNP 短证书”正文，保持 exact certificate、float prototype、外部版本边界三层分开。
