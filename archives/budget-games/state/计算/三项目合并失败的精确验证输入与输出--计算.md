# 三项目合并失败的精确验证输入与输出

## 数学证书与程序的区别

[短失败证书证明](../证明/合并不变性的短失败证书与有理位长--证明.md)对显式非负有理min-of-linear输入语言给coNP包含、正margin/BFS位长和等预算失败实现。这里两主源只是1568B Python脚本与267B固定toy结果；没有求一般输入证书、证明hardness、识别所有cloning矩阵或完整输入解析器。

脚本仅依标准库fractions.Fraction、pathlib、json，不用solver、浮点或随机；main字面数据为

$$A=((2,0,3/2),(0,2,3/2)),\quad I=S=(0,1),$$
$$\delta=(1/4,1/4,1/2),\ z=5/4,\quad
\xi^{(0)}=(1,0),\xi^{(1)}=(0,1),\quad
y_{(0,2)}=y_{(1,2)}=1.$$

**程序零基索引**的项目2是数学一基项目3；不能将JSON的键“0/1”错读为物品编号缺失。$M_{(j,s),r}=a_{rs}-a_{rj}$。

## verify实际检查和可信输入合同

函数依次assert：I/S非空、无重复、索引在R/m内；delta非负且和一、S上严格正；active行值等z、其它行严格大；每j的xi长度等|I|、非负、和一；组合梯度的j坐标在全部m坐标中最大；每个有效(j,s)的y非负（缺键按零）；逐active行累加$y_{j,s}(a_{rs}-a_{rj})$且最小值≥1。结果只在所有断言过后返回。

可信形状/类型由main字面输入保证。helper没有完整检查A非空矩形、所有A非负有理、delta长度恰m，也未强制所有传入数都是Fraction；zip可截断，不相关y键被忽略。故本函数不能原封不动宣称可验证任意不可信序列化输入的通用验证器。使用Python -O会取消assert；本次命令无-O，常规优化级零。扩展成通用工具需加这些输入校验，但本批保原代码不改写。

## 每个输出字段为何成立

两active线性值均$2(1/4)+(3/2)(1/2)=5/4$；逐坐标梯度就是两行$(2,0,3/2),(0,2,3/2)$，各对应正投坐标是最大。对每个active r，

$$(a_{r2}-a_{r0})+(a_{r2}-a_{r1})=1,$$

所以$M^Ty=(1,1)$。JSON的完整schema与值：

| 字段 | 真实值和意义 |
|---|---|
| status | “verified exactly”，只指此函数返回 |
| active_values | 两字符串“5/4” |
| coordinate_gradients | 键“0/1”对应两行有理数字符串 |
| farkas_M_transpose_y | 两字符串“1”，不是容差近似 |

JSON没有保存全部输入A/delta/xi/y、源SHA、预算D或NE策略，不能单靠它恢复完整证书；输入由对应脚本和本页给出，source/run manifests补版本绑定。程序本身也未演算单人偏离或全部预算环境；真实NE及合并严格改善由证明页承担。Farkas符号与共同LP矛盾的数学推理，不是“出现两个1就证明coNP”。
