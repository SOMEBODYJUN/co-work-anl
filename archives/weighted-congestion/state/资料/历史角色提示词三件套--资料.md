# CLEANER：历史清晰者职责

`CLEANER.md` 要求把数学材料整理成未读研究者可直接接题的自足材料：写清一般 unrelated-machine 模型、(UM)-TARGET-v1 的全量词、已知工具、方法障碍、正面接口和剩余义务；区分证明、有限测试、证书、最优性、实现、内审和外审；按 `research/current/unrelated_machines`、`research/questions`、`research/reviews`、`tests/examples/evidence/history` 分层保存。

它还要求历史来源按 `source_crosswalk` 和 `research/CATALOG` 登记，运行 build/check 脚本并在 checkpoint 后才称为保存。角色本身没有证明任何 weighted-congestion 或 unrelated-machines 命题；它是一份生产合同，且路径/命令属于迁移前仓库。

# EXTRACTOR：历史提取者职责

`EXTRACTOR.md` 规定提取者重建工具的输入、输出、量词、构造、证明、总位复杂度和失败边界，明确 Paper Fact 与仓库重构的区别；允许探索共同容量、恢复算子、交换结构、配置相关性和新表示，但不把旧博弈模型接口未经证明搬入调度。

它继承与 CLEANER 相同的旧 (UM)-TARGET-v1 模型和保存合同，要求把独立但未关闭主目标的结果按准确身份保存。这个提示词提供的是角色分工和证据纪律，未给出当前 weighted-congestion 状态、任何定理证明或新的计算结果。

# MODELS：历史模型配置说明

`MODELS.md` 仅说明当时工具可以按用户指定使用 `gpt-6-astra/ultra` 与 `gpt-6.1-sol/ultra`，要求显式配置、按实际工具能力判断模型，并在数学文件中注明贡献来源。它要求干净上下文先重构关键瓶颈，再阅读候选证明；这是一份模型路由与协作配置，不是数学模型的定义或结果。

# 当前使用边界与处置

三份提示词属于 weighted-congestion 历史目录，当前结果分支的 `archives/weighted-congestion`、`cleanup/OBJECTS.md` 和本轮 Boss2/cleaner 提示词已经替代其操作路径。它们可作为历史来源/协作协议的资源边，但不能：

* 改变当前六人客户吸引 SPE 的模型身份；
* 将旧 `UM-TARGET-v1` 导航当成当前数学结论；
* 把 CLEANER/EXTRACTOR 的角色描述或 MODELS 的模型选择升级成 weighted-congestion 定理；
* 代替实际 source read、对象正文、evidence replay、checkpoint 和 done 回执。

原始字节与清单保存在 `archives/weighted-congestion/tools/evidence/history-transition-prompts-20261031/`。处置：`integrated`，作为历史角色/模型资源保存。
