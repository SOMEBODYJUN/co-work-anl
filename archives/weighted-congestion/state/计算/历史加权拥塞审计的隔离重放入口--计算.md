# 历史加权拥塞审计的隔离重放入口

[原程序](../../tools/evidence/weighted-replay-entry/original/tests/audits/weighted_congestion/replay.py)解决的是历史审计的相邻文件路径和输出位置：把已迁移的稿件、程序、输入和证据重新放回一次性旧目录，再启动选定脚本。它本身不计算博弈成本、不搜索PNE、不核严格改善或一般证明。本批完整读4626字节原码和全部CLI/执行路径，逐条解析其实际历史注册表并与冻结inventory比对；真实运行仅`--help`和`--list`各一次，均exit0，数学审计子程序0次、Git命令0次。正常`execute`分支没有在本批运行，不能据此宣称47个被登记审计全部通过。

## 源身份、路径和真实注册表

源码SHA256为`d3bb4004b675e796817e259ac5c4c5b6de918810ebd9ea212c5bb0cb0dcd4a07`。`ROOT=Path(__file__).resolve().parents[3]`，在原层级`tests/audits/weighted_congestion/replay.py`恰定位仓库根；移动脚本而不保层级会改变ROOT。固定注册表是`ROOT/research/weighted_congestion_frontier/INTEGRATION.json`，没有CLI选项替换它。保存的[完整历史注册表依赖](../../tools/evidence/weighted-replay-entry/original/research/weighted_congestion_frontier/INTEGRATION.json)为194010字节、SHA256 `e9f9ce109aa070f105199bf62764c7688eb7d69dbe148d2c349ccc3386dda7d1`；其本源没有在本批重复认领或完成。

该版本`classification`逐旧路径给一个对象，其中`path`是迁移后的规范来源位置。程序只用这张表及其path，不使用`source_files`的170项历史来源、17分支记录、`base_main`或`completed_cleanup`来恢复版本或认证数学。所有字段原样保留；本批对注册表的处理是元数据审阅，不代表阅读、认可了表内每份数学稿或历史处置理由。

| 有path、将复制到镜像的条目 | 164 |
| 无path、跳过的历史条目 | 6 |
| 旧键以.py结尾且有path的条目 | 47个，当前规范path互不重复 |

## 选择、镜像和两个专门兼容分支

`execute(script,timeout=120)`先重读注册表。传入规范path时通过alias还原旧路径；传入旧路径时直接选择。只有旧键存在、以`.py`结尾且条目有path才接受，否则抛`ValueError`提示使用`--list`。它不接受任意未登记路径，不会自动发现后来新增的审计。

选择后对全部50个`evidence/`规范路径读字节取SHA256作为before。随后在ROOT的父目录创建`TemporaryDirectory(prefix="wc-replay-")`，对全部164个有path条目逐项执行：读`ROOT/规范path`原字节，创建镜像内旧路径的父目录，将原字节写入该旧路径。即使只运行一个短审计，也需要这164份当前文件全部可读；它没有按选定脚本依赖闭包挑子集，也没有为缺件生成完整预检报告。`--list`只需注册表，不读取这164个文件，因而列举成功不能证明实际执行依赖齐全。

正常执行分支接着在临时根调用`git init --quiet --initial-branch=main`及一次使用临时Audit身份的空提交。该副本没有设置网络remote，代码没有fetch/push；此操作是为旧审计读取Git版本提供一个本地夹具，不是恢复被冻结原稿提交。读取到的空提交身份不能当原研究版本证据。本批help/list在进入此分支前返回，没有创建临时Git仓库，也没有执行这两条命令。

选定子进程为`[sys.executable, 镜像旧脚本路径, *extra]`，cwd为临时根，继承环境并设`PYTHONDONTWRITEBYTECODE=1`。标准输出/错误均捕获为文本，超时参数默认120秒。程序没有为所有不同脚本统一传输入或输出选项，只有两项特例：

- 旧`.../odd_ring_audit/verify_linear_reset.py`追加`--output 镜像根/linear-reset-replay.json`，使用临时新输出。
- 旧`.../multicolumn_frontier/verify.py`启动前删除镜像中它相邻的`evidence.json`副本，避免该审计正确拒绝覆盖冻结同名文件；只删除临时副本。

这两项改变的是运行位置/输出兼容，不修改原审计数学代码。旧审计可能生成JSON文件，但本入口不会搜集、带出这些新文件；临时上下文结束即清除。若结果不经stdout输出，它不自动进入外层报告。

## 不变性论证及其精确限度

对每个注册项，镜像旧路径的内容与规范来源原字节相同。若被选审计的数学输入全部由镜像中这些文件及自身确定参数给出，且它按恢复的相对布局读取，迁移不改变输入的玩家权、资源多项式、策略集合或偏离定义。例如加权拥塞成本

\[
C_i(s)=\sum_{e\in s_i}c_e\!\left(\sum_{j:e\in s_j}w_j\right)
\]

只依这些数据及真实新用户集，不依文件所在目录名。相同数据由相同成本实现求出的全部指定成本、margin及精确分数保持一致；源文件hash也不因字节不变的复制而改变。这个条件性的目录恢复说明，不能替代逐脚本核对实际输入与相对路径；临时空Git提交、命令和文件绝对位置等元数据也不因此相同。

子进程正常返回后，入口记录所选规范来源文件的**当下**SHA、exit code、耗时以及截断的stdout/stderr；离开临时目录后再次对同50个规范证据路径取after。若before≠after则抛RuntimeError；相等说明这些指定证据在两次观测间字节相同，不是全仓文件不可变证明，也不是数学输出符合冻结结果的证明。它不比较子程序生成JSON与原冻结JSON，更不会检查所有分数、计数或量词。该入口也不是限制任意子程序外部访问的操作系统沙箱；这里的“隔离”指目录和默认输出位置。

入口计算before/after是对当前字节的比较，**没有将`classification[*].sha256`作为预期值校验**。本批将164个历史声明与冻结inventory的完整path版本比对，99个匹配，65个不同，后者全部是`.md`；47个登记Python源码和50个evidence路径的声明均匹配。此处是元数据hash比对，没有读取或复审全部164份当前文件，也不把65处旧声明差异称为数学错误。它实际说明注册表可继续提供旧布局映射，却不自动固定后来修订的正文/审查版本。完整版本身份仍应使用当前源码/输入/正文各自的冻结commit、path和SHA。

## CLI、报告截断和失败合同

命令行有可选位置参数script、`--list`、整型`--timeout`和`--report PATH`。`--help`由argparse直接输出并结束，在读注册表之前返回。`--list`读注册表、输出排序后的47个规范脚本路径即返回；即使同时给script/report也不进入执行分支。普通模式无script时parser报错；但它在此检查前已读取注册表，缺注册表并不会优先得到该友好提示。对timeout没有额外正数验证。

`--report`必须是新文件，先检查是否已存在，最终用`open("x")`独占写入；父目录可自动创建。无此参数仍将完整外层record作为JSON输出stdout。外层record仅含script规范path、source_path旧路径、所选源码当前hash、子程序退出码、三位小数耗时、stdout和stderr。

| 运行结果 | 实际处理 |
| --- | --- |
| 子程序正常返回0 | 形成record，之后核证据before/after，main可写新report并返回0 |
| 子程序正常返回非0 | 仍形成同样record；核证据、写report后将其退出码交给SystemExit |
| 子程序超时、复制缺件、Git命令失败等异常 | 未被该入口捕获为record；相应异常路径不会得到一次正常完成的report |
| 证据after与before不同 | 抛错，不输出一次正常成功record |

stdout只留最后**12000个字符**，stderr只留最后**4000个字符**，不是字节数；capture时先完整读入，再切尾。它没有截断标志、原始完整流的hash或完整流附件。一个大JSON的前部可能已不在报告中，不能把record.stdout当成完整可解析JSON或全数学证据。`--report`保留的是完整外层record，不能补回被切掉的子程序输出。耗时round和timeout只属运行元数据，不承担任何严格数学裁决。

原码没有统一检查被选审计的断言是否启用、其外部库版本或所有依赖hash；继承环境并只改pycache设置。故“该入口exit0”至多表明上述被选过程在当次环境下正常返回及50项证据前后相同。需要的数学认证仍应由审计自身精确断言、完整输出和针对原冻结JSON的比较分别支持。

## 本批实际核验和现有数学资源的区别

本批恢复原source层级并只放入源码与完整注册表依赖。用CPython3.12.14真实运行`--help`一次、`--list`一次，均exit0、stderr空；list逐行等于从这份实际classification生成的排序47行，无重复。每次准确命令、cwd、源码/注册表hash、完整stdout/stderr及其hash保存在[help记录](../../tools/evidence/weighted-replay-entry/cli/help-run.json)和[list记录](../../tools/evidence/weighted-replay-entry/cli/list-run.json)。没有启动任何登记数学脚本，未创建临时Git提交、未测试164文件完整执行分支，也未暗示所有47条审计已在此入口通过。

该历史47脚本集合含三玩家二次、source包络、奇环、密度、power-bridge等早期程序；不含后加cyclic_clone或decision_methods族，不能称为当前WC全部程序。各正式资源已分别保留准确的数学范围和真实执行，例如[三玩家阈值核验](三玩家整数二次例的完整阈值核验--计算.md)、[奇环四程序的实际实例与精确复算](奇环四程序的实际实例与精确复算--计算.md)与[循环复制和锚定时钟核验](循环复制与锚定时钟的精确核验--计算.md)。其中新包装入口、原数学审计和独立实现是三个不同身份；本批没有借这些既有通过记录伪称历史通用入口完成了整套运行。

当前结果分支将原件保存在各独立evidence目录，并不在仓库根重建这164条规范旧来源。仅有本资源两件原件时，help/list可用；正常execute还需完整规范源树。后续使用可按单一数学对象的已保全依赖、完整stdout/JSON、拒绝覆盖新输出及逐字段比较选择对应专用重放器。本文保留历史入口原字节及其可用条件，没有修改全局注册表或将新版包装当原版。

注册表`completed_cleanup`仍称WC-TARGET OPEN，这是历史状态。后续[同权类全前沿与全状态编译](../定理/同权类前沿全覆盖的全状态编译--定理.md)已对每个整数p≥2²⁰构造每态有严格p/10出口的游戏，否定原全类固定C的Cd/ln d目标；入口/注册表没有给出该一般证明。程序资源、数学定理、内部核验与外审/新颖性分别保留。完整[provenance](../../tools/evidence/weighted-replay-entry/provenance.json)给两冻结提交原路径和依赖身份，本批仅完成replay.py这一个源。
