# 1. 对象、程序与精确算术

本批完整阅读四个冻结源：两个 JSON 结果和两份 Python 审计脚本。结果 JSON 原始字节、脚本原始字节、SHA-256 和来源 ID 在 `tools/evidence/density-power-20261030/manifest.json`。两个脚本都使用 `fractions.Fraction`，没有浮点容差、随机种子（幂桥脚本）或数值根近似；密度脚本的随机输入也由固定 seed=20261014 生成，但每个不等式仍以非负有理 m 次幂比较。

脚本语义已逐函数读取：`density` 以半开窗口 `[x,Rx)` 计权重重数；`a_power` 把 `p=1/m` 的根界提升到有理 m 次幂；`audit_game` 穷举策略 profile、逐玩家动作、公共资源和新获得资源的外部性；`endpoint_audit` 检查几何谱与 degree-zero 端点。幂桥脚本逐项实现 `ordered`、`square_power`、`affine_phi`、`compressed` 与 heavy-first/last 路径，并检查半开端点和分段导数相接。

# 2. `weighted_congestion_density.json`：密度矩与有限游戏审计

结果声明两个 claim：`WC-R2-DENSITY-MOMENT v1` 与 `WC-R2-WEIGHT-DENSITY v1`。总量字段为：

* `moment.checks=1248`；参数为 (m=2,3,4,5)、(q=2,3,5)，乘重 1–4，几何序列长度含 0、1、2、5、9、24，并另有 80 轮固定 seed 的随机有理根；每个样本检查密度计数与 m 次幂不等式。
* `games=49`，共 4,864 个 profile、43,748 个动作移动、43,744 个新资源获得、14,588 个零新成本、14,580 个共享资源比较、52 个势最小 profile。参数分为 (m=2,3,4)、(q=2,3)，每组 8 个 trial，再加 all-zero 成本控制。
* `endpoint_checks=40`，覆盖 (d=3,4,8,16,32,64)、(m=2,3,4)、(q=2,3) 的完整几何谱，并检查 degree-zero 的 profile 独立成本。

脚本的关键断言把可能含根的界写成有理式。例如对根 (h_i)、权重 (w_i=h_i^m)，密度 (k) 与系数多项式 degree (d) 给出
\[
\bigl(\sum_i h_i\bigr)^m\le A_R(p)^m,k^{m-1}\sum_iw_i,
\]
其中 `A_R(p)^m` 由 `a_power` 精确计算。游戏审计又检查势增量、外部性、零新资源和 `L<=B*C_i(new)` 的 m 次幂形式；若动作违反 alpha=1+B 的候选不等式，则断言势严格下降且不在最小 profile。

实际输出保留 49 组 `m,q,d,roots` 参数。代表性有限族中，(m=2,q=2,d=1,3,16) 的根序列和 `B_to_m` 分别为 3、9、96；(m=3,q=2,d=16) 的 `B_to_m=1008`；这些是脚本构造的有理参数实例，不能替换任意实系数。半开端点断言明确区分 `[1,4)` 中含 1 不含 4，以及 `4-1/1000` 的扰动会使密度增一。

报告的 limitation 是明确的：有限有理审计，不证明任意实权重、任意实系数、任意 (R) 或任意 (p)。因此本批把 1,248 个矩检查、49 个有限游戏和 40 个端点检查归为“有限实验/条件支撑”，不写成一般 weighted-congestion 近似比或均衡定理。

# 3. `weighted_power_bridge.json`：幂桥、仿射势和 21 条路径

幂桥 JSON 的精确计数为：`ordered_edges=35304`、`power_edges=35304`、`packing_vectors=329`、`affine_edges=25000`、`literal_paths=490`、`rational_exponents=21`。所有计数都由脚本中的 Fraction 断言生成。

## 3.1 有序边与平方幂界

脚本对权重选自 `{1/16,1/4,1,4}` 的长度 1–5 非降多重集、每个非空子集和每个新增权重，使用六类成本多项式（常数、线性、二次、三次和 degree-11）检查
\[
\text{low}\cdot C(\text{new})\le \Delta\operatorname{ordered}\le v\cdot C(\text{new}),
\]
以及由根比 `scale` 给出的粗界。随后用 `square_power` 检查
\[
\Delta\operatorname{square\_power}\ge \sqrt v\,C(\text{new})
\]
和由密度 kernel 给出的上界。这里的 35,304 是具体有限权重/系数组合的边计数，不是任意实数的证明。

## 3.2 packing、仿射和 literal path

329 个 packing vectors 检查 (p=1/2,R=4) 的半开密度式；五组 `(a,b,h_a,h_b)` 与 slope/intercept 组合产生 25,000 个 affine edges。490 个 literal paths 比较 heavy-first/heavy-last 的显式路径和压缩公式；当路径非零时，检查两种顺序的比值不超过根比 `k`。

`affine_phi` 的分段函数在 (x=k y) 处检查函数值和左右导数的接合；还检查 (y=0,1/8,3) 的三种端点。脚本没有在 0/0 情形使用虚构比值，而是把 zero-cost 分支单独处理。

## 3.3 21 个有理指数记录

21 行 `power_path_rows` 将 (p=A/B) 嵌入同一底数 (q)，令 `N=base**(B+2A)`、\(\epsilon=base^{-3B}\)，使 (t=base^{B-A}) 和所有幂值有理。代表性比率包括
\[
27/13,\ 19/6,\ 55/13,\ 9281/1105,\ 551489/20075,
\]
以及 (p=9/10) 时的三条大整数比率。它们展示幂桥在显式有理参数下的增长行为，但结果文件自身的 limitation 已写明：一般证明和任意实参数不在本脚本结论内，也没有均衡不存在推论。

# 4. 两份结果之间的关系与边界

1. 密度源提供 `A_R(p)` 的有限 m 次幂和资源外部性检查；幂桥源把根权、排序路径和仿射势连起来。两者可作为后续加权拥塞正文的证据组件，但本批没有把一个源的有限参数外推到另一个源的任意参数。
2. `weighted_congestion_density.py` 的 49 游戏包含空策略、共享资源和 zero-latency 资源；这只验证该实现对零新成本和 profile 平局的处理。势最小 profile 数为 52，不能解释成均衡唯一性。
3. `weighted_power_bridge.py` 的 21 条路径和 35,304 条边没有求解一般均衡；`limitations` 明确禁止 equilibrium nonexistence inference。后续若要使用 power bridge，必须重新给出实权重域、系数域和路径/策略量词。
4. 这两个对象与当前 CAG 六人 half 目标无直接同一模型身份：它们属于 weighted-congestion / unrelated-machines 数学包，不能移入 customer-attraction 证明链，也不能把有限幂界当成六人目录覆盖证明。

# 5. 接续与处置

* 证明性复用：保留脚本中的 Fraction 断言、半开窗口端点和 degree-zero 分支；新增参数必须重新检查 `B_to_m`、密度计数和 zero-cost 分支。
* 研究复用：若声称任意实权重或任意多项式，应补充独立解析证明；当前 JSON 的 1,248/49/40 与 35,304/25,000/490/329/21 全部标作有限证据。
* 关系登记：第三阶段可以把密度矩作为幂桥的前置证据，把幂桥作为路径顺序比较的条件组件；不得登记为一般近似算法、LP 结论或 equilibrium theorem。

结论等级：本批是“完整脚本实读 + Fraction 有限重放 + 明确边界”；没有新增一般 weighted-congestion 定理、均衡不存在性结论或 CAG half 结果。
