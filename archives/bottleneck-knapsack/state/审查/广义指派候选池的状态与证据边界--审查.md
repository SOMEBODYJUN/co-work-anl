## 2. 八条候选的精确量词和状态

### GA-01：transversal matroid 成本保留 Chernoff 舍入

输入是显式二部图给出的 transversal matroid、任意有理 fractional basis、一个有理 cost、\(k\) 个 \([0,1]\) 系数行。目标是随机多项式位时间输出 basis \(B\)，使 \(c(B)\le c\cdot x\)，并以常数概率同时满足每行相对原均值 \(a_rx\) 的 Chernoff 尺度误差；不要求 marginal preservation。登记状态为 LIKELY_STANDARD_COROLLARY_PENDING_CHECK：母文在 assignment/star-supported rows 上已有成本保持集中舍入，并明确提出 matroid bases；新意依赖显式 strong base-ordering 和 complementary merge 的可构造性。toy 记录了 rank-3 transversal 的17个 bases/136对通过，以及 K4 非 strong-bijection 边界，但明确 is_proof=false。首要义务是核 face-preserving/SwapRounding 误差体、原始 cost 保持和分布合同；若为直接标准推论，应从独立选题池降级。

### GA-02：两种资源值的真预算 Santa Claus

输入有 \(m\) 个玩家、\(n\) 个资源，公共资源值 \(v_j\in\{1,R\}\)、任意非负 \(c_{ij}\) 和总预算 \(B\)，资源允许不分配。目标是在严格预算下得到每个玩家至少 \(OPT/4\) 的分配，位复杂度多项式。母框架有真预算 \(O(\log n)\)，公开提出常数改进；两值限制可能诱导 small-resource/cardinality 结构，但 big-player 选择与共享 small resources 仍耦合。登记状态 BACKUP，toy 只核了 rank-1 两精确预算障碍，未完成两值 BSC 枚举，不能写成 \(1/4\) 算法。

### GA-03：两容量 BMKP 的 \(2/3-\varepsilon\) 候选

输入是公共正有理重量、非负有理利润、容量只取两种 \(B_1,B_2\)，包数任意、容量比无限制、物品允许 unused；目标是固定 \(\varepsilon>0\) 的硬容量 \((2/3-\varepsilon)\)-近似，算法总位复杂度多项式，依赖 \(1/\varepsilon\) 的多项式次数可接受。登记状态 DEEP_UNREVIEWED，是候选池主线。

候选机制为容量-specific heavy profiles/slack、全局 critical expensive items、short exact-fit pairs、cheap rounding。登记的 toy evidence 有 seed=20261020、3,000 joint cases、4,927 joint swaps、8,192 pair exhaustive cases，但明确 is_proof=false。当前正式参数、L1/L2/L3 条件模块、discard \(4p_{\max}\) 舍入和未闭合义务见本档相邻两页；独立反方审查已将整体状态保留为候选，不能从三模块直接推出总算法。

### GA-04：height-2 weighted laminar matroid 常数 prefix 误差

输入为显式 height-2 laminar matroid、任意 element order、非负有理权、fractional basis、一个 cost。目标是 cost 不增加且每个 prefix 的 weighted discrepancy 不超过绝对常数 \(Cw_{\max}\)，多项式时间。登记状态 HOLD。母文已有一般 \(O(\log n)\)、二值 \(C=1\) 和 uniform weighted 结果；候选只在真正超出 consecutive/disjoint blocks 的 bounded-active-width 情况下有价值。首要义务是证明跨子树 exchange charging 不随活动块数增长；登记没有新 prefix experiment，is_proof=false。

### GA-05：restricted Santa Claus 破4的旧目标

目标是 restricted values \(v_{ij}\in\{0,v_j\}\) 下，以正保证给所有玩家的 \((4-\delta)\)-近似多项式算法。登记状态 REJECT_OLD_TARGET：配置 LP gap 和近期机构/作者算法声明造成严重重复风险。该状态只淘汰旧题目表述，不认证近期算法、定理或发表状态；在没有取得完整可审算法前，不应把旧目标继续列为开放主线。

### GA-06：eligible-degree-2 max-GAP 超 \(3/4\)

输入是任意多 bins、每件物品至多两个 eligible bins、bin-dependent sizes/profits 的 offline max-GAP，目标容量严格、随机多项式算法达到期望 \(0.76OPT\)。登记状态 HOLD。母文一般 max-GAP 有绝对常数改进，但两玩家 special results 不能直接迁移到 degree-2/unbounded bins。toy 两个单位包、两个单位物品中独立 sampling 只有 \(3/4\)，correlated matching 可达2；这只是可证伪小例，不是 \(0.76\) 结果。

### GA-07：reserved-capacity Group GAP 从 \(1/6\) 到 \(1/5\)

输入是 unit-sized bins、公共 item sizes、bin-dependent profits、all-or-nothing groups，每组总 size 至多 \(m/2\)，目标硬容量 \(1/5\)-近似。登记状态 BACKUP。母文在同一组约束下给 \(1/6\)，reserved-half 子问题有 \(1/3\) 模块；候选想改善 reserved-capacity 部分，但尚未证明组完成和最终舍入因子能同时保留。没有 dedicated enumeration，不能把比例乘法猜测当作保证。

### GA-08：random-order online GAP 竞争比 \(0.16\)

输入是随机均匀到达顺序的 online max-GAP，item 到达后不可撤销分配/拒绝，要求对每个实例期望利润至少 \(0.16OPT\)、容量严格、每步多项式。登记状态 HOLD。母框架已有约 \((1-\ln2)/2\approx0.1534\) 的复杂 stopping-time 证明；候选只提出 medium-item reserve 改进。关键义务是依赖随机顺序下自适应停止时刻的 residual-capacity 概率；没有完成 online order enumeration，不能升级竞争比。

## 3. 证据分层和跨对象边界

候选 JSON 的 evidence_files 为 toy_audit.py、evidence/toy_audit.json、TWO_CAPACITY_LEMMA.md 和 COST_CHERNOFF_COROLLARY_CHECK.md。它们承担不同层次：

* toy_audit 的有限枚举和 Fraction 检查只能核验具体 rank、pair、joint 或小容量实例；
* TWO_CAPACITY_LEMMA 是 BMKP 候选结构源，最终参数与模块状态需结合独立反方审查；
* COST_CHERNOFF_COROLLARY_CHECK 是 GA-01 是否为标准推论的待核记录，不等同于 matroid 全称证明；
* 母论文/作者 open 位置是研究动机和来源定位，不能单独证明本候选的输入提取、位复杂度、实现或新颖性。

BMKP 是中央 max-min 优化，不是 weighted-congestion 玩家成本或设施客户均衡。候选 JSON 中的“容量”“预算”“舍入”不能自动移植到拥塞存档；反向也不能把拥塞的 PNE/势函数工具当作 BMKP 的分配算法。
