# 模型与精确反例

三源属于 bottleneck/GAP 选题中“向量容量启用值”边界，不是 scalar generalized-assignment 定理。每个物品列给出两个资源上的消耗，启用集合的分数是在线性容量约束和每件物品至多使用一次下可取得的最大总量。源码注释明确指出三列具有 consecutive-ones 结构，故该例专门测试“把标量 LP 的启用值子模性直接推广到向量容量”的诱人扩展。

## 1. Exact Fraction 顶点枚举

来源 `exact_vector_lp.py` 的 ID 为 `2330f622c89c390a540a`，大小 2,187 字节，SHA-256 `d1f1ceed8f0e920f81f155c7148c93bf289fe7dc6f47d3a77848483754f09432`。矩阵为

\[
A=\begin{pmatrix}1&1&0\\1&0&1\end{pmatrix},
\]

其中物品 a 同时消耗两种资源，b、c 各消耗一种。两个资源容量均为 1；对每个启用 mask，脚本列出所有容量、不超过 1 的变量约束，并穷举三条紧约束组成的有理顶点，取最大总分配量。没有浮点求解器或外部依赖。

冻结结果 `exact_vector_lp_results.json`（ID `e14325e30b51eff0c3d8`，804 字节，SHA-256 `c47f7034083e450b9e2215ad4656ce9362000c482ecbf4b60d60be476418eca9`）给出全部 8 个 mask 的值：

| mask | 启用物品 | LP 最优值 | 一个有理 witness |
|---:|---|---:|---|
| 0 | ∅ | 0 | (0,0,0) |
| 1 | a | 1 | (1,0,0) |
| 2 | b | 1 | (0,1,0) |
| 3 | a,b | 1 | (1,0,0) |
| 4 | c | 1 | (0,0,1) |
| 5 | a,c | 1 | (1,0,0) |
| 6 | b,c | 2 | (0,1,1) |
| 7 | a,b,c | 2 | (0,1,1) |

脚本运行后重新生成的 JSON 与冻结结果逐字段相等。关键集合取 \(A=\{a,b\}\)（mask 3）、\(B=\{a,c\}\)（mask 5）：

\[
\phi(A)+\phi(B)=1+1=2,
\qquad
\phi(A\cup B)+\phi(A\cap B)=\phi(\{a,b,c\})+\phi(\{a\})=2+1=3.
\]

子模性要求左边至少右边；这里缺陷为 `rhs-lhs=1`，故启用值明确**不子模**。该结论是一个完整的小规模有理反例，不依赖随机性或求解器容差。它说明即便列满足 consecutive-ones，二维向量容量也不能直接继承标量 LP 的子模性工具。

## 2. 随机 LP 搜索源码及运行边界

来源 `search_lp_submodularity.py` 的 ID 为 `67ef55c86900ff1ddbf1`，大小 2,268 字节，SHA-256 `2fe06d433eda1f1657eabb22795f022c575907b93f79ecda9752c17de2805164`。脚本固定 `random.Random(20261020)`，每次试验随机生成 3×2 size 矩阵（每个元素 0.5 或 1.0）和非负 profit（0、1、2），对 8 个启用 mask 各解一个 SciPy HiGHS LP，再检查所有集合对的子模性差距；目标为 10,000 trial 内找到第一个正缺陷并输出精确候选矩阵。

本批完整读取源码并启动精确运行，但在约两分钟后仍无输出，因长时间 HiGHS 调用而中断；`search_lp_run.json` 保留为空/未完成状态。不能把这次中断解释成“10,000 次均无反例”，也不能把脚本的浮点候选替代上面的有理反例。随机搜索的正确用途是辅助发现其它禁形，当前已知最小反例由 exact_vector_lp.py 独立闭合。

## 3. 与现有 GAP/向量容量边界的关系

现有 bottleneck-knapsack 审查已经把该三物品反例记为连续列二维启用值的 C01/C08 局部证书，并进一步记录二维固定非负矩阵的“两条正比例射线”充分/必要分类候选；本批只补齐三个未处理的原始 probe source 和脚本运行 provenance。不能从一个三物品反例推出所有多资源 LP 都非子模，也不能把两条射线分类草稿当作本批已证明定理。

该反例与 scalar generalized-assignment 的 reserved-capacity/submodular 工具边界相连：任何依赖启用值子模性的扩展，都必须先排除这种跨资源共享列，或显式加入结构条件。它不否定允许其它方法的向量容量近似算法，不涉及 unrelated-machines 六人 SPE 目标。
