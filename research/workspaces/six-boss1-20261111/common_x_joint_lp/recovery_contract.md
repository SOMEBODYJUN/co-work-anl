# 共同 X 联立系统的恢复与独立认证合同

本文件说明已经准备但尚未执行的有理恢复路径。当前基准23625×21021，未来
Main 审定的额外行可通过独立 final/ 版本使用同一列合同；恢复器从冻结
`coordinate_structure.json` 读取实际 shape，不改变冻结行集。

## 1. 所有核心坐标和所有辅助路径

完整向量始终为21021维。潜在核心集合准确为
`0…4848 ∪ 15593…21020`，共10277列。所有原质量、4992 shared624隐藏质量、
16个X质量和420个真实交叠都属于这个集合。只有
`4849…15592`的10744列属于辅助集合，两者不交且并集为全部列。

浮点值仅提议正支持。每个核心坐标若值>1e−11则进入有理未知量，其他核心在
完整向量中显式置零；这没有删去列、hist或隐藏态。任何被错误截断的小质量
都必须承受最终所有精确行和归一的检查。失败只否定该次支持提议。

| 代码阶段 | 对420个真实 y 的操作 | 对10744旧辅助的操作 |
|---|---|---|
| `load` | 与 core 和 forbidden-min 集合逐索引核对 | 与唯一辅助区间逐索引核对 |
| 浮点规范提议 `canonical_old` | 进入前后逐值一致断言 | 7954max、2790min按旧规则重算 |
| 支持生成 | 与shared624、x和原语义一起选为未知量或显式零 | 不进入支持 |
| `project` | 作为独立核心未知量保留；缺支持才置零 | 仅用已建立的旧规范片消元 |
| 活动行 | 两个原上界、新own六facet及全部收益行都保留 | 只跳过已用作规范表示的阈值/上界行 |
| 有理求解后 | 保存10277维原始核心解，包括420 y | 完整有理重算旧规范值 |
| 有理重算后 | 全部核心与保存解逐项相等 | 规范量参加全行检查 |
| dual恢复 | 全21021列包括420真实y均核残差 | 无遗漏规范列 |
| 独立核验 | 与规范化前核心解一致；逐组真实八格检查 | 独立重算全部10744规范值 |

恢复器没有读取旧 `maxb_envelope_structure.json`，没有420个共同X min的
`representation`路径，也不跳过它们的上界。`project`会拒绝任何既未分类为
核心又未提供辅助表示的坐标。对偶消元排序把 y 当核心，排序不删除任何列。

## 2. 活动方程与有理消元

原312个 shared624质量等式和16个B4质量等式强制加入精确方程，不受浮点活跃
阈值影响。旧辅助的零阈值或min平局根据浮点值提出；其余主行按浮点dual权
排序并以1e−10相对系数尺度提出活动方程。归一 O=1 强制加入。

`sameW`仅是一种显式恢复尝试，会另强制继承有理W10；`freeW`不强制该值，
而从恢复后的原质量精确计算目标。两者都不是优化器，不做自动数值重跑。
活动方程、支持、选片描述及所有输入SHA在消元前保存。

求解只用 `fractions.Fraction` 的稀疏高斯消元。未被方程确定的自由量从原浮点
值作分母上限10^12的有理提议；全部主变量随后由精确回代确定。这是寻找一份
证书的尝试，无论浮点精度或自由参数如何，只有完整有理约束检查通过才接受。
每次恢复有显式时间边界与进度日志，失败保存 traceback，不冒称Farkas证书。

## 3. NPZ读取和执行隔离

`recovery_model.py` 用标准库 `zipfile`、NPY头的 `ast.literal_eval` 及
`struct` 解码 plain scalar/vector 数组；拒绝object、structured、二维和Fortran
数组，不执行任何pickle。此读取器已对旧云端真实NPZ中的22个数组与NumPy
标准读取逐值核对，包括完整shape、浮点和字符串状态。

`recover.py`、`recovery_model.py`、`prepare_recovery.py` 和独立证书检查器均
不导入NumPy、SciPy、SymPy或任何优化器。数值数组只被当作已返回的只读证据。
准备脚本先核Main返回的输入和输出清单，再复制到新的recovery目录；原discovery
不变。eligible为false的产物也保存，但恢复入口拒绝把它当作标准成功候选。

另一项有针对性的语义检查把全部420 y改成任意非canonical有理数，然后运行
浮点及有理的旧辅助规范化；420值逐项不变。这只是代码路径检查，不宣称修改后
的合成向量满足新LP，也没有执行任何有理活动面恢复。

## 4. 完整原始、对偶和八格认证

冻结矩阵约定 `A x≥0`、`x≥0`、`bᵀx=1`，目标为最小化 `cᵀx`。浮点调用
使用逐行正尺度s，输入为 `−A_i/s_i x≤0`。因此SciPy不等式marginal m对应
精确非负乘子 `λ_i=−m_i/s_i`；归一乘子不反号。

精确dual必须给出

\[
c=\alpha b+A^T\lambda+r,\qquad\lambda\ge0,\ r\ge0.
\]

有理原始点满足全部冻结行、归一和列非负后，还必须有 `cᵀx=α`，并逐项核
`λ_i(A_i x)=0`、`r_jx_j=0`。规范辅助同样参加所有原始、对偶和互补检查。
在没有匹配dual时，数值optimal或一份有理可行点不能冒充精确最优。

独立检查器由原矩阵的真实状态描述符重建194个R/Z和16个B4组，重新核各组
四态总和、y上界和X质量。取 β=L 后核全部四个上界、全部八格非负和全部
边缘。保存210个八格见证；没有声称它们自动粘成全目录、跨组、跨根共同律。

## 5. 当前执行状态与边界

基准装配、独立结构审计和旧W10 dual零扩展已经完成；原点在所有旧行和原始/
对偶互补上复核通过。基准新行的固定点诊断不依赖恢复代码。

本文件及程序准备阶段优化器调用数0，精确恢复尝试数0。Main尚未交回本系统
云数组；在收到冻结返回产物之前不执行 `sameW`、`freeW` 或 `dual`。

一份有限必要LP的精确最优即使仍低于half，也仅是该必要放松的结果。它不等同
于完整纯SPE实例，更不能据此声称原六人问题的反例或充分完成。
