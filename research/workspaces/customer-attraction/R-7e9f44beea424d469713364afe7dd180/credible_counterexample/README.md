# 可信续局与收益比较桥攻击

主目标一般Q-CAG-HALF未解决。本文只维护本研究员精确可续资产，不改共享账本。

## 已获得并独立核验的结果

`payoff_cap_failure.md`给三人五主题23单位客户的完整纯SPE，实际收益(5,6,12)，
W=OPT=23。它同时否定 W≥(m+1)u_m/2 和任意两人 u_j≤2u_i。
失败由根复制末位主题后真实后继(C,D,C)把原12压至5产生。

`payoff_cap_failure.json`是联合MILP提出、精确锥优化恢复的原始完整策略。
`payoff_cap_failure_markov.json`是同输入、同实际路径收益的计数策略简化。
两者各31历史/124真实偏离已由independent_mechanism完全独立逐单位客户核验。
`audit_payoff_cap.py`是这里另一路不导入规范实现的逐单位客户Fraction审计；
`payoff_cap_audit.json`保存全部155含自身动作比较及三层表格。
正式共享入库交由Boss和background_induction负责；这里不改共享文件。

## 搜索接口与证据范围

- `joint_share_probe.py`复用既有联合MILP，只改末位份额目标。
  `joint_share_m3p5.json`最后一项提出上述反例；固定锥有理最大份额12/23。
- `last_share_probe.py`从规范全集获取种子，独立有序历史抽样非极小可信菜单，
  优化任意玩家份额；普通随机、Möbius正偏置种子都是候选来源。
  m3p5、m3p7、m4p6有限普通扫描和m3p6有限编译种子扫描未发现反例，
  但稍后的联合MILP已经反驳同一桥；这明确说明那些有限负结果证据不足。
  m5p7纯扩样中断，文件只保存已完成的改进项，不代表计划20种子全部完成。
- `pair_probe.py`攻击pairwise因子二；500个m3p5、200个m4p7及500个m3p6
  编译种子所抽完整策略锥都未找到，但同样由上述联合候选精确反例推翻。
- `fixed_path_goal.py`进一步支持u1=1或W=1的完整联合树候选生成，直接攻击
  弱逐人OPT/(2m−1)与真正half。浮点MIP上界一律不作数学证书；只接受提取
  完整动作图后固定锥有理恢复及逐历史核验的实例。
