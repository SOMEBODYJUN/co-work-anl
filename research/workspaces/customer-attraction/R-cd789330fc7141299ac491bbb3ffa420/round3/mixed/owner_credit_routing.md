# owner 未覆盖客户的真实分母路由：一次 e 信用与保留势库存

2026-10-23，mixed_menus/shared 交互重构。身份：任意人数、一般共同目录、完整原真实菜单上的通用客户路由关系；shared已独立推到相同带旧背景的逆归纳式并确认。它尚未将R的整体IC标量权与I的客户路由源耦合，不证明row overload或half。Q-CAG-HALF仍OPEN。

## 1. 固定一次实际叶与owner

固定原完整策略σ的实际终局Z、最优并集O及一次owner分配o(x)，x∈T_o(x)。这些owner与槽配对不随查询叶改变。对一个x∈O，令

    J_x={i:x∈S_i(Z)}, c=|J_x|。

现在假设owner实际未覆盖x，即o(x)∉J_x。允许c=0，故同时涵盖实际遗漏R。对c>0，这个客户在shared的owner势中有

    κ_x=1/(c+1),    sum_i e_i(Z;x)=c/(c+1)。

c=0时，把1/(c+1)=1称为未覆盖客户的保留库存；shared的κ_Q只对实际覆盖客户求和，不应把此1误加进其κ_Q。

## 2. 真实利润分母，保留全部旧角色返还

从owner角色o(x)的任意合法查询a∋x开始。到达非J_x角色i的查询状态(i,a,x)时，读取原实际前缀下的真实Z_i(a)。令

* b为i之前的实际coverer数；这些角色全部属于J_x；
* t为该真实叶中更深coverer且角色属于J_x的数量；
* n为更深coverer且角色不属于J_x的数量。

当前客户真实负载恰为1+b+t+n。对单位流按这个**真实完整负载**均分：

* 当前份1/(1+b+t+n)在非J查询节点吸收；
* 每个过去实际coverer的份直接进入实际J吸收汇；
* 每个未来J coverer的份也直接进入同一实际J吸收汇；
* 每个未来非J coverer的份送往该角色的新合法查询状态。

末一种查询可取其原真实行动，亦可在证明策略中选择任意包含x的合法主题；之后重新读取该查询的原实际前缀真实叶。允许根据已用OPT索引库存随机选择，但每条IC仍须整体乘一个非负标量。

所有非目标后继角色严格增；过去角色只作为吸收汇，不继续展开。所以有限终止。这里既未把I客户负载强行写成1+future，也未删除旧覆盖者的利润。

## 3. 一次共同信用

因为过去加未来的实际J角色共至多c，有b+t<=c。逆角色归纳，若未来非J状态进入实际J汇的概率均至多c/(c+1)，当前该概率至多

    [b+t+n c/(c+1)]/(1+b+t+n) <= c/(c+1)。

精确差为

    [c-b-t]/[(c+1)(1+b+t+n)] >= 0。

故从owner查询的一单位源出发，

    实际J汇吸收 <= c/(c+1)，
    非J真实查询节点吸收 >= 1/(c+1)。             (OWNER-ROUTE)

c=0时，J汇为空，所有流都在真实查询节点吸收，正好恢复R客户的递增角色路由。c>0时，实际汇总吸收可由该客户**同一 actual e 总池**支付；不需要给每个实际角色另领一份c/(c+1)。剩余至少κ_x没有被J汇消耗，数值上正是owner势的保留库存。

实际J汇处理的是客户信用，不再调用某个更早玩家的IC。多角色J只能说首次进入/进入吸收汇的质量，不能把一个继续展开的多行总访问数当成同一量；此处第一次进入J即停止，故没有多次领取目标信用。

## 4. 与一般证明衔接的尚未完成处

OWNER-ROUTE确实提供一个跨任意多次真实菜单重置、旧背景份也完整保留的一次客户预算。它不依赖SPE；SPE用于随后对查询节点按整体收益付款。

但credible当前R流的总吸收系数w=A_R/D只由R源确定。给一个I客户独立添加owner源，并不会自动使其在各查询节点的流入/吸收恰等于同一w乘该客户利润。这样的共同系数耦合才允许把OWNER-ROUTE的e池用于R的行超额；本文未构造它。

自由matching、owner选择和后继合法query选择可帮助构造这个耦合，必须同时遵守剩余OPT索引库存。仅有每客户自己的路由存在性，不能按客户分别重加权IC，也不能宣布Σ_i(L_i−1)u_i<=G已付。所有真实分支的whole-IC系数必须是一份共同解。
