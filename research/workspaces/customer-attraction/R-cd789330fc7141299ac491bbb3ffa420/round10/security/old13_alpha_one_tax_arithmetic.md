# 旧13人完整策略的 α=1 实际税与共同查询预算同时失败

2026-10-24，security10，按 root 指定只重读同一份已加载旧packet作精确算术。没有LP、目录/策略扫描、新输入或新SPE构造。**一般 HALF、真正聚合安全值与存在最优指派付款仍 OPEN。** 本文是既有反例的指定逻辑后果，不认领原反例发现、外审或新颖性。

来源为 `R-c50fecc37aa44fb4a69a2122bb70e5fe/security/refined_tax_k10_packet.json.gz`；该36客户、13玩家、六共同主题(A,B,T,D,E,P)的完整策略已有全自动机定义级核验。实际叶为 P^10,A,A,B，W=33、OPT=36。客户负载分布为

| 客户部分 | 单位客户数 | 实际负载 c |
|---|---:|---:|
| A侧实际覆盖 | 5 | 2 |
| B侧实际覆盖 | 3 | 1 |
| T侧实际遗漏 | 3 | 0 |
| P侧 | 25 | 10 |

令实际覆盖客户集为 C，定义与相邻钱包 Ctot 区别的基本税银行

    g(T)=Σ_(x∈T)1/(c_x+1),
    J_base=Σ_(x∈C)1/(c_x+1).

则精确有

    J_base=5/3+3/2+25/11=359/66,
    (g(A),g(B),g(T),g(D),g(E),g(P))
       =(5/3,3/2,3,5/2,5/2,25/11).

所以 α=1 的实际背景税付款 `m max_T g(T)≤W+J_base` 被同一合法遗漏主题 T 直接否定：

    13 max_T g(T)−W−J_base
       =39−33−359/66=37/66>0.

再定义 root 要求检查的纯共同冻结查询和

    F(T)=(m+1)Σ_(x∈T∩C)1/(c_x+1)+m|T\C|.

它精确等于 `Σ_i f_i(T)`，其中 `f_i(T)=u_i(T,Z_-i)`：对实际负载 c>0 的客户，c个原覆盖角色查询时各给1/c，其他m−c个角色各给1/(c+1)，总和为(m+1)/(c+1)；遗漏客户每个角色查询给1，总和为m。这里没有使用任何加权客户 IC。

同一旧packet给

    (F(A),F(B),F(T),F(D),F(E),F(P))
       =(70/3,21,39,34,34,350/11),

因此纯共同查询预算 `max_T F(T)≤W+J_base` 也严格失败：

    max_T F(T)−W−J_base=37/66>0.

两个最大值都由实际完全遗漏的 T 达到，所以这里 `F(T)=m g(T)=39`，不存在依靠共同查询额外covered项修复的空间。这只排除上述固定基本税付款，不排除换最优指派、自由静态安全背景、Mpath 或 HALF。

`old13_alpha_one_tax_arithmetic.py`仅读原冻结packet，跟随规定动作得到实际计数，再以 Fraction 重算全部六个查询及共同冻结查询恒等式。结果保存为同名JSON，含源packet SHA256；它没有覆写原证据，也不将本次标量计算冒称为重新核完全部有序历史。
