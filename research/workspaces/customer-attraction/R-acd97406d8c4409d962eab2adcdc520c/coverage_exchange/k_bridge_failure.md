# 一个较强逐人覆盖接口的完整反例

本轮曾猜想所有实际玩家满足 OPT_m≤K+(m−1)u_i，其中 K 为目录最大主题大小。该命题为假。它不是主半覆盖反例，也没有反驳较弱的 u_i≥OPT_m/(2m) 或 OPT_m≤K+m u_i。

精确合法输入、完整31节点策略存于 `k_plus_m_minus_one_failure.json`。三名单位提供者，五个共同主题0,...,4。客户块重数（全部为不同单位客户）为：

| 主题集合 | 客户数 |
| --- | ---: |
| {0} | 12 |
| {1} | 8 |
| {0,1} | 1 |
| {2} | 7 |
| {3} | 2 |
| {0,3} | 5 |
| {4} | 5 |
| {0,4} | 7 |
| {2,4} | 4 |
| {1,2} | 3 |
| {1,2,3} | 2 |
| {0,1,4} | 2 |
| {2,3,4} | 4 |

实际路径为 (0,2,4)，收益 (45/2,16,27/2)，W=52，K=27，OPT_3=55。但

K+(m−1)u_3=27+2(27/2)=54<55。

完整策略由 `k_bridge_failure_audit.py` 直接按单位客户定义独立核验；不导入规范模型、求解器或证书核验器。它检查所有31个有序决策历史及155个包含原动作的比较，并枚举全部125个三主题比较元组求 OPT。输出在 `k_bridge_failure_audit.json`。

此例弱逐人半覆盖阈值安全：2m u_3=81≥55；主目标也有 2W=104≥55。有限反例仅否定所写较强接口。发现时先用规范精确全集解算器输出策略，再做上述独立定义级核验。
