# 八客户完整策略压缩规则勘误

正式资源的压缩句遗漏两个真实离轨动作。只需将 `BA、BB、BC→D；BD→C；其余B` 改为 `BA、BB、BC、CB→D；BD、DB→C；其余B`。完整替换文字、原SHA和证据SHA见同名 patch JSON。

冻结 JSON 的21个节点中，CB规定D、DB规定C。现正文压缩句使根改C后走CBB，C覆盖三名客户且与B不交，根得3；原规定ABB的根只得2。因此它不是一份可以替代原证书的SPE规则。修补后根改C走CBD得2，改D走DBC得2，原完整证书的所有动作恢复。

本轮按原JSON逐项阅读和直接收益定义核对；没有运行原BI、SPE核验器或任何新枚举。原JSON证书及M-578的存在性/删除结论仍可用。修正属于同文件正文的真实勘误，需同时刷新引用该资源的ACTUAL-OPTIMUM-PRUNING、M-578、M-c587三项登记版本/绑定及相应任务输入。203十条边没有直接引用这个资源文件，但涉及三对象的端点pin也须跟随更新。
