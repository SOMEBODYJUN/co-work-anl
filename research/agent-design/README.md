# Work + GitHub 数学研究 Agent：可实施设计

设计日期：2026-11-16。适用仓库 `SOMEBODYJUN/co-work-anl`，分支 **rebuild/research-v2**，设计基线 `7dc42458573b6653fccd6606afc2555f2fb466c8`。默认分支 main 是另一个工作面，不能把它的入口、模型或旧图当成本分支现状。

目标是持续研究难的公开数学问题。一个研究组由 **1 Main + 3 Solver** 组成：一条独立原题/障碍线、两条使用成果的研究线。四人都做数学。该设计不替用户选择下一题，也不把已完成的第三阶段构图重新打开。程序原型只读，不启动模型；完整提示词已给出，尚未在新原题上完成长线实战。

## 适配本仓库的取舍

Work 负责实际 `spawn_agent` / `followup_task`。GitHub 保存数学、证据、精确版本、RUN 和恢复入口。`work.py` 负责读取与持久化，不假装 Python 写一个任务 JSON 就启动了模型。无需额外 API 密钥、驻留服务、数据库或新的图格式。

继续使用现有三层知识：`archives/.../state` 是数学正文，`research/registry.json` 是对象身份与版本，`map/edges` 是有解释和证据的关系。`graph-v2.json` 是可重建投影。另在 RUN 保存研究中的工作假设、失败、义务和采用记录；探索假设不混入已确立前提。

借用 Ansatz 的依赖取证和前沿记录，保留本仓库更明确的 ALL/OR、contribution、条件与模型迁移语义；借用 CoCo-Prover 的联合子义务和稳定性思想，但没有 Lean 检查就不使用其 kernel-verified 等级；借用 PACE 的“结论仍真但新用法待核”；借用 OSVerify 的逐项错误验证。Main 不照搬上游只调度不做数学的职责，也不以固定审核席占用三个研究空位。

## 实现状态与边界

现有 `research context` 已完成选定支持的向后 ALL 闭包、双向等价导航、当前绑定检查和局部贡献分流。新增 `research frontier` 消费该输出，列每个替代分支的完整前提、未付条件、局部步骤、反驳目标和循环分量。其最小不动点是 **假设边中所有适用条件均成立时的结构闭包**，不是数学证明，不自动提升任何对象状态。

实际采用必须另有本题应用记录：原题指纹、所用对象/边版本、变量及量词对应、条件逐项付款、正文实读位置、独立复核与准确剩余。没有这一步，结构闭包中的结论仍只是可审读路线。程序不理解自由文本条件，也不验证自然语言证明。

代码先以合成反例与本库真实 SUMmin 等价/局部贡献演练验收。工作流的长线增益、独立线是否产生不同机制、以及最终数学突破，要由下一次真实研究记录验证；文档、单测和图可达性不能替代这些证据。

## 第一轮怎样开始

1. 先固定用户真正要研究的原题及全部模型条件。没有明确选题时完成设计和候选阅读入口，不擅自把全仓目标缩成某个六人或 UM 特例。
2. 填开题合同，读 Main 词，生成同题三份输入。独立线只给原题、定义与事先允许的障碍；成果 A/B 各按实际缺口取证，不按文件数平均分配。
3. 真实派出三个研究者，保存真实 agent ID。Main 自己推进原题的综合或另一项承重推导。中间结果成熟就接回、挑战、反馈原研究者并保存，不等凑齐一轮。
4. 每次重要修订重建本题应用记录及受影响前沿；Git 串行发布并确认 pushed。所有开放义务有准确断点、负责人或明确的暂放原因。

研究公屏沿用仓库现行退役约束。本设计不创建或复活旧研究公屏；跨对话协作以已推送的 RUN、数学文件、精确引用和现行允许的消息入口为准。后续如设计新的研究公屏，须单独明确其用途与路由。
