# 2.5.1/2 程序实现规格

状态：**设计规格，专用程序尚未实现**。以下接口名表示拟实现操作，不是现有CLI。材料清单与编辑任务不等于数学真值登记；本文件不规定2.5.3或超边格式。实现应复用已有安全路径、Git正常推送、凭据与真实读回确认能力，不搭建新数据库或复杂Agent平台。

## 最小数据与目录

本轮机器状态在顶层 `curation/`，不进入 `archives/**/state/` 或未来数学读取正文。旧 `research/curation/` 留给上一版准入原型，不复用其manifest。

| 路径 | 内容 |
| --- | --- |
| `curation/runs/<run>/run.json` | 固定运行ID、结果分支、快照commit、材料范围/排除项、新公屏、当前步骤；run不是Boss或数学对象ID |
| `.../snapshot.jsonl` | 每材料的本地material_id、path、sha256；ID只用于分批，移动/合并后不当作最终数学身份 |
| `.../batches/<batch>.json` | 第一步互斥材料列表、父Boss、内部处理者、写入的批次记录路径及状态 |
| `.../records/<material_id>.json` | 六字段定性记录，规范见[classification-record.schema.json](../curation/schemas/classification-record.schema.json) |
| `.../actions/<material_id>.json` | 分类后实际保留/删除/移附件/提取计划及执行状态、当前去向；分类完成与动作落实分开 |
| `.../tasks/<task>.json` | 第二步对象群、具体问题、输入版本、可写范围、预算、认领与交付 |
| `curation/workspaces/<run>/<Boss>/...` | 未提交定性批次、第二步推导、暂存产物与交接草稿；有引用价值的数学交回正式正文 |

`run.json` 先固定 `archives/<档>/(subarchives/<子>/)*state/` 与直接问题页的当前材料。额外的现行稿件若含尚未入正文的独有数学，显式加到本轮范围；不把root操作文档、旧workspaces、证据中的original/comparison副本又枚举成四千个“新数学对象”。排除是处理范围说明，不是声称这些目录绝无数学。当前被引用的证据需要保留去向，不能随排除而删除。

快照要求与固定Git提交一致，不能先删再补基线。后续增量单独记录，不修改旧快照分母。必须覆盖当前每份候选；元数据缺失或解析失败不能漏列。原路径、SHA由程序生成，代理只填分类与理由。

## 第一步操作

| 拟实现操作 | 必须行为 |
| --- | --- |
| 初始化运行/材料导出 | 绑定稳定Git快照及安全路径；全量生成未定性清单，不自动给类型 |
| 分批 | 仅分配未收回材料；同一材料不同时给两个内部处理者；支持长文拆阅读段落，最终仍一条记录 |
| 收回批次 | 校验六字段、类别/路由、全批覆盖、重复ID、路径和输入SHA；记录中的数学判断来自实际读者，不来自regex |
| 覆盖与队列导出 | 区分未分配、阅读中、已定性、已共享；导出数学材料、第二步候选、证据、非数学和待上下文材料，绝不输出GraphSnapshot |
| 清理计划 | 只从已定性记录形成明确动作；数学含义不由程序决定。non-math才可直接无数学删除；mixed先提取，未知保留 |
| 落实清理 | Boss明确选择一小批，核对源SHA未变、写入范围、附件/数学去向和当前引用后应用；不默认全量unlink |

第一步只有一个Boss协调内部批次，无需每材料远端claim。程序在本地避免重分，Boss按批checkpoint并确认pushed后才记已共享。若收到矛盾分类，不选多数票自动覆盖：保留原件、给Boss两条依据并定向裁定。数学清单包含猜想、具体缺口和未审数学，不只包含定理。

六字段为 `path`、`sha256`、`category`、`math_subject_or_nonmath_reason`、`locator`、`route`。理由和定位各一两句即可，不填写statement/conditions/proof/status/owner IDs等最终知识字段。`related_paths`仅为材料线索，不自动成为关系。

路由为 `retain`（沿用）、`distill`（理解/化简/综合）、`restore`（定位明确的损伤）、`extract`（抽出混合数学）、`attach`（必要证据）、`delete`（明确非数学或已确认纯冗余）、`clarify`（上下文待判）。数学类别的六字段记录不得直接填delete/attach；数学冗余的合并删除另经动作审核，给实际替代去向。非数学/证据不经独立内容判断不能由文件名批量删除；数字页也不能由词频自动转蒸馏。

## 清理与保全

- 定性记录绑定原件；动作记录另给 `planned/applied`、旧路径、当前数学/附件去向、理由、涉及的链接修改和已发布提交。`applied`不是“打算删除”。
- non-math无独有数学，可以删除正式页并去掉无意义入链，不为旧done永久留空壳。旧完成回执保留为当时事件，不篡改；需要时由当前去向表解析。
- evidence-only不是自动保留全部日志，也不是找不到owner就自动删除。对仍承担论证的证据用当前正文路径绑定用途；无需最终数学ID。明显重复且已确认无独有数学/必要证书的可删除；用途尚有疑问则记具体问题。
- mixed/needs-context含数学时须先提取或保住现状；不能整份删除，也不能把独立数学仅塞入无关附件。
- SHA变化只使相关材料记录过期，定向重读变动内容；保留同批其它不变记录。缺少快照/对照无法确认时不删除。

## 第二步最小任务协议

任务包含 `task_id`、第一步material IDs/路径与SHA、共同问题/模型线索、需要理解的具体内容、现成成熟正文、可写路径、应保住的内容、探索预算和验收。一个材料可为多个对象群提供只读输入，但同一当前路径同一时刻只能有一个写入者；不按未来节点粒度强拆。

单Boss内部继续串行分配即可。多Boss时需要以下最小远端事务，不重用旧 `cleanup/sources.json`：

1. 每次从结果分支最新快照读取任务和本run所有有效写入占用。
2. `claim` 只在任务可领、输入版本可用、写入路径不与已领任务相交时生成新任务状态；子目录/重命名/删除目标也纳入相交判断。
3. 通过正常push竞争，拒绝force；远端推进时重新读取并重新判断，不能重放过时占用。
4. 用同一个request_id读回确认；丢失响应不能直接当成功或另发一个新claim。真认证失败立即停止同凭据重试。
5. 当前任务完成后再接下个任务，不预领长期库存；同一clone全部Git操作仍由Boss串行。

状态为 `available → claimed → submitted → completed`；另有 `blocked/handoff/stale`。`submitted`引用已经pushed的产物及commit/path/SHA，`completed`表示本步的编辑和交付验收完成，不表示新定理成立。仅本地草稿留在工作区和交接记录，不能冒充远端交付。

交付允许成熟解释复用、简化见证、一般结果、结构认识、损伤恢复、原见证撤回或具体未解义务。验收看数学正文和材料去向；不得要求accepted边、final manifest或一页一数学ID。

`handoff`释放本人未完任务、保留实际原因/草稿路径/是否共享/具体下一步。无提交的任务不能因超时自动夺走仍在写的成果；明确交接或协调处理。`clean handoff`不释放本run任务，不能混报。

## 实现验收情景

1. 全文只有UUID/PASS的材料，即使原kind是statement，也能定性non-math；格式通过不授数学价值。
2. 有自足结构的具体数字反例归math-exposition；含数字不自动触发蒸馏。
3. 只有best value/负目标值且无数学主张的输出归evidence-only，不产生昂贵蒸馏任务。
4. “计算”页藏一般证明时能标mixed并提取；不得按目录批删。
5. 同页多个范围和状态已写清的命题能直接保留，不强拆未来ID。
6. 独立算法合同可归algorithm-result；裸程序名和样本PASS不自动升级。
7. 缺头部、未知kind、暂无引用均不漏清单，也不自动删除。
8. 批次重复、漏项或SHA过期明确拒收；不抹去其它已收批次。
9. 两Boss抢同群或重叠路径只能一方确认占用；冲突后重读，不静默覆盖。
10. 产物仅本地、push响应丢失、真实认证失败分别有准确状态，不混作completed。
11. 删除包装后必要数学/证据仍有当前去向；纯安排不会改名resource回流数学树。
12. 第一、二步的记录不要求最终节点ID或超边schema，也不调用旧final gate冒称完成。

实现完成后先隔离测试，再用少量真实材料校准分类和动作，最后全量执行；不用单元测试证明数学正确。具体第三步接口等另行设计完成后再加适配层，前两步无需重读已完整定性的全部正文。
