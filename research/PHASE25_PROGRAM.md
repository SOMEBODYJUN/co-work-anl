# 2.5.1/2 程序契约：第一步只分类、编号、建目录

状态：**材料批次与第二步对象群任务程序已实现**：`tools/triage.py`、`tools/curation_tasks.py`、`work.py triage/curation-task`，以及 `start --curation-run` 独立运行域。以下为行为契约；实际命令见[操作手册](CURATION_OPERATIONS.md)。第一步的现行交付仅为全文快速分类、程序编号、完整目录和第二步候选。`tools/triage_clean.py` 及旧运行的清理记录属于已撤销的历史流程，不能把 `plan-clean/apply-clean` 当作现行第一步操作。材料清单与编辑任务不等于数学真值登记；本文件不规定2.5.3或超边格式。

## 最小数据与目录

本轮机器状态在顶层 `curation/`，不进入 `archives/**/state/` 或未来数学读取正文。旧 `research/curation/` 留给上一版准入原型，不复用其manifest。

| 路径 | 内容 |
| --- | --- |
| `curation/runs/<run>/run.json` | 固定运行ID、结果分支、快照commit、材料范围/排除项、新公屏、当前步骤；run不是Boss或数学对象ID |
| `.../snapshot.json` | 程序为每材料生成本地material_id、path、sha256；ID用于分批与完整目录，不当作最终数学身份 |
| `.../batches/<batch>.json` | 第一步互斥材料列表、父Boss、内部处理者、写入的批次记录路径及状态 |
| `.../records/<material_id>.json` | 六字段定性记录，规范见[classification-record.schema.json](../curation/schemas/classification-record.schema.json) |
| `.../actions/<material_id>.json` | 既有运行清理动作的历史记录；现行第一步不新建执行动作，不依其删除数列待办 |
| `.../tasks/<task>.json` | 第二步对象群、具体问题、输入版本、可写范围、预算、认领与交付 |
| `curation/workspaces/<run>/<Boss>/...` | 未提交定性批次、第二步推导、暂存产物与交接草稿；有引用价值的数学交回正式正文 |

`run.json` 先固定 `archives/<档>/(subarchives/<子>/)*state/` 与直接问题页的当前材料。额外的现行稿件若含尚未入正文的独有数学，显式加到本轮范围；不把root操作文档、旧workspaces、证据中的original/comparison副本又枚举成四千个“新数学对象”。排除是处理范围说明，不是声称这些目录绝无数学。当前被引用的证据需要保留去向，不能随排除而删除。

快照要求与固定Git提交一致，不能先删再补基线。后续增量单独记录，不修改旧快照分母。必须覆盖当前每份候选；元数据缺失或解析失败不能漏列。原路径、SHA和材料编号由程序生成，代理只填六字段记录中的内容判断与理由；编号不手填为第七字段。

## 第一步操作

| 操作行为 | 必须行为 |
| --- | --- |
| 初始化运行/材料导出 | 绑定稳定Git快照及安全路径；全量生成未定性清单，不自动给类型 |
| 分批 | 仅分配未收回材料；同一材料不同时给两个内部处理者；支持长文拆阅读段落，最终仍一条记录 |
| 收回批次 | 校验六字段、类别/路由、全批覆盖、重复ID、路径和输入SHA；记录中的数学判断来自实际读者，不来自regex |
| 覆盖与目录导出 | 区分未分配、阅读中、已定性、已共享；完整带号目录覆盖快照每份材料，含七类及路径、类别、理由、定位、route。另导出带号第二步候选及具体待判问题，并提供数学、证据、非数学、待上下文筛选视图；不输出GraphSnapshot |
| 目录闭合检查 | 编号由程序生成且唯一；总目录无漏项、重复或被筛选掉的非数学/证据；第二步候选可追溯到总目录与原SHA。任何route都只是后续建议 |

第一步只有一个Boss协调内部批次，无需每材料远端claim。程序在本地避免重分，Boss按批确认共享状态。若收到矛盾分类，不选多数票自动覆盖：保留原件、给Boss两条依据并定向裁定。数学清单包含猜想、具体缺口和未审数学，不只包含定理。第一步不得删除、移动、改写或合并正文/附件，不执行清理计划、提取、修链接或第二步对象群编辑。

六字段为 `path`、`sha256`、`category`、`math_subject_or_nonmath_reason`、`locator`、`route`。理由和定位各一两句即可，不填写statement/conditions/proof/status/owner IDs等最终知识字段。`related_paths`仅为材料线索，不自动成为关系。

路由为后续建议：`retain`（沿用）、`distill`（理解/化简/综合）、`restore`（定位明确的损伤）、`extract`（将来考虑抽出混合数学）、`attach`（将来考虑归证据）、`delete`（将来考虑去除明确非数学或已确认纯冗余）、`clarify`（上下文待判）。数学类别的六字段记录不得直接填delete/attach；`delete`或`attach`不表示动作已落实。非数学/证据不经独立内容判断不能由文件名批量标记；数字页也不能由词频自动转蒸馏。

## 第一步保全边界与历史动作

- 定性记录绑定原件；既有动作记录中的`applied`仅说明历史已落实事实。现行第一步不新建`planned/applied`动作，不调用`plan-clean/apply-clean`，不重复执行历史清理。
- non-math和evidence-only仍在完整目录中；即使route建议delete/attach，也不在第一步删除、移走、改写或修链接。暂找不到证据owner不等于无用。
- mixed/needs-context含数学时标出位置、具体疑问与后续建议，原页完整保留；不能整份删除，也不能在这一步抽取或合并。
- SHA变化只使相关材料记录过期，定向重读变动内容；保留同批其它不变记录。缺少快照/对照时保持原件并说明问题。

## 第二步最小任务协议

第二步任务由已存在的`tools/curation_tasks.py`管理。任务定义包含`task_id`、第一步目录可追溯的输入路径与SHA、共同问题/模型线索、需要理解的具体内容、可写路径、应保住的内容、探索预算和验收；目录material_id可用于对照，但任务程序的输入字段仍是路径与SHA，不手编数学对象ID。一个材料可为多个对象群提供只读输入，但同一当前路径同一时刻只能有一个写入者；不按未来节点粒度强拆。第一步只输出候选，不在此时认领、编辑或完成这些任务。

单Boss内部继续串行分配即可。多Boss事务已有程序实现，不重用旧 `cleanup/sources.json`；第二步使用时遵守以下契约：

1. 每次从结果分支最新快照读取任务和本run所有有效写入占用。
2. `claim` 只在任务可领、输入版本可用、写入路径不与已领任务相交时生成新任务状态；子目录/重命名/删除目标也纳入相交判断。
3. 通过正常push竞争，拒绝force；远端推进时重新读取并重新判断，不能重放过时占用。
4. 用同一个request_id读回确认；丢失响应不能直接当成功或另发一个新claim。真认证失败立即停止同凭据重试。
5. 当前任务完成后再接下个任务，不预领长期库存；同一clone全部Git操作仍由Boss串行。

状态为 `available → claimed → submitted → completed`；另有 `blocked/handoff/stale`。v2的finish将submit与complete的全部内容校验放在同一事务中完成，不要求为两个远端中间状态分别推送。`submitted`引用已经pushed的产物及commit/path/SHA，`completed`表示本步的编辑和交付验收完成，不表示新定理成立。仅本地草稿留在工作区和交接记录，不能冒充远端交付。

任务初始只锁独立工作区；claim可同时预留已查清的write_paths，后续也可批量extend。真正编辑独占写入；原字节成熟数学以reuse_paths显式共享复用，不为只读引用占写锁。submit至少含一项现行正式数学资产，单独工作区稿或证据不能提交为数学交付；此检查仍不代替内容验收。

交付允许成熟解释复用、简化见证、一般结果、结构认识、损伤恢复、原见证撤回或具体未解义务。验收看数学正文和材料去向；不得要求accepted边、final manifest或一页一数学ID。

`handoff`释放本人未完任务；handoff-all在一次事务内释放本人全部未完任务，保留实际原因/草稿路径/是否共享/具体下一步。无提交的任务不能因超时自动夺走仍在写的成果；明确交接或协调处理。`clean handoff`不释放本run任务，不能混报。

## 实现验收情景

1. 全文只有UUID/PASS的材料，即使原kind是statement，也能定性non-math；格式通过不授数学价值。
2. 有自足结构的具体数字反例归math-exposition；含数字不自动触发蒸馏。
3. 只有best value/负目标值且无数学主张的输出归evidence-only，不产生昂贵蒸馏任务。
4. “计算”页藏一般证明时第一步能标mixed、定位数学并建议第二步提取；不得按目录批删。
5. 同页多个范围和状态已写清的命题能直接保留，不强拆未来ID。
6. 独立算法合同可归algorithm-result；裸程序名和样本PASS不自动升级。
7. 缺头部、未知kind、暂无引用均不漏清单，也不自动删除。
8. 批次重复、漏项或SHA过期明确拒收；不抹去其它已收批次。
9. 两Boss抢同群或重叠路径只能一方确认占用；冲突后重读，不静默覆盖。
10. 产物仅本地、push响应丢失、真实认证失败分别有准确状态，不混作completed。
11. 第一目录保留非数学、证据、混合材料及其编号；既有历史删除的当前去向可追溯，不从route推断新删除已发生。
12. 第一、二步的记录不要求最终节点ID或超边schema，也不调用旧final gate冒称完成。

程序已实现；本稿的第一步验收看完整带号目录、七类覆盖、第二步候选与六字段记录的对应，以及正文/附件没有因本步建议而改变。第二步任务按现有程序另行开展；不用单元测试证明数学正确。具体第三步接口等另行设计完成后再加适配层，前两步无需重读已完整定性的全部正文。

## 协作程序v2实现

- status聚合实时任务与差量；list默认短行/最多20项，按owner、state、available筛选；--full保留完整输出。
- batch一次正常推送处理多个任务，逐项报告成功与冲突；一项冲突不阻断其它不相交任务。claim可合并预留；finish合并submit+complete；handoff-all一次交接。
- 每次事务只物化run/people/tasks元数据与本次所需输入、资产；Git索引与父提交保留完整原树，不展开整仓正文。
- 正常ref竞争包含receive-pack的cannot-lock-ref/expected变体，并刷新重试；意图和完成回执在本clone Git缓存保存，同request_id可retry，不重复创建认领。
- 新事务记录updated_at；没有该字段的历史任务不伪造活动时间，不增加周期打卡。
- 广播资产验证复用Git对象缓存及浅历史边界；同次公屏发布重试不重复验证同一资产。
- assets仍为path/SHA两字段，复用另记reused_paths；旧任务数据与单项CLI继续兼容。

真实命令见CURATION_OPERATIONS.md。v2仅维护基础设施，不改任何既有数学正文、任务状态、完成结果或其它Boss身份。
