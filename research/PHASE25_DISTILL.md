# 2.5.2 对象群整理：任务、预算与交付

本步不进行全仓真值审查，也不制定后续登记或超边格式。唯一完整入口为[当前阶段提示词](../prompts/02.5-2-distill.txt)，内部处理者按同一数学标准接收具体任务，不另配一套提示词。

## 输入、任务种类与分组

第一步每份材料已被实读并定性；第二步只接收明确的处理对象群。输入至少包含：固定原路径与当前内容指纹、第一步分类与理由、可疑数学段落、同模型相关正文线索、建议动作、写入范围。指纹、读取记录和交接状态由程序与工作区保存，不进入数学正文。

| 第二步任务 | 触发条件 | 应交付 |
| --- | --- | --- |
| 补足数学理解 | 原件有数字/动作表/程序输出，但不清楚对象、被否命题、构造为何起作用 | 可理解的模型、准确命题、精确见证及失败机制；解释不了的环节要精确列出 |
| 简化见证 | 很大的具体例子遮住了少数承重结构，尚无清楚小例或解析说明 | 更小且仍满足全部前提的例子，或说明哪些结构目前不能删；不承诺全局最小 |
| 合并综合 | 同一模型、相近量词和失败机制下有多份数值材料/片段 | 统一构造、参数条件、通用论证或清楚的不同机制划分 |
| 修复整理损伤 | 已定位定义缺失、条件遗漏、拆分失效引用、公式损坏、错误归档 | 原有成熟数学的定点恢复；不用把整组重新发明 |
| 提取算法成果 | 文件实际给出判定器/求解器/算法，具有明确输入输出与保证 | 算法问题、合同、方法、正确性根据、复杂度/适用范围；实现仅作附件 |
| 提取混合页 | 数学与日志、身份、运行过程混在一起 | 抽出实质数学、删除纯过程包装，并指向必要代码或证书 |

按同一数学问题、模型、命题家族、构造机制划组，不按源文件平均切块，不预先指定 LP/拓扑/包络等研究路线。不同模型或者“任意固定背景”与“完整 SPE 实际在轨”等不同量词可以比较，但合并时不得吞掉区别。现成成熟正文覆盖的包装组可直接完成去噪，不占用一整轮新研究。

## 有限综合的执行顺序与预算

默认一组先给 45–60 分钟的探索预算，Boss 可按体量调整。该预算限制新增研究投入，不授权仓促删内容；一个长群应拆分可独立交付子群。所有代理先交能够准确写下的正文，不等全轮结束。

1. **定位已有理解。** 读本组正文与必要同模型定义；使用第一步已给线索定向找成熟结果。已存在充分解释时直接复用、合并包装，不再探索同一结论。
2. **说清当前数学。** 对具体反例写清被否命题及其前提、构造、可行性与违例式。把数字分成承重不等式、整数实现/分母清除、纯冗余；不能仅做文字替换。
3. **尝试有限综合。** 优先比较少量有实质差别的方向，例如减少冗余构件、参数化必要不等式、提取一个结构性充分/必要条件、建立更清楚的模型定义。具体方法由处理者自由决定。每一方向都要说清目标和能覆盖的旧认识，不无限扩展搜索；不预设数学方法。
4. **检查改写与替换。** 参数化须同时保全部承重约束。涉及 SPE 的新构造不得以在轨检查替代完整历史要求；同版成熟证明已覆盖的部分不强制再运行。更强结论若要替换旧稿，必须明确同一模型/假设下如何推出各项旧结论，以及旧构造的独立技巧、平局/等号边界的去向。
5. **写出实质结果。** 交可读正文和极简处置说明。预算用完时可以交准确具体见证、已证局部结构和确切缺口；不得伪造一般定理，不得把“没找到更一般结论”作为删除理由。

通常两轮定向补读/补搜后先整理已得认识；继续补读须明确缺失的上下文和新增目标，仍受本群探索预算约束。只有超出当前任务范围才能恢复时，才交 Boss 重分；不能把所有来源履历重新遍历当研究。计算只在能回答明确数学子问题时进行；程序运行失败或抽样阴性不能当作数学结论。

## 允许的完成出口

| 出口 | 必须说清 |
| --- | --- |
| 已有成熟解释，直接复用 | 哪份正文已解释全部必要内容，去掉哪些重复包装 |
| 得到更简洁见证 | 保留的全部前提、精确违例、简化了什么；不宣称未证明的最小性 |
| 得到一般结论/参数族 | 范围、条件、推导、旧结论的覆盖关系、保留的独有认识 |
| 得到结构理解但未一般化 | 精确机制与可复用认识；哪些约束仍只在当前见证成立 |
| 恢复成熟数学 | 原遗漏/误写的准确位置和修正；保住的原有论证 |
| 当前见证本身不成立 | 哪一前提/比较失败，撤回什么，尚可保留的正确片段；不扩大为主问题已解决 |
| 仍有具体缺口 | 缺哪条定义、等式、可行性或量词保证；保留现有数学，不写“继续研究”空话 |

不能作为交付：读了多少字节、完成多少检查、PASS 表、只有“未发现反例”、只有“建议后续研究”、未解释符号的一串数、仅把旧摘要换个名称。

## 结合实读的两项派发示例

### Lipschitz 数值包装：直接复用，不重复发起蒸馏研究

输入包装页 `archives/customer-attraction/state/反例/customer-attraction实际前缀Lipschitz失败证书--反例.md` 只有 `9<39/4`，符号定义需外读。第一步应标“数值/定义不自足，疑有成熟替代”，不能据此判整个反例未知或需要新的参数化。

成熟正文 `archives/customer-attraction/state/反例/实际前缀单主题比例中继的四人反例--反例.md` 已给 f_r 定义、61 客户、完整策略与全部续局下界，明确实际在轨版本。另一正文 `archives/customer-attraction/state/障碍/R12bf实际前缀比例嵌入统一族与61客户有理复核--障碍.md` 已给五客户任意 k 族及跨主题替代信用机制，限定为任意固定背景，并不保证根 SPE 在轨。

合理任务：删除重复裸点包装，使读者直接到现成解释；保住两种量词。这组不必再花一轮找一般结论，更不能用五客户族替换61客户实际在轨证明。

### UM 的过强拒绝：定点恢复，不扩成全面正确性审查

`archives/unrelated-machines/state/审查/私有组退出池共同宏任务与有界profile联合选择最终审查--审查.md` 的“宏数超过 home 即 FAIL”与本页允许 exit 的匹配合同冲突。队列已提供一个 home、一个 sink、两个宏任务的可行小例。

合理任务：删改这一拒绝规则，解释正确联合匹配条件，保留原有匹配构造和保证。只核受影响合同，不重跑所有历史计算，也不把整组成熟匹配证明退回待证。它本身是局部修复，不应被当作数值反例蒸馏新研究。

算法成果边界：具有输入输出说明不够。固定样本审计、普通LP调用、Fraction复放和已知点核验通常仅为证据；独立判定器/求解器须提供可复用数学方法或归约及准确保证。程序页含独立数学结构时提取该数学，不能因“程序”目录或运行合同把整页直接放行。
