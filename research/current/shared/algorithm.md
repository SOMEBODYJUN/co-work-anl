# 有限菜单搜索与证书：可实现规范

输入和均衡定义见 [model.md](model.md)。本文件说明算法实际做什么、哪些检查足以证明一个实例、哪些普遍保证仍依赖 [proof.md](proof.md) 中的研究义务。

## 1. 一个无序位置对的固定菜单

先根据覆盖列表计算私有质量 A、B、共同顾客的有序列表及共同总重 W。每次加入候选前都用 (NE) 检查；以完整概率向量去重。顾客排序和所有同分规则固定，反向位置对只反射这个菜单。

| 家族 | 生成规则 | 前置条件与用途 |
|---|---|---|
| P | 两个全放一侧种子；每名 h 的两个 singleton 种子；保留精确种子或受保护修复结果 | 非 NE 种子只有在原低侧每个共同原子至少等于初始间隙时可修复；首次反转停止 |
| E | 每个共同顾客独立半分 | A=B；给出同址均分见证 |
| T | 指定 h,j，其余放高覆盖侧；低覆盖侧概率为 (1+D/w)/2，D=abs(A-B)+W-w_h-w_j | D 不超过二者权重；相同覆盖时两种方向都列入 |
| C | 调用一次确定性强弦构造；需要时加反射 | 高/低覆盖 U,V 满足 V>φU/2，W<qV，最大共同权重≤(1-q)U；相同覆盖可直接用 E |

C 在 d 尚未计算时生成。不能在看见坏环后临时选新的平衡；这样会改变最小值并破坏菜单量词。空共同列表的纯空向量合法。全放一侧的 P 种子保证菜单非空。

## 2. 搜索伪代码

```text
Solve(weights, coverage, shared_catalog):
    检查权重正且为精确有理数、客户索引合法、共享目录非空
    对每个无序位置对 {s,t}:
        构造 F(s,t)，保存共同顾客顺序
        若 s != t，令 F(t,s) 为 F(s,t) 的逐成员反射
    对每个有序对 (s,t):
        punishment[s,t] = F(s,t) 中第一设施收益最低的成员
        u[s,t] = 该收益
    对每个 t:
        b[t] = argmax_{s in 完整目录} u[s,t]
        d[t] = u[b[t],t]
    在 b 的函数图中取一个环 T（作为证明/诊断信息）
    best = 空
    对完整目录的每个 (s,t) 及每个 e in F(s,t):
        (x,y) = e 的精确收益
        若 x=0<d[t] 或 y=0<d[s]，跳过
        α = max(1, d[t]/x, d[s]/y)，其中 0/0 贡献 0
        保留 α 最小的候选
    若没有候选或 α²-α-1>0，报告搜索未达到定理保证
    输出路径上 e
    对每个 r != s，输出 punishment[r,t] 作为设施 1 偏离续局
    对每个 r != t，输出 punishment[r,s] 的反射作为设施 2 偏离续局
    默认规则 = 全共同顾客放设施 1 后执行规定的受保护修复
    直接验证输出证书
```

搜索全目录而非仅 T²，不改变渐近复杂度，还可能找到更小的菜单内因子。证明的声称是 T² 已有合格候选。环外位置仍进入每个 d，禁止将其删掉。

## 3. 证书验证的最小语义

对给定证书，验证器必须重新从输入读取覆盖关系，而不是信任证书中的共同顾客列表或收益。依次检查：

1. 路径上和所有偏离布局都合法；概率数量及客户顺序准确；概率为精确有理数且在 [0,1]。
2. 重新计算收益及每名顾客的两个条件成本，验证 (NE)。
3. 实际偏离集合恰为 {(1,r,t):r≠s} 与 {(2,s,r):r≠t}；无遗漏、重复或多余布局。
4. 每个偏离者收益不超过其路径上收益的 α 倍。无需菜单、响应环、d 或全局存在性定理。
5. 若证书声称黄金比保证，α≥1 且 α²-α-1≤0。

剩余布局由规范指定的默认纯修复补全；不能把任意一段默认规则文本当成已验证程序。

现有 [shared_phi.py 的 `verify`](../../../facility_spe/shared_phi.py) 检查上述数值条件，但忽略 `default_continuation` 文本、`menu_threats`、`response_cycle` 等解释字段。因此通过验证的意义是“所给局部见证可由规范默认规则扩展”，不是“附带的任意元数据均真实”。[cli/verify_phi.py](../../../facility_spe/cli/verify_phi.py) 调用同一个 `verify`；它与搜索逻辑分离，却不是另一份独立实现。独立检查器应从条件成本直接重算，并明确固定默认规则版本。

## 4. 运算数、位长与内存

每对 k 名共同顾客，P 有 O(k+1) 个种子，每次修复最多 k 次移动、每次扫描 O(k+1)，合计 O((k+1)³)。T 有 O((k+1)²) 个候选，各需 O(k+1) 实体化及验证。E 线性。候选 C 构造为 O((k+1)⁴)，故全局为 O(N²(n+1)⁴) 次有理运算。

显式存全部菜单概率向量需要 O(N²(n+1)³) 个有理数；最终证书只需 O(N(n+1)) 个概率，加布局索引及输入引用。多项式空间不意味着当前实现做了流式内存优化。

这些运算计数之外还要证明位长：纯修复只加减输入权重；盒切片枢轴为切片目标减去端点的带符号和；混合差除以不超过 k 的整数；概率再除以相应正权重。这些受控表达式具有多项式编码长度。前提是交换算法确如附录 B 的有限阶段界运行；仅知势函数增加或减少不够。

实现的黄金比比较完全精确：对有理数 z≥0，z 与 q 的顺序等于 z²+z-1 与 0 的顺序；z<0 单独处理。C 的覆盖条件可化为比较 2V/U-1、W/V、1-max(w)/U 与 q。只有确认 V>0 才做相应除法。没有舍入黄金比或浮点 NE 容差。

## 5. 可运行入口与证据边界

在仓库根目录运行：

```bash
python3 -m facility_spe.shared_phi examples/shared/tiny.json --output certificate.json
python3 -m tests.test_shared_phi
```

输入的权重使用整数或有理数字符串（例如 `"3/7"`），不要使用 JSON 浮点数。`locations` 是按顾客索引列出的覆盖列表；可省略 U1/U2 使用全部位置，也可同时给出集合相等的非空限制目录。

历史记录包括 753 个完整随机/定向证书、10,206 个小规模局部菜单例和另一批 1,771 个完整枚举实例。这些是不同运行口径，不能不加说明地相加作为独立证明次数。本次文档重写没有重跑这些完整实验。三混合局部例覆盖了 C；753 个完整证书中路径上家族计数为 P 662、E 88、T 3、C 0，故仍缺“全局实际选中 C”的定向回归例。
