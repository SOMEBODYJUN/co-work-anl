# 共同尺寸微任务的可重开容量流：精确接口、整化条件与低成本反例

**研究身份（scratch）**：本稿只保存一个新的可判定正面接口和它的边界，不宣称一般 `R||C_max` 的 `(2-epsilon)` 算法。目标是把“接收机可升载”的 repair 写成一个可验证证书：先用有理流检查共同容量，再用有序槽整化。

## 1. 接口

给定机器集 `M`、微任务集 `U`，以及已经冻结的核心任务分配 `sigma_0`。核心在机器 `i` 上的负载记为 `f_i`。每个微任务 `j` 有资格集 `E_j subseteq M`；在资格边上处理时间必须是同一个有理数 `q_j>=0`：

```
p_ij = q_j  (i in E_j),    p_ij = infinity (i notin E_j).
```

给定目标 `B`，微任务重开后的可用容量为 `b_i=B-f_i`。先删去 `b_i<0` 的机器；零尺寸任务可直接放任一资格端。该接口允许接收机负载上升：只要求最终 `f_i +` 微任务负载 `<= B`，不要求 `f_i` 单调不增。

先检查每个 `E_j` 非空；空资格任务立即拒绝。`q_j=0` 的任务任取一个资格端直接放置并从流中删除。对剩余正尺寸任务定义 `q_max=max_j q_j`（空集时为0）。

### UM-COMMON-SIZE-REOPEN-v1（精确可验证合同）

若存在有理 `x_ij>=0` 满足

```
Σ_{i in E_j} x_ij = 1                         (job cover)
Σ_{j:i in E_j} q_j x_ij <= b_i - q_max        (headroom flow)
```

则可在输入和证书 `x` 的总二进制位长多项式时间内输出整任务分配 `tau`，同时保持核心任务不动，并满足

```
f_i + Σ_{j:tau(j)=i} q_j <= B   for every i.
```

更强的证书级充分条件是：给定任意共同尺寸流 `x`，令
`r_i(x)=max{q_j:x_ij>0}`（空支持为0）；若

```
Σ_j q_j x_ij + r_i(x) <= b_i       (H_i)
```

对所有机器成立，则同样可以整化。统一 `q_max` 只是把支持相关的 `r_i` 换成固定阈值后得到的多项式可检查版本。

## 2. 证明：有理流到真实整任务

对每台机器 `i`，按 `q_j` 非增序把每个任务的分数质量 `x_ij` 放入连续单位槽。槽编号为 `0,1,...,ceil(sum_j x_ij)-1`；每个任务在机器 `i` 上的质量区间连接至它相交的至多两个槽。把所有这些边合并成任务—槽二分图。因为每个任务的总区间长度为 `1`，标准有序槽 Hall 论证给出覆盖全部任务的匹配：任意任务子集的区间总长度等于其任务数，落入的槽数至少该值。

若任务 `j` 被匹配到机器 `i`，只有当它的区间跨越一个槽边界时，才可能比该机器上分数前缀多支付一次任务尺寸；按降序排列，该尺寸至多 `r_i(x)`。故

```
load_i(tau) <= Σ_j q_j x_ij + r_i(x).
```

在 `(H_i)` 下这至多 `b_i`，统一头部条件则因为 `r_i(x)<=q_max` 而成立。加回冻结核心得到目标 `B`。所有槽数至多 `n`/机、每个正区间至多跨两槽；有理比较、排序和增广匹配的总位复杂度多项式。算法没有展开以数值容量为单位的槽，槽按“任务质量”计数，因此不产生伪多项式因子。

## 2a. 无加性损失的单位槽位分支

若某个重开连通分量 `K` 中所有微任务的共同尺寸恰为同一个 `q>0`（机器—任务支持图按资格边取连通分量，分量之间没有交叉机器），则不需要支付 `q_max` 头部余量。把机器 `i` 的整数槽数定义为

```
c_i = floor((B-f_i)/q).
```

在该分量上连源→每个任务容量1、任务→其资格机器容量1、机器→汇容量`c_i`的普通网络。最大流值等于任务数，当且仅当存在整任务分配；流的整数性直接给出分配，且每机负载 `q*c_i <= B-f_i`。因此这是一个**无加性损失的可重开修复分支**，完全允许接收机升载，判定和构造均为位多项式。若 `q=0`，任务逐件放任一资格端即可。

若支持图的每个连通分量都满足“该分量内单一`q`”，逐分量运行上述流即得全局整修复。不同`q`的任务共享一台机器时，该分解失效；即使端点处理时间相同于各自`q_j`，不同尺寸的整数装箱耦合仍可能NP难。该边界可通过连通分量和精确有理相等性在P时间检测。

在这个单位槽分支中，流可以直接解释为可重开增广：把机器 `i` 展开为 `c_i` 个槽，保留当前已放任务的槽占用；从一个待重开的任务出发，沿“任务—资格槽—槽中原任务—其余资格槽”的交替路 BFS。找到空槽时沿路反向交换，得到一次整体重开，接收机可以升载而源机同步释放一个槽。每次增广使已覆盖任务数增加1；无增广路时，BFS访问集给出违反普通 Hall 的最小割。因此该分支不仅可判定，也有逐步 repair 证书，且至多 `|U|` 次增广。

## 2b. 机器倍率可分离时的推广

若资格边上的时间具有 `p_ij=a_i q_j` 形式（机器只贡献公共倍率 `a_i>0`，任务只贡献尺寸 `q_j`），可把机器容量缩放为 `b_i/a_i`。因此分数共同容量再次由等端资格的加权流/Hall 精确刻画；最大流先在缩放容量上产生 `x`，再按原时间重算负载。

若进一步 `q_j=q` 在一个支持连通分量内恒定，则直接使用整数槽数
`floor((B-f_i)/(a_i q))`，普通最大流给出无加性损失整修复。倍率一致性只需在每条有限边检查比值 `p_ij/q_j` 是否同一 `a_i`（可用精确有理交叉乘法）；这是一条可判别的结构分解。若任务尺寸 `q_j` 变化，整数问题仍可能是装箱型，不能把缩放后的分数 Hall 当整性。

## 3. 共同容量的精确分数判别（一般矩阵）

若不要求整化，只问是否存在 `x` 满足

```
Σ_i x_ij=1,
Σ_j p_ij x_ij<=b_i,
 x>=0,
```

这是一个显式有理 LP，故可在位多项式时间内判定并给出有理证书。其 Farkas 对偶条件是：对任意非负机器价格 `lambda_i`，

```
Σ_i lambda_i b_i >= Σ_j min_{i:p_ij<infinity} lambda_i p_ij.       (F)
```

`(F)` 只刻画可分流，不是整任务调度的充分条件。给定固定核心分配后，(F) 是一个真正可计算的共同容量接口；失败时 LP 对偶直接返回价格向量，价格向量是 repair 的精确阻塞证书。

在共同尺寸子类 `p_ij=q_j` 上，把每个任务当作需求量 `q_j`，机器容量为 `c_i`，(F) 等价于普通有理最大流。也可写成加权 Hall：

```
Σ_{j in S} q_j <= Σ_{i in N(S)} c_i    for every S subseteq U.    (WH)
```

算法实际用最大流，不枚举 `S`。对于整化合同，取 `c_i=b_i-q_max`；一旦最大流值为 `Σ_j q_j`，有序槽即给出实际 repair。这样“共同容量”与“可重开”都由一次流和一次匹配闭合。

## 3a. 任意处理矩阵的给定支持头部证书

共同尺寸不是唯一可用入口。对任意有限处理矩阵，若给定一个有理分配流 `x`（列和1），令

```
ell_i=Σ_j p_ij x_ij,
M_i=max{p_ij:x_ij>0}  (空支持取0).
```

有序槽舍入的通用界是 `load_i(tau)≤ell_i+M_i`。因此对固定核心 `f` 和目标 `B`，若某个流满足 `ell_i≤B-f_i-M_i`，则同一轮ST匹配就是一个允许接收机增载的整repair。给定 `x` 后检查和构造均为P；若只给矩阵、不提供支持流，寻找同时最小化所有 `M_i` 的稀疏支持会重新出现离散选择，不能把这个证书误当成一般算法。

## 4. 失败割与可重开含义

从任意当前调度选择微任务集合 `U` 后，固定 `J\\U`，令 `f_i` 为固定部分负载。对目标 `B` 运行上述流：

* 成功：返回一个允许接收机上升的整分配，核心任务完全不动；
* 失败：返回最小割（一般矩阵为 `(F)` 的负价格，等端尺寸为 `(WH)` 的违反子集），明确指出哪些微任务共同争夺哪些接收容量。

因此 repair 不是逐机独立迁移：一次流同时决定所有微任务的接收端。可把失败割作为下一轮“扩展重开集合/重选核心”时的确定性输入；但本稿不声称任意扩展规则都终止或在一般矩阵保持统一余量。该未闭合点正是宏任务选择的难处。

## 5. 低成本精确反例（Python 可复核）

### 5.1 加权 Hall/分数容量通过，整任务无解

两台机器，三件微任务，所有资格边都存在：

```
q_1=q_2=q_3=2,     b_A=b_B=3.
```

分数流 `x_{Aj}=x_{Bj}=1/2` 对每件任务成立，每台分数负载为 `3`；所以 `(F)`/`(WH)` 通过。然而任何整分配必有一台机器接至少两件，负载至少4，超过容量3。把统一头部余量加进去后，`c_A=c_B=1`，总需求6无法通过流，正确拒绝。这说明不能把分数共同容量直接当作实际 repair；至少需要一个可验证的整化余量，或使用更强配置证书。

### 5.2 异端处理时间破坏“取每件最小尺寸”的错误流

两台机器、三件任务、目标容量 `b_A=b_B=3`，实际矩阵为

```
       A    B
j1     2  100
j2   100    2
j3     2    2
```

若错误地以每件最小值 `q_j=2` 建共同尺寸流，则三件各半分到两机，得到两台容量3，错误地报告成功。实际完整边都可保留时，枚举八种整分配：`j1` 必须在A，`j2`必须在B，`j3`去任一端，故某机负载为4，实际无解。该例精确说明 `p_ij=q_j` 的等端条件不是记号便利，而是整化证明的必要入口；异端时间必须回到一般配置/广义指派问题。

### 5.3 固定核心只可由共同流整体修复

将5.1的三件任务视为从任意当前来源迁出的微任务，冻结其余负载使两台接收容量各为3。单个任务逐一搬运都可能暂时可行，但最终第三件必与另一件冲突；一次共同流立即给出最小割。若把核心负载改变，容量 `b_i=B-f_i` 会联动变化，不能把各目的地的独立撤离 LP 拼成共同调度。

## 6. P 可计算性与位复杂度边界

* 一般矩阵的可分共同容量：显式有理 LP，P 可判定；Farkas 价格向量给失败证书。
* 共同尺寸矩阵的流证书：有理最大流，P 可判定；(WH) 只作数学解释，不需枚举子集。
* 给定流 `x` 的整化：有序槽匹配，P 可构造；检查 `(H_i)` 只需扫描正支撑。
* 未给流、要求直接寻找满足 `(H_i)` 的稀疏支撑：支持相关最大项使约束非线性；本稿不声称有一般 P 搜索器。统一 `q_max` 头部版本绕开了该搜索，但可能因余量过保守而失败。
* 若允许异端时间 `p_ij`，即使分数 LP有解，整任务可行性包含两机多件相等处理时间的 `P||C_max` 子问题；无一般多项式精确判别，除非 P=NP。

## 7. 与 UM-TARGET-v1 的准确关系

该接口可以作为一般算法中的一个**可验证 repair 分支**：从任意 2-近似状态选一组共同尺寸微任务，冻结其余任务，按目标 `B=(2-epsilon)T` 运行流；若成功即得到真实次二调度。失败割准确告诉算法需要扩大重开集合或改变核心。它允许低负载接收机升载，避开纯逐坐标单调修复的已知障碍。

它不能单独解决一般实例：

1. 任意矩阵中没有等端 `q_j` 表示；
2. 固定核心/宏任务的选择仍可能是共同容量 NP 难；
3. 分数共同容量没有整性，5.1 是最小反例；
4. 统一 `q_max` 头部支付若接近 `T/2`，只能回到约 `2T` 的界。

因此建议把本稿登记为**给定共同尺寸微任务集合的正面 repair lemma + Farkas/最小割阻塞接口**。其最可能推进一般实例的用途是：先由一个更高层结构提取共同尺寸微任务，再用一次联合流而非逐机撤离；高层结构选择和统一余量仍是下一义务。

## 8. 外部承重事实

有序槽整化是 Shmoys–Tardos 的经典 generalized-assignment 舍入：给定分数覆盖，按机器槽排序可使整负载不超过分数负载加该机正支撑最大处理时间。无结构的 `R||C_max` 仍只有经典2近似；配置 LP 在 unrelated graph balancing 上也可有积分间隙2。本文只调用前一事实作为给定证书后的确定性整化，不把它误写成一般 `(2-epsilon)` 算法。
