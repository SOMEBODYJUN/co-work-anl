# 全局基数匹配探针与紧凑共享逃逸间隙

主目标UM-TARGET-v1仍OPEN。本文完成前一阶段“保留资源任务身份、多槽匹配能否修复共享容量”的接口核验：全局基数匹配给安全的位多项式过滤，固定全行下界时一次查询已涵盖所有资源子池；但一族多项式规模的实例同时通过全部查询、全部单机配置条件计数见证及GPC₂，整数最优值仍趋近2。本文不排除条件LST、条件配置LP、真正同时负载约束或OPT相对算法。

来源：匹配子程序是[GHMR的任务权增广](heavy_matching_residual_and_escape.md)的标准容量扩展；紧凑族是[容量一资源星](minimal_star_contraction_and_capacity_gap.md)加全局激活缺口及低成本共享逃逸，本轮主研究者直接构造、内部审查者独立重构。共享逃逸的机制来自boss3既有族及其公屏162的低成本参数攻击；本稿不用两树/高度放大。原资源机制见BLMRS原文§2.1.2，已取得版本/定位沿用manifest。没有全球新颖性、独立论文价值或外审认证。

## 1. 精确的全局单行查询

对象为UM-MODEL-v1。输入合法P、有理T≥0；初始域D_j={i:p_ij≤T}，空域拒绝。当前域只删边。令n为任务数，对每机器i定义

\[
 h_i=\min\{p_{ij}:i\in D_j\},\qquad
 c_i=\begin{cases}0&\text{空行},\\n&h_i=0,\\
 \min(n,\lfloor T/h_i\rfloor)&h_i>0.
 \end{cases} \tag{1}
\]

每个当前T调度在i上至多安排c_i个任务；c_i只是必要基数上界，不是负载容量。

对每个存活边j→v，固定它并去掉j，暂时禁止其余任务放v。令

- Q_vj={a≠j:v∉D_a}：必须在v外完成的任务；
- B_vj={a≠j:v∈D_a}：可留v或外送的任务，任务权w_a=p_va。

在机器M\{v}上以容量c_i找覆盖全部Q_vj的b-matching，并最大化被匹配B_vj的总权W。没有这样的匹配，或

\[
 p_{vj}+\sum_{a\in B_{vj}}p_{va}-W>T, \tag{2}
\]

就标记删除j→v。同步删一轮，重算(1)，至拒绝或无删除。称为**全局单行基数过滤**。查询中的匹配给一个全部任务分配：匹配任务去对应外机，未匹配B与j留v。它仅保证v的真实负载最小、其他机器任务数≤c_i；其他机器真实负载可能超过T。

`UM-GLOBAL-ROW-COUNT-FILTER-v1`：对所有上述P,T，该过滤确定性总位多项式，保留每个T可行调度的全部边；拒绝蕴含OPT>T，接受没有调度保证。

**安全性。** 若当前域保留T调度σ且σ(j)=v，将σ中去v外的任务限制到Q及B，得到覆盖Q的容量匹配。σ在v的真实负载不小于(2)左侧。因此不删σ的边；同步删边及重算row min仍保σ，归纳成立。T=0只剩零边，c_i=n或0，逐任务任取零边即零调度；空任务直接给空分配。

**精确匹配与总位长。** 每机器复制c_i≤n个槽，任务只能用其当前域对应的槽。先增广覆盖Q，再将B按非增p_va依次增广，不能增广则跳过。覆盖Q的可增广集合是收缩横截拟阵；也可直接用GHMR的每权前缀最大基数证明，得到最大任务权。任务权依赖a而非目的边，不能把此贪心扩大到任意边权。每查询至多n次增广，图至多mn槽及ne条边（e为原存活边数），均多项式。非终止轮至少删一边，查询总数≤e(e+1)。h_i来自输入，floor用精确整数除法，c_i截断n避免复制二进制巨大容量；权和的公分母位长至多输入分母位数总和。输出过滤域/见证均为多项式大小。规范代码不实现通用近似算法或目标搜索。

### 为什么无需枚举同一下界的全部资源子池

固定全行有效下界H_i≥0及由其得到的同一组c_i。对任意R⊆M\{v}，子池查询只保留D_a⊆R的必选任务及v∈D_a、D_a\{v}⊆R的可外送任务，按同样权最大化卸载。若全局查询有v负载≤T见证，限制该匹配到子池上述任务：每个必选任务仍在R，匹配的可选任务也必在R；未匹配可选子集的非负权不超过全局未匹配总权。因此子池也通过。全局R=M\{v}本身是一个子池，故全局查询恰支配全部这些R查询。

此处H/c必须固定。若每个子池依据仅涉其内的任务重新提高H_i，就不是本等价合同；不能声称本过滤支配这些更强规则。(1)用全当前行min，是针对该行的最大通用逐任务下界。

## 2. 多项式规模的紧凑族

固定整数k≥2，N=2k²，G=N−2k。机器：N个中心V_a、G个全局机G_g、每块a的k+1个局部机R_a,ℓ，以及一个共享机z。任务如下，其余边不可用。

| 任务 | 全部有限时间 |
| --- | --- |
| X_a，a∈[N] | V_a及全部G_g，均1 |
| Y_a,s，每块k个 | 本块全部R_a,ℓ上1，共享z上1/k |
| Z_a,s，每块k个 | V_a上1/k，本块全部R_a,ℓ上1 |

机器数m=2k³+6k²−2k+1，任务数n=4k³+2k²；显式稠密或稀疏输入均为k的多项式，数值仅{1/k,1,∞}。与前稿k块/缺口1族不同：本稿是N块/缺口2k，加共享z，故另立身份。

**整数最优θ_k=2−1/k。** 假设B<θ_k<2。每全局机至多接一个X，故至少N−G=2k个中心收到X。每个这样的中心若保留≥k−1个Z，负载至少θ_k；所以至少两个Z去本块R。k+1台R每台至多接一个单位任务，k个Y中至少一个必须去z。至少2k个不同块各送一Y，z负载≥2k/k=2>B，矛盾。上界：选任意2k个活跃块，X留中心、一个Z去本块R、其余Z留中心，k个Y占其余k台R；其他X分别给G，其他块全部Z留中心、Y用k台R，z空。最大负载恰θ_k。

## 3. 完整配置及全部两机器见证

T=1时，V_a选{X_a}权1/k、选全k个Z权(k−1)/k。每G_g对每X_a选单项，权1/N。每R_a,ℓ对每Y_a,s选单项权1/(k+1)，对每Z_a,s选单项权1/[k(k+1)]；z总选空。机器权和1，所用配置负载≤1。X总覆盖为1/k+G/N=1，Y覆盖1，Z覆盖(k−1)/k+1/k=1。

GPC₂沿[前稿§4](minimal_star_contraction_and_capacity_gap.md)的完整单机边际/不双选合同。G–G将X_a和X_(a+1 mod N)配对，权1/N。相同块R–R及V–R沿前稿公式（仅使用块内k，不使用总块数）。V_a–G的耦合为：

\[
\begin{array}{c|c|c}
V_a&G_g&\text{质量}\\\hline
\{X_a\}&\{X_b\},b\ne a&1/[k(N-1)]\\
\{\text{全}Z_a\}&\{X_a\}&1/N\\
\{\text{全}Z_a\}&\{X_b\},b\ne a&1/N-1/[k(N-1)].
\end{array} \tag{3}
\]

N=2k²、k≥2保证末项非负。左首行总量1/k，每个右列1/N；所有正质量配置不交。其余机器对支持任务集不交，取乘积，包括所有与空z的pair。故GPC₂(1)可行。没有声称这些pair可共同拼为全局分布。

## 4. 每一机器都可以在全局基数见证中完全空置

初始row min在V及z为1/k，c=k；G及R的row min为1，c=1。下面构造**全部任务避开任意指定机器v**的分配，只满足这些任务数上界。它不是T调度。

基线：选2k个活跃块，按整数上界调度分配。活跃中心接X及k−1个Z，总任务数k；非活跃中心接k个Z；所有G/R至多一任务，z空。

1. v=V_a：选2k个不含a的活跃块，X_a给某G（N−1≥2k且G≥1）。块a的k个Z占k台R，一个Y占余下R，其余k−1个Y给z，任务数≤k。其他块按基线。X总数及全局槽数恰配平。
2. v=G_g：选2k+1个活跃块，其余X用剩余G；每活跃块只外送一个Z，其他照基线。N≥2k+1。
3. v=R_a,ℓ：使a非活跃、选2k个其他活跃块；块a的全部Z留中心，k个Y恰用其余k台R。
4. v=z：采用基线。

全部数目不等式在k=2也成立。给任意存活边j→v，从该avoid-v分配移除j并给v，其他机器计数只减，v真实负载仅p_vj≤1。因此全部边的第1节精确最优查询均通过，首轮零删除。

还有更强的准确结论：对**任意**机器v及**任意**C∈C_v(1)，从avoid-v分配移走C并把C完整放v，就得到“v精确取C、其余机器仅按c计数”的全部任务见证。故即使检查每一个单机配置的这种全局计数延伸，本族也通过；此句不假称指数多配置检查可多项式实现。见证在v满足真实负载，在其他机器不满足一般负载约束。

极小超载星无起点：中心删一个最小Z后仍θ_k>1；G删一项后N−1>1；R删一项后2k−1>1；z删一项后N−1/k>1。每任务至少四可用机器，既有单/双域计数闭包也无起点。因此与这两种预处理交替仍无变化。

`UM-COMPACT-COUNT-ESCAPE-GAP-v1`：上述全部k≥2族满足OPT=θ_k、GPC₂(1)可行、极小星与既有计数闭包无起点、全局单行基数过滤首轮不删边，并有每机每配置的计数延伸见证。故这些必要条件的合取不允许相对接受T统一保证(2−ε)T（任何固定ε>0，取k>1/ε）。仅配置投影/ST已给任意接受实例OPT≤2T；若先消元，则用原消元定理恢复到max(2T,T)=2T。所以该合同在正OPT输入上的上确界gap恰2。无须声称接受对一般T单调、阈值可多项式求得或T_CONF在本族恰1。

## 5. 失败机制、核验与下一义务

这不是再次遗漏资源任务身份：全局匹配已覆盖所有没有v的任务，容量亦允许多槽。失败在其他机器的任务数不是共同真实负载：活跃中心能在计数k内接一个X及k−1个Z，却有负载θ_k；一个查询可以把这类超载移到其他中心。z的k槽只在当前被精确检查的中心确需全部卸载时使用，其他查询不保同一个负载见证。所有单机配置分别通过仍不修复这一点。

可回收：安全精确查询、全池支配同下界子池的引理、多项式规模攻击族、显式完整pair和avoid-v证书。重试必须让多个中心的激活/卸载与共享z容量**共同**成立，或引入与该计数见证不同的信息；不能把逐机最优匹配拼成调度。通用条件块切面分离、可求解耦合与统一舍入仍未闭合。

已有[条件块计数机制](joint_matching_completion_and_block_cuts.md)也能修复本族，不能宣称本文绕过它。对1≤B<θ_k，设r_B=k−⌊k(B−1)⌋≥2。每块有效切面是Σ_s x_(z,Y_a,s)≥(r_B−1)x_(V_a,X_a)，因为X在中心时至少r_B个Z外放，k+1局部槽迫至少r_B−1个Y去z。全局G的单位槽给Σ_a x_(V_a,X_a)≥2k，于是z分数负载≥2(r_B−1)≥2>B，任何配置证书都被排除；B=θ_k由整数调度可行。因此沿用该机制可恢复本族阈值恰θ_k。这只是旧条件块证明的直接适配，不另立新成果；剩余义务是一般可分离性/统一舍入。

规范审计：`tests/audits/unrelated_machines/row_count_probe.py`枚举小矩阵，独立全分配oracle核每次查询的精确最小行负载及过滤安全；`compact_count_escape.py`核配置/全部pair，实际运行k2全部边查询；`independent_row_count_escape.py`不导入上述实现，独立构造全部avoid-v分配、pair校验与单块真实转移的精确对称DP。实际参数、Python版本、源hash、运行命令、有限范围和未查范围在`evidence/runs/unrelated_machines/row_count_escape_audit.json`；输入k2与单机配置证书分别存examples及certificates。所有运算为Fraction/整数，无误差容忍；有限计算不是普遍证明。冻结独立审查见`research/reviews/unrelated_machines/row_count_escape_review.md`。

Truth：声明范围有自足证明并按实际覆盖独立攻击。Value/Mechanism：明确完整身份/多槽仍不替代多机共同负载。Novelty：标准匹配与已有资源机制的专门接口扩展，全球新颖性未认证。Ambition：没有统一近似突破；下一步应攻共同条件容量，避免继续只加强逐查询最大撤离值。
