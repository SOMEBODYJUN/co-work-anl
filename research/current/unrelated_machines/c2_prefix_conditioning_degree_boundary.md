# C₂ 负载证书不能免费提供深层真前缀容量

本稿记录一个精确的表示边界，供条件矩和联合容量路线使用。它不否定 `UM-TARGET-v1`，也不声称 C₂ 松弛本身的完整间隙；它证明：若只给到四阶的真实分配矩（通常记作 C₂-load），则深度四的真实前缀容量并不由该数据决定。任何反复条件化路线必须额外提供更高阶矩、紧凑条件 oracle，或每一步重新生成证书。

## 1. 矩与条件负载

每个任务有 one-hot 选择变量 `x_e∈{0,1}`（同一任务的两个机器 literal 互斥），令

```
y_S = E_μ[∏_{e∈S} x_e].
```

给定相容前缀 `F` 且 `y_F>0`，机器 `i` 的真实条件平均负载为

```
L_i(μ | F) = (Σ_{e∈E_i} p_e y_{F∪{e}}) / y_F.       (1)
```

因此深度 `|F|=t` 的标量条件负载需要 `t+1` 阶矩。条件 degree-one 负载 localizer 的矩项最高次数为 `t+3`，完整条件 C₂ 矩及其 localizer 需要最高 `t+4` 阶。由四阶表只能直接得到 `t≤3` 的标量条件负载，不能自动得到深度四的 continuation capacity。

若 `F` 的概率为零，(1) 不定义；算法必须裁剪该分支或另给条件证书，不能把除零视为容量结论。

## 2. 两个真实最优、低阶相同的来源

取机器 `A,B,C`，阈值 `T=2`。任务 1–4 在 A、B 上处理时间均为零。任务 5 和任务 6 在 A、B 上处理时间均为 `3/2`；用五位 bit `z` 定义：`z_5=0` 时任务 5→A、任务 6→B，`z_5=1` 时任务 5→B、任务 6→A。任务 7 只允许在独立机器 C 上运行，处理时间为 2。对任务 1–4，`z_r=1` 表示选 A，`z_r=0` 选 B。

令 `μ_even`、`μ_odd` 分别为所有五位 bit 串中偶、奇 Hamming 重的均匀分布，各有16个支撑调度，并在每个支撑调度固定任务7→C。每个支撑调度的 A、B 负载各恰为 `3/2`，C负载恰为2；任务7给出 `OPT≥2`，故两份分布都是真实 `OPT=T=2` 调度分布，而不是仅仅 T-可行伪证书。

对任意涉及至多四个不同任务的相容 one-hot 单项式，指定的 bit 赋值都有恰好相同数目的偶、奇补全（未指定的第五位翻转 parity）。因此 `μ_even` 与 `μ_odd` 的所有阶数 `≤4` 矩完全相同，包括由这些矩组成的 `M₂` 和所有四阶 C₂ 负载 localizer。

现在取相容前缀

```
F={z_1=z_2=z_3=z_4=1}.
```

在两个分布中 `y_F=1/16`。偶分布条件下 `z_5=0`，任务5在A、任务6在B；此时若下一步试把任务6放到A会得到 `3>T`，放到B才保持容量。奇分布条件下 `z_5=1`，任务5在B、任务6在A；此时恰好相反。隐藏条目 `y_{F∪{x_{B,5}}}` 是五阶矩：偶分布为0，奇分布为 `1/16`。同一个四阶 C₂ 输入在同一深度四前缀上，不能判定哪一个继续边仍满足容量；该差异不是来源不真实或 OPT 不同造成的。

## 3. 可核验范围与复杂度

上述 parity 事实可由 32 个 bit 串直接枚举核验；每个支撑调度的两台机器负载、`y_F=1/16` 及五阶差异均用整数计数得到。给定显式四阶表和 `F`，式 (1) 的分子、分母只需多项式次有理数加法与交叉相乘；但从四阶表继续到深度四必须取得五阶条目。深度 `t` 的完整条件 C₂ 一般需要 `t+4` 阶；显式存储所有条目随 `t` 指数增长。

## 4. 研究含义

这是一条 `limits` 而不是主目标反例：同一矩阵同时存在两份真实、`T` 可行的低阶来源，低阶数据无法识别深层条件容量。它精确排除以下未付义务：“把四阶 C₂ 证书重复条件化若干步，就自动得到共同真实容量”。可回收接口有三种：

1. 输入高阶/全 prefix 的条件 oracle，并证明其编码长度与查询时间位多项式；
2. 每步重算一个新的残余证书，并证明条件 PSD 与容量局部化；
3. 使用不依赖深层前缀的联合舍入或交换机制。

不能把真实最优分布的存在当作上述 oracle，也不能把有限 parity 枚举升级为一般调度困难性。
