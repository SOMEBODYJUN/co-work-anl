# 从原题持续研究，再把成果接回仓库

当前研究入口是[完整 Main 启动词](../prompts/research-runtime.md)。实际命令、JSON 字段、超边采用和回流合同集中在[完整执行流程](agent-design/HYPEREDGE_WORKFLOW.md)；这里说明日常分工和保存边界。原研究公屏已退役，不按旧词恢复公屏或创建替代页。

## 开题与四人的工作室

先恢复本对话已有目标和 RUN；新开题固定用户原题的模型、域、全部量词、约束及成功标准。原题没有准确正文就写本 RUN 的 problem.md/definitions.md。没有相关成果可以空 seed_ids 研究，不为进入图而更改问题或硬选已有节点。没有用户指定原题时只完成工程准备。

用 `research studio init RUN --spec PATH --expect-branch BRANCH --expect-remote URL` 复用现有 init，生成两份准确输入 packet 和 `research/workspaces/<RUN>/` 下的四个原目录。Main 实际派工，查看超边和短回执，串行发布。

independent 从同一原题、定义和允许障碍独立研究。informed-a 负责 idea，给出可检验路线及首个区分步骤。informed-b 按义务实读原文、执行数学和实现。上下文充足时可以 followup。临近上限时原代理保存逻辑断点和精确引用，再换 fresh 工作者接续，不继承整段聊天。反馈交给原作者修具体推理。

`studio line` 调原来的 save，记录真实 agent_id、配置、本次 session_tag 和同一条不可变 notes/events 链；反馈答复实写后才 ack。恢复时查 Work 实际状态，旧 working 或 agent_id 不证明仍在线。跨会话不能接续就从准确 packet、最新数学、未答反馈、应用和外部 job 标识重新派出，保原线路的数学身份。旧 RUN 的 resume 仍可读；新四槽合同不静默改旧试跑的输入。

## 每个中间结果如何保存

每位研究者连续维护自己的 journal。精确陈述、推导、反例候选、失败范围、计算输入输出或下一义务有接续价值时，及时 save 并由 Main 串行 checkpoint。未审草稿和失败尝试也保存，标清状态；不等全部核完才保全，不以保存成功提升数学等级。

普通推导只需 journal/save。只有要定位复用或冻结回流的承重结果才加 artifact；真正使用一条超边才写 application。单次算术、普通代入、同一论证改写和无独有作用的数值点不逐个造节点、表单或任务。

完整知识仍在正文与必要证据。registry 是稳定身份和版本定位，map/edges 是真实数学关系，投影可以重建；RUN/studio 不建立第二套真值。程序保存的 owner 与 profile 是恢复和输入约定，不能当作共享文件系统的安全隔离。

## 超边怎样变成研究义务

子代理从缺失的实际结论 search，用 context/frontier 跟当前义务的边和依赖，再以 show --body 和原文件读承重段落、必要 evidence 和精确反驳。每条边内全部前提 ALL，不同证明分别 OR。子代理保完整论证，向 Main 交结论、边 ID、证据位置和剩余。

采用时在本 RUN 写全对象/边版本、变量模型和量词对应、每个共同前提、自由文本条件、closing implication，以及证据或精确未付义务。条件债务沿显式应用依赖传递；改名、换人或开放等价环不能消债。局部 contribution 的 result 可以复用，目标 remaining 继续存在，只有具体证明和复核才能支付。失败辅助桥与反驳原题分开，有限扫描与普遍结论分开。

## 成熟结果怎样入现役登记和超边

Main 对有独立复用价值的数学负责定向回流，原题仍开放也及时发布准确局部、条件、有限或开放结果。写对应 state 正文和必要证据，比较稳定身份；同一命题实质改版增 version，新命题才新 ID。写对象 batch 和有实际数学作用的关系 JSON；零边也可以是准确交付。

未登记的新端点可用现有 `edge-bind/edge-check --batch-file` 在内存合并后绑定检查，不先将未审对象写入唯一总表。新承重引理、关键合成及决定性计算交未参与论证者临时复核准确冻结版本，审查保具体步骤、范围、错误与修复证据。不占常驻审核槽，不把“没找到错误”当正向核完。

`artifact → freeze → review → promote` 只用于这类承重交付。冻结须含完整正文、应用的新桥与证据、待发布对象和边 JSON；修复产生新版本。promote 生成本 RUN 的全量 registry 候选及回流收据，并不表示已经登记。Main 再用原 `register`、正式 edge-check、research check/build 和 checkpoint 完成实际回流；只有确认 pushed 才称远端保存。register 的基线守卫拒绝覆盖已推进的 registry；同步后重建增量，不丢同行结果。

研究增量用 `check/build`。旧整阶段验收参数已移除，新研究保自己的定向范围和精确证据。

旧证据被核实有误时，先停用精确失败支持，修当前正文、版本、命中引用与实际消费者；保有效 OR。不能自动把全部后继判假，也不让无关研究等待全仓重清洗。具体更正和接手位置随数学保存。

## 持续执行与完成

计算围绕具体数学问题选后端：短计算当前环境，普通批量优先现有云端通道，Codespaces 用于确需持续交互或特殊环境。保存真实脚本、输入、原始输出与 job 标识，不能用进程成功、收敛或 PASS 替代证明。见[云端入口](GITHUB_RESOURCES.md)。

Main 和三线异步推进，成熟即交，重复失败时综合最强近成功及准确排除范围，再转向实质不同的表示、机制或合成。以覆盖原题全部域、量词和约束的完整证明，或满足全部条件并否定目标的见证判断闭合。内部复核、形式化、外审与发表分别说明。没有闭合就持续有价值研究到用户暂停或真实运行边界，保存原输入、四人笔记、未付义务、反馈和下一动作，不声称后台继续。

[来源和取舍](agent-design/SOURCES.md)说明借鉴边界；当前能力以实际运行与准确版本为准。在其它仓库复用用现有 export_research_template：只带工具、完整提示词与合同，不带本项目数学、凭据、历史或代理；从空 seed_ids 也能开题。
