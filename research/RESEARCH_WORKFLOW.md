# 从已有数学到实际研究，再把成果接回仓库

前置登记给出准确数学身份与正文位置，超边给出完整的支持、反驳和迁移关系；现在围绕用户原题做新研究。Main启动词见[完整Main词](../prompts/research-runtime.md)，两个内部词分别供obstacle/full使用；命令与格式见[IMPLEMENTATION](IMPLEMENTATION.md)，输入spec见[现有模板](templates/research-packet.md)。用户不用另上传一组内部文件。

## 原题、输入和分工

先恢复本对话/RUN已有目标，按用户任务写准模型、定义域、量词、约束与成功目标。获授权自主选题时，从指定范围有价值的开放义务或承重缺口选定目标；只有关键题意仍无法确定才询问，不为了启动改成无关数值特例。

Main核准原题和承重定义，及时把长材料定位、沿超边取证和旧路线比较交空历史子代理，自己继续研究。缺口尚不明确时，长线研究者须综合现有数学、失败机制及最新工作区增量，提出有根据的研究前沿；不要求Main或用户先知道全部种子与缺口。子代理按结论实际能为原题提供什么选择并扩展seed_ids，而非按标题热度或图连通率。原题和定义尚无文件时，保完整原意写入research/workspaces/<RUN>/problem.md及definitions.md，已有准确正文则直接引用；连同有用障碍组成同一spec。没有相关成果时用空 seed_ids 启动，研究者从原题直接推进。

普通研究以 Main 负责主线综合与本 RUN 的 Git 发布，长线研究者负责各自可演变的数学路线，按需派机动代理。用 `research init RUN --spec <路径> --mode open` 生成 full packet，初始没有预设槽位或数学方法。明确需要对照实验时用 comparison 模式保其输入隔离。已有 RUN 恢复原数学、来源及反馈；普通研究按当前设计重新判断派工，不机械恢复失效调度。

Main 通过平台真实派工，给精确子命题、当前条件、候选超边、已有结果/失败边界和独立笔记 `research/workspaces/<RUN>/<solver-id>.md`。普通研究默认 gpt-6.1-sol / ultra / fork_turns=none，用户明确指定时照办。首次实质派工用 `research save` 记录实际 agent ID、model、reasoning_effort、fork_turns 和下一步，后续记录推导和反馈；旧记录的未知配置不补猜。对照运行按原 profile 反馈。

## 同题 Main 的档内文件公屏

`research peers RUN` 按已保存 packet 中原题与定义的精确引用发现其他 RUN，返回 `<所属存档或子档>/collaboration/P-…/README.md` 及各 Main 笔记。普通 open 的 init/resume 返回同一入口。所属档从保存的原题路径或显式 collaboration_scope 恢复，不从当前clone配置或跨档定义猜。原题暂在workspaces时可在spec指明scope；未定归属返回scope-required，先做数学再补准确入口。原题相同而定义不同、同路径改版的RUN另列为待核对应，不自动合并数学身份。problem_id不是跨Main唯一题目标识。发现基于本地快照，先安全同步；working和历史solver_count不证明进程活着或占槽。

文件板与成果在结果分支：读用work.py sync后打开入口与变化文件；发布用checkpoint保存本人BossN.md和相关数学文件，确认pushed。旧read/send/inbox仍属原阶段公屏，不是此板收发入口。共同README保原题、可复用数学、关键缺口和RUN入口；本人板页只保当前断点、输入、交付和接用位置，完整历史按需追读，不把大段旧主笔记每次重新塞给Main。研究开始、派新义务、收到成果及路线转折时读取变化文件。昂贵工作先发表具体义务/输入，确认pushed后再同步核撞题，发现重合便接用或拆分。这里没有原子锁，不承诺完全消除重复；有目的的独立证明可并行。

合作先是研究认识、可复用推导、决定性障碍和更正改变另一条路线，不把公屏做成跨Main互相出题验算。常规核验自家子代理完成，同一昂贵计算共享只是特例。接收方给实际代入位置和新一步，或精确不兼容条件与所需桥。成熟工作区数学可以先用，登记与超边回流随之进行。不同系统先核域与映射，有限最优数值不冒作普遍结论；跨档成果保原owner与条件映射。旧合作入口只留迁移指针。第三阶段期间保留所有旧阶段公屏，全部结束并由用户指定的1号下令后才退役。

## 子代理取证，Main 接回数学

取证代理从当前义务沿ALL前提、OR证明、反例、勘误和增量实读，可跨有数学映射的存档。向发起者或指定回送对象交可代入结论、变量映射、全部承重条件、关键推导、作用、仍欠的桥及出处；完整证明/代码/输入留文件。原研究者接回本路线，Main收需综合的片段，长度由数学需要定。

长线研究者自主拆解本路线、挑战Main设想、做新推导，并能按需派空历史取证或挑战代理。每层都给真实配置和必要任务，不依赖继承上下文。嵌套不可用时Main代派，问题写明发起者和回送对象，结果直接交回原研究者代入，不把全部阅读又吸回Main。临时请求以本次接口为目标，full原题只是约束背景。Main核关键综合接口，具体证明核验、矩阵材料化及机械重放可由其他强子代理承担，不把Main亲自全算当研究准入。

长线线路ID与一时的数学义务不同：局部引理完成后线路有价值就接原代理继续，临时Reader完成才释放；路线结束、需独立重开或不可恢复才换研究者。使用真实平台状态调度，不为填满并发挤掉机动能力。满槽有阻塞请求时，先促低优先短任务交付，必要时保存暂停可恢复线路并按平台能力腾位；否则保请求/回送路径，继续不依赖它的数学，首个空位优先处理。暂停线路之后接回，不虚称已释放或后台仍执行。没有固定研究者配比、压缩率或轮数预算。

研究主笔记随成果重新判断：当前表示和局部进展距原题还欠哪条桥？新增计算若成功会改变什么？重复同一失败机制或只改善同一松弛时，综合准确失败范围、最强近成功及未探索部分，提出实质不同的分解/表示/构造或解析合成；写清新路线逃出哪项旧限制及什么证据能改变决策，不硬指定LP以外的固定方法。取到几条边、生成多少证书不能替代此判断。

## 独立挑战与修复

新的承重引理、关键合成、原题闭合主张及决定路线的精确计算，在作为已确立前提发布前，由未参与该论证的研究者独立挑战。Main主动派发，不以作者先感觉有疑问为前提；已独立核验且内容/版本/用法一致的支持可复用，普通步骤不层层设卡，待挑战候选可明示条件继续探索。不是常驻审批席，也不是不读成果的obstacle对照组。

挑战者收到准确陈述、完整证明/见证、原题定义、实际依赖及必要代码输入输出，定向追证，不接作者“应当正确”的预设。检查模型/量词/条件、联合前提、循环依赖、边界和离轨约束；关键计算还核实际执行与宣称是否一致、是否漏case、伪穷尽、错误剪枝或超时误报。交付写在实际数学笔记中：核验范围和输入，错误/缺口的具体位置、原因和影响，成立部分、修复要求及当前支持范围。程序正常退出、作者自审或多个代理同意均不替代数学判断。

挑战还须按证明顺序正向核承重步骤与引用，未找到反例不当核完；关键证据缺失或仍有gap保未核/候选。原笔记保被核文件/精确版本、核验者/报告位置及范围。问题回原研究者实质修论证/代码/证据、补条件或放弃，改变的陈述、条件与受影响调用接口再查，未受影响已核部分复用；不只改报告为通过。分歧核证据，不投票。Main保结构选择、关键合成和发表判断，不全量重放所有已独立核过的证明/矩阵。[上游机制](UPSTREAM_ADAPTATION.md)给具体来源与边界。

## 研究记录放在哪里

| 内容 | 位置 | 保存时机 |
| --- | --- | --- |
| 原题、定义和当前研究笔记 | `research/workspaces/<RUN>/` | 开题固定原题。证据、局部推导和下一步有实质变化时更新。 |
| 证据包、不可变事件和接续状态 | `research/runs/<RUN>/` | 用 `init` 生成输入，用 `save` 记录实际推进和反馈。 |
| 可复用数学 | 对应 `archives` 的正文、`research/registry.json` 与相关 `map/edges` | 复核后定向回流。原题仍开放时也可以发布准确的局部结论。 |
| 可复算证据 | 相应对象的证据位置及计算回执 | 保留脚本、输入指纹、原始输出和精确的数学解释。 |

## 怎样取用已有数学

search定位后，用show --body读实际正文，用context展开当前要用的证明。核模型、量词顺序、前提、结论和适用域；共享名字、引用或可达路径不证明结论可迁移。完整知识在archives正文及必要证据，registry是定位，graph-v2及三级投影是导航，不另维护数学真值。

单条支持内部为ALL，不同证明为OR；选定分支的必要前提闭包不能因hops而截断。equivalent_to反向也需全部target_ids；定义按当前问题需要读，不经人为模型hub。把条件、各前提作用、变量映射、解释、证据和未付义务一起取用。accepted conditional只说明条件推导成立，未付前提仍须解决，不能据此直接宣称终点已证；推导本身有缺步的proposed、启发、引用、实现及有限观察按真实地位使用。refutes指精确被否陈述；相关过期引用定向核对，无关旧边不使整题停工。

## Solver实际交什么，Main怎样判断

每槽持续维护自己的完整Markdown，不另写每轮行政报告。每个有价值结果应能读到：精确陈述及对原题的作用，模型/量词/条件，完整推导或见证，实际证据和必要计算输入，真实状态，具体未付义务与下一步。只交结论摘要或“可以继续探索”不够接续。

Main收到文件先看它改变原题哪一步，核关键综合接口；具体证明和计算可用上述独立挑战，必要时定向追原文。按以下判断给反馈：

- 覆盖原题全部域、量词和约束的完整证明，才支持相应目标成立；在明确额外假设下推导完整则保条件结论。关键推理仍缺时保候选及精确缺口，不能用条件标签掩盖断证。
- 反例要给满足原模型全部前提的见证，并确实否定目标；否定辅助桥与否定原题分开。有限域的穷尽证明与一般域里的有限扫描分开。
- 部分结果说明推进了原题哪个缺口、贡献什么构造或排除哪条精确路线。未知可以保存，但未成功不能称不可能；普通代入和无独有作用的数值点不另造成果。
- 比较新旧结论时核模型、量词、域、前提和结论。同命题不同证明保独立OR，弱结果有独有构造或边界时保其作用；不凭“更强/更新”覆盖独有数学。
- 发现已有证明缺步，只停用该支持并核是否仍有独立证明；命题被精确反例否定另行处理，不把全部后继自动判假。把具体受影响对象、步骤和关系反馈给正在使用它的full槽。

Main保成立部分，将具体缺步、见证检查或下一数学义务交原Solver继续。两个full重复时按实际进展分配不同未解义务或论证对照点，不预设方法、不设常驻检查者；有分歧就核关键推理而非投票。平台followup才是真实反馈；research save记录同一过程。答复已写入笔记后才--ack-feedback，普通save保未答反馈。

反馈也保原输入约定。涉及成果图或其他Solver新成果的依赖与对照交full承接，不能通过反馈给obstacle灌入成果后仍称独立；正常原题澄清记录实际来源，用户明确改输入实验时用新spec/RUN。

每个可接续推进，包括未核草稿和失败尝试，都写入实际工作文件，按准确状态用 research save 及 checkpoint 保存；保存不等于数学准入，不等审查或计算冻结才保草稿。由Main串行发布RUN、文件及依赖、本人板页与恢复入口并确认pushed。长线研究者局部交付后继续有价值的路线，临时请求完成才释放。关键未付义务写明原研究者继续、实际接手者与文件，或主动暂放的弃因和重开条件。不能把closed局部交付变成承重问题无人接。作者失效时，可接手者从原输入、实物、未答反馈和外部job标识继续，不等作者许可。原题开放就持续补位和调整路线，直到准确闭合、用户暂停或实际运行边界。

换环境时用同一分支、存档、子存档和 Boss 执行 start --resume，从返回的 Boss 工作区打开 README 及实际文件，再执行 research resume RUN。恢复以确认已推送的工作区、RUN、证据和下一步为准。计算仍在外部运行时，把请求或运行标识写入工作区，接续者据此查询和取回。

## 谁负责归档和登记、构图增量

Main实质评议后，把可复用正文写到archives/<存档>/[subarchives/<子档>/]state/<类型>/<对象名>--<类型>.md，保稳定身份与实际状态，必要输入/代码/证据归数学owner。原问题仍open可以继续研究，不必等开放问题全解才保有价值内容。

Main对回流负责，可委派正文、证据引用、稳定身份、登记和关系增量的实质准备，核接口后串行发布。未回流内容在当前笔记保精确位置、状态、所欠步骤和实际接续者，不笼统写以后入库，也不逐算术造对象。复核现行总表和受影响端点，在最新版本合并实质改动；共享整合期间研究照常保存并推进。

承重错误先停用精确失败支持，修当前正文入口、登记和关系；不可变旧证据保原字节，现行入口永久带勘误及影响。共同当前入口醒目标更正及受影响结论，直到实际采用者记明撤用、重证或独立支持，不能随个人页换任务抹去。定向送达后消费者修实际推导，ALL漏付仍是义务，OR有效支持保留，无支持待证而非判假。发现者修完或落实真实接手；尚无人接如实写未派发、最后断点与下一动作，不冒称离线作者已接。

先推登记改版，构图再同步并定向重判受影响pin、关系和支持；保其余有效成果，不重做全仓清洗或让无关研究等待全仓整合。已经认真比较而无边的对象也可以是准确输入，研究不以每个对象都连边为前提。

## 计算服务于当前数学义务

能直接推导就推导，确有问题才计算。负责该数学义务的研究者选择后端、执行、取回真实输出并解释其意义，Main协调共享发布与必要资源，不亲自包办运维或重复验算。短计算当前环境，普通批量优先已有云端通道，Codespaces用于确需持续交互或特殊环境。必要输入输出和外部job标识随结果保存，参数按需读[GITHUB_RESOURCES](GITHUB_RESOURCES.md)。进程成功、数值收敛和PASS不代替证明。

## 迭代顺序和验收

| 顺序 | 先做什么 | 用什么验收 |
| --- | --- | --- |
| 1. 主研究循环 | 启动一条真实开放义务，按需查边、实读、派工、接回并保存 | 恢复能打开原题和承重证据，下一位研究者能从实际缺口继续。 |
| 2. 增量回流 | 把已复核的局部引理、精确反例和有用证书写回正文及登记，更新受影响的边 | 另一次研究能从现行图找到并正确代入。改动一项前提时能定位具体受影响的推导。 |
| 3. 丰富超边 | 优先补下一步缺的桥、容易混用的条件、独立证明和真实障碍。跨档比较按明确的模型对应 | 有一条实际推导因此能接下去，或精确排除一条路线。检索范围按真实使用调整。 |
| 4. 扩算力与复刻 | 按计算的实测需求接入后端，再验证一个空仓的原题和研究恢复入口 | 新后端有真实输入与数学输出，空仓完成一次可恢复的研究循环。 |
| 5. 整理论文 | 在有成熟数学成果后，分开做价值判断、论文编写和选刊 | 每项论文主张可追到准确结论和证据。 |

每次按实际卡点调整所读材料。精确取证需要限定输入时，明确列出选择的边和证据。普通研究保留按需扩展。接力片段的篇幅由公式、条件和论证需要决定。

## 在另一个仓库复用

Work 提供 Main 和子代理，GitHub 保存原题、工作文件和 RUN。仓库模板带根 work.py、它调用的 tools 模块及 tools/vendor 依赖、Main 提示词、spec 格式及存档入口。以后新 Project 只需引入启动器、仓库外凭据、Main 提示词和该仓库地址。用 start 的 --remote、--branch 和 --save 绑定实际项目，按需指定 --subarchive 和 --board-branch。数学对象、证据及超边随着新仓库的题目积累，第一题可以从空 seed_ids 开始。需共享计算时按实际后端把对应工作流装入模板。

当前 start 从目标分支恢复仓库并转交其根 work.py。空 GitHub 仓库先由模板放入上述文件及首个存档入口，再用同一启动方式。复刻验收走一次开题、写实际工作文件、checkpoint、换新 clone 后恢复原 RUN。
