# 2.5.1 材料定性：七类、理由与路由

本稿只设计两步。第 1 步对清点范围内的**每份材料全文实读一次**，决定其数学内容性质与下一步处理路由；不在这一遍重证一般定理、追读全部历史、重跑程序或直接以旧 `done` 放行。第 2 步只对选出的数值见证和片段做实质比较、验证所需范围与数学表达。重新登记、最终准入字段/文件结构、第三阶段超边及未来研究 Agent 协议均由后续另定；这里的清单不是它们的 schema。

本设计据 `AGENTS.md`、`research/CURATION.md`、`cleanup/audits/phase25-design` 的审计，另实读本文六例及 CAG 61 客户完整反例等正式页。审计是定向样本，不推算全仓比例。本文实物例是分类校准；实际运行已由用户授权，逐件判断和清理状态以curation/runs/20261103-boss6-triage为准。

## 第 1 步：一次阅读全文的两个独立判断

先看**内容性质**，再看**处理路由**。文件名、`kind`、数字多少、来源年代、审过/执行过、数学真假均不能单独决定内容性质。七类是阅读分流标签，不是未来数学对象类型。`mixed/needs-context` 保留安全出口，但多命题、多种已清楚区分的状态，或附有少量运行说明，本身不构成混合缺陷。

| 内容性质 | 全文读完后可用的判据 | 首轮路由 |
| --- | --- | --- |
| `math-exposition` | 有可理解的数学模型、定义、命题、猜想、精确缺口、构造或论证，相关数字的作用已有足够解释；未证不影响归类，也不要求必须参数化 | 好正文保留，明确错句/缺条件则定点修复；本类不表示审核真值 |
| `numeric-witness` | 有可指认的数学主张/反例和精确见证，但认识仍主要依赖孤立取值，未解释数字承重作用/可化简结构，或缺必要模型/范围；首轮不验证证书。该类可以已有有效反例，不等于判它错误；已有足够结构说明则归 math-exposition | 保留输入证据，转第 2 步蒸馏 |
| `math-fragment` | 有公式、模型或推导片段，但缺使读者理解它所论对象的入口或承重连接；**不是未证就归此类** | 定向找缺的模型/前提/推导，提取可保数学 |
| `algorithm-result` | 判定器、求解器或证书算法有可读数学合同：输入域、输出、保证、支撑理由或准确条件、边界；首轮只识别已有合同，不运行或验证其正确性 | 保住算法合同与论证，源码/运行另归证据；固定样本自测不足以升格 |
| `evidence-only` | 裸代码、输入、日志、有限输出，没有独立数学合同或陈述；暂时找不到对应数学结果也可归此类，不强迫程序考古 | 归对应结果证据；无用途的重复记录可去噪 |
| `non-math` | 全文只有身份、路径、提交、认领、读取字节数、PASS、来源记账或无内容索引，无独有数学 | 清出正式数学层；必要追溯留机器层/历史 |
| `mixed/needs-context` | 数学与非数学有需不同处置的实质内容，或模型/状态混淆、缺上下文，无法安全定性；清楚区分的多命题页仍归 math-exposition | 标数学位置与具体疑问；先抽取再考虑清包装，未理解的数学绝不删 |

快速判定顺序：纯过程先归 non-math；裸实现/输出先归 evidence-only；独立算法合同归 algorithm-result；其余数学按是否已有解释分流。仅有一串数字、best value、负目标值或采样表而无可指认数学主张，不进入昂贵蒸馏队列。

首轮**不填真值状态或审核结论**。`proved` 等旧 metadata 只作待对照线索；看到同页的已否一般式、未解六人式、已有证明的静态式，不审它们的真值；范围和状态已分别清楚时归 math-exposition，确有混淆时才归 mixed/needs-context。不因错误、未证、无当前引用或非主线排除数学。

读全文的最快实际流程：按清点范围逐件读当前正文全文（含嵌入代码和表格），先写一句“删掉时间与身份后剩下什么”；标关键位置；只为辨清类型翻必要的当前模型或显然相同的权威页；不追外链的全部代码、二进制数据与历史副本。看到冲突、引用悬空或承重摘要，仅列一个定向回读问题，不在首轮解决。可用脚本预列路径、长度、重复 ID 与疑似公式损坏，但不能自动定性。纯身份页阅读全文后即可给去噪路由；不重查其 Git 生成史。每份材料必须有一条清单记录，数学清单包含未证和未审数学，不能只列拟放行的定理。

## 第 2 步：数值见证/片段怎样蒸馏

只处理第 1 步转入这一队列者。按**同一模型、同一被检命题、同一量词与相容参数**聚拢；同一数值可服务不同数学对象，多个数值也可能只是同一机制的复算。优先比较最完整的原输入、数学定义、证书、后续纠错与已有成熟正文，记录重复与独有边界。对每组依次问：

1. 精确输入是什么（人数、目录、客户/任务、参数、允许边界），被检式的全部假设和量词是什么？有限求解器只检了什么域？
2. 数值对应哪项数学断言：真实全历史 SPE 反例、固定合法但未必在轨的背景、一个局部不等式、有限域结果，还是搜索线索？实际后继、所有离轨平局、反向下界和最优性若为命题所需，证书必须覆盖；缺项不能用 `PASS` 填补。
3. 有无统一机制可用解析构造、参数条件、最小障碍、上下界或正确的有限定理表达？只有真的推出旧有限例且保住独有边界，才以较一般表达替代片段；否则如实留精确实例。程序生成的有限表不能代替一般 Hall 证明。
4. 蒸馏结果写成可自读的模型、精确陈述、构造/关键推导、证据所担保范围、不能推出的命题与复用用途。源码、输入、原输出作为可定位证据；重复数字和执行次数不另立数学对象。

**数字不等于待蒸馏。** 精确数值反例即使已能否定命题，若数字作用和构造机制仍不清楚，仍可作为有限综合的对象；这不把它退回“反例未成立”。反之，不因尚无参数族就强制再研究。 已有自足证明的页即使有 61 客户、259 历史、1554 比较，也先走“好正文保留”；孤立的 9 与 39/4 则需接回定义与完整续局论证。纯计算/自测页若只有重放与运行合同，不是独立数学对象；若其正文藏一般证明，先移出证明再处理余下记录。真正独立的求解器/判定器有可复用的数学算法合同，不能因为 `kind: program` 自动删除，也不能因为它叫 solver 自动信任其完备性。

## 最简首轮清单

一行对应一份已读材料；混合页只写定位和分流问题。字段只为调度和防遗失，不预设未来对象 ID、manifest、SHA 审读绑定或图结构：

- `path`、`sha256`（只作原材料版本定位）、`category`（七类之一）。
- `math_subject_or_nonmath_reason`（一句具体数学对象/问题，或无数学理由）、`locator`（关键章节/行/数据键）、`route`（保留、去噪/附件、定点修复、承重恢复、第 2 步蒸馏、暂缓）。
- 可选 `tags` 与 `related_paths`，只在准确关联已有页时填写，不强制调查关系。

数学清单可直接筛出四类有数学内容以及混合待抽取行，并用 `related_paths` 指向重复或更完整正文；非数学清单筛 `non-math`，`mixed/needs-context` 只能待抽取，不能进入直接删除批。它们是首轮阅读索引，非准入声明。数学性质无法确定时保持原件，并在一句摘要里写具体疑问。

## 上一版原型在这两步的过重/越界处

[上一版原型](CURATION_PROTOTYPE_V1.md)的全量 baseline/manifest、当前 SHA、`statement/conditions/support/use/status/dependency_scope`、final export、逐文件 action 和分类更正可供后续重新登记与验收，但若在首轮阅读全文时逐项填完整，4465 候选与大量解析不兼容会把快速定性变成格式工程；且字段通过仍不证明数学正确。上一版 `prompts/02.5-research.md`/worker 把冻结、改写、准入、第三阶段关系指纹/impact、超边语义和数学研究尝试连成一次对象群工作；这些不应成为第 1 步每件材料或第 2 步每个数值片段的完成门槛。尤其不得现在决定“一文件一 ID/必须拆文件/稳定段落端点”中哪种是后续唯一 schema，也不为关系连通、Agent 角色或图的 accepted 边预造结论。

阶段二文档中“资源对象进入图”、旧 audit 的“同页可以稳定段落端点”与现行工具的一页一主 ID 有时间上的设计差异；本稿只指出多状态必须分别说明，具体登记方式留给后续。第 1 步的规模覆盖靠逐件全文读和清单闭合，不靠全量重证、程序重跑、原历史逐字节认证或先行删除。第 2 步要投入数学判断，但只对真的有未表达数值机制/片段者投入；好正文直接保全，纯身份直接去噪建议。
