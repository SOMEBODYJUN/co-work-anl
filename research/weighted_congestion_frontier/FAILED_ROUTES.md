# 失败机制与回收

当前没有团队已完成的数学失败路线。以下是协作设计失败，不能写成数学障碍。

## 把普通保存绑定到整轮证明审查 — 已修正

此前提示词只说检查、add、commit、push，没有可复用执行入口，容易让主 agent 每次重新判断授权、重复手填 hash 或等待一般目标证明结束才保存。用户指出这种流程会浪费研究时间，也使尚有义务但已可复用的 candidate、反例和失败回收迟迟不能持久化。

修正为 CHECKPOINT.md 的确定规则和 checkpoint.sh：文件具有真实增量、身份与证据层级准确、相应核验完成后直接保存；程序执行范围检查、commit、普通 push、远端确认和冻结 descriptor。数学结论升级仍单独审查，保存候选不自动证明它。真实 Git 冲突才按具体文件处理，不能把它解释为数学路线失败。公屏认领仍经 board.py 重新验证，不能借通用 checkpoint 的 merge 覆盖占用条件。

## 固定职能分组与中心派单 — 已撤回

旧思路把工作对话长期固定为 literature、upper、lower、mechanism 等角色，hello 后等待协调者 assignment/ack。它依赖协调者先规划搜索空间，会把可自主解题的天团变成单功能服务，并在协调者暂停时阻塞探索。

用户要求所有团队解决同一个问题、集思广益。新方案统一 TEAM/PEER 提示词，按当前 idea 临时自选动作；文献、计算和审查只是推进某个义务需要的工作。回收持久公屏、精确 claim、冻结资产和独立攻击，不回收路线审批权。

## 冲突认领盲目 rebase — 不可采用

两个 clone 从同一 tip 判断一个 idea 空闲，分别 commit claim。第一 push 成功，第二 push 被拒。第二若直接 rebase 后 push，两个互斥 claim 都会进入远端。错误在于 rebase 只解决文件历史，未重算业务条件。

回收机制：普通 push 作为原子远端更新，失败后 fetch、重建台账、重新验证转移，再生成新 commit；不把旧 claim 原样搬到新 tip。测试覆盖该反例。

## 广义 idea 圈地 — 不可采用

“我做势函数/上界”不能成为独占任务；它没有具体完成条件，会封锁整个搜索空间。认领必须有精确命题、义务、具体机制、下一项检验。只对相同推进单元去重，公开补充、反证或独立审查永远允许。语义相同但措辞不同须人工指出并合并，不宣称自动理解全部数学语义。

## 把高目标、槽位或时长当成自动完成保证 — 不采用

单靠提示词写“必须运行一小时”没有部署层硬保证；本会话七槽位包含根成员，跨对话的账户容量也不能由乘法推出。关键错误是把预算/计划误当实际运行，把局部 lemma 或耗尽预算写成主目标完成。回收方法是 RUNBOOK 的真实身份与计时、局部单元完成后接续新义务，以及 ACCEPTANCE 的交接/资产/阶段突破/主目标解决分离。没有引入强制睡眠、无限空轮询或后台唤醒的虚假承诺。这是运行设计边界，不是数学不可能性。

## 仅列开源名称而不保存可核对原文 — 已补齐

此前来源表主要说明借鉴机制，没有可重用的固定版本原文，容易把数学技能的泛泛“润色”与贡献重建混同，也容易说成复制了外部完整架构。现在 SOURCES 与 upstream/manifest.json 保存本任务选定、许可允许的原文、完整commit和逐字节hash；归档与本项目适配分开。没有获得的 compiler 完整主提示词不能声称已复制，原CLI/Docker无限重启未在Web部署。论文者实际读取贡献重建、数学文章与保真原文，并按结果门槛交付；提取者提炼独立数学对象，不机械服务主主题。

## 五队集中启动的紧循环发布重试 — 已复现并修复

默认六次重试的原工具在五个并发发布端各登记七个成员的真实bare-Git压力测试中，可能连续遇到远端旧tip拒绝并耗尽预算。它没有破坏互斥/状态，也保留pending意图，但不能将较高自定义重试下的成功冒称默认入口同样顺畅。修正为默认二十次有限重试与事件特定的短错峰退避，CLI可设一至五十次；每次重读公屏再验证，仍不盲目rebase。测试改为直接使用默认配置。高峰/断网仍可能用稳定事件ID恢复，不声称无延迟或无失败；短网络退避不用于凑研究时长。

## 保存认证与公屏认证分离导致新会话启动缺口 — 已修正

checkpoint 能记住当前 clone 的外部凭据文件路径，但底层 board.py 使用隔离 Git 工作区，不继承调用方的本地 Git 配置。新 Work 先 register 时仍需临时编写 ASKPASS，造成不必要的启动判断。修正为统一 board.sh 入口：先初始化本 clone 的 wcg.tokenFile，使用现有 checkpoint ASKPASS 向子进程传认证环境，之后公屏和保存可直接运行。底层公屏状态转移不改，也不把 Token 写入事件或配置。文件缺失/无效明确报错，换 clone 重新指定当前会话文件。此为工作流缺口，没有数学真值含义。
