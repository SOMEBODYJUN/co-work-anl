## 接续时首先打开什么

先安全同步，再运行 `python work.py research peers <本人的RUN>`，取各 Main 最新保存的不可变笔记、实际工作区路径和下一步；上表链接方便直接阅读。个人合作页只由本人维护，写当前具体子命题、使用的输入/坐标/归一化、交付文件、已经接用的对方结果及下一步。第一次接续即可从现有 Main 笔记提取这几项，不重写全部历史。

当前入口依据提交 `9c82d313001a40cce98de736ab0cf88a39107954` 的实际文件建立：Boss2 第六轮笔记已经描述接读 Boss1 的 81 查询运输约束，并准备对自身完整624系统做扩展。该说明是可供接续的文件线索，具体的来源、域、矩阵版本与未完成核验以原笔记为准。

两边的系统含不同客户型、坐标和约束范围，有限最优值不能按数字大小直接合并为同一普遍下界。复用先核映射、输入和数学范围；已有精确计算不因换一位 Main 就重做。需要独立复核时说明承重问题。各自未完义务仍由原 Main 接续，本入口不重新分配或终止任何代理、运行及云任务。

## 怎样留下别人能继续的结果

正文或成熟草稿、脚本、准确输入/输出、必要证据与本人的合作页一起 checkpoint；确认 pushed 后才共享该版本。接收方在自己的合作页写实际代入位置、得到的新一步，或精确不能代入的条件/坐标差异及所需桥。正式登记和超边回流与研究同步推进。

本入口让同题成果可见；实际合作要看后续接用记录和数学推进。`working` 和代理ID是保存声明，不证明对应会话此刻活跃。
