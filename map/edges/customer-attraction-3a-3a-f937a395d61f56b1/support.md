# 数学支持：重复末覆盖与前缀缺席判据

## 1. 完整 SPE 的末节点不等式

固定空根背景的任意完整有序历史纯 SPE `sigma`，实际末主题为 `B`。末位若改选严格超集 `T`，在 `B` 上所得份额不减，并从每个非空 `T\\B` 客户取得严格正份额，故最佳回复必须是包含 `B` 的极大覆盖集合。若多个标签覆盖相同客户集，必须全部计入同覆盖重数 `k`。

置 `S=|B|`、`V=W-S`、`d=m-k`、`c_x` 为终局负载、

`R = sum_{x in (union_i S_i)\\B} 1/(c_x+1)`.

对于任意比较主题，逐客户比较重数和最终余载 `b_x=c_x-1_{x in B}` 给

`1_{a_x>0} <= (a_x+b_x)/(b_x+1)`.

比较主题都是末节点的合法偏离，逐个使用末位利润不超过 `u`，再用

`sum_x b_x/(b_x+1) = W-u-R`

得到

`OPT_m <= m u + W-u-R = W+(m-1)u-R`. 这一步使用真实末节点，不冻结任何早期续局。

任意玩家在其节点改选 `B`，沿完整策略的改变后历史每个 `B` 客户至多由 `m` 人均分，故利润至少 `S/m`。`k` 个真实覆盖 `B` 的玩家各得 `u`，于是

`k u <= S <= m u`,
`W >= k u + (m-k)S/m >= k(2m-k)u/m`.

合并并在 `W>0` 时除以 `W`，得

`OPT_m/W <= 1 + m(m-1)/(k(2m-k))`.

`(m-k)^2<=m` 时右侧不超过 2，得到 half。`u=0` 或 `W=0` 直接处理；不能把比例式用于这些边界。

## 2. 残余 `R` 与前缀缺席

对节点 `i` 的任意合法主题 `T`，令 `n_i(x)` 为此前实际玩家中未覆盖客户 `x` 的人数。无论改变后的真实后继怎样完成，若当前选 `T`，客户 `x` 至少分到 `1/(m-n_i(x))`，所以

`u_i >= sum_{x in T} 1/(m-n_i(x))`.

取 `T=B`。对最终负载 `t=k+r` 的客户，`r` 个覆盖 `B` 的非末玩家贡献至少 `r/m`，缺席玩家重排后的贡献至少 `H_m-H_t`；扣掉非 `B` 玩家在该客户上的真实收益 `r/t`，得

`A_r = r/m + H_m-H_t-r/t`
`    = H_m-H_t-(t-k)(m-t)/(m t)`
`    >= k(m-t)/(m t) >= 0`.

按 `X_r` 聚合，`V>=sum_r X_r A_r`。因为至多 `d` 人覆盖 `B` 外客户，`R>=V/(d+1)`。令 `a=(d+2)/(d+1)`，`u=sum_t X_{t-k}/t`，得到

`C_t = t + a[t(H_m-H_t)-(t-k)(m-t)/m]`,
`gamma(m,k)=min_{t=k..m} C_t`,
`W+R >= gamma(m,k)u`.

所以 `gamma>=m-1` 充分推出 half。将 `H_m-H_t` 粗化为 `(m-t)/m` 恢复旧线性残余条件 `m(2d+1)>=d^2(d+2)`；更粗的平方条件 `(m-k)^2<=m` 只是已证充分子域。`gamma` 未通过仅是该路线的未支付区，不是 refutation。

无调和数的多项式充分条件为

`[max(N,0)]^2 <= 8m^2(d+1)(d+2)k`,
`N=2md(d+2)+(d+2)k-2m^2`.

## 3. 有限审计和精确边界

原 `prefix_absence_audit.py` 用 `Fraction` 检查 `m<=12` 的 8178 个 pattern、`m<=100` 的 171700 个 `(m,k,r)`、933 个旧残余蕴含和 1156 个多项式蕴含；其保存 JSON 明确标记为“formula audit passed / finite audit only”，没有客户、目录、历史策略或 LP。定义检查脚本进一步保存并核对 364 个按 `r` 最小值、724 个旧平方包含、171700 个多项式下界和 37820 个 `(d,h)` 松弛端点；5050 行 `all_m_k_cases` 的关系逐行满足：

- `old_square -> old_residual -> harmonic_certifies`；
- `polynomial_certifies -> harmonic_certifies`；
- `harmonic_certifies` 与存储的 `gamma>=m-1` 完全一致。

## 4. 固定审计、真实 SPE 与停止边界

恢复的五人 exact-SPE 审计只取 `(p,anchors)=(7,2),(8,3)` 各三个确定 seed：六个有限实例共有 174 条 ordered-SPE paths，14 条满足基本/残余 half 条件；其 ratio 为 `6/5,7/5,40/31,15/13,35/27,1`。源码中的 `ExactSPESolver` 检查这些固定实例的全部根终局与有序路径，但不枚举一般六人完整策略。

`new-definition-check.json` 的 14 单位客户点由定义脚本逐节点核对 42 个含自身比较、35 个非自身比较和 36 个有序动作对：实际 `(0,1)`，两人收益 `(4,4)`，`W=8`，`OPT=10`，仅有最优有序元组 `(2,3),(3,2)`，`R=9`，税项 `4`，half slack `2W-OPT=6`。这是一个实际完整 SPE 的有限校准点；它保持 half，不能成为全模型反例，也不能把 scalar gamma 证书提升成所有 SPE 的 LP/对偶证书。

任务没有声明固定回复 LP；任何 fixed-response/LP 质量只能在另一个明确对象、完整行约束和合法目录解释下使用。即使某个有限标量判据未命中，仍需证明真实完整 SPE 的所有偏离历史和终局福利，才能称为反例。当前合理 follow-up 是对未认证的 `k,d` 区域建立新的真实支付桥，或给出完整 SPE 的 exact counterexample；本包不把候选 `CA-FIVE-HALF-EXACT-v1`、`CAG-MODEL` 当读取证据。
