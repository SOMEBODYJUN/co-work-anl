# 支持记录：固定 cross ZZ 必要点

## 1. 有限闭包层

闭包程序在固定 hist、K 与 R 边缘后，将每个正 hist 质量切成共同阈值 slab。slab 内 R 位固定，Z 质量满足 `0 <= z_(s,g) <= m_s`；旧 1905 坐标按四态回填，R-R 交叠取 `min(q_g,q_f)`，再对旧仿射行和 60 个 ZZ 槽逐一重算。核心点使用 `--cross --priced --optimum` 版本：旧 4927 行 + 新 60 行 = 4987 行，302 个 Z 变量，24 层。

## 2. 数据级精确检查

逐条读取 `all-row-slacks.json`，确认连续索引、全部 Fraction 可解析、没有负余量，并统计 `Z-Z` 槽 19 正/41 零。逐 slab 读取条件 cube JSON，确认每个 slab 的 atom 质量和等于区间长度，227 个原子均为严格正有理数，24 slab 总质量为 1，302 个 variable index 与正文一致。上述是保存证书和有限必要图的检查；没有重建 4927 行的系数生成器，也没有执行 LP。

## 3. 共同模型的语义限制

共同目录模型的纯 SPE 量词是对全部有序历史和全部标签的单方偏离，并沿同一策略完成真实续局。有限 ZZ 行只表达固定第四位/第五位末回复的聚合比较；条件 cube 只实现会员边缘及所列交叠。故 `W < 1/2` 是固定必要系统的低覆盖候选，不能写成游戏反例；`O=1` 也不自动等于 `OPT_6`，除非另有共同目录和最优元组证明。

## 4. FLOOR 障碍

新索引回复安全引理对 family-0 非对角 30 条实际 R 查询给出完整同一策略下的必要 FLOOR。核心点正文保留旧 hist/R，逐项读得

`30u3-Q = -4749850661723892253166888285611 / 107365313311072858536618851786648`。

这个负值证明固定 hist/R 骨架不能由任何共同目录/策略完成为完整 SPE；它没有否定有限 4987 行点，也没有覆盖改换 R/hist 的其它候选。该作用只记录模型边界，因此采用 `checks` + `relation_mode: context`。
