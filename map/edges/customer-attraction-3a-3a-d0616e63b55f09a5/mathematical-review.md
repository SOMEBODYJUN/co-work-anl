## 实际确认的结论

固定 16 个旧 hist 的 4849 列必要系统中，5692 行新点有 261 个正质量，`O=1`，

```text
W = 1905769909616898376137238949200623274593168205
    / 3898693540058852735821709960049703833207552519 < 1/2
O - 2W = 87153720825055983547232061648457284021216109
        / 3898693540058852735821709960049703833207552519 > 0
```

原 5692 行 necessary replay 的最小有理 slack 为 0。独立标准库审计消费了顶层字段和全部列元数据，逐项核对 194 个 joint groups、2612 个 overlap 上界、三类 actual-B family、maximum-root family、64 个 hist marginals、6 个容量行与 28 条新增菜单价格/CAP 行。所有 28 行在新点均非负，其中 24 条严格正、4 条为零。

旧 5664 点与新点的列描述符、K、16 个 hist 质量和 W 完全相同，但 214 个隐藏质量发生变化：joint-reply 70、overlap 52、actual-B-family-state 52、maximum-root-family-state 40。把新 28 行作用到旧点时，唯一负行是 source2 的 actual-menu-price:6：

```text

/ 652887283919685192981664984788241385973843146740115858240
```

因此旧点不能在保留该隐藏质量和四菜单坐标的同时补成满足真实普通末价条件的完整纯 SPE；新增补价行把这个特定坐标的缺口切断。

## 数学范围

对象使用共同目录完整历史模型：有限单位客户、有限非空标签目录、六名顺序玩家、全有序历史纯 SPE 和均分收益。这里仅保留固定 b-family 生成的有限 necessary system 和指定四个菜单（actual-B-2/3/4 与 maximum-M-root）的 28 条价格/CAP 行。5692 点的有限 necessary 可行性不是共同目录实现，也不是完整策略树。

`B_menu_prices_master.py --all-families --verify` 的历史执行报告给出 5692 行、4849 列、exit 0；独立审计没有重跑旧 5664 builder，而用 point-comparison 精确评估旧点的 28 条新行。因此旧点负行是本次新核查，不能把旧作者的 5664 行报告改写成 5692 行。

## 未付义务与反例边界

本结果没有证明六人全目录存在/不存在 SPE，也没有给出实际 `OPT_6`、全局 half 反例或普遍福利界。5692 点和 5664 点同 W 不代表完成性相同；同样不能把旧点的负价格迁移到新点，或把新点的有限通过迁移到其它 5494/5259 点。跨 hist、跨根枝、全客户联合实现和全部真实后继仍需新的证书。
